# 08 编码与古典密码
## Encoding & Classical Ciphers

> [!info]- 章节信息
> **所属方向**：通用基础 ｜ **难度阶段**：L0 预备期 ｜ **前置要求**：[[03-计算机组成与数据表示|03 计算机组成与数据表示]] · [[06-Python与CTF脚本基础|06 Python 与 CTF 脚本基础]]
> **本章目标**：分清编码、加密、哈希三条路；认全 Base 家族和常见古典密码的「长相」；能手撕 Base64，能对一段维吉尼亚密文做完整破解。

## 1. 先分清三条路

拿到一串可疑字符，第一个动作不是开工具，是判断它站在哪条路上。三条路性质完全不同：

| | 编码 | 加密 | 哈希 |
| --- | ---- | ---- | ---- |
| 密钥 | 没有 | 有 | 没有 |
| 可逆性 | 谁都能逆 | 有密钥才能逆 | 逆不了 |
| 目的 | 方便传输、存储 | 保密 | 完整性校验、指纹 |
| CTF 动词 | decode | decrypt | 查表、碰撞、暴破 |
| 代表选手 | Base64、hex、URL | AES、RC4、RSA | MD5、SHA1 |

一句话：==编码换马甲，加密上锁，哈希烧灰==。马甲谁都能脱，锁得有钥匙，灰谁也拼不回去。

misc 方向大部分的「密码题」其实是编码题。真·加密（AES、RC4 这些带密钥的）归 crypto 方向管。哈希不可逆，比赛里所谓「解 MD5」是拿哈希值去在线彩虹表查（cmd5 之类的站），或者扔 hashcat 暴破，不是数学意义上的逆运算。

> [!warning] 「解码」和「解密」是两条路
> 编码没有密钥，「破解一个 Base64」这个说法本身就不成立。你只是认出了它，然后把它翻回去。拿到密文先问一句：这里面有没有密钥？没有就走「识别 → 解码」，别上来就尝试 AES。

## 2. Base 家族

### 2.1 速查表与实测

| 家族 | 字符集 | 填充符 | 长度比 | 一眼特征 |
| ---- | ---- | ---- | ---- | ---- |
| Base16 / hex | `0-9A-F`（或小写） | 无 | 2:1 | 长度是偶数，只有十六进制字符 |
| Base32 | `A-Z` + `2-7` | `=` | 8:5 | 全大写，结尾常挂一串 `=` |
| Base58 | 比特币字母表 58 个 | 无 | 动态 | ==没有 0、O、I、l==，也没有 `=` |
| Base64 | `A-Za-z0-9+/` | `=` | 4:3 | 大小写敏感，`+` `/` 出没 |
| Base85 | 33~117 号可见字符 | 无 | 5:4 | 标点乱飞，`^` `?` `%` 都有 |

同一段字节喂给五个家族，看它们各变什么德行（实测输出）：

```python
import base64

data = b"flag{n0t_encrypti0n}"          # 19 字节
for name, enc in [("base16", base64.b16encode), ("base32", base64.b32encode),
                  ("base64", base64.b64encode), ("base85", base64.b85encode)]:
    s = enc(data).decode()
    print(f"{name:7} len={len(s):3}  {s}")

# base58：比特币字母表，去掉了 0/O/I/l，无填充符
ALPH = "123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz"
def b58(data: bytes) -> str:
    n = int.from_bytes(data, "big")
    out = ""
    while n:
        n, r = divmod(n, 58)
        out = ALPH[r] + out
    pad = "1" * (len(data) - len(data.lstrip(b"\x00")))   # 前导 0x00 → 前导 '1'
    return pad + out

print(f"base58  len={len(b58(data)):3}  {b58(data)}")
```

```
base16  len= 40  666C61677B6E30745F656E637279707469306E7D
base32  len= 32  MZWGCZ33NYYHIX3FNZRXE6LQORUTA3T5
base64  len= 28  ZmxhZ3tuMHRfZW5jcnlwdGkwbn0=
base85  len= 25  W^7?+du}jvUuAA%a(QrcX)tbm
base58  len= 28  2RmC5owp8JiNV8w9b5q9e6WrNX1E
```

base85 最短也最丑，base16 最长（一个字节硬拆两个字符）。base58 的前导 `1` 是前导 `0x00` 的替身，比特币钱包地址开头一串 `1` 就是这么来的。

### 2.2 Base64 原理：3 字节变 4 字符

为什么是 64：2⁶。拿 64 个安全字符表示任意字节，代价是每 6 位才对应一个字符。流程：3 字节拼成 24 位，切四份，每份 6 位查表。经典例子 `Man` → `TWFu`（实测输出）：

```python
for c in b"Man":
    print(f"{c:3} {c:08b} {chr(c)}")
n = int.from_bytes(b"Man", "big")
print(f"{n:024b}")
print([f"{(n >> s) & 0x3F:06b}={T[(n >> s) & 0x3F]}" for s in (18, 12, 6, 0)])
```

```
 77 01001101 M
 97 01100001 a
110 01101110 n
010011010110000101101110
['010011=T', '010110=W', '000101=F', '101110=u']
```

24 位切成 `010011` `010110` `000101` `101110` 四份，分别是 19、22、5、46，查表得 `T`、`W`、`F`、`u`。末尾凑不满 3 字节就补零继续切，补了几位用 `=` 记账：剩 1 字节补两个 `=`，剩 2 字节补一个。

### 2.3 二十行实现

```python
import base64

T = "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/"

def b64enc(data: bytes) -> str:
    out = []
    for i in range(0, len(data), 3):
        chunk = data[i:i + 3]                     # 3 字节一组
        n = int.from_bytes(chunk.ljust(3, b"\x00"), "big")
        quad = "".join(T[(n >> s) & 0x3F] for s in (18, 12, 6, 0))
        if len(chunk) == 1:
            quad = quad[:2] + "=="
        if len(chunk) == 2:
            quad = quad[:3] + "="
        out.append(quad)
    return "".join(out)

def b64dec(s: str) -> bytes:
    s = s.rstrip("=")
    bits = "".join(format(T.index(c), "06b") for c in s)
    return bytes(int(bits[i:i + 8], 2) for i in range(0, len(bits) - 7, 8))

msg = b"flag{bit_split}"
mine, std = b64enc(msg), base64.b64encode(msg).decode()
print(mine)
print(std)
print(mine == std)
print(b64dec(mine).decode())
```

```
ZmxhZ3tiaXRfc3BsaXR9
ZmxhZ3tiaXRfc3BsaXR9
True
flag{bit_split}
```

> [!note] 为什么要手撕
> 工具一键能干的事，自己写一遍才知道「长度不是 4 的倍数」「结尾多一个 `=`」这类报错从哪来的。[[#7. 编码链识别与剥层|7 节]]的剥层骨架也靠这个底子。

### 2.4 变体：URL-safe 与去填充

```python
raw = b"\xfb\xff\xbf"                 # 这段字节的标准 base64 恰好含 + 和 /
print(base64.b64encode(raw))
print(base64.urlsafe_b64encode(raw))
```

```
b'+/+/'
b'-_-_'
```

URL-safe 变体把 `+` 换成 `-`、`/` 换成 `_`，URL 里传 base64 出问题的第一嫌疑人就是它。另一个常见变体是去填充：密文把 `=` 全删了，解码前补回去就行，`s + "=" * (-len(s) % 4)`。base32hex（字符集 `0-9A-V`）偶尔露面，认字母表即可。

再往深处看一层：==base64 是位切分，base58 是大整数进制转换==。base58 没法按位对齐，所以没有填充符，慢但字符集干净——这正是比特币选它的原因，肉眼难分辨的 `0OIl` 全被踢了。

## 3. 一切皆字节

[[06-Python与CTF脚本基础|06 章]]说过：str 是字符，bytes 是字节，网络和文件里流的永远是 bytes。这一节的全家桶都长在 bytes 上（实测输出）：

```python
from urllib.parse import quote, quote_plus, unquote
import html, quopri

s = "flag{空 格 与 & 符}"
print(quote(s))                                   # URL 编码，字母数字和部分符号不动
print(unquote("flag%7B%E7%A9%BA%20%E6%A0%BC%7D"))
print(quote_plus("a b&c=d"))                      # 表单风格：空格变 +
print(html.escape('<img src=x onerror="alert(1)">'))
print(html.unescape("&lt;script&gt;&amp;123"))
print("旗".encode("unicode_escape"))              # 非 ASCII 变 \uXXXX
print("\u0046\u006c\u0061\u0067")                 # \uXXXX 写在源码里会直接变回字
print(quopri.encodestring("flag，这里有中文和=号".encode()))

x = quote("<script>")                             # 双重编码：%25 是 % 自己
print(x)
print(quote(x))
```

```
flag%7B%E7%A9%BA%20%E6%A0%BC%20%E4%B8%8E%20%26%20%E7%AC%A6%7D
flag{空 格}
a+b%26c%3Dd
&lt;img src=x onerror=&quot;alert(1)&quot;&gt;
<script>&123
b'\\u65d7'
Flag
b'flag=EF=BC=8C=E8=BF=99=E9=87=8C=E6=9C=89=E4=B8=AD=E6=96=87=E5=92=8C=3D=E5=\n=8F=B7'
%3Cscript%3E
%253Cscript%253E
```

五个要点：

1. `quote` 只编码保留字符之外的部分，字母数字和 `-._~` 原样放行；`quote_plus` 是表单风格，空格变 `+`，`&` `=` 也逃不掉。
2. HTML 实体有两套写法：`&amp;` 这类名字形式，`&#x3C;` 这类数字形式，`html.unescape` 都认。
3. `\uXXXX` 是 Unicode 转义，一个中文也能写成 `\u65d7`。有些题把整段 flag 藏成 `\u0066\u006c...`，`decode("unicode_escape")` 一发入魂。
4. Quoted-Printable 把每个非 ASCII 字节写成 `=XX`，一个 UTF-8 中文占三组。看输出中间那个孤零零的 `=\n`：那是按 76 字符强制折行留下的续行符，不是数据，解码前要处理掉。
5. `%253C` 剥一层是 `%3C`，再剥才是 `<`。这叫双重编码，Web 方向拿它绕 WAF 是常规操作。

> [!warning] decode 报错先想到编码不匹配
> `UnicodeDecodeError` 十有八九不是数据坏了，是拿 UTF-8 的钥匙开 GBK 的门。国内老比赛偶尔用 GBK 坑人，换编解码器再试。

## 4. 移位系：转圈、折纸、走格子

### 4.1 凯撒与 ROT13

```python
def shift(s, k):
    """凯撒移位：字母在 26 个位置上转圈，非字母原样保留"""
    out = []
    for c in s:
        if "a" <= c <= "z":
            out.append(chr((ord(c) - 97 + k) % 26 + 97))
        elif "A" <= c <= "Z":
            out.append(chr((ord(c) - 65 + k) % 26 + 65))
        else:
            out.append(c)
    return "".join(out)

pt = "caesar moved the letters, not the meaning"
ct = shift(pt, 3)
print("密文:", ct)
print("ROT13 自反:", shift(shift("hello", 13), 13))
for k in range(26):
    print(f"{k:2d} {shift(ct, -k)}")
```

```
密文: fdhvdu pryhg wkh ohwwhuv, qrw wkh phdqlqj
ROT13 自反: hello
 0 fdhvdu pryhg wkh ohwwhuv, qrw wkh phdqlqj
 1 ecguct oqxgf vjg ngvvgtu, pqv vjg ogcpkpi
 2 dbftbs npwfe uif mfuufst, opu uif nfbojoh
 3 caesar moved the letters, not the meaning
 ……（4 到 25 号位移同理，一眼假，略）
```

凯撒的破解不需要数学：==26 个位移全扫==，两秒结束战斗。ROT13 是 k=13 的特例，加密解密同一个函数，出题人连密钥都懒得发。它唯一的价值是当签到题和当喷雾——把剧透喷成乱码。

### 4.2 栅栏密码（W 形）

字符沿 W 形一上一下走，几栏就有几行，走完按行读。3 栏加密 `flag{r4il_f3nce_w_shape}` 的路线（实测数据画的）：

```
f . . . { . . . l . . . n . . . w . . . a
. l . g . r . i . _ . 3 . c . _ . _ . h . p . }
. . a . . . 4 . . . f . . . e . . . s . . . e
```

三行各读一遍拼起来就是密文。代码加解密各十行（实测输出）：

```python
def fence_enc(s, n):
    rails = [[] for _ in range(n)]
    r, d = 0, 1
    for c in s:
        rails[r].append(c)
        if r == 0:
            d = 1
        elif r == n - 1:
            d = -1
        r += d
    return "".join("".join(x) for x in rails)

def fence_dec(ct, n):
    idx, r, d = [], 0, 1
    for _ in ct:
        idx.append(r)
        if r == 0:
            d = 1
        elif r == n - 1:
            d = -1
        r += d
    res = [""] * len(ct)
    pos = 0
    for rail in range(n):
        for i, rr in enumerate(idx):
            if rr == rail:
                res[i] = ct[pos]
                pos += 1
    return "".join(res)

msg = "flag{r4il_f3nce_w_shape}"
e = fence_enc(msg, 3)
print(e)
print(fence_dec(e, 3))
```

```
f{lnwalgri_3c__hp}a4fese
flag{r4il_f3nce_w_shape}
```

解密的思路：W 形路线本身是确定的，先把每个位置该落在哪一行算出来，再把密文按行数切回去。栏数是唯一参数，==解出乱码就换栏数，2 到 7 逐个试==。

### 4.3 曲路密码

明文按行填进格子，空位补字符，再沿指定的路读。S 形路线（第 0 列从上往下，第 1 列从下往上，交替）：

```
m e e t
a t t h
e s o u
t h g a
t e # #
```

```python
def route_enc(s, cols):
    rows = -(-len(s) // cols)              # 向上取整
    grid = s.ljust(rows * cols, "#")       # 空位补 #
    out = []
    for j in range(cols):
        col = [grid[i * cols + j] for i in range(rows)]
        out.append("".join(col) if j % 2 == 0 else "".join(reversed(col)))
    return "".join(out)

def route_dec(ct, cols):
    rows = len(ct) // cols
    grid = [""] * (rows * cols)
    pos = 0
    for j in range(cols):
        col = [ct[pos + i] for i in range(rows)]
        pos += rows
        for i in range(rows):
            grid[i * cols + j] = col[i] if j % 2 == 0 else col[rows - 1 - i]
    return "".join(grid).rstrip("#")

msg = "meetatthesouthgate"
e = route_enc(msg, 4)
print("enc:", e)
print("dec:", route_dec(e, 4))
```

```
enc: maettehsteetog##auht
dec: meetatthesouthgate
```

读出来的 `maett + ehste + etog# + #auht` 就是密文。「路」由出题人定：S 形、螺旋、对角线都有人用，认不出路就枚举常见路线，列数从 2 试起。补位字符（`#`、`_`、随机字母）经常原样留在密文里，反而是个提示。

## 5. 替换系：认形就赢

这一类的共同点：==没有密钥推理，只有形状识别==。认出来，查表，收工。认不出来，卡到天荒地老。

### 5.1 摩斯

```python
MORSE = dict(zip("abcdefghijklmnopqrstuvwxyz",
                 ".- -... -.-. -.. . ..-. --. .... .. .--- -.- .-.. -- -. --- .--. --.- .-. ... - ..- ...- .-- -..- -.-- --..".split()))
MORSE.update(zip("0123456789", "----- .---- ..--- ...-- ....- ..... -.... --... ---.. ----.".split()))
REV = {v: k for k, v in MORSE.items()}

msg = "hello world 2026"
print(" ".join(MORSE[c] for c in msg.replace(" ", "").lower()))

print("".join(REV[t] for t in ".... . .-.. .-.. ---".split()))
```

```
.... . .-.. .-.. --- .-- --- .-. .-.. -.. ..--- ----- ..--- -....
.... . .-.. .-.. --- / .-- --- .-. .-.. -.. / ..--- ----- ..--- -....

```

特征：点横加空格，`/` 分单词（有的题用 `|` 或 `00`）。数字是五符号码，`1` 是 `.----`，`6` 是 `-....`。摩斯不分大小写。变体玩法：点横互换的反表、拿 `01` 二进制当点横——都是换马甲的查表题。

### 5.2 培根

每个字母 5 位 a/b（实测输出）：

```python
def bacon_enc(s):
    return " ".join(format(ord(c) - 97, "05b").replace("0", "a").replace("1", "b") for c in s)

def bacon_dec(s):
    return "".join(chr(int(w.replace("a", "0").replace("b", "1"), 2) + 97) for w in s.split())

print(bacon_enc("flag"))
print(bacon_dec(bacon_enc("hidden")))
```

```
aabab ababb aaaaa aabba
hidden
```

经典培根只有 24 个字母（I/J、U/V 共用编号），明文带 j、u、v 就对不上，比赛一般用 26 字母版。进阶玩法：a/b 不在字符上，在==字体的粗细、大小写、两张图的差异==上。看到一段「长得一样但个别字母大写」的文本，先想培根。

### 5.3 猪圈与键盘

猪圈（pigpen）纯图形：方格、叉格、带点不带点，26 个字母 26 个形状。没有代码可写，认形状背对照表（dcode.fr 一搜就有），圣堂武士密码是它的花体版。这类图形密码的对策就一句话：把对照表存进手机相册。

键盘密码两大门派。手机九键：字母 = 键号 + 第几个字母，`63` = 6 号键第 3 个 = `o`。电脑键盘：把 flag 用九宫格数字键连线画出来（图形题），或者整体错一格读（`odcs` 风格）。

```python
PAD = {"2": "abc", "3": "def", "4": "ghi", "5": "jkl", "6": "mno",
       "7": "pqrs", "8": "tuv", "9": "wxyz"}
def t9_enc(s):
    return "".join(f"{k}{v.index(c) + 1}" for c in s.lower() for k, v in PAD.items() if c in v)
def t9_dec(d):
    return "".join(PAD[d[i]][int(d[i + 1]) - 1] for i in range(0, len(d), 2))

print(t9_enc("hello"))
print(t9_dec(t9_enc("hello")))
```

```
4232535363
hello
```

两位一组是惯例不是标准，题目不给分隔就得猜切分。数字串里出现 `1` 或 `0` 基本可以排除九键，这两个键上没有字母。

## 6. 维吉尼亚：一次完整破解

凯撒 26 个位移全扫太轻松，于是有人把 26 个凯撒轮着用，这就是维吉尼亚：密钥第 i 位是几，明文第 i 个字母就移几，密钥循环使用。它撑起了「几百年无人能破」的名声，直到频率分析登场。这道分水岭也让它成了 CTF 古典密码的压轴题。

### 6.1 密码本体

```python
def vig_enc(pt, key):
    key, out, i = key.lower(), [], 0
    for c in pt:
        if c.isalpha():
            k = ord(key[i % len(key)]) - 97
            base = 65 if c.isupper() else 97
            out.append(chr((ord(c) - base + k) % 26 + base))
            i += 1
        else:
            out.append(c)
    return "".join(out)
```

密钥只对字母轮转，空格标点白嫖通行。==`i` 只在字母上递增==——记住这句，6.3 有个坑就是它。

### 6.2 先猜密钥长度（重合指数）

难点在不知道密钥，26 位移全扫没得扫了。突破口：密钥有多长，密文就能切成多少列，==每列都是一个纯凯撒==。

猜列数用重合指数（Index of Coincidence）：从文本里随机摸两个字符，恰好相同的概率。英文约 0.066，随机文本约 0.038（就是 1/26）。列切对了，每列只是被整体平移的英文，IoC 靠近 0.066；切错了，四不像，靠近 0.038。

```python
from collections import Counter

def ioc(s):
    """重合指数：随机文本约 0.038，英文约 0.066"""
    n = len(s)
    cnt = Counter(s)
    return sum(v * (v - 1) for v in cnt.values()) / (n * (n - 1))

ca = "".join(c for c in ct if c.isalpha())   # 剔掉空格再分析，密钥只对字母轮转
for kl in range(1, 11):
    cols = [ca[i::kl] for i in range(kl)]
    avg = sum(ioc(c) for c in cols) / kl
    print(f"keylen={kl:2d}  avg IoC={avg:.4f}")
```

### 6.3 再逐列攻（卡方）

列切对了，剩下就是在 26 个凯撒里挑一个。用卡方统计挑：对每个候选位移 k，把列「解密」一遍，数各字母出现次数，跟英语频率表算偏差，挑偏差最小的。

```python
EN_FREQ = [0.08167, 0.01492, 0.02782, 0.04253, 0.12702, 0.02228, 0.02015,
           0.06094, 0.06966, 0.00153, 0.00772, 0.04025, 0.02406, 0.06749,
           0.07507, 0.01929, 0.00095, 0.05987, 0.06327, 0.09056, 0.02758,
           0.00978, 0.02360, 0.00150, 0.01974, 0.00074]

def chi2_best(col):
    n, cnt = len(col), Counter(col)
    best = (1e9, -1)
    for k in range(26):
        s = sum((cnt.get(chr((c + k) % 26 + 97), 0) - EN_FREQ[c] * n) ** 2 / (EN_FREQ[c] * n)
                for c in range(26))
        if s < best[0]:
            best = (s, k)
    return best

kl = 4
rec = "".join(chr(chi2_best(ca[i::kl])[1] + 97) for i in range(kl))
print(f"按 keylen={kl} 逐列卡方 -> 密钥: {rec}")
```

> [!warning] 我踩过的坑：空格不能进切片
> 直接 `ct[i::kl]` 切在带空格的密文上。空格占着位置却不消耗密钥，一列里混进了别列的字母，卡方当场破出 `ohiy`，解出来全是乱码。密钥只对字母轮转，==分析前先把非字母剔干净==。

这套破解对明文长度有门槛：一百字符以下 IoC 开始抽风，几十字符基本靠人眼（见 [[#9. 常见问题|FAQ]]）。

## 7. 编码链识别与剥层

==编码题死在认不出，不死在解不动==。判断顺序四步走：==字符集 → 长度特征 → 填充符 → 熵==。

1. 字符集：`sorted(set(s))` 一把列出用到的字符，对[[#2. Base 家族认脸|2.1 的表]]撞
2. 长度：base64 长度是 4 的倍数，hex 是偶数，base32 是 8 的倍数
3. 填充符：`=` 结尾挂几个；base58 无填充
4. 熵：前三步拿不准，看信息量

```python
import math
from collections import Counter

def entropy(s):
    n = len(s)
    return max(0.0, -sum(v / n * math.log2(v / n) for v in Counter(s).values()))

for probe in ["aaaaaaaa", "flag{abc}", "Wkk1T2VnND0=", "xK9mQ2vL8pZ3wR7T"]:
    print(f"{probe:16} len={len(probe):2}  H={entropy(probe):.2f}")
```

```
aaaaaaaa         len= 8  H=0.00
flag{abc}        len= 9  H=2.95
Wkk1T2VnND0=     len=12  H=3.42
xK9mQ2vL8pZ3wR7T len=16  H=4.00
```

全同字符熵为 0，纯 hex 均匀分布顶到 4.00，base64 顶到 6。==熵高不代表加密了==，只代表字符多样性高，压缩、随机数、加密都能拉高它。

| 密文长相 | 先猜 |
| ---- | ---- |
| `[0-9A-Fa-f]{16,}` 偶数长 | hex |
| 大写字母 + 数字 2-7，`=` 结尾 | base32 |
| 大小写混合，`=` 结尾 | base64 |
| 找不到 0 O I l | base58 |
| 标点乱飞 | base85 / uuencode |
| `%XX` 到处都是 | URL 编码 |
| `&#x...;` 或 `&amp;` | HTML 实体 |
| `\uXXXX` 成串 | Unicode 转义 |
| 点、横、斜杠 | 摩斯 |
| a/b 五位一组 | 培根 |
| 两位数字一组 | 手机九键 |

嵌套编码的剥层骨架（实测输出）：

```python
import base64

def looks_text(b):
    try:
        s = b.decode()
    except UnicodeDecodeError:
        return False
    return all(32 <= ord(c) < 127 for c in s)

def peel_once(data):
    """对当前这一层，把认得出来的编码挨个试"""
    s = data.strip()
    if not looks_text(s):
        return None
    try:
        return "hex", bytes.fromhex(s)
    except ValueError:
        pass
    try:
        return "base64", base64.b64decode(s + b"=" * (-len(s) % 4), validate=True)
    except Exception:
        pass
    return None

inner = b"flag{peel_the_onion}"
layer2 = inner.hex().encode()
layer3 = base64.b64encode(layer2)
print("最外层:", layer3.decode())

cur = layer3
for i in range(10):
    r = peel_once(cur)
    if r is None:
        print("剥完:", cur.decode())
        break
    name, nxt = r
    print(f"第 {i + 1} 层 {name} -> {nxt.decode()}")
    cur = nxt
```

```
最外层: NjY2YzYxNjc3YjcwNjU2NTZjNWY3NDY4NjU1ZjZmNmU2OTZmNmU3ZA==
第 1 层 base64 -> 666c61677b7065656c5f7468655f6f6e696f6e7d
第 2 层 hex -> flag{peel_the_onion}
剥完: flag{peel_the_onion}
```

骨架只省体力，==判断权在人==。每剥一层瞄一眼：URL 剥完还有 `%` 就继续剥，base64 解出二进制乱码就停手换思路。base64 套 hex 套 URL 的三连在比赛里是家常便饭，剥到不是编码为止。

## 8. 工具流：先手撕，再一把梭

CyberChef：GCHQ 出品的编码瑞士军刀，左边原料右边产物，中间拖配方。两个配方出场率最高：Magic（自动猜编码链，套几层它都能一路试到底）和 From Chain（手动把 FromHex → FromBase64 → Decode text 串成一列）。网页版随开随用，GitHub 上有离线包，比赛内网断网时靠它救命。

一把梭系：随波逐流、PuzzleSolver 这类国内整合工具，把 base 全家、摩斯、培根、猪圈、时间戳一股脑塞进右键菜单，粘进去点一下全试。古典密码专精站点是 dcode.fr，猪圈、圣堂武士、曲路的对照表全有。

> [!warning] 一把梭的正确姿势
> ==先理解原理，再梭哈提速==。理由很现实，比赛断网，在线工具直接出局；新变体工具不认得，base64 换个字母表它就瞎；梭不出来时，你不知道卡在哪一层。手撕是兜底能力，工具是效率外挂，顺序别反。

Python 侧的「一把梭」就是 [[#7. 编码链识别与剥层|7 节]]的 peel 骨架，往 `peel_once` 里继续加候选（base32、base85、uuencode、ROT 全扫），就能长成自己的半自动解码器。

## 9. 常见问题

| 现象 | 原因与解决 |
| ---- | ---------- |
| `base64 -d` 报 `invalid input`，Python 报 `Incorrect padding` | 缺 `=` 就补：`s + "=" * (-len(s) % 4)`。实测本机 uutils 0.10.0 的 CLI 对缺 `=` 宽容、对补位后残留非零位的输入反而严格（`bHN=` 拒收）；Python 正好反过来，不查脏位、缺 `=` 必报错 |
| base64 解出来是乱码 | 解出来的可能还是一层编码，或者根本不是 UTF-8 文本；先 `print(bytes)` 看字节再决定下一步 |
| 维吉尼亚破出乱码 | 密钥长度取了倍数假峰（8 而非 4），或明文太短统计失灵；取最小峰，或 1~16 全试一遍看哪个长度出人话 |
| IoC 各长度数值都差不多 | 明文太短。跳过 IoC，直接对每个长度跑卡方，挑解出来像话的 |
| 拼音/中文拼音明文卡方翻车 | 英语频率表不匹配。换目标语言频率表，或逐列把 26 个位移全打出来人工挑 |
| `%253C` 剥一层还剩 `%3C` | URL 双重编码，`unquote` 到没有 `%` 为止 |
| `unquote` 完 `+` 还在 | `quote_plus` 把空格变 `+`，`unquote` 不处理 `+`，换 `unquote_plus` |
| 栅栏解出乱码 | 栏数不对，从 2 遍历到 7 |
| `unicode_escape` 报错 | 它是 str 侧的编解码方法，bytes 要先 `decode`；或直接对 bytes 用 `.decode("unicode_escape")` |
| 摩斯解码对不上 | 各平台字母表、分词符（`/`、\|、`00`）约定不同，先看题目给的表 |
| 培根解到 j/u/v 不对 | 经典培根 24 字母，I/J、U/V 共用编号，换 26 字母版 |
