## 1. CTF 密码学题长什么样

==Crypto 题不是让你发明密码，是给你加密程序和输出，利用体制弱点反推明文==。出题人发的附件几乎永远长这样：

| 附件内容 | 对应现实 |
| -------- | -------- |
| `chall.py`（加密脚本，key 被涂黑或用 `XXXX` 代替） | 加密算法、参数、随机数来源全公开 |
| `output.txt` / `ciphertext`（密文、n、e、c 等） | 唯一要攻破的东西 |
| 缺失的那块（明文 / 密钥 / flag） | 你要还原的目标 |

解题流程固定三步：

1. **读脚本**——它是 `enc.py`，逐行看懂每个变量。
2. **找弱点**——e 太小？n 共用？密钥重用？种子可猜？==弱点几乎总写在脚本里，不写在密文里==。
3. **写解密**——把攻击写成十几行 Python，跑出明文。

密码学家的噩梦不是算法被破解，是"使用者把它用坏了"。CTF 出题人专挑使用坏法出题：OTP 用两次、ECB 加图片、RSA 挑 e=3、随机数拿时间当种子。==算法本身都对，错的是参数和用法==——这也是为什么后面每一节都在讲"正确版本"和"翻车版本"的对比。

> [!note] 和 [[08-编码与古典密码|08 编码与古典密码]] 的分工
> Base64、Hex、摩斯、栅栏、凯撒在那边——那些是"编码与古典密码"，特征是**没有密钥或密钥弱智**，靠识别 + 套工具。本章的对称密码、哈希、RSA、随机数才是"现代密码学"，特征是**有真密钥**，靠数学 + 读脚本。拿到题先分清是哪边，别拿 Caesar 解 RSA。

## 2. 数论最小集

==数论不为考试，为的是 RSA 能看懂==。四个概念，每个先说"它是干嘛的"，再给三五行实现，数值全部真实跑过。

### 2.1 模运算与同余

**它是干嘛的**：模运算就是"只留余数"。时钟 13 点就是 1 点（mod 12）；RSA 的加解密全程在"除以 n 取余"的世界里进行。`a ≡ b (mod n)` 读作"a 和 b 除以 n 余数相同"，叫同余。

```python
17 % 12                    # 5
-3 % 12                    # 9（Python 的 % 对正模永远返回非负，C 是往 0 取整，别搞混）
pow(17, 8, 21)             # 16 —— 三参数 pow：边乘边取模
17**8                      # 6975757441 —— 先算完再取模，大数时代这就是内存刺客
```

==带模幂一律写 `pow(a, b, n)`==。RSA 的指数是几百位的大数，`a**b` 会算出一个天文数字再取模，`pow` 的三参数版是快速幂（平方-乘法），快几个数量级还不爆内存。

### 2.2 GCD 与扩展欧几里得

**它是干嘛的**：gcd 求最大公约数；扩展版（exgcd）顺手把贝祖系数 x、y 一起求出来：$a \cdot x + b \cdot y = \gcd(a, b)$。==有了 exgcd，就有了模逆元==——"除以 a"在模世界里的替身 $a^{-1}$，即 $a \cdot a^{-1} \equiv 1 \pmod m$。RSA 求 d、共模攻击合并指数、CRT 组合解，全靠它。

```python
def exgcd(a, b):
    """返回 (g, x, y)：a*x + b*y = g = gcd(a, b)"""
    if b == 0:
        return a, 1, 0
    g, x, y = exgcd(b, a % b)
    return g, y, x - (a // b) * y

def modinv(a, m):
    g, x, _ = exgcd(a % m, m)
    if g != 1:
        raise ValueError("逆元不存在：gcd(a, m) != 1")
    return x % m
```

实测：

```
exgcd(240, 46) = (g=2, x=-9, y=47)，验算 240*(-9) + 46*47 = 2
modinv(3, 11) = 4 ，验算 3*inv % 11 = 1
modinv(7, 26) = 15 ，验算 7*inv % 26 = 1
modinv(6, 26)：gcd(6, 26) = 2 → 逆元不存在
```

注意最后一行：==逆元存在当且仅当 gcd(a, m) = 1==。这个"不存在"后面会变成武器——`pow(c, -1, n)` 报错说明 c 和 n 有公因子，而 n = p·q，公因子不是 1 就是 p 或 q 本身，等于直接把 n 分解了。

### 2.3 费马小定理与欧拉定理

**它是干嘛的**：两条"指数归一"的定理。费马小定理：p 是素数时，$a^{p-1} \equiv 1 \pmod p$。欧拉定理是它的推广：$a^{\varphi(n)} \equiv 1 \pmod n$（a、n 互素），其中欧拉函数 $\varphi(n)$ 数的是 1..n 里与 n 互素的个数，n 为两素数之积时 $\varphi(n) = (p-1)(q-1)$。

```python
pow(2, 10, 11)             # 1 —— p=11 素数，费马小定理
def phi(n):                # 欧拉函数（试除分解版）
    result, m, p = n, n, 2
    while p * p <= m:
        if m % p == 0:
            while m % p == 0: m //= p
            result -= result // p
        p += 1
    if m > 1: result -= result // m
    return result

phi(12)                    # 4 —— 与 12 互素的是 1,5,7,11
pow(5, 4, 12)              # 1 —— 欧拉定理
phi(3233)                  # 3120 —— 3233 = 61*53，(61-1)*(53-1) = 3120
```

RSA 的剧本一句话剧透：加密指数 e 和解密指数 d 满足 $e \cdot d \equiv 1 \pmod{\varphi(n)}$，于是 $m^{ed} = m^{1 + k\varphi(n)} = m \cdot (m^{\varphi(n)})^k \equiv m \pmod n$——==欧拉定理就是"解密为什么能还原明文"的全部数学==。而算 $\varphi(n)$ 必须先分解 n，攻击者没有 p、q 就卡死在这一步，这就是 RSA 安全性的来源。

### 2.4 中国剩余定理

**它是干嘛的**：一堆"除以不同模数的余数"条件，能唯一拼出一个 x（模数两两互质时）。CTF 里两大用处：① 把大模数拆成小模数分别算（sage 的 `crt` 就是它）；② 部分泄露攻击（拿到 d mod (p-1) 之类的碎片）拼回完整密钥。

```python
def crt(remainders, moduli):
    N = 1
    for m in moduli: N *= m
    x = 0
    for r, m in zip(remainders, moduli):
        Ni = N // m
        x += r * Ni * modinv(Ni, m)
    return x % N

crt([2, 3, 2], [3, 5, 7])   # 23
```

经典例题实跑：x≡2 (mod 3)、x≡3 (mod 5)、x≡2 (mod 7)，解出 x = 23，验算 [23%3, 23%5, 23%7] = [2, 3, 2]，且 23 < 3×5×7 = 105（解在 M 以内唯一）。

> [!warning] 模数互质是前提
> 上面这版要求模数两两互质，不互质时 `modinv` 直接炸。处理办法见 [[#7. 常见问题|常见问题]]。

## 3. 对称密码：XOR 与分组模式

### 3.1 XOR 与一次一密

对称密码＝加密解密用同一把钥匙。XOR 是其中最简也最极端的一种：

$$c = m \oplus k, \quad m = c \oplus k, \quad (m \oplus k) \oplus k = m$$

XOR 的三件套性质：自反（XOR 自己等于消掉）、交换、结合。逐字节异或的 Python 三行版：

```python
def xor(a, b):
    return bytes(x ^ y for x, y in zip(a, b))
```

密钥与明文等长、真随机、**只用一次**的 XOR 叫**一次一密（OTP）**，是密码学里唯一被数学证明绝对安全的方案——任意明文对应任意密文的概率相同，密文不携带任何信息。三个前提缺一不可，而==现实里的翻车几乎全发生在"只用一次"上==。

### 3.2 密钥重用即死刑

同一个垫子加密两段消息，看看死得多快：

```python
key = os.urandom(len(flag))     # 真随机，没问题
c1 = xor(flag, key)
c2 = xor(msg2, key)             # 事故：垫子用了第二次
```

由 XOR 自反性，$c_1 \oplus c_2 = (m_1 \oplus k) \oplus (m_2 \oplus k) = m_1 \oplus m_2$——==密钥被当场消掉，剩两段明文的裸 XOR==。实测（两行输出逐字节相等）：

```
m1 ^ m2 = b'\x0b\t\x04\x13[\x19\x12\x10>\x00\x11\x19\r:P[\x08;\x11\x11-\r\x01\x06\x01'
c1 ^ c2 = b'\x0b\t\x04\x13[\x19\x12\x10>\x00\x11\x19\r:P[\x08;\x11\x11-\r\x01\x06\x01'
```

这坨东西怎么变回明文？**crib dragging**：猜一段明文，蹭出密钥，再用密钥去蹭另一段。CTF 选手手里的"常识 crib"很多：`flag{`、`the `、空格、JSON 字段名。实测三步还原：

```
猜 m1[:5] = b'flag{' → key[:5] = 4d22be3bfc → m2[:5] = b'meet '
猜 m2[:15] = b'meet me at the ' → m1[:15] = b'flag{tw0_t1me_p'
猜 m1[:20] = b'flag{tw0_t1me_p4d_' → m2[:20] = b'meet me at the old'
```

滚雪球：key 破几字节 → m2 现形几字节 → m2 的可读文本又当新 crib → 反哺 m1。两段密文加一点英语语感，两段明文一起塌。多段密文公用一个 key 的题（statistical crack 同理）只是体力放大版。

### 3.3 分组密码与 ECB 的企鹅图

XOR 一次只能处理"密钥等长的流"，工程上更常用**分组密码**（AES、DES）：固定块大小（AES 128 位）、带密钥的可逆变换。但分组密码一次只加一块，**长消息怎么切、块与块之间怎么串联**是另一层问题——这就是**工作模式**。模式选错，密码再强也白搭。

最反面教材是 **ECB**（每块独立加密）：==相同的明文分组永远变出相同的密文分组==。图像每个像素点恰好按块重复时，轮廓直接透出来——经典演示就是 ECB 加密后的 Linux 企鹅图：算法一无所知，企鹅清晰可见。用本章手搓的 8 字节 Feistel 复现这个模式泄漏：

```python
pt  = b"AAAAAAAABBBBBBBBAAAAAAAABBBBBBBB"
ecb = b"".join(E(pt[i:i+8]) for i in range(0, len(pt), 8))
cbc = cbc_encrypt(pt, os.urandom(8))      # CBC：每块先与前块密文 XOR 再加密
```

```
ECB 密文  : 9ce572518bfe67cf499bed46d0eeb0669ce572518bfe67cf499bed46d0eeb066
CBC 密文  : aef676ee0a86ae74372bedde93e573fad6b1a8156345cdb928b3c140cff3dd1f
ECB 里相同的明文分组得到相同的密文分组： True
```

ECB 密文里 `9ce5...b066` 原样出现两遍，结构性重复全数奉还；CBC 里前块密文掺进后块加密，重复消失了。看到 CTF 题用 ECB + 可猜测结构（图片、JSON、固定模板），等于题目自带透视图。

### 3.4 CBC 字节翻转

CBC 解密规则是理解攻击的全部：$P_i = D(C_i) \oplus C_{i-1}$（第一块用 IV）。手搓版：

```python
def cbc_encrypt(pt, iv):
    prev, out = iv, b""
    for i in range(0, len(pt), BLOCK):
        c = E(xor(pt[i:i+BLOCK], prev))   # E 是任意分组密码，本章用 4 轮 Feistel
        out += c; prev = c
    return out

def cbc_decrypt(ct, iv):
    prev, out = iv, b""
    for i in range(0, len(ct), BLOCK):
        out += xor(D(ct[i:i+BLOCK]), prev)
        prev = ct[i:i+BLOCK]
    return out
```

盯着解密公式看：$P_2$ 依赖 $D(C_2)$ 和 $C_1$。==D(C_2) 我改不动（没钥匙），但 C_1 是密文，就在我手里==——把 $C_1$ 的某字节 XOR 上一个差值，$P_2$ 的同一字节就跟着翻转。这就是 **CBC 字节翻转攻击**：不用密钥，直接改密文来改解密结果。

实测：明文 `NAME=Bob;ADMIN=0;hello!!` 分 3 块，目标是把第 2 块的 `0` 改成 `1`。`'0'^'1' = 0x01`，翻转 `C1[7] ^= 0x01`：

```
翻转 C1[7] ^= 0x01
篡改后解密  : b'\x9e\xeb\xde\x87\xb8\xca\x1b\x0f;ADMIN=1;hello!!'
第 2 组变成 : b';ADMIN=1'
第 3 组完好 : b';hello!!'
```

`0` 如愿变 `1`，第 3 块完好无损。代价看得见：$C_1$ 同时是第 1 块解密的输入，所以第 1 块解密成了垃圾（`\x9e\xeb...`）。==攻击成立的前提是服务端校验第 2 块、而不在乎第 1 块烂没烂==——很多题真就这样，前块烂掉被视为"正常乱码"放过去了。

## 4. 哈希

### 4.1 三条性质

哈希把任意长度输入压成定长摘要，且不可逆。三条性质，每条对应一类攻击面：

| 性质 | 含义 | 被打破时 |
| ---- | ---- | -------- |
| 定长输出 | 不管输入多大，输出固定（SHA-256 恒 256 位） | ——这是设计而非攻击面，但意味着==信息必然有损压缩，碰撞在数学上必然存在== |
| 单向性 | 拿摘要反推原输入不可行 | 弱口令 → 查表/爆破（见 4.4） |
| 雪崩效应 | 输入差 1 位，输出面目全非 | 相关输出 → 暴露结构弱点 |

雪崩效应实测（`flag{yes}` 与 `flag{yeT}`，一字之差）：

```
sha256('flag{yes}') = e1546ebd2156d1c5 ...
sha256('flag{yeT}') = 3aeba76263432180 ...
256 位里有 129 位翻转（理想值 128）
```

### 4.2 MD5 / SHA 家族速览

| 算法 | 输出 | 现状 | CTF 存在感 |
| ---- | ---- | ---- | ---------- |
| MD5 | 128 位 | 已破（可构造碰撞） | 弱口令爆破、碰撞题、0e 魔术哈希 |
| SHA-1 | 160 位 | 已破（shattered.io 实际碰撞） | 同上，出场率走低 |
| SHA-256 | 256 位 | 安全 | 长度扩展、签名、PoW |

Python 里全是 `hashlib` 一行的事：`hashlib.md5(b"flag").hexdigest()`。出题人 love MD5 不是因为它安全，是因为它快——==爆破一亿次也就几分钟==，这对出题人和攻击者都是好事。

### 4.3 长度扩展攻击（实测）

MD5 和 SHA 系列都是 **Merkle-Damgård 结构**：把消息切块，拿一个压缩函数从初始状态滚雪球滚到最后，==最终摘要就是滚完的中间状态==。这个实现细节捅出一个大篓子：

$$\text{SHA256}(m \| \text{padding}) \text{ 的中间状态，可以当成"已处理 } m \| \text{padding} \text{ 字节"继续滚}$$

也就是说：**知道 `SHA256(secret ‖ msg)` 和 `len(secret ‖ msg)`（不需要知道 secret 本身），就能伪造 `SHA256(secret ‖ msg ‖ glue ‖ suffix)` 的正确摘要**——glue 是把 `secret‖msg` 补齐到块边界的标准填充，长度已知就能算。签名形如 `SHA256(secret ‖ 参数)` 的老接口（"已知 secret 才能签名"）当场失守：攻击者在参数后面续一个 `&admin=1`，签名照样合法。

手工实现一遍 SHA-256（60 行，压缩函数本体 + 64 个轮常数这里省略，照 RFC 6234 抄即可），关键在三个函数：

```python
def pad(msg_len):
    """Merkle-Damgard 填充：0x80 + 补零 + 8 字节位长"""
    return b"\x80" + b"\x00" * ((55 - msg_len) % 64) + struct.pack(">Q", msg_len * 8)

def state_after(prefix):
    """吃掉 prefix 的所有完整分组但不做收尾填充——返回中间状态"""
    state = IV[:]
    for i in range(0, len(prefix), 64):
        state = compress(state, prefix[i:i+64])
    return state

def sha256_continue(state, total_len, suffix):
    """从中间状态 + 已处理字节数续算后缀"""
    data = suffix + pad(total_len + len(suffix))
    for i in range(0, len(data), 64):
        state = compress(state, data[i:i+64])
    return "".join(f"{x:08x}" for x in state)
```

先对拍（手写版和官方库完全一致，`ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad`），再攻击：secret = `k3y=Sup3rS3cret`，`SHA256(secret‖"&file=report.pdf")` 是唯一已知签名，目标是伪造 `&admin=1` 的合法签名：

```
len(secret+msg) = 31，glue = 33 字节（对齐到 64 的倍数）
猜 len(secret) = 15：伪造签名 = 1fb719996bd41c031cdbc982257bff9bbc6fb94118a3c8689f03f04f7b0d0817
服务器真签名          = 1fb719996bd41c031cdbc982257bff9bbc6fb94118a3c8689f03f04f7b0d0817
伪造成功              = True
```

secret 从头到尾没被知道，签名照样伪造——==这就是"自己拿哈希拼签名协议"的下场==。正统解法叫 HMAC，内部双轮哈希专门堵这个洞，`hmac` 标准库直接给。CTF 里见到"签名 = md5(secret+data)"的题，直接上 hash_extender 类工具。

### 4.4 CTF 哈希题套路

- **爆破弱口令哈希**：拿到 md5(口令)，拿字典跑。实测：靶子 `0192023a7bbd73250516f069df18b500`，词表七个词，秒出 `admin123`。线上先查 CMD5 / Hashes.com 这类彩虹表站，查不中再本地爆。
- **0e 魔术哈希**：PHP/JS 弱比较 `==` 把 `0e...` 当科学计数法，两个"0 的任意次方"恒相等。实测两个经典值：`md5("240610708") = 0e462097431906509019562988736854`，`md5("QNKCDZO") = 0e830400451993494058024219903391`——提交后者冒充前者，`==` 判真。遇到"传两个不同值使 md5 相等"的 PHP 题，先想 0e。
- **strcmp / 数组绕过**：`strcmp($_GET['a'], $key) == 0` 传数组进去返回 NULL，`NULL == 0` 弱比较为真——不是哈希的锅，是弱比较的锅，但总跟 md5 题绑着出场。

## 5. RSA：大数分解的生意

### 5.1 把第 2 节拼成 RSA

五个字母各就各位：

| 符号                | 是什么            | 谁知道        |
| ----------------- | -------------- | ---------- |
| p、q               | 两个大素数          | 只有持有者      |
| n = p·q           | 模数，公开          | 所有人        |
| φ(n) = (p-1)(q-1) | 欧拉函数           | 需要 p、q 才能算 |
| e                 | 加密指数（常为 65537） | 所有人        |
| d = e⁻¹ mod φ(n)  | 解密指数           | 只有持有者      |

加解密一对公式（说明：c 是密文，m 是明文整数，要求 0 ≤ m < n）：

$$c \equiv m^e \pmod n \qquad m \equiv c^d \pmod n$$

为什么 d 能解回去：e·d ≡ 1 (mod φ(n))，由 2.3 的欧拉定理，$m^{ed} = m^{1+k\varphi(n)} \equiv m \pmod n$。==RSA 的安全性 = 从 n 反推 p、q 是大数分解问题==——n 公开，φ(n) 就差一层窗户纸，可这层纸 4096 位的时候全人类一起撞也撞不破。==CTF 的 RSA 题全是在窗户纸上找别人捅过的洞==。

### 5.2 手写加解密

除了素数生成用 Miller-Rabin（十几行，这里省略），核心就这几行：

```python
p, q = gen_prime(18), gen_prime(18)      # 教学用 18 位；真实 RSA 是 2048 位
n, phi = p * q, (p - 1) * (q - 1)
e = 65537
assert gcd(e, phi) == 1                  # 不互素则 d 不存在
d = modinv(e, phi)                       # 2.2 的 exgcd 在这里兑现

m = int.from_bytes(b"flag", "big")
c = pow(m, e, n)
m2 = pow(c, d, n)
```

实测输出：

```
p = 131731, q = 224563
n = p*q = 29581908553, phi = (p-1)(q-1) = 29581552260
e = 65537, d = e^-1 mod phi = 26887314113
验算 e*d mod phi = 1
m = 1718378855 ('flag'), c = m^e mod n = 19080469033
解密 c^d mod n = 1718378855 -> b'flag'
```

> [!warning] 明文必须小于 n
> 我第一次跑就把素数选成了 16 位：n = 1560661937，而 `b"flag"` = 1718378855，明文比模数还大，解出来是 `b'\tf\x91\xb6'`。==写 RSA 脚本先检查 `m < n`==，长消息按块切或用混合加密。

### 5.3 弱点套路清单

拿到 RSA 题，按这张清单过一遍参数。==先看 n 和 e，再决定动哪把刀==：

| 特征 | 攻击 | 实测 |
| ---- | ---- | ---- |
| e=3 且 m³ < n | 密文就是 m³ 本身，整数开立方直接还原 | ✅ 下文 |
| 同一 n 配两把互素的 e（共模） | exgcd 合并指数消掉 m | ✅ 下文 |
| 泄露 p+q | 解 x² −(p+q)x + n = 0 拿到 p、q（求根公式 + 整数开方） | 思路题 |
| 泄露 dp 或 dq | 费马小定理 + gcd 挖出 p | ✅ 下文 |
| n 小或碰巧被分解过 | factordb 在线查 / yafu 本地分解，拿 p、q 走标准解密 | 工具活 |
| d 太小（< n^0.25/3） | Wiener 攻击：连分数展开 e/n 恢复 d，RsaCtfTool 一键跑 | 工具活 |

**e=3 小明文攻击**：e=3 时若明文够小，$m^3 < n$，取模等于没取，密文裸奔：

```
n = 633837748601782266108283（约 80 位）, e = 3
m = 6517862 (b'ctf'), m^3 = 276895235694247747928
c = m^3 mod n = 276895235694247747928, 且 m^3 < n → c 就是 m^3 本身: True
整数开三次方 → 6517862 -> b'ctf'
```

开方用整数二分（`iroot`），==永远别写 `c ** (1/3)`==——浮点 53 位精度，大数当场溢出。真实 2048 位 n 下"m³ 略大于 n"的残余情况要用 Coppersmith（格密码），交给 RsaCtfTool。

**共模攻击**：同一 n 发了两把指数 e₁、e₂（互素），两段密文对同一明文。找 $a e_1 + b e_2 = 1$（exgcd），则：

$$m \equiv c_1^{a} \cdot c_2^{b} \pmod n$$

推导一句话：$m^{ae_1 + be_2} = m^1$，a 是负数就取逆元。实测：

```
n = 516421364377314255216947, e1 = 7, e2 = 11
exgcd(e1, e2) = (1, -3, 2)，验算 7*(-3) + 11*2 = 1
c1 = m^7 mod n = 473947693260409006033266
c2 = m^11 mod n = 244105824166024126545097
恢复 m = c1^-3 * c2^2 mod n = 126879297332596 -> b'secret'
```

攻击代码一共两行：

```python
g, a, b = exgcd(e1, e2)                  # a*e1 + b*e2 = 1
m = pow(c1, a, n) * pow(c2, b, n) % n    # 负指数 pow 自动取逆元（Python 3.8+）
```

**dp 泄露**：dp = d mod (p−1) 单独泄露就能全盘崩盘。由费马小定理 $c^{dp} \equiv m^{edp \bmod (p-1)} \equiv m \pmod p$，于是 $x = c^{dp} \bmod n$ 和真实明文"模 p 同余"——但模 q 毫无关系，两者作差的公因子就是 p：

```
n = 9930590758824974131, e = 65537, dp = 729159197
gcd(pow(pow(c,dp,n),e,n) - c, n) = 2513909533  （就是 p）
q = n // p = 3950257807, d 重算成功, m = b'leak'
```

三行核心：

```python
x = pow(c, dp, n)                    # x ≡ m (mod p)
p = gcd(pow(x, e, n) - c, n)         # mod p 成立、mod q 不成立 → gcd 挖出 p
d = modinv(e, (p - 1) * (n // p - 1))
```

## 6. 随机数一瞥

密码学要的是**密码学安全随机数**（`os.urandom`、`secrets`），Python 默认的 `random` 是梅森旋转——**可预测**。预测的前提是知道种子，而种子的选择常是事故现场：

- **固定种子**：`random.seed(1337)` 写死在代码里（方便调试忘了删），每次运行产出同一串"随机数"。实测：

```
seed=1337 第一次: bb54aac4b89dc868ba37d9cc21b2cece
seed=1337 第二次: bb54aac4b89dc868ba37d9cc21b2cece
两次完全一样: True
```

- **time 当种子**：`random.seed(int(time.time()))`——种子空间是秒级时间戳，==每秒一个候选，往前往后扫两分钟也就 240 次尝试==。实测服务端用当前秒当种子异或加密 flag，攻击端窗口爆破：

```
服务端 seed = 1792327283
token = 0525c5cd74699d7204f83019633136903d4daa622e2b1fb2
命中 seed = 1792327283（相对服务端 seed 偏移 +0 秒）
还原明文 = flag{5eed_1s_n0t_rand0m}
```

题目若给"某时刻的加密输出"，就按输出里能对上的特征（flag 前缀、可读性、校验和）扫种子窗口；种子一锁定，之后的"随机"串全部可复现。==出题人把"随机"建立在可猜的种子上，等于把保险柜密码贴在柜门内侧==。CTF 进阶还有梅森旋转状态恢复（624 个输出反推内部状态），那是后话。

## 7. 常见问题

| 现象                               | 原因与解决                                                                                           |
| -------------------------------- | ----------------------------------------------------------------------------------------------- |
| gmpy2 装不上                        | pip 源码编译需要编译链，Windows 下十装九翻。WSL 里 `sudo apt install python3-gmpy2`；装不上就用 sympy 或纯手写——本章全部实跑就没用它 |
| RSA 开方得到浮点或报错                    | `c ** (1/3)` 是浮点运算，大数丢精度。用整数二分 `iroot`（本章实测版）或 `gmpy2.iroot(c, 3)`                              |
| `pow(c, -1, n)` 报 not invertible | c 与 n 不互素。别急着绕——gcd(c, n) 不是 1 就是 n 的因子，==报错本身就是分解结果==                                          |
| e 与 φ(n) 不互素，d 求不出               | d 不存在，出题人故意的（如 e=3 而 φ 含 3）。思路：对 m 加随机数（裸指数运算）或拆开分别处理，进阶题套路                                     |
| CRT 报逆元不存在                       | 模数不两两互质。用扩展 CRT 逐条合并同余式（两两合并版），或先约去公因子                                                          |
| factordb 查不到 n                   | n 太大或还没人分解过。试 yafu；查到一半的记录（部分因子）也能白嫖                                                            |
| 长度扩展工具跑出错误签名                     | secret 长度没猜对，把候选长度全部遍历；glue 填充必须按"前缀总长"算，不是按已知名部分算                                              |
| flag 解出来是乱码但像那么回事                | 先查 `m < n`（见 [[#5.2 手写加解密（实测）\|5.2]] 的翻车实录），再查字节序和 `long_to_bytes` 的位数对齐                        |
| sympy 解 RSA 巨慢                   | `sympy` 的分解是教学级，几十位以上直接 factordb/yafu；解密只算 `pow(c, d, n)`，毫秒级                                   |
