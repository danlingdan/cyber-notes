## 1. 本章范围与编译基线

[[04-汇编语言精要|通用基础 04 章]]从 C 出发，看编译器把每行代码翻译成什么。逆向的读法相反：汇编已经摆在面前，C 要靠反推。本章把读懂反汇编要用的四块基础——寄存器、指令、条件跳转、寻址——集中过一遍，再用四种代码形状把它们串起来。需要更完整的背景时回翻 04 章；C 层面对应的概念 [[R02-C语言与内存模型回顾|R02]] 已覆盖，这里不再重讲。

> [!warning] 先确认平台、位数与约定，再开始读
> 本章全部示例都是 **x86-64 Linux / System V AMD64 ABI**。Windows x64 前四个参数走 `RCX, RDX, R8, R9`，调用前还要预留 32 字节 shadow space；32 位程序参数全走栈。==拿到题先 `file` 一把确认位数和平台，再按对应约定读==。三种约定的认法 [[R02-C语言与内存模型回顾#9. 三种调用约定的认法|R02 第 9 节]]整理过。

编译基线全书统一，R02 用过一遍：

```bash
gcc -O0 -fno-pie -no-pie xxx.c -o xxx                    # 成品，给 objdump 拆
gcc -O0 -masm=intel -fno-pie -fno-asynchronous-unwind-tables -S xxx.c -o xxx.s   # 编译器视角的纯汇编
```

`-O0` 让每行 C 对应一组直白的汇编，源码与产物逐行好对照；`-fno-pie -no-pie` 把程序固定加载在 0x400000 附近，代码段落在 0x401000 一带、全局数据在 0x404000 附近，反汇编里的地址因此稳定可引用。栈地址每次运行都不同，那是 ASLR 的效果。真实赛题通常开 PIE，全局访问改走 rip 相对寻址（[[#5. 寻址方式|第 5 节]]末的折叠框），先把固定地址的读法练熟。

本章汇编一律 **Intel 语法**。objdump 默认输出 AT&T 语法，两套写法的对照见 [[#6. AT&T 与 Intel 语法|第 6 节]]。

## 2. 寄存器：名字、分工与保存责任

### 2.1 通用寄存器与子寄存器

x86-64 有 16 个 64 位通用寄存器，每个都能拆出低 32 位、16 位、8 位来用，拆出的部分各有名字。"常规用途"一列是 System V AMD64 ABI 的约定，反汇编按这个表对号入座：

| 64 位 | 32 位 | 16 位 | 8 位 | 常规用途（System V） |
| --- | --- | --- | --- | --- |
| rax | eax | ax | al | 返回值；乘除法的隐式操作数 |
| rbx | ebx | bx | bl | 通用；callee-saved，被调方保存 |
| rcx | ecx | cx | cl | 第 4 参数；变位移动指令的位数只能放 cl（`shl eax,cl`） |
| rdx | edx | dx | dl | 第 3 参数；乘除法的高半 / 除法余数 |
| rsi | esi | si | sil | 第 2 参数；串操作源地址 |
| rdi | edi | di | dil | 第 1 参数；串操作目的地址 |
| rbp | ebp | bp | bpl | 帧指针（见 2.2） |
| rsp | esp | sp | spl | 栈指针（见 2.2） |
| r8–r15 | r8d–r15d | r8w–r15w | r8b–r15b | r8、r9 是第 5、6 参数；r12–r15 callee-saved |

命名规律：前 8 个沿用历史名（`rax`→`eax`→`ax`→`al`）；后 8 个用 `d`/`w`/`b` 后缀（`r8d`/`r8w`/`r8b`）。

> [!warning] 写子寄存器对高位的影响
> 写 32 位子寄存器（如 `mov eax,5`）会把该寄存器高 32 位**清零**，rax 变成 `0x0000000000000005`；写 16 位或 8 位子寄存器（`mov ax,...`、`mov al,...`）则其余位**保持不变**。跟踪 64 位值时记住这条，否则会把对 eax 的写入误读成整个 rax 被赋值。

> [!info]- 更细的老名字：ah
> `ax` 的低 8 位是 `al`，高 8 位是 `ah`；`bh`/`ch`/`dh` 同理。手写汇编里能见到，编译器产物中很少。

### 2.2 rsp 与 rbp：栈的两个指针

栈从高地址向低地址生长（内存四区见 [[R02-C语言与内存模型回顾#2. 内存四区：先对完地址再谈别的|R02 第 2 节]]）。`rsp` 永远指向栈顶，即最后压入的那份数据；`rbp` 在函数序言里被定住，作为本帧所有偏移的基准：

```asm
; -O0 典型栈帧布局（以 rbp 为基准，示意）· x86-64 Linux
;   rbp+0x10   第 7 个起的栈参数
;   rbp+0x08   返回地址（call 压入）
;   rbp+0x00   上一层的 rbp（序言 push rbp 存进来）
;   rbp-0x04   局部变量栈槽，向低地址排开
;   rbp-0x20   sub rsp,0x20 划出的局部区下界
;   rsp        当前栈顶
```

三类偏移的固定含义（-O0、有帧指针的函数）：负偏移是局部变量；`rbp+0x8` 是返回地址；`rbp+0x10` 起是栈参数。7.1 的序言尾声就是围绕这张图工作的。

> [!info]- 没有帧指针的函数
> 开优化后，编译器常省略 rbp（帧指针省略），所有偏移改相对 rsp 计算，且编译期就定死。读 -O2 产物时看不到 `mov rbp,rsp`，偏移基准换成 rsp。

### 2.3 caller-saved 与 callee-saved

一个函数 call 另一个函数时，通用寄存器里的旧值还算不算数，System V 把 16 个寄存器分成两类：

| 类别 | 寄存器 | 约定 |
| --- | --- | --- |
| caller-saved（调用者保存，易失） | rax、rcx、rdx、rsi、rdi、r8–r11 | call 返回后内容不可信；调用者还要用就得在 call 前存起来 |
| callee-saved（被调者保存，受保） | rbx、rbp、r12–r15（rsp 亦然） | 被调函数想用必须先 push 存底、返回前 pop 还原；值跨 call 可靠 |

rax 特殊：它是返回值，每次 call 后必然被改写。落到反汇编上有两条直接推论：

- 函数序言出现 `push rbx` 或 `push r12`–`push r15`，说明函数要跨调用保存值，被保存的就是 callee-saved 寄存器；
- 跟踪一个跨过 call 的值，先看它当时在不在 callee-saved 里；在 caller-saved 里，call 之后它已经是别的数据。

04 章把这组约定叫"保存责任"，完整表见 [[04-汇编语言精要#3. 寄存器全家桶：约定与保存责任|04 章寄存器全家桶]]。

### 2.4 标志寄存器 rflags

通用寄存器之外还有一组标志位，打包在 rflags 里。多数算术与位运算指令写结果的同时按结果设置标志；`cmp`、`test` 只设置标志、不写结果；jcc 读标志决定跳不跳。逆向主要盯四个：

| 标志 | 含义 | 置位条件 | 谁在读 |
| --- | --- | --- | --- |
| CF | 进位/借位 | 加法最高位向上进位，或减法最高位借位（==无符号==溢出） | 无符号比较 ja/jb 一族；adc/sbb |
| ZF | 零标志 | 结果为 0 | je/jne 及一切"相等"判断 |
| SF | 符号标志 | 结果最高位为 1（按有符号解释是负数） | js/jns；与 OF 配合的有符号比较 |
| OF | 溢出标志 | 有符号运算结果溢出 | jo/jno；与 SF 配合的有符号比较 |

哪类判断看哪几个标志：

- 判等：只看 ZF（cmp/test 之后 je/jne）；
- 无符号比大小：看 CF，配合 ZF；
- 有符号比大小：看 SF 与 OF，配合 ZF；
- 结果是否为 0：看 ZF（循环里 dec/jne 的搭配就这么工作）。

> [!info]- 其余标志位
> PF（结果低 8 位中 1 的个数为偶）、AF、DF（串操作方向）等在编译器产物里极少出现，遇到再查手册。

具体标志组合怎么落到各条 jcc，[[#4. 条件跳转：jcc 家族|第 4 节]]给全家族对照表。

## 3. 高频指令

以下按用途分组。除标注"语义示意"的块外，所有汇编块都是 `objdump -d -M intel` 的输出；各函数的 `endbr64; push rbp; mov rbp,rsp` 序言相同，重复的例子里截去并注明。

### 3.1 mov 与扩展搬运

`mov 目的,源`：把源复制进目的，==不设标志位==。基本流向四种：立即数→寄存器、寄存器→寄存器、内存→寄存器、寄存器→内存；没有内存到内存。

```asm
; 语义示意 · x86-64 Linux · Intel 语法
mov  eax, 5                     ; 立即数 → 寄存器
mov  ebx, eax                   ; 寄存器 → 寄存器
mov  eax, DWORD PTR [rbp-0x8]   ; 内存 → 寄存器
mov  DWORD PTR [rbp-0x4], 7     ; 立即数 → 内存：内存操作数必须标宽度
```

宽度词：`BYTE PTR` 1 字节、`WORD PTR` 2 字节、`DWORD PTR` 4 字节、`QWORD PTR` 8 字节。只要有一边是内存，宽度就必须写明——CPU 靠它确定搬几个字节。

窄类型升宽的搬运另有一对指令，反汇编里直接对应 C 的整型转换（[[R02-C语言与内存模型回顾#8. 整型溢出在反汇编里留下的痕迹|R02 第 8 节]]）：

| 指令 | 行为 | 对应场景 |
| --- | --- | --- |
| movzx dst,src | 零扩展搬运，高位补 0 | unsigned 窄类型 → 宽类型 |
| movsx dst,src | 符号扩展搬运，按 src 最高位补 | signed 窄类型 → 宽类型 |
| movsxd dst,src | 32 位 → 64 位专用符号扩展 | int → long |

### 3.2 lea：算地址的指令

`lea` 与 `mov` 一字之差，差别在方括号：==mov 带方括号是"把内存里的内容搬进来"，要访存；lea 带方括号是"把方括号算出来的地址这个数放进寄存器"，不访存、也不改标志位==。

原生用途是取地址：`lea rax,[rbp-0x10]` 就是 C 的 `&local`，把局部变量的地址交给别人。

方括号里的基址、变址、比例、位移四件套全都能利用，所以 lea 也是编译器做算术的常用工具，一条指令同时完成乘和加。gcc 15 在 -O0 下翻译 `a + b * 2 + 10` 的产物（序言省略）：

```asm
; x86-64 Linux · System V AMD64 ABI · Intel 语法（objdump -d -M intel 输出，序言省略）
  401124:  89 7d fc          mov    DWORD PTR [rbp-0x4],edi
  401127:  89 75 f8          mov    DWORD PTR [rbp-0x8],esi
  40112a:  8b 45 f8          mov    eax,DWORD PTR [rbp-0x8]
  40112d:  8d 14 00          lea    edx,[rax+rax*1]          ; edx = b*2：是算术，不是取地址
  401130:  8b 45 fc          mov    eax,DWORD PTR [rbp-0x4]
  401133:  01 d0             add    eax,edx
  401135:  83 c0 0a          add    eax,0xa
```

判读方法一条：==看 lea 的结果随后被当什么用==。当普通数参与加减比较，它就是算术；被存进内存或传给别人当指针，它才是取地址。[[#7.4 形状四：数组访问|7.4]] 里乘元素宽的 `lea rdx,[rax+rax*1]` 与这里是同一个形状。

> [!info]- 同一类乘法，gcc 的写法不止一种
> 同样在 -O0，乘 3 与乘 2 的幂 gcc 15 选了别的排法（序言与取参数省略）：
>
> ```asm
> ; x86-64 Linux · Intel 语法（objdump -d -M intel 输出）
> ; x*3:
>   401114:  89 d0             mov    eax,edx
>   401116:  01 c0             add    eax,eax
>   401118:  01 d0             add    eax,edx        ; x*2 + x，两条加法
> ; x*4+8（先算 x+2，再整体 ×4）:
>   401148:  83 c0 02          add    eax,0x2
>   40114b:  c1 e0 02          shl    eax,0x2        ; 左移 2 位 = ×4
> ; x*8-1:
>   40115e:  c1 e0 03          shl    eax,0x3        ; 左移 3 位 = ×8
>   401161:  83 e8 01          sub    eax,0x1
> ```
>
> 乘 2 的幂常写成移位（shl），乘小常数可能拆成加法。具体形状随编译器版本浮动，认"地址公式被当算术用"这个模式即可。

### 3.3 push 与 pop

两条指令各自只动 rsp 与栈顶：

```asm
; 语义示意 · x86-64 Linux · Intel 语法
push rax     ; rsp -= 8，然后把 rax 存到 [rsp]（64 位固定压 8 字节；32 位压 4 字节）
pop  rax     ; 先把 [rsp] 读进 rax，再 rsp += 8
```

push/pop 天然成对：序言 `push rbp` 对尾声 `pop rbp`；函数中途 push 过什么，返回前要按相反顺序 pop 干净，否则 ret 弹出来的就不是返回地址。==读汇编时盯 rsp 的净变化==：`sub rsp,0x20` 之后局部区生效，`leave` 或 `add rsp,0x20` 之后收回。32 位程序传参靠连续 push（[[R02-C语言与内存模型回顾#9. 三种调用约定的认法|R02 第 9 节]]的 cdecl 认法）。

### 3.4 call、ret 与 leave

`call 目标`：把返回地址（==call 的下一条指令的地址==）压栈，然后跳到目标。`ret`：从栈顶弹 8 字节进 rip，跳回去。所以进入函数的第一瞬间 `[rsp]` 指向返回地址；序言 `push rbp` 之后它挪到 `rbp+0x8`。`leave` 是"撤销整个帧"的合并写法：等价于 `mov rsp,rbp` 再 `pop rbp`，一条顶两条。

参数与返回值的约定一句带过：前 6 个整型/指针参数依次 rdi、rsi、rdx、rcx、r8、r9，第 7 个起走栈，返回值在 rax（完整表见 [[04-汇编语言精要#7. 函数调用：call / ret / 序言尾声|04 章函数调用]]）。

`call rdx`、`call rax` 这类寄存器调用，目标要运行时才知道，背后是函数指针（[[R02-C语言与内存模型回顾#5. 函数指针、间接调用与那张地址表|R02 第 5 节]]现场改过它）；`call xxx@plt` 是调外部库函数，经 PLT 跳板进 libc（[[R04-可执行文件格式ELF与PE|R04]]讲 PLT）。

> [!info]- 返回值不止 rax 的场合
> 16 字节以内的结构体通常由 rax 与 rdx 一起返回；更大的结构体由调用者腾好内存、把地址占用 rdi 作为隐藏第一参数传入。PWN 里伪造返回值通常只动 rax，处理大结构体的函数要多看一眼 rdx 或隐藏指针。

### 3.5 乘法与除法

这是新手读汇编的第一个断点：==一部分操作数不写在指令里，固定落在 rax 与 rdx==。64 位下六种形式（32 位把 rax→eax、rdx→edx 对应替换）：

| 形式 | 语义 |
| --- | --- |
| mul r/m | 无符号乘：rdx:rax = rax × r/m（128 位全积） |
| imul r/m | 有符号乘，布局同上（单操作数形式） |
| imul reg,r/m | reg = reg × r/m，截断到寄存器宽度（==编译器最常生成==） |
| imul reg,r/m,imm | reg = r/m × imm |
| div r/m | 无符号除：rdx:rax ÷ r/m → 商在 rax，==余数在 rdx== |
| idiv r/m | 有符号除，商/余数位置同上 |

除法前必须把 128 位被除数 rdx:rax 备好——这就是 `cdq`/`cqo` 或清零 edx 出现在每条除法前面的原因：

- ==有符号==：cdq 把 eax 的符号铺满 edx（64 位用 cqo 铺满 rdx）；
- ==无符号==：高半没有符号可铺，直接清零（gcc 15 在 -O0 下生成 `mov edx,0x0`；手写汇编常用等价且更短的 `xor edx,edx`）。

符号扩展六条指令一张表：左列"升宽度"，右列"铺被除数高半"。

| 指令 | 作用 | 指令 | 作用 |
| --- | --- | --- | --- |
| cbw | al → ax | cwd | ax → dx:ax |
| cwde | ax → eax | cdq | eax → edx:eax |
| cdqe | eax → rax | cqo | rax → rdx:rax |

除法与取余的产物（序言与取参数省略）：

```asm
; x86-64 Linux · System V AMD64 ABI · Intel 语法（objdump -d -M intel 输出，序言省略）
; sdiv: return a / b;      （int，有符号）
  401114:  8b 45 fc          mov    eax,DWORD PTR [rbp-0x4]
  401117:  99                cdq                             ; eax 的符号铺满 edx
  401118:  f7 7d f8          idiv   DWORD PTR [rbp-0x8]      ; 商 → eax
; udiv: return a / b;      （unsigned，无符号）
  40112b:  8b 45 fc          mov    eax,DWORD PTR [rbp-0x4]
  40112e:  ba 00 00 00 00    mov    edx,0x0                  ; 高半清零
  401133:  f7 75 f8          div    DWORD PTR [rbp-0x8]
; smod: return a % b;      （int，取余）
  401146:  8b 45 fc          mov    eax,DWORD PTR [rbp-0x4]
  401149:  99                cdq
  40114a:  f7 7d f8          idiv   DWORD PTR [rbp-0x8]
  40114d:  89 d0             mov    eax,edx                  ; 余数从 edx 取
```

C 的乘法语句几乎只翻译成双操作数 imul（序言与取参数省略）：

```asm
; x86-64 Linux · System V AMD64 ABI · Intel 语法（objdump -d -M intel 输出，序言省略）
; mul_pair: return a * b;   （int）
  401114:  8b 45 fc          mov    eax,DWORD PTR [rbp-0x4]
  401117:  0f af 45 f8       imul   eax,DWORD PTR [rbp-0x8]
; mul64: return a * b;     （long long）
  40112d:  48 8b 45 f8       mov    rax,QWORD PTR [rbp-0x8]
  401131:  48 0f af 45 f0    imul   rax,QWORD PTR [rbp-0x10]
```

单操作数 mul/imul 生成 128 位全积，普通 C 乘法用不到（结果反正要截断，双操作数就够）；它们常见于手写汇编与部分库代码，语义按上表读。

> [!info]- 除以 2 的幂：不生成除法指令
> `x / 2` 在 -O0 下不生成 idiv，而是移位序列：
>
> ```asm
> ; x86-64 Linux · Intel 语法（objdump -d -M intel 输出，序言省略）
> ; half: return x / 2;   （int）
>   40115c:  8b 45 fc          mov    eax,DWORD PTR [rbp-0x4]
>   40115f:  89 c2             mov    edx,eax
>   401161:  c1 ea 1f          shr    edx,0x1f     ; edx = 符号位（负数为 1）
>   401164:  01 d0             add    eax,edx      ; 负数先加 1（偏置）
>   401166:  d1 f8             sar    eax,1        ; 算术右移 1 位 = 除以 2
> ```
>
> sar 对负数是向下取整，C 的除法要向零取整，所以负数先加偏置再移位。shl 左移对应乘 2 的幂；shr 是逻辑右移（高位补 0，对应 unsigned）。见到移位算除法，按"x / 2 的幂（负数带偏置）"还原。

> [!info]- 除法崩溃的两种来源
> div/idiv 在两种情况下触发 #DE 异常，Linux 收到 SIGFPE：除数为 0；有符号商超出范围（如 INT_MIN / -1）。逆向里程序死在除法指令上，先查这两样。

### 3.6 neg、not 与 xor 清零

`neg dst`：dst = 0 − dst（取相反数），按结果设标志——结果非 0 时 CF=1，为 0 时 CF=0。`not dst`：按位取反，==不改任何标志==。编译器产物里，二者分别对应 C 的一元 `-x` 与 `~x`：

```asm
; x86-64 Linux · System V AMD64 ABI · Intel 语法（objdump -d -M intel 输出，序言省略）
; neg_demo: return -x;
  401111:  8b 45 fc          mov    eax,DWORD PTR [rbp-0x4]
  401114:  f7 d8             neg    eax
; not_demo: return ~x;
  401123:  8b 45 fc          mov    eax,DWORD PTR [rbp-0x4]
  401126:  f7 d0             not    eax
```

xor 兼职清零：`xor eax,eax` 长 3 字节，`mov eax,0` 长 5 字节，==编译器清零一律用 xor==。函数开头或 ret 前见到 `xor eax,eax`，读作"返回 0"；call 变参函数前见到，是在给变参约定清 AL（7.1 的 printf 调用前，gcc 也可以写成 `mov eax,0x0`，两种都合法）。

### 3.7 and、test 与 cmp：改值与只改标志

and 与 test 算的是同一件事（按位与），区别只在写不写回：`and dst,src` 把结果存进 dst；`test dst,src` 只设标志、不动 dst。同理 sub 写回、cmp 不写回——==cmp a,b 就是"只留标志的 a−b=="，且第一个操作数是被减数，jg/jl 等方向都按这个顺序读。

test 最常见的形状是 `test eax,eax`：数与自己按位与，值不变，只留下"是否为 0"（ZF）与"正负"（SF），判零几乎都这么写。需要保留位测试的中间值时才用 and，比如掩码结果还要参与运算或作为返回值。

gcc 15 在 -O0 下翻译 `if (x & 1u)` 的产物，and 算值、test 设标志、je 收尾，三件各干各的：

```asm
; x86-64 Linux · System V AMD64 ABI · Intel 语法（objdump -d -M intel 输出，序言省略）
; low_bit: if (x & 1u) return 1; return 0;
  40110e:  89 7d fc          mov    DWORD PTR [rbp-0x4],edi
  401111:  8b 45 fc          mov    eax,DWORD PTR [rbp-0x4]
  401114:  83 e0 01          and    eax,0x1                  ; eax = x & 1（写回）
  401117:  85 c0             test   eax,eax                  ; 只设标志
  401119:  74 07             je     401122 <low_bit+0x1c>    ; 为 0 → 走保底分支
  40111b:  b8 01 00 00 00    mov    eax,0x1
  401120:  eb 05             jmp    401127 <low_bit+0x21>
  401122:  b8 00 00 00 00    mov    eax,0x0
```

> [!info]- 不跳转也能取标志：setcc 与 cmovcc
> 把比较结果直接当返回值时，编译器用 setcc 把标志位变成 0/1 字节。`return x == 0;` 的产物：
>
> ```asm
> ; x86-64 Linux · Intel 语法（objdump -d -M intel 输出，序言省略）
>   401134:  83 7d fc 00       cmp    DWORD PTR [rbp-0x4],0x0
>   401138:  0f 94 c0          sete   al        ; ZF=1 则 al=1，否则 al=0
>   40113b:  0f b6 c0          movzx  eax,al    ; 零扩展成 int 返回
> ```
>
> setcc 家族与 jcc 一一对应（sete/setne/setg/seta/…）；cmovcc 则是"标志满足才搬数"的条件传送。见到它们，直接还原成一条 `return 表达式;`。

## 4. 条件跳转：jcc 家族

cmp/test 设好标志后，jcc 读标志、决定走不走。全家族表（语义按 `cmp a,b` 之后，a、b 即指令里从左到右两个操作数）：

| 指令 | 含义 | 何时跳 | 标志条件 |
| --- | --- | --- | --- |
| je | 相等（equal） | a == b | ZF=1 |
| jne | 不等（not equal） | a != b | ZF=0 |
| jg | 大于（greater） | a > b（有符号） | ZF=0 且 SF=OF |
| jge | 大于等于 | a ≥ b（有符号） | SF=OF |
| jl | 小于（less） | a < b（有符号） | SF≠OF |
| jle | 小于等于 | a ≤ b（有符号） | ZF=1 或 SF≠OF |
| ja | 高于（above） | a > b（无符号） | CF=0 且 ZF=0 |
| jae | 高于等于 | a ≥ b（无符号） | CF=0 |
| jb | 低于（below） | a < b（无符号） | CF=1 |
| jbe | 低于等于 | a ≤ b（无符号） | CF=1 或 ZF=1 |

助记规律一眼记住：==g/l 一族比大小、有符号（greater/less）；a/b 一族比大小、无符号（above/below）==；e/n 管相等，两族通用；带 ge/le/jae/jbe 的含等号。反推技巧：==看比较配的跳转族别，就能反推变量有没有符号==——7.2 的 score 配 jle，所以是 int。

jcc 不只跟 cmp：`test eax,eax` 后接 je/jne 是判零的标准搭配；and、sub 这类写回指令留下的标志同样能喂 jcc（3.7 的 low_bit 就是 and 算值、test 设标志）。

> [!info]- 单标志跳转
> js（SF=1，按有符号解释为负）/jns、jc（CF=1）/jnc、jo（OF=1，有符号溢出）/jno 直接盯单个标志，出现在溢出检查、进位处理等场合。setcc/cmovcc 家族与 jcc 一一对应，见 3.7 的折叠框。

## 5. 寻址方式

统一公式：==有效地址 = 基址 + 变址×比例 + 位移==，比例只能取 1、2、4、8，三段都可以缺省。六种常见形态：

| 方式 | 写法示例 | 有效地址 | 逆向里对应什么 |
| --- | --- | --- | --- |
| 立即寻址 | `mov eax,0x10` | 数就在指令里 | 常量 |
| 寄存器寻址 | `mov eax,ebx` | —— | 缓在寄存器里的变量 |
| 直接内存 | `mov eax,DWORD PTR [0x404060]` | 地址写死在指令里 | 全局变量（-no-pie 下地址固定） |
| 寄存器间接 | `mov eax,DWORD PTR [rax]` | rax | 指针解引用 `*p` |
| 基址+偏移 | `mov eax,DWORD PTR [rbp-0x8]`、`[rax+0x10]` | 基址+位移 | 局部变量；结构体字段 `p->field` |
| 基址+变址+比例 | `mov eax,DWORD PTR [rax+rdx*4]` | 基址 + rdx×4 | 数组 `a[rdx]` |

最要紧的是最后两行在逆向里的含义：

- ==比例因子就是数组元素宽度==：×4 是 int 数组、×2 是 short、×8 是 long long 或 64 位指针数组。看到 `[rax+rdx*4]`，直接读成"rax 是数组首地址，取第 rdx 个 int"；
- ==基址+固定偏移是结构体成员==：偏移就是字段在结构体里的偏移（对齐规则见 [[R02-C语言与内存模型回顾#6. 结构体对齐：ptype /o 直接给答案|R02 第 6 节]]）。

> [!info]- rip 相对寻址与 PIE
> 开 PIE 的程序不能用"地址当立即数"（加载基址每次都变），全局数据的访问改写成 `lea rax,[rip+0x2f09]`：以==下一条指令的地址==为基准加偏移，链接时算好。IDA/Ghidra 会直接注释出目标地址。7.1 的 `mov edi,0x402004` 是 -no-pie 下的写法；两种寻址的更多细节见 [[04-汇编语言精要#5. 寻址方式|04 章寻址方式]]。

## 6. AT&T 与 Intel 语法

objdump 默认输出 AT&T 语法：`mov %edi,-0x4(%rbp)`。==objdump 默认 AT&T，IDA、Ghidra、x64dbg 默认 Intel==。同一份二进制两种拼法，会读一个等于会读另一个。

### 6.1 对照表

| 维度 | AT&T（objdump 默认） | Intel |
| --- | --- | --- |
| 操作数方向 | ==源在前，目的在后== | ==目的在前，源在后== |
| 寄存器 | 带 `%`：`%eax` | 裸名：`eax` |
| 立即数 | 带 `$`：`$0x10` | 裸数：`0x10` |
| 裸数字的含义 | 是内存地址（加 `$` 才是立即数） | 是立即数（加 `[]` 才是内存） |
| 内存写法 | 位移(基址)：`-0x4(%rbp)`；变址：`(%rax,%rdx,4)` | `[rbp-0x4]`；`[rax+rdx*4]` |
| 操作数宽度 | 指令后缀：`movb`/`movw`/`movl`/`movq`（1/2/4/8 字节） | 内存操作数前缀：`BYTE`/`WORD`/`DWORD`/`QWORD PTR` |
| 间接跳转/调用 | 操作数带 `*`：`jmp *%rax` | 裸写：`jmp rax` |

### 6.2 同一个函数的两次反汇编

一行 C：`return a + b * c;`。示例 syntax_muladd.c 全文：

```c
int mul_add(int a, int b, int c) {
    return a + b * c;
}
int main(void) {
    return mul_add(2, 3, 4);
}
```

```bash
gcc -O0 -fno-pie -no-pie syntax_muladd.c -o syntax_muladd
objdump -d syntax_muladd | sed -n '/<mul_add>:/,/^$/p'           # 默认，AT&T
objdump -d -M intel syntax_muladd | sed -n '/<mul_add>:/,/^$/p'  # -M intel 切语法
```

输出（objdump -d，AT&T 语法，节选；开头 `endbr64; push rbp; mov rbp,rsp` 三行两种语法逐字节相同，截去）：

```asm
# x86-64 Linux · System V AMD64 ABI · AT&T 语法
40110e:  89 7d fc     mov    %edi,-0x4(%rbp)
401111:  89 75 f8     mov    %esi,-0x8(%rbp)
401114:  89 55 f4     mov    %edx,-0xc(%rbp)
401117:  8b 45 f8     mov    -0x8(%rbp),%eax
40111a:  0f af 45 f4  imul   -0xc(%rbp),%eax
40111e:  89 c2        mov    %eax,%edx
401120:  8b 45 fc     mov    -0x4(%rbp),%eax
401123:  01 d0        add    %edx,%eax
401125:  5d           pop    %rbp
401126:  c3           ret
```

输出（objdump -d -M intel，同一二进制，节选）：

```asm
; x86-64 Linux · System V AMD64 ABI · Intel 语法
40110e:  89 7d fc     mov    DWORD PTR [rbp-0x4],edi
401111:  89 75 f8     mov    DWORD PTR [rbp-0x8],esi
401114:  89 55 f4     mov    DWORD PTR [rbp-0xc],edx
401117:  8b 45 f8     mov    eax,DWORD PTR [rbp-0x8]
40111a:  0f af 45 f4  imul   eax,DWORD PTR [rbp-0xc]
40111e:  89 c2        mov    edx,eax
401120:  8b 45 fc     mov    eax,DWORD PTR [rbp-0x4]
401123:  01 d0        add    eax,edx
401125:  5d           pop    rbp
401126:  c3           ret
```

左边机器码一列逐字节相同：==两套语法只是同一串字节的两种拼法，翻译的是同一条指令==。逐行互认，最关键的是三处。

1. **imul 的操作数顺序两派相反**。AT&T `imul -0xc(%rbp),%eax`：源在前，eax ← eax × [rbp-0xc]；Intel `imul eax,DWORD PTR [rbp-0xc]`：目的在前。==读 AT&T 的双操作数 imul，目的地在最后==。
2. **add 的读法跟着方向翻**。`add %edx,%eax`（AT&T）与 `add eax,edx`（Intel）字面几乎一样，都是 eax += edx，但"谁接收结果"的位置相反。方向没弄对，AT&T 代码会读反。
3. **宽度标记的位置不同**。AT&T 写在指令尾巴（`movl` 的 l = 4 字节），Intel 写在内存操作数头上（`DWORD PTR`）。

运行 `./syntax_muladd; echo $?`，输出 14（2 + 3×4），行为与汇编对照得上。

> [!warning] gcc -S 还有一层小坑：十进制
> `-S` 输出里偏移是十进制，objdump 是十六进制，同一个数。mul_add 头一条 mov 的三种产物对照：
>
> ```asm
> # x86-64 Linux；三行是同一条指令的三种呈现
> movl	%edi, -4(%rbp)              # gcc -S 默认，AT&T，十进制
> mov	DWORD PTR [rbp-4], edi      # gcc -S -masm=intel，还是十进制
> mov     DWORD PTR [rbp-0x4],edi     # objdump -d -M intel，十六进制
> ```
>
> 数字对不上先查进制。

## 7. 四种代码形状

读汇编不逐行硬啃。编译器翻译 C 只用几套固定排法，==先认形状，再抠细节==。四种形状各配一个完整示例：C 源码 → 编译 → objdump 逐行注释。源码全在正文，动手编译一遍再对照，读得更准。

### 7.1 形状一：函数序言与尾声

三个局部变量加一次 printf（shape1_frame.c）：

```c
#include <stdio.h>
int frame_demo(int a, int b) {
    int local1 = a + 1;
    int local2 = b * 2;
    int total = local1 + local2;
    printf("%d\n", total);
    return total;
}
int main(void) {
    frame_demo(3, 4);
    return 0;
}
```

```bash
gcc -O0 -fno-pie -no-pie shape1_frame.c -o shape1_frame
objdump -d -M intel shape1_frame | sed -n '/<frame_demo>:/,/^$/p'
```

输出（objdump -d -M intel，逐行注释）：

```asm
; x86-64 Linux · System V AMD64 ABI · Intel 语法
0000000000401136 <frame_demo>:
  401136:  f3 0f 1e fa       endbr64                       ; CET 着陆点，行为等同 nop
  40113a:  55                push   rbp                    ; ┐ 序言：保存调用者的 rbp
  40113b:  48 89 e5          mov    rbp,rsp                ; ┘ 设定本帧基准
  40113e:  48 83 ec 20       sub    rsp,0x20               ; 划 0x20 字节：3 个 int 只用 12 字节，余下补对齐
  401142:  89 7d ec          mov    DWORD PTR [rbp-0x14],edi ; 保存参数 a
  401145:  89 75 e8          mov    DWORD PTR [rbp-0x18],esi ; 保存参数 b
  401148:  8b 45 ec          mov    eax,DWORD PTR [rbp-0x14] ; eax = a
  40114b:  83 c0 01          add    eax,0x1                ; eax = a + 1
  40114e:  89 45 f4          mov    DWORD PTR [rbp-0xc],eax  ; local1 存入栈槽
  401151:  8b 45 e8          mov    eax,DWORD PTR [rbp-0x18] ; eax = b
  401154:  01 c0             add    eax,eax                ; eax = b * 2（乘 2 就是自加一次）
  401156:  89 45 f8          mov    DWORD PTR [rbp-0x8],eax  ; local2 存入栈槽
  401159:  8b 55 f4          mov    edx,DWORD PTR [rbp-0xc]
  40115c:  8b 45 f8          mov    eax,DWORD PTR [rbp-0x8]
  40115f:  01 d0             add    eax,edx                ; eax = local1 + local2
  401161:  89 45 fc          mov    DWORD PTR [rbp-0x4],eax  ; total 存入栈槽
  401164:  8b 45 fc          mov    eax,DWORD PTR [rbp-0x4]  ; ┐ 准备 printf 的参数：
  401167:  89 c6             mov    esi,eax                ; │ 第 2 参数 = total
  401169:  bf 04 20 40 00    mov    edi,0x402004           ; │ 第 1 参数 = 格式串地址
  40116e:  b8 00 00 00 00    mov    eax,0x0                ; │ 变参约定：向量寄存器参数 0 个，AL 清零
  401173:  e8 c8 fe ff ff    call   401040 <printf@plt>    ; ┘ 调 libc 的 printf
  401178:  8b 45 fc          mov    eax,DWORD PTR [rbp-0x4]  ; 返回值 = total
  40117b:  c9                leave                         ; ┐ 尾声：mov rsp,rbp 再 pop rbp
  40117c:  c3                ret                           ; ┘ 弹返回地址，回到 main
```

序言三步各干一件事：`push rbp` 保存调用者的 rbp；`mov rbp,rsp` 把 rbp 定在本帧开头；`sub rsp,0x20` 划出局部区（2.2 的帧布局图在这里落地）。此后参数与局部变量全在 `[rbp-0x..]` 的负偏移里；尾声 `leave` 一步还原 rsp 并弹回旧 rbp，`ret` 弹返回地址回到 main。==读任何函数，先找这对序言尾声，边界就定了==。

为什么编译器生成这个形状：-O0 下每个局部变量独占一个栈槽、寄存器参数一进门就抄进栈槽——源码里每个变量都可能被取地址，编译器不假设它能一直待在寄存器里。保守的排法换来源码与汇编逐行对应；开优化后这些栈往返会大量消失。

有三处容易停一下。

- **为什么结尾是 `leave` 不是 `pop rbp`**？[[#6.2 同一个函数的两次反汇编|6.2]] 的 mul_add 结尾就是 `pop rbp; ret`。函数动过 rsp（本例 `sub rsp,0x20`）就用 leave 一步还原；没动过，pop 就够。两种写法等价，gcc 按函数动没动 rsp 选。
- **`mov edi,0x402004` 怎么直接装地址**？-no-pie 程序加载位置固定，编译器把绝对地址当立即数放进指令。PIE 程序（赛题常态）会换成 `lea rdi,[rip+0x2f09]` 的 rip 相对寻址（[[#5. 寻址方式|第 5 节]]折叠框）。
- **`mov eax,0x0` 是干嘛的**？printf 是变参函数，System V 规定 AL 存"向量寄存器参数个数"，没有浮点参数就清零。==call 前冒出 `mov eax,0` 或 `xor eax,eax`，多半是 printf/scanf 一家==。

### 7.2 形状二：比较与跳转

打分函数：90 分以上返回 4，60 到 89 返回 1，59 及以下返回 0（shape2_gate.c）：

```c
int gate(int score) {
    if (score >= 90)
        return 4;
    if (score >= 60)
        return 1;
    return 0;
}
int main(void) {
    return gate(75);
}
```

```bash
gcc -O0 -fno-pie -no-pie shape2_gate.c -o shape2_gate
objdump -d -M intel shape2_gate | sed -n '/<gate>:/,/^$/p'
```

输出（objdump -d -M intel）：

```asm
; x86-64 Linux · System V AMD64 ABI · Intel 语法
0000000000401106 <gate>:
  401106:  f3 0f 1e fa       endbr64
  40110a:  55                push   rbp                 ; 序言（7.1 拆过，下面不再注）
  40110b:  48 89 e5          mov    rbp,rsp
  40110e:  89 7d fc          mov    DWORD PTR [rbp-0x4],edi  ; score 存入栈槽
  401111:  83 7d fc 59       cmp    DWORD PTR [rbp-0x4],0x59 ; score 与 0x59 比较
  401115:  7e 07             jle    40111e <gate+0x18>       ; ≤ 0x59 → 跳去第二道门槛
  401117:  b8 04 00 00 00    mov    eax,0x4                  ; ┌ score ≥ 90：eax = 4
  40111c:  eb 12             jmp    401130 <gate+0x2a>       ; └ 跳去汇合点
  40111e:  83 7d fc 3b       cmp    DWORD PTR [rbp-0x4],0x3b ; score 与 0x3b 比较
  401122:  7e 07             jle    40112b <gate+0x25>       ; ≤ 0x3b → 跳去保底分支
  401124:  b8 01 00 00 00    mov    eax,0x1                  ; 中间档：eax = 1
  401129:  eb 05             jmp    401130 <gate+0x2a>       ; 跳去汇合点
  40112b:  b8 00 00 00 00    mov    eax,0x0                  ; 保底：eax = 0
  401130:  5d                pop    rbp                      ; 汇合点
  401131:  c3                ret
```

有一处要先说破：源码写 `>= 90`，汇编里是 `cmp ...,0x59` 配 `jle`——0x59 是 89。编译器把"≥ 90"改写成等价的"> 89"，而 ==jcc 跳走的那条边永远是"不满足"的情况==，[[04-汇编语言精要#8. 四种"代码形状"|04 章 8.1]]讲"if 是反着翻译的"，这份产物就是实例。想还原源码条件，把"跳过了哪段"反着读。

两个阅读习惯：

- 魔数先换算成十进制再下结论：0x59 是 89、0x3b 是 59，与源码的 90、60 各差 1，正是"反着翻"的痕迹；
- 看跳转族别反推变量类型：jle 属有符号一族，可推 score 是 int；源码若是 unsigned，同一位置会换成 jbe（[[04-汇编语言精要#6. 比较、跳转与标志位|04 章 6.2]]的两套跳转）。

为什么是这副形状：每个分支把自己的返回值装进 eax，然后 jmp 到同一个汇合点收尾——if-else 链的标准排法，分支再多也只是重复"cmp + jcc + mov + jmp"。

运行 `./shape2_gate; echo $?`，输出 1：gate(75) 走的是 0x3b（59）这道门槛。

### 7.3 形状三：循环

计数程序：start 每轮减 3，返回循环了几轮（shape3_countdown.c）：

```c
int count_down(int start) {
    int steps = 0;
    while (start > 0) {
        start -= 3;
        steps++;
    }
    return steps;
}
int main(void) {
    return count_down(20);
}
```

```bash
gcc -O0 -fno-pie -no-pie shape3_countdown.c -o shape3_countdown
objdump -d -M intel shape3_countdown | sed -n '/<count_down>:/,/^$/p'
```

输出（objdump -d -M intel）：

```asm
; x86-64 Linux · System V AMD64 ABI · Intel 语法
0000000000401106 <count_down>:
  401106:  f3 0f 1e fa           endbr64
  40110a:  55                    push   rbp
  40110b:  48 89 e5              mov    rbp,rsp
  40110e:  89 7d ec              mov    DWORD PTR [rbp-0x14],edi  ; start 存入栈槽
  401111:  c7 45 fc 00 00 00 00  mov    DWORD PTR [rbp-0x4],0x0   ; steps = 0（初始化）
  401118:  eb 08                 jmp    401122 <count_down+0x1c>  ; 先跳去【尾部】判断区
  40111a:  83 6d ec 03           sub    DWORD PTR [rbp-0x14],0x3  ; ┌ start -= 3
  40111e:  83 45 fc 01           add    DWORD PTR [rbp-0x4],0x1   ; └ steps++       （循环体）
  401122:  83 7d ec 00           cmp    DWORD PTR [rbp-0x14],0x0  ; 判断区：start 与 0 比较
  401126:  7f f2                 jg     40111a <count_down+0x14>  ; start > 0 → 跳回循环体
  401128:  8b 45 fc              mov    eax,DWORD PTR [rbp-0x4]   ; 返回 steps
  40112b:  5d                    pop    rbp
  40112c:  c3                    ret
```

while 的条件在 C 里写在头部，汇编排的判断却在尾部：初始化之后先 `jmp` 直奔 401122 的判断区，条件成立 `jg` 跳回 40111a 的循环体。==for、while、do-while 在 gcc 产物里是同一副骨架==，区别只在进入循环的那条 jmp：while/for 有，do-while 条件本来就在尾部，连它都省。判断放尾部，每转一圈只需一条向后跳转。

认循环就盯两条跳转：一条向前带出循环体，一条往回收，中间夹的就是循环体。往回那条 jcc 是核心：它拿谁比较、循环变量每轮怎么变，逻辑就读出来了。本例：start 每轮减 3，统计减到非正要几轮。运行 `./shape3_countdown; echo $?`，输出 7——循环体执行时 start 依次是 20、17、14、11、8、5、2，第 8 次判断时 start 已是 -1。

`loop` 指令（rcx 自减一并判零跳转）在这里见不到：gcc 从不生成它，它比等价的 dec/条件跳转慢（[[04-汇编语言精要#8. 四种"代码形状"|04 章 8.2]]有注）。

### 7.4 形状四：数组访问

short 数组按下标取元素，寻址公式的全部零件都会出场（shape4_pick.c）：

```c
short pick_short(short *tab, int idx) {
    return tab[idx + 1];
}
int main(void) {
    short tab[4] = {10, 20, 30, 40};
    return pick_short(tab, 1);
}
```

```bash
gcc -O0 -fno-pie -no-pie shape4_pick.c -o shape4_pick
objdump -d -M intel shape4_pick | sed -n '/<pick_short>:/,/^$/p'
```

输出（objdump -d -M intel）：

```asm
; x86-64 Linux · System V AMD64 ABI · Intel 语法
0000000000401136 <pick_short>:
  401136:  f3 0f 1e fa       endbr64
  40113a:  55                push   rbp
  40113b:  48 89 e5          mov    rbp,rsp
  40113e:  48 89 7d f8       mov    QWORD PTR [rbp-0x8],rdi  ; tab 存入栈槽（指针 8 字节）
  401142:  89 75 f4          mov    DWORD PTR [rbp-0xc],esi  ; idx 存入栈槽
  401145:  8b 45 f4          mov    eax,DWORD PTR [rbp-0xc]  ; eax = idx
  401148:  48 98             cdqe                        ; 符号扩展进 rax：下标是 int，地址运算按 64 位做
  40114a:  48 83 c0 01       add    rax,0x1              ; rax = idx + 1
  40114e:  48 8d 14 00       lea    rdx,[rax+rax*1]      ; ×2：short 元素宽 2 字节（3.2 的 lea 算术）
  401152:  48 8b 45 f8       mov    rax,QWORD PTR [rbp-0x8]  ; rax = tab（基址）
  401156:  48 01 d0          add    rax,rdx              ; rax = tab + (idx+1)*2
  401159:  0f b7 00          movzx  eax,WORD PTR [rax]   ; 读出 tab[idx+1]
  40115c:  5d                pop    rbp
  40115d:  c3                ret
```

识别特征按顺序：下标符号扩展（cdqe，3.5 的表）→ 加偏移 → 乘元素宽（lea）→ 加基址 → 解引用。04 章的例子是 int 数组乘 4，这里 short 乘 2：==比例因子（或乘数）是几，元素就占几字节==，这是从汇编反推数组元素类型的第一线索。`lea rdx,[rax+rax*1]` 与 `[rax*2]` 算出同一个地址，编码器选了基址+变址形式，读的时候别被绕住。运行 `./shape4_pick; echo $?`，输出 30：pick_short(tab, 1) 取的是 tab[2]，下标从 0 数起。

最后一步的 movzx 值得多看一眼。short 是有符号类型，直觉期待 movsx 铺符号位，但 gcc 15 在 -O0 下生成 movzx：函数只承诺返回 16 位值，AX 那 16 位就是全部载荷，放在 eax 低 16 位对调用者同样有效，铺符号位属于白做。==扩展指令出现在"值要变宽"的转换点，不出现在"值保持原样"的地方==。把返回类型从 short 改成 int，同一行代码的收尾变成两条：

```asm
; x86-64 Linux · Intel 语法（pick 改返回 int 后的收尾两条）
movzx  eax,WORD PTR [rax]   ; 先把 16 位读进 eax 低 16 位
cwde                        ; 按 ax 的符号铺满 eax：升级成 int 才需要这一步
```

[[R02-C语言与内存模型回顾#8. 整型溢出在反汇编里留下的痕迹|R02 第 8 节]]的"看到扩展指令反推类型转换"，配上这条一起用：先找转换点，再看值流向哪里。

### 7.5 形状速查表

| 形状 | 识别特征 | 对应源码 |
| --- | --- | --- |
| 序言尾声 | `push rbp; mov rbp,rsp` 开场，`leave; ret` 或 `pop rbp; ret` 收尾 | 任何函数的边界 |
| 比较-跳转 | `cmp`/`test` 紧跟 `jcc`，各分支 `mov eax,N` 后 `jmp` 汇合 | if / else-if 链 |
| 循环 | 向前一条 `jmp` 加向后一条 `jcc`，夹住循环体 | for / while |
| 数组访问 | `cdqe` 系扩展 + `lea` 乘比例 + 基址相加 + 解引用 | `a[i]`、`p->field` |

## 8. 读陌生函数反汇编的三个步骤

形状认熟之后，读一个陌生函数只剩固定三步。

**第一步，序言定边界。** objdump 会用 `<函数名>:` 标出符号表里有的函数；stripped 的题没这待遇（[[R04-可执行文件格式ELF与PE|R04]]讲过 stripped），就扫 `push rbp; mov rbp,rsp` 找函数起点，相邻两对之间是一个函数。

**第二步，比较定分支。** 把 `cmp`、`test` 和跟着的 `jcc` 全抽出来，函数骨架就出来了。以 shape2_gate 为例：

```bash
objdump -d -M intel shape2_gate | sed -n '/<gate>:/,/^$/p' | grep -E 'cmp|test|j'
```

输出：

```
  401111:  83 7d fc 59     cmp    DWORD PTR [rbp-0x4],0x59
  401115:  7e 07           jle    40111e <gate+0x18>
  40111c:  eb 12           jmp    401130 <gate+0x2a>
  40111e:  83 7d fc 3b     cmp    DWORD PTR [rbp-0x4],0x3b
  401122:  7e 07           jle    40112b <gate+0x25>
  401129:  eb 05           jmp    401130 <gate+0x2a>
```

六行没读一条算术指令，函数轮廓已经清楚：两个比较点 0x59 与 0x3b，各配一条 `jle`，两条 `jmp` 汇去同一处——两道门槛的打分函数。

**第三步，call 定交互点。** `call xxx@plt` 是在调库函数，`call rdx` 这类寄存器调用背后是函数指针（[[R02-C语言与内存模型回顾#5. 函数指针、间接调用与那张地址表|R02 第 5 节]]）。库函数行为公开，==看到 `strcmp`/`memcmp` 就知道比较点到了，正确输入的线索常在它旁边==。frame_demo 的交互点：

```bash
objdump -d -M intel shape1_frame | sed -n '/<frame_demo>:/,/^$/p' | grep call
```

输出：

```
  401173:  e8 c8 fe ff ff  call   401040 <printf@plt>
```

这三步是 [[R05-静态分析工具链IDA与Ghidra|R05]] 静态分析与 [[R06-动态调试GDB与x64dbg|R06]] 动态调试共用的底层动作：IDA 的函数窗口对应第一步，xref 与字符串窗口对应第二、三步；GDB 断点常下在第二步的 `cmp` 之后、第三步的 `call` 之前。==工具不同，要找的东西相同==。

## 9. 常见问题

| 现象 | 原因与解决 |
| --- | --- |
| objdump 输出全是 `%eax`、`-0x4(%rbp)` | 默认 AT&T，`-M intel` 切换（见 [[#6. AT&T 与 Intel 语法\|第 6 节]]） |
| AT&T 的 `imul -0xc(%rbp),%eax` 读不出方向 | imul 双操作数在 AT&T 同样源在前，目的地是最后一个；对照 Intel `imul eax,DWORD PTR [rbp-0xc]` |
| `gcc -S` 偏移是十进制，objdump 是十六进制 | 同一个数的两种进制；`-S` 是编译器中间产物，objdump 面对最终成品，两边都要会看 |
| 源码写 `>= 90`，反汇编里找不到 90 | 编译器换成等价的 `> 89`（`cmp ...,0x59` 配 `jle`）；魔数先换算十进制再下结论 |
| 循环找不着 | 判断在尾部：先看 `jmp` 跳去的标签，再看谁 `jcc` 跳回来（见 [[#7.3 形状三：循环\|7.3]]） |
| short 数组只读到 movzx，不见 movsx | 值不升级成更宽类型时 gcc 不铺符号位；返回类型改成 int 才补 cwde（见 [[#7.4 形状四：数组访问\|7.4]]） |
| 局部变量偏移和别人笔记对不上 | 偏移没有公式，编译器版本与选项说了算，以你自己反汇编得到的输出为准（[[R02-C语言与内存模型回顾#3. 用 GDB 把栈帧看在眼里\|R02 第 3 节]]同款提醒） |
| 尾声有时 `leave` 有时 `pop rbp` | 动过 rsp 的函数用 leave 一步还原，没动过 pop 就够，两者等价 |
| `call` 前面莫名一条 `mov eax,0x0` | 变参函数（printf/scanf 家族）的 System V 约定，AL 存向量寄存器参数个数 |
| 每个函数开头都有 `endbr64` | CET 着陆点，行为等同 nop，忽略即可 |
| `div` 前冒出 `mov edx,0x0` 或 `cdq` | 准备被除数高半：无符号清零 edx/rdx，有符号用 cdq/cqo 铺符号（见 [[#3.5 乘法与除法\|3.5]]） |
| `and` 之后紧跟 `test`，看着重复 | and 算出值，test 只设标志不写回，分工不同（见 [[#3.7 and、test 与 cmp：改值与只改标志\|3.7]]） |
| 函数开头 `push rbx` 或 `push r12` | 该函数要跨 call 保存值，这些是 callee-saved 寄存器（见 [[#2.3 caller-saved 与 callee-saved\|2.3]]） |
| 写过 `eax` 后 `rax` 高位全成 0 | 写 32 位子寄存器清零高 32 位，写 16/8 位不影响其余位（见 [[#2.1 通用寄存器与子寄存器\|2.1]]） |
