# R7 编码与算法识别还原

> [!info]- 章节信息
> **所属方向**：逆向工程 ｜ **难度阶段**：L2 核心题型期 ｜ **前置要求**：[[R05-静态分析工具链IDA与Ghidra|R05]] · [[08-编码与古典密码|通用基础 08 章]] · [[09-密码学基础|通用基础 09 章]]
> **本章目标**：拿到密文能在 3 分钟内定家族；在反汇编与伪代码里认出 XOR、Base、TEA 系、RC4、AES/DES、哈希的代码形状；每一种都能用 Python 逆回去，并把常用算法沉淀成一套随身武器库。

## 1. 识别总方法论：先判路，再定家族

[[08-编码与古典密码#1. 先分清三条路|通用基础 08 章]]把"编码换马甲、加密上锁、哈希烧灰"三条路讲了一下；那一节的表在 misc 题里够用。逆向题多了一层：密文不在题目文本里，而是躺在程序的 `.rodata` 或某个常量数组里，判定材料变成"伪代码里看到的算法形状"。本章的全部内容就是两张对应关系：==密文串的特征指向哪个家族==、==代码的形状指向哪个算法==，以及每个家族怎么用 Python 逆回去。

判路还是那四个判据，只是换了问法：

- **可逆性与密钥**：伪代码里出现了密钥数组或密钥派生，就是加密；只有查表换字符，就是编码。
- **字符集**：`sorted(set(s))` 列出密文用到的字符，撞 [[08-编码与古典密码#2. Base 家族|08 章的家族速查表]]。
- **熵**：编码后的文本熵有个上限（hex 顶到 4.0、base64 顶到 6.0，[[08-编码与古典密码#7. 编码链识别与剥层|08 章第 7 节]]算过）；==熵接近该字符集的理论上限、且解不出来的是乱码字节，才指向加密==。
- **长度比**：编码有固定倍数（base64 是 4 的倍数、hex 是偶数）；加密后的原始密文长度==等于明文长度或向上取整到块大小==——常量数组长度是 8 的倍数还是 16 的倍数，直接把候选算法砍掉一半。

先看三个候选串，走一遍判路流程：

```python
# probe.py —— 四件套：长度、字符集、熵、可打印性
import math
from collections import Counter

def entropy(s):
    n = len(s)
    return -sum(v / n * math.log2(v / n) for v in Counter(s).values())

def probe(name, s):
    cs = sorted(set(s))
    n = len(s)
    printable = all(32 <= ord(c) < 127 for c in s)
    print(f"[{name}] len={n} 字符集={len(cs)} 熵={entropy(s):.2f} 可打印={printable}")
    print("     用到的字符:", "".join(cs)[:50])

A = "666c61677b6865785f727d"
B = "ZmxhZ3tiYXNlNjR9"
C = "e10adc3949ba59abbe56e057f20f883e"
for name, s in [("A", A), ("B", B), ("C", C)]:
    probe(name, s)

print()
print("A 按 hex 解 ->", bytes.fromhex(A).decode())
import base64
print("B 按 base64 解 ->", base64.b64decode(B).decode())
print("C：32 位 hex、解出来不可读 -> 不再是编码，按哈希查")
```

输出：

```
[A] len=22 字符集=10 熵=2.86 可打印=True
     用到的字符: 125678bcdf
[B] len=16 字符集=14 熵=3.75 可打印=True
     用到的字符: 39NRXYZhijlmtx
[C] len=32 字符集=16 熵=3.82 可打印=True
     用到的字符: 0123456789abcdef

A 按 hex 解 -> flag{hex_r}
B 按 base64 解 -> flag{base64}
C：32 位 hex、解出来不可读 -> 不再是编码，按哈希查
```

A 是 hex 编码，B 是 base64，C 是 32 位 hex——hex 解出来不可读，且长度恰好是 MD5 摘要的字符数（32），于是从"编码"跳到"哈希"，直接拿去彩虹表查（`e10adc...` 就是 `123456` 的 MD5）。==同一个"32 位 hex"长相，解一次才能定家族==。

## 2. Base 家族：padding、长度与换表

字符集速查、手撕 base64、URL-safe 变体，[[08-编码与古典密码#2. Base 家族|08 章第 2 节]]已经完整讲过，这里只补逆向时最常用的三件事：padding 数量规律、长度换算公式、换表 base64 的识别与破解。

padding 的数量只由"最后一个不完整组剩几个字节"决定，base64 每组 3 字节、base32 每组 5 字节：

```python
import base64

print("== base64：len%3 -> 编码后长度、'=' 个数 ==")
for r in range(3):
    data = b"x" * (5 + r)
    s = base64.b64encode(data).decode()
    print(f"明文 len=5+{r}  密文 len={len(s)}  {s}")
print("== base32：len%5 -> 编码后长度、'=' 个数 ==")
for r in range(5):
    data = b"x" * (11 + r)
    s = base64.b32encode(data).decode()
    print(f"明文 len=11+{r}  密文 len={len(s)}  {s}")

raw = bytes([0xFB, 0xFF, 0xBF, 0xFE])
print()
print("标准 base64 :", base64.b64encode(raw).decode())
print("urlsafe 变体:", base64.urlsafe_b64encode(raw).decode())
```

输出：

```

明文 len=5+0  密文 len=8  eHh4eHg=
明文 len=5+1  密文 len=8  eHh4eHh4
明文 len=5+2  密文 len=12  eHh4eHh4eA==
== base32：len%5 -> 编码后长度、'=' 个数 ==
明文 len=11+0  密文 len=24  PB4HQ6DYPB4HQ6DYPA======
明文 len=11+1  密文 len=24  PB4HQ6DYPB4HQ6DYPB4A====
明文 len=11+2  密文 len=24  PB4HQ6DYPB4HQ6DYPB4HQ===
明文 len=11+3  密文 len=24  PB4HQ6DYPB4HQ6DYPB4HQ6A=
明文 len=11+4  密文 len=24  PB4HQ6DYPB4HQ6DYPB4HQ6DY

标准 base64 : +/+//g==
urlsafe 变体: -_-__g==
```

三条换算公式，反推明文长度用：

$$\text{base64 密文长} = 4\left\lceil \frac{n}{3} \right\rceil \qquad \text{base32 密文长} = 8\left\lceil \frac{n}{5} \right\rceil \qquad \text{hex 密文长} = 2n \tag{1}$$

base64 的 `=`：明文长度余 0 不补、余 1 补两个、余 2 补一个；base32 对应余 0/1/2/3/4 补 0/6/4/3/1 个。==题目把 `=` 删掉是常见操作，解码前用 `s + "=" * (-len(s) % 4)` 补回==。密文里出现 `-` 和 `_`，先试 `urlsafe_b64decode`（[[08-编码与古典密码#2.4 变体：URL-safe 与去填充|08 章 2.4]]）。base58 没有进这组公式：它不是位切分而是大整数进制转换，没有填充符、长度也不固定，字符集（缺 `0OIl`）与原理见 [[08-编码与古典密码#2. Base 家族|08 章第 2 节]]。

### 2.1 换表 base64：解出乱码但字符集正常

出题人常把 64 个字符的排列顺序换掉。特征：==按标准表解码得到乱码，但密文字符集仍然是那 64 个可见字符加 `=`==。还有一路旁证：标准 base64 编码英文时字符分布明显偏斜（小写字母扎堆），换表后解出的字节分布接近均匀——统计一下频次就能加重怀疑。确认后先试最简单的假设——标准表整体旋转了若干位：

```python
import base64

STD = "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/"
ROT = STD[13:] + STD[:13]                     # 出题人的自定义表：标准表转了 13 格
flag = b"flag{custom_table}"
ct = base64.b64encode(flag).decode().translate(str.maketrans(STD, ROT))
print("换表后的密文:", ct)
print("按标准表硬解 :", base64.b64decode(ct))
print("密文字符集:", "".join(sorted(set(ct.rstrip('=')))))
for r in range(64):
    tbl = str.maketrans(STD[r:] + STD[:r], STD)
    out = base64.b64decode(ct.translate(tbl))
    if out.startswith(b"flag"):
        print(f"旋转 {r} 格 -> {out.decode()}")
```

输出：

```
换表后的密文: mz+umE6wqkaBoDCsqTSvoTiK
按标准表硬解 : b'\x9b?\xae\x98N\xb0\xaaF\x81\xa00\xac\xa94\xaf\xa18\x8a'
密文字符集: +6BCDEKSTaikmoqsuvwz
旋转 13 格 -> flag{custom_table}
```

> [!info]- 任意置换的表怎么恢复：已知明文
> 自定义表是 64 个字符的任意排列时，旋转枚举失效，改用已知明文逐位恢复。base64 每 3 字节明文对应 4 个表项：明文前 3 字节已知（flag 题几乎必知 `fla`），就能把密文前 4 个字符映射回下标 0–3 对应的表项；已知明文每多 3 字节，多恢复 4 个表项。恢复不满的部分，利用"标准表里出现过的字符大概率还在原位附近"或直接对剩余位置做排列枚举，配合解出结果是否以 `flag{` 开头来判定。逆向场景里更省力的路：换表逻辑写在程序里，F5 看伪代码直接把那张表抄出来。

## 3. XOR：从单字节到重复密钥

XOR 的自反性（`a ^ b ^ b = a`）[[09-密码学基础#3.1 XOR 与一次一密|09 章 3.1]]讲过，[[R05-静态分析工具链IDA与Ghidra|R05]]的 crackme 也解过一个单字节 XOR。本节把逆向里会遇到的三种形态讲全：单字节密钥、随位置变化的滚动密钥、多字节循环密钥。伪代码里的形状分别是 `buf[i] ^ 0x37`、`buf[i] ^ (i + 0x25)`、`buf[i] ^ key[i % 4]`——看到 `%` 取模下标就往"循环密钥"想。

### 3.1 单字节爆破：可打印性加频率评分

只有 256 种可能，全扫一遍，按"解出来全是可打印字符"粗筛，再按英文字母频率的卡方偏差精排：

```python
EN_FREQ = [0.08167, 0.01492, 0.02782, 0.04253, 0.12702, 0.02228, 0.02015,
           0.06094, 0.06966, 0.00153, 0.00772, 0.04025, 0.02406, 0.06749,
           0.07507, 0.01929, 0.00095, 0.05987, 0.06327, 0.09056, 0.02758,
           0.00978, 0.02360, 0.00150, 0.01974, 0.00074]

def score(bs):
    """可打印性 + 英文字母频率卡方：越像英文分数越小"""
    if not all(32 <= b < 127 or b in (9, 10, 13) for b in bs):
        return float("inf")
    n = len(bs)
    s = 0.0
    for c in range(26):
        obs = sum(1 for b in bs if chr(b).lower() == chr(c + 97))
        exp = EN_FREQ[c] * n
        s += (obs - exp) ** 2 / exp
    for b in bs:                                   # 非字母字符也扣分，控制字符重罚
        if b < 32 or b > 126:
            s += 64
        elif not (97 <= b <= 122 or 65 <= b <= 90 or b == 32):
            s += 8
    return s

pt = b"the quick brown fox jumps over the lazy dog"
CT = bytes(b ^ 0x37 for b in pt)
print("密文(hex):", CT.hex())

cand = []
for k in range(256):
    out = bytes(b ^ k for b in CT)
    cand.append((score(out), k, out))
cand.sort(key=lambda t: t[0])
for s, k, out in cand[:3]:
    print(f"key=0x{k:02x}  score={s:8.1f}  {out.decode(errors='replace')[:44]}")
```

输出：

```
密文(hex): 435f521746425e545c1755455840591751584f175d425a4744175841524517435f52175b564d4e17535850
key=0x37  score=    90.5  the quick brown fox jumps over the lazy dog
key=0x36  score=   146.0  uid!pthbj!csnvo!gny!ktlqr!nwds!uid!m`{x!enf
key=0x35  score=   243.0  vjg"swkai"`pmul"dmz"hworq"mtgp"vjg"ncx{"fme
```

正确密钥 0x37 的得分与第二名拉开一倍以上。==评分只是排序工具，最后一眼人工确认==：flag 题里直接找 `flag{` 开头的候选更快。中文明文把 `EN_FREQ` 换成目标语料频率即可。

### 3.2 滚动 XOR：密钥流本身有规律

密钥字节随下标变化时，单字节爆破失效。但已知明文片段（flag 题 `flag{` 几乎白送）能推出密钥流前缀，规律一眼可辨：

$$c_i = p_i \oplus ((b + i) \bmod 256) \tag{2}$$

```python
flag = b"flag{r0lling_x0r_st4y}"
ct = bytes(b ^ ((0x25 + i) & 0xFF) for i, b in enumerate(flag))
print("rolling 密文(hex):", ct.hex())
crib = b"flag{r"
ks = bytes(a ^ b for a, b in zip(ct[:len(crib)], crib))
print("crib 推出密钥流前 6 字节:", ks.hex())
key_stream = [(0x25 + i) & 0xFF for i in range(len(ct))]
print("规律: 逐位 +1，起点 0x25 ->", bytes((a ^ b) for a, b in zip(ct, key_stream)).decode())
```

输出：

```
rolling 密文(hex): 434a464f52581b40414741576e4a03466a45430c4047
crib 推出密钥流前 6 字节: 25262728292a
规律: 逐位 +1，起点 0x25 -> flag{r0lling_x0r_st4y}
```

`25 26 27 28 29 2a` 是公差为 1 的等差数列——推断出通项就能算出任意位置的密钥字节，不需要完整密钥流。常见的滚动变体还有 `^ (i * k)`、`^ (key[i % n] + i)`，都用同一招：先推前几个字节，看出通项，再全文展开。

### 3.3 多字节重复密钥：先定长度，再推密钥

密钥循环使用是这类题的命门。定长度有两个统计量，都只用密文本身：

- **移位重合**：统计 `ct[i] == ct[i+s]` 的比例。密钥周期为 L 时，s 取 L 的倍数会让重复率冒头（周期对齐，相同的明文字节撞出相同的密文字节），随机数据的基线是 1/256 ≈ 0.004。
- **分列重合指数**：按候选长度把密文切成若干列，每列算 [[08-编码与古典密码#6. 维吉尼亚：一次完整破解|重合指数]]（08 章 6.2 用它破过维吉尼亚，同一套数学搬到这里）。切对了，每列都是"单字节 XOR 的英文"，重合指数靠近英文水平；切错了，靠近随机水平。

```python
from collections import Counter

def ioc(bs):
    n = len(bs)
    cnt = Counter(bs)
    return sum(v * (v - 1) for v in cnt.values()) / (n * (n - 1))

msg = (b"cryptanalysis of repeating key xor starts with the key length: "
       b"guess the period, split the cipher text into columns, and each "
       b"column turns into a single byte xor that brute force can solve")
key = b"key!"
ct2 = bytes(b ^ key[i % 4] for i, b in enumerate(msg))

print("移位重合法：ct[i]==ct[i+s] 的比例，峰出现在密钥长度的倍数上")
for s in range(1, 13):
    eq = sum(1 for i in range(len(ct2) - s) if ct2[i] == ct2[i + s])
    print(f"  shift={s:2d}  {eq / (len(ct2) - s):.3f}")
```

### 4.1 卡西斯基试验：重复串的间距

原理一句话：密钥长度为 L 时，==相同的明文片段只要距离是 L 的倍数，加密结果就完全相同==。在密文里找重复的字母组，记录两两间距，求最大公约数——公约数就是 L 的候选：

```python
from math import gcd
from collections import defaultdict

def vig_enc(pt, key):
    key, out, i = key.lower(), [], 0
    for c in pt:
        if c.isalpha():
            k = ord(key[i % len(key)]) - 97
            base = 65 if c.isupper() else 97
            out.append(chr((ord(c) - base + k) % 26 + base))
            i += 1
        else:
            out.append(c)
    return "".join(out)

pt = ("the repetition of the cipher text is the opening: when the same group "
      "of letters shows up again, the distance between the two copies is a "
      "multiple of the key length, because the same key bytes line up under "
      "the same letters. the more the text repeats the common words, the "
      "faster this test finds the period of the key")
ct = vig_enc(pt, "cipher")
print("密文:", ct[:70], "...")

ca = "".join(c for c in ct if c.isalpha())   # 密钥只轮转字母，先剔掉非字母
pos = defaultdict(list)
for i in range(len(ca) - 3):
    pos[ca[i:i + 3]].append(i)

dist = []
for g, ps in pos.items():
    for a in range(len(ps)):
        for b in range(a + 1, len(ps)):
            dist.append((g, ps[a], ps[b], ps[b] - ps[a]))
dist.sort(key=lambda t: -t[3])
print("重复三元组（组, 位置a, 位置b, 间距）:")
for row in dist[:9]:
    print("  ", row)

best = max(pos.items(), key=lambda kv: len(kv[1]))   # 出现次数最多的组
g = 0
ps = best[1]
for a in range(len(ps)):
    for b in range(a + 1, len(ps)):
        g = gcd(g, ps[b] - ps[a])
print(f"出现 {len(ps)} 次的组 {best[0]!r}: 两两间距 gcd =", g, "-> keylen 候选")
```

```
   ('igg', 4, 238, 234)
```

`vpt` 是 `the` 的密文，出现 4 次，两两间距全是 6 的倍数，gcd 直接给出密钥长度 6（`cipher` 的长度）。列出的全部间距也几乎都是 6 的倍数——==偶尔有一两个不是，是无关明文偶然撞出相同密文组的噪声，不影响多数投票==。实用建议：重合指数给曲线、卡西斯基给整数，两个一起看，keylen 基本不会选错。

### 4.2 变体速览：认出形状就查表

猪圈、键盘、培根、摩斯的识别方法 [[08-编码与古典密码#5. 替换系：认形就赢|08 章第 5 节]]已讲；栅栏的 W 形走位在 [[08-编码与古典密码#4.2 栅栏密码（W 形）|08 章 4.2]]。逆向 misc 交叉题里还常遇到两个变体，各记一句特征：

- **栅栏变体**：除了 W 形还有"普通栅栏"——把明文切成 N 段后逐段交错读。解出乱码先在 W 形与普通栅栏之间切换，栏数 2 到 7 逐个试。
- **云影密码**：密文只含数字 `1、2、4、8` 和分隔符 `0`，一组数字求和得到字母序号（1=A … 26=Z）。特征极强，看到就按求和解：

```python
def cloud_dec(s):
    out = []
    for group in s.split("0"):
        if group:

def cloud_enc(s):

                v.append(str(d))
                n -= d
        parts.append("".join(v))
    return "0".join(parts) + "0"
```

## 5. TEA、XTEA、XXTEA：一个魔数定三家

FEW（Tea family）三兄弟是 CTF 逆向出场率最高的自实现分组密码：结构简单到出题人愿意手写，又自带一个全局唯一的魔数 ==0x9E3779B9==（黄金分割常数取整）。看到这个立即数，家族就定了，剩下的事是分辨三兄弟、抄对参数、逆推。

### 5.1 TEA 的代码形状

标准 TEA：64 位块（两个 `uint32_t`）、128 位密钥（四个 `uint32_t`）、32 轮。C 实现只有几行：

```c
/* tea.c —— TEA 加解密的 C 参考实现 */
#include <stdio.h>
#include <stdint.h>

void tea_encrypt(uint32_t v[2], const uint32_t k[4]) {
    uint32_t v0 = v[0], v1 = v[1], sum = 0, delta = 0x9E3779B9;
    for (int i = 0; i < 32; i++) {
        sum += delta;
        v0 += ((v1 << 4) + k[0]) ^ (v1 + sum) ^ ((v1 >> 5) + k[1]);
        v1 += ((v0 << 4) + k[2]) ^ (v0 + sum) ^ ((v0 >> 5) + k[3]);
    }
    v[0] = v0; v[1] = v1;
}

void tea_decrypt(uint32_t v[2], const uint32_t k[4]) {
    uint32_t v0 = v[0], v1 = v[1], delta = 0x9E3779B9;
    uint32_t sum = delta * 32;                    /* 逆着走：sum 从终点开始减 */
    for (int i = 0; i < 32; i++) {
        v1 -= ((v0 << 4) + k[2]) ^ (v0 + sum) ^ ((v0 >> 5) + k[3]);
        v0 -= ((v1 << 4) + k[0]) ^ (v1 + sum) ^ ((v1 >> 5) + k[1]);
        sum -= delta;
    }
    v[0] = v0; v[1] = v1;
}

int main(void) {
    uint32_t v[2] = {0x01234567, 0x89abcdef};
    uint32_t k[4] = {0x11111111, 0x22222222, 0x33333333, 0x44444444};
    tea_encrypt(v, k);
    printf("%08x%08x\n", v[0], v[1]);
    tea_decrypt(v, k);
    printf("%08x%08x\n", v[0], v[1]);
    return 0;
}
```

编译后反汇编，加密侧的形状（x86-64 Linux，`gcc -O0`，省略栈维护指令；objdump 用法见 [[R05-静态分析工具链IDA与Ghidra#2.3 objdump：定位 main 并读出校验逻辑|R05 2.3]]）：

```asm
  401190:  mov    eax,DWORD PTR [rbp-0x4]
  401193:  add    DWORD PTR [rbp-0xc],eax         ; sum += delta（每轮开头）
  401196:  mov    eax,DWORD PTR [rbp-0x10]        ; 取 v1
  401199:  shl    eax,0x4                         ; v1 << 4
  4011a4:  lea    ecx,[rdx+rax*1]                 ; (v1<<4) + k[0]
  4011ad:  add    eax,edx                         ; v1 + sum
  4011af:  xor    ecx,eax                         ; 前两项异或
  4011b6:  shr    eax,0x5                         ; v1 >> 5
  4011c5:  add    eax,ecx                         ; 三项合
  4011c7:  xor    eax,edx
  4011c9:  add    DWORD PTR [rbp-0x14],eax        ; v0 += ……（轮函数）
  401206:  add    DWORD PTR [rbp-0x8],0x1         ; i++
```

伪代码里它更直白：`v0 += ((v1<<4)+k0)^(v1+sum)^((v1>>5)+k1); v1 += ((v0<<4)+k2)^(v0+sum)^((v0>>5)+k3); sum += 0x9E3779B9;` 循环 32 次。==`(<<4)^(>>5)` 加三次异或是 TEA 家族的指纹==，即使 delta 被出题人改掉，这个形状也在。

解密函数的特征是 sum 反着走——从 32 轮累加的终点 `0x9E3779B9 × 32 mod 2³² = 0xC6EF3720` 开始减：

```asm
  40124c:  mov    DWORD PTR [rbp-0x4],0x9e3779b9
  401253:  mov    eax,DWORD PTR [rbp-0x4]
  401256:  shl    eax,0x5                         ; delta << 5 = delta*32
  401259:  mov    DWORD PTR [rbp-0xc],eax         ; sum 初值 = 0xC6EF3720
```

==看到 `0xC6EF3720` 或 `delta << 5`，这是解密函数==；`+=` 全换 `-=`、两行轮函数对调、sum 递减，就是完整逆过程。

### 5.2 三兄弟结构差异

| | TEA | XTEA | XXTEA |
| ---- | ---- | ---- | ---- |
| 块长 | 8 字节 | 8 字节 | 8 字节起步，4 字节粒度可变（`n` 个 `uint32`） |
| 轮函数 | `(v1<<4)+k0` 三项异或 | `((v1<<4)^(v1>>5))+v1` | MX 宏，`z`/`y` 是滚动邻居 |
| 密钥用法 | 固定 `k0..k3` 各对应一项 | `key[sum & 3]` 与 `key[(sum>>11) & 3]` | `key[(p & 3) ^ e]`，`e=(sum>>2)&3` |
| 轮数 | 固定 32 | 可变（默认 32） | `6 + 52/n`，随块长变 |
| 识别要点 | 魔数 + 固定密钥项 | 魔数 + sum 决定密钥下标 | 魔数 + `(p&3)^e` + 块长可变 |

XTEA 把"加法"换成"移位异或后再加自身"，并让 sum 的位决定本轮用哪个密钥字；XXTEA 把整个消息当一个块处理，轮函数里的 `z`、`y` 是相邻两个字的滚动窗口。逆推时==先按魔数定家族，再照下表抄参数==。

### 5.3 Python 实现与逆推

Python 没有天然 32 位溢出，==每个加法、左移之后都要 `& 0xFFFFFFFF`==，这是 Python 实现 TEA 系对不上 C 结果的第一原因：

```python
M = 0xFFFFFFFF
DELTA = 0x9E3779B9

def tea_enc(v, k, rounds=32):
    v0, v1, s = v[0], v[1], 0
    for _ in range(rounds):
        s = (s + DELTA) & M
        v0 = (v0 + (((((v1 << 4) & M) + k[0]) & M) ^ ((v1 + s) & M) ^ ((((v1 >> 5)) + k[1]) & M))) & M
        v1 = (v1 + (((((v0 << 4) & M) + k[2]) & M) ^ ((v0 + s) & M) ^ ((((v0 >> 5)) + k[3]) & M))) & M
    return [v0, v1]

def tea_dec(v, k, rounds=32):
    v0, v1 = v[0], v[1]
    s = (DELTA * rounds) & M
    for _ in range(rounds):
        v1 = (v1 - (((((v0 << 4) & M) + k[2]) & M) ^ ((v0 + s) & M) ^ ((((v0 >> 5)) + k[3]) & M))) & M
        v0 = (v0 - (((((v1 << 4) & M) + k[0]) & M) ^ ((v1 + s) & M) ^ ((((v1 >> 5)) + k[1]) & M))) & M
        s = (s - DELTA) & M
    return [v0, v1]

v = [0x01234567, 0x89ABCDEF]
k = [0x11111111, 0x22222222, 0x33333333, 0x44444444]
c = tea_enc(v, k)
print("python tea_enc:", f"{c[0]:08x}{c[1]:08x}")
print("python tea_dec:", "".join(f"{x:08x}" for x in tea_dec(c, k)))
```

```python
def xtea_enc(v, key, rounds=32):
    v0, v1, s = v[0], v[1], 0
    for _ in range(rounds):
        v0 = (v0 + ((((((v1 << 4) & M) ^ (v1 >> 5)) + v1) & M) ^ ((s + key[s & 3]) & M))) & M
        s = (s + DELTA) & M
        v1 = (v1 + ((((((v0 << 4) & M) ^ (v0 >> 5)) + v0) & M) ^ ((s + key[(s >> 11) & 3]) & M))) & M
    return [v0, v1]

def xtea_dec(v, key, rounds=32):
    v0, v1 = v[0], v[1]
    s = (DELTA * rounds) & M
    for _ in range(rounds):
        v1 = (v1 - ((((((v0 << 4) & M) ^ (v0 >> 5)) + v0) & M) ^ ((s + key[(s >> 11) & 3]) & M))) & M
        s = (s - DELTA) & M
        v0 = (v0 - ((((((v1 << 4) & M) ^ (v1 >> 5)) + v1) & M) ^ ((s + key[s & 3]) & M))) & M
    return [v0, v1]

def mx(z, y, s, p, e, key):
    return ((((z >> 5) ^ ((y << 2) & M)) & M) + (((y >> 3) ^ ((z << 4) & M)) & M)) & M \
        ^ (((s ^ y) + (key[(p & 3) ^ e] ^ z)) & M)

def btea_enc(v, key):                      # XXTEA，v 是 n 个 uint32 组成的列表
    n = len(v)
    rounds = 6 + 52 // n
    s, z = 0, v[n - 1]
    for _ in range(rounds):
        s = (s + DELTA) & M
        e = (s >> 2) & 3
        for p in range(n - 1):
            y = v[p + 1]
            v[p] = (v[p] + mx(z, y, s, p, e, key)) & M
            z = v[p]
        y = v[0]
        v[n - 1] = (v[n - 1] + mx(z, y, s, n - 1, e, key)) & M
        z = v[n - 1]
    return v

def btea_dec(v, key):
    n = len(v)
    rounds = 6 + 52 // n
    s = (rounds * DELTA) & M
    y = v[0]
    for _ in range(rounds):
        e = (s >> 2) & 3
        for p in range(n - 1, 0, -1):
            z = v[p - 1]
            v[p] = (v[p] - mx(z, y, s, p, e, key)) & M
            y = v[p]
        z = v[n - 1]
        v[0] = (v[0] - mx(z, y, s, 0, e, key)) & M
        y = v[0]
        s = (s - DELTA) & M
    return v

xc = xtea_enc(v, k)

print("xxtea roundtrip:", btea_dec(cc[:], k) == blk)
```

> [!warning] TEA 系对不上答案的四个高频原因
> ① 字节序：伪代码里的 `uint32` 是按小端从内存取的，密文 8 字节要 `struct.unpack('<2I', data)` 而不是按大端切；② 密钥形态：题目 key 是 ASCII 串（如 `b"thisiskey"`）还是 16 字节 hex，先分清再切四个 `uint32`；③ 轮数被改：出题人常把 32 改成 16 或 64，==轮数要跟伪代码里 cmp 的常数走==；④ 溢出：Python 侧漏掉任何一处 `& 0xFFFFFFFF`，第一轮就会跑偏。delta 换成别的值同理——一切以伪代码为准。

> [!info]- TEA 家族的密码学弱点（了解即可）
> TEA 存在相关密钥攻击（等价密钥对），XTEA 与 XXTEA 是官方修补。CTF 里极少要求数学破译，==考点始终是"认出结构、抄对参数、逆推"==；真遇到弱化版（轮数砍到个位数），也可用其结构不对称性做差分分析，但那是 crypto 方向的进阶内容。

## 6. RC4：256 次打乱加吐字节

RC4 是流密码：用密钥把 0–255 打乱成一个状态表，之后每输出一个字节就再交换一次，从表里取字节与明文异或。伪代码特征极强，==看到"256 次循环填表 + 两个下标交换 + `& 0xff`"就是 RC4==：

```python
def rc4(key: bytes, data: bytes) -> bytes:
    S = list(range(256))
    j = 0
    for i in range(256):                                  # KSA：用密钥打乱 S 盒
        j = (j + S[i] + key[i % len(key)]) & 0xFF
        S[i], S[j] = S[j], S[i]
    out = bytearray()
    i = j = 0
    for c in data:                                        # PRGA：吐密钥流并异或
        i = (i + 1) & 0xFF
        j = (j + S[i]) & 0xFF
        S[i], S[j] = S[j], S[i]
        out.append(c ^ S[(S[i] + S[j]) & 0xFF])
    return bytes(out)

print("key='Key'    pt='Plaintext'    ct =", rc4(b"Key", b"Plaintext").hex())
print("key='Wiki'   pt='pedia'       ct =", rc4(b"Wiki", b"pedia").hex())
print("keystream(key='Key', 8B)         =", rc4(b"Key", b"\x00" * 8).hex())
ct = rc4(b"Key", b"Plaintext")
print("同 key 再异或一次:", rc4(b"Key", ct))
```

输出：

```
key='Key'    pt='Plaintext'    ct = bbf316e8d940af0ad3
key='Wiki'   pt='pedia'       ct = 1021bf0420
keystream(key='Key', 8B)         = eb9f7781b734ca72
同 key 再异或一次: b'Plaintext'
```

前两行是公开的标准测试向量，可以用来确认自己的实现没有写错。第三行展示了流密码的本质：加密全零串得到的就是纯密钥流。第四行说明==加解密是同一个函数==——密文再过一遍 RC4 就回到明文，解题脚本只需要一个函数。

对拍的参考形状（伪代码视角）：

```c
/* KSA：j 的更新里揉进了密钥；PRGA：i、j 轮流喂对方 */
for (i = 0; i < 256; i++) {
    j = (j + S[i] + key[i % keylen]) & 0xff;
    swap(S[i], S[j]);
}
for (每个字节) {
    i = (i + 1) & 0xff;
    j = (j + S[i]) & 0xff;
    swap(S[i], S[j]);
    out = in ^ S[(S[i] + S[j]) & 0xff];
}
```

> [!warning] RC4 题的三个坑
> ① 密钥是 `bytes` 不是 `str`：`rc4(b"Key", ...)`，`str` 要先 `encode()`；② drop 变体：有的实现丢弃密钥流前 N 字节（RC4-drop[256] 丢弃前 256 个），伪代码里表现为 PRGA 前多一个"空转循环"，照抄即可；③ 密钥长度不限：RC4 接受 1–256 字节密钥，看到 5 字节、13 字节的 key 都正常。

## 7. AES 与 DES：认常数、看分组

AES/DES 的内部结构不需要逆向选手掌握，[[09-密码学基础#3.3 分组密码与 ECB 的企鹅图|09 章 3.3]]已用"相同的明文分组得到相同的密文分组"讲清了 ECB 的泄漏方式。这一节全是==认==：认常数、认分组长度、认工作模式的后果。

### 7.1 常数特征与全盘搜索

| 常数 | 属于 | 长相 |
| ---- | ---- | ---- |
| S-box 首行 `63 7C 77 7B F2 6B 6F C5 30 01 67 2B FE D7 AB 76` | AES 替换层 | 256 字节表，首字节 `0x63` |
| 表首项 `0xC66363A5` | AES T-table（Te0） | 512 字节（4 列×128 项）或 1024 字节表 |
| PC1 首行 `57 49 41 33 25 17 09` | DES 密钥调度 | 56 项的置换表，最大值 60 以内 |
| `0x67452301 0xEFCDAB89 0x98BADCFE 0x10325476` | MD5 / SHA1 初始 IV | 四个 32 位常数 |
| `0x6A09E667`（IV）、`0x428A2F98`（轮常数） | SHA256 | 常在展开的哈希函数里 |

T-table 首项 `0xC66363A5` 里就藏着 S-box：它的四个字节是 `(2·sbox[0], sbox[0], sbox[0], 3·sbox[0])`（乘法在 GF(2⁸) 上），所以 `c6 = 2×63`、`a5 = 3×63`。==软件实现的 AES 常把 SubBytes、ShiftRows、MixColumns 合并成查 T-table==，所以有的二进制里没有裸 S-box、只有大表——两种形态都要会认。

拿到一个二进制，直接按字节序列搜，比肉眼翻数据区快得多。下面在一个真实的密码库模块上示范（换成题目文件时把读文件那行换成 `open("chall","rb").read()` 即可）：

```python
import struct
import Crypto.Cipher, pathlib

SO_DIR = pathlib.Path(Crypto.Cipher.__file__).parent

TE0_LE = bytes([0xA5, 0x63, 0x63, 0xC6])       # Te0 首项 0xC66363A5 的小端字节

print(f"在 {len(blob)//1024} KB 的 AES 模块里搜常数：")

print("  完整 S-box 前缀 63 7c 77 7b ->", "未找到" if blob.find(SBOX_HEAD) < 0 else hex(blob.find(SBOX_HEAD)))

print("  Te0 首项小端 a5 63 63 c6 -> 文件偏移", hex(off))
print("  该处 4 字节按小端整数读:", f"{struct.unpack('<I', blob[off:off+4])[0]:08x}")

PC1_HEAD = bytes([0x39, 0x31, 0x29, 0x21, 0x19, 0x11, 0x09])   # 57,49,41,33,25,17,9
blob_d = (SO_DIR / "_raw_des.abi3.so").read_bytes()
print(f"在 {len(blob_d)//1024} KB 的 DES 模块里搜常数：")
print("  DES PC1 前 7 字节 39 31 29 21 19 11 09 -> 文件偏移", hex(blob_d.find(PC1_HEAD)))
```

输出：

```

  完整 S-box 前缀 63 7c 77 7b -> 未找到
  Te0 首项小端 a5 63 63 c6 -> 文件偏移 0x6440
```

结果印证了上面的说法：这个 AES 实现只存 T-table（裸 S-box 搜不到），DES 的 PC1 表原样躺在数据区。搜索时注意==表项的字节序==：`0xC66363A5` 按小端落盘是 `a5 63 63 c6`，两个方向都搜一遍最稳妥。

> [!info]- 常数搜不到的三种情况
> ① 编译器把常数拆进指令流或用移位组合拼出（`0x9E3779B9` 在 -O1 下可能被折叠进 sum 的预计算）；② 表在运行时生成（S-box 可以由 GF(2⁸) 求逆加仿射变换现算），静态搜不到就动态断点抓；③ 走了硬件指令：x86 的 AES-NI 提供 `aesenc`/`aesdec` 指令，反汇编里没有任何表和轮循环，只有一串 `aesenc xmm0, xmm1`——看到这组指令直接判 AES。

### 7.2 分组长度与 ECB 重复块

密文长度本身就是识别信息：==8 的倍数指向 DES/TEA 系（8 字节块），16 的倍数指向 AES（16 字节块）==。工作模式的判断看重复：ECB 模式下相同明文块的密文块相同，把密文按块切开比对即可，不需要密钥：

```python
from Crypto.Cipher import AES, DES

key = bytes(range(16))
bA = b"USERNAME=alice; "                    # 16 字节
bB = b"ROLE=user;SIGN=X"                    # 16 字节
pt = bA + bB + bA
ecb = AES.new(key, AES.MODE_ECB).encrypt(pt)
cbc = AES.new(key, AES.MODE_CBC, iv=b"\x00" * 16).encrypt(pt)
print("明文 3 块: 第 0 块 == 第 2 块 =", bA)
print("ECB 密文块:")
for i in (0, 16, 32):
    print(f"  块{i//16}: {ecb[i:i+16].hex()}")
print("CBC 密文块:")
for i in (0, 16, 32):
    print(f"  块{i//16}: {cbc[i:i+16].hex()}")
print("ECB 块0==块2:", ecb[0:16] == ecb[32:48], " CBC 块0==块2:", cbc[0:16] == cbc[32:48])
```

```
  块2: 1766609746e3a9b64082b01bae6841d7
```

### 7.3 CBC 字节翻转

CBC 的解密规则是一切的基础：

$$P_i = D(C_i) \oplus C_{i-1} \tag{3}$$

第一块用 IV 顶替 $C_0$。$D(C_i)$ 动不了（没有密钥），但 $C_{i-1}$ 是密文，就在手里——==把 $C_{i-1}$ 的某个字节异或上差值，$P_i$ 的同位置字节就跟着翻转==。[[09-密码学基础#3.4 CBC 字节翻转|09 章 3.4]]用手写的分组密码演示过原理，这里在真 AES 上走一遍，攻击步骤完全相同：

```python
from Crypto.Cipher import AES

key = b"0123456789abcdef"
iv = b"\x00" * 16
pt = b"PAY=100;;;;;;;;;" + b";ADMIN=0;;;;;;;;"          # 两块，各 16 字节
ct = AES.new(key, AES.MODE_CBC, iv).encrypt(pt)
tampered = bytearray(ct)
tampered[7] ^= 1                                        # '0' ^ '1' = 0x01
pt2 = AES.new(key, AES.MODE_CBC, iv).decrypt(bytes(tampered))
print("原明文:", pt[:16], pt[16:])
print("翻转 C1[7] 后解出:", pt2[:16], pt2[16:])
```

输出：

```
原明文: b'PAY=100;;;;;;;;;' b';ADMIN=0;;;;;;;;'
翻转 C1[7] 后解出: b"\x0b/\xd3'\xbcCTi\xb8\x83\x0e\x14\xe5\x9a\x02\xe7" b';ADMIN=1;;;;;;;;'
```

第 2 块的 `0` 变成 `1`，代价是第 1 块解密成了乱码（$C_1$ 同时是第 1 块解密的输入）。==攻击适用条件：服务端只校验第 2 块的内容，不在乎第 1 块烂掉==——出题人把"上一块乱码"当正常现象放行时才有机会。目标块是第 1 块时，翻转对象换成 IV，同样成立。

DES 的题做法相同，只是块长换成 8、密钥 8 字节：

```python
from Crypto.Cipher import DES

dk = b"8bytekey"
d = DES.new(dk, DES.MODE_ECB).encrypt(b"flagdes!")   # 明文必须凑满 8 的倍数
print(d.hex(), len(d), "字节")
```

输出：

```
d8b30b0ef725c47f 8 字节
```

> [!warning] 库函数的报错本身就是参数提示
> `AES.new(b'short', AES.MODE_ECB)` 会直接报 `ValueError: Incorrect AES key length (5 bytes)`——AES 只接受 16/24/32 字节密钥；ECB/CBC 的 `encrypt` 报 `Data must be aligned to block boundary in ECB mode` 说明明文没凑满块长。==报错信息把正确的参数要求原样告诉你了==，逆推密钥长度时先让程序自己报一遍。

## 8. 哈希与编码链：剥层

### 8.1 哈希的认法

哈希不可逆（[[09-密码学基础#4. 哈希|09 章第 4 节]]），逆向题里它几乎总是当==校验器==出现：程序算出输入的 MD5 与常量比对，你不需要"解密"哈希，只需要认出它是哈希、找到原始输入。认法靠输出长度与字符集：

```python
import hashlib, base64

for name in ("md5", "sha1", "sha256"):
    h = hashlib.new(name, b"flag").hexdigest()
    print(f"{name:7} len={len(h):3}  {h}")
md5b64 = base64.b64encode(hashlib.md5(b"flag").digest()).decode()
print("md5 摘要转 base64:", md5b64, "len =", len(md5b64))
```

输出：

```
md5     len= 32  327a6c4304ad5938eaf0efb6cc3e53dc
sha1    len= 40  112f3a99b283a4e1788dedd8e0e5d35375c33747
sha256  len= 64  807d0fbcae7c4b20518d4d85664f6820aafdf936104122c5073e7744c46c4b87
md5 摘要转 base64: MnpsQwStWTjq8O+2zD5T3A== len = 24
```

| 长度（hex 字符） | 32 | 40 | 56 | 64 | 96 | 128 |
| ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| 候选 | MD5 | SHA1 | SHA224 | SHA256 | SHA384 | SHA512 |

摘要也常以 16 字节原始二进制或 base64 形式存进常量表：24 位、以 `==` 结尾的 base64 解出 16 字节，先试 MD5。0e 魔术哈希、长度扩展这些"哈希当靶子"的打法归 crypto，见 [[09-密码学基础#4.4 CTF 哈希题套路|09 章 4.4]]。

加盐的表现：`md5(salt + password)`。盐不告诉你，字典爆破永远对不上——==先去字符串窗口翻常量串==，可疑的短串拼进候选重算即可：

```python
salt = b"s@lt_2026"
pwd = b"admin123"
print("md5(salt+pwd) =", hashlib.md5(salt + pwd).hexdigest())
```

输出：

```

```

### 8.2 多层嵌套的逐层剥离

flag 题的常见形态是编码、加密、哈希叠在一起：外层 base64、中层 hex、内层 XOR，末尾再挂一个哈希前缀做校验。剥层流程固定：==每剥一层，先看剥出来的东西像不像下一层的字符集，再决定下一刀==；哈希校验最后用来确认结果：

```python
import hashlib, base64

flag = b"flag{lay3rs_0n_lay3rs}"
key = bytes([0x5A, 0x3C, 0x17, 0x9E])
xored = bytes(b ^ key[i % 4] for i, b in enumerate(flag))
layer_hex = xored.hex().encode()
layer_b64 = base64.b64encode(layer_hex).decode()
blob = layer_b64 + "$" + hashlib.md5(flag).hexdigest()[:8]   # 题面给的串
print("题目给的串:", blob)

body, check = blob.split("$")
step1 = base64.b64decode(body)
print("第 1 层 base64 ->", step1[:40], "...")
step2 = bytes.fromhex(step1.decode())
print("第 2 层 hex    ->", len(step2), "字节二进制，不是文本")
key_guess = bytes([0x5A, 0x3C, 0x17, 0x9E])
step3 = bytes(b ^ key_guess[i % 4] for i, b in enumerate(step2))
print("第 3 层 XOR    ->", step3.decode())
print("md5 校验:", hashlib.md5(step3).hexdigest()[:8], "==", check,
      "->", hashlib.md5(step3).hexdigest()[:8] == check)
```

输出：

```
题目给的串: M2M1MDc2ZjkyMTUwNzZlNzY5NGU2NGMxNmE1MjQ4ZjIzYjQ1MjRlYzI5NDE=$662a1465
第 1 层 base64 -> b'3c5076f9215076e7694e64c16a5248f23b4524ec' ...
第 2 层 hex    -> 22 字节二进制，不是文本
第 3 层 XOR    -> flag{lay3rs_0n_lay3rs}
md5 校验: 662a1465 == 662a1465 -> True
```

内层 XOR 的密钥从哪来：逆向题里它就在伪代码里（4 字节常量数组），misc 题里靠 `flag{` 已知明文异或密文推出（第 3 节的方法）。自动剥层骨架 [[08-编码与古典密码#7. 编码链识别与剥层|08 章 7 节]]给过一个，第 9 节把它收进武器库。

## 9. 实战落地：维护一套算法武器库

每个算法手写过一遍后，把代码沉淀成固定结构，比赛时只做两件事：认出算法、抄进现成函数。武器库的三条组织原则：

- ==一个算法一个文件==，文件里有 `NAME`、`selftest()`、`cli()` 三件套；
- ==自测用公开测试向量或与参考实现对拍的值==，改坏了立刻能发现；
- 入口脚本自动发现模块，一条命令跑全部自测，命令行参数原样转发给对应模块。

目录结构：

```
arsenal/
├── arsenal.py          # 统一入口：selftest + 命令行转发
└── algos/
    ├── __init__.py
    ├── base_family.py  # base 编解码与剥层
    ├── xor_tools.py    # XOR 三件套
    ├── rc4.py          # RC4
    └── tea.py          # TEA / XTEA / XXTEA
```

入口 `arsenal.py` 全文：

```python
#!/usr/bin/env python3
"""arsenal.py —— 算法武器库统一入口
用法:
  python3 arsenal.py selftest            # 跑全部模块自测
  python3 arsenal.py <模块名> <参数...>   # 转发给该模块的 cli()
"""
import importlib
import pathlib
import sys

ALGOS = {}
for f in sorted((pathlib.Path(__file__).parent / "algos").glob("[!_]*.py")):
    m = importlib.import_module(f"algos.{f.stem}")
    ALGOS[getattr(m, "NAME", f.stem)] = m

def selftest():
    bad = []
    for name, m in ALGOS.items():
        try:
            m.selftest()
            print(f"{m.NAME:<12} OK")
        except Exception as e:
            bad.append(name)
            print(f"{m.NAME:<12} FAIL: {e}")
    sys.exit(1 if bad else 0)

def main():
    if len(sys.argv) >= 2 and sys.argv[1] == "selftest":
        return selftest()
    if len(sys.argv) < 2 or sys.argv[1] not in ALGOS:
        print("可用模块:", " ".join(ALGOS))
        sys.exit(2)
    ALGOS[sys.argv[1]].cli(sys.argv[2:])

if __name__ == "__main__":
    main()
```

模块样板 `algos/xor_tools.py` 全文——接口约定就三条：`NAME` 是命令行里的模块名，`selftest()` 里放测试向量，`cli()` 解析自己的参数：

```python
"""xor_tools —— XOR 三件套：定长 key、单字节爆破、rolling"""
NAME = "xor"

def xor_bytes(data: bytes, key: bytes) -> bytes:
    return bytes(b ^ key[i % len(key)] for i, b in enumerate(data))

def rolling_xor(data: bytes, start: int, step: int = 1) -> bytes:
    return bytes(b ^ ((start + i * step) & 0xFF) for i, b in enumerate(data))

def brute_single(ct: bytes):
    """按可打印性粗筛，返回全部候选 (key, 明文)"""
    out = []
    for k in range(256):
        pt = bytes(b ^ k for b in ct)
        if all(32 <= b < 127 for b in pt):
            out.append((k, pt))
    return out

def selftest():
    assert xor_bytes(b"abc", b"\x20") == b"ABC"
    assert rolling_xor(b"\x00\x00\x00", 0x25) == bytes([0x25, 0x26, 0x27])
    hits = brute_single(bytes(b ^ 0x37 for b in b"hello"))
    assert any(k == 0x37 and pt == b"hello" for k, pt in hits)

def cli(args):
    """xor dec <hex密文> <hex密钥> | xor rolling <hex密文> <起点十进制>"""
    if args[0] == "dec":
        print(xor_bytes(bytes.fromhex(args[1]), bytes.fromhex(args[2])))
    elif args[0] == "rolling":
        print(rolling_xor(bytes.fromhex(args[1]), int(args[2])))
```

## 10. 常见问题

| 现象 | 原因与解决 |
| ---- | ---- |
| base64 按标准表解出乱码，但字符集就是那 64 个 | 换表 base64。先枚举 64 种旋转（[[#2. Base 家族：padding、长度与换表\|2.1]]），不行就去伪代码里抄表，或用已知明文恢复 |
| base32 串被当 base64 解出垃圾 | 字符集重叠导致误判。剥层器按"hex → base32 → base64"的顺序试，且 base32 只在长度为 8 的倍数、字符集全大写时才试 |
| Python 的 TEA 与 C 结果对不上 | 四个高频原因见 [[#5. TEA、XTEA、XXTEA：一个魔数定三家\|5.3 的 warning]]：字节序、密钥形态、轮数被改、漏 `& 0xFFFFFFFF` |
| TEA 解出乱码但算法认对了 | 轮数或 delta 与伪代码不一致；解密侧 sum 初值必须是 `轮数 × delta`，不是固定 `0xC6EF3720`（轮数被改时该值也变） |
| XXTEA 换了块长就解不对 | 轮数 `6 + 52/n` 与块长绑定，加解密两侧块长必须一致；解密循环从后往前、sum 从终点递减 |
| RC4 解出乱码 | 密钥传成了 str、或题目是 drop 变体（丢弃前 N 字节密钥流）；对照伪代码逐条抄 KSA/PRGA |
| AES 报 `Incorrect AES key length` | 密钥不是 16/24/32 字节。出题人的 key 常是 16 字符 ASCII 串或 hex 转的 16 字节，先分清 |
| ECB 密文没发现重复块 | 不能证明不是 ECB——可能明文块本身不重复。结构固定的数据（模板 JSON、位图）才有可观察的重复 |
| CBC 翻转后目标字节没变 | 改错了块：$P_i$ 依赖 $C_{i-1}$，要改的是目标块的前一块；目标是第一块时改 IV。改完目标块，前一块的解密结果必然乱掉，属于预期 |
| 加盐哈希怎么都爆不出来 | 盐在程序里。字符串窗口找常量串，或断在哈希函数入口看实际输入 |
| 伪代码里看不到 AES 的表和轮循环 | 走了 AES-NI 指令（`aesenc`/`aesdec`），或查表逻辑在动态库里。全盘搜常数（7.1）或确认导入表 |
| 常数全盘搜索也搜不到 | 表在运行时生成（S-box 可现算）、或常数被编译器折叠（-O1 下 delta 可能被预计算）。改用动态断点从内存抓 |
| 单字节 XOR 爆出多个可读候选 | 取卡方分最小的，再用语义确认（flag 题 `flag{` 开头优先）；明文不是英文时换频率表 |
| 装不上 pycryptodome | `pip3 install --user --break-system-packages pycryptodome`；装不上时本章的 XOR/TEA 系/RC4/Base/哈希全部只需标准库 |
