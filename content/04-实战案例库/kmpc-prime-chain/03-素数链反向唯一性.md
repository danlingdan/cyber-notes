算法还原完了，坏消息摆在桌面上：链长 v 是 `rand()` 给的，种子不知道；每步的 j 也已经丢掉了，`result.txt` 里只剩链尾 q。顺推是不行了。这一章回答一个问题——**从 q 出发，能不能确定性地一步步退回链头 p**。

## 链的一步在代数上是什么

把 KMPC 的一步 `t ← t·j + 1` 移一下项：

```
q − 1 = j × t        （q 是新的一环，t 是上一环，t 是素数，j ≤ 65536 的小偶数）
```

正向走这一步很容易：手里有 t，从小到大试 j，每个候选做一次素性检验，平均试 ln(t)/2 次。反向的处境是：手里只有 q，知道 `q − 1 = j × t`，但 j 和 t 都不知道——问题变成"q − 1 的哪个因子是上一环"。

```
p ──×j₁+1──> ×j₂+1──> ×j₃+1──> ... ──×jₙ+1──> q

每一步：  qₖ − 1 = jₖ · qₖ₋₁
```

> [!important]- 反向唯一的论证
> 假设同一个 q 有两种退法：`q − 1 = j·P = j′·P′`，其中 P ≠ P′ 都是素数，j、j′ 都 ≤ 65536。不妨设 P > P′。从 `j·P = j′·P′` 看，P 整除右边的 `j′·P′`；P 是素数且 P ≠ P′，所以 **P 必须整除 j′**。但 P 是链上的上一环，除链头附近几层外都在 2³² 以上，而 j′ ≤ 65536——P > j′，整除不可能成立。矛盾。
> 所以**满足"除出来是素数"的小因子 j 至多一个**。找到它，就找到了上一环，没有歧义。

推论里那个"链上每环 > 2³²"依赖明文是可见 ASCII：每块 4 字节首字节 ≥ 0x21，所以链头 m > 0x21212121 ≈ 2²⁹，p = nextprime(m) 更大，翻三番就越过 2³²。从 q（近两千位）往回退时，前面两百来层全在 2³² 以上，唯一性铁得很；真正需要留神的是链头附近最后两三层。

## 链尾附近：别赌唯一性，用 DFS 兜底

链头附近的 t 只有 2³⁰ 上下的量级，`t − 1` 理论上可能同时存在两种"小因子 × 半大素数"的拆法（上面的论证要求大因子 > 65536，在 2³⁰ 附近不再显然）。处理方式很简单：**不赌**。每一层把所有候选都收进搜索，错的分支退一两层就会撞墙（除出来的不是素数，或者终点校验不过），自动回溯：

```
dfs(t):
    若 t < 2^33：试 m = t − diff_i，校验 0 ≤ m < 2^32 且 nextprime(m) == t，
                通过 → 返回链头
    对 (t−1) 的每个小因子 j：
        tp = (t−1) / j
        若 tp 变小且是素数 → dfs(tp)
```

实测 20 块的搜索全部走的是唯一分支，DFS 的兜底一次都没真正派上用场——但写不写它，是"碰巧能跑"和"结构上正确"的区别。

## 往哪儿退是头：diff 当对账单

链头 p = nextprime(m)，m 是 32 位整数，所以 **p < 2³² + 一个素数间隔 < 2³³**。回退过程中一旦 t < 2³³，就进入候选区：试 `m = t − diff_i`，校验 `0 ≤ m < 2³²` 且 `nextprime(m) == t`。两条都过，这块就解完了。

> [!info]- 为什么 2³³ 当阈值是安全的
> m 最大 0xFFFFFFFF，比它大的下一个素数离它不超过几百（32 位附近的素数间隔远小于 2³²），所以链头必然在 2³³ 以内。阈值取大了的代价只是多试几次无果的终点校验——校验是确定性的，假链头混不进来。

> [!tip]- diff 这行小数字是出题人送的对账单
> 第一眼看到 `result.txt` 里 20 个 ≤ 30 的小整数，很难猜它是什么。还原完算法回头看：diff = nextprime(m) − m，只由明文决定，和随机量无关。它的价值在解密端——没有它，你把链退到 2³³ 以下后，还要在成千上万个素数里猜哪个是链头；有它，链头变成可判定的：`t − diff` 得落在 32 位内、而且减完恰好使 t 是下一个素数。逆向题里"多出来的一行输出"几乎总是这个用途：**给验证留接口**。

## 实现两件套

### 一次 gcd 收齐全部小因子

每层要枚举 `t − 1` 的全部因子 j（j ≤ 65536）。t − 1 是近两千位的大数，对它直接试除到 65536 要六千多次大数取模，不划算。用 gcd 一次到位：

```python
L = lcm(1, 2, 3, ..., 65536)        # 预计算一次，约 9600 位
g = gcd(t - 1, L)                   # 一次大数 gcd
# t-1 的所有 ≤ 65536 的因子，全部来自 g 的因子组合
# g 比 L 小得多，对 g 做普通试除分解，再枚举全部因子
```

> [!info]- 为什么 gcd 一下就够
> 一个数 n 的"不超过 65536 的因子"，恰好由 n 里所含的小素数幂决定；而 L = lcm(1..65536) 收纳了每个小素数的满额幂次。`gcd(n, L)` 把 n 的小素数部分整个截下来——n 的大素数因子（上一环 t）一个都进不来。之后的工作全在几百位以内的 g 上做，试除和枚举因子都是小数运算。

### 素性检验：小素数试除 + 12 基 Miller-Rabin

求解脚本里的 `is_prime` 是自实现的：先用 47 以内的素数试除筛掉明显的合数，再跑 12 个固定基的 Miller-Rabin。

> [!info]- Miller-Rabin 30 秒版
> 基于两条事实：`a^(n-1) ≡ 1 (mod n)`（费马小定理，n 为素数时），以及 1 的平方根在模素数世界只能 ±1（二次探测）。把 n−1 拆成 `2^s·d`，检验 `a^d` 出发平方开上去的序列，不合规矩就宣布合数。单轮误判率 < 1/4，12 个固定基联合误判率 < 4⁻¹² ≈ 6×10⁻⁸，而且本题就算某一步误判，下一层的素性检验或终点校验也会把这个错误分支淘汰——错误不累积。

> [!warning]- 自实现 nextprime 要留个心眼
> 终点校验里用到了 `nextprime(m) == t`，这是自己写的函数，而 GMP 的 `mpz_nextprime` 有自己的素性判据（内部也是 Miller-Rabin，参数不同）。两边判法如果在对某个边界数上不一致，校验会偶发失败。本题 20 块全部对上，没踩到坑；写通用工具时值得在 2³² 附近抽查对拍，或直接用 gmpy2 统一两边。

到此数学部分齐了：回退方向唯一（2³² 以上严格成立）、终点可判定（diff + nextprime 校验）、每层代价可控（一次 gcd + 少量 MR）。下一章把这些落成代码。
