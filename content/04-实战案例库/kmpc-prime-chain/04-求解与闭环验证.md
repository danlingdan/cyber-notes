前两章的数学和算法结构落成 `solve_kmpc.py`，150 行，纯 Python 标准库。结构总览：

```
is_prime(n)             47 以内小素数试除 + 12 基 Miller-Rabin
next_prime(n)           从 n 往上找素数（只用在 < 2^33 的小数区）
small_multipliers(n)    gcd(n, lcm(1..65536)) → 试除分解 → 枚举全部小因子
solve_block(q, diff)    DFS 回退素数链，终点用 diff + nextprime 校验
main                    解析 result.txt → 20 块回退 → 按 4 字节拼明文
```

## solve_block：搜索骨架

```python
SIZE_LIMIT = 1 << 33          # 链头必然小于 2^33

def solve_block(q, diff):
    def dfs(t):
        if t < SIZE_LIMIT:                        # 进入链头候选区
            m = t - diff
            if 0 <= m < (1 << 32) and next_prime(m) == t:
                return m                          # 终点校验通过
        for j in small_multipliers(t - 1):        # t-1 的全部小因子（升序）
            tp = (t - 1) // j
            if tp > 2 and tp.bit_length() < t.bit_length() and is_prime(tp):
                r = dfs(tp)                       # 退一层
                if r is not None:
                    return r                      # 这条支路通了
        return None                               # 全部候选失败，自动回溯
    return dfs(q)
```

> [!info]- 三个条件各拦什么
> - `tp.bit_length() < t.bit_length()`：链上每步至少翻倍（j ≥ 2），上一层必须严格小于当前层。这一刀顺手把 j=1 的平凡候选（tp = t−1，几乎不缩小）筛掉
> - `is_prime(tp)`：反向唯一的判据本体——除出来必须是素数才有资格当上一环
> - 终点的 `next_prime(m) == t`：diff 只保证了"t − diff 是个 32 位数"，还得确认 t 真是它的下一个素数，链头才算找对

> [!info]- DFS 在防什么
> [[03-素数链反向唯一性]] 的唯一性论证在 t > 2³² 的区域严格成立，但链头附近最后两三层只有 2³⁰ 量级，理论上存在多种拆法。DFS 把每层的全部候选都试一遍：错分支要么下一层除不出素数，要么终点校验不过，代价一两层就死。实测 20 块全都走唯一分支，兜底没真正触发——这是结构正确的成本，不是浪费。

`main` 部分是管道胶水：读 `result.txt` 两行，`ast.literal_eval` 解析成整数列表，断言各 20 个，逐块求解后 `m.to_bytes(4, 'big')` 拼接。每块求解前先断言 `is_prime(q)`——链尾必须是素数，这条对 result.txt 本身的健全性检查零成本，能第一时间发现"文件抄错一位"这类事故。


> [!info]- 逐列读这份输出
> - `steps`：DFS 进入的层数，等于链长（v−1）加 1。20 块全部落在 169–230，和 [[02-还原加密算法]] 推导的 v−1 ∈ [135, 272] 相容；均匀性也符合直觉——v 的三个成分里 rand()%65 只贡献 ±32 的抖动
> - `pp`：链头素数，而 `pp − m` 应当正好等于该块的 diff。抽第 0 块验证：`m = 0x666c6167` 的十进制是 1718378855（这种转换交给脚本/计算器，口算十六进制必错），`1718378861 − 1718378855 = 6 = diff[0]` ✓。脚本里每块都有这条断言，链头找错当场就报
> - `m=0x666c6167`：ASCII 直接可读，f/l/a/g。最后一块 `0x31306e7d` = `10n}`，收尾的右括号在，拼出来的 flag 结构完整

> [!example]- 82 秒花在哪，怎么更快
> 每层一次大数 gcd（九千多位的 L 参与运算）、每层若干次近两千位数的 Miller-Rabin。Python 的大整数运算走 CPython 的手写实现，比 GMP 慢一个数量级。换 gmpy2 的 `is_prime`/`next_prime`，预计 10 秒级；写成 C++ 直接调 GMP，能贴着正向加密的速度。纯标准库版本的意义是零依赖、随处可跑——82 秒对打题来说完全够用。

## 闭环验证：让加密器自己认账

解出来不算完。最硬的验证是把 flag 喂回 KMPC 本体，看它吐出的 diff 行和题目给的是不是同一份：

```
$ mkdir /tmp/kmpc && cd /tmp/kmpc
$ printf '%s' "flag{Y0u_oU_u_4rE_Re_3_Go0d_OoD_0d_D_47_t_l1bgMp_4Nd_7h15_4sYmM3tr1c_3nCrYp710n}" \
      | /path/to/KMPC
input your message: Encryption finished.
$ head -1 result.txt
[6, 2, 8, 11, 30, 2, 8, 6, 15, 2, 14, 19, 9, 14, 14, 18, 20, 14, 6, 20]
```

与题目 `result.txt` 第 1 行一致。第 2 行（q 列表）和题目对不上——正常，这次运行的 `rand()` 种子是新的。

> [!important]- 为什么 diff 行能对上、q 行对不上
> diff = nextprime(m) − m，只由明文决定，是**确定性指纹**；q 经过 v−1 步随机长度的链，同一明文每次的密文都不同。这个不对称正好被验证利用：拿确定性部分逐字节对拍，随机部分直接忽略。反过来这也是逆向题通用的一条验证纪律——**能喂回原程序对拍的，就不要拿肉眼比对**。

> [!tip]- 这次对拍顺手赚到的两个情报
> - 程序是 getline 整行读入：另喂一次 `"ab cd"`（5 字符），diff 数组有 2 个元素——5 个字符被整行读走、补空格到 8。若是 `operator>>`，只会读到 `ab`，补到 4，diff 只有 1 个元素。一条管道命令区分两个库函数
> - 正向加密 80 字符实测 63 秒（GMP，C 代码）。比反向的 82 秒还快一点，但同量级——因为两边做的素性检验次数在数学上同阶，语言差异（C 对 Python）被算法差异（正向每步平均试几百个候选、反向每层只查几个因子）大幅抵消了

一键脚本 `reproduce_local.sh` 把"求解 → 提取 flag → 喂回加密器 → diff 行对拍"串起来：

```bash
$ KMPC_DIR=/path/to/ext.rev.not-symmetric bash reproduce_local.sh
[*] step 1: 反向走素数链求解
（20 块输出 + flag，同上）
[*] step 2: 闭环验证 —— 把 flag 喂回 KMPC 本体
[*] diff 行与题目 result.txt 逐字节一致，闭环通过
```
