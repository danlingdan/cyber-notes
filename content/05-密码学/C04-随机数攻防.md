# C04 随机数攻防

> [!info]- 章节信息

> **本章目标**：能讲清 MT19937 的 twist 与 tempering 两步结构，逐位手写 untemper；用 624 个连续输出克隆 CPython 的 random 生成器，预测 random() / randint / randbytes；观测不完整时用 z3 建模或 twist 关系补全；掌握 LCG 的三类参数恢复；认识 Java、glibc、node 侧生成器的同源攻击面；知道开发与出题两侧怎么防。

## 1. 两类随机：本章攻击的是"统计随机但可预测"

[[09-密码学基础#6. 随机数一瞥|09 章第 6 节]]已经划出两条界线：密码学要用 `os.urandom` / `secrets` 这类安全随机，Python 默认的 `random` 是梅森旋转（MT19937），可预测；固定种子和时间种子是两种最常见的事故。固定种子与时间种子覆盖的是"种子可猜"的情形。本章处理种子不可猜的情形：==种子取自系统熵，爆破种子这条路走不通，但生成器的结构漏洞照样把全部"随机"出卖==。

先把两类随机分开。真随机（`os.urandom`）每字节来自物理熵源，历史不决定未来；伪随机数生成器（PRNG）从一个**种子**出发，按固定算法推出整条序列——种子相同则序列逐位相同。统计测试只检查输出的分布像不像均匀随机，==分布像均匀随机与"不可预测"是两回事==：只要拿到生成器的内部状态（或足够多的输出），之后每一位都是确定的。

MT19937 的参数：状态是 624 个 32 位字（19968 位，其中 31 位恒为固定模式，有效状态 19937 位），周期 $2^{19937}-1$，输出通过一整套均匀性统计测试。它的弱点同样写在结构里：下一状态由当前状态完全决定，而输出与状态之间只隔一层可逆的位变换（第 2 节）。于是攻击面按"你手里有什么"分类：

| 你拿到的信息 | 攻击 | 出处 |
| ---- | ---- | ---- |
| 种子写死在代码里 | 直接重演整条序列 | [[09-密码学基础#6. 随机数一瞥\|09 章第 6 节]] |
| 种子 = 秒级时间戳 | 时间窗口爆破 | [[09-密码学基础#6. 随机数一瞥\|09 章第 6 节]] |
| 种子 = 进程号 / 小计数器 | 小空间枚举 | 本章 5.3 |
| 种子不可猜，但能拿到连续输出 | untemper 恢复状态，克隆生成器 | 本章 2–3 |
| 输出残缺（丢位 / 缺号） | z3 建模或 twist 关系补全 | 本章 4 |
| 换了生成器（LCG / Java / glibc） | 同思路的结构攻击 | 本章 6–7 |

> [!note] 版本背景
> 本章脚本按 Python 3.14 编写。CPython 的 `random.Random` 从 Python 2 一路到现在都是 MT19937（C 实现，`Lib/random.py` 只是外层封装），str/bytes 种子的转换路径见 5.2。Java 部分按 openjdk 21 的 `java.util.Random`。

## 2. MT19937：twist 与 tempering

MT19937 的全部行为由两步组成：**twist** 把 624 字的状态数组整体旋转成下一个状态；**tempering** 对每个被取出的字做四步位运算后输出。==tempering 的每一步都是可逆位运算==，这是整章攻击的前提。

### 2.1 状态数组与 twist

生成器保存 624 个 32 位字和一个读取位置。每次要输出时先看读取位置有没有走到数组末尾：没走到就直接取下一个字；走到了，先把整个数组旋转一遍（这一步叫 twist），再从头取。旋转规则：

$$y = (\text{mt}_i \,\&\, \mathtt{0x80000000}) \;|\; (\text{mt}_{(i+1) \bmod 624} \,\&\, \mathtt{0x7FFFFFFF}) \tag{4.1}$$

$$\text{mt}_i \leftarrow \text{mt}_{(i+397) \bmod 624} \,\oplus\, (y \gg 1) \,\oplus\, (\mathtt{0x9908B0DF}\cdot(y \,\&\, 1)) \tag{4.2}$$

式 (4.1) 把第 $i$ 个字的最高位和第 $i+1$ 个字的低 31 位拼成一个临时量 $y$；式 (4.2) 用 $y$ 右移一位、配上隔 397 个字的那个字，$y$ 的最低位是 1 时再异或常数 `0x9908B0DF`。624 个字都这样更新一遍，数组就变成下一轮的状态。对应的生成函数如下——它取自本章贯穿使用的最小类 `MT`（`self.mt` 存 624 字状态数组、`self.idx` 存读取位置；类壳与种子初始化在 5.1 给出），后续对拍脚本都从它 import：

```python
MASK32 = 0xFFFFFFFF
N, M = 624, 397          # 状态字数、twist 配对距离

def genrand(self):
    """产出一个 32 位输出；消耗到末尾才做一次 twist"""
    mt = self.mt
    if self.idx >= N:
        for i in range(N):
            y = (mt[i] & 0x80000000) | (mt[(i + 1) % N] & 0x7FFFFFFF)
            v = mt[(i + M) % N] ^ (y >> 1)
            if y & 1:
                v ^= 0x9908B0DF
            mt[i] = v & MASK32
        self.idx = 0
    y = mt[self.idx]
    self.idx += 1
    return temper(y)
```

### 2.2 tempering：输出前的四步位运算

状态字不直接输出，先过四步 tempering：

```python
def temper(y):
    """MT19937 输出前的 tempering，四步位运算"""
    y ^= y >> 11
    y ^= (y << 7) & 0x9D2C5680
    y ^= (y << 15) & 0xEFC60000
    y ^= y >> 18
    return y & MASK32
```

==只有两种积木：右移后异或、左移按掩码截断后异或==。每一步对一个 32 位数都是一一映射（下面构造出逆就证明了这一点），所以 tempering 可逆，==从输出能逐位算回状态字==。

### 2.3 两块积木的逆

记 $w = 32$（字宽）。两种积木的逆都靠"先定死已知的一段，再逐位推进"：

**右移异或 $y = x \oplus (x \gg s)$ 的逆**。$x \gg s$ 的高 $s$ 位是 0，所以 $x$ 的高 $s$ 位等于 $y$ 的高 $s$ 位；往下每一位 $x_i = y_i \oplus x_{i+s}$，右操作数在更高位、已经算好——==从最高位往最低位逐位推进==：

```python
def inv_rshift_xor(y, s, w=32):
    """x ^ (x >> s) 的逆：x 的高 s 位等于 y 的高 s 位，随后自高向低逐位 x_i = y_i ^ x_{i+s}"""
    x = y
    for i in range(w - 1, -1, -1):
        if i + s < w:
            xi = ((y >> i) ^ (x >> (i + s))) & 1
            x = (x & ~(1 << i)) | (xi << i)
    return x & ((1 << w) - 1)
```

**左移掩码异或 $y = x \oplus ((x \ll s)\ \&\ \text{mask})$ 的逆**。$x \ll s$ 的低 $s$ 位是 0，所以 $x$ 的低 $s$ 位等于 $y$ 的低 $s$ 位；往上每一位 $x_i = y_i \oplus (x_{i-s}\ \&\ \text{mask}_i)$，右操作数在更低位、已经算好——==从最低位往最高位逐位推进==：

```python
def inv_lshift_xor_mask(y, s, mask, w=32):
    """x ^ ((x << s) & mask) 的逆：x 的低 s 位等于 y 的低 s 位，随后自低向高逐位 x_i = y_i ^ (x_{i-s} & mask_i)"""
    x = y
    for i in range(s, w):
        xi = ((y >> i) ^ ((x >> (i - s)) & 1) * ((mask >> i) & 1)) & 1
        x = (x & ~(1 << i)) | (xi << i)
    return x & ((1 << w) - 1)
```

> [!warning] 两种积木的推进方向相反
> 右移丢的是高位信息，逆要从高位往低位推；左移丢的是低位信息，逆要从低位往高位推。把方向写反是最常见的实现错误，而且对拍时表现为"少数位对不上"，不明显。写完先拿随机数各验十万组再组合。

### 2.4 untemper 与对拍

把四步按相反顺序撤掉，就得到 untemper：

```python
def untemper(y):
    """tempering 的逆：按相反顺序撤四步"""
    y = inv_rshift_xor(y, 18)
    y = inv_lshift_xor_mask(y, 15, 0xEFC60000)
    y = inv_lshift_xor_mask(y, 7, 0x9D2C5680)
    y = inv_rshift_xor(y, 11)
    return y & MASK32
```

```python
# untemper_check.py —— 每一步逆运算的单独验证 + untemper 整体对拍
import random
from mt import temper, untemper, inv_rshift_xor, inv_lshift_xor_mask, MASK32

random.seed(7)

# 1) 两个积木：各拿 100000 个随机 32 位数验一遍
ok_r = ok_l = True
for _ in range(100000):
    x = random.getrandbits(32)
    y = x ^ (x >> 11)
    if inv_rshift_xor(y, 11) != x:
        ok_r = False
    x = random.getrandbits(32)
    y = x ^ ((x << 15) & 0xEFC60000)
    if inv_lshift_xor_mask(y, 15, 0xEFC60000) != x:
        ok_l = False
print("右移异或的逆 10 万组成立:", ok_r)
print("左移掩码异或的逆 10 万组成立:", ok_l)

# 2) untemper(temper(x)) == x，同样 10 万组
ok_t = True
for _ in range(100000):
    x = random.getrandbits(32)
    if untemper(temper(x)) != x:
        ok_t = False
print("untemper(temper(x)) == x  10 万组成立:", ok_t)

# 3) 用 CPython random 的真实输出对拍：untemper 后重新 temper 应还原
random.seed(1234)
outs = [random.getrandbits(32) for _ in range(5)]
print("CPython 输出        :", [hex(o) for o in outs])
print("untemper 再 temper  :", [hex(temper(untemper(o))) for o in outs])
print("逐个还原            :", [untemper(temper(o)) == o for o in outs])

# 4) 三个示例输出逐步展示
x = 0x1234ABCD
print()
print("示例 x = 0x1234abcd")
print("  temper(x) =", hex(temper(x)))
```

> [!info]- 不动点迭代写法
> CTF 圈流传另一种更短的写法：不逐位推进，把逆运算当不动点迭代 $x \leftarrow y \oplus (x \gg s)$，反复代入若干次：
>
> ```python
> def inv_rshift_xor_fix(y, s, w=32):
>     x = y
>     for _ in range(32 // s + 1):
>         x = y ^ (x >> s)
>     return x & 0xFFFFFFFF
> ```
>
> 收缩原理：迭代一次，最高 $s$ 位就固定为正确值（它们不受 $x \gg s$ 影响）；每多迭代一次，从上往下再多固定 $s$ 位；$\lceil 32/s \rceil$ 次后全部位正确。左移掩码版同构：`x = y ^ ((x << s) & mask)`，从低位向上固定。两种写法等价，逐位版便于理解、迭代版便于默写，对拍结果一致。

> [!info]- tempering 为什么存在
> 不做 tempering 的 MT 生成器有可观测的分布缺陷：低位字的均匀性差（对某些统计测试不达标）。tempering 是一个固定的可逆位变换，把每个输出字的位打散，让任意连续输出序列的均匀性达标。它的设计目标是"骗过统计测试"，不是"抵抗状态恢复"——事实上它对状态恢复毫无抵抗，因为它是可逆的。

## 3. 624 个输出恢复全部状态

### 3.1 原理：untemper 与 setstate

一轮（两次 twist 之间）恰好产出 624 个输出，等于把当前状态数组逐字 temper 一遍。所以：

1. 拿到**连续的 624 个** `getrandbits(32)` 输出；
2. 逐个 untemper，得到**完整的 624 字状态数组**；
3. 用 `setstate` 把这组状态装进一个新的 `random.Random`，读取位置设为 624——下一次取值会先 twist，与服务端的推进节奏一致；
4. 此后新对象与原对象输出完全相同：==不需要种子，状态本身就是种子==。

```python
clone = random.Random()
clone.setstate((3, tuple(untemper(o) for o in outs) + (624,), None))
```

`setstate` 吃一个三元组：版本号 3、625 个整数（624 个状态字加末尾的读取位置）、高斯缓存放 `None`。末尾索引设 624 表示"数组已耗尽"，与"服务端刚发完 624 个输出"的状态对齐。

> [!info]- 为什么任意连续 624 个都对齐
> twist 每 624 次取值发生一次，所以从任何一个位置数起，连续 624 个输出都恰好覆盖一个完整的状态数组——起点不必是种子后的第一轮。读取位置设 624 之后，克隆对象与服务端在"下一次调用先 twist"上步调一致。真正的约束是==连续==：中间跳过或漏收输出、或序列被 `seed()` 重置过，624 个字就不再来自同一个数组，克隆出的对象从第一步就错了。缺号的情形见 4.3。

### 3.2 靶场：未知种子下的密钥流预测

自造一个 CTF 常见形态的靶子：服务端用系统熵做种子（时间、pid 爆破都失效），先把 624 个 32 位输出交给客户端，再用同一个生成器吐出的字节流异或加密 flag。客户端不知道种子，但 624 个输出已经够它克隆整个生成器。

```python
# server.py —— 靶场：种子来自系统熵（不可猜），发 624 个 32 位输出，随后用同一生成器的字节流异或加密 flag
import random
import socket

FLAG = b"flag{mt19937_n0t_csprng}"

srv = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
srv.bind(("127.0.0.1", 6401))
srv.listen(1)
print("listening on 127.0.0.1:6401")

conn, _ = srv.accept()
rng = random.Random()                       # 种子取自操作系统熵，攻击方拿不到

data = b"".join(rng.getrandbits(32).to_bytes(4, "little") for _ in range(624))
conn.sendall(data)

ks = rng.randbytes(len(FLAG))               # 密钥流也出自同一个 MT19937
ct = bytes(a ^ b for a, b in zip(FLAG, ks))
conn.sendall(ct)

conn.sendall(b"".join(rng.getrandbits(32).to_bytes(4, "little") for _ in range(3)))
conn.close()
srv.close()
```

攻击端收下数据，克隆，预测密钥流：

```python
# solve.py —— 攻击端：收 624 个输出 → untemper → 克隆生成器 → 预测密钥流解 flag → 核对后续输出
import random
import socket

def inv_rshift_xor(y, s, w=32):
    x = y
    for i in range(w - 1, -1, -1):
        if i + s < w:
            xi = ((y >> i) ^ (x >> (i + s))) & 1
            x = (x & ~(1 << i)) | (xi << i)
    return x & 0xFFFFFFFF

def inv_lshift_xor_mask(y, s, mask, w=32):
    x = y
    for i in range(s, w):
        xi = ((y >> i) ^ ((x >> (i - s)) & 1) * ((mask >> i) & 1)) & 1
        x = (x & ~(1 << i)) | (xi << i)
    return x & 0xFFFFFFFF

def untemper(y):
    y = inv_rshift_xor(y, 18)
    y = inv_lshift_xor_mask(y, 15, 0xEFC60000)
    y = inv_lshift_xor_mask(y, 7, 0x9D2C5680)
    y = inv_rshift_xor(y, 11)
    return y

s = socket.create_connection(("127.0.0.1", 6401))
buf = b""
while len(buf) < 624 * 4 + 24 + 12:
    chunk = s.recv(65536)
    if not chunk:
        break
    buf += chunk
s.close()

outs = [int.from_bytes(buf[i * 4:i * 4 + 4], "little") for i in range(624)]
tail = buf[-12:]
ct = buf[624 * 4:-12]

clone = random.Random()
clone.setstate((3, tuple(untemper(o) for o in outs) + (624,), None))

ks = clone.randbytes(len(ct))
flag = bytes(a ^ b for a, b in zip(ct, ks))
print("还原出的 flag:", flag.decode())

pred = [clone.getrandbits(32) for _ in range(3)]
real = [int.from_bytes(tail[i * 4:i * 4 + 4], "little") for i in range(3)]
print("后续 3 个输出的预测与服务器一致:", pred == real)
```

### 3.3 random、randint、randbytes 的换算

克隆出 `Random` 对象后，预测任何 API 的做法都是==在克隆对象上调用同一个 API==，不必手算换算。但读懂换算关系才能应付"题面只给部分输出"的局面：

```python
# clone_check.py —— 克隆生成器后预测各个 API；验证 random() 的两输出拼合公式
import random
from mt import MT, untemper

r1 = random.Random()                          # 种子来自系统熵，攻击方不知道
outs = [r1.getrandbits(32) for _ in range(624)]

clone = random.Random()
clone.setstate((3, tuple(untemper(o) for o in outs) + (624,), None))

print("预测 getrandbits(32):", [r1.getrandbits(32) for _ in range(5)] == [clone.getrandbits(32) for _ in range(5)])
print("预测 random()       :", all(r1.random() == clone.random() for _ in range(10)))
print("预测 randint(0,99)  :", [r1.randint(0, 99) for _ in range(10)] == [clone.randint(0, 99) for _ in range(10)])
print("预测 randint(0,1e9) :", [r1.randint(0, 10**9) for _ in range(10)] == [clone.randint(0, 10**9) for _ in range(10)])
print("预测 choice         :", [r1.choice("abcdefgh") for _ in range(10)] == [clone.choice("abcdefgh") for _ in range(10)])
print("预测 randbytes      :", r1.randbytes(16) == clone.randbytes(16))

print()
print("== random() 的两输出拼合公式 ==")

print("random.Random(424242).random()      =", c.random())
```

换算关系逐条说清：

| API | 底层消耗 | 换算 |
| ---- | ---- | ---- |
| `getrandbits(k)`，$k \le 32$ | 1 个输出 | `genrand() >> (32 - k)` |
| `getrandbits(k)`，$k > 32$ | $\lceil k/32 \rceil$ 个输出 | 逐字填充，低位字在前 |
| `random()` | 2 个输出 | 式 (4.3) |
| `randbytes(n)` | $\lceil 8n/32 \rceil$ 个输出 | `getrandbits(8n).to_bytes(n, 'little')` |
| `randint(a, b)` | 不定 | `a + _randbelow(b+1-a)`，拒绝采样见 4.1 |

$$\text{random()} = \frac{(a \gg 5)\cdot 2^{26} + (b \gg 6)}{2^{53}}, \quad a, b \text{ 为连续两个 } 32 \text{ 位输出} \tag{4.3}$$

式 (4.3) 就是 clone_check 末尾对拍的那行公式：`random()` 每次消耗**两个**输出，53 位精度里高 26 位出自第一个输出、低 27 位出自第二个。==用"一个输出算一次 random()"的换算必然对不上==。

## 4. 观测不完整：丢位与缺号

题面往往不给完整的 32 位输出。两种残缺：**丢位**（只给每个输出的高几位，典型是 `randint(0, N)` 小范围输出）与**缺号**（输出本身完整，但条数不够或有遗漏）。

### 4.1 randint 到底泄露多少位

`randint(a, b)` 落到 `_randbelow_with_getrandbits`：

```python
def _randbelow_with_getrandbits(self, n):
    if not n:
        return 0
    getrandbits = self.getrandbits
    k = n.bit_length()          # n = b + 1 - a
    r = getrandbits(k)
    while r >= n:
        r = getrandbits(k)      # 超界重摇，每次重摇消耗一个输出
    return r
```

所以 `randint(0, N)` 的每个尝试输出的是某个 32 位生成器输出的**高 $k$ 位**（$k = (N+1).\text{bit\_length}()$）。三种情形：

| 题面 | $k$ | 泄露 |
| ---- | ---- | ---- |
| `randint(0, 1)` | 1 | 每 32 位输出只露 1 位 |
| `randint(0, 99)` | 7 | 每 32 位输出露高 7 位，且超界（$\ge 100$）时重摇、消耗不定 |
| `randint(0, 255)` | 8 | 每 32 位输出露高 8 位，$N+1$ 恰为 $2^k$，无重摇，一条输出对应一次 |

$N+1$ 是 2 的幂时映射干净（一条输出一条结果）；否则拒绝采样让"消耗的输出个数"本身随机，建模时要把它当未知量处理。

### 4.2 z3 求解：缩小版 MT

丢位之后 untemper 没法逐字做了——每条输出缺着低位。这类问题的一般解法是==把状态当成未知数，把 twist 和 tempering 写成约束，交给 z3 求解==。MT19937 全尺寸的状态是 19937 位，直接上全尺寸约束规模大；建模技术先用一个**同构的缩小版**走通——参数对应关系不变，字数和字宽缩小：8 个字、每字 8 位、twist 配对距离 3、高 1 位进 twist、tempering 换成 8 位版的两步。

```python
# z3_mini_mt.py —— z3 求解缩小版 MT19937 的内部状态（同构的 twist + tempering）
# 场景：只拿到三轮 randint(0,15)（每个输出只剩高 4 位），恢复状态并预测第四轮
import time
from z3 import BitVec, BitVecVal, LShR, If, Solver, sat, simplify

N, M = 8, 3          # 8 个字、twist 配对距离 3（真实 MT 是 624 与 397）
UP, LOW, A = 0x80, 0x7F, 0xB4   # 高 1 位进 twist，其余 7 位补位（真实 MT 是 1/31 位）

def twist(s):
    out = []
    for i in range(N):
        y = (s[i] & UP) | (s[(i + 1) % N] & LOW)
        v = s[(i + M) % N] ^ (y >> 1)
        if y & 1:
            v ^= A
        out.append(v & 0xFF)
    return out

def temper(x):
    y = x ^ (x >> 4)
    y ^= (y << 2) & 0x53
    return y & 0xFF

def twist_sym(s):
    out = []
    for i in range(N):
        y = (s[i] & UP) | (s[(i + 1) % N] & LOW)
        v = s[(i + M) % N] ^ LShR(y, 1)
        v = If(y & 1 == 1, v ^ A, v)
        out.append(v)
    return out

def temper_sym(x):
    y = x ^ LShR(x, 4)
    y = y ^ ((y << 2) & 0x53)
    return y

# 建模前先核对：符号版与具体版在真实状态上算出同一轮次
chk = [simplify(v).as_long() for v in twist_sym([BitVecVal(x, 8) for x in range(8)])]
assert chk == twist(list(range(8))), "twist_sym 与 twist 不一致"

# 真实发生过的四条轮次与观测（只看每个输出的高 4 位）
true_state = [0xA3, 0x71, 0xF0, 0x5C, 0x9E, 0x28, 0xD4, 0x6B]
r1 = twist(true_state); o1 = [temper(v) for v in r1]
r2 = twist(r1);         o2 = [temper(v) for v in r2]
r3 = twist(r2);         o3 = [temper(v) for v in r3]
r4 = twist(r3);         o4 = [temper(v) for v in r4]
obs1 = [v >> 4 for v in o1]
obs2 = [v >> 4 for v in o2]
obs3 = [v >> 4 for v in o3]

S = [BitVec(f"s{i}", 8) for i in range(N)]
T1 = twist_sym(S)
T2 = twist_sym(T1)
T3 = twist_sym(T2)
sol = Solver()
for i in range(N):
    sol.add(LShR(temper_sym(T1[i]), 4) == obs1[i])
    sol.add(LShR(temper_sym(T2[i]), 4) == obs2[i])
    sol.add(LShR(temper_sym(T3[i]), 4) == obs3[i])

t0 = time.time()
res = sol.check()
dt = time.time() - t0
print("check =", res, " 求解耗时 %.2f 秒" % dt)

rec = [sol.model()[S[i]].as_long() for i in range(N)]
print("恢复的状态:", [hex(v) for v in rec])
print("真实的状态:", [hex(v) for v in true_state])
print("状态逐字一致:", rec == true_state)

# 解是否唯一：排除已找到的解再 check
sol.add(S[0] != rec[0])
for i in range(1, N):
    sol.add(S[i] != rec[i])
print("排除该解后再求:", sol.check())

r = rec
for _ in range(4):            # 初态到第 4 轮共 4 次 twist
    r = twist(r)
pred = [temper(v) for v in r]
print("第 4 轮输出高 4 位  预测:", [v >> 4 for v in pred])
print("第 4 轮输出高 4 位  真实:", [v >> 4 for v in o4])
print("预测一致:", [v >> 4 for v in pred] == [v >> 4 for v in o4])
```

建模三步照搬进任何 PRNG：未知数（8 个 8 位 BitVec，对应真实 MT 的 624 个 32 位 BitVec）、符号版轮函数（把 twist、tempering 的每个位运算原样翻译，`>>` 要用 `LShR` 保持无符号语义）、观测约束（"输出的高 4 位等于观测值"）。两个习惯值得保留：建模前先用具体值核对符号版轮函数（assert 那两行），求出解后排除再 check 一次确认唯一——==z3 只对写进模型的约束负责，多解时它返回的那个解未必是真实状态==。这套方法与 LFSR 类线性生成器的约束求解同源，[[C03-序列密码与LFSR|C03]] 把 GF(2) 线性这一侧展开。

### 4.3 缺号：相邻方程解回丢失的字

缺号是另一种残缺：输出本身是完整的 32 位，但漏收了若干条。先记两个可以直接用的事实：

- ==手里只要有连续完整的 624 个输出，克隆照做==（3.1 的结论），缺在更早的轮次根本不用管；
- 缺号发生在"手里最后一轮"、需要把缺的**值本身**找回来时（它可能就是密钥流的某一段），用 twist 的位级关系解方程。

设漏收的是某轮的第 $i$ 个状态字 $\text{old}_i$（由它的输出 untemper 而来），手里有该轮其余全部字，以及**下一轮**的第 $i-1$、$i$ 两个输出。看式 (4.1) 的 $y$ 的构成：==$y$ 的最高位来自 $\text{old}_i$，低 31 位来自 $\text{old}_{i+1}$==——这一条写反，后面全错。于是：

- 下一轮第 $i$ 个字（式 4.2）里含有 $y \gg 1$，其第 30 位就是 $\text{old}_i$ 的第 31 位——一条方程钉死 1 位；
- 下一轮第 $i-1$ 个字的 $y'$ 以 $\text{old}_i$ 的低 31 位为底，其第 30 位必须等于 $\text{old}_{i-1}$ 的最高位（已知）——用这一条定出常数项加没加，其余 30 位直接读出。

两条方程合起来，32 位全部解出：

```python
# missing_check.py —— 缺了 1 个输出：用下一轮的相邻两个输出把 32 位全部解回来
import random

N, M = 624, 397
A = 0x9908B0DF

def inv_rshift_xor(y, s, w=32):
    x = y
    for i in range(w - 1, -1, -1):
        if i + s < w:
            xi = ((y >> i) ^ (x >> (i + s))) & 1
            x = (x & ~(1 << i)) | (xi << i)
    return x & 0xFFFFFFFF

def inv_lshift_xor_mask(y, s, mask, w=32):
    x = y
    for i in range(s, w):
        xi = ((y >> i) ^ ((x >> (i - s)) & 1) * ((mask >> i) & 1)) & 1
        x = (x & ~(1 << i)) | (xi << i)
    return x & 0xFFFFFFFF

def untemper(y):
    y = inv_rshift_xor(y, 18)
    y = inv_lshift_xor_mask(y, 15, 0xEFC60000)
    y = inv_lshift_xor_mask(y, 7, 0x9D2C5680)
    y = inv_rshift_xor(y, 11)
    return y

rng = random.Random(777)
raw = [rng.getrandbits(32) for _ in range(2 * N)]      # 连续两轮共 1248 个输出
old = [untemper(v) for v in raw[:N]]                   # 前一轮的 624 个状态字

i = 100                                                # 攻击者恰好漏收了第 100 个输出
mid_i   = raw[N + i]                                   # 下一轮的第 i 个输出（已收到）
mid_im1 = raw[N + i - 1]                               # 下一轮的第 i-1 个输出（已收到）
true_word = old[i]

# 方程一：mid[i] = old[(i+M)%N] ^ (y>>1) ^ (A if y&1)，y 的低 31 位来自已知的 old[i+1]
V = untemper(mid_i) ^ old[(i + M) % N] ^ (A if old[(i + 1) % N] & 1 else 0)   # = y >> 1
bit31 = (V >> 30) & 1                                  # y 的第 31 位就是 old[i] 的第 31 位

# 方程二：mid[i-1] 的方程里，y' 的低 31 位来自 old[i] 的位 30..0，
# 其中位 30 必须等于 old[i-1] 的最高位——用这一点定出 magic 常量加没加，顺带读出位 30..1
W = untemper(mid_im1) ^ old[(i - 1 + M) % N]
for b in (0, 1):
    yh = W ^ (A if b else 0)                           # 假设选择子 b0=b 后的 y' >> 1
    if ((yh >> 30) & 1) == ((old[(i - 1) % N] >> 31) & 1):
        b0 = b
        bits301 = yh & 0x3FFFFFFF                      # 位 29..0 = old[i] 的位 30..1
        break

rec = (bit31 << 31) | (bits301 << 1) | b0
print("漏收的第 %d 个输出对应的状态字" % i)
print("  真实值 =", hex(true_word))
print("  解回值 =", hex(rec))
print("  32 位全中:", rec == true_word)
```

缺多个输出时同理：每个缺字占用下一轮相邻两条方程，缺 $k$ 个就列 $2k$ 条，方程不够或两轮都残缺时，把缺字全部设为 BitVec 未知数、按 4.2 的框架交给 z3。

> [!info]- 全尺寸求解的成本账与工具
> 把 4.2 的建模原样放大到真实 MT19937：624 个 32 位符号字、每轮 twist 是 624 次 32 位符号位运算，观测 $k$ 位时凑满 19937 位约束大约需要 $\lceil 19937 / (624k) \rceil$ 轮。约束规模上来之后 z3 的求解时间以分钟计并可能超时，全尺寸丢位攻击在实战里的三条替代路：一、等观测（服务端往往吐得到第二轮、第三轮数据）；二、用现成工具（pip 包 `mt19937predictor` 封装了"喂 624 个输出、取后续预测"；GitHub 上的 untwister 支持多种生成器的丢位求解）；三、检查题目是否真需要状态——很多题只需要"下一个值"，缺号补全（4.3）或克隆（第 3 节）就够了。

## 5. 种子的形态坑

状态恢复不需要种子；但大量题目种子本身就是弱熵。09 章做过固定种子与时间种子，这里补齐剩下的形态，前提是搞清==种子进 MT19937 的完整通路==。

### 5.1 int 种子：拆 32 位字进 init_by_array

CPython 把任意 int 种子拆成 32 位字数组（低位字在前），交给 `init_by_array` 做两轮混淆：

```python
def init_genrand(self, s):
    mt = self.mt
    mt[0] = s & MASK32
    for i in range(1, N):
        mt[i] = (1812433253 * (mt[i - 1] ^ (mt[i - 1] >> 30)) + i) & MASK32
    self.idx = N

def init_by_array(self, key):
    mt = self.mt
    self.init_genrand(19650218)                  # 固定底种子先铺满 624 字
    i, j = 1, 0
    k = max(N, len(key))
    while k:                                     # 第一轮：种子字参与，乘子 1664525
        mt[i] = ((mt[i] ^ ((mt[i - 1] ^ (mt[i - 1] >> 30)) * 1664525)) + key[j] + j) & MASK32
        i += 1
        j += 1
        if i >= N:
            mt[0] = mt[N - 1]
            i = 1
        if j >= len(key):
            j = 0
        k -= 1
    for k in range(N - 1, 0, -1):                # 第二轮：不再用 key，乘子 1566083941
        mt[i] = ((mt[i] ^ ((mt[i - 1] ^ (mt[i - 1] >> 30)) * 1566083941)) - i) & MASK32
        i += 1
        if i >= N:
            mt[0] = mt[N - 1]
            i = 1
    mt[0] = 0x80000000
```

两个对复现有用的细节：底种子固定为 19650218（MT 论文作者生日编码的惯例值，不是熵）；种子为 0 时数组是 `[0]`，负种子取绝对值——`seed(-5)` 与 `seed(5)` 同序列。

### 5.2 str 与 bytes 种子：encode 加 sha512

str/bytes/bytearray 种子不直接进 `init_by_array`，先走一步转换：`encode()` 成字节后**拼接自身的 SHA-512 摘要**，再按大端转成 int。也就是：

```python
s = int.from_bytes(seed_bytes + hashlib.sha512(seed_bytes).digest(), "big")
```

三个直接推论：==同内容的 str 与 bytes 种子产生同一条序列==（都先变同一串字节）；种子的位数被 sha512 撑到 512 位以上（短字符串也变成大整数）；这条转换从 Python 3.6 起就是 `Lib/random.py` 的固定实现，到本章的 3.14 没变。更老的 Python 2 用的是另一种字符串哈希式转换，`seed(a, version=1)` 参数就是为复现那种老行为保留的——跨 Python 2/3 对照老题解的种子时必须想到这一层。

用第 2、5.1 节的纯 Python 实现整条通路对拍——int 种子、str 种子、bytes 种子全部一致，整条通路与 CPython 相同：

```python
# seed_check.py —— 纯 Python MT 与 CPython random 的种子对拍：int / str / bytes
import hashlib
import random
from mt import MT

def cross(seed, label):
    b = MT()
    b.seed(seed)
    mine = [b.getrandbits(32) for _ in range(5)]
    ref = random.Random(seed)
    theirs = [ref.getrandbits(32) for _ in range(5)]
    print(f"{label:22s} 一致 = {mine == theirs}   首个输出 = {hex(mine[0])}")

print("== int 种子 ==")
cross(0, "seed(0)")
cross(12345, "seed(12345)")
cross(2**64 + 305419896, "64 位大整数种子")

print()
print("== str / bytes 种子 ==")
cross("abc", "seed('abc')")
cross(b"abc", "seed(b'abc')")
cross("mt19937", "seed('mt19937')")
print("str 与 bytes 同流:",
      [random.Random('abc').getrandbits(32) for _ in range(3)] ==
      [random.Random(b'abc').getrandbits(32) for _ in range(3)])
v = int.from_bytes(b"abc" + hashlib.sha512(b"abc").digest(), "big")
print("seed('abc') 喂给 init_by_array 的整数:", v.bit_length(), "位")
print("  低 64 位 =", hex(v & 0xFFFFFFFFFFFFFFFF))

print()
print("== getrandbits 多字与 random() 路径 ==")
b = MT(); b.seed(20260101)
c = random.Random(20260101)
print("getrandbits(64) 一致:", b.getrandbits(64) == c.getrandbits(64))
print("getrandbits(7)  一致:", b.getrandbits(7) == c.getrandbits(7))
print("random() 三个值一致 :", [b.random() for _ in range(3)] == [c.random() for _ in range(3)])
```

### 5.3 pid、计数器与小空间枚举

种子不可猜的前提是种子空间够大。常见反例：`random.seed(os.getpid())`（进程号上限默认 32768）、循环计数器 `random.seed(i)`、递增序号。这类种子的枚举成本与 09 章的时间窗口同级，攻击写法也相同：拿输出试种子的候选空间，命中特征（flag 前缀、可读性）即锁定：

```python
# pid_check.py —— 种子是进程号：服务端 random.seed(os.getpid())，攻击端全扫 pid 空间
import os
import random

FLAG = b"flag{p1d_1s_n0t_s3cret}"
pid = os.getpid()

rng = random.Random(pid)
ct = bytes(a ^ b for a, b in zip(FLAG, rng.randbytes(len(FLAG))))
print("服务端进程号 =", pid)
print("密文 =", ct.hex())
print()

for cand in range(1, 65536):                 # Linux pid 上限默认 32768，扫到 65536 兜底
    ks = random.Random(cand).randbytes(len(ct))
    pt = bytes(a ^ b for a, b in zip(ct, ks))
    if pt.startswith(b"flag{"):
        print("命中种子 =", cand, "（与真实进程号一致:", cand == pid, "）")
        print("明文 =", pt.decode())
        break
```

## 6. LCG 攻击

线性同余生成器（LCG）是另一大宗族，状态转移只有一步乘加：

$$x_{n+1} = (a \cdot x_n + c) \bmod m \tag{4.4}$$

Java 的 `Random`（7.1）、大量教材与老库函数都是 LCG。它的统计性质一般，结构性质更差：==输出就是状态本身==（或状态的简单截断），参数一旦恢复，整条序列尽收眼底。求逆元用 `pow(x, -1, m)`，原理是扩展欧几里得（[[09-密码学基础#2.2 GCD 与扩展欧几里得|09 章 2.2]]，数论侧的展开在 [[C02-数论进阶与原根|C02]]）。

### 6.1 已知模数：两条差分解出 a 与 c

$m$ 已知（$2^{32}$、$2^{48}$ 这类固定值最常见）时，连续三条输出足够。相邻两条作差消掉 $c$：

$$x_{n+2} - x_{n+1} \equiv a \cdot (x_{n+1} - x_n) \pmod m \;\Rightarrow\; a = (x_{2}-x_{1})(x_{1}-x_{0})^{-1} \bmod m \tag{4.5}$$

再代回式 (4.4) 得 $c$。

### 6.2 未知模数：差分 gcd

$m$ 未知时先用差分把它挖出来。对差分 $t_i = x_{i+1} - x_i$（普通整数相减，不取模），差分序列满足 $t_{i+1} \equiv a \cdot t_i \pmod m$，于是：

$$t_{i+2} \cdot t_i - t_{i+1}^2 \equiv 0 \pmod m \tag{4.6}$$

式 (4.6) 的左边是 $m$ 的倍数；多写几组一起求最大公约数，通常直接得到 $m$ 本身（得到的是倍数时预测照样成立，需要精确 $m$ 再除小因子）。拿到 $m$ 后回到 6.1。

### 6.3 截断输出：z3 求解

只拿到输出的高 16 位（低位被截掉）时，差分法失效（截断破坏线性），轮到 z3：状态是 32 位未知数，把式 (4.4) 的乘加写成 BitVec 约束、观测写成"高 16 位相等"，十几条输出即可解出初始状态——模数是 $2^{32}$ 时 BitVec 定宽运算天然就是 mod $2^{32}$，连取模都不用写。

三合一脚本：


## 7. 其他语言一瞥

换个语言，攻击面的形状不变：==状态决定一切，输出与状态之间只隔一层可逆（或部分可逆）变换==。

### 7.1 Java Random：48 位 LCG

`java.util.Random` 是 48 位 LCG，Javadoc 直接写明算法——规范即说明书：

$$\text{seed} \leftarrow ((\text{seed} \oplus \mathtt{0x5DEECE66D}) \cdot \mathtt{0x5DEECE66D} + \mathtt{0xB}) \bmod 2^{48} \tag{4.7}$$

三个要点：构造或 `setSeed` 时先与 `0x5DEECE66D` 异或（混淆，不改变可预测性）；`next(bits)` 取的是 48 位状态的**高** bits 位；`nextInt(bound)` 有两条路径——bound 为 2 的幂时用乘法伸缩，否则用 `next(31) % bound` 加拒绝重试。照 Javadoc 手写一份，与 openjdk 21 的实际输出对拍，并顺手做经典攻击：`nextInt()` 给出完整 32 位输出，两条输出之间夹着 16 位未知，暴力 $2^{16}$ 补齐后连构造种子一起回推（用乘法逆元倒退一步去混淆）：

```java
import java.util.Random;

public class JavaRandomDemo {
    public static void main(String[] args) {
        Random r = new Random(123456789012345L);
        System.out.println("== nextInt() 三次 ==");
        for (int i = 0; i < 3; i++) System.out.println(r.nextInt());
        System.out.println("== nextInt(100) 五次 ==");
        for (int i = 0; i < 5; i++) System.out.println(r.nextInt(100));
        System.out.println("== nextInt(128) 三次 ==");
        for (int i = 0; i < 3; i++) System.out.println(r.nextInt(128));
    }
}
```

```python
# java_check.py —— 手写 java.util.Random 并与 openjdk 实际输出对拍；再从两个 nextInt() 恢复种子
import subprocess

MASK48 = (1 << 48) - 1
MULT = 0x5DEECE66D
ADD = 0xB

class JavaRandom:
    def __init__(self, seed):
        self.seed = (seed ^ MULT) & MASK48      # setSeed 的“混淆”：先异或再加掩码

    def next(self, bits):
        self.seed = (self.seed * MULT + ADD) & MASK48
        r = self.seed >> (48 - bits)
        if bits == 32 and r >= 2**31:           # Java int 是 32 位补码
            r -= 2**32
        return r

    def nextInt(self, bound=None):
        if bound is None:                       # nextInt() = next(32)，完整 32 位
            return self.next(32)
        if (bound & -bound) == bound:           # 2 的幂：乘法伸缩，不走取模
            return (bound * self.next(31)) >> 31
        while True:
            bits = self.next(31)
            val = bits % bound
            if bits - val + (bound - 1) < 2**31:  # Java 里该式溢出成负数时重摇
                return val

out = subprocess.run(["java", "JavaRandomDemo"], capture_output=True, text=True).stdout.splitlines()
java_ints = [int(v) for v in out[1:4]]
java_100  = [int(v) for v in out[5:10]]
java_128  = [int(v) for v in out[11:14]]
print("Java 实际输出 nextInt() 三次 :", java_ints)
print("Python 复现 nextInt() 三次   :", end=" ")
r = JavaRandom(123456789012345)
mine = [r.nextInt() for _ in range(3)]
print(mine)
print("一致:", mine == java_ints)

r2 = JavaRandom(123456789012345)
[r2.nextInt() for _ in range(3)]              # 与 Java 程序相同：先消耗 3 个 nextInt()
print("nextInt(100) 一致:", [r2.nextInt(100) for _ in range(5)] == java_100)
print("nextInt(128) 一致:", [r2.nextInt(128) for _ in range(3)] == java_128)

print()
print("== 从前两个 nextInt() 输出恢复构造种子 ==")
o1, o2, o3 = java_ints
hi32 = o1 & 0xFFFFFFFF                    # 第一次 next(32) 后 48 位状态的高 32 位
hits = []
for low in range(1 << 16):                # 低 16 位只有 65536 种
    s1 = (hi32 << 16) | low
    s2 = (s1 * MULT + ADD) & MASK48
    v2 = s2 >> 16
    if v2 >= 2**31:
        v2 -= 2**32
    if v2 == o2:
        s0 = ((s1 - ADD) * pow(MULT, -1, 1 << 48)) % (1 << 48)   # 倒退一步去混淆
        hits.append(s0 ^ MULT)
print("候选种子:", hits)
print("真实构造种子: 123456789012345")
print("恢复命中:", hits == [123456789012345])
```

> [!warning] 复现 nextInt(bound) 的两处细节
> 一是 2 的幂路径不做取模——`nextInt(128)` 是 `(128 * next(31)) >> 31`，写成 `next(31) % 128` 有限概率对不上；二是非 2 幂路径的拒绝重试：`bits - val + (bound-1)` 溢出为负时整轮重摇，漏掉这个循环，遇到触发重摇的输出就错位。对拍对不上时先数"消耗了几个 next(31)"。

### 7.2 glibc rand()：TYPE_3 加法反馈

glibc 的 `rand()` 默认走 TYPE_3：34 个 32 位字的状态，初始化用 16807 乘法迭代（模 $2^{31}-1$）铺前 31 个字、复制 3 个字、丢弃 310 次预热，之后每步是纯加法反馈：

$$r_i = (r_{i-3} + r_{i-31}) \bmod 2^{32}, \qquad \text{rand()} = r_i \gg 1 \tag{4.8}$$

转移只用到 $r_{i-3}$ 与 $r_{i-31}$ 两个字，==手里攒 34 个连续输出就覆盖了向前预测所需的全部状态==；又因为输出只是右移一位（最低位被丢），每个未来输出的候选至多差 1。Python 复现递推与 C 实际输出对拍：

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    srand(12345);
    for (int i = 0; i < 8; i++)
        printf("%d\n", rand());
    return 0;
}
```

```python
# glibc_check.py —— glibc rand()（TYPE_3 加法反馈）的纯 Python 复现，与 C 程序输出对拍
import subprocess

def glibc_rand(seed, count):
    r = [0] * (344 + count)
    s = seed if seed != 0 else 1
    r[0] = s
    for i in range(1, 31):                    # 31 个初始字：16807 乘法迭代 mod 2^31-1
        r[i] = (16807 * r[i - 1]) % 2147483647
    for i in range(31, 34):                   # 状态数组扩到 34 个字
        r[i] = r[i - 31]
    for i in range(34, 344):                  # 310 次预热丢弃
        r[i] = (r[i - 31] + r[i - 3]) % 2**32
    out = []
    for i in range(344, 344 + count):         # 正式输出：加法反馈后取高 31 位
        r[i] = (r[i - 31] + r[i - 3]) % 2**32
        out.append(r[i] >> 1)
    return out

c_out = [int(v) for v in subprocess.run(["./glibc_demo"], capture_output=True,
                                        text=True).stdout.splitlines()]
py_out = glibc_rand(12345, 8)
print("C srand(12345) 后 8 个 rand():", c_out)
print("Python 递推复现             :", py_out)
print("一致:", c_out == py_out)
```

### 7.3 node 的 Math.random：xorshift128+

> [!info]- 概念一瞥
> V8（node 与 Chrome）的 `Math.random` 用 xorshift128+：128 位状态、移位异或转移，每个 double 输出泄露其中一个 64 位状态字的高 52 位。它同样"没有种子接口、种子取自系统熵"，但两三个连续输出就足以把 128 位状态列成约束交给 z3——建模方法与 4.2 完全同构（移位异或翻成约束），CTF 里打 node/浏览器侧伪随机就这一条路。本章不展开。

三种语言的攻击面放在一张表里：

| 环境 | 生成器 | 状态 | 攻击入口 |
| ---- | ---- | ---- | ---- |
| Python `random` | MT19937 | 624 × 32 位 | 624 输出 untemper（本章 2–3） |
| Java `Random` | 48 位 LCG | 48 位 | 2 个 nextInt() 暴力 + 逆元（7.1） |
| glibc `rand()` | TYPE_3 加法反馈 | 34 字 | 34 个输出递推预测（7.2） |
| V8 `Math.random` | xorshift128+ | 128 位 | 2–3 个输出 z3 建模（7.3） |

## 8. 防御

开发与出题两侧的清单一致，核心是[[09-密码学基础#6. 随机数一瞥|09 章第 6 节]]那句结论的落地：

- **密钥、token、nonce 一律出自安全随机**：`secrets.token_bytes` / `token_hex` / `SystemRandom`，或密码学库自带的 CSPRNG 接口。09 章给过对照表，这里只强调本章新增的判断依据：==凡是"输出与状态之间只隔可逆变换"的生成器，就不该出现在任何安全位置==。
- **区分"可复现的随机"与"不可预测的随机"**。仿真回放、单元测试要固定种子；密钥生成要不可预测。混淆这两个需求就是本章每一节的来源。真需要固定种子时，种子按密钥管理：出自 CSPRNG、不进日志、不进版本库。
- **分组密码的 nonce/IV 同理**：从 MT19937 或 LCG 出的 IV 等于没有 IV，[[C05-分组密码内部|C05]] 在分组模式侧接着讲。
- **限制输出量**。必须用普通 PRNG 的场景（游戏、抽样），别把生成器的输出成流公开——连续 624 个 32 位输出就是整台生成器的移交。

> [!note] 出题人自查三问
> 一问种子：pid、时间戳、计数器、循环变量当种子，等于把密钥空间降到万级（5.3）。二问输出：题面发出去的 getrandbits / randint 结果加起来够不够 624 个 32 位（第 3 节）、够不够几十条 LCG 输出（第 6 节）。三问 API：加密用的 keystream 出自哪台生成器——`random.randbytes` 出的"密钥流"就是本章 3.2 靶场的原题。

CTF 侧拿到 Crypto 题的反向清单只有两问：**种子哪来的**（可猜就爆种子，不可猜就等输出），**输出给多少**（够了 624 个就走 untemper，不够就 z3）。

## 9. 常见问题

| 现象 | 原因与解决 |
| ---- | ---- |
| untemper 写完对不上少数位 | 两种积木的推进方向写反：右移的逆自高向低、左移的逆自低向高（[[#2.3 两块积木的逆\|2.3]]）；先用随机数各验十万组再组合 |
| untemper 结果 temper 回去不还原 | 中间结果漏了 `& 0xFFFFFFFF`：Python 整数无限宽，左移不截断，位宽越滚越大 |
| 624 个输出克隆后预测全错 | 输出不连续（漏收 / 混入 reseed）或 `setstate` 格式错：必须是 `(3, 625 个整数, None)`，末尾索引 624（[[#3.1 原理：untemper 与 setstate\|3.1]]） |
| 手算 random() 换算对不上 | random() 每次消耗**两个**输出（式 4.3），按单输出换算必错（[[#3.3 random、randint、randbytes 的换算\|3.3]]） |
| 克隆后 randint 预测错位 | `_randbelow` 有拒绝重试，每条 randint 消耗的输出个数不定；直接在克隆对象上调同 API，别手算（[[#4.1 randint 到底泄露多少位\|4.1]]） |
| 全尺寸 MT 丢位建模 z3 跑不完 | 约束规模到了分钟级以上是正常的：先在小模型验建模，实战用 `mt19937predictor` / untwister 或等更多观测（4.3 末尾折叠框） |
| z3 返回 sat 但预测错 | 约束不足导致多解，z3 给的是"一个可行解"；补观测、或排除已得解再 check 确认唯一（[[#4.2 z3 求解：缩小版 MT\|4.2]]） |
| 缺号解回的字不对 | twist 关系里 $y$ 的位序搞反：$y$ 的最高位来自 $\text{old}_i$、低 31 位来自 $\text{old}_{i+1}$（[[#4.3 缺号：相邻方程解回丢失的字\|4.3]]） |
| 同一 str 种子两个 Python 出不同序列 | 版本跨了 Python 2/3 边界：老版走 version=1 式转换，Python 3.6 起（含 3.14）都是 sha512 转换（[[#5.2 str 与 bytes 种子：encode 加 sha512\|5.2]]） |
| `seed(b"x")` 与 `seed("x")` 出不同序列 | 同内容 bytes 与 str 在 Python 3 里必同流；不同流说明有一边是 Python 2 或显式 `version=1` |
| Java 复现 nextInt(bound) 对不上 | 漏了 2 的幂乘法伸缩路径或拒绝重试循环；对不上先数消耗了几个 `next(31)`（[[#7.1 Java Random：48 位 LCG\|7.1]]） |
| glibc rand 复现对不上 | 预热 310 次没丢、`srand(0)` 要按 1 处理、输出是右移一位后的 31 位（[[#7.2 glibc rand()：TYPE_3 加法反馈\|7.2]]） |
| LCG 差分 gcd 求出 0 | 相邻差全零（输出全等）或条数太少；多取几条输出、确认差分非零再求 gcd（[[#6.2 未知模数：差分 gcd\|6.2]]） |
| `seed(-5)` 与 `seed(5)` 序列相同 | CPython 对 int 种子取绝对值，负号不是额外熵源（[[#5.1 int 种子：拆 32 位字进 init_by_array\|5.1]]） |

## 10. 配套练习与延伸阅读

> [!note] 实战任务
> 在 [[01-练习平台索引|练习平台索引]] 的平台里用 "MT19937"、"random"、"LCG" 作关键词各找一道状态恢复题：一道要求用 624 输出克隆预测（第 3 节），一道是丢位或缺号变体（第 4 节）。CryptoHack（cryptohack.org）按主题组织题库，含伪随机数相关题目；picoCTF 的 Cryptography 分类亦有随机数题。每道题记录：生成器是什么、输出给了多少、种子在哪个环节可猜——对不上这三问的题，回到对应小节补课。

配套练习：

1. 把 2.3 的逐位逆换成 2.4 折叠框里的不动点迭代写法，重跑 untemper_check.py 的十万组对拍；再把 tempering 改成去掉任一步的版本，观察对拍失败，确认四步缺一不可。
2. 给 server.py 加一道限制：只发 `randint(0, 65535)`（每条丢 16 位）。先确认第 3 节的克隆脚本失效，再按 4.3 末尾折叠框的思路选工具或建模补全。
3. 把 6.3 的截断观测改成只拿高 8 位，增加输出条数直到 z3 重新可解，记录"观测位数 × 条数"的变化，体会约束总量决定可行性。
4. Java 侧做单输出版种子恢复：只拿一个 `nextInt()` 输出（48 位状态的高 32 位），暴力低 16 位得到 65536 个候选，再用后续的输出甄别出真种子，与 7.1 的双输出版对比。
5. 把 5.3 的骨架改成时间窗爆破变体：服务端 `random.seed(int(time.time()))`，攻击端在 ±60 秒窗口内枚举——与 [[09-密码学基础#6. 随机数一瞥|09 章第 6 节]]的做法对照，体会"同一骨架、换候选空间"。

延伸阅读：

- Matsumoto & Nishimura，*Mersenne Twister: A 623-dimensionally equidistributed uniform pseudorandom generator*（1998）：MT19937 的原始论文，全部常数与参数表的出处。
- CPython 源码：`Lib/random.py`（str/bytes 种子转换与 `_randbelow`）与 `Modules/_randommodule.c`（`init_by_array` 与 genrand 的 C 实现）——本章 5.1、5.2 的行为都能在源码里逐行对上。
- `java.util.Random` 的官方 Javadoc：48 位 LCG、`next`、`nextInt` 的算法白纸黑字写在类文档里，是"规范即说明书"的范例。
- pip 包 `mt19937predictor`（喂 624 个输出、取后续预测的现成实现）与 GitHub 上的 untwister（多生成器、支持丢位求解）——4.3 末尾折叠框提到的两件工具。
