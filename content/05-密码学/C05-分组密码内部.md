## 1. 两大家族：Feistel 与 SPN

[[09-密码学基础#3.3 分组密码与 ECB 的企鹅图|09 章 3.3]] 把分组密码定义成"固定块大小、带密钥的可逆变换"，并用一个手搓的 Feistel 复现了 ECB 的模式泄漏。本章回答那个定义一笔带过的部分：这个"带密钥的可逆变换"内部怎么造出来。难点是一个表面矛盾：==变换必须可逆，不然解不了密；又必须把明文搅得面目全非，不然挡不住分析==。1970 年代以来的主流分组密码都在两条工程路线里选一条解决这个矛盾。

**Feistel 结构**（Horst Feistel，IBM，1970 年代）：把 $2n$ 位明文对半分成 $L_0$、$R_0$，每轮只动一半——右半进轮函数 $F$，输出异或到左半，然后两半交换：

$$L_{i+1} = R_i, \qquad R_{i+1} = L_i \oplus F(R_i, K_i) \tag{5.1}$$

$F$ 可以是任何搅乱函数，不可逆都行。解密是同一套轮子倒着走：由 (5.1) 反解

$$L_i = R_{i+1} \oplus F(L_{i+1}, K_i), \qquad R_i = L_{i+1} \tag{5.2}$$

只需要再算一次 $F$，连逆函数都不用。==可逆性由结构保证，与 $F$ 无关==——这是 Feistel 一族能放心使用任意（甚至有损的）轮函数的原因，DES、TEA 都是这条路。

**SPN 结构**（Substitution-Permutation Network，代换-置换网络）：不分半，每轮对全部比特动手——先异或轮密钥，过一个==代换层==（S 盒：逐字节/半字节的非线性查表），再过一个==置换层==（位重排或矩阵乘法）。代换层负责混淆，置换层负责扩散，这两个词是 Shannon 1949 年起的名字，沿用至今：混淆把密文与密钥的关系复杂化，扩散把明文的统计结构摊进整个分组。SPN 没有结构白送的可逆性，==每个部件都必须自己可逆==：S 盒是双射，置换层本身是双射，AES 就是这么设计的。

| | Feistel（DES、TEA 一族） | SPN（AES 一族） |
| ---- | ---- | ---- |
| 每轮作用范围 | 一半比特进轮函数 | 全部比特 |
| 可逆性 | 结构保证，轮函数随意 | 每个部件必须可逆 |
| 轮函数 | 可以有损、可以无 S 盒 | 代换层与置换层成对出现 |
| 扩散速度 | 一半一半慢慢渗 | 两轮打满全状态（AES 的设计指标） |
| 代表 | DES、3DES、TEA/XTEA、SM4（非平衡） | AES、PRESENT、Skinny |

与流密码的边界一句带过：[[C03-序列密码与LFSR|C03]] 的流密码按位/字节生成密钥流再异或，分组密码一次搅乱一整块；分组密码配 CTR 这类模式也能当流密码用，那是模式层的事，下一章展开。

最后是全章的背景判断，也是现代分组密码的共识：

==AES 发布二十多年，算法本身没有被公开的实用攻击攻破；真实世界里发生的破译，全部打在使用方式与实现上==——ECB 的模式泄漏（[[09-密码学基础#3.3 分组密码与 ECB 的企鹅图|09 章 3.3]]）、IV 重用、可预测的随机 IV、写错的填充、侧信道。本章 6、7 节会看到差分与线性分析这两个"算法层"武器的完整形态：它们在 toy 密码上锋利，对完整 AES 只能停在减轮的理论结果。==CTF 里 AES 题的突破口几乎永远在模式与参数，不在 AES 的轮函数本身==——模式层攻击的全集在下一章 C06 展开。

## 2. DES 与教学版 Feistel

### 2.1 DES 速览

DES（Data Encryption Standard）是第一个大规模商用的分组密码，1977 年成为美国联邦标准（FIPS 46）。结构是标准 Feistel：

| 部件 | 内容 |
| ---- | ---- |
| 分组/密钥 | 64 位分组；64 位密钥装载，其中 8 位奇偶校验，有效 56 位 |
| 轮数 | 16 轮，每轮对半交换（式 5.1） |
| 轮函数 F | 32 位入 → E 扩展成 48 位 → 异或 48 位轮密钥 → 8 个 S 盒各收 6 位吐 4 位 → P 置换重排 32 位 |
| S 盒 | 6 进 4 出的非线性查表，DES 安全性的全部来源 |
| 密钥调度 | PC-1 从 64 位选 56 位分两半，每轮各自循环左移 1 或 2 位，PC-2 每轮压出 48 位轮密钥 |

三件历史事实值得记：

- **56 位密钥不够**：1998 年 EFF 的 Deep Crack 机器用约 25 万美元的硬件在 56 小时内穷举出 DES 密钥。DES 的致命伤只有密钥长度——算法本身至今没有比穷举好太多的普适攻击；
- **3DES 是过渡不是归宿**：E-D-E 三重 DES 把有效密钥拉到 112/168 位，撑了二十年；NIST SP 800-131A Rev. 2 已限定 3DES 自 2023 年底起不再用于加密，只许解密旧数据；
- **接棒者是 AES**：2001 年 NIST 选定 Rijndael（Daemen 与 Rijmen 设计）为 AES，标准文本 FIPS 197，第 4 节起展开。

DES 对今天的价值在教学：结构小到能完整看懂——E/S/P 三层各是干什么的、为什么 S 盒必须非线性、密钥调度怎么把一把主密钥摊成 16 把轮密钥，这些概念在 AES 里全部有对应物，只是尺寸更大。

> [!info]- DES S 盒的一段设计史
> S 盒出自 IBM 的 Lucifer 团队（Feistel 在内），NSA 参与修改：把 128 位密钥砍到 56 位，同时把 S 盒换成更抗差分的一版。1990 年差分分析公开发表时，学界一度怀疑被 NSA 动过的 S 盒藏了后门；1992 年 Coppersmith 披露：设计者在 1974 年就知道差分攻击，S 盒恰恰是按抗差分标准挑的。这是公开标准里"藏着二十年安全余量"的著名案例——也解释了为什么 DES 只输在密钥长度。

### 2.2 手写 4 轮 Feistel：可逆性看清楚

[[09-密码学基础#3.3 分组密码与 ECB 的企鹅图|09 章 3.3]] 用过一个 8 字节的 4 轮 Feistel 当黑盒 `E` 去演示 ECB/CBC（[[09-密码学基础#3.4 CBC 字节翻转|09 章 3.4]]），本节把这个黑盒拆开，完整实现三十行：

```python
# feistel_demo.py —— 4 轮教学版 Feistel：64 位分组，轮函数故意做成非单射（32 位进、12 位出）
MASK32 = 0xFFFFFFFF
KEYS = [0x0F1E2D3C, 0x3C2D1E0F, 0x55667788, 0x99AABBCC]

def F(r, k):
    return (((r ^ k) * 0x9E3779B1) & MASK32) >> 20

def encrypt(pt, keys):
    l, r = (pt >> 32) & MASK32, pt & MASK32
    for k in keys:
        l, r = r, l ^ F(r, k)          # 半轮：左半直接抄右半，右半吃掉 F 的输出
    return (l << 32) | r

def decrypt(ct, keys):
    l, r = (ct >> 32) & MASK32, ct & MASK32
    for k in reversed(keys):
        l, r = r ^ F(l, k), l
    return (l << 32) | r

def decrypt_bad_order(ct):             # 结构正确但轮密钥顺序不反转
    l, r = (ct >> 32) & MASK32, ct & MASK32
    for k in KEYS:
        l, r = r ^ F(l, k), l
    return (l << 32) | r

pt = 0x0123456789ABCDEF
ct = encrypt(pt, KEYS)
print("明文 =", format(pt, "016x"), " 密文 =", format(ct, "016x"))
print("解密 =", format(decrypt(ct, KEYS), "016x"), " 往返成立:", decrypt(ct, KEYS) == pt)

print("F(0x00000000) =", hex(F(0, KEYS[0])), " F(0x00000001) =", hex(F(1, KEYS[0])))
seen = {}
for x in range(1 << 20):
    v = F(x, KEYS[0])
    if v in seen:
        print("F 碰撞: F(%s) = F(%s) = %s —— 轮函数本身不可逆" % (hex(seen[v]), hex(x), hex(v)))
        break
    seen[v] = x

wrong = [k ^ 0x10101010 for k in KEYS]
print("错密钥解密 =", format(decrypt(ct, wrong), "016x"), " 等于明文:", decrypt(ct, wrong) == pt)
print("不反转轮序解密 =", format(decrypt_bad_order(ct), "016x"), " 等于明文:", decrypt_bad_order(ct) == pt)
```

```bash
python3 feistel_demo.py
```

输出：

```
明文 = 0123456789abcdef  密文 = 0123492589abc8f6
解密 = 0123456789abcdef  往返成立: True
F(0x00000000) = 0x772  F(0x00000001) = 0x155
F 碰撞: F(0x269) = F(0x801) = 0x598 —— 轮函数本身不可逆
错密钥解密 = 0123449b89abc694  等于明文: False
不反转轮序解密 = 012348ca89abcb2b  等于明文: False
```

逐行读输出：

- 密文 `0123492589abc8f6` 与明文 `0123456789abcdef` 高半段多处相同：4 轮太少、轮函数每轮只吐 12 位，扩散远不充分。==Feistel 结构只负责"能解回去"，把明文搅乱是轮函数强度和轮数的任务==——DES 用 16 轮和一个精心设计的 F 就是在补这一课；
- `F(0x269) = F(0x801) = 0x598`：两个不同输入映到同一输出，轮函数是彻底的有损函数，而往返照样成立——(5.2) 的承诺兑现；
- 换密钥解密、不反转轮序解密，得到的都不是明文：==结构对、钥匙不对，出不来明文==。

> [!warning] 解密的轮密钥顺序必须反转
> 加密第 1 轮用的 $K_0$ 最后用，解密就要先用 $K_3$。写解密函数忘掉 `reversed()` 是 Feistel 类题的第一大笔误——不报错，只是解出一串看似密文的乱码。TEA 一族同款坑在 [[#8. TEA/XTEA/XXTEA：Feistel 变体与等效密钥|第 8 节]] 再遇。

## 3. GF(2^8)：AES 的数学地基

AES 把一个字节当成 GF(2^8) 里的元素做四则运算。GF(2^8) 不需要任何抽象代数基础，只需要两句话：一个字节 $b_7 b_6 \ldots b_0$ 代表多项式 $b_7 x^7 + b_6 x^6 + \cdots + b_1 x + b_0$，系数只有 0 和 1。例如：

$$\texttt{0x57} = x^6 + x^4 + x^2 + x + 1$$

- **加法**：多项式加法，系数逐位相加、不进位——就是 XOR；
- **乘法**：多项式乘起来之后，对一个固定的 8 次不可约多项式取模：

$$m(x) = x^8 + x^4 + x^3 + x + 1 \qquad (\texttt{0x11B}) \tag{5.3}$$

乘出 8 次以上的项就异或掉 $m(x)$ 的倍数，结果回到 8 次以内。==不取模就只是普通多项式乘法，除不开、也谈不上逆元==——模多项式保证全部非零字节构成 255 阡的乘法群，每个非零字节都有逆。四则运算的完整实现：

```python
# gf256.py —— GF(2^8)：AES 的字节代数。字节 b = b7..b0 表示多项式 b7·x^7 + ... + b1·x + b0
POLY = 0x11B                                   # 模多项式 x^8 + x^4 + x^3 + x + 1（去掉 x^8 的系数就是 0x1B）

print("0x57 =", " + ".join("x^%d" % i for i in (6, 4, 2, 1, 0)))

def gadd(a, b):                                # 加法 = 多项式加法 = 系数按位异或
    return a ^ b

def xtime(a):                                  # 乘 x：左移一位，冲出 8 次项就模上 POLY
    a <<= 1
    return (a ^ POLY) & 0xFF if a & 0x100 else a

def gmul(a, b):                                # 乘法：按 b 的每个位累加 a 的倍数，倍增用 xtime
    p = 0
    while b:
        if b & 1:
            p ^= a
        a = xtime(a)
        b >>= 1
    return p

print("0x57 + 0x83 =", hex(gadd(0x57, 0x83)))
print("0x57 * 0x83 =", hex(gmul(0x57, 0x83)))
print("xtime(0x57) =", hex(xtime(0x57)), " xtime(0xAE) =", hex(xtime(0xAE)), " xtime(0x80) =", hex(xtime(0x80)))

def ginv(a):                                   # 逆元：非零元全体是 255 阶群，a^255 = 1，故 a^254 = a^-1
    r = 1
    for _ in range(254):
        r = gmul(r, a)
    return r

print("0x53 的逆元 =", hex(ginv(0x53)), " 验算 0x53 * 逆元 =", hex(gmul(0x53, ginv(0x53))))

LOG = [0] * 256                                # 对数表：生成元取 0x03
EXP = [0] * 256
x = 1
for i in range(255):
    EXP[i] = x
    LOG[x] = i
    x = gmul(x, 3)

def gmul_tab(a, b):                            # 查表乘法：对数相加模 255
    if a == 0 or b == 0:
        return 0
    return EXP[(LOG[a] + LOG[b]) % 255]

same = all(gmul(a, b) == gmul_tab(a, b) for a in range(256) for b in range(256))
print("手写乘法与查表法在全部 65536 组上一致:", same)
print("0x03 的幂取遍全部 255 个非零元:", sorted(EXP[:255]) == list(range(1, 256)))
```

```bash
python3 gf256.py
```

输出：

```
0x57 = x^6 + x^4 + x^2 + x^1 + x^0
0x57 + 0x83 = 0xd4
0x57 * 0x83 = 0xc1
xtime(0x57) = 0xae  xtime(0xAE) = 0x47  xtime(0x80) = 0x1b
0x53 的逆元 = 0xca  验算 0x53 * 逆元 = 0x1
手写乘法与查表法在全部 65536 组上一致: True
0x03 的幂取遍全部 255 个非零元: True
```

读输出：

- `0x57 + 0x83 = 0xd4`：异或，无进位；
- `0x57 * 0x83 = 0xc1`：这个例子出自 FIPS 197 标准文本，数值可以逐位对照；
- `xtime(0x57) = 0xae`、`xtime(0xae) = 0x47`：连乘两次 x，最高位都没溢出；`xtime(0x80) = 0x1b`：溢出一个 8 次项，异或 0x11B 拉回来。==乘 2 忘掉这一步模约简，是手写 AES 的第一大错==（[[#10. 常见问题|常见问题]]）；
- `0x53 的逆元 = 0xca`，乘回 1 验算通过。求逆用恒等式 $a^{254} = a^{-1}$：非零元全体是 255 阶群，$a^{255} = 1$；
- 查表法用生成元 0x03 建对数表，乘法变成对数相加，65536 组逐对对照全部一致。

> [!note] 生成元 0x03
> 0x03 的幂恰好取遍全部 255 个非零元（输出最后一行核对的就是这件事），这样的元素叫乘法群的生成元。AES S 盒的参考实现就是用 0x03 建对数/指数表来求逆的；查表乘法 `EXP[(LOG[a]+LOG[b])%255]` 与逐位乘法完全等价，速度更快。

## 4. AES 轮变换：SubBytes、ShiftRows、MixColumns、AddRoundKey

AES（FIPS 197，2001）分组 128 位，密钥 128/192/256 位三档对应 10/12/14 轮。本章实现 128 位档。结构是标准 SPN，每轮依次：SubBytes → ShiftRows → MixColumns → AddRoundKey，最后一轮没有 MixColumns。

16 字节明文排成 4×4 的**状态矩阵**，按列填充：输入字节 in[0..3] 是第 0 列。本章代码用长度 16 的一维数组存状态，下标 $i$ 直接就是 $r + 4c$。

**SubBytes**：逐字节查 S 盒。S 盒不是拍脑袋编的表，每格都是两步算出来的：

$$S(a) = \mathrm{Affine}(a^{-1}), \qquad a^{-1} \cdot a \equiv 1 \pmod{m(x)} \tag{5.4}$$

第一步在 GF(2^8) 求逆（0 的逆定为 0），第二步过一个固定仿射变换：$b'_i = b_i \oplus b_{(i+4) \bmod 8} \oplus b_{(i+5) \bmod 8} \oplus b_{(i+6) \bmod 8} \oplus b_{(i+7) \bmod 8} \oplus c_i$，常数 $c = \texttt{0x63} = 01100011$。单字节示例走一遍：0x53 的逆元是 0xCA（[[#3. GF(2^8)：AES 的数学地基|第 3 节]] 的 `ginv` 算出的正是它），仿射之后得 0xED——[[#5. 密钥扩展与手写 AES-128|第 5 节]] 输出第一行的 `S(0x53) = 0xed` 就是这条链。

> [!info]- 为什么这么造
> 求逆给 S 盒带来干净的代数性质：没有不动点（$S(a) = a$ 仅 $a = 0$）、没有互逆序（$S(a) = S^{-1}(a)$ 仅 $a = 0$）；仿射变换再抹掉"纯求逆"在域上留下的低次代数表达式。结果用 [[#6. 差分分析入门：打穿一个 toy SPN|第 6 节]] 和 [[#7. 线性分析：偏差与 MASK|第 7 节]] 的语言说：AES S 盒的最大差分概率 4/256 = $2^{-6}$，最大线性偏差 $2^{-4}$，都压在设计上界附近。

**ShiftRows**：第 $r$ 行循环左移 $r$ 位。它不改变任何字节，只把字节搬到别处——一列里的 4 个字节从此各奔一行。

**MixColumns**：把状态的每一列当 GF(2^8) 上的多项式与固定多项式相乘取模；写成矩阵就是列向量乘一个循环移位系数矩阵：

$$\begin{pmatrix} s'_0 \\ s'_1 \\ s'_2 \\ s'_3 \end{pmatrix} = \begin{pmatrix} 02 & 03 & 01 & 01 \\ 01 & 02 & 03 & 01 \\ 01 & 01 & 02 & 03 \\ 03 & 01 & 01 & 02 \end{pmatrix} \begin{pmatrix} s_0 \\ s_1 \\ s_2 \\ s_3 \end{pmatrix} \tag{5.5}$$

乘 2 用 xtime、乘 3 = xtime 再异或原值（[[#3. GF(2^8)：AES 的数学地基|第 3 节]]），矩阵每行只有两处真正的乘法。

**AddRoundKey**：状态逐字节异或当前轮密钥，全部轮里唯一的密钥注入点。

分工一句话：==SubBytes 负责混淆（非线性），ShiftRows 加 MixColumns 负责扩散==。SubBytes 逐字节独立、毫无扩散；ShiftRows 把列摊到行上、MixColumns 把行混回列里，两者合起来两轮就能把 1 个字节的变化摊满全部 16 字节——这是 AES 算好的指标（宽轨迹策略，[[#6.5 真实 AES 为什么打不动|6.5]]）。最后一轮省掉 MixColumns 是标准定义：末层的列混合可以并进等效轮密钥，省一遍运算、不降安全性。

## 5. 密钥扩展与手写 AES-128

密钥扩展把 16 字节主密钥摊成 11 把轮密钥（44 个 4 字节字）：W[0..3] 直接抄主密钥；W[i] 由 W[i-1] 加工后异或 W[i-4] 得到，每逢 i 是 4 的倍数多做三件事——RotWord（循环左移一字节）、SubWord（逐字节过 S 盒）、异或 Rcon（轮常数，$x^{i/4-1}$，即 01 02 04 08 10 20 40 80 1B 36）。完整实现与检查分两段，合成一个脚本：

```python
# aes_hand.py（上半）—— GF(2^8) 基础件、S 盒构造、密钥扩展
from Crypto.Cipher import AES
from Crypto.Random import get_random_bytes

POLY = 0x11B                                   # GF(2^8) 模多项式 x^8 + x^4 + x^3 + x + 1

def xt(a):
    a <<= 1
    return (a ^ POLY) & 0xFF if a & 0x100 else a

def gm(a, b):
    p = 0
    while b:
        if b & 1:
            p ^= a
        a = xt(a)
        b >>= 1
    return p

def rotl8(x, n):
    return ((x << n) | (x >> (8 - n))) & 0xFF

GINV = [0] * 256                               # GF(2^8) 逆元表：穷举乘法表
for a in range(1, 256):
    for b in range(1, 256):
        if gm(a, b) == 1:
            GINV[a] = b
            break

SBOX = [GINV[a] ^ rotl8(GINV[a], 1) ^ rotl8(GINV[a], 2) ^ rotl8(GINV[a], 3)
        ^ rotl8(GINV[a], 4) ^ 0x63 for a in range(256)]     # 求逆 + 仿射
ISBOX = [0] * 256
for a in range(256):
    ISBOX[SBOX[a]] = a

print("S(0x00) =", hex(SBOX[0]), " S(0x53) =", hex(SBOX[0x53]), "（0x53 的逆元 =", hex(GINV[0x53]), "→ 仿射）")

RCON = [0x00, 0x01, 0x02, 0x04, 0x08, 0x10, 0x20, 0x40, 0x80, 0x1B, 0x36]

def key_expansion(key):                        # 16 字节密钥 -> 44 个 4 字节字
    w = [list(key[4 * i:4 * i + 4]) for i in range(4)]
    for i in range(4, 44):
        t = list(w[i - 1])
        if i % 4 == 0:
            t = [SBOX[b] for b in t[1:] + t[:1]]     # RotWord + SubWord
            t[0] ^= RCON[i // 4]                      # 异或 Rcon
        w.append([w[i - 4][j] ^ t[j] for j in range(4)])
    return w
```

```python
# aes_hand.py（下半）—— 四个轮变换、加解密、三组检查
def sub_bytes(s):      return [SBOX[b] for b in s]
def inv_sub_bytes(s):  return [ISBOX[b] for b in s]
# 平面下标 = r + 4c（列主序），列表推导必须按 c 外层 r 内层输出，输出顺序才是列主序
def shift_rows(s):     return [s[r + 4 * ((c + r) % 4)] for c in range(4) for r in range(4)]
def inv_shift_rows(s): return [s[r + 4 * ((c - r) % 4)] for c in range(4) for r in range(4)]

def mix_columns(s):
    out = list(s)
    for c in range(4):
        a = [s[r + 4 * c] for r in range(4)]
        out[0 + 4 * c] = gm(2, a[0]) ^ gm(3, a[1]) ^ a[2] ^ a[3]
        out[1 + 4 * c] = a[0] ^ gm(2, a[1]) ^ gm(3, a[2]) ^ a[3]
        out[2 + 4 * c] = a[0] ^ a[1] ^ gm(2, a[2]) ^ gm(3, a[3])
        out[3 + 4 * c] = gm(3, a[0]) ^ a[1] ^ a[2] ^ gm(2, a[3])
    return out

def inv_mix_columns(s):
    out = list(s)
    for c in range(4):
        a = [s[r + 4 * c] for r in range(4)]
        out[0 + 4 * c] = gm(14, a[0]) ^ gm(11, a[1]) ^ gm(13, a[2]) ^ gm(9, a[3])
        out[1 + 4 * c] = gm(9, a[0]) ^ gm(14, a[1]) ^ gm(11, a[2]) ^ gm(13, a[3])
        out[2 + 4 * c] = gm(13, a[0]) ^ gm(9, a[1]) ^ gm(14, a[2]) ^ gm(11, a[3])
        out[3 + 4 * c] = gm(11, a[0]) ^ gm(13, a[1]) ^ gm(9, a[2]) ^ gm(14, a[3])
    return out

def add_round_key(s, w, rnd):
    for c in range(4):
        for r in range(4):
            s[r + 4 * c] ^= w[4 * rnd + c][r]
    return s

def encrypt_block(pt, key):
    w = key_expansion(key)
    s = list(pt)
    add_round_key(s, w, 0)
    for rnd in range(1, 11):
        s = sub_bytes(s)
        s = shift_rows(s)
        if rnd < 10:
            s = mix_columns(s)
        add_round_key(s, w, rnd)
    return bytes(s)

def decrypt_block(ct, key):
    w = key_expansion(key)
    s = list(ct)
    add_round_key(s, w, 10)
    for rnd in range(9, -1, -1):
        s = inv_shift_rows(s)
        s = inv_sub_bytes(s)
        add_round_key(s, w, rnd)
        if rnd > 0:
            s = inv_mix_columns(s)
    return bytes(s)

# ---- 检查一：FIPS 197 附录 C.1 已知答案 ----
key = bytes.fromhex("000102030405060708090a0b0c0d0e0f")
pt = bytes.fromhex("00112233445566778899aabbccddeeff")
ct = encrypt_block(pt, key)
print("FIPS C.1 密文 =", ct.hex())
print("期望          = 69c4e0d86a7b0430d8cdb78070b4c55a, 相等:", ct.hex() == "69c4e0d86a7b0430d8cdb78070b4c55a")
print("解密还原      =", decrypt_block(ct, key).hex(), " 等于明文:", decrypt_block(ct, key) == pt)

# ---- 检查二：随机密钥/明文与 pycryptodome 单块对拍 ----
ok = True
for _ in range(5):
    k = get_random_bytes(16)
    m = get_random_bytes(16)

# ---- 检查三：FIPS 197 附录 B 例子的第一轮轨迹 ----
key = bytes.fromhex("2b7e151628aed2a6abf7158809cf4f3c")
```

## 6. 差分分析入门：打穿一个 toy SPN

差分分析（Biham 与 Shamir，1990）是分组密码的第一个系统性统计攻击，公开发表后直接重塑了此后所有 S 盒的设计标准。本节造一个 16 位的 toy SPN，把完整流程走一遍：造差分分布表 → 找高概率差分路径 → 选择明文 → 末轮密钥投票 → 反推主密钥。

### 6.1 靶子：4 轮 toy SPN

16 位分组；4 个 4 位 S 盒并行当代换层；一个固定的位置换当扩散层（第 $i$ 位搬去第 $4i \bmod 15$ 位，第 15 位不动）；密钥调度故意极简：5 把 16 位轮密钥全部是主密钥循环左移 0 到 4 位。加密 4 轮：前 3 轮"异或轮密钥 → S 层 → P 层"，第 4 轮"异或轮密钥 → S 层 → 异或末轮密钥"收尾。

```python
# toyspn_attack.py（第 1 段）—— toy SPN 靶子：S 层、P 层、密钥调度、加解密
import random

SBOX = [0xE, 0x4, 0xD, 0x1, 0x2, 0xF, 0xB, 0x8, 0x3, 0xA, 0x6, 0xC, 0x5, 0x9, 0x0, 0x7]
ISBOX = [0] * 16
for i, v in enumerate(SBOX):
    ISBOX[v] = i
PERM = [(4 * i) % 15 for i in range(15)] + [15]
IPERM = [0] * 16
for i in range(16):
    IPERM[PERM[i]] = i

def permute(x):
    y = 0
    for i in range(16):
        if (x >> (15 - i)) & 1:
            y |= 1 << (15 - PERM[i])
    return y

def unpermute(x):
    y = 0
    for i in range(16):
        if (x >> (15 - i)) & 1:
            y |= 1 << (15 - IPERM[i])
    return y

def s_layer(x):
    v = 0
    for j in range(4):
        v |= SBOX[(x >> (12 - 4 * j)) & 0xF] << (12 - 4 * j)
    return v

def inv_s_layer(x):
    v = 0
    for j in range(4):
        v |= ISBOX[(x >> (12 - 4 * j)) & 0xF] << (12 - 4 * j)
    return v

def rotl16(x, n):
    return ((x << n) | (x >> (16 - n))) & 0xFFFF

def round_keys(master):                        # 密钥调度：轮密钥 = 主密钥循环左移 r 位
    return [rotl16(master, r) for r in range(5)]

def encrypt(pt, keys):
    x = pt
    for r in range(4):
        x ^= keys[r]
        v = s_layer(x)
        x = permute(v) if r < 3 else v
    return x ^ keys[4]

def decrypt_block(c, keys):
    x = inv_s_layer(c ^ keys[4]) ^ keys[3]
    x = inv_s_layer(unpermute(x)) ^ keys[2]
    x = inv_s_layer(unpermute(x)) ^ keys[1]
    x = inv_s_layer(unpermute(x)) ^ keys[0]
    return x

random.seed(20261024)
MASTER = 0x5B7A
KEYS = round_keys(MASTER)
flag = b"flag{d1ff_w1n}"
ct_flag = b"".join(bytes([encrypt((flag[i] << 8) | flag[i + 1], KEYS) >> 8,
                          encrypt((flag[i] << 8) | flag[i + 1], KEYS) & 0xFF])
                   for i in range(0, len(flag), 2))
print("靶子: 主密钥 = %04x（攻击者不知道），明文 = %s" % (MASTER, flag.decode()))
print("7 个分组密文(hex):", ct_flag.hex())
p0 = 0x1234
print("自检 decrypt(encrypt(p)) == p:", decrypt_block(encrypt(p0, KEYS), KEYS) == p0)
```

出题侧把 flag 逐 16 位分组加密；攻击侧只知道密文，外加"可以任选明文差分请靶子加密"这一条（选择明文）。

### 6.2 差分与差分分布表

固定一对值 $(x, x')$，它们的**异或差**是 $\Delta x = x \oplus x'$——注意是异或不是减法。进 S 盒之前两个输入异或的是同一把轮密钥，差不受影响：

$$\Delta u = (x \oplus K) \oplus (x' \oplus K) = x \oplus x' \tag{5.6}$$

S 盒是非线性的，同一个输入差会映射出不同的输出差。把每种 $\Delta_{in} \to \Delta_{out}$ 出现的次数数成一张 16×16 的表，就是**差分分布表**（DDT）：$\mathrm{DDT}[a][b] = \#\{x : S(x) \oplus S(x \oplus a) = b\}$。它只依赖 S 盒本身——==攻击者没有密钥也能把 DDT 完整算出来==。

```python
# toyspn_attack.py（第 2 段）—— 差分分布表
DDT = [[0] * 16 for _ in range(16)]
for a in range(16):
    for x in range(16):
        DDT[a][SBOX[x] ^ SBOX[x ^ a]] += 1
print("DDT[0x6]:", {hex(d): c for d, c in enumerate(DDT[6]) if c})
print("DDT[0xB]:", {hex(d): c for d, c in enumerate(DDT[0xB]) if c})
```

完整运行与输出在 [[#6.4 最后一轮密钥恢复|6.4]] 末尾，这里先读两行 DDT：

- `DDT[0xB]`：输入差 0xB 的 16 个输入里，8 个的输出差是 0x2，各 2 个是 0x5、0x7、0xD、0xF。==一行里的最大值除以 16，就是这条差分通过 S 盒的概率==——0xB → 0x2 的概率是 8/16 = 1/2；
- 若 S 盒是"完美随机"的双射，每格期望值是 1（概率 1/16）。AES S 盒的最大格值是 4（概率 2^-6），这张玩具表里出现了 8——==S 盒 DDT 的峰值大小，直接决定差分攻击的难度==。

### 6.3 差分路径与概率

DDT 只描述一轮。多轮的**差分特征**（characteristic）把每轮的输入差、输出差串成一条链，总概率是各跳 S 盒差分概率的乘积——P 层是确定性的位重排，不耗概率：

$$p = \prod_{r} \Pr[\Delta v_r \mid \Delta u_r] \tag{5.7}$$

拿 DDT 在 16 位差分状态上做动态规划（每层按 DDT 全分支展开、经 P 层确定性传播、保留每落点的最大概率路径），在全部 64 个"单半字节活跃"起点里搜 3 轮最优特征，脚本与结果收进折叠框：

> [!info]- 最优 3 轮特征的搜索脚本（toyspn_explore.py）
>
> ```python

>         nib = (d >> (12 - 4 * j)) & 0xF
>         if nib:
>             opts.append([(od << (12 - 4 * j), DDT[nib][od]) for od in range(16) if DDT[nib][od]])
>         else:
>             opts.append([(0, 1)])
>     out = {}
>     for combo in itertools.product(*opts):
>         nd, cnt = 0, 1
>         for v, c in combo:
>             nd |= v
>             cnt *= c
>         if out.get(nd, 0) < cnt:

>     return out

总概率 $(8/16)(6/16)(36/256) = 0.0264$。这条链最有价值的地方在终点：==Δu4 = 0x0606 只激活最后一轮的两个 S 盒（半字节 1、3，各带输入差 6）==——前 3 轮的概率消耗，换来最后一轮只剩 8 位未知密钥要猜。

### 6.4 最后一轮密钥恢复

攻击模型：攻击者任选明文 $p$ 与 $p \oplus \Delta P$（$\Delta P = \texttt{0x0B00}$）请靶子加密，拿到两份密文。第 4 轮是 $c = S(u_4) \oplus K_4$，而 $u_4$ 的差分被特征定死为 0x0606。对末轮密钥的两个活跃半字节穷举全部 $16 \times 16$ 个候选 $(g_1, g_3)$，用逆 S 盒把密文剥掉最后一层，检验

$$\mathrm{ISBOX}[c_j \oplus g_j] \oplus \mathrm{ISBOX}[c'_j \oplus g_j] \stackrel{?}{=} 6 \tag{5.8}$$

正确的候选下，走了特征的明文对必然通过检验；没走的以 $2^{-8}$ 的概率碰巧通过；错误候选只有后者。1 万对明文之后数票：

```python
def encrypt_trace(pt, keys):
    vs, x = [], pt
    for r in range(4):
        x ^= keys[r]
        v = s_layer(x)
        vs.append(v)
        x = permute(v) if r < 3 else v
    return vs

D = [0x0B00, 0x0200, 0x0060, 0x0550]           # Δu1, Δv1, Δv2, Δv3
DELTA_P = D[0]

print("差分路径: Δu1=%04x -> Δv1=%04x ->P-> Δu2=%04x -> Δv2=%04x ->P-> Δu3=%04x -> Δv3=%04x ->P-> Δu4=%04x"
      % (D[0], D[1], permute(D[1]), D[2], permute(D[2]), D[3], D_U4))
print("路径概率 = (8/16)*(6/16)*(36/256) = %.5f" % ((8 / 16) * (6 / 16) * (36 / 256)))

N_CHECK = 50000
hit = 0
for _ in range(N_CHECK):

    vb = encrypt_trace(p ^ DELTA_P, KEYS)
    if (va[0] ^ vb[0]) == D[1] and (va[1] ^ vb[1]) == D[2] and (va[2] ^ vb[2]) == D[3]:
        hit += 1

N = 10000

for _ in range(N):

print("对 (K4 半字节1, K4 半字节3) 的 256 个候选投票，前 4 名：")

    print("  K4[1]=%x K4[3]=%x  票数 %d" % (g1, g3, cnt))

# 密钥调度 K4 = rotl16(K,4)：K4 半字节 1 就是主密钥半字节 2，K4 半字节 3 就是主密钥半字节 0。
# 主密钥剩下半字节 1、3 共 8 位，用一对已知明文穷举补全：
known_p, known_c = pts[0], pairs[0][0]

for n1 in range(16):

pt_flag = b""
```

### 6.5 真实 AES 为什么打不动

把同一套流程对准 AES：AES S 盒的 DDT 峰值是 4（概率 $2^{-6}$），而且设计者用**宽轨迹策略**（wide trail）选定了 ShiftRows 与 MixColumns 的扩散参数，保证任何 4 轮差分特征至少激活 25 个 S 盒——按最大差分概率折算，4 轮特征的概率上界是 $2^{-150}$。toy 的 4 轮特征概率是 $2^{-5.2}$，AES 的同位置上界是 $2^{-150}$：==差约 145 个数量级，明文对数量 $N$ 从一万对变成天文数字==。完整 AES-128 十轮还要在这之上再叠 6 轮，公开文献里对全轮 AES 的最好结果也只把 $2^{128}$ 的穷举压缩了不到两个比特。§1 的共识在这里有了算术支撑：==S 盒加扩散构成的算法层防线，正是差分/线性分析打不动的那一层；真实攻击全部发生在模式与实现层==。

## 7. 线性分析：偏差与 MASK

线性分析（Matsui，1993）是差分的孪生武器：差分追踪"两份输入的异或差"，线性分析追踪**固定掩码下的奇偶关系**。对 S 盒挑两组掩码 $\alpha$（输入）、$\beta$（输出），考察等式

$$\alpha \cdot x \oplus \beta \cdot S(x) = 0 \qquad (\alpha \cdot x \text{ 表示 } x \text{ 与 } \alpha \text{ 按位与后 1 的个数的奇偶}) \tag{5.9}$$

它对随机 $x$ 成立的概率几乎从不正好是 1/2，偏离量 $\epsilon = \Pr[\text{成立}] - 1/2$ 叫**偏差**。==偏差非零，意味着输入输出的奇偶位之间存在可测的相关，密钥再长也抹不掉==。把每个 $(\alpha, \beta)$ 的偏差数成 16×16 的**线性逼近表**（LAT），就是线性分析版的 DDT。整段实验一个脚本：LAT 峰值、两轮逼近的精确偏差、抽样对照：

```python
# linear_toy.py —— 线性分析：LAT、偏差、piling-up 引理、两轮线性逼近的预测与对照
import random

SBOX = [0xE, 0x4, 0xD, 0x1, 0x2, 0xF, 0xB, 0x8, 0x3, 0xA, 0x6, 0xC, 0x5, 0x9, 0x0, 0x7]
PERM = [(4 * i) % 15 for i in range(15)] + [15]

def permute(x):
    y = 0
    for i in range(16):
        if (x >> (15 - i)) & 1:
            y |= 1 << (15 - PERM[i])
    return y

def s_layer(x):
    v = 0
    for j in range(4):
        v |= SBOX[(x >> (12 - 4 * j)) & 0xF] << (12 - 4 * j)
    return v

def parity(x, m):
    return bin(x & m).count("1") & 1

# LAT：LAT[a][b] = #{x : a·x = b·S(x)} - 8，偏差 = LAT / 16
LAT = [[sum(1 for x in range(16) if parity(x, a) == parity(SBOX[x], b)) - 8
        for b in range(16)] for a in range(16)]
print("LAT 峰值条目（|值| 前 5，a 为输入掩码，b 为输出掩码）:")
flat = sorted(((abs(LAT[a][b]), a, b) for a in range(1, 16) for b in range(1, 16)), reverse=True)
for v, a, b in flat[:5]:
    print("  a=%x b=%x  LAT=%+d  成立概率 %2d/16  偏差 %+.3f" % (a, b, LAT[a][b], 8 + LAT[a][b], LAT[a][b] / 16))

# 两轮组合：x --S--> v --P--> w --S--> y，全表预计算（2^16 个输入）
def scatter(mask):
    y = 0
    for i in range(16):
        if (mask >> (15 - i)) & 1:
            y |= 1 << (15 - PERM[i])
    return y

TBL = [s_layer(permute(s_layer(x))) for x in range(1 << 16)]

# 每条逼近只用两个近似：第 1 轮单半字节 (a1 -> b1)，b1 限单比特，使 P 后仍只激活一个半字节；
# 第 2 轮在该半字节内选 |LAT| 最大的 (m -> b2)。piling-up：总偏差 = 2·(2e1)·(2e2)。
cands = []
for j in range(4):
    for a1 in range(1, 16):
        for bit in range(4):
            b1 = 1 << bit
            e1 = LAT[a1][b1] / 16
            if e1 == 0:
                continue
            a2 = scatter(b1 << (12 - 4 * j))
            pos = next(i for i in range(16) if (a2 >> (15 - i)) & 1)
            m = (a2 >> (12 - 4 * (pos // 4))) & 0xF
            for b2 in range(1, 16):
                e2 = LAT[m][b2] / 16
                if e2 == 0:
                    continue
                pred = 2 * (2 * e1) * (2 * e2)
                cands.append((abs(pred), pred, a1 << (12 - 4 * j), b2 << (12 - 4 * (pos // 4))))
cands.sort(reverse=True)

print("piling-up 预测偏差最大的 5 条两轮逼近（对照全表枚举的精确偏差）:")
for _, pred, inmask, outmask in cands[:5]:
    cnt = sum(1 for x in range(1 << 16) if parity(x, inmask) == parity(TBL[x], outmask))
    exact = cnt / (1 << 16) - 0.5
    print("  in=%04x out=%04x  预测 %+.4f  精确 %+.4f" % (inmask, outmask, pred, exact))

# 对照组：只允许 |LAT| = 2 的小偏差近似，piling-up 应当准得多
small = [c for c in cands if c[0] <= 0.126 and c[0] > 0.124]
if small:
    _, pred, inmask, outmask = small[0]
    cnt = sum(1 for x in range(1 << 16) if parity(x, inmask) == parity(TBL[x], outmask))
    exact = cnt / (1 << 16) - 0.5
    print("小偏差对照: in=%04x out=%04x  预测 %+.4f  精确 %+.4f" % (inmask, outmask, pred, exact))

pred, inmask, outmask = cands[0][1], cands[0][2], cands[0][3]
random.seed(20261024)
M = 400000
agree = 0
for _ in range(M):
    x = random.getrandbits(16)
    if parity(x, inmask) == parity(TBL[x], outmask):
        agree += 1
print("取第一条: 随机 %d 个输入的抽样频率 = %.4f, 抽样偏差 = %+.4f" % (M, agree / M, agree / M - 0.5))
```

读输出，三件事：

- **LAT 峰值 ±6**：玩具 S 盒的最大偏差 0.375，大得离谱——AES S 盒是 $2^{-4} = 0.0625$，DES 的更小。S 盒压偏差，压的就是这张表的峰值；
- **两轮逼近真实存在**：掩码链 $a_1 \to b_1 \to a_2 \to b_2$（第一轮的输出掩码经 P 层位置换直接变成第二轮的输入掩码）串出的关系 $a_1 \cdot x \oplus b_2 \cdot y = 0$，精确偏差 +0.1875（$2^{16}$ 全表枚举），40 万随机输入抽出的 +0.1887 与它吻合——==多轮线性关系可测量，抽样与枚举互相印证==；
- **piling-up 引理在这张玩具表上失准**：串接 $n$ 个近似时，标准估计公式是

$$\epsilon_{\text{总}} \approx 2^{n-1} \prod_{i=1}^{n} 2\epsilon_i \tag{5.10}$$

  它预测 +0.75，精确值只有 +0.1875——(5.10) 假设各近似统计独立，==偏差越大、状态越小，独立性失效越狠==。真实密码的偏差在 $2^{-4}$ 以下、状态以千比特计，piling-up 才是可用的估算工具；玩具上只取它"偏差同号、量级可观"的定性，精确值交给全表枚举，核对交给抽样。

**MASK 概念**：$\alpha$、$\beta$ 就叫掩码（MASK）——固定"盯住哪些位"的图案。多轮线性路径就是掩码的传播链：输入掩码进 S 盒，查 LAT 挑偏差最大的输出掩码；过 P 层，位置换直接搬移掩码位；再进下一轮 S 盒。Matsui 用两轮逼近加一轮滤波，以 $2^{43}$ 已知明文恢复了 16 轮 DES 的密钥——与差分并列，是史上唯二对 DES 全轮的系统性统计攻击。

| | 差分分析 | 线性分析 |
| ---- | ---- | ---- |
| 数据 | 选择明文（要控制差分） | 已知明文即可 |
| 追踪对象 | 异或差在 S 盒里的传播 | 掩码奇偶关系的偏差 |
| 数据结构 | DDT | LAT |
| 末轮恢复 | 逆 S 盒剥层，逐半字节投票 | 逐位计票（奇偶计数偏向哪边） |
| 代表战果 | Biham-Shamir 1991，DES | Matsui 1993，DES，$2^{43}$ 已知明文 |

CTF 里纯线性分析的 toy 题少见（数据量要求大），但 LAT 与偏差是评估 S 盒、读代数攻击论文的基本功。

## 8. TEA/XTEA/XXTEA：Feistel 变体与等效密钥

### 8.1 结构：无 S 盒的 Feistel

TEA（Tiny Encryption Algorithm，Wheeler，1994）：64 位分组拆成两个 32 位字 $v_0, v_1$，128 位密钥拆成 4 个 32 位字，32 轮。没有 S 盒，混淆全靠移位、异或、模 $2^{32}$ 加法的混合，每对半轮形如

$$v_0 \mathrel{+}= ((v_1 \ll 4) + K_0) \oplus (v_1 + s) \oplus ((v_1 \gg 5) + K_1), \qquad s \mathrel{+}= \delta \tag{5.11}$$

下一半轮对称，用 $K_2, K_3$ 更新 $v_1$。$\delta = \texttt{0x9E3779B9} = \lfloor 2^{32}/\varphi \rfloor$（$\varphi$ 是黄金比 1.618…）是固定常数，作用是让每轮的 $s$ 不同——没有它，32 轮的运算模式完全重复。TEA 没有密钥调度：$K_0 \ldots K_3$ 原样每轮上场，==这个"简洁"正是它的结构性漏洞==（8.2 节）。

```python
# tea_demo.py（上半）—— TEA 加解密与块处理
import struct
from Crypto.Random import get_random_bytes

DELTA = 0x9E3779B9
M32 = 0xFFFFFFFF

def tea_encrypt(v0, v1, key, rounds=32):
    k0, k1, k2, k3 = key
    s = 0
    for _ in range(rounds):
        s = (s + DELTA) & M32
        v0 = (v0 + ((((v1 << 4) + k0) ^ (v1 + s) ^ ((v1 >> 5) + k1)) & M32)) & M32
        v1 = (v1 + ((((v0 << 4) + k2) ^ (v0 + s) ^ ((v0 >> 5) + k3)) & M32)) & M32
    return v0, v1

def tea_decrypt(v0, v1, key, rounds=32):
    k0, k1, k2, k3 = key
    s = (DELTA * rounds) & M32
    for _ in range(rounds):
        v1 = (v1 - ((((v0 << 4) + k2) ^ (v0 + s) ^ ((v0 >> 5) + k3)) & M32)) & M32
        v0 = (v0 - ((((v1 << 4) + k0) ^ (v1 + s) ^ ((v1 >> 5) + k1)) & M32)) & M32
        s = (s - DELTA) & M32
    return v0, v1

def tea_ecb(data, key, rounds=32):
    out = b""
    for i in range(0, len(data), 8):
        a, b = struct.unpack(">II", data[i:i + 8])
        out += struct.pack(">II", *tea_encrypt(a, b, key, rounds))
    return out

def tea_dec_ecb(data, key, rounds=32):
    out = b""
    for i in range(0, len(data), 8):
        a, b = struct.unpack(">II", data[i:i + 8])
        out += struct.pack(">II", *tea_decrypt(a, b, key, rounds))
    return out

key = (0x01234567, 0x89ABCDEF, 0xFEDCBA98, 0x76543210)
flag = b"flag{9e3779b9}"
pad = flag + b"\x00" * (-len(flag) % 8)
ct = tea_ecb(pad, key)
print("TEA 密文 =", ct.hex())
print("解密     =", tea_dec_ecb(ct, key).rstrip(b"\x00"))
```

### 8.2 等效密钥：4 把密钥加密出同一份密文

盯着 (5.11) 的半轮看最高位。$K_0$ 的最高位只在 $(v_1 \ll 4) + K_0$ 这一项里出现：翻转它，这一项的最高位翻转、其余 31 位纹丝不动（加法的低 31 位不受加数最高位影响）。$K_1$ 的最高位同理，只翻 $(v_1 \gg 5) + K_1$ 的最高位。==两处翻转出现在同一个异或里，互相抵消，半轮输出逐位不变==。$v_1$ 的半轮用 $K_2, K_3$，完全不受影响。于是

$$K' = (K_0 \oplus 2^{31},\ K_1 \oplus 2^{31},\ K_2,\ K_3)$$

与原密钥加密出完全相同的密文；把 $K_2, K_3$ 的最高位一起翻同理成立；组合起来，==每个 TEA 密钥有 3 把等效密钥（连同自己共 4 把），128 位密钥实际只有 126 位有效==。脚本中段做完整核对（对应输出的第 3 到第 6 行）：

```python
# tea_demo.py（中段）—— 等效密钥构造与批量核对
key2 = (key[0] ^ 0x80000000, key[1] ^ 0x80000000, key[2], key[3])
print("等效密钥 A（K0、K1 最高位一起翻）加密同密文:", tea_ecb(pad, key2) == ct)
print("用等效密钥 A 解密:", tea_dec_ecb(ct, key2).rstrip(b"\x00"))
key3 = (key[0], key[1], key[2] ^ 0x80000000, key[3] ^ 0x80000000)
print("等效密钥 B（K2、K3 最高位一起翻）加密同密文:", tea_ecb(pad, key3) == ct)

# 4 个等效变体（含原密钥）在随机密钥上的通用性
MSB = 0x80000000
ok = True
for _ in range(200):
    k = struct.unpack(">IIII", get_random_bytes(16))
    m = get_random_bytes(8)
    ref = tea_ecb(m, k)
    for f in ((0, 0, 0, 0), (MSB, MSB, 0, 0), (0, 0, MSB, MSB), (MSB, MSB, MSB, MSB)):
        kk = (k[0] ^ f[0], k[1] ^ f[1], k[2] ^ f[2], k[3] ^ f[3])
        ok &= tea_ecb(m, kk) == ref
print("200 把随机密钥 x 4 个等效变体全部同密文:", ok)
```

> [!info]- 为什么恰好是"最高位"
> 翻转加数的第 $b$ 位，和的第 $b$ 位跟着翻，但第 $b$ 位以上的进位可能变化，差异会向高位扩散；只有 bit 31 上面没有位，翻转的效果被严格限制在这一位里，抵消才是逐位干净的。这就是等效密钥只出现在最高位上的原因——也解释了为什么这个漏洞跟移位/加法的具体参数无关，是"加法异或混合"结构的通病。

CTF 用法一句话：题目给出"密文 + 密钥的一部分"，或要求证明两把不同密钥加密同一密文时，直接按上式构造等效密钥补齐缺失，不必爆破 $2^{31}$。

### 8.3 XTEA 的修正与 XXTEA

XTEA（Wheeler 与 Needham，1997）就是冲着密钥调度来的，半轮改成：

```text
v0 += (((v1 << 4) ^ (v1 >> 5)) + v1) ^ (s + K[s & 3]);   s += delta
v1 += (((v0 << 4) ^ (v0 >> 5)) + v0) ^ (s + K[(s >> 11) & 3])
```

四把密钥字按 $s$ 的位段轮换上场，TEA 那种"K0/K1 永远管 $v_0$、K2/K3 永远管 $v_1$"的固定槽位消失，8.2 的抵消构造不再成立。脚本末段给出 XTEA 的加解密实现与往返检查（对应输出的最后一行）：

```python
# tea_demo.py（末段）—— XTEA：sum 控制的轮密钥槽位
def xtea_encrypt(v0, v1, key, rounds=32):
    k = list(key)
    s = 0
    for _ in range(rounds):
        v0 = (v0 + (((((v1 << 4) ^ (v1 >> 5)) + v1) & M32) ^ ((s + k[s & 3]) & M32))) & M32
        s = (s + DELTA) & M32
        v1 = (v1 + (((((v0 << 4) ^ (v0 >> 5)) + v0) & M32) ^ ((s + k[(s >> 11) & 3]) & M32))) & M32
    return v0, v1

def xtea_decrypt(v0, v1, key, rounds=32):
    k = list(key)
    s = (DELTA * rounds) & M32
    for _ in range(rounds):
        v1 = (v1 - (((((v0 << 4) ^ (v0 >> 5)) + v0) & M32) ^ ((s + k[(s >> 11) & 3]) & M32))) & M32
        s = (s - DELTA) & M32
        v0 = (v0 - (((((v1 << 4) ^ (v1 >> 5)) + v1) & M32) ^ ((s + k[s & 3]) & M32))) & M32
    return v0, v1

m = struct.unpack(">II", get_random_bytes(8))
a, b = xtea_encrypt(*m, key)
print("XTEA 加解密往返:", xtea_decrypt(a, b, key) == m)
```

XXTEA（1998，Corrected Block TEA）再进一步：把整条消息当一个大块做混合，块长可变；CTF 里偶见，认出名字即可。

### 8.4 CTF 出场形态与解密模板

TEA 一族是逆向题常客，识别特征固定四条：

1. 常数 `0x9E3779B9`——在反汇编里搜这个立即数是最快入口；
2. 8 字节一组的数据处理，拆成两个 32 位字；
3. `<< 4` 与 `>> 5` 的成对移位；
4. 外层 32 次的循环加一个累加变量。

题面常被魔改：换 delta、加轮数、移位量改成 3/7、异或与加法互换、密钥从字符串散列而来。==解密脚本必须照抄题目二进制里的实际运算再反向写==，拿标准模板硬套魔改题只会得到乱码。整个解题脚本就是 8.1 中 `tea_dec_ecb` 的函数体加两行拆包——输入题目给的密钥与密文 hex，逐 8 字节 `struct.unpack(">II")`、调 `tea_decrypt`、`pack` 回去。

> [!note] 与 pycryptodome 的分工
> 库里收录的是 AES、DES、DES3、Blowfish、ChaCha20、ARC4 这些标准算法（见 [[C01-密码学导论与工具链|C01]] 的四层分工），TEA/XTEA/XXTEA 不在其中——它们本来就是教学与嵌入式里的小算法。==遇到 TEA 题就手写 32 轮循环==，8.1 的三十行可以直接背。

> [!warning] TEA 的变体写法远不止一种
> 流传的 TEA 代码里，`(v1<<4)+k0` 有写作 `(v1<<4)^k0` 的，移位量有 3/7 的，解密时 `sum` 有逐轮重算的——看起来都"像 TEA"。逆向时把二进制里的运算逐条抄下来，解密脚本按抄下来的写；先入为主套标准模板，错误不会报错，只会给出乱码。

## 9. pycryptodome AES 用法速览

```python
# pyca_aes.py —— pycryptodome 的 AES：单块、ECB+PKCS7、CBC 往返
from importlib.util import find_spec
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad, unpad
from Crypto.Random import get_random_bytes

names = ["AES", "ARC4", "Blowfish", "CAST", "ChaCha20", "DES", "DES3", "Salsa20"]
print("pycryptodome 提供的密码:", [n for n in names if find_spec("Crypto.Cipher." + n)])

key = get_random_bytes(16)

block = b"0123456789abcdef"                        # 恰好 16 字节，可裸加密单块
c0 = AES.new(key, AES.MODE_ECB).encrypt(block)
p0 = AES.new(key, AES.MODE_ECB).decrypt(c0)
print("单块裸加解密往返:", p0 == block)

pt = b"flag{padding_1s_needed}"                    # 23 字节，不是 16 的倍数
ct = AES.new(key, AES.MODE_ECB).encrypt(pad(pt, 16))
print("ECB + PKCS7: 明文 %d 字节 -> 密文 %d 字节, 解密还原:" % (len(pt), len(ct)),
      unpad(AES.new(key, AES.MODE_ECB).decrypt(ct), 16) == pt)

iv = get_random_bytes(16)
ct = AES.new(key, AES.MODE_CBC, iv=iv).encrypt(pad(pt, 16))
ok = unpad(AES.new(key, AES.MODE_CBC, iv=iv).decrypt(ct), 16) == pt
print("CBC + PKCS7 往返:", ok)
```

```bash
python3 pyca_aes.py
```

输出：

```
pycryptodome 提供的密码: ['AES', 'ARC4', 'Blowfish', 'CAST', 'ChaCha20', 'DES', 'DES3', 'Salsa20']
单块裸加解密往返: True
ECB + PKCS7: 明文 23 字节 -> 密文 32 字节, 解密还原: True
CBC + PKCS7 往返: True
```

三条正确姿势：

- **单块才裸加密**：`encrypt` 不做任何填充，输入必须是 16 的倍数；一般消息用 `pad(pt, 16)` / `unpad(...)`（PKCS#7：缺 $n$ 字节就补 $n$ 个 $n$）；
- **ECB 只用于单块或无结构数据**：多块 ECB 的重复泄漏见 [[09-密码学基础#3.3 分组密码与 ECB 的企鹅图|09 章 3.3]] 的企鹅图；
- **IV 每条消息随机新起**：`get_random_bytes(16)`。IV 重用的后果在 CBC 字节翻转（[[09-密码学基础#3.4 CBC 字节翻转|09 章 3.4]]）与流密码的密钥流重用（[[C03-序列密码与LFSR|C03]] 第 6 节的 WEP）里都见过。

模式层的攻击全集——ECB 分组重排、padding oracle、CBC 位翻转、nonce 重用——是下一章 C06 的主题。

## 10. 常见问题

| 现象 | 原因与解决 |
| ---- | ---- |
| 手写 AES 与库对拍不上，S 盒和轮密钥都对 | 状态行/列顺序错位：平面数组下标是 $r + 4c$（列主序），ShiftRows 的列表推导必须按 c 外层 r 内层输出（[[#5. 密钥扩展与手写 AES-128\|第 5 节]] 的 warning）；被转置的状态密文必然错 |
| MixColumns 算出超过 0xFF 的字节 | 乘 2、乘 3 没做 GF(2^8) 模约简：乘 2 过一遍 xtime，乘 3 = xtime 结果再异或原值（[[#3. GF(2^8)：AES 的数学地基\|第 3 节]]） |
| 想改动 S 盒的几个值做"定制 AES" | 单独改值会破坏"求逆 + 仿射"结构，连双射性都可能丢；做题时把题目给的表整张抄进代码，不要重造 |
| TEA 解密出来是乱码 | 三查：sum 是否从 $\delta \times 32$ 递减、块是否按 8 字节两个 u32 拆、struct 端序是 `>II` 还是 `<II`；再不对就是魔改轮函数，回反汇编逐条抄（[[#8.4 CTF 出场形态与解密模板\|8.4]]） |
| TEA 加密函数看着没错，密文和题目对不上 | 密钥四字的顺序或端序错：题目常给 16 字节字符串密钥，按大端还是小端解成 4 个 u32，结果完全不同 |
| 差分攻击的第一名票数和理论估计对不上 | 正常：第一名吸收的不只主特征，还有同终态的次优路径；判断标准是第一名显著抛离第二名，不是票数精确吻合（[[#6.4 最后一轮密钥恢复\|6.4]]） |
| 差分投票全是平票 | 明文差分没取成特征的入口 Δu1，或把 DDT 值当概率（对子数要除以 $16^{\text{活跃半字节数}}$）；先用已知密钥的演示场景统计路径命中率核对 |
| 差分只恢复了部分子密钥 | 特征的 Δu4 只覆盖部分活跃 S 盒：换一条终点落在其他半字节的差分再跑，或对剩余位做已知明文穷举（[[#6.4 最后一轮密钥恢复\|6.4]] 的两段式） |
| toy SPN 加一轮，差分攻击就失效 | 特征概率每多一轮至少除以 16，$N$ 不变时信号沉入噪声：按 $p$ 加大明文对数量，或接受"轮数就是安全边界"（[[#6.5 真实 AES 为什么打不动\|6.5]]） |
| pycryptodome 报"数据不是 16 的倍数" | 裸加密不做填充：先 `pad(pt, 16)`，解密后 `unpad`；只有恰好整块的数据才直接 encrypt（[[#9. pycryptodome AES 用法速览\|第 9 节]]） |
