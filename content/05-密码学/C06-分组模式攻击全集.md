## 1. 模式家族与安全性直观

### 1.1 五种模式怎么串联

分组密码 $E_K$ 本身只会做一件事：16 字节进、16 字节出。长消息要先切块，再把块与块**串**起来，串法就是工作模式。[[09-密码学基础#3.3 分组密码与 ECB 的企鹅图|09 章 3.3]] 已经用 ECB 的企鹅图说明"不串"的下场，[[09-密码学基础#3.4 CBC 字节翻转|09 章 3.4]] 手搓过 CBC；本章把五种常用模式放进同一张表。表的关键不在加密公式本身，而在三列性质：**块与块依赖谁、能不能并行、篡改一块密文会影响哪些明文**。

| 模式 | 第 $i$ 块的关系 | 依赖前块 | 并行性 | 篡改 $C_j$ 一个字节的影响 |
| ---- | ---- | ---- | ---- | ---- |
| ECB | $C_i = E_K(P_i)$ | 无 | 加解密都可并行 | 第 $j$ 块整体变乱 |
| CBC | $C_i = E_K(P_i \oplus C_{i-1})$ | 是 | 加密串行，解密可并行 | 第 $j$ 块整体变乱 + 第 $j{+}1$ 块同位置翻转 |
| CFB | $C_i = P_i \oplus E_K(C_{i-1})$ | 是 | 加密串行，解密可并行 | 第 $j$ 块同位置翻转 + 第 $j{+}1$ 块整体变乱 |
| OFB | $C_i = P_i \oplus z_i$，$z$ 与密文无关 | 否 | 加解密都可并行 | 只第 $j$ 块同位置翻转 |
| CTR | $C_i = P_i \oplus E_K(\text{nonce} \| i)$ | 否 | 加解密都可并行 | 只第 $j$ 块同位置翻转 |

OFB 和 CTR 把分组密码当"密钥流发生器"用：密钥流 $z$ 只由密钥和初始值决定，与明文密文都无关。这正是 [[C03-序列密码与LFSR|C03]] 里同步流密码的形态——$z = G(K)$，只是生成器换成了分组密码。这个视角直接决定了第 4 节的结论：[[09-密码学基础#3.2 密钥重用即死刑|09 章 3.2]] 的"密钥重用即死刑"对 CTR/OFB 原样生效，只不过"密钥"换成了 nonce。CFB 则是自同步流密码的代表，密钥流来自前一块密文，同 IV 只泄漏第一块。

> [!note] pycryptodome 里 CFB 的段大小
> pycryptodome 的 `MODE_CFB` 默认 `segment_size=8`，即按字节反馈的 CFB8；标准文献与 TLS 里说的 CFB 指 `segment_size=128` 的 CFB128。两种密文互不兼容，复现别人的密文时先对齐这个参数。

> [!info]- 为什么 CBC 加密不能并行、解密却可以
> 加密方向上，$C_i = E_K(P_i \oplus C_{i-1})$ 的输入里有上一块的**密文输出**，必须等前一块算完；解密方向上，$P_i = D_K(C_i) \oplus C_{i-1}$ 的两个操作数 $C_i$、$C_{i-1}$ 都是攻击者/接收者已经拿到的密文，各块可以同时算。这个不对称在第 2 节会被反复利用——攻击者手里的密文，就是解密方向的"并行输入"。

### 1.2 篡改传播范围

表的最后一列是本章多类攻击的物理基础，配一组数据。同一段 32 字节明文分别在五种模式下加密，把密文第 1 字节翻转后解密，数每块里错了几个字节：

```python
# modes_overview.py —— 五种模式同一明文加密；篡改密文第 1 字节，看错误传播范围
from Crypto.Cipher import AES
from Crypto.Random import get_random_bytes

key = get_random_bytes(16)
iv = get_random_bytes(16)
pt = b"AAAABBBBCCCCDDDDEEEEFFFFGGGGHHHH"      # 32 字节，正好两块

def enc(name):
    if name == "ECB": return AES.new(key, AES.MODE_ECB)
    if name == "CBC": return AES.new(key, AES.MODE_CBC, iv=iv)
    if name == "CFB": return AES.new(key, AES.MODE_CFB, iv=iv, segment_size=128)
    if name == "OFB": return AES.new(key, AES.MODE_OFB, iv=iv)
    if name == "CTR": return AES.new(key, AES.MODE_CTR, nonce=bytes(8))

def diff_blocks(a, b):
    return [sum(1 for x, y in zip(a[i:i+16], b[i:i+16]) if x != y)
            for i in range(0, len(a), 16)]

print("明文 32 字节分两块；篡改：密文第 1 字节翻转后解密")
for name in ["ECB", "CBC", "CFB", "OFB", "CTR"]:
    ct = enc(name).encrypt(pt)
    bad = bytearray(ct); bad[0] ^= 0x01
    pt2 = enc(name).decrypt(bytes(bad))
    d = diff_blocks(pt, pt2)
    print(f"{name}: 块1 错 {d[0]:2d}/16 字节，块2 错 {d[1]:2d}/16 字节")
```

```bash
python3 modes_overview.py
```

输出：

```

ECB: 块1 错 16/16 字节，块2 错  0/16 字节
CBC: 块1 错 16/16 字节，块2 错  1/16 字节
CFB: 块1 错  1/16 字节，块2 错 16/16 字节
OFB: 块1 错  1/16 字节，块2 错  0/16 字节
CTR: 块1 错  1/16 字节，块2 错  0/16 字节
```

五个数与表逐行对应：CBC 把"整个块变乱"留给当前块、把"同位置翻转"留给下一块（这就是字节翻转攻击的落点）；CFB 正好反过来；OFB/CTR 的密钥流与密文无关，错一个字节就只错一个字节——==流式模式下密文每一位都直接对应明文一位，改写权完全在持有密文的人手里==，第 4 节会把这个性质用足。

### 1.3 ECB 加密 oracle：逐字节恢复明文

1.1 的表里 ECB 是"不串"的那一行，1.2 的传播表给它的判语是"篡改哪块哪块乱"。它在保密性上还有更根本的口子：==ECB 没有任何随机化——同一明文块永远加密成同一密文块==。攻击者不需要密钥，只要能"喂一段明文、拿回一段密文"（加密 oracle），就能把服务端藏在加密流程里的机密逐字节问出来。

服务形态。典型载体是把攻击者可控的输入拼进加密流程：前缀是服务自加的字段（会话标识、字段名），后缀是服务要保住的机密（flag、token）：

$$E_K(\text{prefix} \,\|\, \text{user\_input} \,\|\, \text{unknown}) \tag{6.6}$$

自建这样一个靶。KEY、PREFIX、FLAG 都不交给攻击者，攻击者拿到的只有 `oracle` 函数——注意里面没有 IV、没有 nonce，同一输入永远得到同一密文：

```python
# ecb_server.py —— ECB 加密 oracle 靶：固定密钥下加密「前缀 + 用户输入 + 未知串」
import os

from Crypto.Cipher import AES
from Crypto.Util.Padding import pad

KEY = os.urandom(16)          # 服务端密钥，攻击者不可见
PREFIX = os.urandom(23)       # 服务端自加的固定前缀，长度对攻击者未知
FLAG = b"flag{ecb_byt3_at_a_t1me}"

def oracle(user_input: bytes) -> bytes:
    """服务接口：加密 前缀 + 用户输入 + 未知串，返回密文。
    无 IV、无 nonce——同一输入永远得到同一密文"""
    return AES.new(KEY, AES.MODE_ECB).encrypt(pad(PREFIX + user_input + FLAG, 16))
```

确定性是全部攻击的前提，先确认一次——同一输入问两遍，密文一字不差：

```bash
python3 -c "from ecb_server import oracle; print(oracle(b'A'*16).hex()); print(oracle(b'A'*16).hex())"
```

输出：

```
490d858684f0cfe03f202e7054e84e9660ef4bec88268b5d776c1255fb09d57a34d136ca9c2d60eb77234ad855575205e789681de980ec7b5ddff1fd11fdd320
490d858684f0cfe03f202e7054e84e9660ef4bec88268b5d776c1255fb09d57a34d136ca9c2d60eb77234ad855575205e789681de980ec7b5ddff1fd11fdd320
```

对比 [[#2.2 漏洞形态与 HTTP 靶|2.2]] 的 padding oracle 靶：那里每次 `GET /session` 都重新随机 IV，token 每次不同；这里的 oracle 没有任何随机化，==问一次就固定一次==，攻击者构造的明文块能被原样比对。

### 1.4 块长识别：密文长度的跳变

攻击要按块对齐，先量出块长。办法是递增输入、观察密文长度：明文每跨过一次块边界，PKCS#7 就多补一块，密文长度跳一次——==相邻两次跳变的间隔就是块长==：

```python
# ecb_detect.py —— 侦察：块长识别（长度跳变）+ 模式确认（重复块）
from ecb_server import oracle

print("== 输入长度 0..19 对应的密文长度 ==")
lens = []
for n in range(20):
    ct = oracle(b"A" * n)
    lens.append(len(ct))
for start in range(0, 20, 10):
    print("  n=%2d..%2d: %s" % (start, start + 9,
          " ".join("%3d" % v for v in lens[start:start + 10])))
jumps = [n for n in range(1, 20) if lens[n] != lens[n - 1]]
print("  长度跳变发生在 n =", jumps)
print("  相邻跳变间隔 =", [b - a for a, b in zip(jumps, jumps[1:])], "-> 块长 16")

ct = oracle(b"A" * 64)
blocks = [ct[i:i + 16] for i in range(0, len(ct), 16)]
seen = {}
for i, b in enumerate(blocks):
    seen.setdefault(b, []).append(i)
dup = {b: idx for b, idx in seen.items() if len(idx) > 1}
print("== 输入 64 个 'A' 时的重复块 ==")
print("  密文 %d 字节 = %d 块，重复的 16 字节块 %d 个" % (len(ct), len(blocks), len(dup)))
for b, idx in dup.items():
    print("  %s 出现在块 %s" % (b.hex(), idx))
```

```bash
python3 ecb_detect.py
```

```

  n=10..19:  64  64  64  64  64  64  64  80  80  80
  长度跳变发生在 n = [1, 17]
```

两个结论：块长 16（AES 的块长，[[09-密码学基础|09 章]]）；64 个 A 里对齐的三个整块密文相同——==看到重复的 16 字节块即可断定 ECB==（第 5 节的判模表也靠它）。重复块落在块 2、3、4，还顺带确认了一件事：受控输入在密文里确实按整块铺开，逐字节的比对有块可用。

### 1.5 逐字节恢复主循环

先看机制，暂且假设受控输入从块边界开始（前缀长度未知的一般情形交给 1.6）。给输入垫 15 个填充字节 `A`，明文排布变成：

```
……前缀…… | A A A A A A A A A A A A A A A | unknown[0] | unknown[1] ……
          └───── 恰好一个块 ─────┘
```

块边界处那个密文块是 $E_K(\text{A}^{15} \| \text{unknown}[0])$。枚举 256 个候选字节 $g$，构造参照明文 $\text{A}^{15} \| g$ 去问 oracle：==参照密文块与目标密文块相同，当且仅当 $g$ 就是 unknown 的第一个字节==。第一字节到手后把它垫进已知串，同法推第二字节；每推进一步，垫的 A 少一个、已知的多一个，待猜字节始终被顶到同一个块的最后一格。设已恢复 $m$ 字节，目标在第 $k$ 块（$k = \lfloor m/16 \rfloor$），块内位置 $j = m \bmod 16$，被猜的是 $\text{unknown}[m] = \text{unknown}[16k{+}j]$：

$$\text{target} = E_K\big(\text{窗口}[15\text{ 字节}] \,\|\, \text{unknown}[16k{+}j]\big), \qquad \text{ref}(g) = E_K\big(\text{已知串}[15\text{ 字节}] \,\|\, g\big) \tag{6.7}$$

窗口的取法：$k = 0$ 时是 A 的填充（$\text{A}^{15-j}$），$k \ge 1$ 时 A 已经用尽，窗口就是已恢复串自身的尾巴 $\text{unknown}[16k{+}j-15 : 16k{+}j]$——两种情况代码统一写成"垫 $\text{A}^{15-j}$、拼上已知串"，比对的都是同一个块号。拿 1.6 的运行结果对照：已恢复 `b'fl'` 时 $m=2$、$j=2$，垫 $\text{A}^{13}$，目标块为 $E_K(\text{A}^{13} \|$ `fl` $\| \, ?)$，候选扫到 `a` 命中——输出里第 2 字节正是 `a`。一个字节至多 256 次询问。它与式 (6.3) 的 padding oracle 是同一思想的两面：==那边问解密端"认不认这个填充"，这边问加密端"认不认这个块"==，可区分的响应就是信息来源。

### 1.6 未知前缀：先对齐魔法串

1.3 的靶子在输入前面拼了 23 字节随机前缀且长度未知——输入不再落在块边界，直接套主循环会在错位的块上比对。先用魔法串探对齐：喂「$p$ 个填充字节 X + 整两个块的魔法串 `A`$\times 32$」，$p$ 从 0 数到 15。==$p$ 恰好把前缀补满整块时，`A`$\times 32$ 从块边界开始，相邻两块明文相同、密文必相同==；其余 $p$ 下 A 区跨块错位，不会出现重复块对。命中的 $p$ 就是以后每次询问要垫的字节数，重复块对的位置就是受控数据的首块号。完整攻击脚本把探测与主循环合成一体：

```python
# ecb_attack.py —— ECB byte-at-a-time 完整攻击：
# 前缀对齐（魔法串） -> 定位受控块 -> 逐字节恢复
# 攻击者只 import oracle，不知道 KEY、PREFIX、FLAG 的任何内容
from Crypto.Util.Padding import unpad

from ecb_server import oracle

def blocks(ct: bytes):
    return [ct[i:i + 16] for i in range(0, len(ct), 16)]

# ---- 第 1 步：对齐。喂「填充字节 X*p + 两个块的魔法串 A*32」，
# p 从 0 增到 15，直到密文里出现相邻两个相同的块——
# 那说明 prefix+X*p 恰好填满整块，A*32 从块边界开始、两块密文必然相同 ----
print("== 第 1 步：前缀对齐探测 ==")
OFF = None
for p in range(16):
    bs = blocks(oracle(b"X" * p + b"A" * 32))
    pair = next((i for i in range(len(bs) - 1) if bs[i] == bs[i + 1]), None)
    print("  p=%2d -> %s" % (p, "重复块在 %d、%d" % (pair, pair + 1) if pair is not None else "无重复"))
    if pair is not None and OFF is None:
        OFF = pair          # 受控数据（A*32）从这个块号开始
        PAD = p             # 以后每次询问都先垫 X*p，把前缀填满整块
print("  结论：垫 %d 个 X 后受控数据落在块 %d 起（前缀长度 mod 16 = %d）"
      % (PAD, OFF, (16 - PAD) % 16))

# ---- 第 2 步：逐字节恢复。垫齐之后，"X*PAD + A*(15-m)" 的密文里，
# 块 OFF+k 恰好等于 E( A*(15-m) + 未知串[16k : 16k+m+1] )：
# 加长一个字节的参照版把已知前缀 + 猜测字节塞进同一位置，对比即可验猜 ----
print("== 第 2 步：逐字节恢复 ==")
known = b""
while True:
    k, m = divmod(len(known), 16)        # k = 第几块，m = 在块内第几格
    filler = b"X" * PAD + b"A" * (15 - m)
    ct = oracle(filler)
    bs = blocks(ct)
    if OFF + k >= len(bs):               # 目标块号超出密文：到头了
        break
    target = bs[OFF + k]
    for g in range(256):                 # 猜未知串第 len(known) 个字节
        probe = blocks(oracle(filler + known + bytes([g])))
        if probe[OFF + k] == target:
            known += bytes([g])
            print("  第 %2d 字节 = 0x%02x %r  已恢复 %r" % (len(known) - 1, g, chr(g), known))
            break
    else:                                # 256 个候选无一命中：结束
        break

# 恢复会越过未知串末尾吃进服务端的 PKCS#7 填充，剥掉它
print("== 第 3 步：剥填充 ==")
print("  原始恢复串:", known)
try:
    known = unpad(known, 16)
except ValueError:
    pass
print("  未知串:", known.decode())
```

> [!warning] 尾部会多问出一两个填充字节
> 服务端对 prefix + input + unknown 整体做 PKCS#7 填充，恢复越过未知串末尾后，目标块里出现的是填充字节而非机密——先会命中一两个当次恰好确定的填充值，随后对不上而停止。剥掉尾部（`unpad`，或取可打印前缀）即得结果。服务端不填充（明文恰好对齐）时，恢复到未知串末尾自然停止，没有这一步。

> [!info]- 无前缀的服务是本节的特例
> 前缀长度为 0 或恰是 16 的倍数时，p = 0 直接命中、受控数据从块边界开始，主循环原样适用。cryptopals（入口见 [[01-练习平台索引|练习平台索引]]）Set 2 的 Challenge 12 是无前缀版、Challenge 14 是随机前缀版，与本节流程一一对应；Challenge 13 考的是 4.3 折叠框提到的 ECB 剪切粘贴，与逐字节恢复互补——一个读、一个写。

## 2. Padding Oracle 攻击

这是分组模式攻击里出场率最高、推导最典型的一类，按"原理 → 手工利用 → 自动化 → 自建靶实战"的次序完整走一遍。

### 2.1 填充规则

CBC 要求明文长度是块长的整数倍，PKCS#7 负责补齐：缺 $k$ 字节就在末尾补 $k$ 个值为 $0x0k$ 的字节；==明文恰好对齐时，补一整个块的 $0x10$==——解密端必须先看到合法填充才知道末尾要剥几字节，对齐的明文也得有填充可剥。

```python
# pkcs7_demo.py —— PKCS#7 填充规则与整块填充分支
from Crypto.Util.Padding import pad, unpad

for m in [b"flag{p4dd1ng}", b"B" * 16]:                 # 13 / 16 字节
    p = pad(m, 16)
    k = 16 - len(m) % 16
    print(f"明文 {len(m):2d} 字节 {m!r}")
    print(f"  填充后 {len(p):2d} 字节，填充字节 0x{k:02x} × {k}")
    print(f"  填充后字节: {p!r}")
    assert unpad(p, 16) == m
```

解密端校验的是**最后一块** $P_n$ 的末尾：

$$\text{填充合法} \iff P_n \text{ 的末 } k \text{ 字节均为 } 0x0k,\quad k \in \{1, 2, \dots, 16\} \tag{6.2}$$

### 2.2 漏洞形态与 HTTP 靶

padding oracle 的成立条件只有一条：==服务端解密后，把"填充错误"与"业务错误"用可区分的方式报出来==。填充校验发生在解密内部、业务校验在它之后——只要响应不同（报错文案不同、状态码不同、甚至一个多花一次数据库查询），攻击者就拿到了一台"回答填充是否合法"的应答器。每次询问泄露的信息是解密的中间值末字节。

下面自建一个这样的靶。服务端持有随机密钥和一个会话明文（相当于被偷走的加密 cookie），提供两个接口：`GET /session` 发一个加密 token，`POST /decrypt` 收 token 并解密校验——填充错误返回 `padding_error: true`，填充合法但业务校验不过返回 `access denied`：

```python
# oracle_server.py —— padding oracle 靶：/decrypt 把"填充错误"与"业务错误"分开报
import json
import os
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer

from Crypto.Cipher import AES
from Crypto.Util.Padding import pad, unpad

KEY = os.urandom(16)
SECRET = b"flag{p4dd1ng_0r4cl3}"          # 服务端保管的会话明文，攻击者不可见

def enc(data: bytes) -> bytes:
    iv = os.urandom(16)
    return iv + AES.new(KEY, AES.MODE_CBC, iv).encrypt(pad(data, 16))

class Handler(BaseHTTPRequestHandler):
    def log_message(self, *args):          # 关掉逐请求访问日志
        pass

    def _json(self, obj):
        body = json.dumps(obj).encode()
        self.send_response(200)
        self.send_header("Content-Type", "application/json")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def do_GET(self):
        if self.path == "/session":                       # 发一个加密 token，相当于被偷到的 cookie
            self._json({"token": enc(SECRET).hex()})
        else:
            self._json({"hint": 'GET /session | POST /decrypt {"token": "<hex>"}'})

    def do_POST(self):
        n = int(self.headers.get("Content-Length", 0))
        req = json.loads(self.rfile.read(n))
        raw = bytes.fromhex(req["token"])
        iv, ct = raw[:16], raw[16:]
        try:
            pt = unpad(AES.new(KEY, AES.MODE_CBC, iv).decrypt(ct), 16)
        except ValueError:
            self._json({"padding_error": True})                       # 填充错误：单独报
            return
        if b"admin=true" in pt:
            self._json({"padding_error": False, "result": "welcome, admin"})  # 业务成功
        else:
            self._json({"padding_error": False, "result": "access denied"})   # 业务错误

class Server(ThreadingHTTPServer):
    request_queue_size = 128            # 默认 backlog 只有 5，并发探测会被拒绝（connection reset）
    daemon_threads = True

if __name__ == "__main__":
    print("padding oracle listening on 127.0.0.1:6610", flush=True)
    Server(("127.0.0.1", 6610), Handler).serve_forever()
```

### 2.3 攻击原理：逐字节推导

CBC 解密规则（[[09-密码学基础#3.4 CBC 字节翻转|09 章 3.4]] 的式子）是全部推导的起点：

$$P_i = D_K(C_i) \oplus C_{i-1}, \qquad C_0 = \text{IV} \tag{6.1}$$

记 $D_K(C_i)$ 为**中间值** $D$：它只由密钥和当前密文块决定，攻击者改不了，但它落进明文之前还要异或上 $C_{i-1}$——==而 $C_{i-1}$ 是密文，就在攻击者手里==。攻击从最后一块 $C_n$ 开始：把"前块"整个换成自己构造的 $\text{prev}'$，与 $C_n$ 拼成一个新 token 送去问 oracle。末字节先看：令 $\text{prev}'[15] = g$，则

$$P'[15] = D[15] \oplus g \;\Rightarrow\; \text{取到使 } P'[15] = 0x01 \text{ 的 } g \text{ 时} \quad D[15] = g \oplus 0x01 \tag{6.3}$$

$P'[15] = 0x01$ 时按式 (6.2) 填充必合法、与前 15 字节无关，所以 $g$ 从 0 扫到 255，一旦 oracle 说"填充合法"，$D[15]$ 就确定了。接下来钉死已知的 $D[15]$，把 $P'[15]$ 设成 $0x02$，扫 $\text{prev}'[14]$ 找 $D[14]$；如此推进到 $D[0]$，16 个字节全部到手，明文块按式 (6.1) 算出：

$$P_n = D \oplus C_{n-1}$$

然后把同样的流程挪到 $C_{n-1}$ 上（这次可篡改的是 $C_{n-2}$），逐块向左推完整个 token。每块至多 $256 \times 16 = 4096$ 次询问，全部不需要密钥。

> [!warning] $k=1$ 那一轮有假阳性
> 扫 $\text{prev}'[15]$ 找 $0x01$ 时，能命中合法填充的不止"真 $0x01$"一种：原 token 自己的合法填充（例如 $0x0c \times 12$）在 $g$ 扫到原字节时照样合法，$0x02\,0x02$ 的巧合也可能撞上。处理办法：收集**全部**命中，把前一个字节改掉再问一次——真 $0x01$ 与前一字节无关、依旧合法，假命中的填充会被破坏。$k \ge 2$ 之后命中要求末尾连续 $k$ 字节都对上，假阳性概率约 $2^{-120}$ 量级，命中即停。

### 2.4 手工利用：恢复第一个字节

先手工走一遍式 (6.3) 的第一轮：固定末块 $C_2$，扫前块 $C_1$ 的最后一个字节：

```python
# probe_manual.py —— 手工利用第一步：只恢复最后一个明文字节
import json
import urllib.request

URL = "http://127.0.0.1:6610"

        URL + "/decrypt",
        data=json.dumps({"token": token.hex()}).encode(),
        headers={"Content-Type": "application/json"})

        return json.loads(r.read())
```

### 2.5 自动化：逐块恢复全部明文

完整攻击脚本：从最后一个字节往前逐字节、从最后一个块往前逐块，恢复整个 token：

```python
# oracle_attack.py —— padding oracle 完整攻击：从最后一个字节往前逐块恢复明文
import json
import time
import urllib.request

from Crypto.Util.Padding import unpad

URL = "http://127.0.0.1:6610"
opener = urllib.request.build_opener(urllib.request.ProxyHandler({}))   # 绕开系统代理

def xor(a, b):
    return bytes(x ^ y for x, y in zip(a, b))

def padding_ok(token: bytes) -> bool:
    """问一次 oracle：这个 token 解出来填充是否合法"""
    req = urllib.request.Request(
        URL + "/decrypt",
        data=json.dumps({"token": token.hex()}).encode(),
        headers={"Content-Type": "application/json"})
    with opener.open(req) as r:
        return not json.loads(r.read())["padding_error"]

def recover_intermediate(prev: bytes, block: bytes):
    """恢复中间值 D(block)。prev 是攻击者可任意篡改的前块（或 IV）"""
    prev = bytearray(prev)
    inter = bytearray(16)
    queries = 0
    for k in range(1, 17):                  # 让末尾依次解成 0x01, 0x02, ..., 0x10
        pos = 16 - k                        # 本轮探测的字节位置
        for j in range(pos + 1, 16):        # 已经推出的字节钉死
            prev[j] = inter[j] ^ k
        hits = []
        for g in range(256):                # 探测未知的 D[pos]
            prev[pos] = g
            queries += 1
            if padding_ok(bytes(prev) + block):
                hits.append(g)
                if k > 1:                   # k > 1 时假阳性概率可忽略，命中即停
                    break
        if k == 1 and len(hits) > 1:        # 0x01 有假阳性，改前一字节复试
            save = prev[pos - 1]
            for g in hits:                  # 逐个复试，留下翻转后仍合法的那个
                prev[pos] = g
                prev[pos - 1] = save ^ 0xFF
                if padding_ok(bytes(prev) + block):
                    break
            prev[pos - 1] = save
            hits = [g]
        inter[pos] = hits[0] ^ k
    return bytes(inter), queries

def padding_oracle_attack(token: bytes) -> bytes:
    iv, ct = token[:16], token[16:]
    blocks = [ct[i:i + 16] for i in range(0, len(ct), 16)]
    plain = b""
    queries = 0
    for i in range(len(blocks) - 1, -1, -1):        # 从最后一个块往前打
        block, prev = blocks[i], (blocks[i - 1] if i else iv)
        inter, q = recover_intermediate(prev, block)
        queries += q
        plain = xor(inter, prev) + plain            # P_i = D(C_i) ^ C_{i-1}
        print(f"  块 {i + 1}: 中间值 {inter.hex()}  明文 {plain[:16]!r}")
    print(f"共 {queries} 次询问")
    return plain

if __name__ == "__main__":
    with opener.open(URL + "/session") as r:        # 拿到被偷的 cookie
        token = bytes.fromhex(json.loads(r.read())["token"])
    print("目标 token:", token.hex())
    t0 = time.perf_counter()
    plain = padding_oracle_attack(token)
    print(f"耗时 {time.perf_counter() - t0:.1f} s")
    print("还原明文 :", plain)
    print("去填充后 :", unpad(plain, 16).decode())
```

```
  块 2: 中间值 ecf5ce15cc44dea35b989a4720360ad8  明文 b'cl3}\x0c\x0c\x0c\x0c\x0c\x0c\x0c\x0c\x0c\x0c\x0c\x0c'
```

### 2.6 提速：并发探测

oracle 的每次询问互相独立（同一个 $D[pos]$ 的 256 个候选互不依赖），一轮探测天然可以并发。把串行版的内层扫描换成线程池，其余逻辑不动：

```python
# oracle_attack_fast.py 与串行版的差异：每轮 256 个候选同时发出
import threading
from concurrent.futures import ThreadPoolExecutor

local = threading.local()

def get_opener():
    if not hasattr(local, "opener"):        # 每线程一个 opener，绕开系统代理
        local.opener = urllib.request.build_opener(urllib.request.ProxyHandler({}))
    return local.opener

POOL = ThreadPoolExecutor(max_workers=16)

def recover_intermediate(prev: bytes, block: bytes):
    prev, inter = bytearray(prev), bytearray(16)
    queries = 0
    for k in range(1, 17):
        pos = 16 - k
        for j in range(pos + 1, 16):
            prev[j] = inter[j] ^ k

        def probe(g):
            p = bytearray(prev); p[pos] = g
            return g if padding_ok(bytes(p) + block) else None

        hits = [g for g in POOL.map(probe, range(256)) if g is not None]
        queries += 256
        # ……k == 1 的假阳性复试与 inter[pos] 的计算同串行版……
```

并发版为了实现简单，每轮把 256 个候选问满（不提前停），总询问数回到理论上限的 8192，总耗时却与串行版的 3.8 s 基本持平——单字节一轮从"平均上百次串行往返"变成"一批同时发出"。本地靶上 HTTP 建连开销占大头，吞吐约提升一倍；换到远程靶，网络往返时间大，提速比向线程数靠拢。判定 $k=1$ 假阳性的复试依赖上一轮结果，保持串行，只多几次询问。

> [!info]- 继续压时间的三个方向
> 一、连接复用：urllib 每次请求新建 TCP 连接，换 `http.client.HTTPConnection` 长连接，本地吞吐还能翻倍以上。二、增大并发数的同时给服务端留余量——本靶把 `request_queue_size` 调到 128，就是为了并发探测时不触发 connection reset。三、多块 token 可以按块并行：各块的中间值恢复互不依赖，16 块的 cookie 理论上再乘一个块数加速比。

### 2.7 变体与真实案例

- **计时 oracle**：报错差异不只可以写在响应体里，也可以写在响应时间里——服务端对填充错误立即返回、对合法填充再走一步 HMAC 校验才返回，两种路径的耗时差把 oracle 搬到时间轴上。攻击逻辑与逐字节探测完全不变，判据从"响应内容"换成"响应时间"，每个候选多测几次取中位数压噪声。TLS 1.0 时代的 Lucky13 攻击就是 CBC 填充校验的计时变体。
- **cookie 即靶子**：本靶的 token 就是加密 cookie 的替身。现实形态通常是"加密 cookie + 统一错误页"，但填充异常往往通过状态码差异（500 与 200）、响应长度差异露出来——可区分性在，oracle 就在。
- **真实世界**：2010 年 ASP.NET 的 padding oracle 让微软发了紧急补丁（MS10-070），同年 JavaServer Faces 的实现存在同类漏洞；公开工具 POET 是这一时期的代表。此后"解密失败一律返回统一错误、认证交给 AEAD"成为服务端共识。

## 3. CBC 进阶误用

### 3.1 IV 固定：首块等值泄漏

CBC 的第一块是 $C_1 = E_K(P_1 \oplus \text{IV})$。IV 固定时，==两个首块相同的消息，首块密文完全相同==——观察者不知道密钥，也能断定"这两条消息的开头一样"：

```python
# cbc_fixed_iv.py —— 固定 IV：首块明文相同 → 首块密文相同
from Crypto.Cipher import AES
from Crypto.Random import get_random_bytes
from Crypto.Util.Padding import pad

key = get_random_bytes(16)
msgs = [
    b"admin=0;transfer=100",
    b"admin=0;transfer=999",
    b"admin=1;transfer=100",
]

def enc(m, iv):
    return AES.new(key, AES.MODE_CBC, iv=iv).encrypt(pad(m, 16))

print("== 固定 IV（全零）==")
for m in msgs:
    ct = enc(m, bytes(16))
    print(f"  {m.decode():22s} 首块密文 {ct[:16].hex()}")

print("== 每次随机 IV ==")
for m in msgs:
    ct = enc(m, get_random_bytes(16))
    print(f"  {m.decode():22s} 首块密文 {ct[:16].hex()}")
```

固定 IV 下，前两条消息的首块密文一字不差——"前 16 字节相同"这个事实直接写在密文里；换成随机 IV，等值关系消失。固定 IV 的 CBC 首块因此退化成"带固定偏移的 ECB"：对首个数据块做分类统计（哪些用户开了 admin、哪些请求是同一种模板）照样可行。

> [!warning] IV 不需要保密，但需要不可预测
> 随机 IV 随密文明文传输完全没问题；错的是**固定** IV、可预测 IV（如计数器递增）。CBC 只要求 IV 不可预测，GCM/CTR 还要求不重复——两者的差别在第 6 节 GCM 的 warning 里展开。

### 3.2 IV 可控：字节翻转

IV 可控时 CBC 有更直接的改写法——字节翻转，[[09-密码学基础#3.4 CBC 字节翻转|09 章 3.4]] 已完整做过：改 $C_{i-1}$ 的某个字节，$P_i$ 同位置跟着翻转，代价是前一块解密成乱码。它与 padding oracle 的分工一句话说清：==字节翻转是"写"（把明文改成想要的值），padding oracle 是"读"（逐字节恢复明文）==；两者都不需要密钥，组合起来读写通吃。

### 3.3 CBC-R：只有加密 oracle 也能伪造

字节翻转和 padding oracle 都建立在"能送密文去解密"上。如果服务端只有加密口子（解密结果不回显、报错也不可区分），CBC 还能反过来构造：想要一段解密成指定明文 $P_1 \| P_2 \| \cdots$ 的密文，自己选一个随机块 $C_0$ 当 IV，然后令

$$C_i = E_K(P_i \oplus C_{i-1}) \tag{6.5}$$

按式 (6.1)，接收方解密得到 $D_K(C_i) \oplus C_{i-1} = P_i \oplus C_{i-1} \oplus C_{i-1} = P_i$——==构造即成立，整条密文没有一个乱码块==。前提是攻击者能对任意 $x$ 求得 $E_K(x)$：加密 oracle 的 IV 已知时，喂 $x \oplus \text{IV}$、取返回密文的首块即可，一个块花一次询问。

```python
# cbc_r.py —— CBC-R：只有加密 oracle、IV 不可控，也能构造解密成任意明文的密文
from Crypto.Cipher import AES
from Crypto.Random import get_random_bytes
from Crypto.Util.Padding import pad, unpad

KEY = get_random_bytes(16)
FIXED_IV = get_random_bytes(16)           # 靶子的 IV 写死且不随请求变化，攻击者无法控制

def xor(a, b):
    return bytes(x ^ y for x, y in zip(a, b))

# ---- 靶子：只有一个加密口子 + 一个校验口子 ----
def enc_oracle(data: bytes) -> bytes:
    """加密任意数据，返回 IV 拼密文。IV 是靶子自己的固定值，不受攻击者控制"""
    return FIXED_IV + AES.new(KEY, AES.MODE_CBC, iv=FIXED_IV).encrypt(pad(data, 16))

def check(token: bytes) -> str:
    """解密 token 并做业务校验"""
    iv, ct = token[:16], token[16:]
    pt = unpad(AES.new(KEY, AES.MODE_CBC, iv=iv).decrypt(ct), 16)
    return "welcome, admin" if b"admin=true" in pt else "access denied"

# ---- 攻击 ----
def e(x: bytes) -> bytes:
    """从加密 oracle 提取单块加密 E(x)：IV 已知，喂 x ^ FIXED_IV，取返回的首块"""
    return enc_oracle(xor(x, FIXED_IV))[16:32]

P1 = b"junkjunkjunkjunk"                    # 想让解密结果出现的明文，逐块喂进 oracle
P2 = b"admin=true" + bytes([6]) * 6         # 末块自带合法填充，unpad 后恰好是想要的内容

C0 = get_random_bytes(16)                   # 随机块，伪造密文里它扮演 IV
C1 = e(xor(P1, C0))                         # 要 D(C1) ^ C0 = P1，即 C1 = E(P1 ^ C0)
C2 = e(xor(P2, C1))                         # 要 D(C2) ^ C1 = P2，即 C2 = E(P2 ^ C1)
forged = C0 + C1 + C2

print("固定 IV（不可控）:", FIXED_IV.hex())
print("伪造 token       :", forged.hex())
print("靶子校验结果     :", check(forged))
print("解密出的明文     :", AES.new(KEY, AES.MODE_CBC, iv=C0).decrypt(C1 + C2))
```


```
伪造 token       : 07e693768ac4d95eb1af5a4bd12ed9a4aa50393be0abedec4b284faae2b2b72b98547a1b77a701dd353836e4c8ff14b4
```

靶子的 IV 固定且不受攻击者控制，校验口子的解密结果也不回显——CBC-R 依然构造出通过 `admin=true` 校验的 token。三种 CBC 手段的投入产出放在一起看：

| 手段 | 需要的口子 | 产物 | 代价 |
| ---- | ---- | ---- | ---- |
| 字节翻转 | 解密服务，IV 可控 | 改写目标块明文 | 前一块解密成乱码 |
| padding oracle | 解密服务，报错可区分 | 恢复全部明文 | 每块至多 4096 次询问 |
| CBC-R | 加密服务，IV 已知 | 任意明文的合法密文 | 每块 1 次询问 |

> [!note] CBC-R 的适用前提
> 伪造密文里 $C_0$ 是攻击者自选的随机块，接收端把它当 IV——所以 IV 由密文携带（IV 前置在 token 里）的系统才有 CBC-R 的落点。IV 从密钥派生、不随密文传输的系统不存在"给接收端指定 IV"的位置，CBC-R 不成立——那相当于每次通信换密钥，本来就规避了这类攻击。

## 4. CTR/OFB/CFB 的 nonce 重用

### 4.1 本质：密钥流重用

[[C03-序列密码与LFSR|C03]] 把流密码分成同步与自同步两类，按这个分类对号入座：

- **CTR / OFB**（同步）：密钥流只由密钥和初始值决定。同一密钥下 nonce 相同，整条密钥流相同。
- **CFB**（自同步）：密钥流来自前一块密文，同 IV 只保证第一块密钥流相同，泄漏限于首块。

对同步的两类，重用 nonce 等于把 [[09-密码学基础#3.1 XOR 与一次一密|09 章 3.1]] 的一次一密用到第二次——XOR 的自反性当场消掉密钥流：

$$c_1 \oplus c_2 = (m_1 \oplus z) \oplus (m_2 \oplus z) = m_1 \oplus m_2 \tag{6.4}$$

09 章 3.2 已经为 OTP 版演示过恢复手法（crib dragging），CTR 只是给 $z$ 换了个来源，恢复过程逐字照搬。

### 4.2 异或消 key 与 crib dragging

同一密钥、同一 nonce 加密两条消息，先看 $c_1 \oplus c_2$ 是否等于 $m_1 \oplus m_2$，再用可猜测的明文片段滚雪球：

```python
# nonce_reuse.py —— CTR 同一 nonce 加密两条消息 = 密钥流重用，crib dragging 还原
from Crypto.Cipher import AES
from Crypto.Random import get_random_bytes

key = get_random_bytes(16)
nonce = get_random_bytes(8)

def xor(a, b):
    return bytes(x ^ y for x, y in zip(a, b))

def enc(m):
    return AES.new(key, AES.MODE_CTR, nonce=nonce).encrypt(m)

m1 = b"flag{tw0_n0nc3_0ne_k3y}"        # 23 字节
m2 = b"meet me at the old bridge"      # 25 字节
c1, c2 = enc(m1), enc(m2)

print("c1 ^ c2 == m1 ^ m2 :", xor(c1, c2) == xor(m1, m2))

# 第 1 步：猜 m2 开头 5 字节
ks = xor(b"meet ", c2[:5])
print("猜 m2[:5]  -> m1[:5]  =", xor(ks, c1[:5]))
# 第 2 步：把 m2 的可读前缀拉长
ks = xor(b"meet me at the ", c2[:15])
print("猜 m2[:15] -> m1[:15] =", xor(ks, c1[:15]))
# 第 3 步：m1 是 flag 形态，凑出全文后反哺 m2
ks = xor(m1, c1)
print("凑出 m1 全文 -> m2[:23] =", xor(ks, c2[:23]))
```

```bash
python3 nonce_reuse.py
```

输出：

```

猜 m2[:5]  -> m1[:5]  = b'flag{'
猜 m2[:15] -> m1[:15] = b'flag{tw0_n0nc3_'
凑出 m1 全文 -> m2[:23] = b'meet me at the old brid'
```

$c_1 \oplus c_2$ 与 $m_1 \oplus m_2$ 逐字节相等，密钥流被消掉；随后猜一段、蹭一段，两段明文一起现形。多条消息共用一个 nonce 的题只是体力放大版，统计法（利用空格的异或性质）可以自动化，见第 8 节练习。

### 4.3 CTR 密文的任意改写

1.2 节的传播表给过结论：流式模式错一个字节就只错一个字节。把它用在攻击上——翻转密文里任意字节，解密结果同位置翻转，不需要知道密钥：

```python
# ctr_malleability.py —— CTR 密文可任意篡改：翻转密文字节 = 翻转对应明文字节
from Crypto.Cipher import AES
from Crypto.Random import get_random_bytes

key, nonce = get_random_bytes(16), get_random_bytes(8)

def enc(m):
    return AES.new(key, AES.MODE_CTR, nonce=nonce).encrypt(m)

def dec(c):
    return AES.new(key, AES.MODE_CTR, nonce=nonce).decrypt(c)

token = b"role=guest;exp=2099"
ct = enc(token)
delta = bytes(a ^ b for a, b in zip(b"guest", b"admin"))     # 逐字节差值
bad = ct[:5] + bytes(a ^ b for a, b in zip(ct[5:10], delta)) + ct[10:]

print("原始明文:", dec(ct).decode())
print("篡改明文:", dec(bad).decode())
```

```bash
python3 ctr_malleability.py
```

输出：

```
原始明文: role=guest;exp=2099
篡改明文: role=admin;exp=2099
```

`guest` 改 `admin`，密文里对应 5 个字节异或上差值即可，其余部分完好。=="传输密文、校验明文"的设计在流式模式下等于把改写权交给任何拿到密文的人==；字节翻转（CBC）好歹要牺牲一块，CTR/OFB 连代价都没有。堵法只有第 6 节的认证加密。

> [!info]- ECB/CBC 下同样的改写为什么难
> ECB 没有链式结构，改写靠"块剪切粘贴"：把别处出现的 `;admin=` 块整块搬过来，前提是明文里恰好存在可对齐的块（cryptopals Set 2 Challenge 13 专门考这个）；CBC 的字节翻转要牺牲前一块。CTR 的改写既不需要搬运也不需要牺牲块——代价是零，这正是它必须配认证标签的原因。

## 5. 检测与定位

拿到一段密文流量或一份加密代码，按三步定位模式与攻击面。

**第一步，读代码**。`grep MODE_`（pycryptodome）、`openssl enc -aes-...`、`Cipher.getInstance("AES/...")` 一眼定模式；同时盯 IV/nonce 的来源——写死、计数器、还是随机。

**第二步，黑盒体检**。没有源码时对密文本身做三项观察：

```python
# detect_mode.py —— 拿到密文先判模式：块对齐、重复块、相近明文的密文差异
from Crypto.Cipher import AES
from Crypto.Random import get_random_bytes
from Crypto.Util.Padding import pad

key, iv, nonce = get_random_bytes(16), get_random_bytes(16), get_random_bytes(8)

def rep16(ct):
    blocks = [ct[i:i+16] for i in range(0, len(ct), 16)]
    return len(blocks) - len(set(blocks))

pt = (b"AAAAAAAAAAAAAAAABBBBBBBBBBBBBBBBAAAAAAAAAAAAAAAA") * 2   # 96 字节，结构重复
samples = [
    ("ECB", AES.new(key, AES.MODE_ECB).encrypt(pt)),
    ("CBC", AES.new(key, AES.MODE_CBC, iv=iv).encrypt(pt)),
    ("CTR", AES.new(key, AES.MODE_CTR, nonce=nonce).encrypt(pt[:41])),   # 41 字节，故意不对齐
]
print("== 密文体检 ==")
for name, ct in samples:
    print(f"  {name}: 长度 {len(ct):3d}（16 对齐 {len(ct) % 16 == 0}），重复 16 字节块 {rep16(ct)} 个")

print("== 相近明文观察（两段只差最后 1 字节）==")
m1, m2 = b"user=guest;sid=0001", b"user=guest;sid=0002"
pair = [
    ("CTR 同 nonce", AES.new(key, AES.MODE_CTR, nonce=nonce).encrypt(m1),
                     AES.new(key, AES.MODE_CTR, nonce=nonce).encrypt(m2)),
    ("CBC 同 IV  ", AES.new(key, AES.MODE_CBC, iv=iv).encrypt(pad(m1, 16)),
                     AES.new(key, AES.MODE_CBC, iv=iv).encrypt(pad(m2, 16))),
    ("CBC 随机 IV", AES.new(key, AES.MODE_CBC, iv=get_random_bytes(16)).encrypt(pad(m1, 16)),
                     AES.new(key, AES.MODE_CBC, iv=get_random_bytes(16)).encrypt(pad(m2, 16))),
]
for name, c1, c2 in pair:
    n = sum(1 for a, b in zip(c1, c2) if a != b)
    print(f"  {name}: 长度 {len(c1):2d}，密文不同字节 {n:2d} 个")
```

```bash
python3 detect_mode.py
```

输出：

```
== 密文体检 ==
  ECB: 长度  96（16 对齐 True），重复 16 字节块 4 个
  CBC: 长度  96（16 对齐 True），重复 16 字节块 0 个
  CTR: 长度  41（16 对齐 False），重复 16 字节块 0 个
== 相近明文观察（两段只差最后 1 字节）==
  CTR 同 nonce: 长度 19，密文不同字节  1 个

```

三项观察各自指向一个结论：

| 观察 | 结论 |
| ---- | ---- |
| 长度是 16 的倍数 | 块模式候选（ECB/CBC）；不是则倾向 CTR/OFB/CFB8 |
| 有重复的 16 字节块 | ECB（或 CBC 撞上重复前块，罕见）——直接进入 [[#1.6 未知前缀：先对齐魔法串\|1.6]] 的逐字节恢复 |
| 相近明文的密文只差个别字节 | 同密钥流（nonce 重用）——差异字节就是明文差异位置 |
| 相近明文的密文只差末块 | CBC 同 IV：首块相同、改动随链传播 |

**第三步，看报错**。响应或日志里出现 `padding`、`unpad`、`bad decrypt`、`MAC check failed` 之类的区分性文案，对应的口子就找到了——前者是 padding oracle 的入口（第 2 节），后者说明用的是 AEAD、这条路不通。拿本章靶子练手：48 字节的 token 正好是 IV + 2 块，先按第 2 节打一遍，再用本节的观察法复核。

## 6. 防御与 AEAD

### 6.1 为什么需要认证加密

回头数一遍本章的攻击：padding oracle 吃"填充校验结果可区分"，ECB 逐字节恢复吃"加密结果确定、同块同密文"，CBC-R 和字节翻转吃"改过的密文照样被解密"，nonce 重用与 CTR 改写吃"密钥流可预测、密文可改"——共同根是==分组密码只保证机密性（没密钥算不出明文），从不保证完整性（改过的密文会被照样处理）==。解密端唯一的"完整性检查"是 PKCS#7 填充校验，而它恰恰变成了 oracle。结论：加密之外必须再加认证，且认证要在解密之前完成校验。

### 6.2 AES-GCM 的正确用法

GCM 是当前的主流选择：底层是 CTR 加密，额外算出一个认证标签（tag），覆盖密文和附加认证数据（AAD）。pycryptodome 把"加密 + 出标签"和"校验 + 解密"做成一体的两个方法：

```python
# aead_gcm.py —— 认证加密的正确用法：加密与标签一体，篡改必被拒
from Crypto.Cipher import AES, ChaCha20_Poly1305
from Crypto.Random import get_random_bytes

key, nonce = get_random_bytes(16), get_random_bytes(12)      # GCM 标准 nonce 12 字节
msg = b"transfer=100;to=bob"

ct, tag = AES.new(key, AES.MODE_GCM, nonce=nonce).encrypt_and_digest(msg)
print("密文 :", ct.hex())
print("标签 :", tag.hex())

pt = AES.new(key, AES.MODE_GCM, nonce=nonce).decrypt_and_verify(ct, tag)
print("合法密文解出:", pt.decode())

bad = bytearray(ct); bad[0] ^= 0x01
try:
    AES.new(key, AES.MODE_GCM, nonce=nonce).decrypt_and_verify(bytes(bad), tag)
    print("篡改密文: 通过（不应发生）")
except ValueError as e:
    print("篡改密文 ->", type(e).__name__, ":", e)

bad_tag = bytearray(tag); bad_tag[0] ^= 0x01
try:
    AES.new(key, AES.MODE_GCM, nonce=nonce).decrypt_and_verify(ct, bytes(bad_tag))
    print("伪造标签: 通过（不应发生）")
except ValueError as e:
    print("伪造标签 ->", type(e).__name__, ":", e)

key2 = get_random_bytes(32)
ct2, tag2 = ChaCha20_Poly1305.new(key=key2, nonce=nonce).encrypt_and_digest(msg)
pt2 = ChaCha20_Poly1305.new(key=key2, nonce=nonce).decrypt_and_verify(ct2, tag2)
print("chacha20-poly1305:", pt2.decode())
```

```bash
python3 aead_gcm.py
```

输出：

```
密文 : 353e59af6c723e28db27f97b6283c55ed22304
标签 : 8716ccfe2f952caafe0c910d5b11406e
合法密文解出: transfer=100;to=bob
篡改密文 -> ValueError : MAC check failed
伪造标签 -> ValueError : MAC check failed
chacha20-poly1305: transfer=100;to=bob
```

密文翻 1 位、标签翻 1 位，`decrypt_and_verify` 都抛 `ValueError`，解密根本不发生——第 2 节的 oracle 和第 3、4 节的改写在 GCM 下全部失效，篡改者拿不到任何区分性响应。需要认证但不加密的字段（如消息头）用 `cipher.update(aad)` 在 `encrypt_and_digest` 之前挂进去，AAD 被标签覆盖但不出现在密文里。

> [!warning] GCM 的 nonce 重用更致命
> CTR 重用 nonce 丢的是机密性；GCM 重用 (key, nonce) 连认证一起丢——认证子钥可以被计算出来，攻击者随后能给任意密文伪造合法标签。因此 GCM 的 nonce 管理：每条消息 `get_random_bytes(12)` 随机取（同一密钥的消息量要控制在 $2^{32}$ 以内压碰撞概率），或用严格单调的计数器，二者都归结为一条——==同一密钥下 nonce 绝不重复==。

### 6.3 ChaCha20-Poly1305 与旧系统改造

ChaCha20-Poly1305 是移动端与 TLS 里常见的另一套 AEAD，接口与 GCM 同形（上面输出的最后一行），密钥 32 字节、nonce 12 字节，软件实现速度通常快于 AES-GCM。TLS 1.3（RFC 8446）删除了全部 CBC 套件，只保留 AEAD。改造没有 AEAD 的旧系统时，用 Encrypt-then-MAC：`HMAC-SHA256(key_mac, IV ‖ ct)` 附在密文后，先校验后解密，校验失败返回与解密失败相同的统一错误——同时断掉第 2 节的 oracle 和第 3、4 节的改写。

## 7. 常见问题

| 现象 | 原因与解决 |
| ---- | ---- |
| oracle 靶问不出可区分的响应 | 靶子把填充错误与 MAC/业务错误合并成同一个响应，可区分性没了，padding oracle 不成立（[[#2.2 漏洞形态与 HTTP 靶\|2.2]]）；自建靶保持两类响应分离，合并的靶试计时差异（[[#2.7 变体与真实案例\|2.7]]） |
| 16 线程并发探测报 ConnectionResetError | `http.server` 默认 listen backlog 只有 5，并发连接被内核拒绝；服务端把 `request_queue_size` 调大（本靶设 128），客户端对 reset 加一次重试 |
| 恢复出 32 字节"明文"，后半段是重复的 `\x0c` | 那是 PKCS#7 填充本身，`unpad` 剥掉即可（[[#2.5 自动化：逐块恢复全部明文\|2.5]]） |
| ECB 逐字节恢复的结尾多出 `\x01` 一类尾巴 | 恢复越过了未知串末尾，吃进了服务端的 PKCS#7 填充；`unpad` 剥掉即可（[[#1.6 未知前缀：先对齐魔法串\|1.6]]） |
| 攻击跑完明文是乱码但格式像那么回事 | 把中间值 $D$ 当成了明文：少异或了前块，$P_i = D(C_i) \oplus C_{i-1}$（[[#2.3 攻击原理：逐字节推导\|2.3]]） |
| $k=1$ 那轮找到的字节不对 | 假阳性：原 token 自己的合法填充、$0x02\,0x02$ 巧合都能命中；收集全部命中后改前一字节复试（[[#2.4 手工利用：恢复第一个字节\|2.4]]） |
| 手写 unpad 对整块明文报错或剥错位数 | 漏了整块填充分支：明文恰为块长整数倍时补一整块 $0x10$（[[#2.1 填充规则\|2.1]]）；直接用 `Crypto.Util.Padding` 的 pad/unpad |
| CTR 密文跨库解不开，或只有第一块对 | 双方切分 16 字节计数器初值的方式不同：pycryptodome 按 nonce 长度切（8 字节 nonce → 64 位计数器从 `initial_value` 起），openssl 的 `-iv` 是完整 16 字节初值；对拍时把 nonce 长度、初始值、字节序三件事对齐 |
| `AES.new(..., MODE_CTR, nonce=16字节)` 报错 | pycryptodome 要求 nonce 少于块长（至多 15 字节），给计数器留位；惯用 12 字节（与 GCM 对齐）或 8 字节 |
| GCM 解密偶发 MAC check failed，但密文没动过 | 同一密钥下 nonce 重复了（随机数源有竞态，或手动计数撞号）；每消息 `get_random_bytes(12)` 或全局严格单调计数（[[#6.2 AES-GCM 的正确用法\|6.2]]） |
| 照老教程写 `Crypto.Random.new().read(16)` 报 ImportError | pycryptodome 移除了 Random 模块，改用 `Crypto.Random.get_random_bytes`；GCM 标签用 `encrypt_and_digest`/`decrypt_and_verify` 一体生成，不要 `encrypt` 完再单独拼校验 |
| 手写 GCM 与标准实现对不上 | GCM 内部计数器有固定起点：12 字节 nonce 时 $J_0 = \text{nonce} \| 0x00000001$，加密从 $J_0{+}1$ 开始；应用层不用复刻它，只保证 nonce 不重复 |

## 8. 配套练习与延伸阅读

配套练习：

1. 把本章 oracle 靶改成计时版：填充合法的请求多睡 30 毫秒，删掉 `padding_error` 字段，重写攻击脚本——判据换成响应时间，每个候选测 3 次取中位数，恢复同一个 flag。
2. 把 CBC-R 靶的 `FIXED_IV` 换成从密钥派生的值（如 `AES.new(KEY, AES.MODE_ECB).encrypt(bytes(16))`）且不再随密文返回，重跑 `cbc_r.py`，确认伪造失效，并用一句话说明是哪个前提塌了。
3. 给 4.2 节的靶加第三条同 nonce 密文（英文长句），用空格异或性质做统计恢复：对每个位置枚举候选字节，$m_i \oplus m_j$ 高频为 0 的位置大概率两边都是空格。
4. 把 detect_mode.py 的"相近明文观察"做成自动化黑盒判模器：输入一个加密接口，输出"块模式/流模式、同 IV/同 nonce 嫌疑"，对几种自选配置各判一次。
5. cryptopals（入口见 [[01-练习平台索引|练习平台索引]]）按图索骥：Set 2 Challenge 12/14（ECB 逐字节恢复的无前缀版与随机前缀版，对应 [[#1.6 未知前缀：先对齐魔法串\|1.6]]）、Challenge 13（ECB 剪切粘贴）、Challenge 16（CBC 字节翻转）、Set 3 Challenge 17（padding oracle）、Challenge 19/20（固定 nonce 的 CTR 多消息统计恢复）。
