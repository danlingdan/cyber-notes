# C12 数字签名
## Digital Signatures

> [!info]- 章节信息

> **本章目标**：分清签名与加密各自要的安全属性，掌握"签摘要不签原文"的范式；会利用 RSA 教科书签名的乘法结构和 Bleichenbacher e=3 宽松校验伪造签名；会手写 ElGamal 与 DSA 的签发和验证，能从 k 重用、k 部分泄漏（格攻击）两条路恢复私钥；会把同一套公式平移到 ECDSA；会用 Ed25519 并说清它为什么从设计上避免了 k 事故；最后收敛成一份签名工程检查清单。

[[09-密码学基础|09 章]]第 5 节讲的是 RSA 的"加密"用法——公钥加密、私钥解密，目标是只有持有者能读。本章把私钥的用法反过来：私钥运算生成签名，任何人拿公钥检验。这个"反过来"不是形状上的镜像替换：加密保护内容，签名证明来源，两者要的安全性质不同，事故的形态也不同。前几章的积累在这里汇合：[[C02-数论进阶与原根|C02]] 的阶、原根与离散对数是 ElGamal/DSA 的地基，[[C07-RSA攻击I|C07]] 的参数体检思维在签名侧同样适用，[[C08-RSA攻击II|C08]] 的格与 LLL 在 [[#4.4 k 部分泄漏：HNP 格攻击入门|4.4]] 直接上场，[[C04-随机数攻防|C04]] 的随机源问题会以"签名随机数 k"的形式再次出现。

## 1. 签名解决什么问题

### 1.1 三属性与"反过来用"

先把加密与签名并排对比：

| | 加密 | 签名 |
| ---- | ---- | ---- |
| 核心运算的执行者 | 接收方（拿公钥加密） | 发送方（拿私钥签名） |
| 安全目标 | 除持有者外无人能读（机密性） | 任何人都能核实消息出自那把私钥（真实性） |
| 攻击者要什么 | 读出明文 | 为"没签过的消息"造出合法签名 |
| 性质名称 | 语义安全 | 不可伪造性 |

签名要同时给出三个保证：==认证==（消息确实出自那把私钥）、==完整性==（消息未被改动——改一个比特验证就失败）、==不可否认==（签名者事后无法抵赖）。不可否认这一条把 MAC 排除在外：[[C10-哈希进阶|C10]] 第 4 节的 HMAC 同样提供真实性与完整性，但它的验证密钥就是签发密钥，双方都能算——你无法向第三方证明"这是对方发的，不是我编的"。签名靠非对称结构解决：私钥只有一方持有。

"把 RSA 加密反过来用"在数学上确实是成立的形状：$ed \equiv 1 \pmod{\varphi(n)}$ 使 $m^{ed} \equiv m \pmod n$ 对 e、d 对称，用 d 运算、用 e 检验，就是"签名"。但==加密方案安全，推不出把私钥当签名用也安全==——两者的安全性质不同，出的事故也不同。教科书 RSA（无任何填充，直接 $s = m^d \bmod n$）两头都有洞：加密侧的确定性与小指数问题见 [[09-密码学基础#5.3 弱点套路清单|09 章 5.3]] 与 [[C07-RSA攻击I|C07]]；签名侧的两个坑是下一节的内容。

### 1.2 哈希先签：签摘要，不签原文

现代签名方案没有直接签原文的，全部两步走：

$$\sigma = \mathrm{Sign}\big(H(m)\big), \qquad \mathrm{Verify}(m, \sigma):\ \mathrm{Check}\big(\sigma,\ H(m)\big) \tag{1.1}$$

三个理由。一，原文任意长，而模运算一次只吃得下小于模数的数，签摘要则输入永远定长。二，签名长度固定为模数长度，与消息长短无关。三，把"不可伪造"归约到哈希的性质上：想伪造消息 m 的签名，等价于构造出 $H(m') = H(m)$ 的另一个 m'（第二原像）或构造一个碰撞对——攻击对象是 [[C10-哈希进阶|C10]] 的哈希安全性，不是签名算法的数论。哈希先签还顺手切断了一类结构攻击：下一节的乘法伪造在"签摘要"版本上不成立，因为 $H(m_A \cdot m_B) \ne H(m_A) \cdot H(m_B)$。

本章后面所有方案——RSA（PKCS#1）、ElGamal、DSA、ECDSA、Ed25519——式 (1.1) 的骨架完全相同，差别只在 Sign 的数论内核，以及一个反复出事故的随机数 k。

## 2. RSA 签名：教科书陷阱与填充校验

### 2.1 教科书签名：乘法组合即伪造

教科书签名的全部定义：

$$s = m^d \bmod n, \qquad \mathrm{Verify}(m, s):\ s^e \bmod n \overset{?}{=} m \tag{2.1}$$

确定性、无随机数、消息整数直接进模运算。攻击者只要见过两条真签名 $(m_A, s_A)$、$(m_B, s_B)$，不碰私钥就能拼出第三条：

$$s = s_A \cdot s_B \bmod n \implies s^e = s_A^e \cdot s_B^e = m_A \cdot m_B \bmod n \tag{2.2}$$

它是消息 $m_C = m_A \cdot m_B \bmod n$ 的合法签名，而 $m_C$ 从没被签过。同族手法还有：任取 w，$s' = s_A \cdot w \bmod n$ 是 $m' = m_A \cdot w^e \bmod n$ 的合法签名。跑一遍：

```python
# rsa_textbook.py —— 教科书签名 s = m^d：乘法组合伪造
from hashlib import sha256
from sympy import nextprime
from Crypto.Util.number import bytes_to_long

p = nextprime(2**254 + 111111)
while p % 3 != 2:
    p = nextprime(p)
q = nextprime(2**254 + 987654321)
while q % 3 != 2:
    q = nextprime(q)
n = p * q
e = 3
d = pow(e, -1, (p - 1) * (q - 1))
print("n =", n)
print("n 位数:", n.bit_length(), "bit")

def sign_raw(m_int):
    return pow(m_int, d, n)          # 教科书签名：私钥直接作用于消息本身

def verify_raw(m_int, s):
    return pow(s, e, n) == m_int     # 教科书验证：公钥还原

mA = bytes_to_long(b"pay alice 10")
mB = bytes_to_long(b"pay bob 20")
sA, sB = sign_raw(mA), sign_raw(mB)
print("原签名可验证:", verify_raw(mA, sA), verify_raw(mB, sB))

# 伪造：mC = mA*mB mod n 从未被签名，sC = sA*sB mod n
mC = mA * mB % n
sC = sA * sB % n
print("verify(mA*mB mod n, sA*sB mod n) =", verify_raw(mC, sC))

# 同族手法：一条真签名乘自选的 w，得到 m' = mA * w^e 的合法签名
w = bytes_to_long(b"evil")
s_evil = sA * w % n
m_evil = mA * pow(w, e, n) % n
print("verify(mA*w^e mod n, sA*w mod n) =", verify_raw(m_evil, s_evil))

# 对照：hash-then-sign 切断乘法结构
def sign_hs(msg):
    return pow(bytes_to_long(sha256(msg).digest()), d, n)

def verify_hs(msg, s):
    return pow(s, e, n) == bytes_to_long(sha256(msg).digest()) % n

mX, mY = b"contract X", b"contract Y"
sX, sY = sign_hs(mX), sign_hs(mY)
print("hash-then-sign 下 sX*sY 能通过验证的消息:",
      [m for m in (mX, mY, mX + mY) if verify_hs(m, sX * sY % n)])
```

最后三行的对照就是式 (1.1) 的价值：换了 hash-then-sign，$s_X \cdot s_Y$ 不再是任何已知消息的合法签名——要让它验证通过需要 $H(m) = H(X) \cdot H(Y) \bmod n$，要么解哈希的原像，要么构造碰撞，两条路都归结为哈希安全性。

> [!note] 根因：签名对象带了乘法结构
> 教科书签名是模 n 上的同态映射 $m \mapsto m^d$：消息侧相乘，签名侧跟着相乘。式 (1.1) 的哈希先把消息压缩成定长摘要，这条同态性就断了。所有标准签名都"签摘要"，这是原因之一。

### 2.2 Bleichenbacher e=3 伪造：宽松校验的代价

hash-then-sign 的 RSA 标准化版本是 PKCS#1 v1.5：签名前把摘要装进一个固定格式的填充块 EM（encoded message，长度等于模数字节数 K），再对整个块做式 (2.1)。形状：

```text
00 01 FF FF ...... FF 00 | DigestInfo（19 字节） | H（32 字节）
                     ^^^^ 分隔  |←—————— 固定 51 字节 ——————→|
       FF 填到只剩 51 字节（个数 = K - 54）
```

DigestInfo 是标识哈希算法的 ASN.1 前缀，SHA-256 对应 `3031300d060960864801650304020105000420`。==正确实现逐字节比对整个 EM==：`00 01`、FF 的个数、分隔的 `00`、DigestInfo、哈希，每个字节都不能差。现实里常见的偷懒写法：检查开头是 `00 01`，跳过一段 FF，遇到 `00` 后能对上 DigestInfo 与哈希就算通过——FF 多长、尾部位模式一律不看。

[[C07-RSA攻击I|C07]] 的体检表说过 e 偏小先想开方；签名侧的 e = 3 配合这种宽松校验，就是 Bleichenbacher 在 2006 年给出的伪造，==全程只需要公钥==。

原理：攻击者自己拼期望的 EM——头部加 DigestInfo 加目标消息的哈希，左对齐、低位垫零——把它当整数 T，取整数立方根 $x_0 = \lfloor T^{1/3} \rfloor$。$x_0^3 \le T < (x_0+1)^3$，两者相差不足 $3x_0^2$，对 K 字节的 T 来说，扰动只够伸到最底部约 K/3 字节。==固定部分压进顶部 1/3，开立方带来的扰动就全部落在没人检查的垃圾区==，$s = x_0$ 就是合法签名。

有一个取整方向上的细节：直接取 $x_0$ 时 $x_0^3 = T - D$，而 T 的低位是零填充，减法要向高位借位，固定区的最后一个字节（哈希末字节）会被减 1。改取 $x = x_0 + 1$：$x^3 = T + D'$，多出的部分落进低位垃圾区，固定区完好。

```python
# bleichen.py —— Bleichenbacher e=3 签名伪造：宽松校验靶 vs 严格校验靶
import gmpy2
from hashlib import sha256
from sympy import nextprime
from Crypto.Util.number import bytes_to_long, long_to_bytes

# 固定密钥：约 2048 位，e = 3（p、q 都取 mod 3 = 2，保证 d 存在）
p = nextprime(2**1023 + 123456789)
while p % 3 != 2:
    p = nextprime(p)
q = nextprime(2**1023 + 9876543210123456789)
while q % 3 != 2:
    q = nextprime(q)
n = p * q
e = 3
d = pow(e, -1, (p - 1) * (q - 1))
print("n 位数:", n.bit_length(), "bit   e =", e)

K = n.bit_length() // 8                       # EM 的字节数（255）
DIGEST_INFO = bytes.fromhex("3031300d060960864801650304020105000420")   # SHA-256 的 19 字节前缀

def verify_strict(msg, sig):
    """严格校验：EM = 00 01 FF*201 00 DigestInfo H，逐字节比对整个块"""
    em = long_to_bytes(pow(sig, e, n), K)
    t = K - 3 - len(DIGEST_INFO) - 32
    return em.startswith(b"\x00\x01" + b"\xff" * t + b"\x00" + DIGEST_INFO
                         + sha256(msg).digest())

def verify_lenient(msg, sig):
    """宽松校验：只看 00 01、一段 FF、一个 00、DigestInfo+哈希；其后是垃圾也放行"""
    em = long_to_bytes(pow(sig, e, n), K)
    if em[0] != 0x00 or em[1] != 0x01:
        return False
    i = 2
    while i < K and em[i] == 0xFF:            # FF 跑多长都不管，>= 8 即可
        i += 1
    if i - 2 < 8 or em[i] != 0x00:
        return False
    return em[i + 1:i + 1 + len(DIGEST_INFO) + 32] == DIGEST_INFO + sha256(msg).digest()

# 伪造目标：一条从未被签名的消息（攻击全程只用公钥 n, e）
msg = b"unlock the vault"
H = sha256(msg).digest()

# 期望的 EM：固定部分左对齐，低位垫 0
Tb = b"\x00\x01" + b"\xff" * 24 + b"\x00" + DIGEST_INFO + H
T = bytes_to_long(Tb) * 256 ** (K - len(Tb))
print("目标消息:", msg.decode())
print("期望 EM 固定部分:", len(Tb), "字节（其余", K - len(Tb), "字节是垃圾区）")

x0 = int(gmpy2.iroot(T, 3)[0])
x = x0 + 1        # 向下取整的 x0^3 = T - D 会在零填充区产生借位，波及固定区末字节；
                  # 取 x0+1：(x0+1)^3 = T + D'，多出的部分落在低位垃圾区，固定区完好
print("x^3 与 T 相差不超过 3x^2 ≈ 2^%.0f bit，即低约 %d 字节不可控"
      % (gmpy2.log2(3 * x**2), (int(gmpy2.log2(3 * x**2)) + 7) // 8))
print("x^3 < n:", x**3 < n)

print("宽松校验通过伪造签名:", verify_lenient(msg, x))
print("严格校验通过伪造签名:", verify_strict(msg, x))

# 对照：真签名（私钥签完整 EM）两把校验都过
EM = b"\x00\x01" + b"\xff" * (K - 3 - len(DIGEST_INFO) - 32) + b"\x00" + DIGEST_INFO + H
true_sig = pow(bytes_to_long(EM), d, n)
print("真签名: 宽松 =", verify_lenient(msg, true_sig), " 严格 =", verify_strict(msg, true_sig))
```

> [!warning] 攻击的是验证器，不是 RSA
> 这条攻击里 2048 位模数的分解难度完全没被触碰，坏的是"没把 EM 检查完"的实现；当年 Firefox 的 NSS 签名校验漏洞就属于此类。修复方向两条：严格实现按字节比对完整 EM；换 RSA-PSS——填充掺随机数并配有安全证明，验证同样逐字节严格。

## 3. ElGamal 签名

### 3.1 构造与手写实现

[[C02-数论进阶与原根|C02]] 讲过：mod p 乘法群里从 $y = g^x$ 反推 x 是离散对数问题。ElGamal 签名（1985）把这个困难性变成体制。密钥：大素数 p 与乘法群元素 g 公开；私钥 x，公钥 $y = g^x \bmod p$。

签消息 m：取随机数 k，要求 $1 < k < p-1$ 且 $\gcd(k, p-1) = 1$，输出一对 $(r, s)$：

$$r = g^k \bmod p \tag{3.1}$$

$$s = \big(H(m) - x \cdot r\big) \cdot k^{-1} \bmod (p-1) \tag{3.2}$$

验证：

$$g^{H(m)} \equiv y^r \cdot r^s \pmod p \tag{3.3}$$

为什么式 (3.3) 成立：式 (3.2) 两边乘 k 得 $ks \equiv H - xr \pmod{p-1}$，于是 $y^r \cdot r^s = g^{xr} \cdot g^{ks} = g^{xr + ks} = g^{H + t(p-1)} \equiv g^H \pmod p$，最后一步是费马小定理（[[09-密码学基础#2.3 费马小定理与欧拉定理|09 章 2.3]]）。

两个 mod 要分清：==r 和验证等式活在 mod p 的乘法群里；s 是指数世界的量，活在 mod p-1 下==。用 [[C02-数论进阶与原根|C02]] 的阶语言说：g 的幂以 p-1 为周期，指数只有 mod p-1 才有意义。这也解释了 k 的互素要求——式 (3.2) 要算 $k^{-1} \bmod (p-1)$，逆元存在条件就是 $\gcd(k, p-1) = 1$（[[09-密码学基础#2.2 GCD 与扩展欧几里得|09 章 2.2]]）。

```python
# elgamal.py —— ElGamal 签名：手写签发/验证 + k 重用恢复私钥
from math import gcd
from hashlib import sha256
from sympy import nextprime

p = nextprime(10**18)                     # 19 位素数，教学尺度
g = 5                                     # 乘法群元素（验证等式对任意 g 成立）
x = 12345678901234567                     # 私钥
y = pow(g, x, p)                          # 公钥
print("p =", p)
print("g = %d, x = %d, y = g^x mod p = %d" % (g, x, y))

def H(m):
    """消息 -> 摘要整数：双方约定的确定映射，这里取 SHA-256 mod (p-1)"""
    return int.from_bytes(sha256(m).digest(), "big") % (p - 1)

def sign(m, k, xs):
    assert 1 < k < p - 1 and gcd(k, p - 1) == 1, "k 必须与 p-1 互素"
    r = pow(g, k, p)
    s = (H(m) - xs * r) * pow(k, -1, p - 1) % (p - 1)
    return r, s

def verify(m, r, s):
    if not (0 < r < p and 0 <= s < p - 1):
        return False
    return pow(g, H(m), p) == pow(y, r, p) * pow(r, s, p) % p

# 正常签发与验证（k 还要保证产生的 r 与 p-1 互素，3.2 节解 x 时要用 r 的逆元）
m1 = b"invoice 2026-001"
k1 = 7654321987654321
while gcd(pow(g, k1, p), p - 1) != 1:
    k1 += 2
r1, s1 = sign(m1, k1, x)
print("\n消息:", m1.decode(), "  k =", k1)
print("r =", r1)
print("s =", s1)
print("验证:", verify(m1, r1, s1), "  篡改消息后:", verify(b"invoice 2026-999", r1, s1))

# k 重用：第二条签名暴露私钥
m2 = b"invoice 2026-002"
r2, s2 = sign(m2, k1, x)
print("\nk 重用签第二条消息, r2 == r1:", r2 == r1)
print("s2 =", s2)

# s1 - s2 = (H1-H2)*k^-1 (mod p-1) -> k；再代回任一条 -> x
k_rec = (H(m1) - H(m2)) * pow(s1 - s2, -1, p - 1) % (p - 1)
x_rec = (H(m1) - s1 * k_rec) * pow(r1, -1, p - 1) % (p - 1)
print("恢复 k:", k_rec, " 相等:", k_rec == k1)
print("恢复 x:", x_rec, " 相等:", x_rec == x)

r3, s3 = sign(b"forged by attacker", k1, x_rec)
print("攻击者用恢复的私钥签任意消息 -> 验证:", verify(b"forged by attacker", r3, s3))
```

### 3.2 k 重用：两条签名解出私钥

k 复用的后果比加密侧（两段密文直接消出明文差，[[09-密码学基础#3.2 密钥重用即死刑|09 章 3.2]]）更彻底。设两条消息共用一个 k，则 r 相同（式 (3.1) 只依赖 k），两条 s 是关于同一个未知数 k 的两条方程：$s_1 k \equiv H_1 - xr$、$s_2 k \equiv H_2 - xr \pmod{p-1}$。相减消掉 $xr$：

$$k \equiv (H_1 - H_2)\,(s_1 - s_2)^{-1} \pmod{p-1} \tag{3.4}$$

代回任意一条：

$$x \equiv (H_1 - s_1 k) \cdot r^{-1} \pmod{p-1} \tag{3.5}$$

上面输出的下半段就是这两式的直接计算：恢复出的 k、x 与签发时用的值逐一相等，攻击者随后用恢复的私钥给新消息签名，验证通过——私钥失守。

> [!warning] 不互素也能打
> 式 (3.4) 需要 $(s_1 - s_2)$ 与 $p-1$ 互素，式 (3.5) 需要 r 与 $p-1$ 互素。不互素不是无解：把 $p-1$ 按公因子拆开、各域解出候选再用 CRT 拼合（[[09-密码学基础#2.4 中国剩余定理|09 章 2.4]]），与 [[C07-RSA攻击I|C07]] 处理"e 与 φ 不互素"的分域取根是同一套动作，只是候选多了几步筛选。

## 4. DSA

### 4.1 从 ElGamal 到 DSA

ElGamal 签名有两处工程缺陷：签名长度 $2|p|$ 比特，比同安全级别的方案长一倍；s 的模 p-1 是偶数，互素与逆元的边界情况多。DSA（Digital Signature Algorithm，NIST FIPS 186，1991 年标准化）把整个指数世界搬进一个素数阶子群：签名缩短为 $2|q|$ 比特，指数模数从合数 p-1 换成素数 q。

参数三件套（[[C02-数论进阶与原根|C02]] 3.1 的阶语言）：

- 素数 q（160 到 256 位）与素数 p，满足 $q \mid p-1$；
- $g = h^{(p-1)/q} \bmod p \ne 1$——这样 g 的阶恰是 q；
- 私钥 $x \in [1, q-1]$，公钥 $y = g^x \bmod p$。

签消息 m（z 是摘要按最左 |q| 位截断后的整数）：

$$r = (g^k \bmod p) \bmod q \tag{4.1}$$

$$s = k^{-1}\,(z + x \cdot r) \bmod q \tag{4.2}$$

验证：先查 $0 < r, s < q$，然后算

$$w = s^{-1} \bmod q, \qquad u_1 = z w \bmod q, \qquad u_2 = r w \bmod q \tag{4.3}$$

最后检查

$$\big(g^{u_1} \cdot y^{u_2} \bmod p\big) \bmod q \overset{?}{=} r \tag{4.4}$$

==r 为什么要 mod q==：推导验证等式，$g^{u_1} y^{u_2} = g^{zw + xrw} = g^{w(z + xr)} = g^{ws \cdot k} = g^{k + tq} \equiv g^k \pmod p$——但这里只用到 $ws \equiv k \pmod q$ 和 $g^q \equiv 1$，指数相等只精确到 mod q。式 (3.3) 那种把指数直接放进等式的写法在子群里不再严格成立，DSA 改成比对这个元素的子群坐标 r。

摘要截断是最常见的实现错误：z 取哈希输出的==最左 |q| 位==，不是 mod q。SHA-256 配 256 位的 q 时哈希全长 256 位，两种算法恰好一致；配 160 位的 q 时 mod q 把高 96 位搅进来，数值完全不同，验证双双失败。

```python
# dsa_def.py —— DSA 参数生成与手写签发/验证（4.2/4.3/4.4 节沿用）
from hashlib import sha256
from sympy import nextprime, isprime

# 参数：q 为 128 位素数，p 为 512 位且 q 整除 p-1，g 的阶是 q
q = nextprime(2**127 + 1234567890)
k = 2**384
while True:
    p = k * q + 1
    if p.bit_length() == 512 and isprime(p):
        break
    k += 2
h = 2
g = pow(h, (p - 1) // q, p)
while g == 1:
    h += 1
    g = pow(h, (p - 1) // q, p)

x = 98765432101234567890123456789012345678       # 私钥
y = pow(g, x, p)                                 # 公钥

def z_of(msg):
    """DSA 的摘要处理：SHA-256 取最左 128 位（|q| 位）"""
    hv = int.from_bytes(sha256(msg).digest(), "big")
    return hv >> (256 - q.bit_length())

def sign(msg, kk):
    r = pow(g, kk, p) % q
    s = pow(kk, -1, q) * (z_of(msg) + x * r) % q
    return r, s

def verify(msg, r, s):
    if not (0 < r < q and 0 < s < q):
        return False
    w = pow(s, -1, q)
    u1 = z_of(msg) * w % q
    u2 = r * w % q
    return pow(g, u1, p) * pow(y, u2, p) % p % q == r

if __name__ == "__main__":
    print("q =", q)
    print("p =", p)
    print("p 位数: %d bit,  q 整除 p-1: %s,  g 的阶是 q: %s"
          % (p.bit_length(), (p - 1) % q == 0, pow(g, q, p) == 1))
    print("x =", x)
    print("y =", y)

    m1, m2 = b"transfer 100", b"transfer 999"
    kk = 2**127                                  # < q 的固定 k（4.3 节故意重用）
    r1, s1 = sign(m1, kk)
    r2, s2 = sign(m2, kk)
    print("\n签名 1 (msg=transfer 100):")
    print("  r =", r1)
    print("  s =", s1)
    print("  验证:", verify(m1, r1, s1), "  篡改后:", verify(b"transfer 001", r1, s1))
    print("签名 2 (msg=transfer 999):")
    print("  r =", r2, "\n  s =", s2, "\n  验证:", verify(m2, r2, s2))
```

### 4.2 pycryptodome 对拍

手写公式与库对拍：同一组参数，手写验证库的签名、库验证手写的签名，两边都过，公式和 API 才算同时掌握。pycryptodome 的入口有两条高频注意事项：

- `DSA.construct((y, g, p, q, x))` 从参数拼钥匙，==顺序是 (y, g, p, q, x)==，不是按公式里出现的先后；
- `DSS.new(key, mode, encoding)` 造签名器。mode 两种：`fips-186-3`（随机 k）与 `deterministic-rfc6979`（k 由私钥和摘要确定性导出）。前者强制标准 L/N 参数组合（1024/160 起步），教学尺寸的 (512, 128) 会被它拒绝；后者没有这个限制。encoding 默认 `binary`（r、s 定长字节拼接），要 DER 编码得显式传 `encoding="der"`。

```python
# dsa_cross.py —— pycryptodome 对拍（参数与 sign/verify 接 4.1 的 dsa_def.py）
from Crypto.PublicKey import DSA
from Crypto.Signature import DSS
from Crypto.Hash import SHA256

key = DSA.construct((y, g, p, q, x))   # 顺序 (y, g, p, q, x)——不是 (x, p, q, g)

def der_encode(r, s):
    def integer(v):
        b = v.to_bytes((v.bit_length() + 8) // 8, "big")   # 高位为 1 时补 0x00
        return b"\x02" + bytes([len(b)]) + b
    body = integer(r) + integer(s)
    return b"\x30" + bytes([len(body)]) + body

def der_decode(sig):
    assert sig[0] == 0x30
    def integer(i):
        ln = sig[i + 1]
        return int.from_bytes(sig[i + 2:i + 2 + ln], "big"), i + 2 + ln
    r, i = integer(2)
    s, i = integer(i)
    return r, s

m1 = b"transfer 100"
r1, s1 = sign(m1, 2**127)              # 与 4.1 节同一组 (m, k)，得到同一对 (r1, s1)

# deterministic-rfc6979：k 由 (x, H(m)) 确定性导出
sig_lib = DSS.new(key, "deterministic-rfc6979", encoding="der").sign(SHA256.new(m1))
print("pycryptodome DSS 签名 DER %d 字节:" % len(sig_lib))
print(" ", sig_lib.hex())
r_lib, s_lib = der_decode(sig_lib)
print("  解出 r =", r_lib)
print("       s =", s_lib)
print("  手写公式验证库签名:", verify(m1, r_lib, s_lib))
same = DSS.new(key, "deterministic-rfc6979", encoding="der").sign(SHA256.new(m1)) == sig_lib
print("  同消息再签一次结果相同:", same)
DSS.new(key.public_key(), "deterministic-rfc6979", encoding="der").verify(
    SHA256.new(m1), der_encode(r1, s1))
print("  库验证手写签名 (4.1 节的 r1, s1): True")
```

> [!note] RFC 6979
> deterministic-rfc6979 的 k 由 HMAC(x, z) 一族确定性导出：同一消息同一 k，不同消息不同 k，随机数源彻底退出签名流程。它与 Ed25519 的确定性 nonce（[[#6.1 确定性 nonce：随机数退出签名流程|6.1]]）是同一个思想在两条技术路线上的落法。HMAC 的结构见 [[C10-哈希进阶|C10]] 第 4 节。

### 4.3 k 重用：两行解出私钥

DSA 的 s 公式与 ElGamal 同构，k 重用的解法也只差符号。两条签名共用 k 则 $r_1 = r_2$，相减消 x：

$$k \equiv (z_1 - z_2)\,(s_1 - s_2)^{-1} \pmod q \tag{4.5}$$

$$x \equiv (s_1 k - z_1) \cdot r_1^{-1} \pmod q \tag{4.6}$$

q 是素数，逆元总在（k、r 撞 0 的概率忽略不计），连分域处理都不需要——比 ElGamal 的版本更简洁。

```python
# dsa_kreuse.py —— DSA k 重用恢复私钥（参数与 sign/z_of 接 4.1 的 dsa_def.py）
m1, m2 = b"transfer 100", b"transfer 999"
kk = 2**127                                       # < q 的固定 k，两条签名共用
r1, s1 = sign(m1, kk)
r2, s2 = sign(m2, kk)
print("k 重用，r1 == r2:", r1 == r2)
print("r =", r1)
print("s1 =", s1)
print("s2 =", s2)

# s1 - s2 = (z1 - z2)*k^-1 (mod q) -> k；代回 s1 = k^-1*(z1 + x*r1) -> x
k_rec = (z_of(m1) - z_of(m2)) * pow(s1 - s2, -1, q) % q
x_rec = (s1 * k_rec - z_of(m1)) * pow(r1, -1, q) % q
print("恢复 k:", k_rec, " 相等:", k_rec == kk)
print("恢复 x:", x_rec, " 相等:", x_rec == x)
print("g^x_rec == y:", pow(g, x_rec, p) == y)
```

> 验证方就能做 k 重用检测：==r 相同即是标志==，因为 r 由式 (4.1) 直接从 k 算出。收集一个体系的多条签名、按 r 分组，是审计签名实现的例行动作。

### 4.4 k 部分泄漏：HNP 格攻击入门

全泄漏与全重用是显式事故；更隐蔽的是==部分泄漏==：侧信道（功耗、计时、故障注入）让每条签名只漏出 k 的一段比特。漏得足够多，格算法能把私钥拼出来——这是隐藏数问题（Hidden Number Problem, HNP）。

设定：q 为 128 位，每条签名的 k 泄漏低 64 位，即 $k = l + 2^{64} u$，l 已知，$u < 2^{63}$ 未知。把 DSA 签名方程变形（式 4.2 两边乘 k）：

$$s \cdot k \equiv z + x \cdot r \pmod q \tag{4.7}$$

代入 $k = l + 2^{64}u$，两边乘 $r^{-1}$，把 x 解出来：

$$x \equiv \underbrace{r^{-1}(s\,l - z)}_{a} + \underbrace{r^{-1} \cdot s \cdot 2^{64}}_{b} \cdot u \pmod q \tag{4.8}$$

每条签名给出一对已知的 $(a_i, b_i)$ 和一个小未知数 $u_i$。x 是全尺寸（约等于 q），不小；小的只有 $u_i$。任取一条作基准（第 0 条），两两相减把 x 消掉：

$$u_j \equiv P_j\, u_0 + Q_j \pmod q, \qquad P_j = b_j^{-1} b_0, \quad Q_j = b_j^{-1}(a_0 - a_j) \tag{4.9}$$

于是候选解 $(u_0, u_1, \dots, u_{t-1}, 1)$ 是一个 t+1 维格里的==短向量==：前 t 个坐标都小于 $2^{64}$，末位是 1。[[C08-RSA攻击II|C08]] 第 2、3 节的直觉原样适用——把"小未知数满足模方程"翻译成"格里的短向量"，LLL 负责把它找出来。格的基按式 (4.9) 直接写出：

```text
[ 1  P_1 P_2 ... P_{t-1}  0 ]     u_0 方向：每个 u_j ≡ P_j·u_0
[ 0  Q_1 Q_2 ... Q_{t-1}  1 ]     常数方向：补上 Q_j，末位是常数槽
[ q·I_t（t 行）           0 ]     把每个坐标约到 mod q
```

目标向量恰好是前两行的整数组合（$u_0$ 倍第一行 + 1 倍第二行 + 若干 q 行把各坐标收进范围）。

```python
# hnp_dsa.py —— DSA 私钥恢复：每条签名的 k 泄漏低 64 位（HNP 格攻击）
# 参数与 z_of 接 4.1 的 dsa_def.py；签名生成单独写（k 的结构不同）
from fpylll import IntegerMatrix, LLL

U = [0x1D2E3F4A5B6C7D80, 0x2C3B4A59687F6E70, 0x0918273645546372, 0x5A493827160506F8,
     0x3141592653589790, 0x2718281828459040, 0x1618033988749890, 0x5772156649015320]
L = [0x0FEEDFACE0DDBA11, 0xCAFEBABE12345678, 0x0123456789ABCDEF, 0xDEADBEEF01234567,
     0x1111222233334444, 0x5555666677778888, 0x9999AAAABBBBCCCC, 0xDDDDEEEEFFFF0000]
msgs = ["payment 00%d" % i for i in range(1, 9)]

sigs = []                        # 攻击者可见的全部信息：r, s, 摘要 z, 泄漏的低 64 位 l
for m, u, l in zip(msgs, U, L):
    k = u * 2**64 + l            # k = l + 2^64 * u：l 泄漏，u 是未知高位（k < q，u < 2^63）
    assert k < q
    r = pow(g, k, p) % q
    s = pow(k, -1, q) * (z_of(m.encode()) + x * r) % q
    sigs.append({"m": m, "r": r, "s": s, "l": l})
for sg in sigs[:3]:
    print("msg=%s  r=%d  s=%d  l=%#018x" % (sg["m"], sg["r"], sg["s"], sg["l"]))
print("（共 %d 条签名，其余省略）" % len(sigs))

# 方程整理：s*k = z + x*r (mod q),  k = l + 2^64*u
#   -> x = a_i + b_i*u_i (mod q)，a_i = r^-1*(s*l - z)，b_i = r^-1*s*2^64
# 与第 0 条相减消掉 x：u_j = P_j*u_0 + Q_j (mod q)，P_j = b_j^-1*b_0，Q_j = b_j^-1*(a_0-a_j)

def attack(subset):
    t = len(subset)
    A = [pow(sg["r"], -1, q) * (sg["s"] * sg["l"] - z_of(sg["m"].encode())) % q for sg in subset]
    B = [pow(sg["r"], -1, q) * sg["s"] * 2**64 % q for sg in subset]
    P = [pow(B[j], -1, q) * B[0] % q for j in range(1, t)]
    Q = [pow(B[j], -1, q) * (A[0] - A[j]) % q for j in range(1, t)]

    # (t+1) 维格：目标短向量 (u_0, u_1, ..., u_{t-1}, 1)
    rows = [[1] + P + [0], [0] + Q + [1]]
    for i in range(t):
        row = [0] * (t + 1)
        row[i] = q
        rows.append(row)
    M = IntegerMatrix.from_matrix(rows)
    LLL.reduction(M)

    for i in range(M.nrows):
        row = [M[i][j] for j in range(t + 1)]
        if abs(row[t]) != 1:                     # 常数槽必须是 +-1
            continue
        sign = row[t]
        us = [sign * row[j] for j in range(t)]   # 末位是 -1 时整行取反
        if all(0 <= u < 2**64 for u in us):
            return (A[0] + B[0] * us[0]) % q, us
    return None, None

x2, _ = attack(sigs[:2])
print("\n用 2 条签名攻击 ->", "失败（约减出的都是更短的无关向量）" if x2 is None
      else "g^x==y:%s（碰巧）" % (pow(g, x2, p) == y))
x8, us8 = attack(sigs)
print("用 8 条签名攻击 -> 恢复 x =", x8)
print("g^x_rec == y:", pow(g, x8, p) == y, "  与真私钥相等:", x8 == x)
print("恢复的未知高位 u 与真值逐项相等:", us8 == U)
```

从 8 条各自"只见低 64 位"的签名里，私钥完整恢复，连 8 个未知高位 u 也逐一还原（与生成靶子用的 U 列表逐项相等）。

> [!info]- 为什么 2 条不够、8 条稳
> 目标向量长度约 $2^{64}\sqrt{t+1}$；格的典型向量长度（[[C08-RSA攻击II|C08]] 2.2 的 $\det^{1/d}$）是 $q^{(t-1)/(t+1)} = 2^{128(t-1)/(t+1)}$。t=2 时是 $2^{42.7}$，远短于目标——格里有大量更短的无关向量，LLL 找到的是它们；t=3 处在临界（两边都是 $2^{64}$ 量级），命中与否取决于具体数值；t=8 时 $2^{99.6}$ 对 $2^{66.4}$，余量 33 比特，稳定命中。泄漏越少（u 越大）需要的签名越多，这笔账算法不变。

> [!note] 往下走
> HNP 的完整版处理更一般的泄漏形态：已知 k 的最高位、分段泄漏、每次只漏几个比特。经典起点是 Boneh–Venkatesan 的 HNP 论文（CRYPTO 1996）；把格攻击推到"每条泄漏几个比特也够"的是 Minerva、LadderLeak 这批 2019–2020 年的工作，对应的正是真实世界的侧信道漏洞。CTF 出题通常停在本文这个"一笔账能算清"的档位：泄漏量给足、签名条数给足，检查点就是恢复出 x。

## 5. ECDSA

### 5.1 同一套公式搬到曲线上

ECDSA 把 DSA 的乘法群换成椭圆曲线点群（曲线的数学在 [[C11-椭圆曲线与ECDLP|C11]]）：$g^k \bmod p$ 换成点乘 $kG$，q 换成基点的阶 n，d 是私钥标量，公钥是点 $Q = dG$。签名：

$$r = (kG)_x \bmod n \tag{5.1}$$

$$s = k^{-1}\,(z + r \cdot d) \bmod n \tag{5.2}$$

验证：查 $0 < r, s < n$，算 $w = s^{-1} \bmod n$，检查

$$\big( (z w)\cdot G + (r w)\cdot Q \big)_x \bmod n \overset{?}{=} r \tag{5.3}$$

推导与式 (4.4) 逐字平行。k 重用也是同一道方程：

$$k = (z_1 - z_2)(s_1 - s_2)^{-1}, \qquad d = (s_1 k - z_1)\, r_1^{-1} \pmod n \tag{5.4}$$

==k 重用即死，这条在曲线上一点没变==。

```python
# ecdsa.py —— ECDSA：手写签发/验证（pycryptodome 做点乘）+ pycryptodome 对拍 + k 重用
from hashlib import sha256
from Crypto.PublicKey import ECC
from Crypto.Signature import DSS
from Crypto.Hash import SHA256

# P-256 的阶 n（公开常数）
n = 0xFFFFFFFF00000000FFFFFFFFFFFFFFFFBCE6FAADA7179E84F3B9CAC2FC632551

G = ECC.construct(curve="P-256", d=1).pointQ    # d=1 的公钥就是生成元 G
d = 0x2B4E7F5A1C3D9E8F0A1B2C3D4E5F60718293A4B5C6D7E8F9012345678ABCDEF0
Q = d * G                                       # 公钥点
print("曲线 P-256, 阶 n 为 %d bit" % n.bit_length())
print("私钥 d =", hex(d))
print("公钥 Q = d*G 的 x 坐标:", hex(int(Q.x)))

def z_of(m):
    """P-256 的阶是 256 位，SHA-256 摘要 256 位，正好全长使用（哈希比 n 长才需左截）"""
    return int.from_bytes(sha256(m).digest(), "big")

def sign(m, kk):
    R = kk * G
    r = int(R.x) % n
    s = pow(kk, -1, n) * (z_of(m) + r * d) % n
    return r, s

def verify(m, r, s):
    if not (0 < r < n and 0 < s < n):
        return False
    w = pow(s, -1, n)
    X = z_of(m) * w % n * G + r * w % n * Q     # u1*G + u2*Q
    return int(X.x) % n == r

m1 = b"tx: 100 coins to alice"
m2 = b"tx: 999 coins to bob"
kk = 0x1F2E3D4C5B6A79880917A6B5C4D3E2F10F1E2D3C4B5A69788796A5B4C3D2E1F0
r1, s1 = sign(m1, kk)
r2, s2 = sign(m2, kk)
print("\n签名 1 (%s):" % m1.decode())
print("  r =", hex(r1))
print("  s =", hex(s1))
print("  验证:", verify(m1, r1, s1), "  篡改后:", verify(b"tx: 1 coin to alice", r1, s1))
print("签名 2 (%s):" % m2.decode())
print("  验证:", verify(m2, r2, s2))

# ---------- pycryptodome 对拍 ----------
key = ECC.construct(curve="P-256", d=d)
lib_sig = DSS.new(key, "deterministic-rfc6979", encoding="der").sign(SHA256.new(m1))
print("\npycryptodome ECDSA 签名 DER %d 字节: %s..." % (len(lib_sig), lib_sig[:16].hex()))

def der_decode(sig):
    def integer(i):
        ln = sig[i + 1]
        return int.from_bytes(sig[i + 2:i + 2 + ln], "big"), i + 2 + ln
    r, i = integer(2)
    s, i = integer(i)
    return r, s

def der_encode(r, s):
    def integer(v):
        b = v.to_bytes((v.bit_length() + 8) // 8, "big")
        return b"\x02" + bytes([len(b)]) + b
    body = integer(r) + integer(s)
    return b"\x30" + bytes([len(body)]) + body

r_l, s_l = der_decode(lib_sig)
print("  手写公式验证库签名:", verify(m1, r_l, s_l))
DSS.new(key.public_key(), "deterministic-rfc6979", encoding="der").verify(SHA256.new(m2), der_encode(r2, s2))
print("  库验证手写签名: True")

# ---------- k 重用：与 DSA 同一套公式 ----------
print("\n== k 重用 ==")
print("r1 == r2:", r1 == r2)
k_rec = (z_of(m1) - z_of(m2)) * pow(s1 - s2, -1, n) % n
d_rec = (s1 * k_rec - z_of(m1)) * pow(r1, -1, n) % n
print("恢复 k 与真值相等:", k_rec == kk)
print("恢复 d 与真值相等:", d_rec == d)
print("d_rec * G == Q:", d_rec * G == Q)
```

代码里有四个 pycryptodome 的实用点：`ECC.construct(curve=..., d=...)` 从标量拼钥匙，公钥点在 `key.pointQ`；公钥点用 `key.public_key()` 取（不是 RSA 的 `publickey()`）；d=1 的钥匙公钥恰是生成元 G，手写公式直接可用；点乘是 `*`、点加是 `+`。签名模式这里选 `deterministic-rfc6979`：`fips-186-3` 在 P-256 这类标准曲线上同样可用（不受 [[#4.2 pycryptodome 对拍|4.2]] 那个 L/N 限制），但它每次签名取随机 k，输出的 (r, s) 逐次不同；确定性模式的 DER 逐字节稳定，便于比对与归档——与 [[#4.2 pycryptodome 对拍|4.2]] 的 DSA 是同一个选择。

> [!warning] 比特币钱包的事故
> 2013 年 8 月，安卓系统比特币钱包依赖的随机数组件出缺陷，部分交易签名产生重复的 k；链上数据人人可见，攻击者照式 (5.4) 算出私钥，转走钱包的全部资金。公开区块链让"签名全量存档"与"按 r 分组的重用检测"同时对攻击者可用——防御方做审计和攻击方找靶子，读的是同一张表。

[[#4.4 k 部分泄漏：HNP 格攻击入门|4.4]] 的 HNP 格攻击同样适用于 ECDSA，方程形状不变。nonce 偏差类攻击在学术与实战两条线上都还活跃；CTF 里常见的出题形态是"每条签名泄漏 k 的固定几个比特 + 足够多条签名"，检查点同样是恢复私钥。

## 6. Ed25519

### 6.1 确定性 nonce：随机数退出签名流程

DSA/ECDSA 的全部本章事故都指向同一个设计决定：==k 在每次签名的瞬间取自随机数源==。随机源弱（[[C04-随机数攻防|C04]] 的整章主题）、重用一次、漏几个比特，私钥都会失守。EdDSA（Ed25519 是其主力实例，RFC 8032）把 k 改成确定性推导：

$$k = H_{512}(\mathrm{prefix} \,\|\, M) \bmod n \tag{6.1}$$

$H_{512}$ 是 SHA-512：32 字节种子哈希出 512 位，后半 256 位叫 prefix，只随私钥存在，外界不可知。同一把私钥签同一条消息永远得到同一个签名；签不同消息 k 必不同；攻击者不知道 prefix，既无法预测 k，也无法让两条消息共享 k——==随机数的质量从安全论证里消失了==。

Python 生态里 pynacl 是 libsodium 的绑定：`pip3 install pynacl`。API 三件套：`SigningKey`（32 字节种子唯一决定）、`sign`、`VerifyKey.verify`。

```python
# ed25519.py —— Ed25519（pynacl / libsodium 绑定）：确定性 nonce 与基本用法
from nacl.signing import SigningKey, VerifyKey
from nacl.exceptions import BadSignatureError

# 32 字节种子决定全部私钥（Ed25519 的"私钥"就是种子；此值取自 RFC 8032 测试向量）
seed = bytes.fromhex("4ccd089b28ff96da9db6c346ec114e0f5b8a319f35aba624da8cf6ed4fb8a6fb")
sk = SigningKey(seed)
vk = sk.verify_key
print("种子(私钥)     =", seed.hex())
print("公钥           =", bytes(vk).hex(), " (%d 字节)" % len(bytes(vk)))

msg = b"release 1.0 approved"
signed = sk.sign(msg)
sig = signed.signature
print("\n消息:", msg.decode())
print("签名 =", sig.hex())
print("签名长度:", len(sig), "字节")

# 确定性：同一私钥同一消息，签名逐字节相同；没有随机数参与
sig2 = sk.sign(msg).signature
print("同一消息再签一次, 签名相同:", sig == sig2)

# 验证
try:
    vk.verify(msg, sig)
    print("验证通过: True")
except BadSignatureError:
    print("验证通过: False")

# 篡改即拒
try:
    vk.verify(b"release 2.0 approved", sig)
    print("篡改消息后验证: 通过")
except BadSignatureError:
    print("篡改消息后验证: BadSignatureError（拒绝）")
try:
    vk.verify(msg, bytes(bytearray(sig[:63]) + bytearray([sig[63] ^ 1])))
    print("翻转签名末 1 位后验证: 通过")
except BadSignatureError:
    print("翻转签名末 1 位后验证: BadSignatureError（拒绝）")
```

> [!warning] Ed25519 不是万能
> 三条边界。一，确定性是双刃：任何人可以离线检验"这条消息是否被这把钥匙签过"，低熵消息能被字典比对——协议里别拿签名当秘密。二，常数时间不随算法自动到来：实现若在计算 k 或点乘时泄漏时序，prefix 照样被侧信道抠出来，选库要确认实现声明（libsodium 是常数时间实现）。三，生态兼容场景（TLS 证书链、既有 P-256 体系）仍要写 ECDSA，此时 k 的纪律靠 RFC 6979 的确定性导出来补。

## 8. 常见问题

| 现象 | 原因与解决 |
| ---- | ---- |
| 手写 DSA 签发正常、验证恒为 False | 摘要处理错了：z 要取哈希的==最左 \|q\| 位==，写成 mod q 数值就完全不同（[[#4.1 从 ElGamal 到 DSA\|4.1]]）；哈希位宽小于 \|q\| 时还要左补零 |
| ElGamal 签发时 `pow(k, -1, p-1)` 报 not invertible | gcd(k, p-1) ≠ 1，换 k 重试即可；DSA 没有这个坑——q 是素数，[1, q-1] 内的 k 必有逆 |
| 手写 DSA 把 s、w 一类量的模写成 p-1，验证恒不通过 | DSA 的 s、w、u1、u2 全部活在 mod q 下，只有 g、y 的幂运算在 mod p；把 ElGamal 的 mod p-1 习惯带进来，验证等式两边就对不上（[[#4.1 从 ElGamal 到 DSA\|4.1]]） |
| DSA 参数生成 `p = k*q+1` 迟迟不出素数，像死循环 | 先核对 k 的位宽：p 要 512 位，k 得从 2^384 起；从 2^383 起差一位，循环不会停（[[#4.1 从 ElGamal 到 DSA\|4.1]]） |
| `DSA.construct((x, p, q, g))` 报错或验证失败 | 参数顺序是 `(y, g, p, q, x)`，不是按公式出现顺序（[[#4.2 pycryptodome 对拍\|4.2]]） |
| `DSS.new(key, "fips-186-3")` 报 L/N is not compliant | fips 模式只认标准参数组（1024/160 起步）；教学尺寸的密钥换 `deterministic-rfc6979`（[[#4.2 pycryptodome 对拍\|4.2]]） |
| 从 DSS 拿到的"DER"解不出 (r, s)，首字节不是 0x30 | encoding 默认是 binary（r、s 定长拼接）；DER 要显式传 `encoding="der"`（[[#4.2 pycryptodome 对拍\|4.2]]） |
| k 重用检测只比 r，仍被打穿 | r 相同只能检测出"全重用"；k 各不相同的部分泄漏走 HNP（[[#4.4 k 部分泄漏：HNP 格攻击入门\|4.4]]）。检测 r 之外还要按泄漏面评估 |
| HNP 格约减出的 x 验证不过 | 三查：格的维度是 t+1（两条种子行加 t 条 mod q 行），行、列方向与 [[C08-RSA攻击II\|C08]] 2.5 的行约定一致；式 (4.9) 的 Q_j 符号是 $a_0 - a_j$；末位是 -1 时要整行取反再查范围（[[#4.4 k 部分泄漏：HNP 格攻击入门\|4.4]]） |
| Bleichenbacher 伪造里 icbrt(T) 直接开出来校验不过 | 向下取整在零填充区产生借位，哈希末字节被减 1；取 icbrt(T)+1，让溢出落进垃圾区（[[#2.2 Bleichenbacher e=3 伪造：宽松校验的代价\|2.2]]） |
| 伪造签名的垃圾区写不下 | 垃圾区只有约模数字节的 1/3；DigestInfo 加哈希共 51 字节，加头部必须压进顶部 1/3，模数不够长就换短哈希或加长 n（[[#2.2 Bleichenbacher e=3 伪造：宽松校验的代价\|2.2]]） |
| ECDSA 手写公式里把 q 写进去 | 曲线场景的模是基点的阶 n（P-256 为 256 位），变量名混用是常见错误源（[[#5.1 同一套公式搬到曲线上\|5.1]]） |
| pynacl 装不上 | `pip3 install pynacl` 常规即可；受限环境用 openssl 命令行（`genpkey -algorithm ed25519` 加 `pkeyutl -sign/-verify`）走同款流程 |

## 9. 配套练习与延伸阅读

> [!note] 实战任务
> 1. **HNP 靶场扩容**：把 [[#4.4 k 部分泄漏：HNP 格攻击入门\|4.4]] 的靶改成 q 为 256 位、每条泄漏低 128 位，先按折叠框里的账估算需要几条签名，再实现打穿；泄漏减半到 64 位重复一次，对比条数。
> 2. **收紧校验**：把 [[#2.2 Bleichenbacher e=3 伪造：宽松校验的代价\|2.2]] 的宽松靶改成严格版（FF 个数与总长都检查），重放伪造签名确认被拒；然后逐项放宽，找出你的实现还能被打穿的最宽松形态。
> 3. **手写 RFC 6979**：按规范用 hmac 标准库（[[C10-哈希进阶\|C10]] 第 4 节）实现 DSA 的确定性 k，与 pycryptodome 的 deterministic-rfc6979 模式在同参数同消息下对拍，两边签名逐字节一致才算过。
> 4. **ElGamal 重用的完整版**：把 [[#3.2 k 重用：两条签名解出私钥\|3.2]] 的恢复改写成不依赖互素条件的版本（分域解候选 + CRT 拼合），自造一组 $\gcd(s_1 - s_2,\ p-1) = 2$ 的数据打穿。

配套练习：

1. **可延展性**：对 [[#4.1 从 ElGamal 到 DSA|4.1]] 验证通过的 $(r, s)$ 计算 $s' = q - s$ 再验一次——同样通过，一条消息有两个合法签名。这在比特币早期造成过交易标识混淆（延展性攻击）；给 verify 加上 $s \le q/2$ 的规范化检查封掉它。
2. **重用审计脚本**：收集 20 条 DSA 签名（其中混入若干固定 k 的），按 r 分组检出重用组，对每组用式 (4.5)(4.6) 恢复私钥并核对 $g^x = y$。
3. **e=5 的 Bleichenbacher**：把 [[#2.2 Bleichenbacher e=3 伪造：宽松校验的代价|2.2]] 的 e 换成 5，重算垃圾区大小（$5x^4$ 占多少字节），判断 2048 位模数配 SHA-256 还装不装得下，写出结论。
4. **库签名注入**：用 [[#5.1 同一套公式搬到曲线上|5.1]] 的手写公式给 pycryptodome 构造一个"指定 k"的 ECDSA 签名（DER 编码后交给库验证），再对同一签名跑 [[#4.3 k 重用：两行解出私钥|4.3]] 的恢复公式——理解"知道 k 就等于知道私钥"这句话的完整含义。
