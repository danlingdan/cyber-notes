## Protocol-Level Cryptography

> [!info]- 章节信息

> **本章目标**：手写 mod p 的 Diffie-Hellman 交换，p、g、公钥、共享秘密全程算通；本地三进程靶打穿"交换无认证"的中间人，并给协商参数签名把中间人拦下；认识参数三陷阱（p 太小、g 的阶太小、小子群探测）并完整执行 mod p 版小阶元素提取私钥；用 openssl 的 s_server/s_client 观察 TLS 1.2 与 1.3 握手的每个阶段，读懂一条 ciphersuite；把 Heartbleed、ROBOT、Logjam、DROWN、降级族收进"环节 → 大案 → 根因"一张表；拿到"自定义安全协议"题会按清单找逻辑洞。

[[C02-数论进阶与原根|C02]] 第 4 节埋过一句伏笔：离散对数的困难性是 DH 一类体制的安全根基。本章兑现它——先手写一遍 mod p 的 Diffie-Hellman（下称 DH）交换，然后沿着"流程"这一层往下挖。核心观察是一句话：==单看每个算法都没有问题，出事的是把它们拼起来的方式==。交换本身没有认证，中间人当场成立；参数选错（p 小、g 阶小、p-1 带小因子），离散对数的难度凭空塌掉；RSA 密钥交换不提供前向保密，服务器私钥一泄，历史流量全部可解。

与已落库各章的分工：[[C02-数论进阶与原根|C02]] 的原根、元素的阶、BSGS 与离散对数复杂度本章直接拿来用，不再推导；[[C11-椭圆曲线与ECDLP|C11]] 第 5 节从曲线侧讲过"实现不校验对端公钥"的无效曲线攻击，本章把同一形态补全到 mod p 一侧（[[#2.3 小子群探测：不校验对端公钥的代价|2.3]]）；[[C09-RSA攻击III|C09]] 第 5 节的 Bleichenbacher padding oracle 在 [[#4. TLS 大案概览：五个样本与一张表|第 4 节]]以 ROBOT 的名义回归；签名的体制内部在 [[C12-数字签名|C12]]，本章把它当工具使（给参数签名）。

## 1. Diffie-Hellman 密钥交换：公开信道上造出共享秘密

### 1.1 流程与手写实现

DH 解决一个问题：alice 与 bob 从未见过面，只能在公开信道上通话，要商量出一个只有他俩知道的数。流程四步：

1. 双方约定公开参数：大素数 p 与生成元 g（g 的阶必须够大，不满足会怎样见 [[#2.2 g 不是原根：子群把密钥空间压小|2.2]]）；
2. alice 挑私钥 a（保密），发公钥 $A = g^a \bmod p$；
3. bob 挑私钥 b（保密），发公钥 $B = g^b \bmod p$；
4. alice 算 $s = B^a \bmod p$，bob 算 $s = A^b \bmod p$，两者自动相等：

$$s = B^a = (g^b)^a = (g^a)^b = A^b \pmod p \tag{1.1}$$

窃听者手里有 p、g、A、B，要得到 s 必须先从 A 反解出 a——这就是 [[C02-数论进阶与原根#4.2 BSGS：大步小步，空间换时间|C02 4.2]] 的离散对数问题，参数正常时不可行。s 不能直接当密钥用（它是个模 p 整数，取值不均匀，还可能是 1 或 p−1 这类小值），要过一遍密钥派生函数（KDF）摊平成密钥流，之后的全部通信换对称密码。手写一遍（p = 2q+1，q 为 256 位素数；g 取模 p 的原根）：

```python
# v1_dhe_basic.py —— mod p Diffie-Hellman 全流程：p、g、私钥、公钥、共享 s
import random, hashlib
from dhparams import P, G, q

random.seed(20261024)                # 教学代码用固定种子；真实实现必须用 secrets/os.urandom
a = random.randrange(2, q)           # alice 的私钥
b = random.randrange(2, q)           # bob 的私钥
A = pow(G, a, P)                     # alice 的公钥
B = pow(G, b, P)                     # bob 的公钥
s1 = pow(B, a, P)                    # alice 算共享秘密
s2 = pow(A, b, P)                    # bob 算共享秘密

print("p (%d bit) = %d" % (P.bit_length(), P))
print("q (%d bit) = %d, p = 2q+1" % (q.bit_length(), q))
print("g =", G)
print("a =", a)
print("b =", b)
print("A = g^a mod p =", A)
print("B = g^b mod p =", B)
print("alice 算 s = B^a mod p =", s1)
print("bob   算 s = A^b mod p =", s2)
print("两边一致:", s1 == s2)
k = hashlib.sha256(str(s1).encode()).digest()    # 真实协议把 s 交给 KDF，不直接当密钥用
print("KDF(s) 前 16 字节 =", k[:16].hex())
```

> [!info]- 公共参数怎么来（dhparams.py）
> p 取安全素数 p = 2q+1（q 也是素数，[[C02-数论进阶与原根#1.4 确定性底数与素数生成|C02 1.4]] 强素数伏笔的着落点）。选安全素数的理由在 [[#2.3 小子群探测：不校验对端公钥的代价|2.3]]：安全素数下乘法群的子群阶只有 1、2、q、2q 四档，小阶元素只剩 ±1，一眼能识别。g 用 sympy 的 `primitive_root` 求原根。生成参数的几行：
>
> ```python
> from sympy import nextprime, isprime
> from sympy.ntheory.residue_ntheory import primitive_root
>
> q = nextprime(2**255 + 12345678901234567890)
> while not isprime(2 * q + 1):
>     q = nextprime(q + 1)
> P = 2 * q + 1
> G = primitive_root(P)
> ```
>
> 教学靶用 256 位 p；真实的 mod p 部署从 2048 位起步（[[#2.4 公共素数与 Logjam|2.4]] 讲为什么），现代协议更常用椭圆曲线版（ECDHE，[[C11-椭圆曲线与ECDLP|C11]]）。

### 1.2 中间人：交换本身没有身份

回看四步流程里的每条消息：A、B 只是两串数字，数字不会自称来自谁。==DH 解决"窃听者解不出 s"，不解决"对端是谁"==。中间人 mallory 站到信道中间，对 alice 冒充 bob、对 bob 冒充 alice：给 alice 换上自己的 $A_1 = g^{m_1}$，给 bob 换上自己的 $A_2 = g^{m_2}$，于是两条 DH 分别在"alice–mallory"与"mallory–bob"之间建立，alice 与 bob 之间反而没有任何共享秘密。此后每条消息 mallory 拆开读一遍，再用对端会话的密钥重新加密转发。

三进程靶：bob 监听 7702；mallory 监听 7703，同时作为客户端连 7702；alice 连 7703——它以为自己连的是 bob（真实场景里对应 DNS 劫持、网关转发一类的位置占领）。协议是两行文本格式：`A <公钥>` / `B <公钥>` 协商，`M <base64 密文>` 传消息。三份脚本共用这一段小函数：

```python
# 公共代码：三份脚本里都有（socket、hashlib、base64、AES 与下面三个函数）
import socket, random, hashlib, base64
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad, unpad
from dhparams import P, G                 # dhparams.py 见 1.1 的折叠框

def kdf(s):                               # 真实协议用 HKDF 一类 KDF，这里用 SHA-256 演示
    return hashlib.sha256(str(s).encode()).digest()[:16]

def enc(k, msg):                          # AES-ECB 仅为演示可对拍
    return base64.b64encode(AES.new(k, AES.MODE_ECB).encrypt(pad(msg, 16))).decode()

def dec(k, blob):
    return unpad(AES.new(k, AES.MODE_ECB).decrypt(base64.b64decode(blob)), 16)
```

```python
import random
# ……（公共代码省略）……
from dhparams import P, G

random.seed(31337)
m1 = random.randrange(2, P - 2)      # 与 alice 会话的私钥

fa_r, fa_w = conn_a.makefile("rb"), conn_a.makefile("wb")

A1 = pow(G, m1, P)
fa_w.write(("B %d\n" % A1).encode()); fa_w.flush()   # 给 alice 换上自己的"B"
s1 = pow(alice_A, m1, P)                     # mallory 与 alice 的共享秘密

conn_b = socket.create_connection(("127.0.0.1", 7702))
fb_r, fb_w = conn_b.makefile("rb"), conn_b.makefile("wb")

fb_w.write(("A %d\n" % A2).encode()); fb_w.flush()   # 给 bob 换上自己的"A"
bob_B = int(fb_r.readline().split()[1])      # 截下 bob 的 B，不给 alice
s2 = pow(bob_B, m2, P)                       # mallory 与 bob 的共享秘密

print("[mallory] 与 alice 的会话 s1 =", s1, flush=True)
print("[mallory] 与 bob   的会话 s2 =", s2, flush=True)

for _ in range(2):
    msg = dec(k1, fa_r.readline().split()[1])          # alice -> bob

    reply = dec(k2, fb_r.readline().split()[1])        # bob -> alice
    print("[mallory] bob->alice 明文: %r" % reply, flush=True)
    fa_w.write(("M %s\n" % enc(k1, reply)).encode()); fa_w.flush()
```

- 全程的模幂运算、AES、base64 都是对的——==加密强度、密钥长度、算法选型与这次失守完全无关==，缺口只有一处：交换没有认证。

### 1.3 修复：给协商参数签名

修复思路直接：把"我是谁"绑定到参数上。alice 发 A 时附上她对 A 的 RSA-PSS 签名，bob 用 alice 的公钥验签，不过就断开；反方向同理（工程上签名还要覆盖 p、g 与整份握手抄本，[[#3.2 RSA 密钥交换与 (EC)DHE：前向保密|3.2]] 的 TLS 1.3 就是这么做的；只签 A 不签参数的变体仍留有洞，见 [[#6. CTF 里的协议题形态|第 6 节]]的检查清单）。签名的体制内部见 [[C12-数字签名|C12]]，本节用 pycryptodome 当工具。信任锚是双方各持的固定 RSA 密钥对——真实部署里公钥放在证书里由 CA 签名分发，TLS 的做法见 [[#3.1 握手骨架|3.1]]：

> [!info]- 信任锚与签名字段（authkeys.py）
>
> ```python
> # authkeys.py —— alice 与 bob 各持一对固定 RSA 密钥（素数确定性生成，输出可复现）
> from sympy import nextprime
> from Crypto.PublicKey import RSA
> from Crypto.Signature import pss
> from Crypto.Hash import SHA256
>
> def _key(salt):
>     p = nextprime(2**511 + salt)
>     q = nextprime(2**511 + salt * 2 + 1111111)
>     e = 65537
>     n = p * q
>     d = pow(e, -1, (p - 1) * (q - 1))
>     return RSA.construct((n, e, d, p, q))
>
> ALICE_PRIV = _key(11111111)
> BOB_PRIV = _key(22222222)
> ALICE_PUB = RSA.construct((ALICE_PRIV.n, ALICE_PRIV.e))
> BOB_PUB = RSA.construct((BOB_PRIV.n, BOB_PRIV.e))
>
> def sign(priv, data: bytes) -> bytes:
>     return pss.new(priv).sign(SHA256.new(data))
>
> def verify(pub, data: bytes, sig: bytes) -> bool:
>     try:
>         pss.new(pub).verify(SHA256.new(data), sig)
>         return True
>     except (ValueError, TypeError):
>         return False
> ```

两个角色在 1.2 脚本上各改一处——协商行多带一个签名字段，收到后先验签：

mallory 的脚本与 1.2 结构相同，只有一处差异：她也在"签名"，但只能用自己的钥匙签——能签出合法的签名，却签不出 alice 或 bob 的签名：

```python
# auth_mallory.py 的关键改动：用自己的钥匙冒名（能签，但对不上 alice/bob 的公钥）
```

## 2. DH 的参数陷阱

p、g 是公开参数。参数选错时，攻击者不需要任何 oracle，数学直接塌。三个陷阱按出现频率排：p 太小、g 的阶太小、对端公钥不校验。

### 2.1 p 太小：离散对数把私钥直接解出来

DH 安全性的全部来源，是离散对数在 p 这个尺度上的困难性——[[C02-数论进阶与原根#4.2 BSGS：大步小步，空间换时间|C02 4.2]] 给过账：BSGS 的步数按 $\sqrt p$ 走。p 一小，步数跟着小。教学靶用 [[C02-数论进阶与原根|C02]] 用过的 p = 1000003（原根 2），交换本身完全正常，窃听者只看公开值：

```python
# v2_smallp.py —— 小素数 p：交换照常工作，离散对数把私钥直接解出来
import random, time
from sympy import discrete_log
from sympy.ntheory.residue_ntheory import primitive_root

p = 1000003
g = primitive_root(p)
random.seed(2026)
a = random.randrange(2, p - 2)
b = random.randrange(2, p - 2)
A, B = pow(g, a, p), pow(g, b, p)
s = pow(B, a, p)
print("p = %d, g = %d" % (p, g))
print("alice 私钥 a =", a, "  公钥 A = g^a =", A)
print("bob   私钥 b =", b, "  公钥 B = g^b =", B)
print("真实 s =", s)

t0 = time.perf_counter()             # 窃听者：手里只有公开的 p、g、A、B
a_hat = discrete_log(p, A, g)
b_hat = discrete_log(p, B, g)
dt = time.perf_counter() - t0
s_hat = pow(B, a_hat, p)
print("窃听者解出 a' =", a_hat, " b' =", b_hat, "  耗时 %.3f s" % dt)
print("窃听者算 s' = B^a' =", s_hat, "  等于真实 s:", s_hat == s)
```

### 2.2 g 不是原根：子群把密钥空间压小

g 的阶决定公钥空间的规模。$\text{ord}(g) = m$ 时，$A = g^a$ 只能取 $\langle g \rangle$ 里的 m 个值，私钥只有 $a \bmod m$ 生效，共享 s 同样只有 m 个可能值——m 一小，枚举就行。教学靶还在 p = 1000003 上：p−1 = 2 × 3 × 166667，取 $g_{\text{bad}} = 2^{(p-1)/6}$，它的阶恰好是 6：

```python
# v3_smallg.py —— g 不是原根：小阶生成元把公钥空间压成 6 个值
import random
from sympy import factorint

p = 1000003
g2 = 2                               # mod p 的原根（C02 3.3）
g_bad = pow(g2, (p - 1) // 6, p)     # 原根的 (p-1)/6 次幂：阶只剩 6
print("p - 1 =", factorint(p - 1))

o, e = 1, g_bad % p
while e != 1:                        # 数出 g_bad 的阶
    e = e * g_bad % p
    o += 1
print("g_bad = 2^((p-1)/6) mod p =", g_bad, " 阶 =", o)

vals, e = [], 1
for _ in range(o):
    vals.append(e)
    e = e * g_bad % p
print("g_bad 的全部幂（公钥的全体可能值）:", vals)

random.seed(2034)
a = random.randrange(2, p - 2)       # alice 以为自己的私钥空间是 [2, p-2]
A = pow(g_bad, a, p)
b = random.randrange(2, p - 2)
B = pow(g_bad, b, p)
s = pow(B, a, p)
print("alice 私钥 a =", a, "  公钥 A =", A, "  落在 6 个可能值里:", A in vals)

x = next(x for x in range(o) if pow(g_bad, x, p) == A)   # 窃听者：6 次尝试
s_hat = pow(B, x, p)
svals = sorted({pow(B, t, p) for t in range(o)})
print("窃听者枚举 x =", x, "（恰为 a mod 6 =", a % 6, "）")
print("共享 s 的可能取值至多 6 个，去重后", len(svals), "个:", svals)
print("窃听者算 s' = B^x =", s_hat, "  等于真实 s:", s_hat == s)
```

### 2.3 小子群探测：不校验对端公钥的代价

1.3 的认证回答"对端是谁"；这一节是另一类检查——==对端发来的那个数，落没落进约定的群==。安全素数 p 下小阶元素只有 1 和 p−1，识别容易；一旦 p−1 带一串小因子（历史遗留的参数组、CTF 的自造参数、"参数由对端发来"的自定义协议），阶为 k 的小阶元素就成批出现。

攻击形态与 [[C11-椭圆曲线与ECDLP#5.2 最小服务靶与完整攻击|C11 5.2]] 的无效曲线攻击同构，这里是 mod p 版。设服务的私钥是 d，收到对端"公钥" X 后直接算 $s = X^d \bmod p$，不校验 X。攻击者送 $k$ 阶元素：

$$h_k = g^{(p-1)/k}, \qquad \text{ord}(h_k) = k \tag{2.1}$$

服务算出的 $s = h_k^d$ 只能取 k 个值（$d \bmod k$ 的函数）。协议里服务通常再用 s 派生密钥、加密一段固定确认串发回对端（真实协议里的 Finished 消息就承担这个角色）——这串密文对攻击者就是 oracle：枚举 k 个候选 $s_t = h_k^t$，哪个候选派生的密钥能解开确认串，就得到 $d \equiv t \pmod k$。换多个 k，CRT（[[09-密码学基础#2.4 中国剩余定理|09 章 2.4]]）拼回 d。

靶的服务监听 7704，收到 `X <num>` 后回一行 `OK <base64(AES(s, "KEYCONF-OK!"))>`：

```python
# v5_sub_server.py —— 小子群靶：收到对端"公钥"不做任何校验，直接算共享秘密并回加密的确认串
import json, socket, hashlib, base64
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad

prm = json.load(open("sub_params.json"))
p, d, B = prm["p"], prm["d"], prm["B"]

srv = socket.socket()
srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
srv.bind(("127.0.0.1", 7704)); srv.listen(8)
print("[靶] 监听 127.0.0.1:7704", flush=True)
while True:
    conn, _ = srv.accept()
    fr = conn.makefile("rb")
    conn.sendall(("PUB %d\n" % B).encode())
    line = fr.readline()
    if not line:
        conn.close(); continue
    X = int(line.split()[1])
    s = pow(X, d, p)                     # X 的阶没人查：s 可能落进小阶子群
    k = hashlib.sha256(str(s).encode()).digest()[:16]
    ct = AES.new(k, AES.MODE_ECB).encrypt(pad(b"KEYCONF-OK!", 16))
    conn.sendall(("OK %s\n" % base64.b64encode(ct).decode()).encode())
    print("[靶] 收 X=%d... -> 回确认密文" % X, flush=True)
    conn.close()
```

```python
# v5_sub_attack.py —— 小子群探测：送小阶元素，用确认密文当 oracle 提 d mod k，CRT 拼回 d
import json, socket, hashlib, base64
from Crypto.Cipher import AES
from Crypto.Util.Padding import unpad

prm = json.load(open("sub_params.json"))
p, g, B = prm["p"], prm["g"], prm["B"]
hs = {int(k): v for k, v in prm["hs"].items()}

def ask(X):
    sock = socket.create_connection(("127.0.0.1", 7704))
    fr = sock.makefile("rb")
    fr.readline()                                    # PUB <B>
    sock.sendall(("X %d\n" % X).encode())
    tag, b64 = fr.readline().split()
    sock.close()
    return base64.b64decode(b64)

def key_ok(ct, s):                                   # 试探：s 的候选能否解开确认密文
    k = hashlib.sha256(str(s).encode()).digest()[:16]
    try:
        return unpad(AES.new(k, AES.MODE_ECB).decrypt(ct), 16) == b"KEYCONF-OK!"
    except ValueError:
        return False

res, mods = [], []
for k, h in sorted(hs.items()):
    ct = ask(h)                                      # 服务算 s = h^d 并加密确认串
    t_hit = next(t for t in range(k) if key_ok(ct, pow(h, t, p)))
    print("k=%-3d: d ≡ %2d (mod %d)" % (k, t_hit, k))
    res.append(t_hit); mods.append(k)

def crt(remainders, moduli):                         # 09 章 2.4 的最小 CRT
    N = 1
    for m in moduli:
        N *= m
    x = 0
    for r, m in zip(remainders, moduli):
        Ni = N // m
        x += r * Ni * pow(Ni, -1, m)
    return x % N

d_hat = crt(res, mods)
print("CRT 拼出 d =", d_hat)
print("验算 g^d_hat == 服务公钥 B:", pow(g, d_hat, p) == B)
```

### 2.4 公共素数与 Logjam

90 年代美国出口管制给加密产品设了上限：对称密钥 40 位、DH 参数 512 位，由此出现一批"出口级"（export-grade）套件。管制早已取消，这些套件在代码里活到了 2010 年代。Logjam（2015）把这笔旧账算了两道：对 512 位出口 DH 组，改进的离散对数算法当场解出私钥，实时攻击现场连接；更重的一击打向公共素数——当年大量服务器共用少数几个标准的 1024 位 DH 素数，攻击者对其中一个做一次以月计的预计算，之后解该组上的每个连接只要分钟级，预计算成本被所有用户摊薄。修复随之落地：出口套件全部移除、参数升到 2048 位以上、RFC 7919 把"用哪个素数组"变成协商里点名并可认证的字段——[[#1.3 修复：给协商参数签名|1.3]] 的参数认证与 [[#2.1 p 太小：离散对数把私钥直接解出来|2.1]] 的参数底线在这里汇合。

> [!info]- 为什么"公共参数"仍然安全：预计算的账
> 预计算攻击打的不是"参数公开"，是"参数共享且偏弱"。[[C02-数论进阶与原根#4.2 BSGS：大步小步，空间换时间|C02 4.2]] 的账在这里原样生效：$p$ 上升 1 位，$\sqrt p$ 乘 $\sqrt 2$；2048 位的 $\sqrt p \approx 2^{1024}$，任何预计算都到不了。标准组（RFC 7919 的 ffdhe2048 等）公开、固定、被亿万服务共用，只要参数够强，"共享"反而是优点——省去生成与协商的自造风险。弱的共享参数（512 位出口组、过时的 1024 位组）才是靶子。

## 3. TLS：把算法组合成协议

### 3.1 握手骨架

TLS 做的事是"先非对称、后对称"，握手分四个阶段：

1. **认证**：服务器出示证书，客户端沿证书链验证到本地信任锚——[[#1.2 中间人：交换本身没有身份|1.2]] 的身份问题在这一步解决；
2. **密钥交换**：(EC)DHE 或 RSA，商定只有双方知道的共享秘密——[[#1.1 流程与手写实现|1.1]] 的 DH 加上认证；
3. **派生**：KDF 把共享秘密与双方随机数、整份握手抄本一起派生会话密钥组；
4. **对称加密**：应用数据全部走会话密钥的认证加密。

==非对称算法只出现在认证与密钥交换，数据加密全是对称==——[[09-密码学基础|09 章]]讲过的对称/非对称分工，在工程上的落点就是这四步。TLS 1.3 相对 1.2 的主要改动：证书之后的握手消息全部加密（[[#3.3 本地靶：openssl 观察一次握手|3.3]] 的消息序列里能看到）、握手轮次减一、RSA 密钥交换被移除（下一节讲为什么）。

### 3.2 RSA 密钥交换与 (EC)DHE：前向保密

两种密钥交换的本质差别在"会话密钥依赖哪些秘密"：

- **RSA 密钥交换**：客户端生成一段 premaster secret，用服务器**证书里的 RSA 公钥**加密发过去，会话密钥由它派生。premaster 就躺在记录下来的流量里——==拿到服务器私钥的人，能解开全部历史流量==。这叫没有前向保密（forward secrecy）。
- **(EC)DHE**：双方各出一份当次会话的临时参数（临时私钥用完即弃），会话密钥由本次 DH 共享秘密派生。事后服务器私钥泄漏，攻击者也只能解出"私钥泄漏之后的、用私钥认证的新会话"，历史流量仍然安全——前向保密。

差别在握手上可直接观察：ECDHE 握手里有一条 **ServerKeyExchange**（服务器的临时 DH 参数，用证书私钥签名——[[#1.3 修复：给协商参数签名|1.3]] 的"参数签名"在这里落地），ClientKeyExchange 只装客户端的临时参数，几十字节；RSA 密钥交换没有 ServerKeyExchange，ClientKeyExchange 装的是 RSA 加密的 premaster，随模数走（2048 位就是 256 字节）。[[#3.3 本地靶：openssl 观察一次握手|3.3]] 的两条 trace 并排看。

### 3.3 本地靶：openssl 观察一次握手

先造一张自签证书（`-nodes` 不给私钥加密，`-subj` 免交互），再起一个只讲 TLS 1.2、只留 ECDHE 套件的服务器，用 `s_client -msg` 打一次握手。`-msg` 打印记录层与握手层的消息类型和长度，正对 [[#3.2 RSA 密钥交换与 (EC)DHE：前向保密|3.2]] 的观察点：

```bash
openssl req -x509 -newkey rsa:2048 -nodes -keyout key.pem -out cert.pem -days 1 -subj /CN=localhost
openssl s_server -www -accept 7710 -cert cert.pem -key key.pem -tls1_2 -cipher ECDHE-RSA-AES256-GCM-SHA384 &
sleep 1
echo | openssl s_client -connect 127.0.0.1:7710 -tls1_2 -cipher ECDHE-RSA-AES256-GCM-SHA384 -msg \
      | grep -E 'Handshake|ChangeCipherSpec|Cipher is|Temp Key'
```

输出：

```
<<< TLS 1.2, Handshake [length 012c], ServerKeyExchange
<<< TLS 1.2, Handshake [length 0004], ServerHelloDone

>>> TLS 1.2, ChangeCipherSpec [length 0001]

<<< TLS 1.2, Handshake [length 0010], Finished
```

对照 [[#3.1 握手骨架|3.1]] 的四阶段读：Certificate 是认证阶段（自签证书，链只有一层）；ServerKeyExchange 是密钥交换阶段，服务器给出临时 X25519 参数并用证书私钥签名（`Peer Temp Key: X25519, 253 bits` 是这次会话的临时曲线点）；ClientKeyExchange 0x25 = 37 字节，只装客户端的 32 字节临时点；之后 ChangeCipherSpec 与 Finished 切换进对称加密，NewSessionTicket 是会话恢复的凭证（[[#5. 会话恢复与 0-RTT|第 5 节]]）。

## 4. TLS 大案概览：五个样本与一张表

TLS 二十多年的大案，按"坏在哪一层"排成一条线：实现层、填充处理层、参数层、新旧并存层、协商层。每个案子一段史实、一句话原理、一条修复。

**Heartbleed（2014）**。TLS 心跳（heartbeat）扩展允许一端发"带 n 字节数据的心跳请求、对端原样回显"，请求里的长度字段由发送方自报。OpenSSL 的实现按自报长度拷贝响应，没有与实际收到的报文长度核对——攻击者自报 64 KB、实发 1 字节，就能读出进程内存里至多 64 KB 的越界数据，反复请求可以刮到别的会话数据乃至私钥。修复是边界检查；这个扩展此后被大多数实现移除。实现层的洞与 [[C15-实现漏洞与侧信道|C15]] 的主题同层。

**ROBOT（2017）**。Bleichenbacher 1998 年对 PKCS#1 v1.5 的 padding oracle（[[C09-RSA攻击III|C09]] 第 5 节的完整利用链）在 TLS 的 RSA 密钥交换里复活：不同实现把"填充错误"与其他解密错误用不同的 alert、时序甚至断连行为区分出来，攻击者据此对记录的 premaster 密文逐位夹逼，解出会话。修复两条：解密失败统一报错、恒定时间；TLS 1.3 直接移除 RSA 密钥交换（[[#3.2 RSA 密钥交换与 (EC)DHE：前向保密|3.2]]）。

**Logjam（2015）**。[[#2.4 公共素数与 Logjam|2.4]] 已完整讲过：出口级 512 位 DH 组当场可破，公共 1024 位素数可预计算。修复：出口套件移除、参数升级、RFC 7919 标准组协商。

**DROWN（2016）**。同一张证书既服务 TLS 又挂在还在讲 SSLv2 的老服务上时，攻击者把 TLS 握手里的 RSA 密文转译成 SSLv2 的探测包——SSLv2 的弱填充让 Bleichenbacher oracle 的效率高出许多，数万次探测即可解出 TLS 会话的 premaster。根因是新旧协议并存加上跨协议复用密钥。修复：彻底关闭 SSLv2、证书密钥不复用于废弃协议。

**降级族（FREAK、POODLE 与 SCSV 时代）**。中间人改写 ClientHello 里的套件列表（或版本号），让双方"自愿"协商出最弱的套件——FREAK 把 RSA 密钥交换压到出口级的 512 位密钥，POODLE 逼出 CBC 的 padding 弱点。根因一条：协商结果本身没有被认证，参数又是 1.2 里那种"裸数字"。过渡期补救是 `TLS_FALLBACK_SCSV` 标记（告诉服务器"这是一次降级重试，别再降"）；TLS 1.3 用 [[#3.3 本地靶：openssl 观察一次握手|3.3]] 看到的 CertificateVerify 根治——==整份握手抄本被签名，改过的参数验签必失败==。

| 环节 | 大案（年份） | 一句话原理 | 根因 | 修复 |
| ---- | ---- | ---- | ---- | ---- |
| 心跳实现 | Heartbleed（2014） | 按请求自报的长度拷贝响应，越界读至多 64 KB 内存 | 长度字段未与实际报文核对 | 边界检查；扩展被移除 |
| RSA 密钥交换 | Bleichenbacher（1998）/ROBOT（2017） | 填充错误可区分成 oracle，逐位夹出 premaster | 解密失败的报错可区分（[[C09-RSA攻击III\|C09]] 第 5 节） | 统一报错 + 恒定时间；TLS 1.3 移除 RSA 密钥交换 |
| DH 参数组 | Logjam（2015） | 出口组当场破，公共组预计算一次全体遭殃 | 参数弱且大量服务器共享 | 参数 2048 位起；RFC 7919 标准组协商 |
| 新旧并存 | DROWN（2016） | 把 TLS 握手转译成 SSLv2 的填充 oracle 解出会话 | SSLv2 未关 + 证书跨协议复用 | 关闭 SSLv2，密钥不复用 |
| 版本/套件协商 | FREAK、POODLE 等降级族 | 中间人改协商消息，逼双方选弱套件 | 协商参数未被整体签名 | TLS 1.3 对握手抄本签名（CertificateVerify） |

五个案子收成一句话：==每个协议层都要为"上一层的假设被打破"负责==——心跳假设长度字段可信、RSA 假设填充错误不可区分、DH 假设参数够强、运维假设旧协议已关、协商假设消息没被改。假设逐条列出来，就是第 6 节自查清单的骨架。

## 5. 会话恢复与 0-RTT

完整握手每次都要跑非对称运算，代价不小，TLS 用**会话恢复**省掉它：握手结束时服务器把会话状态（含主密钥）加密成 **session ticket** 发给客户端保存，下次连接客户端原样带回，双方凭它直接恢复会话密钥（[[#3.3 本地靶：openssl 观察一次握手|3.3]] 两条 1.2 trace 里的 NewSessionTicket 就是它）。代价是密钥管理面变大：==ticket 加密密钥泄漏，凭它恢复的会话一并失守，伪造 ticket 还能冒充服务器发凭证==——服务器必须定期轮换 ticket 密钥，轮换过急又会打碎客户端手里的有效 ticket，是个需要权衡的旋钮。TLS 1.3 的 **0-RTT** 更进一步：恢复会话时客户端的第一个飞行（flight）里就直接携带应用数据。代价是这些数据不做防重放保护——攻击者录一份 0-RTT 请求原样重发，服务器可能当成新请求收下，所以标准只允许幂等请求走 0-RTT，敏感操作必须等完整握手完成。

## 6. CTF 里的协议题形态

协议层题在 Crypto 方向的典型形态：给一份"自定义安全协议"的脚本（握手 + 加密的 `enc.py`，交互服务在远端），流程长得像本章的靶子，要求找出逻辑洞。逐项按这张清单过：

| 检查项 | 问什么 | 典型漏洞形态 |
| ---- | ---- | ---- |
| 认证覆盖 | 哪些字段被签名/MAC 覆盖？p、g、序号在内吗？ | 签了 A 没签 g：参数被换成弱参数或小阶元素（[[#2.3 小子群探测：不校验对端公钥的代价\|2.3]]） |
| 身份绑定 | 验签用的公钥从哪来？会被对端替换吗？ | 公钥从网络收 → mallory 自签自验，中间人复活（[[#1.3 修复：给协商参数签名\|1.3]]） |
| 对端公钥校验 | 收到的群元素验不验"落在正确的群"？ | 小阶元素探测、CRT 拼私钥（[[#2.3 小子群探测：不校验对端公钥的代价\|2.3]]） |
| nonce/计数器 | 随机数与序号会重用吗？来源可预测吗？ | 重用即 [[C03-序列密码与LFSR\|C03]] 的密钥重用同构；可预测种子见 [[C04-随机数攻防\|C04]] |
| 降级位 | 版本、套件字段被认证覆盖吗？ | 改字段逼双方选弱算法（[[#4. TLS 大案概览：五个样本与一张表\|第 4 节]] 降级族） |
| 重放窗口 | 挑战值、时间戳、序号的时效怎么判？ | 无窗口 → 抓包原样重放（[[#5. 会话恢复与 0-RTT\|第 5 节]] 0-RTT 的教训） |

两个可自造的最小靶，把"协议洞"与前面各章的武器接起来：

1. **无认证 DH + CBC**：把 [[#1.2 中间人：交换本身没有身份|1.2]] 靶的会话加密换成 CBC，消息里带可改字段（如 `role=user`）。两层洞叠加：先按 1.2 打穿 MITM 拿到会话密钥，再按 [[C06-分组模式攻击全集|C06]] 的字节翻转改密文里的 role 字段——练"密钥协商的洞"与"消息完整性的洞"各开各的，合起来才是完整的攻击面。
2. **签名不覆盖参数**：把 [[#1.3 修复：给协商参数签名|1.3]] 的签名内容从 `A` 缩到只剩 A、把 p 与 g 留在签名外，再把协议参数换成 [[#2.3 小子群探测：不校验对端公钥的代价|2.3]] 那种 p−1 带小因子的组——签名验签全部通过，私钥照样被 CRT 拼出来。"签名存在"与"签名覆盖足够"是两件事。

> [!note] 与平台题的衔接
> CryptoHack（见 [[01-练习平台索引|练习平台索引]]）的 RSA 分类里有以 padding oracle 为背景的题目，与 [[#4. TLS 大案概览：五个样本与一张表|第 4 节]]的 ROBOT 同根；"自定义协议找逻辑洞"一类的题在各赛事的 Crypto/Web 交叉区常见——动笔之前先按清单过一遍，答案通常就在清单命中的那一行。

| 小子群靶 CRT 拼出的 d 验算不过 | d 不小于各模数之积时 CRT 解不唯一：参数生成时把 d 压在小素数之积 S 以内（[[#2.3 小子群探测：不校验对端公钥的代价\|2.3]] 折叠框的 gen 脚本） |
| 小子群靶每个 k 都探出 d ≡ 0 | 送的 X 是 1 或 p−1（阶 1、2 的平凡元素），只反映 d 的平凡信息：用 $h_k = g^{(p-1)/k}$ 造真正的 k 阶元素（[[#2.3 小子群探测：不校验对端公钥的代价\|2.3]]） |

| s_client 报 no cipher match / handshake failure | 两侧 `-cipher` 列表交集为空，或在 TLS 1.3 模式指定了 RSA 密钥交换套件——RSA kx 套件只在 TLS 1.2 生效，补 `-tls1_2`（[[#3.3 本地靶：openssl 观察一次握手\|3.3]]） |

| sympy 的 discrete_log 在"正常参数"上长时间不返回 | $\sqrt p$ 步对 2048 位不可行，运行时长本身就是复杂度的体现；秒破只对 [[#2.1 p 太小：离散对数把私钥直接解出来\|2.1]] 那种小 p 成立（[[C02-数论进阶与原根#4.2 BSGS：大步小步，空间换时间\|C02 4.2]]） |

## 8. 配套练习与延伸阅读

> [!note] 实战任务
> 1. **审一条真实握手**：用 [[#3.3 本地靶：openssl 观察一次握手\|3.3]] 的方法对任一你有权测试的 HTTPS 服务（自建站、实验靶机）跑 `-msg`，记录协议版本、协商套件、ServerKeyExchange 的有无，按 [[#3.2 RSA 密钥交换与 (EC)DHE：前向保密\|3.2]] 判断它是否带前向保密，并读出套件名四段。
> 2. **oracle 题回访**：CryptoHack（见 [[01-练习平台索引\|练习平台索引]]）RSA 分类里 padding oracle 背景的题目打完之后，回看 [[C09-RSA攻击III\|C09]] 第 5 节的利用链与 [[#4. TLS 大案概览：五个样本与一张表\|第 4 节]] ROBOT 一行，确认"实现多说了一句话"这一根因在两边一致。
> 3. **清单实战**：拿 [[#6. CTF 里的协议题形态\|第 6 节]]的清单去审一道"自定义协议"型 CTF 题（各赛事 Crypto/Web 交叉区常见），逐行记录"命中/不命中"，把命中的那一行对应的本章小节重读一遍。

配套练习：

1. 把 [[#1.2 中间人：交换本身没有身份|1.2]] 靶的会话加密换成 CBC，消息里加 `role=user` 字段：先按 1.2 打通 MITM 拿到会话密钥，再按 [[C06-分组模式攻击全集|C06]] 的 CBC 字节翻转把 role 改成 admin，体会"密钥协商"与"消息完整性"两层洞的组合。
2. 给 [[#1.3 修复：给协商参数签名|1.3]] 的靶做"覆盖面收缩"实验：签名只覆盖 A 不覆盖 p、g，把 `dhparams.py` 换成 [[#2.3 小子群探测：不校验对端公钥的代价|2.3]] 那种 p−1 带小因子的参数组，观察验签全过、私钥仍被 CRT 拼出；再改回全覆盖签名验证拦截生效。
3. 用 [[#2.3 小子群探测：不校验对端公钥的代价|2.3]] 的探测脚本去打 [[#1.1 流程与手写实现|1.1]] 的安全素数靶：确认小阶元素只剩 1 与 p−1、每个至多提供 1 比特（d 的奇偶），再算一算"安全素数下拼出完整 d 要多少次询问"——把 [[#2.4 公共素数与 Logjam|2.4]] 折叠框的结论落成数字。
4. 把 [[#3.3 本地靶：openssl 观察一次握手|3.3]] 做成对照矩阵：同一张证书配三组套件（ECDHE-RSA-AES256-GCM-SHA384 / AES256-GCM-SHA384 / TLS 1.3 默认），记录 ServerKeyExchange 有无与 ClientKeyExchange 长度，解释 0x25 与 0x106 的字节构成（X25519 点 32 字节 + 头部；RSA 块 256 字节 + 头部）。
