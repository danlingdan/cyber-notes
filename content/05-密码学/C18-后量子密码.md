# C18 后量子密码
## Post-Quantum Cryptography

> [!info]- 章节信息
> **所属方向**：密码学 ｜ **难度阶段**：L4 高级期 ｜ **前置要求**：[[09-密码学基础|09 章]] · [[C13-格密码与LLL|C13]] · [[C12-数字签名|C12]]
> **本章目标**：划清量子威胁的真实边界——Shor 解决哪两类问题、Grover 对对称与哈希只做了什么、先存后解为什么把迁移时钟拨到现在；认识格基、哈希基、编码基三大家族与 NIST 首批标准 ML-KEM、ML-DSA、SLH-DSA；从零手写 Lamport 一次性签名并算清"一个密钥只能签一次"的泄露账；看懂 ML-KEM"公钥 = 矩阵 + 噪声"的结构与标准参数的尺寸量级；掌握迁移期的混合密钥交换现状与"换的是公钥体系"这条主线。

[[09-密码学基础|09 章]]把密码学分成对称、哈希、公钥三块。公钥这一块的每一章——[[C07-RSA攻击I|C07]] 起的 RSA 三部曲、[[C11-椭圆曲线与ECDLP|C11]] 的 ECC、[[C12-数字签名|C12]] 的整条签名演进线——全部依赖两类数论问题：大数分解与离散对数。1994 年的 Shor 算法证明，足够大的量子计算机能在多项式时间解这两类问题，公钥体系需要整体更换；1996 年的 Grover 算法只给对称密码与哈希带来平方加速，密钥加倍即可继续使用。后量子密码（Post-Quantum Cryptography, PQC）研究"换什么、怎么换"：第 1 节划清威胁边界，第 2 节过三大家族与首批标准，第 3 节手写最古老也最直白的哈希签名并算清泄露账，第 4 节看 ML-KEM 与 ML-DSA 的结构和尺寸，第 5 节看迁移期的混合模式。[[C13-格密码与LLL|C13]] 与 [[C14-格密码应用|C14]] 的格基础是第 2、4 节的地基。

## 1. 量子计算威胁的真实边界

### 1.1 Shor：公钥体系整体失效

1994 年 Peter Shor 给出量子算法：在一台容错量子计算机上，大数分解与离散对数（含椭圆曲线版本 ECDLP）都能多项式时间解决。经典世界里这两类问题覆盖了全部公钥密码——分解之上是 RSA，离散对数之上是 DH、ElGamal、DSA，ECDLP 之上是 ECDSA 与 Ed25519。==Shor 的攻击范围恰好覆盖现有公钥体系的全部，对称密码与哈希不在其中==：

| 方案 | 依赖的数学问题 | Shor 之后 |
| ---- | ---- | ---- |
| RSA（[[C07-RSA攻击I\|C07]]–[[C09-RSA攻击III\|C09]]） | 大数分解 | 失效 |
| DH、ElGamal、DSA（[[C02-数论进阶与原根\|C02]]） | 模 p 离散对数 | 失效 |
| ECDSA、Ed25519（[[C11-椭圆曲线与ECDLP\|C11]]、[[C12-数字签名\|C12]]） | ECDLP | 失效 |
| AES、SHA-256 等对称与哈希 | 无此类代数结构 | 只受 1.2 的平方加速 |

> [!info]- Shor 在算什么：把分解归约成求周期
> 以分解 $n = p \cdot q$ 为例。随机选 $a < n$，考虑函数 $f(x) = a^x \bmod n$：[[09-密码学基础|09 章]] 2.3 的费马小定理保证 $f$ 是周期函数，存在周期 $r$ 使 $a^r \equiv 1 \pmod n$（$r$ 为偶数时才能继续）。此时 $a^{r/2}$ 的平方等于 1，即它是 $x^2 \equiv 1 \pmod n$ 的根；模两个素数的乘积下这个方程共有 4 个根，除平凡根 $\pm 1$ 外，剩下两个满足"模 p 等于 1、模 q 等于 −1"（或反过来）。$a^{r/2}$ 命中非平凡根的概率约为一半，此时 $\gcd(a^{r/2} - 1,\ n)$ 与 $\gcd(a^{r/2} + 1,\ n)$ 就给出 $p$ 或 $q$（[[09-密码学基础|09 章]] 2.2 的 gcd）；不中就换一个 $a$ 重来。整条归约里唯一的硬步骤是求周期 $r$，量子傅里叶变换多项式时间做这件事。离散对数同构：求 $x$ 使 $g^x \equiv y \pmod p$ 同样归约为周期问题。分解、离散对数、椭圆曲线离散对数最终都归到同一个"求周期"，这就是它们被同一算法一起覆盖的原因。

现状：能跑 Shor 分解 RSA-2048 的容错量子机，工程估算需要百万量级的物理量子比特连续运行数小时以上；公开报道的量子设备分解过的最大 RSA 型合数还停留在几十比特的玩具尺度。但"造不出来"不等于"不用防"——1.3 讲为什么现在就要动。

### 1.2 Grover：对称与哈希只折半

1996 年 Lov Grover 给出无结构搜索的平方加速：$N$ 个候选里找唯一目标，经典需要 $N$ 量级的查询，量子只要 $\sqrt{N}$ 量级。落到密码上是两条：

- 对称密钥穷举：AES-128 从 $2^{128}$ 降到约 $2^{64}$ 次量子操作；
- 哈希原像：SHA-256 从 $2^{256}$ 降到约 $2^{128}$。

也就是==强度减半，不是归零==。对策只要一句话：==长度加倍，强度复原==——AES-256 在量子模型下仍有 $2^{128}$ 强度，SHA-256 的原像仍有 $2^{128}$。[[09-密码学基础|09 章]] 4.2 的哈希家族表在量子视角下一行都不用划掉。

> [!note] $2^{64}$ 是渐进理想值，不是真实造价
> Grover 的加速来自叠加态上的反复迭代：迭代串行，把搜索摊到多台量子机上时间不会线性缩短；电路深度还受硬件相干时间上限约束，常数因子巨大。密码管理文献（如 NIST 的密钥长度建议）对"实际可行的量子加速"估得比理想模型松得多。保守结论不变：对称侧用 256 位密钥、384 位哈希就把这条线封死，真正的迁移压力在公钥。

> [!info]- 哈希碰撞的量子加速与既有弱点无关
> 碰撞查找存在比平方更快的量子算法（BHT，约 $2^{n/3}$），但它需要大容量量子内存，常数大到没有现实意义。MD5 与 SHA-1 本来就被经典碰撞攻破（[[C10-哈希进阶|C10]]），量子不改变它们已失效的结论，也不给 SHA-256 添新伤。

### 1.3 先存后解与 CTF 视角

量子机没有到，威胁已经到。攻击者今天就可以把加密流量原样录下存着，等量子机出现再解——这叫**先存后解**（harvest now, decrypt later）。它改变的不是攻击能否成功，而是==什么时候成功：只要数据需要保密的时间跨度比量子机的问世日期长，今天用 RSA/ECDH 传输就已经在泄漏==。长期档案、医疗记录、生物特征属于这一类。NIST 2016 年启动 PQC 征集、2024 年定稿首批标准、浏览器与 CDN 2024 年起默认混布，紧迫性全部来自"存储便宜、降临日期不确定"，与量子机的发布日程无关。

CTF 视角一句：赛题里的"量子"基本是模拟或玩具——小参数上的周期归约、toy 格密码、手搓哈希签名，考的是原理理解，不需要量子编程；倒是本章 5.1 的标准库支持是现在就能直接上手的环境。

## 2. 三大 PQC 家族

PQC 的选材标准只有一条：==所依赖的数学问题在量子模型下也没有已知多项式算法==。格、哈希、编码三个家族从 2016 年的 NIST 征集走到 2024 年的首批标准，代表三条技术路线。每条路线看四件事：数学对象、安全假设、代表算法、标准化状态。

### 2.1 格基

数学对象是 [[C13-格密码与LLL|C13]] 的高维整数格。安全假设主要两个：

- **LWE**（Learning With Errors，带误差学习）：给定随机矩阵 $A$ 与 $t = A s + e$（$s$ 是小系数秘密向量，$e$ 是小系数噪声向量），从 $(A, t)$ 反推 $s$、或把 $(A,t)$ 与随机对区分开，是难的；
- **SIS**（Short Integer Solution，短整数解）：给定 $A$，找非零短向量 $x$ 使 $A x \equiv 0$，是难的。

[[C14-格密码应用|C14]] 讲这两个假设怎么被做成可用的加密与签名构件。代表算法三个：

- **ML-KEM**（原名 Kyber）：密钥封装机制，NIST FIPS 203；
- **ML-DSA**（原名 Dilithium）：数字签名，NIST FIPS 204；
- **FN-DSA**（原名 Falcon）：数字签名，FIPS 206 规格制定中。

前两者基于 Module-LWE——把 LWE 的系数从普通整数换成多项式环 $\mathbb{Z}_q[X]/(X^{256}+1)$ 上的元素，运算并行度高、参数紧凑，名字里的 ML 即 Module-Lattice。格基的参数余量由攻击能力决定：[[C13-格密码与LLL|C13]] 的 LLL/BKZ 近似质量决定"多少维才安全"，标准参数就是按已知最强攻击加余量倒推出来的。

### 2.2 哈希基

数学对象只有哈希函数与 Merkle 树，安全假设只有"抗原像、抗第二原像"——==不依赖任何数论难题，是三大家族里论证最保守的一支==。发展脉络从一次一签开始：Lamport 签名（1979，下一节手写）→ WOTS 链式改进（仍一次一签）→ Merkle 树把大量一次性公钥聚成一个树根（多次签名，但要记录已用叶子）→ SPHINCS+ 用随机选叶与多层树去掉状态。标准化结果两个：

- **SLH-DSA**（原名 SPHINCS+）：无状态哈希签名，FIPS 205；公钥 32 字节，签名以 7856 字节起步；
- **XMSS、LMS**（RFC 8391 / RFC 8554，NIST SP 800-208）：有状态版本，叶子序号丢失或回退即泄露，只用于固件签名等管得好状态的专用场景。

### 2.3 编码基

数学对象是线性纠错码。一般线性码的译码（syndrome decoding）是 NP 难问题；McEliece 体制（1978 年提出）把一个"能快速译码的好码"（Goppa 码）藏进线性变换后面，公钥看起来像随机码，只有持有者能译码。代表算法 **Classic McEliece**：提出至今近五十年没有出现有效攻击，是所有 PQC 候选里安全资历最深的一个；代价是公钥以二十多万字节计（比 ML-KEM 大两百倍），密文反而只有百字节级。NIST 2025 年 3 月补选的第五个 KEM **HQC** 同样走编码路线（准循环码），标准草案制定中；Classic McEliece 本身不在首批标准之列，标准化工作转向其他标准组织。

### 2.4 家族对照

| 家族 | 数学对象 | 安全假设 | 代表算法 | 标准化状态 |
| ---- | ---- | ---- | ---- | ---- |
| 格基 | 高维整数格 | LWE / SIS（Module-LWE） | ML-KEM、ML-DSA、FN-DSA | FIPS 203 / 204 已定稿；FIPS 206 制定中 |
| 哈希基 | 哈希函数 + Merkle 树 | 哈希抗原像 / 抗第二原像 | SLH-DSA；XMSS / LMS（有状态） | FIPS 205 已定稿；XMSS/LMS 见 RFC 与 SP 800-208 |
| 编码基 | 线性纠错码 | 一般码译码 NP 难 | Classic McEliece、HQC | HQC 2025-03 补选为第五个 KEM；Classic McEliece 未入选 |

> [!info]- 其余家族：两条"入选后被破"的警示
> NIST 征集前后收到过更多家族的候选，两个著名的失败值得记住。
> **多变量**：用"解一般多元二次方程组是 NP 难"当假设。代表 Rainbow 一路走到签名赛道的三强决选（另两家是 Dilithium 与 Falcon），2022 年被 Ward Beullens 用一台笔记本一个周末的计算量恢复私钥，没撑到定稿。
> **同源（isogeny）**：在超奇异椭圆曲线的同源图上找路径。代表 SIKE 是 2017 年征集时的 KEM 候选，2022 年 7 月被 Castryck 与 Decru 的经典攻击打穿——SIKEp434 的私钥在单核上约一小时恢复，后续改进到分钟级。
> 两条的共同点：攻击全部是**经典**攻击，与量子无关；时点都发生在方案进入 NIST 流程**之后**。==入选候选只说明没有被攻破过，不等于安全==——这也是最终标准集中到格、哈希、编码三条论证最充分路线上的原因。

## 3. Lamport 签名：手写一套哈希签名

### 3.1 原理：一位两根串

Lamport 签名（1979）是 2.2 那条演进线的起点。要签的消息先压成 256 位 SHA-256 摘要（[[C12-数字签名|C12]] 1.2 的"签摘要不签原文"），然后：

- **密钥生成**：为摘要的每一位准备一对 32 字节随机串，共 $256 \times 2 = 512$ 根；公钥是这 512 根串各自的 SHA-256 值；
- **签名**：摘要的每一位是 0 或 1，公布该位置被选中的那一根串，共 256 根；
- **验证**：把签名里的每根串哈希一次，与公钥对应位置的值比对，256 个位置全部一致才算通过。

==安全性直接落在哈希函数上==：改签名里的一根串，要找到原像或碰撞；给新消息造签名，需要新摘要的每一位恰好有串可用——3.3 算这笔账。

### 3.2 全流程实现

纯标准库实现，密钥生成用 `os.urandom`（[[C04-随机数攻防|C04]] 的纪律：签名密钥不用可预测的 `random`）：

```python
# lamport.py —— Lamport 签名核心：密钥生成、签发、验证、篡改检测
import hashlib
import os

N = 256                       # 一次签一个 SHA-256 摘要：256 位，一位对应一对随机串

def H(b):
    return hashlib.sha256(b).digest()

def bits(d):
    """256 位摘要 -> 256 个 0/1（高位在前）"""
    return [(byte >> j) & 1 for byte in d for j in range(7, -1, -1)]

# 密钥生成：256 x 2 个 32 字节随机串；公钥是它们各自的哈希
sk = [[os.urandom(32), os.urandom(32)] for _ in range(N)]
pk = [[H(x) for x in pair] for pair in sk]

def sign(msg):
    d = H(msg)
    return d, [sk[i][b] for i, b in enumerate(bits(d))]

def verify(msg, d, sig):
    if H(msg) != d or len(sig) != N:
        return False
    return all(H(s) == pk[i][b] for i, (b, s) in enumerate(zip(bits(d), sig)))

if __name__ == "__main__":
    print("== 密钥生成 ==")
    print("私钥: %d x 2 个 32 字节随机串，共 %d 字节" % (N, N * 2 * 32))
    print("公钥: 同样 %d x 2 个哈希值，共 %d 字节" % (N, N * 2 * 32))

    msg = b"pq-demo message 001"
    d1, sig1 = sign(msg)
    print()
    print("== 签发与验证 ==")
    print("签名尺寸: %d 根 32 字节串 = %d 字节" % (len(sig1), len(sig1) * 32))
    print("验证:", verify(msg, d1, sig1))

    bad = list(sig1)
    bad[100] = bytes(b ^ 1 for b in bad[100])     # 篡改其中一根串的一个位
    print("篡改签名后:", verify(msg, d1, bad))
    print("旧签名配新消息:", verify(b"pq-demo message 002", d1, sig1))
```

```bash
python3 lamport.py
```

输出：

```
== 密钥生成 ==
私钥: 256 x 2 个 32 字节随机串，共 16384 字节
公钥: 同样 256 x 2 个哈希值，共 16384 字节

== 签发与验证 ==
签名尺寸: 256 根 32 字节串 = 8192 字节
验证: True
篡改签名后: False
旧签名配新消息: False
```

三点观察：

- **验证就是哈希比对**：`verify` 没有任何代数运算，256 次 SHA-256 加 256 次字节比较，这就是"安全性归约到哈希"的直白形态；
- **篡改必然现形**：签名里任何一根串变了位，对应位置的哈希就对不上公钥；旧签名换个消息复用，第一行的摘要检查就挡住了；
- **尺寸是代价**：私钥 16384 字节、公钥 16384 字节、签名 8192 字节。对照 [[C12-数字签名|C12]] 6.1 的 Ed25519——公钥 32 字节、签名 64 字节，哈希签名的尺寸差出两个数量级。3.4 讲怎么压，4.4 的表里有正规 PQC 的折中结果。

### 3.3 为什么一个密钥只能签一次

Lamport 的密钥库里，每个位置有 0、1 两根串。签一条消息，每个位置只公布"二选一"里被选中的一根；签第二条消息，两位摘要不同的位置就把两根都公布了。写一个攻击者视角的统计脚本，把泄露随签名条数的账算出来：

```python
# lamport_leak.py —— 重签泄露：暴露串的账，10 条签名后伪造从未签过的消息
from lamport import H, bits, N, sign, verify

def leak_from(sigs):
    """攻击者视角：从收集到的签名里恢复已知串。known[i][b] = 位置 i、位值 b 的串"""
    known = [dict() for _ in range(N)]
    for d, sig in sigs:
        for i, (b, s) in enumerate(zip(bits(d), sig)):
            known[i][b] = s
    return known

msgs = [b"pq-demo message %03d" % i for i in range(1, 11)]
sigs = [sign(m) for m in msgs]                    # 同一把密钥连签 10 条：事故现场

for t in (1, 2, 5, 10):
    known = leak_from(sigs[:t])
    full = sum(1 for i in range(N) if len(known[i]) == 2)    # 0/1 两根都暴露的位置
    forced = N - full                                          # 还缺串的位置
    print("t=%2d 条签名: %3d 个位置两根串全暴露，%3d 个位置仍缺串（伪造须对齐 %d 位）"
          % (t, full, forced, forced))

def forge(prefix, known):
    """磨计数后缀：找一个摘要不缺串的新消息，用已知串拼出它的签名"""
    nonce = 0
    while True:
        m = prefix + b"#" + str(nonce).encode()
        d = H(m)
        bs = bits(d)
        if all(b in known[j] for j, b in enumerate(bs)):
            return m, d, [known[j][b] for j, b in enumerate(bs)]
        nonce += 1

m3, d3, sig3 = forge(b"attacker forged payment 999", leak_from(sigs))
print()
print("伪造目标: %r（从未被持有者签过）" % m3)
print("磨了 %d 次后缀" % int(m3.split(b'#')[1]))
print("用泄露串拼出的伪造签名通过验证:", verify(m3, d3, sig3))
```

python3 lamport_leak.py
```

t= 2 条签名: 135 个位置两根串全暴露，121 个位置仍缺串（伪造须对齐 121 位）
t= 5 条签名: 241 个位置两根串全暴露， 15 个位置仍缺串（伪造须对齐 15 位）
t=10 条签名: 256 个位置两根串全暴露，  0 个位置仍缺串（伪造须对齐 0 位）

伪造目标: b'attacker forged payment 999#0'（从未被持有者签过）
磨了 0 次后缀
用泄露串拼出的伪造签名通过验证: True
```

逐条读账。缺串位置的期望由式 (3.1) 给出：

$$\mathbb{E}[\#\text{缺串位}] \;=\; 256 \cdot 2^{\,1-t} \tag{3.1}$$

- **签 1 条**：每个位置只暴露二选一中的一根。伪造新消息需要新摘要与旧摘要 256 位全部一致——第二原像问题，好哈希下不可行（[[C10-哈希进阶|C10]] 的单向性）。此时方案是安全的；
- **签 2 条**：两条随机摘要平均 128 位不同，==差异位上两根串全部到手==——一半密钥库已经拼出来。但仍有约 128 个位置缺串，伪造需新摘要恰好对齐这些位，期望工作量 $2^{128}$，理论缺口在、实践尚安全；
- **每多签 1 条**：按式 (3.1)，缺串位置数每签一条大约减半。$t = 5$ 剩约 16 位，$t = 9$ 期望已不足 1 位；本例 10 条后 256 个位置全部暴露；
- **之后伪造**：不再需要碰运气。攻击者给目标消息加计数后缀，磨到某个摘要恰好不缺串为止（本例第一次尝试就命中），==用已知串拼出一条从未签过的消息的合法签名==——私钥在事实上已全部泄露。

> [!warning] 重签不是"风险变大"，是确定性泄露
> 式 (3.1) 是指数递减：同一把 Lamport 密钥每多签一条，安全余量按指数收缩，不存在"多签几条应该没事"。发现重用，按式 (3.1) 估缺串位数——几十位以内就当下失守处理。这也解释了 3.4 为什么把"叶子序号只许前进"当有状态哈希签名的要害：序号回退就是重签。

CTF 形态：手搓 Lamport / WOTS 类题目的考点就是本节的位泄露——数清楚每个位置的暴露情况，伪造须对齐的位数在几十以内时，磨消息后缀即可直接伪造。

### 3.4 从一次到多次：WOTS 与 Merkle 树

Lamport 有两张尺寸账要还：签名 8192 字节、一次一签。两条经典改进各还一张。

**WOTS：用计算换尺寸**。把"一位两根串"换成"一条哈希链签多位"：私钥是随机串 $X$，对它连续哈希 $2^w - 1$ 次，链尾公布为公钥。签一个 $w$ 位的块：设块值为 $v$（$0 \le v < 2^w$），签名就是 $X$ 连续哈希 $v$ 次的中间值；验证者从收到的值继续哈希 $2^w - 1 - v$ 次，应到达公钥链尾。$w = 4$ 时每条链签 4 位，签 256 位摘要只需 64 条链、签名 64 根串（2048 字节，Lamport 的四分之一），代价是签发与验证各多做一串哈希。安全论证仍然只有哈希，仍然一次一签。

**Merkle 树：用路径换次数**。造 $2^{20}$ 个一次性密钥对（WOTS 或 Lamport），把它们的一次性公钥当叶子，两两哈希聚成一棵二叉树，==只公布 32 字节的树根当真公钥==。第 $i$ 次签名用第 $i$ 个叶子的一次性密钥，并附上从叶子到根的一条认证路径——20 个中间哈希；验证者用路径现场重算出树根比对，对得上即证明"这个叶子公钥属于这棵树"。密钥容量一百万次，公钥从 16 MB 压到 32 字节，代价是签名多出约 640 字节的路径。XMSS 与 LMS 就是"Merkle 树 + WOTS"的标准化版本。

> [!warning] 树聚出来的次数是有状态的
> 第 $i$ 个叶子只能用一次（3.3 的账），所以签名器必须持久记录"下一个可用叶子序号"，且只许前进。服务器回滚、快照恢复、多进程并发签名，都会让同一叶子签两次——泄露照式 (3.1) 结算。管不好状态的系统直接用无状态的 SLH-DSA（随机选叶 + 多层树，签名 7856 字节起步）或换 ML-DSA。

哈希签名家族演进到 SLH-DSA 完成无状态化：只依赖哈希，代价是签名尺寸回到 8 KB 量级——与 4.4 的 ML-DSA 对比后会发现，"假设更保守"与"签名更大"是同一次交换的两端。

## 4. Kyber 与 Dilithium 结构速览

本节是概念加 toy 直觉，不展开安全证明；所有标准参数按 FIPS 原值引用。

### 4.1 LWE：公钥 = 矩阵 + 噪声

**LWE 问题**：公开随机矩阵 $A$（$n \times n$，系数在模 $q$ 的整数环上）；秘密 $s$ 与噪声 $e$ 都是小系数向量；公布

$$t = A s + e \pmod q \tag{4.1}$$

对知道 $s$ 的人，$(A, t)$ 是 $n$ 条带小噪声的线性方程；对不知道的人，$(A, t)$ 与随机矩阵对不可区分。反推 $s$ 等价于在 $n$ 维格上找短向量——[[C13-格密码与LLL|C13]] 的约减算法在高维格上只剩近似能力，[[C14-格密码应用|C14]] 把这个假设做成体制的过程就是在此之上加工程化。"小"是整个体制的前提：噪声让方程失真，小系数让真解成为格上的孤立短向量。

跑一个 $n = 8$、$q = 97$ 的 toy，流程与 ML-KEM 同型（1 位消息的封装 / 解封装）：

```python
# kyber_toy.py —— LWE toy 加解密：ML-KEM "公钥 = 矩阵 + 噪声" 的最小可跑直觉
import random

n, q = 8, 97            # toy 尺度；ML-KEM 用多项式环 Z_3329[X]/(X^256+1) 上的同型结构
rng = random.Random(2026)

def small(scale=2):
    """小系数：toy 里取均匀 [-scale, scale]；真实方案取中心二项分布"""
    return rng.randint(-scale, scale)

# 密钥生成：公开随机矩阵 A；私钥 s（小向量）；公钥 t = A·s + e（带噪声）
A = [[rng.randint(0, q - 1) for _ in range(n)] for _ in range(n)]
s = [small() for _ in range(n)]
e = [small() for _ in range(n)]
t = [sum(A[i][j] * s[j] for j in range(n)) + e[i] for i in range(n)]
print("== 密钥生成 ==")
print("私钥 s =", s)
print("公钥噪声项 e =", e)
print("公钥 t = A·s + e mod %d =" % q, t)

def encap(m, scale=2):
    """封装：随机小向量 r 与噪声 e1、e2；1 位消息编码成 q/2 的倍数"""
    r  = [small(scale) for _ in range(n)]
    e1 = [small(scale) for _ in range(n)]
    e2 = small(scale)
    u = [sum(A[j][i] * r[j] for j in range(n)) + e1[i] for i in range(n)]   # u = A^T·r + e1
    v = (sum(t[i] * r[i] for i in range(n)) + e2 + m * (q // 2)) % q        # v = t·r + e2 + mu
    return u, v

def decap(u, v):
    """解封装：v - s·u = mu + 组合噪声；居中后按 q/4 门槛判 0/1"""
    val = (v - sum(s[i] * u[i] for i in range(n))) % q
    val = (val + q // 2) % q - q // 2            # 居中到 (-q/2, q/2]
    m = 0 if abs(val) < q // 4 else 1
    noise = min(abs(val), abs(abs(val) - q // 2))  # 判位依据值离 0 / ±q/2 中心的距离 = 组合噪声
    return m, val, noise

print()
print("== 封装 / 解封装（翻转门槛 q/4 = %.1f）==" % (q / 4))
for m in (0, 1):
    u, v = encap(m)
    m2, val, noise = decap(u, v)
    print("封装 m=%d -> 解封装 %d（组合噪声 %d）" % (m, m2, noise))

print()
print("== 噪声超预算：封装端小系数放大到 [-30, 30]，连试 8 次 ==")
err = 0
for trial in range(8):
    u, v = encap(1, scale=30)
    m2, val, noise = decap(u, v)
    err += (m2 != 1)
    print("  第 %d 次: 解封装 %d（组合噪声 %d）" % (trial + 1, m2, noise))
print("8 次里解封装出错 %d 次" % err)
```

```bash
python3 kyber_toy.py
```

```

私钥 s = [2, 1, -2, 1, 2, 2, 1, 1]
公钥噪声项 e = [2, 0, 1, 2, 1, 2, 2, -2]
公钥 t = A·s + e mod 97 = [303, 680, 373, 530, 522, 388, 432, 447]

== 封装 / 解封装（翻转门槛 q/4 = 24.2）==
封装 m=0 -> 解封装 0（组合噪声 0）
封装 m=1 -> 解封装 1（组合噪声 20）

  第 1 次: 解封装 0（组合噪声 20）

```

三段读法：

- **解封装为什么能还原**：把 $u$ 代入消元，

$$v - s^{\mathsf T} u \;=\; m \cdot \frac{q}{2} \;+\; \underbrace{e_2 + r^{\mathsf T} e - s^{\mathsf T} e_1}_{\text{组合噪声}} \pmod q \tag{4.2}$$

组合噪声三项全是"小 × 小"的和：toy 参数下它只有十几以内（输出里两次分别是 0 与 20），没碰到 $q/4 = 24.25$ 的翻转门槛，判位依据值贴近 0 或 $\pm q/2$，按最近值判 0/1 即还原明文；
- **噪声超预算就出错**：小系数放大 15 倍后组合噪声绕满整个模空间，落在哪算哪，越过 $q/4$ 门槛的次数就是出错的次数，8 次错 3 次——==噪声越过预算，解密结果就随机出错==；
- **参数是算出来的**：公钥里的 $e$ 是对外可见的误差项，想从 $t = As + e$ 反推 $s$ 就要去解"格里找短向量"。把 $e$ 调小或把 $q$ 调大都会同时改变这道题的难度与正确性——==标准里的 $q$、维度、噪声分布是噪声预算的解，不是风格选择==。

> [!info]- 从 toy 到 ML-KEM 的四处工程化
> ML-KEM-768 与上面的 toy 同构，差别在四处。一，**环结构**：系数不是普通整数，而是多项式环 $\mathbb{Z}_{3329}[X]/(X^{256}+1)$ 的元素，一次"乘法"并行处理 256 个系数；Module-LWE 的 Module 指把若干个这种多项式摞成向量。二，**噪声分布**：小系数取中心二项分布 $\eta = 2$，不是均匀区间。三，**压缩**：公钥与密文的系数截低位存储，1184 与 1088 字节的密文尺寸是压出来的，截断误差算进噪声预算。四，**FO 变换**：把"窃听者选密文"安全升级为"篡改者改密文也拿不到信息"——解封装先按收到的密文重算一遍加密过程核对，对不上时**不报错**，返回一个由密文决定的伪随机密钥（隐式拒绝），让篡改者分不清对错。CTF 里的 Kyber / NTRU 类题目常把第四处拆掉只留裸加密内核，攻击面集中在噪声预算与解密失败上。

### 4.2 ML-KEM 的封装与解封装

KEM（Key Encapsulation Mechanism，密钥封装机制）与加密的差别：封装的"明文"不是自选消息，而是算法自己采样的随机密钥——TLS 这类协议只需要一把共享会话密钥，KEM 正对着这个需求（协议层的落地在 [[C17-协议密码学|C17]]）。ML-KEM 的三步流程：

- **密钥生成**：种子展开出公共矩阵 $A$（所有人算出同一个 $A$，公钥里只存种子）；采样小系数 $s$、$e$，按式 (4.1) 算 $t$。公钥 = $(A, t)$，私钥 = $s$；
- **封装（任何人）**：采样小系数 $r$、$e_1$、$e_2$ 与随机消息 $m$；算 $u = A^{\mathsf T} r + e_1$、$v = t^{\mathsf T} r + e_2 + \mathrm{encode}(m)$；密文 = $(u, v)$，共享密钥 = KDF$(m \,\|\, H(\text{密文}))$；
- **解封装（持有 $s$）**：按式 (4.2) 算 $v - s^{\mathsf T}u$，过 $q/4$ 门槛解出 $m$，同一个 KDF 得到同一把共享密钥。

对照 4.1 的输出：封装端出两条带噪向量，解封装端一次噪声相消——逐行对应，toy 就是 ML-KEM 的骨架。

### 4.3 ML-DSA：Fiat-Shamir with aborts

签名侧的 ML-DSA 用同一套 Module-LWE/SIS 材料，核心技巧一句话：**Fiat–Shamir with aborts**。签名者采样小系数掩饰向量 $y$，算承诺 $w = A y$；挑战 $c$ 由消息与承诺哈希得到（Fiat–Shamir：把交互式证明压成非交互签名）；应答 $z = y + c \cdot s$。问题在于 $z$ 的分布会泄露 $s$ 的信息，于是加一道检查：==$z$ 的范数超过阈值就丢弃整轮、重采 $y$ 再来==——这就是 aborts；只有范数合格的 $z$ 才发布，每条签名的泄露量被压进安全证明算得清的预算。验证方检查 $A z - c\,t$ 与挑战承诺一致、范数合格。

对照 [[C12-数字签名|C12]]：ECDSA 的 nonce 泄几个比特就丢私钥（该章 4.4 的 HNP 格攻击），ML-DSA 每条签名同样带随机性，但"范数检查 + 弃权重试"让泄露有账可算；实现层的侧信道要求（常数时间、防功耗分析）则在 [[C15-实现漏洞与侧信道|C15]] 的框架下照旧成立。

| 方案 | 公钥 | 私钥 | 密文 / 签名 | 规格 |
| ---- | ---- | ---- | ---- | ---- |
| RSA-2048 | 256 B | 约 1.2 KB（DER） | 签名 256 B | PKCS#1（RFC 8017） |
| X25519 | 32 B | 32 B | 共享密钥 32 B | RFC 7748 |
| Ed25519 | 32 B | 32 B | 签名 64 B | RFC 8032 |

名字对照：ML-KEM-768 即原 Kyber768，ML-DSA-44 即原 Dilithium2——NIST 定稿时把候选名统一换成了正式名。签名尺寸用 openssl 直接量：

```bash
openssl genpkey -algorithm ML-DSA-44 -out mldsa.pem
printf "msg" > msg.txt
openssl pkeyutl -sign -inkey mldsa.pem -rawin -in msg.txt -out sig44
openssl genpkey -algorithm SLH-DSA-SHA2-128s -out slh.pem
openssl pkeyutl -sign -inkey slh.pem -rawin -in msg.txt -out sigslh
stat -c "%n %s 字节" sig44 sigslh
```

输出：

```
sig44 2420 字节
sigslh 7856 字节
```

三句读法：

- 公钥与签名比 ECC 大 20–40 倍，但停在 KB 量级——不是不可用，是协议字段要为它扩容（TLS 握手包、证书、DNSSEC 的 UDP 尺寸上限都受影响）；
- SLH-DSA 公钥最小（哈希基特性：32 字节树根）、签名最大——==假设更保守与签名更大是同一次交换的两端==；
- ==PQC 迁移的成本主要在带宽与字段长度，不在计算量==：ML-KEM 的封装耗时与 X25519 同一量级，ML-DSA 的签名耗时与 ECDSA 同一量级。

> [!note] 为什么叫混合（hybrid）
> 会话密钥由两路共同导出：量子机提前问世，X25519 那半被 Shor 解开，ML-KEM 那半仍在，会话安全；ML-KEM 日后曝出新弱点（回顾 2.4 的 SIKE），X25519 那半仍然成立。==两侧只要有一侧安全，会话密钥就安全==。反之，只留 ML-KEM 关掉 X25519，会话安全就仅取决于单一新假设，还失去与不支持 PQC 组对端的兼容——混合期的新旧并联，是用一点带宽换两侧互备。

证书链那边是签名算法的更换：服务器身份从 RSA/ECDSA 证书迁到 ML-DSA 证书。握手用混合 KEM 保机密性、证书链用 PQC 签名保认证，两条线各自推进。

### 5.2 要换的是什么

整张迁移清单其实只有两行：

- **对称与哈希：基本不换**。Grover 的平方加速以长度换回：AES-256 继续（量子强度 $2^{128}$），SHA-256 仍可用，更稳妥的组合是 AES-256 + SHA-384；分组结构、工作模式、HMAC 全都不动——[[C05-分组密码内部|C05]]、[[C06-分组模式攻击全集|C06]]、[[C10-哈希进阶|C10]] 的内容原样有效；
- **公钥体系：整条换**。密钥交换与加密：RSA、(EC)DH → ML-KEM 混合组；签名：RSA、ECDSA、Ed25519 → ML-DSA（状态管得好的场景可选 SLH-DSA）；证书链、代码签名、身份认证同步跟进。

==后量子迁移换的是公钥算法，不是整个密码栈==。工程上配套的要求叫算法敏捷性（crypto-agility）：算法名写在配置与协商字段里而不是写死在代码里，为下一次（希望不需要的）迁移留门。

### 5.3 CTF 与工程的时间线

两条时间线分开看：

- **CTF**：PQC 题当前考的是原理还原——手搓 Lamport 的位泄露（3.3）、toy LWE/NTRU 的噪声预算（4.1）、小参数上的格约减（[[C13-格密码与LLL|C13]] 的 fpylll 工具直接适用）。等标准库普及（5.1 的 OpenSSL 3.5 已经就位），题型会向参数误配与实现侧信道（[[C15-实现漏洞与侧信道|C15]]）迁移——那正是传统密码题已经走过的路；
- **工程**：机密性已换完大半（TLS 混合握手默认化），签名与证书链在跟进；存量 RSA-2048 证书在过渡期仍然合法。迁移按数据保密期分批推进——保密期长的先换（1.3 的先存后解决定了这是唯一合理的顺序），其余跟随设备与协议的默认值更新。

> [!info]- 保守一侧：NSA 的 CNSA 2.0 参数
> 美国国家安全系统使用的 CNSA 2.0 套件把余量拉满：AES-256、SHA-384、ML-KEM-1024、ML-DSA-87，并给出到 2033 年完成迁移的时间表。一般系统不必照搬这个重量级组合，但"对称拉长、公钥换 PQC、全程留混合期"的三段式与 5.2 的结论一致。

## 6. 常见问题

| 现象 | 原因与解决 |
| ---- | ---- |
| 认为"量子计算机一出来 AES 就废了" | Grover 只有平方加速：AES-128 有效强度减半（且串行难并行、常数大），AES-256 仍有 $2^{128}$ 量子强度；对称侧加长密钥即可，不换算法（[[#1.2 Grover：对称与哈希只折半\|1.2]]） |
| 认为"SHA-256 被量子威胁，要全线换 SHA-3" | 哈希只有次指数级量子加速，SHA-256 原像仍有 $2^{128}$；SLH-DSA 内部用的还是 SHA-2/SHAKE——哈希是 PQC 的构件，不是被淘汰者（[[#2.2 哈希基：假设最保守\|2.2]]） |
| 同一把 Lamport 密钥签了多条消息 | 缺串位置每签一条减半（式 3.1，$t$ 条后期望 $256 \cdot 2^{1-t}$ 位），约 10 条后即可伪造任意消息；发现重用按 [[#3.3 为什么一个密钥只能签一次\|3.3]] 的账评估，或直接换钥 |
| XMSS/LMS 服务器重启后签名失败或泄露 | 叶子序号状态丢失或回退，同一一次性密钥签了两次；状态必须持久化且只许前进，管不好状态就换 SLH-DSA / ML-DSA（[[#3.4 从一次到多次：WOTS 与 Merkle 树\|3.4]]） |
| 把 SIKE、Rainbow 拿来当 PQC 方案选型 | 两者均已被经典攻击攻破（SIKE 2022 年单核小时级恢复密钥，Rainbow 2022 年被笔记本量级的计算恢复私钥）；选型只认 NIST 最终标准（[[#2.4 家族对照\|2.4]] 的折叠框） |
| 自行调小 Kyber 参数想让 toy 跑快点 | 模数 $q$、维度、噪声分布共同决定噪声预算与安全强度，改动同时破坏正确性与安全论证；toy 用于理解，生产用标准参数（[[#4.1 LWE：公钥 = 矩阵 + 噪声\|4.1]]） |
| toy LWE 解密时对时错 | 组合噪声 $e_2 + r^{\mathsf T}e - s^{\mathsf T}e_1$ 越过 $q/4$ 门槛即随机出错：缩小噪声系数、调大 $q$、或降低消息编码密度（[[#4.1 LWE：公钥 = 矩阵 + 噪声\|4.1]]） |
| 混合组里只保留 ML-KEM、关掉 X25519 | 混合的意义是两侧互为保险；只留新算法会让会话安全仅取决于单一新假设，也失去与不支持 PQC 组对端的兼容（[[#5.1 TLS 的混合密钥交换\|5.1]]） |
| 旧版 openssl 没有 ML-KEM / ML-DSA | 3.5 起原生内置；3.2–3.4 可装 oqs-provider 插件补齐（[[#5.1 TLS 的混合密钥交换\|5.1]]） |
| 启用混合组后个别客户端握手失败 | ML-KEM-768 公钥 1184 字节让握手包多出约 1 KB，个别中间设备处理不了大握手包；服务端临时关闭混合组或对端降级可定位（[[#5.1 TLS 的混合密钥交换\|5.1]]） |
| CTF 手搓 Lamport 题不知从哪下手 | 数每个位置的暴露情况：被签摘要之间的差异位即两根全暴露位；伪造须对齐的位数在几十以内就磨消息后缀（[[#3.3 为什么一个密钥只能签一次\|3.3]]） |

## 7. 配套练习与延伸阅读

> [!note] 实战任务
> 1. **泄露账复查**：把 [[#3.3 为什么一个密钥只能签一次\|3.3]] 的签名条数从 10 降到 8、9，记录"伪造须对齐位数"与磨后缀的实际尝试次数；再把消息改成定长格式（后缀不可加），说明伪造何时失效。
> 2. **WOTS 手写**：实现 $w = 16$ 的 WOTS（一条链签 4 位），对比 Lamport 的签名尺寸与验证端哈希次数，核对"计算换尺寸"的账。
> 3. **噪声预算实验**：把 [[#4.1 LWE：公钥 = 矩阵 + 噪声\|4.1]] 的 $q$ 从 97 提到 193（其余不变），重跑噪声放大实验，对照 $q/4$ 门槛解释出错率变化。
> 4. **握手探测**：对支持 PQC 的服务端执行 `openssl s_client -groups X25519MLKEM768 -msg -connect 主机:443`，在报文输出里找 ClientHello 的 key_share 扩容与协商结果。

配套练习：

1. 给 [[#3.2 全流程实现|3.2]] 加"部分泄露"档：每条签名只公开一半位置的串（模拟侧信道），重算拼出伪造能力需要的签名条数，与 [[C15-实现漏洞与侧信道|C15]] 的泄露面思维对照。
2. 用 [[C13-格密码与LLL|C13]] 的 fpylll 直接解 [[#4.1 LWE：公钥 = 矩阵 + 噪声|4.1]] toy 的 LWE：8 维小格一次约减就能恢复 $s$——参数 toy 化后格攻击是即时的，标准参数的维度就是按这类攻击加的余量。
3. 把 [[#4.2 ML-KEM 的封装与解封装|4.2]] 的流程映射回 4.1 的代码，指出 toy 缺的 FO 变换那一环，然后手工篡改密文 $v$ 的一位，观察 toy 与"隐式拒绝"行为的差别。
4. 查 FIPS 203 的参数表，把 ML-KEM-512 与 ML-KEM-1024 的公钥/私钥/密文尺寸补进 [[#4.4 参数尺寸对照|4.4]] 的表，并用 5.1 的 openssl 生成密钥核对公钥尺寸。
