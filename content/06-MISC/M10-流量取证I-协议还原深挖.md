## 1. 定位：从文件容器到流量容器

[[M09-视频隐写|M09]]的结尾把下一站指向网络流量——夹带的思路不变，住处换成了协议字段。本章承接这条线索。

[[12-隐写与流量取证|12 章 7 节]]已经给过流量题的最小闭环：显示过滤器速查表、Protocol Hierarchy / Follow Stream / Export Objects 三个 GUI 动作、四大套路（明文 flag、编码 flag、USB 键鼠、ICMP/DNS 夹带）。GUI 手法做赛题够用，但有三类它覆盖不了的场景：出题人自造的协议 Wireshark 不认识；隧道把文件切成几十片分散在几十个报文里，靠界面逐包看效率低也容易看漏；要做批量提取与自动化时，点选动作无法复用。本章按四层递进补齐：

| 节 | 主题 | 解决什么 |
| ---- | ---- | ---- |
| 2 | scapy 最小入门与造靶 | 自己生成确定性流量，后面每节的靶都出自这里 |
| 3 | pcap 文件结构手撕 | global header、record、逐层剥掉协议头的字节定位 |
| 4 | tshark 脚本化 | 统计、会话、字段提取的可复用四步范式 |
| 5 | HTTP 对象批量导出 | 命令行导出、分块传输、多部分表单 |

| 8 | DNS 隧道还原 | 子域名与 TXT 双通道的还原 |

贯穿全章的视角是 [[M02-文件格式深拆I-PNG全解|M02]]与 [[M09-视频隐写|M09]]用过的容器树：PNG 是一串 chunk，MP4 是一棵 box 树，pcap 同样是"长度字段驱动的容器"——文件头之后是一条条报文记录，每条记录内部又套着 Ethernet → IP → TCP/UDP 的协议树。==协议还原的全部工作，就是在"容器 → 帧 → 协议"这三层树上，把散在各帧里的字节按规则拼回去==。

协议本身在 [[10-网络协议基础|10 章]]讲过；本章的靶子全部用 scapy 现场生成，struct 的完整用法见 [[M01-MISC导论与工具箱#4.1 struct 的完整用法|M01 4.1]]。

## 2. scapy 最小入门与本章靶场

scapy 随 [[M01-MISC导论与工具箱#2.2 四条安装渠道|M01 2.2]]的 apt 清单装好（python3-scapy），它把报文当对象构造：一个包由多层协议叠成，`/` 运算符把层从外到内串起来，字符串直接跟在末层后面就是载荷（Raw 层）。

### 2.1 最小入门：构造、落盘、读回

```python
# one.pcap —— 一个包落盘
import calendar

from scapy.all import Ether, ICMP, IP, wrpcap

pkt = (Ether(src="52:54:00:12:34:56", dst="52:54:00:78:9a:bc")
       / IP(src="10.0.0.1", dst="10.0.0.2")
       / ICMP(id=1, seq=1) / b"hello")
pkt.time = calendar.timegm((2026, 10, 24, 12, 0, 0))    # 固定时间戳
wrpcap("one.pcap", [pkt])
```

```bash
tshark -r one.pcap
```

输出：

```text
    1   0.000000     10.0.0.1 → 10.0.0.2     ICMP 47 Echo (ping) request  id=0x0001, seq=1/256, ttl=64
```

构造与落盘就这么三行：`wrpcap("文件名", 包列表)` 把包列表写成 pcap，格式与抓包工具产出的完全一致，tshark、Wireshark、本章 3 节的手撕解析器都当普通 pcap 读。

> [!note] wrpcap 不发包，pkt.time 决定时间戳
> `wrpcap` 只写文件，不产生网络流量，普通用户即可运行；scapy 的 `send()` / `sr1()` 才是真发包，需要 root 与可用网络，本章全程不用。`pkt.time` 不赋值时取当前时间；造靶时用 `calendar.timegm` 固定下来，脚本重跑能得到逐字节一致的 pcap。

### 2.2 造靶方法论

还原是赛场上要考的动作，造靶是练这个动作的低成本途径。真实赛题给的是出题人抓好的 pcap，你只有结果没有过程；自造靶把过程也握在手里：藏了什么、按什么顺序、有没有噪声，全部自己说了算，还原对不对当场可判。三条原则：

1. **确定性**：内容、包数、时间戳全部固定，脚本可复跑，输出可与同学比对。
2. **私货装进合法字段**：echo 的 data、DNS 的查询名与 TXT、TCP 载荷——[[12-隐写与流量取证|12 章 7.3]]四大套路里的识别特征，反过来写就是造靶配方。
3. **加噪声**：混入普通流量，靶子才接近赛题；还原脚本被迫先做过滤，这本身就是训练点。

> [!warning] 本库环境抓真实回环流量的坑：一律 wrpcap
> 本库的 WSL 用 mirrored 网络模式（`wslinfo --networking-mode` 可查），回环抓包有两处异常：`tshark -i lo` 只能看到 ICMP，TCP 回环流量一个包都抓不到；改用 `-i any` 能抓到，但每个包重复出现两次，重组时全是"重传"噪声。所以本章所有靶一律 wrpcap 生成。在真机 Linux 上抓本地服务是常规操作：服务起在 5010 端口，`tshark -i lo -f "tcp port 5010" -w http.pcap` 挂在后台，另开终端用 curl 发请求即可（抓包需要 root 或 wireshark 组成员身份；`-f` 的语法与用途见 4.3 的警告框）。

下面造贯穿 3、4 节的靶场 demo.pcap：ICMP 一问一答、DNS 一问一答、一段 TCP 三次握手加一对 HTTP 请求响应、一段普通 UDP，共 10 个包。

```python
# build_demo.py —— 造 demo.pcap：ICMP / DNS / TCP+HTTP / UDP 各来一段
import calendar

from scapy.all import DNS, DNSQR, DNSRR, Ether, ICMP, IP, Raw, TCP, UDP, wrpcap

BASE = calendar.timegm((2026, 10, 24, 12, 0, 0))   # 2026-10-24 12:00:00 UTC
C_MAC, S_MAC = "52:54:00:12:34:56", "52:54:00:78:9a:bc"
C_IP, S_IP = "10.13.0.2", "10.13.0.1"

def eth_ip(payload, *, src=C_IP, dst=S_IP):
    if src == C_IP:
        ether = Ether(src=C_MAC, dst=S_MAC)
    else:
        ether = Ether(src=S_MAC, dst=C_MAC)
    return ether / IP(src=src, dst=dst) / payload

pkts = []
t = 0.0

def add(p, *, src=C_IP, dst=S_IP):
    global t
    pkt = eth_ip(p, src=src, dst=dst)     # 先组装成完整帧
    pkt.time = BASE + t                   # 再对顶层帧赋时间戳
    t += 0.5
    pkts.append(pkt)

# [1][2] ICMP echo 一问一答
add(ICMP(type=8, id=0x1234, seq=1) / Raw(b"payload-demo-0001"))
add(ICMP(type=0, id=0x1234, seq=1) / Raw(b"payload-demo-0001"), src=S_IP, dst=C_IP)

# [3][4] DNS 查询 A 记录 + 应答
add(UDP(sport=40001, dport=53) /
    DNS(id=0x0001, rd=1, qd=DNSQR(qname="www.example.com", qtype="A")))
add(UDP(sport=53, dport=40001) /
    DNS(id=0x0001, qr=1,
        qd=DNSQR(qname="www.example.com", qtype="A"),
        an=DNSRR(rrname="www.example.com", type="A", rdata="93.184.216.34", ttl=300)),
    src=S_IP, dst=C_IP)

# [5]-[9] TCP 三次握手 + 一对 HTTP 请求响应
sport, dport, cseq, sseq = 44444, 80, 1000, 5000
get = b"GET /index.html HTTP/1.1\r\nHost: www.example.com\r\nUser-Agent: curl/8.16.0\r\n\r\n"
resp = b"HTTP/1.1 200 OK\r\nContent-Type: text/html\r\nContent-Length: 2\r\n\r\nhi"
add(TCP(sport=sport, dport=dport, flags="S", seq=cseq))
add(TCP(sport=dport, dport=sport, flags="SA", seq=sseq, ack=cseq + 1), src=S_IP, dst=C_IP)
add(TCP(sport=sport, dport=dport, flags="A", seq=cseq + 1, ack=sseq + 1))
add(TCP(sport=sport, dport=dport, flags="PA", seq=cseq + 1, ack=sseq + 1) / Raw(get))
add(TCP(sport=dport, dport=sport, flags="PA", seq=sseq + 1, ack=cseq + 1 + len(get)) / Raw(resp),
    src=S_IP, dst=C_IP)

# [10] 一段普通 UDP 载荷
add(UDP(sport=5000, dport=5000) / Raw(b"udp-payload-demo"))

wrpcap("demo.pcap", pkts)
print(f"demo.pcap 共 {len(pkts)} 个包")
```

scapy 会自动算好 IP/TCP/UDP/ICMP 的校验和，字段给全即可。TCP 的序号要自己维护：SYN 消耗一个序号，之后的 seq/ack 都从 `+1` 之后起算——上面握手段的 `cseq + 1` 就是这件事。DNS 的应答包把查询的 `qd` 原样带回，再加 `an` 应答记录。

## 3. pcap 文件结构手撕

```bash
file demo.pcap
```

输出：

```text
demo.pcap: pcap capture file, microsecond ts (little-endian) - version 2.4 (Ethernet, capture length 65535)
```

pcap 文件只有两部分：一个 24 字节的 **global header**，之后一条接一条的 **record**。本节按 [[M02-文件格式深拆I-PNG全解|M02]]拆 chunk 的同一套 struct 手法拆它。

### 3.1 global header：24 字节定全局

| 字段 | 大小 | demo.pcap 的值 | 说明 |
| ---- | ---- | ---- | ---- |
| magic | 4 字节 | `d4 c3 b2 a1` | 字节序开关，见下文 |
| version_major / minor | 2 + 2 字节 | 2 / 4 | 格式版本 |
| thiszone | 4 字节 | 0 | 时区偏移，现代规范恒写 0 |
| sigfigs | 4 字节 | 0 | 时间戳理论精度，置 0 |
| snaplen | 4 字节 | 65535 | 单包最大抓取长度 |
| network | 4 字节 | 1 | 链路类型，1 = Ethernet |

magic 是整个文件格式的机关：写入方把值 `0xa1b2c3d4` 按自己的字节序落盘，x86 小端机器写出 `d4 c3 b2 a1`，大端机器写出 `a1 b2 c3 d4`。读取方读出这 4 字节拼成整数，等于 `0xa1b2c3d4` 就按小端读后续字段，等于 `0xd4c3b2a1` 就按大端读——[[12-隐写与流量取证|12 章 2.1]]魔数表里 pcap 那行的两种写法，就是这同一个值的两种落盘形态。[[03-计算机组成与数据表示|03 章]]说过网络字节序是大端，但 pcap 的 record 头跟随 global header 判定出的字节序，与网络序无关。

### 3.2 record：长度字段驱动遍历

每条 record 是 16 字节头加报文本体：

| 字段 | 大小 | 说明 |
| ---- | ---- | ---- |
| ts_sec | 4 字节 | 时间戳秒 |
| ts_usec | 4 字节 | 时间戳微秒 |
| incl_len | 4 字节 | 本条记录实际存了多少字节 |
| orig_len | 4 字节 | 抓到时原有多长 |

遍历机制与 PNG chunk 的长度字段、MP4 box 的 size 完全同源：读 16 字节头，按 `incl_len` 跳过报文本体，落到下一条 record。`orig_len < incl_len` 不会出现；反过来 `orig_len > incl_len` 说明包被 snaplen 截断过，重组时数据可能缺一截。

```python
# pcap_parse.py —— 手撕 pcap：global header + 逐包 record，再按链路层逐层剥头
import struct

MAGIC_LE = 0xA1B2C3D4   # 文件里字节序为 d4 c3 b2 a1 -> 小端
MAGIC_BE = 0xD4C3B2A1   # 文件里字节序为 a1 b2 c3 d4 -> 大端

data = open("demo.pcap", "rb").read()

# ---- 第一段：24 字节 global header ----
magic = struct.unpack("<I", data[:4])[0]
if magic == MAGIC_LE:
    en = "<"      # 之后所有多字节字段都按小端读
elif magic == MAGIC_BE:
    en = ">"      # 之后所有多字节字段都按大端读
else:
    raise SystemExit("不是经典 pcap 文件（可能是 pcapng）")
ver_maj, ver_min, thiszone, sigfigs, snaplen, linktype = struct.unpack(
    en + "HHiIII", data[4:24])
print(f"global header: 版本 {ver_maj}.{ver_min}  snaplen={snaplen}  链路类型={linktype}")
LINKTYPES = {1: "Ethernet", 101: "raw IP", 113: "Linux cooked"}
print(f"链路类型 {linktype} = {LINKTYPES.get(linktype, '未知')}")

# ---- 第二段：逐包 record ----
IP_TYPES = {1: "ICMP", 6: "TCP", 17: "UDP"}
pos = 24
idx = 0
while pos < len(data):
    ts_sec, ts_usec, incl_len, orig_len = struct.unpack(en + "IIII", data[pos:pos+16])
    pkt = data[pos+16 : pos+16+incl_len]
    idx += 1
    # Ethernet：0-5 目的 MAC，6-11 源 MAC，12-13 类型
    eth_type = struct.unpack(">H", pkt[12:14])[0]
    line = f"#{idx:<2} {ts_sec}.{ts_usec:06d}  incl={incl_len:<4} orig={orig_len:<4}"
    if eth_type != 0x0800:
        print(line + f"  eth_type=0x{eth_type:04x}（非 IPv4）")
        pos += 16 + incl_len
        continue
    # IPv4：14 字节以太网头之后；首字节低 4 位是 IHL，头长 = IHL*4
    ihl = (pkt[14] & 0x0F) * 4
    proto = pkt[14 + 9]
    ip_src = ".".join(str(b) for b in pkt[14+12:14+16])
    ip_dst = ".".join(str(b) for b in pkt[14+16:14+20])
    line += f"  {ip_src} -> {ip_dst}  {IP_TYPES.get(proto, proto)}"
    l4 = 14 + ihl                      # 传输层头起点
    if proto == 1:                     # ICMP：类型/代码/校验和/id/seq 共 8 字节头
        t, code, cks, ident, seq = struct.unpack(">BBHHH", pkt[l4:l4+8])
        line += f"  type={t} id=0x{ident:04x} seq={seq}"
    elif proto == 6:                   # TCP：端口/序号，首字节高 4 位是数据偏移
        sp, dp = struct.unpack(">HH", pkt[l4:l4+4])
        off = (pkt[l4+12] >> 4) * 4
        line += f"  {sp} -> {dp}  载荷 {len(pkt) - l4 - off} 字节"
    elif proto == 17:                  # UDP：固定 8 字节头
        sp, dp, ulen, _ = struct.unpack(">HHHH", pkt[l4:l4+8])
        line += f"  {sp} -> {dp}  载荷 {ulen - 8} 字节"
    print(line)
    pos += 16 + incl_len
print(f"record 共 {idx} 个，解析到文件尾 {pos} = 文件长度 {len(data)}")
```

### 3.3 Ethernet → IP → TCP/UDP：逐层定位载荷

record 里的报文是逐层套的，每层的头都有固定位置（协议号为 6 是 TCP、17 是 UDP、1 是 ICMP）：

| 层 | 起点 | 关键字段与偏移 | demo 第 1 包的读法 |
| ---- | ---- | ---- | ---- |
| Ethernet | 0 | 12–13 类型字段，0x0800 = IPv4 | `0800` → 里面是 IP |
| IPv4 | 14 | 首字节低 4 位是 IHL，头长 = IHL×4；14+9 协议号；14+12 起源 IP、14+16 起目的 IP | IHL=5 → 头长 20；协议 1 → ICMP |
| ICMP | 14 + IHL×4 | 8 字节头：类型/代码/校验和/id/seq | type=8，id=0x1234，seq=1 |
| TCP | 14 + IHL×4 | 0–2 源端口、2–4 目的端口；+12 字节高 4 位是数据偏移，头长 = 偏移×4 | 头长之后是载荷 |
| UDP | 14 + IHL×4 | 固定 8 字节头：源/目的端口、长度、校验和 | 载荷 = 长度字段 − 8 |

==载荷起点 = 14 + IHL×4 + 传输层头长==。后面几节的隧道还原、自定义协议还原，输入侧都要先算出这个起点——解析器里 `l4 = 14 + ihl` 那一行就是它的实现。以太网类型 0x0806 是 ARP、0x86DD 是 IPv6，拿到非 0x0800 的帧照 3.2 解析器的分支跳过或单独处理。

### 3.4 容器树对照与 pcapng

三种容器放在一起看，遍历思想是同一套：

| 容器 | 遍历机制 | 完整性 |
| ---- | ---- | ---- |
| PNG chunk（[[M02-文件格式深拆I-PNG全解\|M02]]） | 4 字节长度 + 4 字节类型 + 数据 + 4 字节 CRC | 每块自校验 |
| MP4 box（[[M09-视频隐写\|M09]]） | 4 字节大小 + 4 字节类型 + 数据，可嵌套成树 | 无校验 |
| pcap record | 16 字节头（两个时间戳、两个长度）+ 报文 | 无块级校验；IP/TCP 头各带校验和 |

pcap record 没有"类型"字段——每条记录必然是一帧报文，帧内是什么协议靠剥层判断；完整性也不靠块级 CRC，IP 头和 TCP/UDP 头各自带校验和，被改过的包要靠 4 节的 tshark 提示或自己重算才能发现。解析脚本遇到"incl_len 越过文件尾"就说明结构坏了，这与 [[M02-文件格式深拆I-PNG全解|M02 6 节]]按 chunk 结构走到 IEND 是同一类防线。

> [!info]- pcapng：另一种容器格式
> Wireshark 1.1 起默认保存 pcapng：magic 是 `0a 0d 0d 0a`，按"块"组织（每块自带类型与长度），支持多网卡信息、注释、纳秒精度。tshark 两种格式都能读，`file` 能区分（`tshark -r demo.pcap -w demo.pcapng` 转换后 `file demo.pcapng` 报 `pcapng capture file - version 1.0`）。手撕解析器只认经典 pcap 时，用 `editcap -F pcap in.pcapng out.pcap` 转回——editcap 随 tshark 一起安装。赛题两种格式都会出现，先 file 再动手。

### 4.4 可复用的四步范式

把上面的动作排成固定顺序，任何流量包都能按此开拆：

1. ==`-z io,phs` 看协议占比==，反常的层是入口；
2. ==`-z conv,tcp` / `-z conv,udp` 找会话==，字节数大、端口偏门的优先；
3. ==`-Y` 收敛==到目标会话或目标协议；
4. ==`-T fields -e` 批量提取==，输出喂给 Python 脚本做字节层还原。

前两步各一行命令，第三步把几千个包收敛到几十个，第四步的输出直接是 struct 解析器的输入（[[M01-MISC导论与工具箱#4.1 struct 的完整用法|M01 4.1]]）。5–8 节的所有解靶脚本，输入侧都是第 4 步的产物。

## 5. HTTP 对象批量导出

HTTP 是流量题的重灾区（[[12-隐写与流量取证|12 章 7.3]]），明文 flag 与编码 flag 靠 `-Y 'http contains "flag"'` 就能打中；本节补三件 GUI 覆盖不住的：命令行批量导出传输对象、分块传输的还原、多部分表单的还原。

### 5.1 造靶：一台主机的三件 HTTP 事

靶子 http.pcap：10.13.0.2 这台主机做了三件事——下载 /photo.png（普通 Content-Length 响应）、访问 /status（chunked 分块响应）、向 /upload 上传一个 multipart 表单（一个文本字段加一个 zip 文件）。三条独立 TCP 连接，每条都有握手与挥手：

```python
# build_http.py —— 造 http.pcap：三条 TCP 连接分别送 普通下载 / 分块响应 / multipart 上传
import calendar
import io
import zipfile

from PIL import Image, PngImagePlugin
from scapy.all import Ether, IP, Raw, TCP, wrpcap

BASE = calendar.timegm((2026, 10, 24, 13, 0, 0))
C_MAC, S_MAC = "52:54:00:12:34:56", "52:54:00:78:9a:bc"
C_IP, S_IP = "10.13.0.2", "10.13.0.1"

# 素材 1：一张普通 PNG（带一条无关紧要的 tEXt）
img = Image.new("RGB", (64, 48), (252, 252, 251))
meta = PngImagePlugin.PngInfo()
meta.add_text("Comment", "plain photo, nothing here")
buf = io.BytesIO()
img.save(buf, "PNG", pnginfo=meta)
PNG = buf.getvalue()

# 素材 2：上传用的 ZIP，内含 flag.txt（ZipInfo 固定内嵌时间，保证靶可复现）
info = zipfile.ZipInfo("flag.txt", date_time=(2026, 10, 24, 13, 0, 0))
mem = io.BytesIO()
with zipfile.ZipFile(mem, "w", zipfile.ZIP_DEFLATED) as z:
    z.writestr(info, "flag{exp0rt_0bj3cts}\n", compress_type=zipfile.ZIP_DEFLATED)
ZIP = mem.getvalue()

t = [0.0]
def add(pkts, p, src=C_IP):
    if src == C_IP:
        ether = Ether(src=C_MAC, dst=S_MAC)
    else:
        ether = Ether(src=S_MAC, dst=C_MAC)
    pkt = ether / IP(src=src, dst=S_IP if src == C_IP else C_IP) / p
    pkt.time = BASE + t[0]                # 先组装、后赋时间戳，避免被顶层覆盖
    t[0] += 0.5
    pkts.append(pkt)

def conn(pkts, sport, exchange):
    """exchange: [(方向, 字节)]，'c' 客户端 -> 服务器，'s' 反向"""
    cseq, sseq = 1000, 5000
    add(pkts, TCP(sport=sport, dport=80, flags="S", seq=cseq))
    add(pkts, TCP(sport=80, dport=sport, flags="SA", seq=sseq, ack=cseq + 1), src=S_IP)
    add(pkts, TCP(sport=sport, dport=80, flags="A", seq=cseq + 1, ack=sseq + 1))
    cseq, sseq = cseq + 1, sseq + 1
    for direction, data in exchange:
        if direction == "c":
            add(pkts, TCP(sport=sport, dport=80, flags="PA", seq=cseq, ack=sseq) / Raw(data))
            cseq += len(data)
        else:
            add(pkts, TCP(sport=80, dport=sport, flags="PA", seq=sseq, ack=cseq) / Raw(data), src=S_IP)
            sseq += len(data)
    add(pkts, TCP(sport=sport, dport=80, flags="FA", seq=cseq, ack=sseq))
    add(pkts, TCP(sport=80, dport=sport, flags="FA", seq=sseq, ack=cseq + 1), src=S_IP)
    add(pkts, TCP(sport=sport, dport=80, flags="A", seq=cseq + 1, ack=sseq + 1))

def req(method, uri, extra="", body=b""):
    head = (f"{method} {uri} HTTP/1.1\r\nHost: 10.13.0.1\r\n"
            f"User-Agent: curl/8.16.0\r\nAccept: */*\r\n{extra}").encode()
    if body:
        head += f"Content-Length: {len(body)}\r\n".encode()
    return head + b"\r\n" + body

pkts = []

# 连接 1：普通下载，Content-Length 响应
resp1 = (b"HTTP/1.1 200 OK\r\nContent-Type: image/png\r\n"
         b"Content-Disposition: attachment; filename=\"photo.png\"\r\n"
         + f"Content-Length: {len(PNG)}\r\n\r\n".encode() + PNG)
conn(pkts, 50001, [("c", req("GET", "/photo.png")), ("s", resp1)])

# 连接 2：Transfer-Encoding: chunked 响应
body = b"hint: check exported objects"
chunks = [body[:6], body[6:12], body[12:]]
chunked = b"".join(f"{len(c):x}\r\n".encode() + c + b"\r\n" for c in chunks) + b"0\r\n\r\n"
resp2 = (b"HTTP/1.1 200 OK\r\nContent-Type: text/plain\r\nTransfer-Encoding: chunked\r\n\r\n"
         + chunked)
conn(pkts, 50002, [("c", req("GET", "/status")), ("s", resp2)])

# 连接 3：multipart/form-data 上传
BOUND = b"----ctfboundary42"
part1 = (b"--" + BOUND + b"\r\n"
         b'Content-Disposition: form-data; name="note"\r\n\r\n'
         b"hello from client\r\n")
part2 = (b"--" + BOUND + b"\r\n"
         b'Content-Disposition: form-data; name="file"; filename="report.zip"\r\n'
         b"Content-Type: application/zip\r\n\r\n"
         + ZIP + b"\r\n")
mpbody = part1 + part2 + b"--" + BOUND + b"--\r\n"
req3 = req("POST", "/upload",
           extra="Content-Type: multipart/form-data; boundary=----ctfboundary42\r\n",
           body=mpbody)
conn(pkts, 50003, [("c", req3), ("s", b"HTTP/1.1 200 OK\r\nContent-Length: 2\r\n\r\nok")])

wrpcap("http.pcap", pkts)
print(f"http.pcap 共 {len(pkts)} 个包；PNG {len(PNG)} B，ZIP {len(ZIP)} B，multipart 体 {len(mpbody)} B")
```

输出：

```text
http.pcap 共 24 个包；PNG 183 B，ZIP 137 B，multipart 体 371 B
```

### 5.3 Transfer-Encoding: chunked 的还原

响应头带 `Transfer-Encoding: chunked` 时，报文体按块发送，每块三段：十六进制长度行 + `\r\n` + 数据 + `\r\n`，最后以长度为 0 的块收尾。用它替代 Content-Length，服务器可以边生成边发，不必先算总长。Follow TCP Stream 的 hex 模式能看到原始分块帧——完整输出里请求侧靠左、响应侧缩进，下面截取响应侧：

```bash
tshark -r http.pcap -q -z follow,tcp,hex,1
```

输出：

```text
	00000000  48 54 54 50 2f 31 2e 31  20 32 30 30 20 4f 4b 0d  HTTP/1.1  200 OK.
	00000010  0a 43 6f 6e 74 65 6e 74  2d 54 79 70 65 3a 20 74  .Content -Type: t
	00000020  65 78 74 2f 70 6c 61 69  6e 0d 0a 54 72 61 6e 73  ext/plai n..Trans
	00000030  66 65 72 2d 45 6e 63 6f  64 69 6e 67 3a 20 63 68  fer-Enco ding: ch
	00000040  75 6e 6b 65 64 0d 0a 0d  0a 36 0d 0a 68 69 6e 74  unked... .6..hint
	00000050  3a 20 0d 0a 36 0d 0a 63  68 65 63 6b 20 0d 0a 31  : ..6..c heck ..1
	00000060  30 0d 0a 65 78 70 6f 72  74 65 64 20 6f 62 6a 65  0..expor ted obje
	00000070  63 74 73 0d 0a 30 0d 0a  0d 0a                    cts..0.. ..
```

`36 0d 0a` 是第一块："6\r\n"——十六进制 6 字节的数据 `hint: `；之后 `6\r\n` + `check `、`10\r\n` + `exported objects`（十六进制 10 = 16 字节），最后 `0\r\n\r\n` 收尾。tshark 已经把块拼好，`http.file_data` 直接给出还原后的原始体：

```bash
tshark -r http.pcap -Y 'http.response && http.transfer_encoding=="chunked"' \
    -T fields -e http.file_data > ch.hex
python3 -c "import binascii; print(binascii.unhexlify(open('ch.hex').read().strip()).decode())"
```

输出：

```text
hint: check exported objects
```

==分块只是传输形态，`http.file_data` 拿到的永远是拼好的原始体==；手工解分块只在 Wireshark 认不出协议或分块套在自定义协议里时才需要，套路就是按"长度行 + 数据"循环切。

### 5.4 multipart/form-data 的还原

浏览器上传文件走 multipart/form-data：请求头声明一个 boundary 分界串，报文体按分界串切成多个部件，每个部件自带一段头（Content-Disposition 写明字段名与文件名），头与内容以空行分界，最后以 `--boundary--` 收尾。5.2 导出的 upload 对象（371 字节）就是这个体。切割脚本：

```python
# carve_chapter.py —— 按 boundary 切开 multipart 体，取出文件部件
BOUND = b"----ctfboundary42"
body = open("objs/upload", "rb").read()
print(f"POST 体共 {len(body)} 字节，boundary = {BOUND.decode()}")
for part in body.split(b"--" + BOUND):
    part = part.lstrip(b"\r\n")
    if not part or part.startswith(b"--"):
        continue                                          # 收尾的 --boundary--
    head, _, content = part.partition(b"\r\n\r\n")        # 部件头与内容以空行分界
    content = content.rsplit(b"\r\n", 1)[0]               # 去掉部件尾的 \r\n
    disp = [l.decode() for l in head.split(b"\r\n") if b"Content-Disposition" in l][0]
    name = disp.split('name="')[1].split('"')[0]
    if "filename=" in disp:
        fn = disp.split('filename="')[1].split('"')[0]
        open(fn, "wb").write(content)
        print(f"  部件 name={name} filename={fn} -> {fn} {len(content)} 字节")
    else:
        print(f"  部件 name={name} 内容 {content!r}")
```

输出：

```text
POST 体共 371 字节，boundary = ----ctfboundary42
  部件 name=note 内容 b'hello from client'
  部件 name=file filename=report.zip -> report.zip 137 字节
```


输出：

```text

Archive:  report.zip
  inflating: flag.txt                
flag{exp0rt_0bj3cts}
```

三处结构细节都要处理：部件头与内容之间是 `\r\n\r\n`（空行）；每个部件的内容末尾带一个 `\r\n`（属于分界行，不属于内容）；结尾的 `--boundary--` 是收尾标记，不是部件。不走导出对象也可以直接提字段：`tshark -r http.pcap -Y 'http.request.method=="POST"' -T fields -e http.file_data` 输出请求体的 hex，`bytes.fromhex` 之后进同一个切割脚本。

## 6. 自定义协议逆向还原

出题人自造协议时，Wireshark 只能认出"这是 TCP 载荷"，剩下的还原全靠自己。本节从造到解完整走一遍，最后总结成通用步骤。

### 6.1 靶：CTFP 协议分帧传文件

自造一个二进制协议 CTFP，在 TCP 上分帧传一个 zip：每帧 = magic（4 字节 `CTFP`）+ 版本（1 字节）+ 帧类型（1 字节：1 START / 2 DATA / 3 FIN）+ 序号（2 字节大端）+ 载荷长度（2 字节大端）+ 载荷。START 的载荷是文件名，DATA 的载荷是文件分片，FIN 的载荷是整个文件的 CRC32。另加两条 7777 端口的明文心跳作噪声，同一帧格式再走一遍 UDP 作变体：

```python
# build_proto.py —— 造 proto.pcap：CTFP 走 TCP 传 zip，同帧格式走 UDP 传文本，外加噪声
import calendar
import io
import struct
import zipfile
import zlib

from scapy.all import Ether, IP, Raw, TCP, UDP, wrpcap

BASE = calendar.timegm((2026, 10, 24, 14, 0, 0))
C_MAC, S_MAC = "52:54:00:12:34:56", "52:54:00:aa:bb:01"
C_IP, S_IP = "10.13.0.2", "10.13.0.9"
MAGIC = b"CTFP"

def frame(ftype, seq, payload=b""):
    """CTFP 帧：magic(4) | version(1) | type(1) | seq(2,大端) | len(2,大端) | payload"""
    return MAGIC + bytes([1, ftype]) + struct.pack(">HH", seq, len(payload)) + payload

t = [0.0]
pkts = []
def add(p, src=C_IP):
    if src == C_IP:
        ether = Ether(src=C_MAC, dst=S_MAC)
    else:
        ether = Ether(src=S_MAC, dst=C_MAC)
    pkt = ether / IP(src=src, dst=S_IP if src == C_IP else C_IP) / p
    pkt.time = BASE + t[0]                # 先组装、后赋时间戳，避免被顶层覆盖
    t[0] += 0.5
    pkts.append(pkt)

# ---- 噪声：另一台主机 7777 端口的心跳文本 ----
add(TCP(sport=60000, dport=7777, flags="PA", seq=7, ack=1) / Raw(b"heartbeat: alive"))
add(TCP(sport=7777, dport=60000, flags="PA", seq=1, ack=17) / Raw(b"ack"), src=S_IP)

# ---- 主菜：TCP 55555 -> 9999，CTFP 分帧传 notes.zip ----
info = zipfile.ZipInfo("flag.txt", date_time=(2026, 10, 24, 14, 0, 0))
mem = io.BytesIO()
with zipfile.ZipFile(mem, "w", zipfile.ZIP_DEFLATED) as z:
    z.writestr(info, "flag{cust0m_pr0t0_r3st0red}\n", compress_type=zipfile.ZIP_DEFLATED)
ZIP = mem.getvalue()
CHUNK = 32
frames = [frame(1, 0, b"notes.zip")]
for i in range(0, len(ZIP), CHUNK):
    frames.append(frame(2, len(frames) - 1, ZIP[i:i + CHUNK]))
frames.append(frame(3, len(frames) - 1, struct.pack(">I", zlib.crc32(ZIP))))

sport, dport, cseq, sseq = 55555, 9999, 3000, 8000
add(TCP(sport=sport, dport=dport, flags="S", seq=cseq))
add(TCP(sport=dport, dport=sport, flags="SA", seq=sseq, ack=cseq + 1), src=S_IP)
add(TCP(sport=sport, dport=dport, flags="A", seq=cseq + 1, ack=sseq + 1))
cseq, sseq = cseq + 1, sseq + 1
for fr in frames:
    add(TCP(sport=sport, dport=dport, flags="PA", seq=cseq, ack=sseq) / Raw(fr))
    cseq += len(fr)
    add(TCP(sport=dport, dport=sport, flags="A", seq=sseq, ack=cseq), src=S_IP)
add(TCP(sport=sport, dport=dport, flags="FA", seq=cseq, ack=sseq))
add(TCP(sport=dport, dport=sport, flags="FA", seq=sseq, ack=cseq + 1), src=S_IP)

# ---- 变体：同一帧格式改走 UDP，传一段文本 ----
KEY = b"k3y=st4sh-2026"
uframes = [frame(1, 0, b"key.txt")]
for i in range(0, len(KEY), 8):
    uframes.append(frame(2, len(uframes) - 1, KEY[i:i + 8]))
uframes.append(frame(3, len(uframes) - 1))
for fr in uframes:
    add(UDP(sport=5555, dport=9999) / Raw(fr))

wrpcap("proto.pcap", pkts)
print(f"proto.pcap 共 {len(pkts)} 个包；notes.zip {len(ZIP)} B 分 {len(frames)} 帧；"
      f"key.txt {len(KEY)} B 分 {len(uframes)} 帧（UDP）")
```

输出：

```text

```

### 6.3 对照多包猜字段

字段表是猜出来的，依据是多包对照。盯着上面三行 hex：

- 每行开头都是 `43 54 46 50`，即 ASCII "CTFP"——magic，协议帧的定位锚；
- 接着两字节 `01 01`：第 1 字节在三行里恒为 01，当版本；第 2 字节出现 01、02、02，当帧类型；
- 再往后 `00 00 00 09`：拆成两个 2 字节大端整数，0000 与 0009。第 1 帧总长 19 字节，头占 10 字节，载荷恰 9 字节，且 `6e6f7465732e7a6970` 解出 ASCII "notes.zip"——所以 0000 是序号、0009 是载荷长度；
- 第 2、3 帧：类型 02、序号 0000、0001 递增、长度 0020 = 32，载荷恰 32 字节——DATA 帧，序号是分片编号。

| 偏移 | 大小 | 猜测 | 依据 |
| ---- | ---- | ---- | ---- |
| 0–3 | 4 字节 | magic `CTFP` | 每帧都出现 |
| 4 | 1 字节 | 版本 | 三帧恒为 01 |
| 5 | 1 字节 | 帧类型 | 只见 01 / 02 / 03 |
| 6–7 | 2 字节 | 序号（大端） | DATA 帧递增 |
| 8–9 | 2 字节 | 载荷长度（大端） | 与载荷字节数吻合 |
| 10– | 可变 | 载荷 | START 是文件名，DATA 是数据，FIN 是 4 字节校验值 |

==猜字段的收口手段是长度字段==：长度声明与载荷字节数逐帧吻合，结构就立住了；对不上就换一种拆法再试。FIN 帧载荷 4 字节，像 CRC32——解靶时复核。

### 6.4 struct 还原脚本

```python
# solve_proto.py —— 从 stdin 读 tshark 提取的帧字节（hex），按 CTFP 结构还原文件
import struct
import sys
import zlib

frames = []
for line in sys.stdin:                      # 每行一个 TCP 载荷的 hex（可能带冒号分隔）
    hx = line.strip().replace(":", "")
    if not hx:
        continue
    raw = bytes.fromhex(hx)
    if raw[:4] != b"CTFP":                  # magic 不对：噪声，跳过
        print(f"  跳过非 CTFP 载荷 {len(raw)} 字节: {raw[:12]!r}...")
        continue
    ver, ftype = raw[4], raw[5]
    seq, ln = struct.unpack(">HH", raw[6:10])
    payload = raw[10:10 + ln]
    ok = "OK" if len(payload) == ln == len(raw) - 10 else "LEN 不符"
    frames.append((ftype, seq, payload))
    print(f"  帧 type={ftype} seq={seq} len={ln} 载荷 {len(payload)} B [{ok}]")

name = b"".join(p for t, s, p in frames if t == 1)
data = b"".join(p for t, s, p in frames if t == 2)
fin = [p for t, s, p in frames if t == 3]
print(f"START 文件名: {name.decode()}   DATA 共 {len(data)} B   FIN 帧 {len(fin)} 个")
if fin and len(fin[0]) == 4:
    stored = struct.unpack(">I", fin[0])[0]
    calc = zlib.crc32(data) & 0xFFFFFFFF
    print(f"FIN 内 CRC32: 存储 {stored:08x} / 重算 {calc:08x} -> {'一致' if stored == calc else '不一致'}")
else:
    print("FIN 无校验字段（可选），跳过完整性核对")
out = name.decode()
open(out, "wb").write(data)
print(f"写出 {out}，{len(data)} 字节")
```


> [!warning] TCP 不保证"一帧一包"
> scapy 靶里一个 TCP 报文装一帧，是造靶时的简化。真实抓包里发送方可能把两帧合并进一个报文（Nagle 算法），也可能把一帧劈进两个报文（超过 MSS 被分段），逐包解帧会错位。通用做法是先按流重组再解帧：`tshark -r proto.pcap -q -z follow,tcp,raw,1` 输出整条流的连续 hex（每行一段），把它喂给同一个解帧函数——帧边界由帧内的长度字段自己找回来，不依赖报文边界。==解帧逻辑永远不要假设"包边界 = 帧边界"==。

> [!info]- UDP 变体：同一帧格式换个容器
> 22–25 号包是同一 CTFP 帧格式走 UDP 的变体（5.1 造靶脚本的最后一段）。UDP 数据报自带边界，通常一帧一包（大报文的 IP 分片由 tshark 自动重组），提取字段换成 `udp.payload` 即可，解帧代码一行不用改：
>
> ```bash
> tshark -r proto.pcap -Y 'udp.port==9999' -T fields -e udp.payload | python3 solve_proto.py
> ```
>
> 输出：
>
> ```text
>   帧 type=1 seq=0 len=7 载荷 7 B [OK]
>   帧 type=2 seq=0 len=8 载荷 8 B [OK]
>   帧 type=2 seq=1 len=6 载荷 6 B [OK]
>   帧 type=3 seq=2 len=0 载荷 0 B [OK]
> START 文件名: key.txt   DATA 共 14 B   FIN 帧 1 个
> FIN 无校验字段（可选），跳过完整性核对
> 写出 key.txt，14 字节
> ```
>
> 这里的 FIN 没带校验字段（可选字段的写法），解靶脚本按"字段可选"处理——未知协议里别假设每个字段都存在。

### 6.5 未知协议还原的通用步骤

把本节的做法收敛成固定五步：

1. ==统计会话==（`-z conv,tcp` / `-z conv,udp`），字节数大、端口偏门的会话是主战场；
2. ==按字节定位协议帧==：已知 magic 用 `frame contains "CTFP"` 或 `tcp.payload contains 43:54:46:50`；完全未知就先 `strings` 扫可读串、看反复出现的字节模式；
3. ==对照多包猜字段==：恒定的当 magic/版本，递增的当序号，与载荷长度吻合的当长度字段；
4. ==struct 写解析器==，逐帧校验长度与校验值，对不上就回第 3 步换拆法；
5. ==按序号重组，file 认真身==，按容器类型进 [[M01-MISC导论与工具箱|M01 5.2]]的固定动作清单。

## 7. ICMP 隧道完整还原

### 7.1 靶与识别

ICMP echo 的 data 字段是天然的携带舱：长度任意、内容任意，id 与 seq 两个字段是现成的编号系统。造靶：一张 PNG 切成 24 字节一片，每片装进一个 echo 请求，id 固定 0x1337、seq 从 0 递增；混入两条 id=1 的普通 ping（请求 + 应答）作噪声：

```python
# build_icmp.py —— 造 icmp.pcap：ICMP echo data 字段分片藏 PNG，混入普通 ping 噪声
import calendar
import io

from PIL import Image, PngImagePlugin

# 藏的货：一张带 tEXt 的 PNG，切成 24 字节一片

buf = io.BytesIO()
img.save(buf, "PNG", pnginfo=meta)
PNG = buf.getvalue()
CHUNK = 24
pieces = [PNG[i:i + CHUNK] for i in range(0, len(PNG), CHUNK)]

t = [0.0]
pkts = []

    if src == C_IP:
        ether = Ether(src=C_MAC, dst=S_MAC)
    else:
        ether = Ether(src=S_MAC, dst=C_MAC)
    pkt = ether / IP(src=src, dst=S_IP if src == C_IP else C_IP) / p

    t[0] += 0.5
    pkts.append(pkt)

# 隧道主体：id=0x1337，seq 从 0 递增，data 字段放分片
for seq, piece in enumerate(pieces):
```

```python
# solve_icmp.py —— 按 id 分组、按 seq 排序，拼回 ICMP data 字段里的文件
import sys
from collections import defaultdict

streams = defaultdict(dict)          # {id: {seq: bytes}}
for line in sys.stdin:
    ident, seq, hx = line.strip().split("\t")
    if not hx:
        continue                     # 有的 echo 头后没有 data 字段
    streams[ident][int(seq)] = bytes.fromhex(hx)

for ident, frags in streams.items():
    print(f"id={ident}: {len(frags)} 片，seq {min(frags)}~{max(frags)}")
    data = b"".join(frags[s] for s in sorted(frags))
    if int(ident) == 0x1337:
        open("secret.png", "wb").write(data)
        print(f"  -> secret.png {len(data)} B")
    else:
        print(f"  -> 普通流量，拼接样本 {data[:20]!r}，不入库")
```

```text
secret.png: PNG image data, 64 x 48, 8-bit/color RGB, non-interlaced
File: secret.png (185 bytes)
```

pngcheck 报 4 个 chunk 全部干净——拼接无误；flag 在 tEXt 块里，exiftool 一条命令取回（chunk 结构见 [[M02-文件格式深拆I-PNG全解|M02]]）。

> [!warning] 拼接前先做两道过滤
> 第一道按 `icmp.type==8`：echo 应答（type 0）的 data 与请求一字不差，混进重组流就是整体翻倍。第二道按 id 分组：不同会话的 ping 别拼在一起，上面 id=1 的普通流量就是这样被剔除的。seq 的起点（0 还是 1）从数据本身判断——第一片是不是文件头，一眼可辨。

> [!note] 常见变体
> 真题的变体是加大识别与排序难度：id 逐包随机（分组键换成时间顺序）、序号不写在 seq 而写进 data 前 2 字节、数据只出现在 reply 方向。分组键跟着变，重组思路不变。data 字段整体再过一层 base64 或加密（[[08-编码与古典密码|08 章]]）也很常见，剥层顺序是先重组后解码。

## 8. DNS 隧道完整还原

[[12-隐写与流量取证|12 章 7.3]]对 DNS 隧道也只给了一句话（子域名拼 flag）；完整的 DNS 隧道要传整个文件，通常双向都用：查询名带出数据，TXT 记录带回数据。

### 8.1 靶：查询带走文件，TXT 带回口令

协议设计：出方向把文件 base32 编码后切片，每片放进一个查询的子域名标签，序号前缀保证顺序可还原，固定后缀 `.up.tunnel.example.com` 当频道名；回方向，服务器在每条应答的 TXT 记录里带回另一路数据（本靶是一段口令提示，格式 `序号:分片`），不带数据的应答回 ACK。

选 base32 而不是 base64 有明确理由：DNS 域名大小写不敏感，链路上可能被统一改写大小写，全大写的 base32（字母表 A–Z、2–7，[[08-编码与古典密码|08 章]]）不会被改坏。单个标签最长 63 字符，所以分片长度留足余量取 32。base32 每字符携带 5 位，编码 n 字节得：

$$\text{base32 字符数} = \left\lceil \frac{8n}{5} \right\rceil \tag{8.1}$$

```python
# build_dns.py —— 造 dns.pcap：子域名分片外传加密 zip，TXT 记录回传解压口令，外加普通查询噪声
import base64
import calendar
import os
import subprocess

from scapy.all import DNS, DNSQR, DNSRR, Ether, IP, UDP, wrpcap

BASE = calendar.timegm((2026, 10, 24, 16, 0, 0))
C_MAC, S_MAC = "52:54:00:12:34:56", "52:54:00:78:9a:bc"
C_IP, S_IP = "10.13.0.2", "10.13.0.1"
SUFFIX = ".up.tunnel.example.com"        # 固定域名后缀
CHUNK = 32                               # 每个标签最多 63 字符，留足余量

def b32_chunks(data):
    """base32 编码、去掉填充、切成定长片段"""
    s = base64.b32encode(data).decode().rstrip("=")
    return [s[i:i + CHUNK] for i in range(0, len(s), CHUNK)]

# 外传货：口令加密的 vault.zip（ZipCrypto，口令 st4sh-tunnel-2026）；先清掉旧产物再打包
for old in ("vault.zip", "flag.txt"):
    if os.path.exists(old):
        os.remove(old)
open("flag.txt", "w").write("flag{dns_qn4m3_r3assembled}\n")
os.utime("flag.txt", (BASE, BASE))     # 固定 mtime，zip 内嵌时间随之固定
subprocess.run(["zip", "-P", "st4sh-tunnel-2026", "-q", "vault.zip", "flag.txt"], check=True)
ZIP = open("vault.zip", "rb").read()
q_chunks = b32_chunks(ZIP)

# 回传货：TXT 记录分片送出口令提示，骑在外传查询的应答里
PWD_MSG = b"PWD:st4sh-tunnel-2026"
t_chunks = b32_chunks(PWD_MSG)

t = [0.0]
pkts = []
def add(p, src=C_IP):
    if src == C_IP:
        ether = Ether(src=C_MAC, dst=S_MAC)
    else:
        ether = Ether(src=S_MAC, dst=C_MAC)
    pkt = ether / IP(src=src, dst=S_IP if src == C_IP else C_IP) / p
    pkt.time = BASE + t[0]                # 先组装、后赋时间戳，避免被顶层覆盖
    t[0] += 0.5
    pkts.append(pkt)

def tunnel_round(seq, chunk):
    """一对查询/TXT 应答：查询带出方向分片，应答 TXT 带回方向分片"""
    qname = f"{seq:02d}.{chunk}{SUFFIX}"
    txt = (f"{seq:02d}:{t_chunks[seq]}" if seq < len(t_chunks) else "ACK").encode()
    add(UDP(sport=40000 + seq, dport=53) /
        DNS(id=0x1000 + seq, rd=1, qd=DNSQR(qname=qname, qtype="TXT")))
    add(UDP(sport=53, dport=40000 + seq) /
        DNS(id=0x1000 + seq, qr=1,
            qd=DNSQR(qname=qname, qtype="TXT"),
            an=DNSRR(rrname=qname, type="TXT", ttl=60, rdata=txt)),
        src=S_IP)

# 噪声：一次普通 A 记录查询
add(UDP(sport=40100, dport=53) /
    DNS(id=0x0900, rd=1, qd=DNSQR(qname="www.example.com", qtype="A")))
add(UDP(sport=53, dport=40100) /
    DNS(id=0x0900, qr=1, qd=DNSQR(qname="www.example.com", qtype="A"),
        an=DNSRR(rrname="www.example.com", type="A", rdata="93.184.216.34", ttl=300)),
    src=S_IP)

for seq, chunk in enumerate(q_chunks):          # 出方向分片在查询名里，回方向分片在应答 TXT 里
    tunnel_round(seq, chunk)

wrpcap("dns.pcap", pkts)
print(f"dns.pcap 共 {len(pkts)} 个包；vault.zip {len(ZIP)} B -> {len(q_chunks)} 个查询分片；"
      f"口令消息 {len(PWD_MSG)} B -> {len(t_chunks)} 个 TXT 分片")
```

输出：

```text
dns.pcap 共 26 个包；vault.zip 222 B -> 12 个查询分片；口令消息 21 B -> 2 个 TXT 分片
```

先看两个通道的原始数据长什么样：

```bash
tshark -r dns.pcap -Y 'dns.flags.response==0' -T fields -e dns.qry.name | head -3
tshark -r dns.pcap -Y 'dns.flags.response==1 && dns.txt' -T fields -e dns.id -e dns.txt | head -4
```

输出：

```text
www.example.com
00.KBFQGBAKAAEQAAAAAAAFSXLVAVEXUKAA.up.tunnel.example.com
01.AAABYAAAAAEAAHAAMZWGCZZOOR4HIVKU.up.tunnel.example.com
```

```text
0x1000	00:KBLUIOTTOQ2HG2BNOR2W43TFNQWTEMBS
0x1001	01:GY
0x1002	ACK
0x1003	ACK
```

查询名第一段是序号、第二段是分片、后缀是频道；TXT 的格式是 `序号:分片`，不带数据的应答是 ACK。`dns.flags.response==0` 筛查询、`==1` 筛应答，`dns.txt` 存在才匹配，噪声查询天然落不到 TXT 通道里。

### 8.2 还原查询通道

```python
# solve_dns.py —— DNS 隧道重组。用法：
#   python3 solve_dns.py name < 提取的 qry.name 列表   -> 还原 vault_restored.zip
#   python3 solve_dns.py txt  < 提取的 dns.txt 列表    -> 还原 TXT 回传消息
import base64
import re
import sys

SUFFIX = ".up.tunnel.example.com"
mode = sys.argv[1]
frags = {}
for line in sys.stdin:
    line = line.strip()
    if mode == "name":
        if not line.lower().endswith(SUFFIX):
            continue                     # 后缀对不上：普通查询，跳过
        head = line[: -len(SUFFIX)]
        seq, _, chunk = head.partition(".")
        frags[int(seq)] = chunk
    else:
        m = re.fullmatch(r"(\d+):([A-Z2-7]+)", line)
        if not m:
            continue                     # 不符合 "序号:分片" 格式，跳过
        frags[int(m.group(1))] = m.group(2)

print(f"收到 {len(frags)} 个分片，序号 {min(frags)}~{max(frags)}")
b32 = "".join(frags[s] for s in sorted(frags))
data = base64.b32decode(b32 + "=" * (-len(b32) % 8))
if mode == "name":
    open("vault_restored.zip", "wb").write(data)
    print(f"vault_restored.zip 还原完成，{len(data)} 字节")
else:
    print(f"TXT 回传消息: {data.decode()}")
```

```bash
tshark -r dns.pcap -Y 'dns.flags.response==0' -T fields -e dns.qry.name \
    | python3 solve_dns.py name
md5sum vault.zip vault_restored.zip
```

输出：

```text
收到 12 个分片，序号 0~11
vault_restored.zip 还原完成，222 字节
93286fb8dce513ad8d22d9577890211e  vault.zip
93286fb8dce513ad8d22d9577890211e  vault_restored.zip
```

两个 md5 一致——==重组结果与原始文件逐字节相同==，这与 [[M02-文件格式深拆I-PNG全解|M02 3 节]]的 CRC 校验是同一个思想：还原有没有出错，拿校验值说话，不靠肉眼。注意对照的是同一次打包内的两个副本：ZipCrypto 的 12 字节加密头里 11 字节是随机的，每次重跑 build_dns.py 打出的 vault.zip 字节都不同，重组端拼出的也随之不同——但每一轮内"原件 vs 还原件"必然一致。

> [!note] 解码报 Incorrect padding 的原因
> 分片按 32 字符切，总长不一定是 8 的倍数，而 base32 解码要求长度为 8 的倍数。脚本里 `"=" * (-len(b32) % 8)` 把填充补回去再解——8.1 的式 (8.1) 算出的字符数是编码后的长度，切片剥掉填充后长度已经变了。

> [!note] 真实隧道工具长什么样
> 教学靶把分片明文摆在标签里；工业级工具 dnscat2、iodine 会把载荷加密后再编码、用 TXT/NS/MX 多种记录类型轮换、分片大且密集。识别入口不变：`-z io,phs` 里 DNS 占比反常、查询名长度分布异常（大量接近 63 字符的标签）、同一后缀的查询高频出现。还原思路与本章相同：剥协议外壳 → 按序拼接 → 解码 → 按容器进 [[M01-MISC导论与工具箱|M01]]的工作流。

## 9. 常见问题

| 现象 | 原因与解决 |
| ---- | ---- |
| tshark 读文件报 Only read filters, not capture filters | 把 BPF 捕获过滤器写进了 `-f`。读文件用 `-Y` 显示过滤器，`-f` 只配 `-i` 抓包用（4.3） |
| `-T fields -e` 提出来的列全是空 | 字段名写错，或该包根本没有这一层。`tshark -G fields \| grep 关键词` 核对拼写；字段名以 Wireshark 包详情括号里的名字为准 |
| `-z` 统计和逐包列表混在一起 | 忘了 `-q`。统计类命令一律加 `-q` 只出统计（4.1） |
| 手撕解析器在 pcapng 上直接抛异常 | pcapng 的 magic 与块结构都不同（3.4 折叠框）。先 `file` 认格式，或 `editcap -F pcap` 转回经典 pcap |
| HTTP 服务在偏门端口，`-Y http` 筛不出任何包 | 解析器按端口分发。`-d tcp.port==5010,http` 强制解析，Wireshark 里用 Decode As（5.5） |
| 导出对象名是 object5.image/png 这类兜底名 | 命名规则是 Content-Disposition > URI 末段 > 兜底。对象名只是线索，`file` 认真身（5.2） |
| multipart 切出的文件缺头缺尾 | 部件头与内容以 `\r\n\r\n` 分界、内容末尾的 `\r\n` 属于分界行、结尾的 `--boundary--` 不是部件，三处都要处理（5.4） |
| ICMP 重组的文件打不开 | 混入了 echo reply（type 0）或不同 id 的普通 ping。先 `icmp.type==8` 再按 ident 分组（7.2） |
| base32 拼接后解码报 Incorrect padding | 分片剥掉了填充，总长不是 8 的倍数。补齐 `=` 再解（8.2） |
| 自定义协议逐包解帧在真实 pcap 上错位 | TCP 不保证一帧一包：合并与分段都会打乱边界。先按流重组（`-z follow,tcp,raw,N`）再解帧，帧边界由长度字段找回（6.4） |
