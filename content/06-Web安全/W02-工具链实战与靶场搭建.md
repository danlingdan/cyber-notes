## Toolchain in Practice & Building Your Own Labs

## 1. 本章定位

[[11-Web安全版图与Burp#2. 工具链|11 章的工具链一节]]用一览表给过工具的一句话定位：Proxy 抓包、Repeater 改重放、Intruder 爆破。表能回答"这是什么"，回答不了"怎么用到能干活"——监听地址绑错、拦截规则配反、字典打完不知道哪个命中，都是动手之后才会遇到的问题。本章按"先有靶、再用工具"的顺序把这些问题过一遍，报文结构的细节在 [[W01-Web安全导论与HTTP深化|W01]] 已经深化过，这里直接用。

过程中还有一个反复出现的背景需求：学每类漏洞都需要一个可以随意测试的服务。在线平台的题目打完就关、看不到代码，比赛靶机赛后再也连不上。==自建靶场把漏洞点、源码、运行方式都放在自己手里==：改一行代码就能观察"防御加上之后攻击怎么失效"，这个实验在线平台做不了。第 2 节先把靶场方法建立起来，本章后面所有演示都打在它上面。

> [!note] 本章的实验约定
> 靶场统一用 PHP 内置服务器与 Python 标准库起在 82XX 段端口（8200 起步），流量全部用 curl 发起，curl 一律加 `--noproxy '*'`——该参数让 curl 跳过环境里配置的一切代理（系统代理、`http_proxy` 一类环境变量）直连目标，避免代理软件改了响应还查不出原因。命令与输出成对给出，输出块标题写"输出："。

## 2. 自建靶场：php -S 与 Python 标准库

### 2.1 为什么自建

四个理由，按重要程度排：

| 理由 | 说明 |
| ---- | ---- |
| 可控 | 漏洞在哪一行是自己写的，"输入 → 代码路径 → 输出"全程可追踪，不用对着黑盒猜 |
| 可改 | 把漏洞行包上 `htmlspecialchars()`、改成参数化查询，立刻得到"修好的版本"，对比攻击结果的变化 |
| 可复现 | 一个目录加一条命令就是全部材料，换台机器照跑，写笔记不缺现场 |
| 断网可用 | 全部流量走 127.0.0.1，不需要外网，也不给真实站点发一个字节 |

现成镜像靶场（[[13-Docker与赛题环境|13 章]]拉起的 sqli-labs、DVWA 之类）适合按题型刷关卡，自建靶场适合学原理，两者互补，本章讲后者。

### 2.2 php -S：一行命令起一个网站

PHP 内置服务器随 php 一起装好，不需要 Apache/Nginx。常用形式一张表：

| 用法 | 作用 |
| ---- | ---- |
| `php -S 127.0.0.1:8200` | 监听 127.0.0.1:8200，文档根是当前目录 |
| `-t 目录` | 指定文档根目录（默认当前目录） |
| `-S 0.0.0.0:8200` | 绑所有网卡；只在 WSL 内测试用 127.0.0.1，要 Windows 浏览器访问才改 0.0.0.0 |
| `-c 文件` | 指定 php.ini（要开 `allow_url_include` 这类配置时用） |
| `-d 键=值` | 单项覆盖配置，如 `-d display_errors=1`，不用专门写 ini 文件 |

它是单进程服务器，同一时刻只处理一个请求，速度慢也不抗并发——生产环境不用它，当靶场正合适：==请求次序完全确定，不会出现并发干扰==。

> [!info]- router 脚本：接管所有请求
> `php -S 127.0.0.1:8200 router.php` 的第三个参数是 router 脚本：每个 HTTP 请求先执行它，脚本返回 `false` 时按静态文件处理，返回字符串则当作响应体。要做"所有路径都进同一个函数"的靶子（路由型应用）就用它，比在 index.php 里写一串 if-elseif 干净。

### 2.3 最小漏洞页模板

一个文件同时提供两类靶点：GET 参数回显（练反射型 XSS、编码问题）和 POST 登录口（练爆破、注入），后续章节在这个模板上加功能。`index.php` 全文：

```php
<?php
// index.php —— 最小漏洞页模板：GET 参数回显 + POST 登录判断
$name = $_GET['name'] ?? 'guest';              // 漏洞点：未转义直接回显进 HTML
$msg  = '';
if ($_SERVER['REQUEST_METHOD'] === 'POST') {   // 登录口：响应内容有差异，供爆破判别
    $user = $_POST['user'] ?? '';
    $pass = $_POST['pass'] ?? '';
    $msg  = ($user === 'admin' && $pass === 'admin123')
          ? 'login ok, flag{w02_l4b_b4s1c}'
          : 'login failed';
}
?>
<!doctype html>
<html>
<head><meta charset="utf-8"><title>W02 lab</title></head>
<body>
  <h1>Hello, <?= $name ?>!</h1>
  <form method="POST" action="/">
    user: <input name="user">
    pass: <input name="pass" type="password">
    <button>login</button>
  </form>
  <?php if ($msg !== ''): ?>
  <p><?= $msg ?></p>
  <?php endif; ?>
</body>
</html>
```

启动并访问。GET 请求把 `?name=` 原样嵌进 `<h1>`：

```bash
php -S 127.0.0.1:8200 -t .
```

输出：

```
[Fri Oct 23 18:35:33 2026] PHP 8.5.4 Development Server (http://127.0.0.1:8200) started
```

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8200/?name=ctf'
```

输出：

```
<!doctype html>
<html>
<head><meta charset="utf-8"><title>W02 lab</title></head>
<body>
  <h1>Hello, ctf!</h1>
  <form method="POST" action="/">
    user: <input name="user">
    pass: <input name="pass" type="password">
    <button>login</button>
  </form>
  </body>
</html>
```

POST 登录口的对错两种结果，差别只在最后那一行 `<p>`：

```bash
curl -s --noproxy '*' -X POST -d 'user=admin&pass=wrong' http://127.0.0.1:8200/ | grep -o '<p>[^<]*</p>'
curl -s --noproxy '*' -X POST -d 'user=admin&pass=admin123' http://127.0.0.1:8200/ | grep -o '<p>[^<]*</p>'
```

输出：

```
<p>login failed</p>
<p>login ok, flag{w02_l4b_b4s1c}</p>
```

两种响应的状态码都是 200，==差别只在响应体的一行文字和总长度上==——记住这一点，第 4 节爆破全靠它当判别依据。

### 2.4 Python 回显靶：把收到的请求原样退回

[[06-Python与CTF脚本基础|06 章]] 用 `http.server` 起过站点，11 章的 ping 工具也是同一套写法。下面这个变体只做一件事：把收到的请求行和请求头原样打印回给客户端——验证"代理到底把我的请求改成了什么样"时，它是最直接的观测点。`echo_server.py` 全文：

```python
# echo_server.py —— 回显请求的 Python 靶机：验证代理与插件改写效果的最直接手段
from http.server import BaseHTTPRequestHandler, HTTPServer


class EchoHandler(BaseHTTPRequestHandler):
    def do_GET(self):
        lines = [f"{self.command} {self.path} {self.request_version}"]
        lines += [f"{k}: {v}" for k, v in self.headers.items()]
        data = "\n".join(lines).encode()
        self.send_response(200)
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.send_header("Content-Length", str(len(data)))
        self.end_headers()
        self.wfile.write(data)


HTTPServer(("127.0.0.1", 8220), EchoHandler).serve_forever()
```

后台运行 `python3 echo_server.py &`，curl 打过去，收回的就是靶机看到的原始请求：

```bash
curl -s --noproxy '*' http://127.0.0.1:8220/
```

输出：

```
GET / HTTP/1.1
Host: 127.0.0.1:8220
User-Agent: curl/8.18.0
Accept: */*
```

需要精细控制响应行为（按路径返回不同内容、按请求头变化响应、制造固定延迟）的靶子都从这个骨架改起；纯静态文件则直接 `php -S` 更省事。

### 2.5 目录组织与端口约定

建议在实验机上单独开一个目录放靶场，每章一个子目录：

```text
labs/
├── w02/
│   ├── index.php        # 最小漏洞页
│   ├── echo_server.py   # 回显靶
│   └── w02_addon.py     # mitmproxy 插件（第 5 节会用到）
├── w03/                 # 后续每章一个子目录
└── w04/
```

端口约定：每章占 82XX 段的十位（W02 用 8200、8210、8211、8220），靶机用段内最小的端口，代理、插件监听往后排。这样同时开几个靶也不冲突，看到端口号就知道是哪章的靶。后续各章的靶场均沿用这套做法，不再重复交代。

## 3. Burp 深入：Proxy 与 Repeater

### 3.1 Proxy：监听、拦截规则与 history

**监听配置**：设置对话框 → Tools → Proxy → Proxy listeners。默认有一条 127.0.0.1:8080，Binding 页改端口与绑定地址——只在本机用保持 loopback；要虚拟机或别的设备连进来才绑 0.0.0.0 并放行防火墙。浏览器代理指到这个地址即可开始抓包（FoxyProxy 配法见 [[11-Web安全版图与Burp#2.1 Burp Suite：中间人本尊|11 章 2.1]]）。不想装证书，用 Proxy → Intercept 标签里的 Open Browser：Burp 内置的浏览器自动信任 Burp 的 CA，HTTPS 不装证书就能抓。

**拦截与条件规则**：Proxy → Intercept 的 "Intercept is on/off" 是总开关，开着时每条请求都停下来等 Forward——逐条点很快就烦，实际用法是配**条件规则**只拦关心的请求：设置对话框 → Tools → Proxy → "Intercept requests based on the following rules" → Add。每条规则四个要素：

| 要素 | 内容 | 例子 |
| ---- | ---- | ---- |
| 布尔关系 | 与上一条规则之间 AND / OR | 两条规则要同时满足用 AND |
| 匹配类型 | 域名、IP、协议、HTTP 方法、URL、文件扩展名等 | URL |
| 匹配关系 | Matches / Does not match / Is in target scope 等 | Matches |
| 条件值 | 字符串或正则 | `^/login` |

"只拦 method 为 POST 且 URL 以 /login 开头的请求"就是两条 AND 规则；不匹配的请求自动放行，浏览器不弹任何提示。

**HTTP history**：Proxy → HTTP history 列出所有经过代理的请求。表格上方的过滤栏按 MIME 类型、状态码、关键词筛选，搜索框跨所有列匹配底层原始数据；Filter on/off 一键在过滤视图与全量视图之间切换且不丢条件。读一条请求重点看三处：Inspector 拆开的参数与 cookie、响应的状态行与头部、响应体里回显输入的位置。

**scope**：Target → Scope → Add，按协议 + 主机 + 端口 + 路径把靶机圈进来。拦截规则可以引用 Is in target scope，history 可以只显示 scope 内条目，Intruder 和扫描器对 scope 外目标会警告。

> [!warning] 先定 scope，再上自动化
> 对无权测试的目标发起爆破或扫描是违规行为。开工前把 scope 圈到靶机地址，让工具发出的每一条请求都落在授权范围内；scope 之外的目标，工具碰不到，你也碰不到。

### 3.2 Repeater：手工改重放

在 history 里右键 → Send to Repeater（快捷键 Ctrl+R）把请求送进一个标签。标签可以双击重命名、右键改颜色，一道题开一组标签是常规用法。

面板布局：同一标签内请求面板与响应面板上下同屏，分隔条可拖。改一处、点 Send、响应立即出现在右半屏，==响应面板顶部标着响应字节数和耗时毫秒数，这两个读数就是"响应有没有变"的第一判据==——第 4 节爆破做的正是把这两列读数自动化。

消息编辑器顶部有四个视图标签：

| 视图 | 用途 |
| ---- | ---- |
| Pretty | 自动缩进排版 JSON/XML/HTML/JS，读结构化响应先用它 |
| Raw | 原始报文，改请求在这里 |
| Hex | 十六进制视图，每行 16 字节，看不可见字符、插删字节 |
| Render | 把 HTML/图片响应按浏览器效果渲染出来，验证 XSS 类回显常用 |

编辑器底部有搜索栏：输入关键词即时高亮全部命中，方向键逐个跳转——长响应里找自己的输入（回显点、报错、flag）就靠它；先选中一段文字再按 Ctrl+S，选中的词在全文高亮。右侧 Inspector 侧栏把请求拆成 Request attributes、Header、参数、Cookie 几组名值对，值会自动逐层解码（HTML → URL → Base64，每层都能单独剥掉），比在 Raw 里肉眼解编码快。

换行风格有专门控制：请求 Inspector 的 Request attributes 里有一个 `\n` 切换按钮，把请求行的换行在 `\r\n`（标准）与 `\n`（省掉回车）之间切换；对应的全局设置是 Repeater 设置里的 Normalize HTTP/1 line endings（默认给每行补回 `\r`）。测"服务器对两种换行处理是否不一致"时，动的就是这两处。

右键菜单两个高频项：**Follow redirection**——响应是 302 时一键跟随跳转再发一次，配合设置里的 Process cookies in redirects 自动带上跳转响应种下的 cookie，登录成功后跳转的场景常用；**Show response in browser**——Burp 生成一个经代理的临时 URL，把这条响应放进真实浏览器看渲染与 JS 行为。

> [!note] Update Content-Length 默认开着
> Repeater 设置里的 Update Content-Length 默认启用：改完 body 自动重算 Content-Length。手动编辑忘掉这一步，服务器按旧长度截断或拼接 body，是"明明改对了却没生效"的经典原因，遇到行为异常先核对长度与头部。

> [!info]- 版本差异与找设置的最快方法
> Burp 界面随版本变动较大（旧版 Proxy 的配置在 Proxy → Options 子标签，新版收进了设置对话框），本章写的是较新版本的路径。找不到某项设置时，用设置对话框顶部的搜索框直接搜关键词（Content-Length、Intercept……），比记菜单层级可靠。Community 与 Professional 的功能差异集中在自动化：Intruder 限速、扫描器只在 Professional 可用；手工测试三件套 Proxy/Repeater/Decoder 两版都有。

## 4. Intruder 深入：自动化爆破

### 4.1 四种攻击模式

入口：history 或 Repeater 右键 → Send to Intruder。Positions 页用 `§` 包住变量（Add § / Clear § / Auto §，Auto § 把所有参数值一键标成位置），消息编辑器上方的下拉选攻击类型。四种模式的全部区别就是"几个位置、配几组 payload、怎么配"：

| 模式 | 组合方式 | 请求次数 | 适用场景 |
| ---- | ---- | ---- | ---- |
| Sniper（默认） | 一组 payload 依次填进每个位置：位置 1 穷尽后换位置 2 | 位置数 × payload 数 | 单参数探测：某个字段注入、单字段爆破 |
| Battering ram | 一组 payload 同时填进所有位置 | payload 数 | 多个位置要同一个值（cookie 与 body 同值） |
| Pitchfork | 每个位置各一组 payload，第 i 个配第 i 个并行推进 | 最短那组的长度 | 成对数据：已知的用户名-密码对、ID 与配套字段 |
| Cluster bomb | 每个位置各一组 payload，取全部组合 | 各组数量的乘积 | 用户名 × 密码全组合爆破 |

### 4.2 payload 类型与处理

Payloads 页选 payload 类型，最常用四种：

| 类型 | 干什么 | 什么时候用 |
| ---- | ---- | ---- |
| Simple list | 粘贴或载入一份列表 | 绝大多数场景，自带若干常用小字典 |
| Runtime file | 攻击运行时逐行读文件 | 超大字典，避免整份装进内存 |
| Brute forcer | 给定字符集与长度范围，生成全排列 | 短验证码、短 token（数量随长度指数涨） |
| Null payloads | payload 为空串，只重复发基请求 | 保活 session、测速率限制、制造重复请求 |

Payload processing 在每个 payload 进请求前按顺序过一遍规则链：加前后缀、Match/replace、hash（MD5/SHA 系列）、encode/decode（Base64、URL 等）——"字典里的密码要先 MD5 再提交"这类需求靠它，不必手工生成一份 hash 字典。Payload encoding 部分控制在发送前对哪些字符做 URL 编码。

### 4.3 判别响应：Grep - Match 与 Grep - Extract

攻击结果是一张表，一行一个 payload。判别命中靠两件内置工具：

- **Grep - Match**：给一串关键词，结果表多一列勾选框，响应里含该词就打勾——把 `login ok` 配进去，勾就是命中；
- **Grep - Extract**：在攻击设置页 Grep - Extract → Add，用正则或起止串定义一段要抽取的内容，每个响应抽出的文字单列显示——把 `<p>[^<]*</p>` 配进去，每个 payload 对应的登录结果直接排成一列，不必逐行点开响应。

### 4.4 Community 限速与命令行等价做法

> [!warning] Community 版的 Intruder 有限速
> Community 版对 Intruder 攻击内置速率限制，请求之间被强制插入等待，大字典实际不可用。没有 Professional 时，等价做法就是本节的脚本——Intruder 的本质是"按模式组合参数、发请求、按规则判别响应"，几十行 Python 全都做得到。

下面是 Cluster bomb 的命令行等价：用户名 × 密码全组合打 2.3 节的登录口，判别依据是响应内容（失败响应长度全部相同，命中行更长且含 `login ok`）。`brute_login.py` 全文：

```python
# brute_login.py —— Intruder Cluster bomb 的命令行等价：用户名 × 密码全组合
# 判别依据不是状态码（失败也是 200），而是响应内容里的差异
import itertools

import requests

URL = "http://127.0.0.1:8200/"
s = requests.Session()
s.trust_env = False                      # 不读系统代理设置，等价于 curl 的 --noproxy '*'

users = ["admin", "root", "guest"]
passwords = ["123456", "password", "admin123", "letmein"]

for user, password in itertools.product(users, passwords):
    r = s.post(URL, data={"user": user, "pass": password})
    mark = "  <== hit" if "login ok" in r.text else ""
    print(f"{user:<6s} {password:<10s} len={len(r.text):4d}{mark}")
```

靶机保持运行（2.3 节启动的 php -S），执行：

```bash
python3 brute_login.py
```

输出：

```
admin  123456     len= 302
admin  password   len= 302
admin  admin123   len= 319  <== hit
admin  letmein    len= 302
root   123456     len= 302
root   password   len= 302
root   admin123   len= 302
root   letmein    len= 302
guest  123456     len= 302
guest  password   len= 302
guest  admin123   len= 302
guest  letmein    len= 302
```

`itertools.product` 就是 Cluster bomb 的笛卡尔积；`len` 列对应 Intruder 结果表的响应长度列；`mark` 的判定就是 Grep - Match。把 users 和 passwords 换成读文件、每发之间加 `time.sleep()`，又分别对应 Runtime file 和 Resource pool 的限速。==结构对上了，剩下只是字典大小==。

## 5. mitmproxy：可编程的命令行代理

Burp 是图形界面程序，受 GUI 限制：进不了无人值守的脚本流程，改包逻辑要写插件装进去。mitmproxy 把同样的中间人代理做成了命令行工具，==HTTP/HTTPS 流量的截获、查看、改写全部可以进 Python 脚本==。

### 5.1 三种形态与安装

| 命令 | 形态 | 用在哪 |
| ---- | ---- | ---- |
| `mitmproxy` | 终端交互界面 | 手工看流量：方向键选 flow，回车看详情，q 退出 |
| `mitmweb` | 浏览器界面 | 想要图形界面时的替代，Web 界面在 127.0.0.1:8081（代理本身仍在 8080，两个端口别混） |
| `mitmdump` | 无界面 | 本章使用的形态：打日志、跑插件、录流量，可进脚本与定时任务 |

三者是同一引擎的不同外壳，代理默认都监听 8080，`--listen-port` 换端口。安装进独立的虚拟环境，避免和系统 Python 包冲突：

```bash
sudo apt-get install -y python3-venv
python3 -m venv /opt/mitmenv
/opt/mitmenv/bin/pip install mitmproxy
/opt/mitmenv/bin/mitmdump --version
```

输出：

```
Mitmproxy: 12.3.0
Python:    3.14.4
```

### 5.2 起代理，看流量

2.3 节的靶机保持运行，另开一个终端起 mitmdump：

```bash
/opt/mitmenv/bin/mitmdump --listen-port 8210
```

输出：

```
[18:37:12.391] HTTP(S) proxy listening at *:8210.
```

第三个终端，先直连、再走代理各请求一次：

```bash
curl -s --noproxy '*' 'http://127.0.0.1:8200/?name=direct' | grep '<h1>'
curl -s -x http://127.0.0.1:8210 'http://127.0.0.1:8200/?name=via_mitm' | grep '<h1>'
```

输出：

```
  <h1>Hello, direct!</h1>
  <h1>Hello, via_mitm!</h1>
```

两条请求都正常拿到页面。代理侧终端此刻已经打印出第二条请求的完整轨迹：

```
[18:37:14.153][127.0.0.1:47310] client connect
[18:37:14.156][127.0.0.1:47310] server connect 127.0.0.1:8200
127.0.0.1:47310: GET http://127.0.0.1:8200/?name=via_mitm
              << 200 OK 281b
[18:37:14.157][127.0.0.1:47310] server disconnect 127.0.0.1:8200
[18:37:14.157][127.0.0.1:47310] client disconnect
```

逐行读：curl 先连上代理（client connect），代理再去连靶机（server connect），然后是请求行与响应行（状态 200、响应 281 字节），最后两侧断开。==日志里只有 via_mitm 这一条：加 `--noproxy` 直连的那条根本没经过代理==——代理看到的永远只是"经过它的流量"，Burp 的 HTTP history 遵循同一条规则。

### 5.3 录制与回放

`-w` 把经过代理的流量原样存盘；`-r` 配 `-n`（不起代理、只读文件）回放。靶机保持运行，起一个带 `-w` 的代理：

```bash
/opt/mitmenv/bin/mitmdump --listen-port 8210 -w flows.mitm
```

输出：

```
[18:35:22.770] HTTP(S) proxy listening at *:8210.
```

另开终端，经代理发一条 GET（`curl -s -x http://127.0.0.1:8210 'http://127.0.0.1:8200/?name=record_a'`）和一条 POST（`curl -s -x http://127.0.0.1:8210 -X POST -d 'user=admin&pass=wrong' http://127.0.0.1:8200/`），代理终端会像 5.2 节那样打出两条 flow；然后 Ctrl-C 停掉代理，流量已经写进 `flows.mitm`。回放刚录下的文件：

```bash
/opt/mitmenv/bin/mitmdump -nr flows.mitm
```

输出：

```
127.0.0.1:46262: GET http://127.0.0.1:8200/?name=record_a
              << 200 OK 281b
127.0.0.1:46274: POST http://127.0.0.1:8200/
              << 200 OK 302b
```

GET 和 POST 连同请求头、响应头、响应体完整还原。典型用途：把靶机流量录下来离线分析，或交给插件做二次处理。

### 5.4 插件：用 Python 改写流量

`-s` 给代理挂一个 Python 脚本，每条流量经过都触发钩子。改写请求头与响应内容的完整插件，`w02_addon.py` 全文：

```python
# w02_addon.py —— mitmproxy 插件：改写请求头与响应内容
import logging


class W02Addon:
    def request(self, flow):
        # 每条请求经过代理时执行：换掉 User-Agent，补一个标记头
        flow.request.headers["User-Agent"] = "w02-addon/1.0"
        flow.request.headers["X-CTF-Lab"] = "w02"

    def response(self, flow):
        # 每条响应返回时执行：把页面里的 Hello, 换成标记文本
        if flow.response.headers.get("content-type", "").startswith("text/html"):
            flow.response.set_text(
                flow.response.get_text().replace("Hello,", "[addon] hello,"))
        logging.info("%s -> %d bytes" % (flow.request.path, len(flow.response.content)))


addons = [W02Addon()]
```

挂上插件起代理（按端口约定排到 8211）：

```bash
/opt/mitmenv/bin/mitmdump --listen-port 8211 -s w02_addon.py
```

输出：

```
[18:40:25.915] Loading script w02_addon.py
[18:40:25.933] HTTP(S) proxy listening at *:8211.
```

先打 PHP 靶的回显点，再看回显靶（2.4 节的 echo_server.py，监听 8220）收到的请求头：

```bash
curl -s -x http://127.0.0.1:8211 'http://127.0.0.1:8200/?name=addon' | grep '<h1>'
curl -s -x http://127.0.0.1:8211 -A 'original-agent' 'http://127.0.0.1:8220/'
```

输出：

```
  <h1>[addon] hello, addon!</h1>
```

```
GET / HTTP/1.1
Host: 127.0.0.1:8220
User-Agent: w02-addon/1.0
Accept: */*
Proxy-Connection: Keep-Alive
X-CTF-Lab: w02
```

两个方向都验证到：response 钩子把页面里的 `Hello,` 换成了 `[addon] hello,`；request 钩子把 curl 发出的 `original-agent` 整个换成 `w02-addon/1.0`，并补上了 `X-CTF-Lab` 头——回显靶收到的就是改写后的请求。插件里 `logging.info` 打的日志同时出现在代理终端上：

```
[18:40:27.680] /?name=addon -> 286 bytes
[18:40:27.687] / -> 117 bytes
```

每条流过的请求，路径与响应字节数一目了然。

> [!warning] 改写作用于所有流量
> 钩子对经过代理的每一条请求生效，不是只有 curl 发的那条——挂着改写插件用浏览器上网，每个页面都会被改。实验结束随手停掉代理；要缩小生效范围，在钩子开头按 host 或路径加条件判断。

### 5.5 HTTPS 证书与 Burp 对比

HTTPS 拦截两者用同一套原理：代理持有自己签发的 CA 证书，对每个站点现场签一张假证书交给客户端，把真实流量在代理处解密；客户端必须信任这张 CA 才不报警。安装途径：Burp 是开着代理访问 `http://burp` 下载证书（[[11-Web安全版图与Burp#2.1 Burp Suite：中间人本尊|11 章 2.1]]装过），mitmproxy 是首次启动时把 CA 生成在 `~/.mitmproxy/` 下，浏览器开着代理访问 `http://mitm.it` 按平台下载安装。

| 维度 | Burp Suite | mitmproxy |
| ---- | ---- | ---- |
| 界面 | 图形界面，Community 版免费 | 终端 mitmproxy / 浏览器 mitmweb / 无界面 mitmdump |
| 改写方式 | 手工改，或写插件（Java/Jython）装进 GUI | Python 脚本直接挂 `-s`，改一行重启生效 |
| 自动化与 CI | GUI 程序，难以进无人值守流程 | mitmdump 无界面，可直接进脚本与流水线 |
| 证书 | 自签 CA，`http://burp` 下载 | 同一原理，CA 在 `~/.mitmproxy/`，`http://mitm.it` 下载 |

选型标准一句话：手工测试、看页面、配合扫描器，Burp 顺手；要"流量经过就自动改一点什么"、要进脚本、要在没有图形界面的环境里跑，mitmproxy。==两者代理的是同一类流量，用熟一个，另一个只剩界面差异==。

> [!info]- mitmproxy 交互界面速览
> `mitmproxy` 界面里：方向键在 flow 列表移动，回车进详情（再按 tab 在请求/响应间切换），q 返回或退出；`f` 输入过滤表达式，如 `~u login`（URL 含 login）、`~m POST`（POST 请求）；`w` 把选中的 flow 存盘。完整表达式语法在 docs.mitmproxy.org 的 filters 一节。

## 6. Decoder、Comparer 与插件生态

**Decoder** 是编解码工作台。转换可以叠多层（URL 编码外面套 Base64、外面再套 Hex），从外到内逐层剥；Smart decode 按钮自动猜当前内容的编码方式一键剥一层。手工构造"先编码再嵌进参数"的 payload、还原响应里的编码串，都用它。从 history 或 Repeater 选中文字右键 Send to Decoder 直接带过去。

**Comparer** 做两段内容的差异对比，支持字符、词、字节三种粒度。把两个疑似只有细微差别的响应各 Send to Comparer，点 Compare，差异逐块标色。"这两个响应到底有没有实质区别"是盲注、越权判断里反复出现的问题，人眼对比几百字节的 HTML 不可靠。

**插件生态**：Extender → BApp Store 是官方插件市场，Community 版可安装免费插件。高频插件分四类，记类型比记名字有用：

| 类型 | 代表插件 | 干什么 |
| ---- | ---- | ---- |
| 隐藏参数发现 | Param Miner | 爆破探测请求里没出现过的参数名与请求头 |
| 越权检测 | Autorize | 用低权限会话重放高权限请求，自动对比响应找未授权访问 |
| 流量日志增强 | Logger++ | 全工具流量落库，支持多行表达式检索 |
| 扫描规则增强 | Active Scan++ | 补充扫描规则与 payload |

安装前看一眼插件的维护状态与适配的 Burp 版本；来源不明的第三方插件不要装——它能接触并修改你的全部流量。

## 7. 常见问题

| 现象 | 原因与解决 |
| ---- | ---- |
| 浏览器走 Burp 访问 HTTPS 报证书告警 | Burp CA 没装或装错位置：装进"受信任的根证书颁发机构"（[[11-Web安全版图与Burp#2.1 Burp Suite：中间人本尊\|11 章 2.1]]）；临时验证用 Proxy 标签里的 Open Browser 内置浏览器 |
| curl 的响应里混进了没见过的内容 | 系统代理往响应里插了东西：加 `--noproxy '*'` 直连复测 |
| `curl -x` 连 mitmdump 被拒绝 | 代理没起或端口不对：先确认启动行里的 `proxy listening at *:端口`（[[#5.2 起代理，看流量\|5.2]]） |
| mitmproxy 拦 HTTPS 时客户端报证书错误 | mitmproxy 的 CA 未被信任：安装 `~/.mitmproxy/mitmproxy-ca-cert.pem`，或开着代理访问 `http://mitm.it` 下载（[[#5.5 HTTPS 证书与 Burp 对比\|5.5]]） |
| php -S 报 Address already in use | 上次的进程还占着端口：`ss -ltnp \| grep 8200` 找到 PID 再 kill，或换端口 |
| Windows 浏览器连不上 WSL 里的靶机 | 靶机绑了 127.0.0.1 只在 WSL 内可见：改绑 `0.0.0.0` 或用 WSL 的 IP；只在 WSL 内 curl 测试时 127.0.0.1 更简单 |
| Intruder 或脚本跑完全部"失败" | 判别依据选错：登录失败也常返回 200，要盯响应内容或长度差异（[[#4.3 判别响应：Grep - Match 与 Grep - Extract\|4.3]]、[[#4.4 Community 限速与命令行等价做法\|4.4]]） |
| Repeater 里改了 body 却没生效 | Content-Length 没对上：确认 Repeater 设置里 Update Content-Length 开着（[[#3.2 Repeater：手工改重放\|3.2]]） |
| mitmdump 录制时报 unserializable object | 安装的 mitmproxy 与系统 Python 版本不匹配（发行版仓库里的旧包配新 Python 时出现）：按 [[#5.1 三种形态与安装\|5.1]] 用 venv 装新版 |
| `-r` 读出的 flow 比录的少 | 请求还没完成代理就被杀掉，数据没落盘：等响应回来再 Ctrl-C |
| mitmweb 的页面打不开 | Web 界面在 8081，代理在 8080，两个端口各管各的：浏览器访问的是 8081（[[#5.1 三种形态与安装\|5.1]]） |
