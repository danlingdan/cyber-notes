题目附件就两个文件：一个 42KB 的 ELF（C++ 写的"加密器"，链接 GMP，未 strip）和一份 `result.txt`——第一行 20 个不超过 30 的小整数，第二行 20 个几百位的大整数。程序把 80 字符的明文按 4 字节切块，每块取 nextprime 当链头，沿"`t ← t·j + 1`、j 取最小值使结果为素数"的链条走两百来步，步数还掺了 `rand()`。看起来是"不爆破时间种子就解不开"，实际上链条自己把回去的路标写进了每个大整数的因子分解里。

> [!info]- 这是一道什么类型的题
> 逆向题（reverse）：出题人给你**加密器**和**密文**，明文不给。你的任务是读懂加密器（反汇编），再想办法从密文把明文算回来。它跟 pwn 的分工不同——pwn 是"让程序执行我想执行的代码"，rev 是"让密文说出它知道的事"。这道题没有远程服务器，没有 shell，胜负全在"能不能看穿算法结构"上。

> [!info]- 适用对象与读法
> 会读 x86-64 汇编、知道素数是什么，就够了。GMP、Miller-Rabin 这些名词第一次出现时，正文下方都有**默认折叠的 callout**，点开从零讲起。
> 阅读顺序：导读 → 侦察定位 → 还原算法 → 数学分析 → 求解验证 → 复盘。只想看结论的，[[04-求解与闭环验证]] 开头的输出就是答案。

> [!info]- 基础技术用语
> - **GMP**：GNU Multiple Precision，C 语言的大数运算库。RSA 一类题目里 `__gmpz_*` 开头的函数全是它
> - **mpz_t**：GMP 的大整数类型。一个 mpz 变量在内存里是"当前字数 + 符号 + 数据指针"三件套，所以函数传参传的是它的**指针**
> - **素性检验**：判断一个数是不是素数。工程上用的几乎都是概率算法（Miller-Rabin），跑得快，误判率可控
> - **nextprime**：比 n 大的最小素数
> - **大端序**：多字节数据高位在前。"flag" 四个字节按大端读成整数是 0x666c6167（'f'=0x66 在最前）
> - **素数链**：本文的核心对象——从素数 p 出发反复做 `t ← t·j + 1`（j 取使结果为素数的最小正整数），每一环都是素数
> - **PIE**：位置无关可执行文件，每次加载到随机地址。对这道题无所谓，因为我们不碰内存布局，只读静态文件

## 题目文件与第一判断

文件阵容：`KMPC`（42360 字节）、`result.txt`（第 1 行 diff 列表，第 2 行 20 个大整数）。没有 README，没有远程端。

> [!important]- 拿到文件先形成的三个判断
> 1. **未 strip 的 C++ 程序 + 导入表里一堆 `__gmpz_*`**：算法库自己报了名字，不用猜"这是不是改过的 RSA"。符号表和导入表是出题人送的礼物 → [[01-侦察与GMP函数定位]]
> 2. **第 1 行是一排小整数（全部 ≤ 30）**：这行必然是某种"确定性距离"。出题人白给你一排数，先默认它有用——后面会看到它正好当回退终点的对账单 → [[03-素数链反向唯一性]]
> 3. **步数依赖 `srand(time(0))`**：表面在逼你爆破种子。先别顺着这个暗示走，把链的结构想清楚再决定——爆破是最贵的那条路，往往不是出题人留给你的路 → [[05-复盘与推广]]

全局架构：

```
          明文 flag（80 字符，20 块 × 4 字节）
                  │  4 字节按大端读成 32 位整数 m
                  ▼
        p = nextprime(m)          diff = p − m ──────→ result.txt 第 1 行
                  │  v = i + (key[i%20] ^ 0xCC) + rand()%65   ← key 藏在立即数里，v 未知
                  ▼
        素数链：t ← t·j + 1（j 取最小正整数且 t·j+1 为素数），走 v−1 步
                  │  每一步 t 都翻倍以上，链尾 q 涨到近两千位（比特）的大素数
                  ▼
        链尾 q ──────────────────────────────────→ result.txt 第 2 行

  解密（反向）：q − 1 = j × t，对每个小因子 j 做除法 + 素性检验，
  一层层退回链头 p，m = p − diff，4 块字节拼回明文
```

最终成果（WSL Ubuntu 26.04，纯 Python 标准库实测）：

```
block  0: steps= 169  pp=1718378861  m=0x666c6167
block  1: steps= 181  pp=2069442679  m=0x7b593075
block  2: steps= 178  pp=1601131879  m=0x5f6f555f
...
block 19: steps= 193  pp= 825257617  m=0x31306e7d

message : flag{Y0u_oU_u_4rE_Re_3_Go0d_OoD_0d_D_47_t_l1bgMp_4Nd_7h15_4sYmM3tr1c_3nCrYp710n}

real    1m22.324s
```

> [!info]- 逐行读这份输出
> - `steps`：这块链回退的步数（等于正向链长 v−1 加 1）。实测 169～230，正好落在 [[02-还原加密算法]] 推导的 v−1 ∈ [135, 272] 区间里——两个独立途径互相印证
> - `pp`：链头素数 p，也就是 `nextprime(m)`
> - `m=0x666c6167`：十六进制直接就是 ASCII——0x66='f'、0x6c='l'、0x61='a'、0x67='g'。每块 4 字符，20 块按顺序拼起来就是 flag
> - `real 1m22s`：纯 Python、零第三方库的耗时。作为对比，正向加密（C + GMP）同样这 80 字符要 63 秒——两边居然是同量级的，[[04-求解与闭环验证]] 里解释为什么

## 文件索引

| 文件 | 说明 |
|---|---|
| `solve_kmpc.py` | 单文件求解脚本，纯标准库，`python3 solve_kmpc.py result.txt` |
| `reproduce_local.sh` | 一键复现：求解拿 flag + 把 flag 喂回 KMPC 本体对拍 diff 行 |
| `assets/kmpc_disasm.txt` | 关键函数反汇编记录（capstone，Intel 语法），[[02-还原加密算法]] 的底稿 |

题目原始文件（`KMPC`、`result.txt`）不在这个目录，`reproduce_local.sh` 用 `KMPC_DIR=/path/to/ext.rev.not-symmetric` 指定。

## 快速上手

```bash
# 只求解（不需要二进制，只需要 result.txt）
python3 solve_kmpc.py /path/to/result.txt

# 求解 + 闭环验证（需要题目附件目录）
KMPC_DIR=/path/to/ext.rev.not-symmetric bash reproduce_local.sh
# 输出末尾应当看到：[*] diff 行与题目 result.txt 逐字节一致，闭环通过
```
