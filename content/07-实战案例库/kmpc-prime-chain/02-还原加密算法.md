三个业务函数加一个 main，全部从反汇编读出来。本文所有汇编都是 x86-64 Linux，Intel 语法，System V ABI（前四个整型参数依次走 rdi、rsi、rdx、rcx）。完整反汇编底稿在 `assets/kmpc_disasm.txt`，正文只摘关键行。

## pad_message：补空格对齐 4 字节

```asm
; pad_message(const string& msg) @ 0x2787，返回拼好的 string
27b2: call  0x24b0              ; rax = msg.length()
27bf: neg   rax
27c2: and   eax, 3              ; (-len) & 3 —— 差几个空格才到 4 的倍数
27ea: call  0x2fc2              ; string(n, 0x20)，0x20 就是空格
2801: call  0x3042              ; padded += spaces
```

还原成 C++ 一行：

```cpp
padded = msg + string((-len(msg)) & 3, ' ');
```

> [!info]- `neg` + `and` 为什么是"差几个到 4 的倍数"
> `neg rax` 把长度变成负数（补码），`and 3` 取低两位。举例 len=5：`-5` 的补码低两位是 `11`，`-5 & 3 = 3`——补 3 个空格到 8，正好是 4 的倍数。len=4 时 `-4 & 3 = 0`，一个不补。这套写法比 `4 - len % 4` 再对 4 取模要短，编译器对 `(4 - n % 4) % 4` 一类的表达式经常优化成这样。

输入是从哪来的？main 里在调用它之前有一句 `getline(cin, msg)`（桩 `0x22a0`，符号表点名）。所以是**整行读入**，空格也是明文的一部分。这有个一行命令的验证法，后面 [[04-求解与闭环验证]] 实测：喂 `"ab cd"`（5 字符）进去，diff 数组有 2 个元素——说明 5 个字符全被读走、补到 8；假如是 `operator>>`（遇空白截断），只会读到 `ab`，补到 4，diff 只有 1 个元素。

## bytes_to_long：4 字节大端拼整数

```asm
; bytes_to_long(unsigned long& out, const unsigned char* p, unsigned long n) @ 0x25e9
2616: mov   rax, [rbp-0x18]     ; rax = out
2619: shl   rax, 8              ; out <<= 8（腾一个字节的位置）
262b: movzx eax, byte ptr [p+i] ; 取第 i 个字节
2631: lea   rdx, [rcx + rax]    ; out += 字节
263c: add   qword ptr [rbp-8], 1
2649: jb    0x2612              ; 循环 n 次
```

即 `out = out*256 + byte`，从左往右吃——**大端**。main 里调用前先 `call c_str()`（桩 `0x22e0`）拿到字符串首地址、再 `rdx = i << 2` 平移 `4*i`，所以第 i 块就是 `padded.c_str() + 4*i` 起的 4 个字节，没有任何拷贝。

> [!info]- 大端小端 30 秒版
> 同样 4 个字节 `66 6c 61 67`，按大端读是 0x666c6167（'f' 是最高位字节），按小端读是 0x67616c66。人写数字习惯大端（高位在左），x86 内存布局习惯小端，所以"字节串转整数"必须先问一句按哪头读。本题按大端——解密端拼回字符串时也要用 `to_bytes(4, 'big')`，两端必须一致。

## KMPC：素数链本体

```asm
; KMPC(mpz_t out, int v, unsigned long start) @ 0x264f
2683: call  0x23c0              ; mpz_init_set_ui(t, start)      t = 起点
268f: call  0x23f0              ; mpz_init(u)                    工作变量
2694: mov   dword ptr [rbp-0x3c], 1
      ; ── 外层：for (i = 1; i < v; i++) ──
26a0:   mov   qword ptr [rbp-0x38], 1        ; j = 1
        ; ── 内层：找最小的 j 使 t*j+1 是素数 ──
26ba:   call  0x2420              ; mpz_mul_ui(u, t, j)      u = t * j
26d2:   call  0x2480              ; mpz_add_ui(u, u, 1)      u += 1
2716:   mov   esi, 0xa
2719:   call  0x2490              ; mpz_probab_prime_p(u, 10)  素性检验
2720:   je    0x26d9              ; 返回 0（合数）→ j++ 重试
2722:   lea   rdx, [rbp-0x20]
2730:   call  0x2430              ; mpz_set(t, u)            t = u，进入下一轮
273f: jl    0x26a0
2753: call  0x2430              ; mpz_set(out, t)          链尾交给 out
```

翻译成 C：

```c
void KMPC(mpz_t out, int v, unsigned long start) {
    mpz_t t, u;
    mpz_init_set_ui(t, start);
    mpz_init(u);
    for (int i = 1; i < v; i++) {
        unsigned long j = 1;
        for (;; j++) {
            mpz_mul_ui(u, t, j);
            mpz_add_ui(u, u, 1);          // u = t*j + 1
            if (mpz_probab_prime_p(u, 10)) break;
        }
        mpz_set(t, u);                    // t ← t*j + 1
    }
    mpz_set(out, t);
}
```

> [!info]- mpz_probab_prime_p 的第二个参数
> 10 是**重复轮数**：Miller-Rabin 跑 10 个随机基。返回值 2 = 确定是素数，1 = 概率上是素数，0 = 确定是合数。汇编里 `je`（等于 0 才跳回去重试）意味着 1 和 2 都当作素数接受。这种"概率素数"在密码学工程里是标准做法，误判率低于 4⁻¹⁰，对这道题的所有结论都没有影响。

> [!tip]- 链上每步的 j 实际必为偶数
> 链上的 t 全是素数。从第 2 步起 t 是奇素数，`t·j` 是奇数，`t·j + 1` 是偶数——大于 2 的偶数全是合数，过不了素性检验。所以 j=1 只在起点可能是 2 时出现一次，此后每步 j ∈ {2, 4, 6, …}。这条性质下一章要用：它保证链每一环**至少翻一倍**。

还有一个细节在 main 的调用点：传给 KMPC 的起点是 `mpz_get_ui(p)` 的返回值（桩 `0x24f0`），也就是把链头素数**取回成 64 位整数**再传进去，函数里再 `init_set_ui` 装回大数。链头本来就小于 2³³，64 位装得下，这个来回不算丢精度——但读汇编时容易在这里迷路，因为"大数变小数再变大数"看着像多余动作。

## main：把积木拼起来

去掉 STL 和异常处理的噪音后，main 的骨架（完整版见 disasm 底稿）：

```asm
; main @ 0x2889
28ad: call  0x2340              ; time(0)
28b4: call  0x2360              ; srand(eax)
28f5: call  0x22a0              ; getline(cin, msg)
290e: call  0x2787              ; pad_message(msg) → padded
2929: movabs rax, 0x545f7972546e6f44
2933: movabs rdx, 0x5f65747572425f6f
2945: movabs rax, 0x656d69545f6574
294f: mov   qword ptr [rbp-0x23], rax    ; ← 第三段故意错位存放
      ; ── 每块循环 ──
2a0c: call  0x25e9              ; bytes_to_long(m, c_str() + 4i, 4)
2a44: call  0x2470              ; mpz_nextprime(p, p)
2a58: call  0x24f0              ; mpz_get_ui(p)          链头取回 64 位
2a8b: call  0x3246              ; diff.push_back(get_ui(p) - m)
2a90: call  0x22c0              ; rand()
2b34: call  0x264f              ; KMPC(q, v, start)
2bdb: call  0x23b0              ; ofstream("result.txt")   循环外，只开一次
```

### 两段魔法数除法

rand 之后紧跟两段看着眼生的算术：

```asm
2a9a: imul  rax, rax, 0x7e07e07f
2aa1: shr   rax, 0x20
2aa5: sar   eax, 5              ; = rand() / 65
2ad1: movabs rdx, 0xcccccccccccccccd
2ade: mul   rdx
2ae1: shr   rdx, 4              ; = i / 20
```

> [!info]- 编译器的乘法除法
> 除以常数在编译器眼里可以换成"乘以魔法数 + 移位"：`0x7e07e07f / 2³⁷ ≈ 1/65`，`0xcccccccccccccccd / 2⁶⁴ ≈ 0.8` 再配移位凑出 1/20。不用手推验证，认出形状即可——**大常数 imul/mul 接一串移位，基本就是除法或取模**。源码分别是 `rand() % 65` 和 `i % 20`（取模 = 减掉商乘除数，后面几行的 shl/add 就是在干这个）。

### v 的公式

拼起来就是：

```
v = i + (key[i % 20] ^ 0xCC) + rand() % 65
```

`key` 是栈上那个由 movabs 拼出来的 20 字节缓冲。三个立即数按小端展开成字节：

| 立即数 | 落点偏移 | ASCII |
|---|---|---|
| `0x545f7972546e6f44` | 0x00–0x07 | `DonTry_T` |
| `0x5f65747572425f6f` | 0x08–0x0F | `o_Brute_` |
| `0x00656d69545f6574` | 0x0D–0x13 | `t_eTime`（第三段只取低 7 字节） |

第三段存放在基址 +0x0D 处，把第二段的尾巴覆盖掉，合并出 `DonTry_To_Brute_Time`——出题人把嘲讽写在 key 里（"试试爆破时间种子啊"），又故意不用字符串常量。

> [!info]- movabs 是什么，为什么 .rodata 里搜不到这个 key
> `movabs rax, 立即数` 是把 64 位常数直接装进寄存器，编译器给短的字符串字面量（≤8 字节）常做这个优化——字符串不进 .rodata，`strings` 扫不到。反制也简单：movabs 在反汇编里反而更扎眼，逐个按小端拆字节即可。第三段只有 7 个有效字节（最高位是 0x00），而且落点错开 5 字节，两段重叠区以后写的为准——手拼时照着汇编里的存放地址来，别想当然地首尾相接。

### v 的范围

key 的字符都是可见 ASCII（0x42–0x79），`^ 0xCC` 后落在 136–190；i 取 0–19，`rand() % 65` 取 0–64。所以：

```
v ∈ [0 + 136 + 0, 19 + 190 + 64] = [136, 273]
```

链长是 v − 1 ∈ [135, 272]。[[04-求解与闭环验证]] 的实测回退步数 169–230 落在区间内，这个推导算是被双向确认了。

### 完整加密流程

```c
srand(time(0));
getline(cin, msg);
padded = msg + string((-len(msg)) & 3, ' ');     // 补空格到 4 的倍数
key = "DonTry_To_Brute_Time";                    // 三个 movabs 拼的，.rodata 里没有
n = padded.length() / 4;
for (i = 0; i < n; i++) {
    m = be32(padded.c_str() + 4*i);              // bytes_to_long，大端
    mpz_set_ui(p, m);
    mpz_nextprime(p, p);                         // 链头
    diff[i] = mpz_get_ui(p) - m;                 // ← result.txt 第 1 行
    v = i + (key[i % 20] ^ 0xCC) + rand() % 65;  // v ∈ [136, 273]
    KMPC(q, v, mpz_get_ui(p));                   // 素数链走 v-1 步
    out[i] = q;                                  // ← result.txt 第 2 行
}
// "[diff, ...]\n[q, ...]\n" 写入 result.txt（[、, 、]\n[、]\n 都是 .rodata 现成的字面量）
```

flag 是 80 字符 → 正好 20 块，零填充，和 `result.txt` 里两个长度为 20 的数组对上。
