## 本地一键复现

```bash
$ KMPC_DIR=/path/to/ext.rev.not-symmetric bash reproduce_local.sh
[*] step 1: 反向走素数链求解
block  0: steps= 169  pp=1718378861  m=0x666c6167
...
message : flag{Y0u_oU_u_4rE_Re_3_Go0d_OoD_0d_D_47_t_l1bgMp_4Nd_7h15_4sYmM3tr1c_3nCrYp710n}
[*] step 2: 闭环验证 —— 把 flag 喂回 KMPC 本体
[*] diff 行与题目 result.txt 逐字节一致，闭环通过
```

脚本依赖只有 bash + python3；闭环那一步需要能运行 `KMPC` 本体的 Linux 环境（它在 WSL 里直接跑通，Windows 原生没有 ELF 运行时）。脚本会在临时目录里跑加密器，不会碰题目原目录的 `result.txt`。

## 故障排查表

| 现象 | 原因 | 处理 |
|---|---|---|
| 某块 DFS 返回 None | 终点阈值内的假链头全被淘汰 / 小因子上界不够 | 检查 J_LIMIT 是否 ≥ 加密端可能的 j（本题 ≤ 几千，65536 有富余）；确认 DFS 没有提前剪枝 |
| 终点校验 `nextprime(m)==t` 偶发不一致 | 自实现素性判据与 GMP 边界差异 | 两边都提高 MR 轮数，或改用 gmpy2 统一 |
| 解出的 m 拼不出可读文本 | 字节序搞反 | 大端。`0x666c6167` 应该读出 `flag`，拿它对表 |
| 程序跑完没写 result.txt | 当前目录不可写 | 它按相对路径 `result.txt` 写文件，cd 到可写目录再跑 |
| 喂了 flag 却 diff 对不上 | 输入带了换行或回车 | 用 `printf '%s'` 不带换行地喂；getline 会把换行前的一切当明文，diff 块数立刻变多 |

最后一行值得展开：`echo` 默认带 `\n`，getline 读到的就是 81 字节，补空格后 84 字节 = 21 块，diff 数组长度直接对不上 20——闭环验证对输入的洁净度比想象中敏感。

## 爆破种子为什么是坑：算一笔账

顺着 key 里那句嘲讽走一遍，才知道它有多贵。

正推需要每个块的 `v = i + (key[i%20]^0xCC) + rand()%65`，20 块共享一个 `srand(time(0))` 的种子。glibc 的 `rand()` 序列由种子完全确定，所以理论上可行：枚举种子 → 重放 rand 序列得到全部 v → 正推 20 条链 → 与 result.txt 比对。

代价：一条链约 200 步，每步平均要做 ln(t)/2 ≈ 700 次候选素性检验才能找到那个最小 j；20 块合计约 280 万次大数素性检验。**C + GMP 跑一遍就要 63 秒（实测）**——这是单个种子的开销。种子是 `time(0)`，窗口未知，按几小时算就是上万个候选种子。反向法：82 秒，一次，与时间彻底无关。

> [!info]- 解密根本不需要 key，也不需要 seed
> v 只决定链走多长，不改变链的形状——每一环都是"`q−1` 分解成小因子 × 素数"。反向回退时链多长就退多深，终点由 diff 宣布。所以那层 `^0xCC` 的 key 混淆、movabs 藏字符串的功夫，全部花在了不需要被攻破的地方。识别"哪些混淆是装饰"，有时候比破掉它们更省时间。

## 这道题的"非对称"破在哪

题目目录名叫 `ext.rev.not-symmetric`，出题人的意图写在脸上：造一个正向好算、反向算不动的加密。三个设计缺陷叠加，让"反向算不动"落空：

1. **每步取最小 j**。这把 `q − 1` 的因子结构钉死成"一个小偶数 × 一个素数"，反向的每一环变成了可判定的整除问题。假如 j 从一大堆候选里随机挑（甚至挑一个 64 位的大数），反向每层就面对指数级的因子组合——不可逆是真的可以造出来的，只是正向也得付出代价
2. **diff 公布**。回退有了确定终点，"链头是哪个素数"从猜测题变成判断题。去掉 diff 行，攻击者退到 2³³ 以下仍然要在几万个素数里碰运气——32 位的块空间太小，运气也够用，但门槛高了一个量级
3. **块只有 4 字节**。明文空间 2³²，每块可以独立攻破，块与块之间零耦合。块越大，单块结构越复杂，回退终点的搜索空间越大

> [!info]- 素数链其实是 Pratt 素性证书
> 这条链的形状——p₀ 是素数，p₁ = j₁p₀ + 1 是素数，p₂ = j₂p₁ + 1 是素数……——正是 **Pratt 证书**的递归结构。证明一个大数 P 是素数的经典方法（Pocklington 引理）就是：给出 P−1 的完整分解，其中大因子部分递归地用同样方式证明是素数。出题人正向走的是"生成大素数"的标准流程，而**生成即证明，证明即路标**：证书的每一步都写在 q − 1 的因子分解里。想造真单向的链，得避开"上一层信息完整编码在 q−1 里"的结构，这很难和"链上每环都是素数"共存。

> [!tip]- 判断"单向"别信感觉，问结构
> 一个变换是不是单向，不看它跑起来多费劲，看**值域里的元素泄漏了多少构造路径**。这道题里 q 泄漏了（q − 1 = j·t 写在因子结构里），diff 又把终点位置送了出来。凡是靠"乘积 + 素性"定义的构造，检验方向永远比构造方向便宜——逆着走只需要整除和判素，顺着走却要做搜索。这句话对 RSA 素数生成、对各种"自造非对称加密"都成立，是这道题最值钱的收获。

## 其它可行路线

**gmpy2 加速版**：算法不动，`is_prime`/`next_prime` 换库函数。大数运算进 GMP，预计 10 秒级。适合把解题脚本改成通用工具时用。

**C++ 反向器**：试除用 `mpz_divexact_ui`，判素用 `mpz_probab_prime_p`，与加密器同库同速，反向一次的时间能压到和正向 63 秒同档。收益纯粹是速度，本题用不上。

**中间相遇不可行，提一句为什么不**：meet-in-the-middle 需要"从两头各走一半、中间可匹配"的结构（比如 MD5 的某些攻击面）。素数链严格单调，中间值没有可匹配的判据（你不知道中间长什么样），两头凑不起来。

## 方法论 checklist

"自造密码学 + GMP"类逆向题的推进顺序：

- **侦察（10 min）**：`file`/`ldd` 看链接了谁——链接库点名算法家族；`readelf -r` 把库函数全对上号，导入表就是半份算法文档；`nm -C` 收函数名和模板实例化（容器类型都在符号里）；`objdump -s -j .rodata` 收提示串和输出格式
- **还原（1 h）**：对照 PLT 表逐个 call 注解；大常数 imul/mul + 移位认成除法取模；movabs 立即数按小端拼 ASCII，注意落点错位；xor 常数一律记录
- **结构分析（30 min，本题胜负手）**：还原完别急着写求解。先把核心函数写成代数式——KMPC 写成 `q − 1 = j·t` 的那一刻，反向可行性就摆在纸面上了
- **实现（1 h）**：素性检验用小素数试除 + 固定基 Miller-Rabin；小因子用 gcd(lcm(1..N)) 一次收齐；搜索别赌唯一性，DFS 兜底
- **验证（10 min）**：闭环对拍——明文喂回加密器，确定性部分（diff 行）必须逐字节一致；随机部分（q 行）不比对。能喂回原程序验证的，不要用肉眼

> [!important]- 最值得带走的一句话
> 把核心循环写成代数式再下结论。这道题如果直接从"v 未知、种子未知"开始悲观爆破，一天就烧进去了；`t·j + 1` 移项成 `q − 1 = j·t` 只需要五秒钟，而它直接宣告种子无关。逆向的胜负手经常不在反汇编工具里，在"肯不肯先把程序翻译回数学"这一步。
