题目附件是两包磁盘镜像：一个 RAID 0 阵列的 8 块盘（每块 16 MiB）和一个 RAID 5 阵列的 5 块盘（每块 32 MiB），对应两小问。出题人不给任何盘序、条带大小与布局参数——每块盘都是一片裸数据，唯一的出路是把文件系统自己留在盘上的冗余结构（GPT 主备头、XFS 的 AG 超级块副本）当作锚点，反推出阵列的组装参数，拼回完整磁盘，挂载后跑盘内自带的 `getflag.py` 换 flag。

> [!info]- 这是一道什么类型的题
> 取证题（forensics）里的磁盘阵列还原：出题人把一个正常的磁盘镜像拆成 N 块盘的条带再打乱顺序交给你，你的任务是把拆散的条带按正确的顺序、正确的校验关系拼回去。它和隐写题的分工不同——隐写的证据藏在单个文件的字节里，这道题的证据藏在**文件系统结构与物理盘位置的对应关系**里：文件系统按阵列坐标写入的每一个冗余副本，都泄露一个"阵列坐标 → 盘内坐标"的映射点。

> [!info]- 适用对象与读法
> 知道文件、扇区、文件系统是什么，就够了。RAID、GPT、XFS 这些名词第一次出现时，正文下方都有**默认折叠的 callout**，点开从零讲起。
> 阅读顺序：导读 → RAID0 盘序推定 → RAID0 组装取 flag → RAID5 布局求解 → 复盘。只想要答案的，[[02-组装RAID0与校验取flag]] 和 [[03-RAID5布局求解与终审]] 末尾的输出就是两个 flag。

> [!info]- 基础技术用语
> - **RAID 0**：把数据按"条带"（chunk）轮流切到多块盘上，容量叠加、无冗余。恢复只需要盘序和条带大小
> - **RAID 5**：在 RAID 0 的基础上，每个条带拿一块盘存其余盘的异或（校验块），坏一块盘不丢数据。恢复还要多答一问：校验块在盘间的轮换方式（布局）
> - **GPT**：UEFI 的分区表。头部写在阵列的第一个逻辑扇区（LBA 1），备份头写在最后一个 LBA——阵列的首尾各有一个现成锚点
> - **XFS AG**：XFS 文件系统把空间切成若干分配组（AG），每个 AG 开头都放一份超级块副本——4 个 AG 就是阵列坐标轴上 4 个已知点
> - **mdadm**：Linux 的软 RAID 管理工具。`--build` 模式不写元数据，按你给的参数临时拼阵列，适合拼"别人的"阵列
> - **loop 设备**：把一个普通文件伪装成块设备的机制，`losetup` 挂上之后就能对镜像分区、挂载

## 来源与附件

比赛：Hackergame 2021（第八届中国科学技术大学信息安全大赛，2021 年 10 月），MISC 方向题目「阵列恢复大师」。官方题解归档在 GitHub 仓库 [USTC-Hackergame/hackergame2021-writeups](https://github.com/USTC-Hackergame/hackergame2021-writeups)，附件为比赛平台分发的两个压缩包：

| 附件 | 内容 | 小问 |
| ---- | ---- | ---- |
| `diskresuce-raid0.zip` | 8 块盘镜像，每块 16 MiB，文件名是 11 位随机串 | RAID 0 |
| `diskresuce-raid5.zip` | 5 块盘镜像，每块 32 MiB，文件名同为随机串 | RAID 5 |

两问的阵列里各有一份 `files/` 目录与 `getflag.py`：按顺序读全部文件、算哈希、对上出题人预置的总校验和就给 flag——这个校验和同时就是"数据恢复是否完全正确"的裁判。

> [!important]- 拿到文件先形成的三个判断
> 1. **盘上可能有文件系统级的冗余结构**：GPT 主备头、XFS 的 AG 副本都按阵列坐标写死位置，是现成的映射锚点 → [[01-侦察与RAID0盘序推定]]
> 2. **RAID 5 的异或校验有对称性**：一个条带五块盘异或恒为零，"谁当校验盘"从校验关系本身读不出来，布局判别要靠文件系统与文件校验和终审 → [[03-RAID5布局求解与终审]]
> 3. **`getflag.py` 的总校验和是免费的裁判**：拼错了哈希对不上，拼对了自然通过，不需要额外找验证手段 → [[02-组装RAID0与校验取flag]]

全局架构：

```
        8/5 块裸盘镜像（无任何元数据）
                │  扫签名：EFI PART / XFSB 落点
                ▼
   RAID 0：GPT 主备头 + 4 个 XFS AG 副本 = 6 个锚点
                │  锚点拟合 → 条带 128 KiB + 5 个盘序位置
                ▼
        mdadm --build 拼阵列（剩余 3! 种排列挂载验证）
                │  mount -t xfs, offset=1MiB
                ▼
        files/ + getflag.py ──→ flag{4857cdeac07d8456fcaedb61d07b0b7d}

   RAID 5：首尾两个 GPT 锚点各锁定"数据盘+校验盘"一对
                │  4 布局 × 6 条带 × 120 盘序 → 锚点过滤剩 32 组候选
                │  异或校验全对称（五盘异或恒 0），当不了裁判
                ▼
        纯 Python 组装器逐组试拼 → 挂载 ext4 → 盘内 getflag.py 终审
                │  第一组即通过
                ▼
        flag{a18325a1ec0f58292908455c2df8ffcd}
```

最终成果（WSL Ubuntu 本地环境）：

```
Flag: flag{4857cdeac07d8456fcaedb61d07b0b7d}     ← RAID 0 问
Flag: flag{a18325a1ec0f58292908455c2df8ffcd}     ← RAID 5 问
```

> [!info]- 逐行读这份输出
> - 两个 flag 都由盘内 `getflag.py` 打印：脚本遍历 `files/` 下全部文件，把每个文件的 SHA-256 十六进制串接起来，总 SHA-256 等于出题人预置值时，打印总串的 MD5 作为 flag
> - ==flag 正确的充分条件是"每一个字节都在正确的位置"==：错一个文件的字节序，总校验和就变。所以它顺带证明了阵列还原是完备的
> - 两份 `getflag.py` 结构相同、预置校验和不同（RAID 0 份为 `23d2780e...30cd7`，RAID 5 份为 `df81eca7...f9d7`），对应两个独立小问

## 文件索引

| 文件 | 说明 |
|---|---|
| `parse_meta.py` | 解析 GPT 头/分区表与 XFS 超级块（[[01-侦察与RAID0盘序推定\|01 章]]） |
| `derive_r0.py` | RAID 0 锚点搜索与盘序推定，`ATTACH_R0=<附件目录> python3 derive_r0.py` |
| `assemble_r0.sh` | RAID 0 组装：mdadm --build + 剩余三位置排列挂载验证 + 取 flag |
| `solve_r5.py` | RAID 5 求解：锚点过滤候选、异或对称性演示、逐组组装挂载终审 |
| `reproduce_local.sh` | 一键复现：`sudo ATTACH=<附件目录> bash reproduce_local.sh` |

题目原始附件不在这个目录，`reproduce_local.sh` 用 `ATTACH=` 指定解包后的目录，结构为 `$ATTACH/raid0/*.img` 与 `$ATTACH/raid5/*.img`。

## 快速上手

```bash
# 需要 root（losetup / mount / mdadm），附件目录按上表结构组织
sudo ATTACH=/path/to/attachments bash reproduce_local.sh
# 末尾两行输出即两个 flag
```
