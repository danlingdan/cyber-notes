这道题的全部工具是 python3、mdadm、losetup、mount 四样，全程无网络。复盘把两问的解题动作收拢成一条可复用的流程，再列出几类常见变式。

## 解题动作的固定顺序

```
清点附件 → 逐盘扫签名 → 解析文件系统参数 → 锚点拟合阵列参数
        → 组装（mdadm --build 或自写组装器）→ 挂载验证 → 盘内评分器终审
```

| 动作 | RAID 0 问 | RAID 5 问 |
| ---- | ---- | ---- |
| 阵列容量 | 8 × 16 MiB，无冗余 | 5 × 32 MiB，有效 4 × 32 MiB |
| 锚点来源 | GPT 主备头 + 4 个 XFS AG 副本 | 首尾 GPT 头各成对出现 |
| 锚点钉死什么 | 条带 128 KiB + 5 个盘序位置 | "数据盘+校验盘"两对盘 |
| 剩余自由度 | 3! = 6 种排列 | 32 组（布局 × 条带 × 盘序） |
| 自由度的裁判 | XFS 挂载 | ext4 挂载 + getflag 校验和 |
| 异或/校验的角色 | 不适用 | 只能证伪，不能判别（五盘异或恒零） |

三个可迁移的要点：

1. ==文件系统的冗余结构就是阵列坐标系的已知点==。GPT 主备头位置写死，XFS 每个 AG 开头都有超级块副本，ext4 有主备超级块——拆阵列的人拆得动数据，拆不动"结构必须写在哪个逻辑位置"这条规则。
2. ==校验关系只能证伪、不能判别==。RAID 5 的异或恒等式对角色对称，条带大小取 2 的幂分块时关系依旧成立；它的用途是快速否决错位候选，把小规模候选集留给语义层裁判。
3. ==盘内自带的评分器是免费的终审==。`getflag.py` 遍历全部文件算总哈希，等于出题人自带了一个"恢复是否逐字节正确"的检验器。类似的评分器在取证题里很常见（挂载后校验挂载点哈希、比对导出镜像的签名），见到就用，不要自己另造验证。

> [!info]- 环境注记
> 验证环境是 WSL2（Ubuntu），内核自带 XFS（`CONFIG_XFS_FS=y`）与 ext4，loop 设备可用，mdadm 与 cryptsetup 用 apt 安装。两问的挂载命令分别是 `mount -t xfs -o ro,norecovery,offset=1048576` 与 `mount -t ext4 -o ro,offset=1048576`——只读加不回放日志，是取证挂载的默认姿势。RAID 0 问依赖 mdadm 的 `--build`，RAID 5 问只靠 Python 标准库逐条带复制，任何有 Python 的 Linux 环境都能跑。

## 变式与延伸

- **RAID 6 / RAID 10**：RAID 6 每条带两个校验块（P+Q，Q 是伽罗瓦域上的 Reed-Solomon），锚点法照用，但校验对称性的分析要多做一层；RAID 10 先镜像后条带，盘对结构会在签名落点上留下周期特征。
- **带元数据的阵列**：真题里更多阵列带 md 超级块或厂商元数据（版本、盘序、条带全写在盘尾或盘首），`mdadm --assemble` 直接能吃。本题是"无元数据"的极端形态，考的恰恰是元数据缺失时怎么从文件系统反推。
- **加密叠加**：阵列拼对之后分区可能是 LUKS 容器（分区头有 `LUKS\xba\xbe` 魔数），需要 cryptsetup 打开再挂载内层文件系统；识别标志与挂载动作都和本题一致，只是多一层。
- **条带非对齐的假阵列**：出题人可能故意用非 2 的幂条带或奇数偏移。此时 GPT 锚点的拟合会无解，需要把式 (R.1) 换成字节级映射重新推导——锚点法不变，映射公式换掉。
