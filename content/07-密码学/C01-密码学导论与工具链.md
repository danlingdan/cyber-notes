## 2. Python 密码环境：四层分工

| 层 | 包名 | 管什么 | 代表函数 |
| ---- | ---- | ---- | ---- |
| 标准库 | hashlib / hmac / secrets / random | 摘要、带密钥摘要、安全随机、可预测随机 | `sha256`、`hmac.new`、`token_hex`、`getrandbits` |
| 工业实现 | pycryptodome | 对称加密、非对称加密、填充 | `AES`、`RSA`、`pad`、`getPrime` |
| 数论函数 | sympy | 素数、分解、阶、离散对数 | `nextprime`、`factorint`、`n_order`、`discrete_log` |
| 大数底座 | gmpy2 | 整数 k 次方根、模逆、素性判定 | `iroot`、`invert`、`gcd`、`is_prime` |

取用顺序：标准库随解释器走，永远可用；加密解密用 pycryptodome（模式、填充、密钥生成按标准实现）；数论查询用 sympy；Python 整数没有的原语（开 k 次方、模逆、下一个素数）用 gmpy2。[[09-密码学基础|09 章]]手写 exgcd、CRT 是懂原理的路径；从本系列起，解题脚本直接用库。

### 2.1 标准库

```python
import hashlib, hmac, secrets, random

# hashlib：摘要，不可逆，校验和指纹都用它
print(hashlib.sha256(b"flag{hashlib}").hexdigest())

# hmac：带密钥的摘要。自己拼 secret+data 的写法有长度扩展洞（09 章讲过），签名用它
print(hmac.new(b"k3y", b"msg", hashlib.sha256).hexdigest())

# secrets：密码学安全随机。token、密钥、盐都从这里出
print(secrets.token_hex(16), "(每次运行都不同)")

# random：梅森旋转，可预测。种子一固定，序列逐位复现
random.seed(1337)
r1 = random.getrandbits(64)
random.seed(1337)
r2 = random.getrandbits(64)
print(r1, r2, r1 == r2)
```

输出：

```
60841f3b23d4c021ae6fd5dba6985b584ef908ad3e19d42476392a5df71c2962
7c0e03d85b6ccac680ea6500e7dc506720bd332aa9aa8e24e6cbf8e0afeea228
523e4cf852caf876894a21954344640c (每次运行都不同)
17073114832458550531 17073114832458550531 True
```

四件套的分工要分清：hashlib 与 hmac 都不可逆，但 hmac 有密钥；secrets 与 random 都产随机数，但只有 secrets 能用于密码学——`random` 的可预测性本身就是攻击面，[[C04-随机数攻防|C04]] 整章讲怎么攻。

### 2.2 pycryptodome

```python
from Crypto.Cipher import AES
from Crypto.PublicKey import RSA
from Crypto.Util.Padding import pad

key = b"0123456789abcdef"
ct = AES.new(key, AES.MODE_ECB).encrypt(pad(b"flag{industry}", 16))
print(ct.hex())
pt = AES.new(key, AES.MODE_ECB).decrypt(ct)
print(pt)

key2 = RSA.generate(1024)
print(key2.n.bit_length(), key2.e)
```

输出：

```
834157ca0b3197867e41c5038875b63a
b'flag{industry}\x02\x02'
1024 65537
```

三个细节：`pad` 把 14 字节明文补到 16 字节，补的字节值就是补的个数（`\x02\x02`），解密后要 `unpad` 掉；ECB 模式在这里只作演示，它的模式泄漏见 [[09-密码学基础#3.3 分组密码与 ECB 的企鹅图|09 章 3.3]]；`RSA.generate` 返回的是密钥对象，`n`、`e`、`d`、`p`、`q` 都是属性。导入名是 `Crypto`——装了另一个发行版 pycryptodomex 时导入名是 `Cryptodome`，两个包不要混装（见 [[#7. 常见问题|常见问题]]）。

### 2.3 sympy

```python
import sympy
from sympy import nextprime, isprime, factorint, n_order, discrete_log

print(nextprime(10**6))                    # 素数生成
print(isprime(2**61 - 1))                  # 素性判定

print(n_order(7, 41))                      # 模 41 下 7 的阶
print(discrete_log(101, 5, 2))             # 解 2^k ≡ 5 (mod 101)
print(sympy.sqrt(2).evalf(20))             # 任意精度数值
```

输出：

```
1000003
True
{193707721: 1, 761838257287: 1}
40
24
1.4142135623730950488
```

`factorint` 返回"素因子: 次数"的字典；$2^{67}-1 = 193707721 \times 761838257287$，即 Cole 在 1903 年给出的著名分解。`n_order` 与 `discrete_log` 的数学含义是 [[C02-数论进阶与原根|C02]] 的主题，这里先记下"sympy 有这两个函数"。

### 2.4 gmpy2

```python
import gmpy2

c = 276895235694247747928
print(gmpy2.iroot(c, 3))                   # 整数三次方根，附带"是否开尽"标志

p = gmpy2.next_prime(10**30)               # 下一个素数
q = gmpy2.next_prime(10**31)
print(p)
phi = (p - 1) * (q - 1)
d = gmpy2.invert(65537, phi)               # 模逆元
print(d * 65537 % phi == 1)
print(gmpy2.gcd(2**64 * 3**10, 2**10 * 5**20))
print(gmpy2.is_prime(2**127 - 1))
```

输出：

```
(mpz(6517862), True)
1000000000000000000000000000057
True
1024
True
```

gmpy2 是 GMP 多精度运算库的 Python 绑定，补的是 Python 整数没有的原语：`iroot` 返回 `(根, 是否整开)` 二元组，`invert` 是模逆元，`next_prime`、`is_prime` 都是毫秒级。返回值类型是 `mpz`，能和 `int` 直接混合运算；单独 print 一个 `mpz` 显示为普通十进制，装在元组里才带 `mpz` 前缀（上面输出第一行那样），不影响使用。

## 3. bytes 与 int 的互转全集

Crypto 题的数据要在两种表示之间来回转换：明文是 bytes（flag），运算对象是 int（RSA 的 m、c）。互转是每个解题脚本的第一步和最后一步，==转错一次，后面全部白算==。

### 3.1 to_bytes 与 from_bytes：length 与 byteorder

```python
from Crypto.Util.number import long_to_bytes, bytes_to_long

m = b"flag{xor}"

# bytes -> int：byteorder 指定字节序，大端是 CTF 惯例
n = int.from_bytes(m, "big")
print(n)
print(n.to_bytes(9, "big"))            # int -> bytes：length 给够，原样还原
print(n.to_bytes(12, "big"))           # length 给多，左边补 0x00
print(n.to_bytes(12, "little"))        # byteorder 给小端：字节序整个翻过来
try:
    n.to_bytes(4, "big")
except OverflowError as e:
    print("OverflowError:", e)
```

输出：

```
1889377532527210623613
b'flag{xor}'
b'\x00\x00\x00flag{xor}'
b'}rox{galf\x00\x00\x00'
OverflowError: int too big to convert
```

两个参数都有坑：`length` 装不下直接抛 `OverflowError`，字节需求量用 `(n.bit_length() + 7) // 8` 现算；`byteorder` 写成 `"little"` 不报错，但字节序整个反过来——解出 `b'}rox{galf'` 这类倒序串，先查字节序。CTF 里几乎全用 `"big"`，只有题目脚本明确写了 little-endian 才跟着改。

### 3.2 long_to_bytes：自动长度与前导零

pycryptodome 给的两个函数把 `length` 参数自动化了：

```python
print(long_to_bytes(n))                # 长度自动算，原样还原
print(long_to_bytes(0x00ff))           # 前导零字节被剥掉
print(bytes_to_long(b"\x00\x00abc"))   # bytes_to_long 不剥前导零，照样转

# 0 的特殊行为
print(long_to_bytes(0), bytes(1).hex(), (0).to_bytes(1, "big").hex())
```

输出：

```
b'flag{xor}'
b'\xff'
6382179
b'\x00' 00 00
```

`long_to_bytes` 与 `to_bytes` 的行为差别就一条：==`long_to_bytes` 按数值算长度，前导零字节不保留；`to_bytes` 按指定长度补齐，前导零保留==。数值上 `0x00ff` 和 `0xff` 是同一个整数，转回 bytes 后前者只剩 `b'\xff'`——加密解密全程走 int 的题不受影响，但只要有一方按定长字节块处理（分组密码、哈希输入），差一个 `0x00` 就对不上。

> [!warning] 解密结果比预期短一字节，先查前导零
> `long_to_bytes(m)` 出来的结果长度不对，最常见原因就是明文最高位是 `\x00` 被剥掉了。修复方式：按 `n.bit_length()` 算出理论长度，用 `m.to_bytes(长度, "big")` 补回；或按分块大小手工左侧补零。

### 3.3 hex 与 base64：编码层还是密码层

```python
import base64

data = b"round trip"

h = data.hex()
print(h)
print(bytes.fromhex(h))                # bytes.hex 的逆，空格分隔也能吃

b64 = base64.b64encode(data)
print(b64)
print(base64.b64decode(b64))
```

输出：

```
726f756e642074726970
b'round trip'
b'cm91bmQgdHJpcA=='
b'round trip'
```

`bytes.hex()` 与 `bytes.fromhex()`、`base64.b64encode()` 与 `b64decode()` 两对函数够覆盖绝大多数题目。识别一个串是 hex 还是 base64、怎么层层剥开，是 [[08-编码与古典密码#7. 编码链识别与剥层|08 章 7 节]]的内容；这里只补一条分工：==编码转换用标准库，加解密才用密码库==——拿到一串 hex 先 `bytes.fromhex` 看里面是什么，再决定走哪条路。

## 4. 大数运算陷阱

Crypto 的数都是几百位的大整数，Python 的 `int` 天生支持任意精度，但几条语言级规则在大数上会造成静默错误。三参数 `pow(a, b, n)` 边乘边取模是唯一正确的模幂写法（[[09-密码学基础#2.1 模运算与同余|09 章 2.1]]），整数开方必须用 `iroot` 而不是浮点（[[09-密码学基础#5.3 弱点套路清单|09 章 5.3]]）——这两条在此只做引用，本节把剩下几个坑补全。

### 4.1 浮点开方不可信

```python
import gmpy2

c = 276895235694247747928          # 09 章 e=3 小明文攻击里的 m**3

print(c ** (1/3))                  # 浮点除不尽
print(int(c ** (1/3)) ** 3 == c)   # int() 向零截断，立方回去对不上
r, exact = gmpy2.iroot(c, 3)
print(r, exact, r ** 3 == c)

# 更大的数：浮点只有 53 位精度，误差看得见
big = (gmpy2.mpz(123456789012345678901234567890)) ** 3
r2, _ = gmpy2.iroot(big, 3)
fl = int(big ** (1/3))
print("iroot:", r2)
print("浮点 :", fl, "  差:", r2 - fl)
```

输出：

```
6517861.999999994
False
6517862 True True
iroot: 123456789012345678901234567890
浮点 : 123456789012345220480882442240   差: 458420352125650
```

第一个例子里 `c ** (1/3)` 算出 `6517861.999999994`，`int()` 截断成 6517861，立方回去不等于 c；第二个例子里浮点立方根与真值差了 $4.6 \times 10^{14}$。==整数世界的问题用整数工具解：开方用 `gmpy2.iroot(c, k)`，模幂用三参数 `pow`，全程不引入浮点==。

### 4.2 整除与真除

```python
N = 1600000000044444446720121932664199055831
q1 = 40000000000987654349
print(N // q1)                     # 整除：精确
print(N / q1)                      # 真除：结果是 float
print((N // q1) == q1)

try:
    pow(2, 65537 / 2, N)           # / 的结果传进 pow
except TypeError as e:
    print("TypeError:", e)
```

输出：

```
40000000000123456819
4.000000000012345e+19
False
TypeError: pow() 3rd argument not allowed unless all arguments are integers
```

Python 3 的 `/` 永远返回 float——大数一进 float 就只剩 53 位有效数字，连"整除成功"这种判断都会变 False。经典事故是 `pow(c, d/2, n)` 这类写法：本意是"指数除以 2"，实际直接 TypeError。所有参与密码运算的除法写 `//`，需要"除以 2"的场合 `d >> 1` 也行。

### 4.3 sympy 的边界

`factorint` 和 `discrete_log` 都是通用算法，能解什么规模的数有明确边界。同一个脚本，换不同的 n：

```python
import time
from sympy import factorint, nextprime

# 40 位半素数：两个无关联的 20 位素数
N = nextprime(12345678901234567890) * nextprime(98765432109876543210)
print(N, "(%d 位)" % len(str(N)))

t0 = time.perf_counter()
print(factorint(N))
print("factorint: %.2f s" % (time.perf_counter() - t0))
```

输出：

```
1219326311370217953830056380270522784921 (40 位)
{mpz(12345678901234567891): 1, 98765432109876543331: 1}
factorint: 2.62 s
```

| n 的规模 | factorint 的表现 |
| ---- | ---- |
| 40 位半素数 | 秒级 |
| 50 位半素数 | 个位秒数 |
| 70 位半素数 | 500 秒内没有完成 |
| 617 位（真实 RSA 的 2048 比特） | 无望 |

`discrete_log` 同理：上一节 `discrete_log(101, 5, 2)` 秒出，换成 1024 位素数群就不再返回——通用算法的复杂度按群规模的平方根走，1024 位群的平方根依然是天文数字。

> [!warning] 别把真实 RSA 的 n 喂给 factorint 干等
> CTF 附件里六百位的 n 不是算力能碰的。分解走两条路：先查 factordb（出题人复用旧素数时白嫖），再试 yafu（一百位以内实用）；两条路都断，说明突破口在脚本弱点而不是 n 本身——回到"读脚本"那一步。

## 5. 外部工具流

四个工具覆盖"分解—自动攻击—重型数论"三层，每个都值得单独立项。先给一张总表，再逐个跑通：

| 工具 | 干什么 | 一句话定位 |
| ---- | ---- | ---- |
| factordb | 在线分解数据库 | 先查有没有人分解过，命中就是零成本 |
| yafu | 本地分解器 | 一百位以内的 n 交给他 |
| RsaCtfTool | RSA 弱点自动尝试 | 喂 n、e、c，把已知攻击扫一遍 |
| sage | 重型数论系统 | 格、椭圆曲线、多项式环，进阶题的标配 |

### 5.1 factordb：先查有没有人分解过

factordb.com 收录了全世界提交过的分解记录。网页搜框直接贴 n，脚本里用 factordb 包：

```bash
curl -s 'http://factordb.com/api?query=1522605027922533360535618378132637429718068114961380688657908494580122963258952897654000350692006139'
```

输出：

```
{"id":1100000000020360822,"status":"FF","factors":[["37975227936943673922808872755445627854565536638199",1],["40094690950920881030683735292761468389214899724061",1]]}
```

这是 RSA-100——1991 年被分解的著名百位数。`status` 字段是关键：`FF` 表示完全分解，`factors` 直接给出两个 50 位素因子；`C` 表示库里还没有分解记录。脚本里的等价写法：

```python
from factordb.factordb import FactorDB

N = 1522605027922533360535618378132637429718068114961380688657908494580122963258952897654000350692006139
f = FactorDB(N)
f.connect()
print("位数 =", len(str(N)))
print("状态 =", f.get_status())
print("因子 =", f.get_factor_list())
```

输出：

```
位数 = 100
状态 = FF
因子 = [37975227936943673922808872755445627854565536638199, 40094690950920881030683735292761468389214899724061]
```

拿到 p、q 之后就是标准解密流程（[[09-密码学基础#5.2 手写加解密|09 章 5.2]]）。出题人从旧题库里搬 n、或用了弱生成器时，这一查就直接拿到分解，所以==factordb 永远是分解的第一步==。

### 5.2 yafu：本地分解

yafu 把 ECM、二次筛（SIQS）、数域筛按 n 的规模自动调度，命令行一条：

```bash
echo "factor(12193263113702179522618634306324734898519990636989)" | yafu
```

输出（中间的 ECM 进度行略去）：

```
starting SIQS on c50: 12193263113702179522618634306324734898519990636989

Total factoring time = 0.8917 seconds

***factors found***
P25 = 1234567890123456789012353
P25 = 9876543210987654321098813
```

同一个 50 位数，sympy 花个位秒数，yafu 一秒内完成，n 更大时这个差距还会拉大。yafu 要在它的安装目录下运行（读取同目录的配置文件）；进入交互界面后直接输 `factor(数值)` 效果相同。

### 5.3 RsaCtfTool：弱点自动尝试

RsaCtfTool 把几十种 RSA 已知攻击集成在一个入口后面。造一把费马可破的弱钥（q 取 p 附近的素数）当靶子：

```python
# gen_weak.py —— 费马弱钥靶：q 取 p 附近的素数
from Crypto.Util.number import bytes_to_long
from sympy import nextprime

p = 1000000000000000000000000555699
q = nextprime(p + 6 * 10**10)          # 与 p 只差相对极小的一段
n = p * q
e = 65537
m = bytes_to_long(b"flag{f3rm4t_2_ez}")
assert m < n
c = pow(m, e, n)
print("n =", n)
print("e =", e)
print("c =", c)
```

输出：

```
n = 1000000000000000000060001111402000000000000033342248803601397
e = 65537
c = 542389607211328160835840783325909983935207703236028709125987
```

p、q 这么接近时，费马分解几步就合拢——这正是 [[09-密码学基础#5.3 弱点套路清单|09 章 5.3]] 泄露 p+q 一行背后的原理。把三个数喂给 RsaCtfTool，指定攻击名：

```bash
RsaCtfTool -n 1000000000000000000060001111402000000000000033342248803601397 \
           -e 65537 \
           --decrypt 542389607211328160835840783325909983935207703236028709125987 \
           --attack fermat
```

输出：

```
[*] Performing fermat attack on /tmp/tmphmysnc5v.
[*] Attack success with fermat method !

Results for /tmp/tmphmysnc5v:

Decrypted data :
HEX : 0x666c61677b6633726d34745f325f657a7d
INT (big endian) : 34852863801140654897777187214196314831485
utf-8 : flag{f3rm4t_2_ez}
```

不指定 `--attack` 时它会把全部攻击扫一遍，代价是时间长得多。攻击名清单用 `RsaCtfTool --help` 查，factordb、fermat、wiener、stereotyped_message、hastads、bellcore、dp_leak、partial_d 等纯 Python 实现开箱即用。边界也要清楚：==RsaCtfTool 试的是参数层面的已知弱点；写在脚本逻辑里的弱点（密钥重用、填充错误）它看不见==，那些还得靠读脚本。

### 5.4 sage：重型数论

SageMath 是集大成的数学系统，语法是 Python 的超集，数论、代数、格密码的重型运算都有内置：

```
# c01_demo.sage
print(factor(1219326311370217953830056380270522784921))

E = EllipticCurve(GF(9739), [497, 1768])
P = E(8045, 6936)
print(E)
print("P  =", P)
print("2P =", 2 * P)
print("E.order() =", E.order())
```

```bash
sage c01_demo.sage
```

输出：

```
12345678901234567891 * 98765432109876543331
Elliptic Curve defined by y^2 = x^3 + 497*x + 1768 over Finite Field of size 9739
P  = (8045 : 6936 : 1)
2P = (3450 : 9714 : 1)
E.order() = 9735
```

第一行把 [[#4.3 sympy 的边界|4.3]] 那个 40 位数再分解一次（sage 自己的分解器同样能做）；后面几行在素数域 $\mathrm{GF}(9739)$ 上建了一条椭圆曲线，算了点加法 `2P` 和曲线的阶。椭圆曲线是公开钥密码的另一大族，曲线运算与离散对数的展开是本系列后面的事，这里只确认 sage 的入口用法。格密码（Coppersmith、LLL）同理——sage 是那些章节的运行环境。

### 5.5 PARI/GP：一行命令的数论

`gp` 是个交互式数论计算器，单条命令的场合比 sage 轻：

```
znorder(Mod(2, 101))
znlog(Mod(5, 101), Mod(2, 101))
quit
```

```bash
gp -q < c01_demo.gp
```

输出：

```
100
24
```

`znorder(Mod(2, 101))` 求 2 在模 101 乘法群里的阶，结果是 100 = 101 − 1，说明 2 是模 101 的原根；`znlog(Mod(5, 101), Mod(2, 101))` 解离散对数 $2^k \equiv 5 \pmod{101}$，得 k = 24。阶与原根是 [[C02-数论进阶与原根|C02]] 的主题，届时这两个命令会用透。

## 6. 解题工作流模板

### 6.1 目录组织

一道 Crypto 题的附件就两个文件，解题目录保持这个最简结构：

```
challenge/
├── chall.py        # 出题人的加密脚本（key 被涂黑）
├── output.txt      # 出题人跑出来的输出
└── solve.py        # 你的解题脚本
```

### 6.2 solve.py 的标准骨架

按 [[09-密码学基础|09 章]]的三步写：读脚本懂了题意之后，solve.py 固定三段——读输出、攻击、转字节。拿 09 章 5.2 的 RSA 参数当例题（`chall.py` 用小素数加密了 `b"flag"`，`output.txt` 如下）：

```
n = 29581908553
e = 65537
c = 19080469033
```

```python
# solve.py —— 标准骨架：读输出 → 找弱点 → 写解密
from sympy import factorint
from Crypto.Util.number import long_to_bytes

# 1. 读输出：output.txt 的键值对收进一个字典
params = {}
for line in open("output.txt"):
    k, v = line.split("=")
    params[k.strip()] = int(v.strip())
n, e, c = params["n"], params["e"], params["c"]

# 2. 攻击：n 只有 11 位，factorint 直接分解；大 n 换 factordb / yafu（见 5 节）
p, q = factorint(n)
assert p * q == n                      # 分段 assert：这一步不成立，后面全白跑
d = pow(e, -1, (p - 1) * (q - 1))

# 3. 解密 + 转字节
m = pow(c, d, n)
print(long_to_bytes(m))
```

```bash
python3 solve.py
```

输出：

```
b'flag'
```

三段的分工与本题的对应：第 1 段把附件变成变量，任何格式的 output.txt 都用"逐行 split 等号"这套写法兜底；第 2 段是解题的数学主体，本题的弱点是 n 太小可分解，换一道题就换成对应的攻击；第 3 段固定为 `pow(c, d, n)` 加 `long_to_bytes`——无论攻击是什么，最后总是这一对。

> [!note] 分段 assert 的价值
> 攻击脚本一跑几十秒，错误暴露得越晚浪费越多。每个数学前提写成 assert：`p * q == n` 检查分解真的成立，`m < n` 检查明文没越界（[[09-密码学基础#5.2 手写加解密|09 章 5.2]] 的教训），`long_to_bytes` 出来先看长度对不对。assert 停在哪一行，问题就在哪一段。

### 6.3 从模板到真题

模板覆盖的是"标准 RSA"形态，真题的变化都发生在第 2 段：弱点可能是 e 太小（整数开方）、共模（exgcd 合并指数）、dp 泄露（gcd 挖 p）——这些攻击本体都在 [[09-密码学基础#5.3 弱点套路清单|09 章 5.3]] 的清单里，本系列后面逐个展开并配新工具。==骨架不变，变的只有中间那几行==：把每类攻击写成可插拔的片段，解题时按特征挑选组装，这是后续章节组织代码的统一方式。

## 7. 常见问题

| 现象 | 原因与解决 |
| ---- | ---- |
| `from Crypto...` 报 ModuleNotFoundError，但 pip 里能看到包 | 装的是 pycryptodomex，它的导入名是 `Cryptodome`；两个包只留一个，统一用 pycryptodome 的 `Crypto` 导入名 |
| gmpy2 pip 安装时编译报错 | 源码编译需要编译链和 Python 头文件：`apt install build-essential python3-dev` 后重装；Ubuntu 也可直接 `apt install python3-gmpy2` |
| `long_to_bytes` 的结果比预期短一个字节 | 前导零字节被剥掉了（[[#3.2 long_to_bytes：自动长度与前导零\|3.2]]）；需要定长时改用 `m.to_bytes(字节数, "big")` |
| `to_bytes` 报 OverflowError: int too big to convert | length 给小了；字节数用 `(n.bit_length() + 7) // 8` 现算 |
| `pow` 报 TypeError: 3rd argument not allowed unless all arguments are integers | 指数或底数里混进了 `/` 的浮点结果（[[#4.2 整除与真除\|4.2]]）；整除写 `//` |
| factorint 跑了很久没动静 | 超出适用边界（[[#4.3 sympy 的边界\|4.3]]）；换 factordb 查表或 yafu 分解，同时回头重读脚本找弱点 |
| discrete_log 在大群里不返回 | 通用算法复杂度按群规模平方根走，只适合教学尺寸；真实规模走 gp 的 znlog 或专用路径（[[#4.3 sympy 的边界\|4.3]]） |
| RsaCtfTool 的参数总报错 | 各版本参数有差异，攻击名以 `RsaCtfTool --help` 列出的为准（[[#5.3 RsaCtfTool：弱点自动尝试\|5.3]]） |
| sage 提示命令不存在 | sage 装在 conda 环境里，PATH 没带上；按安装方式先激活环境再调用 |
| yafu 在其他目录启动报错 | yafu 要读同目录的配置文件，cd 进安装目录再运行（[[#5.2 yafu：本地分解\|5.2]]） |
| 解出来是乱码但数值形状正常 | 先查 `m < n`（[[09-密码学基础#5.2 手写加解密\|09 章 5.2]]），再查字节序和前导零（[[#3.2 long_to_bytes：自动长度与前导零\|3.2]]） |
| base64 解码报 Incorrect padding | 编码剥层问题，不是密码问题，处理方法见 [[08-编码与古典密码#9. 常见问题\|08 章常见问题]] |
