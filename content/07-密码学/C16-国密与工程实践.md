## 1. 国密家族一览

国密是商用密码算法序列的统称，"SM"取自"商密"的拼音缩写，数字是序号不是版本号。三个主力算法 2012 年先以行业标准 GM/T 发布，2016 年升格为国家标准 GB/T，标准号与定位如下：

| 算法 | 标准号 | 类型 | 关键参数 | 国际对照 |
| ---- | ---- | ---- | ---- | ---- |
| SM4 | GB/T 32907-2016 | 分组密码 | 128 位分组、128 位密钥、32 轮 SPN | AES-128 |
| SM3 | GB/T 32905-2016 | 密码杂凑 | 512 位分组、64 轮、256 位输出 | SHA-256 |
| SM2 | GB/T 32918-2016 | 公钥密码（加密 / 签名 / 密钥交换） | 256 位素域曲线 | ECDSA / ECDH / ECIES |
| ZUC | — | 序列密码（4G/5G 通信加密） | 祖冲之算法 | SNOW 3G，见 [[C03-序列密码与LFSR\|C03]] |
| SM9 | — | 标识密码（公钥即身份串） | 双线性对 | IBC 一族 |

应用场景一句话概括：==凡是有"合规"二字的系统，几乎都部署了国密==——政务系统、网银 U 盾与银联芯片卡、物联网安全模组、国密 TLS 网关，背后是商用密码应用安全性评估一类的强制要求。这也解释了它在 CTF 里的出场方式：题目背景大多是"某政务/金融系统"的仿真。

CTF 里四个方向的出场形态：

- **misc**：给一段 SM3 摘要做完整性校验，或给一张"SM4 加密的图片"——识别算法加解密就是全部工作量；
- **web**：登录接口的前端用 SM2/SM4 加密参数（JS 里带国密库），密文序拼错、密钥硬编码是常见题眼；
- **crypto**：标准算法配错误参数——k 可猜、IV 固定、摘要拼接错误；难度集中在使用层，不在算法层；
- **reverse**：二进制没带库，要靠常数认出 SM4/SM3（[[#6. CTF 实战视角：识别与工具箱|第 6 节]] 的魔术常数表）。

> [!note] 打法定位：算法无洞，打使用
> 与 [[C05-分组密码内部|C05]] 对 AES 的判断相同：三个国密算法本身没有公开的实用攻击，==CTF 的突破口全部在使用层==——模式层（[[C06-分组模式攻击全集|C06]]）、参数与随机数层（[[C04-随机数攻防|C04]]）、实现层（[[C15-实现漏洞与侧信道|C15]]）。本章先解决"认得出来、用得起来"，各节顺手给出对应的移植版攻击。

## 2. SM4：第二个 32 轮 SPN

[[C05-分组密码内部|C05]] 讲过 AES 是 SPN 结构的代表。SM4 是同一结构的第二个成规模实例：不分组对半，每轮对全部 128 位动手，代换层与置换层成对出现。差异在部件的选型：

| | AES-128（[[C05-分组密码内部\|C05]]） | SM4 |
| ---- | ---- | ---- |
| 分组 / 密钥 | 128 位 / 128 位 | 128 位 / 128 位（只有这一档） |
| 轮数 | 10 | 32 |
| 代换层 | 1 个 8 进 8 出 S 盒 | 1 个 8 进 8 出 S 盒（表不同） |
| 扩散层 | ShiftRows + MixColumns（GF(2^8) 列混合） | 轮函数内的 L：32 位字循环移位异或 |
| 密钥扩展 | RotWord + SubWord + Rcon | 同款 S 盒 + 两项旋转异或 L' + CK 常数列 |
| 收尾 | 末轮省掉 MixColumns | 反序变换 R：32 位字按逆序输出 |

加密把 128 位明文拆成 4 个 32 位字 $X_0 \ldots X_3$，32 轮迭代：

$$X_{i+4} = X_i \oplus T\left(X_{i+1} \oplus X_{i+2} \oplus X_{i+3} \oplus rk_i\right), \qquad T = L \circ \tau \tag{16.1}$$

$\tau$ 是代换层：4 个字节并行查 S 盒。$L$ 是扩散层，四个旋转异或项：

$$L(B) = B \oplus \mathrm{rotl}(B,2) \oplus \mathrm{rotl}(B,10) \oplus \mathrm{rotl}(B,18) \oplus \mathrm{rotl}(B,24) \tag{16.2}$$

密钥扩展把 16 字节主密钥 $MK$ 先与固定常数 $FK$ 逐字异或得到 $K_0 \ldots K_3$，再用同一个 $\tau$ 配一个缩水的线性层 $L'$（只有 13、23 两项）滚出 32 个轮密钥：

$$L'(B) = B \oplus \mathrm{rotl}(B,13) \oplus \mathrm{rotl}(B,23), \qquad rk_i = K_{i+4} = K_i \oplus L'\!\left(\tau(K_{i+1} \oplus K_{i+2} \oplus K_{i+3} \oplus CK_i)\right) \tag{16.3}$$

$CK$ 的 32 个 32 位常数不用抄表，标准给的是生成规则：$CK_i$ 的 4 个字节依次是 $(4i+j)\cdot 7 \bmod 256$（$j = 0,1,2,3$），代码一行生成。解密与加密共用同一轮函数，==只有轮密钥倒序==——形式上与 [[C05-分组密码内部|C05]] 的"轮序反转"一致。

```python
FK = [0xA3B1BAC6, 0x56AA3350, 0x677D9197, 0xB27022DC]
CK = [sum(((4 * i + j) * 7 % 256) << (24 - 8 * j) for j in range(4)) for i in range(32)]

def rotl(x, n):
    return ((x << n) | (x >> (32 - n))) & 0xFFFFFFFF

def tau(x):                                    # 代换层：4 字节并行过 S 盒
    return (SBOX[x >> 24] << 24) | (SBOX[(x >> 16) & 0xFF] << 16) \
         | (SBOX[(x >> 8) & 0xFF] << 8) | SBOX[x & 0xFF]

def T(x):                                      # 加密轮合成：tau 后接四项 L
    b = tau(x)
    return b ^ rotl(b, 2) ^ rotl(b, 10) ^ rotl(b, 18) ^ rotl(b, 24)

def T2(x):                                     # 密钥扩展合成：tau 后接两项 L'
    b = tau(x)
    return b ^ rotl(b, 13) ^ rotl(b, 23)

def round_keys(mk):                            # 16 字节主密钥 -> 32 个轮密钥
    k = [int.from_bytes(mk[4 * i:4 * i + 4], "big") ^ FK[i] for i in range(4)]
    rks = []
    for i in range(32):
        k.append(k[i] ^ T2(k[i + 1] ^ k[i + 2] ^ k[i + 3] ^ CK[i]))
        rks.append(k[-1])
    return rks

def encrypt_block(pt, rks):
    x = [int.from_bytes(pt[4 * i:4 * i + 4], "big") for i in range(4)]
    for i in range(32):
        x.append(x[i] ^ T(x[i + 1] ^ x[i + 2] ^ x[i + 3] ^ rks[i]))
    return b"".join(x[35 - i].to_bytes(4, "big") for i in range(4))   # 反序变换 R

def decrypt_block(ct, rks):                    # 解密：同一轮函数，轮密钥倒序
    return encrypt_block(ct, rks[::-1])

# ---- 检查一：GB/T 32907 附录 A 标准测试向量 ----
```

读输出三件事：

- **标准向量命中**：密钥与明文同为 `0123456789abcdeffedcba9876543210` 时，标准规定的单块密文就是 `681edf34d206965e86b3e94f536e4246`——S 盒、CK、密钥扩展、32 轮迭代里任何一处抄错，这串 hex 都出不来，==标准向量命中是手写实现的最强验收==；
- **轮密钥前 4 个**与 gmssl 内部算出的轮密钥逐字一致——S 盒、FK、CK、密钥扩展四层任何一处抄错，这里先炸；
- **解密是加密的轮密钥倒序版**：`decrypt_block` 只有一行，往返成立。

> [!warning] SM4 的密钥只有 16 字节一档，超长会被 gmssl 静默截断
> AES 有 128/192/256 三档密钥，SM4 只有 128 位一档。而 gmssl 的 `set_key` 对 24、32 字节密钥**不报错**——它只读前 16 字节，后 8/16 字节直接丢弃。给 SM4 传 `sha256(secret)` 当密钥（32 字节），实际生效的只有它的前一半；=="256 位密钥"是错觉==。写题、解题都显式 `key[:16]` 或断言长度。

模式层一句带过：SM4 分组同为 16 字节，ECB/CBC/CTR 的语义、PKCS7 填充、以及攻击面与 AES ==完全同构==——[[C06-分组模式攻击全集|C06]] 的 padding oracle、CBC 位翻转、ECB 重复检测原样适用，把脚本里的 AES 换成 SM4 即可。算法层（S 盒 + L）与 AES 同等强度，==别在轮函数上找洞，去模式、参数、随机数上找==（[[C05-分组密码内部|C05]] 的结论整体平移）。

## 3. SM3：MD 迭代与长度扩展

SM3 的结构定性一句话：==Merkle–Damgård 迭代，与 SHA-256 同家族==——[[C10-哈希进阶|C10]] 的迭代哈希框架原样适用，不是海绵结构；512 位分组、64 轮压缩函数、256 位输出，输出就是最终 8 个 32 位状态字的串联。

| | SHA-256 | SM3 |
| ---- | ---- | ---- |
| 结构 | Merkle–Damgård 迭代 | Merkle–Damgård 迭代 |
| 分组 / 字长 | 512 位 / 32 位 | 512 位 / 32 位 |
| 轮数 | 64 | 64 |
| 消息扩展 | 64 个词 W[0..63] | 68 个词 W[0..67]，另配 W'[0..63] |
| 轮常数 | 64 个 | 2 个（按轮段取用） |
| 填充 | 0x80 + 补零 + 8 字节大端位长 | 同左，逐字节相同 |
| 输出 | 256 位 | 256 位 |

压缩函数的完整手写实现约 60 行，配合 GB/T 32905 附录 A 的两个标准向量、gmssl 对拍和长度扩展演示：

```python
# sm3_hand.py —— 手写 SM3 + GB/T 32905 标准向量 + 与 gmssl 对拍 + 长度扩展演示
import os

IV = [0x7380166F, 0x4914B2B9, 0x172442D7, 0xDA8A0600, 0xA96F30BC, 0x163138AA, 0xE38DEE4D, 0xB0FB0E4E]

def rotl(x, n):
    return ((x << n) | (x >> (32 - n))) & 0xFFFFFFFF

def p0(x):
    return x ^ rotl(x, 9) ^ rotl(x, 17)

def p1(x):
    return x ^ rotl(x, 15) ^ rotl(x, 23)

def cf(v, block):                              # 压缩函数：吃一个 64 字节分组
    w = [int.from_bytes(block[4 * i:4 * i + 4], "big") for i in range(16)]
    for j in range(16, 68):
        w.append(p1(w[j - 16] ^ w[j - 9] ^ rotl(w[j - 3], 15)) ^ rotl(w[j - 13], 7) ^ w[j - 6])
    w1 = [w[j] ^ w[j + 4] for j in range(64)]
    a, b, c, d, e, f, g, h = v
    for j in range(64):
        t = 0x79CC4519 if j < 16 else 0x7A879D8A
        ss1 = rotl((rotl(a, 12) + e + rotl(t, j % 32)) & 0xFFFFFFFF, 7)
        ss2 = ss1 ^ rotl(a, 12)
        ff = a ^ b ^ c if j < 16 else (a & b) | (a & c) | (b & c)
        gg = e ^ f ^ g if j < 16 else (e & f) | ((~e & 0xFFFFFFFF) & g)
        tt1 = (ff + d + ss2 + w1[j]) & 0xFFFFFFFF
        tt2 = (gg + h + ss1 + w[j]) & 0xFFFFFFFF
        d, c, b, a = c, rotl(b, 9), a, tt1
        h, g, f, e = g, rotl(f, 19), e, p0(tt2)
    return [a ^ v[0], b ^ v[1], c ^ v[2], d ^ v[3], e ^ v[4], f ^ v[5], g ^ v[6], h ^ v[7]]

def pad(msg_len):                              # 填充与 SHA-256 同构：0x80 + 补零 + 8 字节大端位长
    return b"\x80" + b"\x00" * ((55 - msg_len) % 64) + (msg_len * 8).to_bytes(8, "big")

def sm3(msg, v=None, prefix_len=0):            # prefix_len：续算时的"已处理字节数"（长度扩展用）
    v = IV if v is None else v
    data = msg + pad(prefix_len + len(msg))
    for i in range(0, len(data), 64):
        v = cf(v, data[i:i + 64])
    return "".join("%08x" % x for x in v)

# ---- 检查一：GB/T 32905 两个标准向量 ----
m1 = b"abc"
m2 = b"abcd" * 16
print("向量1 手写 =", sm3(m1))
print("向量1 期望 = 66c7f0f462eeedd9d1f2d46bdc10e4e24167c4875cf2f7a2297da02b8f4ba8e0")
print("向量2 手写 =", sm3(m2))
print("向量2 期望 = debe9ff92275b8a138604889c18e5a4d6fdb70e5387e5765293dcba39c0c5732")

# ---- 检查二：与 gmssl 对拍 ----
from gmssl import sm3 as gsm3
ok = all(sm3(m) == gsm3.sm3_hash(list(m))
         for m in (m1, m2, b"flag{sm3}", os.urandom(53)))
print("手写与 gmssl 在 4 组消息上一致:", ok)

# ---- 检查三：长度扩展：secret 前缀 MAC 伪造 ----
secret = b"k3y=Sup3rS3cret"                   # 15 字节，攻击者不知道
msg = b"&file=report.pdf"
mac = sm3(secret + msg)                        # 服务端只公开这个
print("\n已知 MAC(secret||msg) =", mac[:32], "...")

def extend(digest_hex, orig_len, suffix):
    v = [int(digest_hex[8 * i:8 * i + 8], 16) for i in range(8)]
    aligned = (orig_len + 64) // 64 * 64       # 原填充收尾后对齐到的分组边界
    return sm3(suffix, v=v, prefix_len=aligned)

for L in range(1, 33):                         # 攻击者只能猜 secret 长度
    total = L + len(msg)
    glue = b"\x80" + b"\x00" * ((55 - total) % 64)
    forged = extend(mac, total, b"&admin=1")
    # 服务端收到的完整消息 = msg||glue||原长度字段||suffix，对它算 sm3(secret||整串)
    true_mac = sm3(secret + msg + glue + (total * 8).to_bytes(8, "big") + b"&admin=1")
    if forged == true_mac:
        print("猜 len(secret) = %2d：伪造签名 = %s" % (L, forged))
        print("服务器真签名          = %s" % true_mac)
        print("伪造成功              =", forged == true_mac)
        break
else:
    print("伪造失败")
print("secret 从头到尾未被读取，命中长度:", L)
```

## 4. SM2：椭圆曲线上的公钥算法

SM2 是一条 256 位素域短 Weierstrass 曲线（曲线名 sm2p256v1），代数骨架与 [[C11-椭圆曲线与ECDLP|C11]] 讲的完全一致：点加法、标量乘、ECDLP，一个字都不用改。参数直接落进 [[C11-椭圆曲线与ECDLP|C11]] 的点运算骨架：

```python
# ec_sm2.py —— sm2p256v1 曲线参数与最小点运算（仿射坐标，无穷远点记 None）；点运算骨架同 C11 第 2 节
P  = 0xFFFFFFFEFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF00000000FFFFFFFFFFFFFFFF
A  = P - 3
B  = 0x28E9FA9E9D9F5E344D5A9E4BCF6509A7F39789F515AB8F92DDBCBD414D940E93
N  = 0xFFFFFFFEFFFFFFFFFFFFFFFFFFFFFFFF7203DF6B21C6052B53BBF40939D54123
GX = 0x32C4AE2C1F1981195F9904466A39C9948FE30BBFF2660BE1715A4589334C74C7
GY = 0xBC3736A2F4F6779C59BDCEE36B692153D0A9877CC62A474002DF32E52139F0A0

def add(pt, q):
    if pt is None: return q
    if q  is None: return pt
    x1, y1 = pt
    x2, y2 = q
    if x1 == x2 and (y1 + y2) % P == 0:
        return None                                 # 竖线情形：和为无穷远点
    if pt == q:                                     # 切线情形：倍点
        lam = (3 * x1 * x1 + A) * pow(2 * y1, P - 2, P) % P
    else:
        lam = (y2 - y1) * pow(x2 - x1, P - 2, P) % P
    x3 = (lam * lam - x1 - x2) % P
    return (x3, (lam * (x1 - x3) - y1) % P)

def mul(k, pt):
    r = None
    while k:
        if k & 1:
            r = add(r, pt)
        pt = add(pt, pt)
        k >>= 1
    return r

if __name__ == "__main__":                     # 自检：位数与 2G、nG
    print("n 位数 =", N.bit_length(), "  p 位数 =", P.bit_length())
    print("2G     = %064x%064x" % mul(2, (GX, GY)))
    print("n*G    =", mul(N, (GX, GY)))         # 基点的阶是 n：nG = 无穷远点
```

### 4.1 加密：KDF 混合与两种密文序

SM2 加密（GB/T 32918.4）用随机数 $k$ 把"椭圆曲线点乘"变成"对称掩码"——接收方公钥 $P_B$，明文 $M$：

$$C_1 = kG, \quad [x_2, y_2] = kP_B, \quad t = \mathrm{KDF}(x_2 \| y_2,\ klen), \quad C_2 = M \oplus t, \quad C_3 = \mathrm{SM3}(x_2 \| M \| y_2) \tag{16.4}$$

KDF 是以 SM3 为基础的掩码生成函数，输出 $klen$ 字节（单位是**字节**）。解密方拿自己的 $d$ 算 $[x_2, y_2] = dC_1$，重建 $t$ 异或回明文，再重算 $C_3$ 核对。==异或掩码这一层就是混合加密的微观形态==，整节 §5 都在讲它的宏观版。

密文排布有两个历史版本，互操作对不上十有八九栽在这里：

| 排布 | 出处 | 备注 |
| ---- | ---- | ---- |
| $C_1 \| C_3 \| C_2$ | 2016 版标准默认 | gmssl 的 `mode=1` |
| $C_1 \| C_2 \| C_3$ | 旧版草案与大量旧实现 | gmssl 的 `mode=0` |

另一个长度陷阱：$C_1$ 是 64 字节的 $x \| y$ 拼接，不少实现还在前面再加 1 字节的非压缩点标志 `0x04`——==同一份密文在不同库眼里长度差 1 字节==。gmssl 的密文不带 `0x04`，密文总长恒为 64 + 32 + 明文长。

脚本 import 的 `sm3lib` 是第 3 节手写 SM3 存成的模块（任何正确的 SM3 实现封一层 bytes 进 hex 出的接口都行）：

```python
# sm2_gmssl.py —— gmssl 的 SM2：加解密两种密文序、黑盒判别密文序、签名验签、ASN.1
import sys, os
sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))
from ec_sm2 import P, A, B, N, GX, GY, mul

D = 0x3945208F7B2144B13F36E38AC6D39F95889393692860B51A42FB81EF4DF7C5B8   # 私钥（演示用固定值）
d_hex = "%064x" % D
pub = mul(D, (GX, GY))                                                   # 公钥 P_A = d*G
pub_hex = "%064x%064x" % pub
print("私钥 d  =", d_hex)
print("公钥 dG =", pub_hex)

c1c2c3 = sm2.CryptSM2(d_hex, pub_hex, mode=0)      # mode=0: C1||C2||C3
c1c3c2 = sm2.CryptSM2(d_hex, pub_hex, mode=1)      # mode=1: C1||C3||C2

# ---- 加解密往返：两种密文序 ----
msg = b"flag{sm2_kdf}"
for name, box in (("C1C2C3", c1c2c3), ("C1C3C2", c1c3c2)):
    ct = box.encrypt(msg)
    pt = box.decrypt(ct)
    print("%s: 明文 %d 字节 -> 密文 %d 字节 (=64+32+明文长), 往返:" % (name, len(msg), len(ct)), pt == msg)

# ---- 黑盒判别密文序：拿 mode=0 的密文交换出 mode=1 的排布 ----
ct = c1c2c3.encrypt(msg)                           # C1||C2||C3
L, n = len(msg), len(ct)
swap = ct[:64] + ct[64 + L:] + ct[64:64 + L]       # C1||C3||C2
print("交换尾部两段后按 C1C3C2 解密:", c1c3c2.decrypt(swap) == msg)
print("不交换直接按 C1C3C2 解密, 明文前 8 字节:", c1c3c2.decrypt(ct)[:8].hex(), "(垃圾)")

# ---- 签名验签：sign_with_sm3 内部先算 Z_A ----
sig = c1c2c3.sign_with_sm3(b"hello sm2")           # 返回 r||s 的 128 个 hex 字符
ok  = c1c2c3.verify_with_sm3(sig, b"hello sm2")
bad = c1c2c3.verify_with_sm3(sig, b"hello sm3")    # 换一个字节的消息
print("\n签名 r||s =", sig)
print("原消息验签:", ok == 1, "  篡改消息验签:", bad == 1)

asn1 = sm2.CryptSM2(d_hex, pub_hex, asn1=True).sign_with_sm3(b"hello sm2")
print("ASN.1 DER 编码签名长度 =", len(asn1) // 2, "字节, 开头 =", asn1[:16])

# ---- 手写签名与 gmssl 同 digest 同 k 对拍（推导见 4.2）----
uid = b"1234567812345678"                           # gmssl 内部写死的默认 UID
entl = (len(uid) * 8).to_bytes(2, "big")
z = sm3(entl + uid + A.to_bytes(32, "big") + B.to_bytes(32, "big")
        + GX.to_bytes(32, "big") + GY.to_bytes(32, "big")
        + pub[0].to_bytes(32, "big") + pub[1].to_bytes(32, "big"))
e_bytes = bytes.fromhex(sm3(bytes.fromhex(z) + b"hello sm2"))   # e = SM3(Z_A || M)
K = 0x1B2A3C4D5E6F708192A3B4C5D6E7F8091A2B3C4D5E6F708192A3B4C5D6E7F809
x1, _ = mul(K, (GX, GY))
e = int.from_bytes(e_bytes, "big")
r = (e + x1) % N
d1 = pow(D + 1, N - 2, N)
s = d1 * (K - r * D) % N
mine = "%064x%064x" % (r, s)
gms  = c1c2c3.sign(e_bytes, "%064x" % K)            # gmssl 的底层 sign：直接吃 digest 与 K
print("手写 SM2 签名与 gmssl 同 k 同消息一致:", mine == gms)
```

```python
# sm2_lowk.py —— SM2 加密侧低熵 k：拿 C3 当校验器离线爆破

from ec_sm2 import GX, GY, mul

K_BAD = 3                                       # 事故：出题人用小常数当 k

C1 = "%064x%064x" % mul(K_BAD, (GX, GY))        # C1 = kG

t = bytes.fromhex(sm3_kdf(("%064x%064x" % (x2, y2)).encode(), len(msg)))

ct = bytes.fromhex(C1) + c2 + c3                # C1||C2||C3（自造，演示用）
print("出题侧: k = %d（未公开）, 密文 %d 字节 = 64 C1 + %d C2 + 32 C3" % (K_BAD, len(ct), len(c2)))

# ---- 攻击：k 的空间小, 逐个试, C3 = SM3(x2||M||y2) 就是校验器 ----
```

### 4.2 签名：比 ECDSA 多一步 Z_A

SM2 签名（GB/T 32918.2）的流程与 ECDSA（[[C12-数字签名|C12]]）同骨架，多出来的东西叫 $Z_A$——签的不只是消息，还是"签名者身份"：

$$Z_A = \mathrm{SM3}\left(\mathrm{ENTL}_A \| ID_A \| a \| b \| G_x \| G_y \| x_A \| y_A\right) \tag{16.5}$$

$\mathrm{ENTL}_A$ 是身份串 $ID_A$ 的**位长**（2 字节大端），曲线参数与公钥全部拌进 $Z_A$——同一枚签名换一个 UID 就验不过，这是它和 ECDSA 的第一个差异。摘要与签名：

$$e = \mathrm{SM3}(Z_A \| M), \qquad (x_1, y_1) = kG, \qquad r = (e + x_1) \bmod n, \qquad s = \left[(1+d)^{-1}(k - rd)\right] \bmod n \tag{16.6}$$

$r$、$s$ 任一为 0 或 $r + k = n$ 时换 $k$ 重签。验签侧：

$$t = (r + s) \bmod n, \qquad (x_2, y_2) = sG + tP_A, \qquad \text{通过} \iff (e + x_2) \bmod n = r \tag{16.7}$$

与 ECDSA 的逐项对照：

| | ECDSA（[[C12-数字签名\|C12]]） | SM2 |
| ---- | ---- | ---- |
| 摘要 $e$ | $H(M)$ | $\mathrm{SM3}(Z_A \| M)$，多了 $Z_A$ 一层 |
| $r$ | $(kG)_x \bmod n$，只看 $k$ | $(e + (kG)_x) \bmod n$，==掺了消息== |
| $s$ | $k^{-1}(e + rd)$ | $(1+d)^{-1}(k - rd)$ |
| 验签组合点 | $u_1 G + u_2 P_A$（$u$ 由 $e,s$ 反算） | $sG + tP_A$（$t = r + s$） |
| $k$ 的敏感度 | 重用 / 低熵即死（C12） | 同左，公式换形状（4.3） |

gmssl 把签名拆成两层 API，正好对应"有没有 $Z_A$"：底层 `sign(data, K)` 的 `data` 是**已经算好的 32 字节摘要**（内部不再算 $Z_A$，$K$ 还能显式传入）；`sign_with_sm3(data, uid)` 才是完整流程，内部固定使用默认 UID `1234567812345678`。4.1 输出里"手写与 gmssl 一致"的那行，就是按式 (16.5)、(16.6) 手算 $Z_A$ 与 $e$、再调底层 `sign` 对拍的结果。

> [!warning] 验签恒失败的三大来源：Z_A、UID、格式
> SM2 验签不通过时，算法实现出错排第三，前两名是：**$Z_A$ 参与不一致**——用底层 `sign` 直接签了明文（没拌 $Z_A$），或签名方与验签方 UID 不同；**格式不一致**——裸 $r \| s$ 与 ASN.1 DER 互相硬塞。全部表现为"静默地验不过"，不报任何错。排查顺序：先重算 $Z_A$，再对 UID，最后看签名字节数。

### 4.3 k 重用与低熵 k：移植 C12 的攻击

[[C12-数字签名|C12]] 对 DSA/ECDSA 的结论——==$k$ 重用一次，私钥当场出土==——在 SM2 上原样成立，只是代数形状换一下。两枚签名共用同一个 $k$：

$$s_1(1+d) = k - r_1 d, \qquad s_2(1+d) = k - r_2 d$$

两式相减消掉 $k$，解出私钥：

$$d = \frac{s_1 - s_2}{r_2 - r_1 - s_1 + s_2} \bmod n \tag{16.8}$$

自造靶走完整流程：gmssl 用同一个 $K$ 签两条转账消息，攻击侧只拿两枚签名，恢复过程不碰曲线点运算，纯模逆元：

```python
# sm2_kreuse.py —— SM2 签名 k 重用恢复私钥：gmssl 签两枚同 k 签名，纯模运算恢复 d
import sys, os
sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))
from ec_sm2 import A, B, N, GX, GY, mul
from sm3lib import sm3
from gmssl import sm2

D = 0x3945208F7B2144B13F36E38AC6D39F95889393692860B51A42FB81EF4DF7C5B8   # 受害者私钥
d_hex = "%064x" % D
pub = mul(D, (GX, GY))
pub_hex = "%064x%064x" % pub
box = sm2.CryptSM2(d_hex, pub_hex)

def digest(msg, pub):                          # e = SM3(Z_A || M)，Z_A 按默认 UID 算
    uid = b"1234567812345678"
    entl = (len(uid) * 8).to_bytes(2, "big")
    z = sm3(entl + uid + A.to_bytes(32, "big") + B.to_bytes(32, "big")
            + GX.to_bytes(32, "big") + GY.to_bytes(32, "big")
            + pub[0].to_bytes(32, "big") + pub[1].to_bytes(32, "big"))
    return bytes.fromhex(sm3(bytes.fromhex(z) + msg))

msg1, msg2 = b"transfer 100 to alice", b"transfer 100 to bob"
e1, e2 = digest(msg1, pub), digest(msg2, pub)
K = 0x5E3D1C9A8B7F2E4D6C0A9B8E7F6D5C4B3A29180F1E2D3C4B5A6978899AABBCC0   # 事故：两枚签名共用
k_hex = "%064x" % K

sig1 = box.sign(e1, k_hex)
sig2 = box.sign(e2, k_hex)
r1, s1 = int(sig1[:64], 16), int(sig1[64:], 16)
r2, s2 = int(sig2[:64], 16), int(sig2[64:], 16)
print("消息1:", msg1.decode())
print("  签名1 r1 =", sig1[:64])
print("         s1 =", sig1[64:])
print("消息2:", msg2.decode())
print("  签名2 r2 =", sig2[:64])
print("         s2 =", sig2[64:])
print("两枚签名合法（gmssl 验签）:", box.verify(sig1, e1) == 1, box.verify(sig2, e2) == 1)
print("同一 k：SM2 的 r = (e + x1) mod n 掺了消息摘要, r1 != r2:", r1 != r2)

# ---- 纯模运算恢复 d，全程不用曲线点运算 ----
denom = (r2 - r1 - s1 + s2) % N
d_hat = (s1 - s2) * pow(denom, N - 2, N) % N
print("\n恢复 d = (s1-s2)/(r2-r1-s1+s2) mod n")
print("恢复值 =", "%064x" % d_hat)
print("真实值 =", d_hex)
print("相等:", d_hat == D)

# ---- 恢复的私钥是完整可用的：导出公钥，gmssl 正常签验 ----
pub_hat = mul(d_hat, (GX, GY))
box_hat = sm2.CryptSM2("%064x" % d_hat, "%064x%064x" % pub_hat)
sig_new = box_hat.sign_with_sm3(b"any message")
print("恢复私钥导出公钥 = 原公钥:", pub_hat == pub, " 新签名可验:", box_hat.verify_with_sm3(sig_new, b"any message") == 1)

# ---- 变体：k 可猜（counter/时间戳）时一枚签名即可 ----
K2 = 1                                          # 极端事故：k 从 1 开始计数
sig3 = box.sign(e1, "%064x" % K2)
r3, s3 = int(sig3[:64], 16), int(sig3[64:], 16)
d_hat2 = (K2 - s3) * pow(s3 + r3, N - 2, N) % N
print("\nk=1 这枚签名 r3 =", sig3[:64])
print("已知 k 公式 d = (k-s)/(s+r) mod n, 恢复值等于真实值:", d_hat2 == D)
```

三段读法：

- **靶子**：两枚签名都能过验签（是合法签名），攻击面不在合法性在随机数；
- **SM2 特有的检测盲区**：ECDSA 里同 $k$ 直接表现为 $r_1 = r_2$（$r$ 只看 $kG$），可以靠"扫 $r$ 相同"找靶；==SM2 的 $r$ 掺了消息摘要，同 $k$ 两枚签名的 $r$ 也不相同==——检测信号失效，但式 (16.8) 里 $r_1$、$r_2$ 各就各位，攻击照打；
- **恢复即接管**：恢复出的 $d$ 导出的公钥与原公钥相同、能签出可通过验证的新签名——私钥级别的完整失守。已知 $k$（时间戳、计数器）时退化成一枚签名的事：$d = (k - s)(s + r)^{-1} \bmod n$。

> [!info]- 两个现实案例与一个防御
> 现实里这类事故的著名案例：索尼 PS3 的代码签名 ECDSA 把 $k$ 写成常数，任何人都能算出私钥签自家软件；2013 年多个 Android 比特币钱包因 `SecureRandom` 熵不足，签名 $k$ 可预测，钱包被扫荡——后者的形态就是本节的"低熵 $k$"。防御与 [[C12-数字签名|C12]] 的结论一致：$k$ 必须来自密码学安全随机数（[[C04-随机数攻防|C04]]）；更稳的做法是 RFC 6979 式确定性派生——$k$ 由私钥与消息摘要决定，既不重复也不依赖随机源的质量。

> [!warning] gmssl 默认的 k 不是密码学安全随机数
> gmssl 3.2.2 内部生成 $k$ 用的是 `random.choice`——[[C04-随机数攻防|C04]] 里的梅森旋转，可预测。==用 gmssl 写加密/签名服务时，$k$ 要自己用 `os.urandom`/`secrets` 生成再传入==（签名走底层 `sign(data, K)`；加密的 $k$ 在 `encrypt` 内部生成，要求高时得换库或改源）。反过来，解题时遇到"题目用 gmssl 默认参数"的场合，可预测性本身可能就是题眼。

## 5. 混合加密工程实践

公钥算法慢、且只能加密短数据（[[09-密码学基础#5.2 手写加解密|09 章 5.2]] 的 $m < n$ 检查），所以长数据的加密永远是分工合作：==对称算法加密数据，非对称算法只加密那一把对称密钥==：

$$\text{密文} = \mathrm{SM4\_CBC}(M,\ k_{\text{会话}}), \qquad \text{包裹} = \mathrm{SM2_{enc}}(k_{\text{会话}},\ P_B) \tag{16.9}$$

正确姿势的完整往返（发送方随机生成 $k_{\text{会话}}$ 与 IV，接收方先拆包裹再解数据）：

```python
# hybrid_demo.py —— 混合加密：正确姿势（SM4-CBC + SM2 包密钥）与错误姿势靶（裸 RSA e=3 包密钥）
import sys, os
sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))
from ec_sm2 import GX, GY, mul
from gmssl import sm2
from gmssl.sm4 import CryptSM4, SM4_ENCRYPT, SM4_DECRYPT
import gmpy2

report = (b"CONFIDENTIAL: flag{hybr1d_d0ne_r1ght}" + b" body " * 40)

# ---- 正确姿势：SM4-CBC 加数据，SM2 只包 16 字节对称密钥 ----
D = 0x3945208F7B2144B13F36E38AC6D39F95889393692860B51A42FB81EF4DF7C5B8
d_hex = "%064x" % D
pub_hex = "%064x%064x" % mul(D, (GX, GY))
sm2box = sm2.CryptSM2(d_hex, pub_hex, mode=1)          # 收发双方各持一半，这里同盒演示

key = os.urandom(16)
iv = os.urandom(16)
enc = CryptSM4(SM4_ENCRYPT); enc.set_key(key, SM4_ENCRYPT)
ct = enc.crypt_cbc(iv, report)
wrapped = sm2box.encrypt(key)                           # 非对称部分只碰 16 字节密钥
print("数据 %d 字节, SM4-CBC 密文 %d 字节, SM2 包裹的密钥 %d 字节" % (len(report), len(ct), len(wrapped)))

dec = CryptSM4(SM4_DECRYPT); dec.set_key(key, SM4_DECRYPT)
print("接收侧解出密钥解密数据:", dec.crypt_cbc(iv, ct) == report)

# ---- 错误姿势靶：会话密钥用裸 RSA(e=3, 无填充)包裹 ----
import sympy
from math import gcd
e = 3
nxt = 2 ** 256 + 0x9E37
while True:                                    # 选到 gcd(e, (p-1)(q-1)) = 1 的素数对为止
    p = sympy.nextprime(nxt)
    q = sympy.nextprime(p + 0x3B9A)
    if gcd(e, (p - 1) * (q - 1)) == 1:
        break
    nxt = p + 1
n = p * q
m = int.from_bytes(key, "big")
c = pow(m, e, n)
print("\n裸 RSA 靶: n %d 位, e = %d, 会话密钥 128 位, key^3 %d 位 < n" % (n.bit_length(), e, (m ** 3).bit_length()))
m_hat, exact = gmpy2.iroot(c, 3)
print("密文直接开三次方, 整开成立:", exact, " 恢复密钥:", m_hat == m)
dec2 = CryptSM4(SM4_DECRYPT); dec2.set_key(int(m_hat).to_bytes(16, "big"), SM4_DECRYPT)
print("用恢复密钥解数据:", dec2.crypt_cbc(iv, ct) == report)

# ---- 对照：同一把密钥换成 RSA-OAEP 包裹，开方攻击失效 ----
from Crypto.PublicKey import RSA
from Crypto.Cipher import PKCS1_OAEP
rsakey = RSA.construct((n, e, pow(e, -1, (p - 1) * (q - 1)), p, q))
oaep_ct = PKCS1_OAEP.new(rsakey).encrypt(key)
m_oaep, exact2 = gmpy2.iroot(int.from_bytes(oaep_ct, "big"), 3)
print("OAEP 包裹后密文 %d 字节, 开三次方得整开:" % len(oaep_ct), exact2, " 且不等于密钥:", m_oaep != m)
print("OAEP 正常解包:", PKCS1_OAEP.new(rsakey).decrypt(oaep_ct) == key)
```

错误靶的塌法一眼见底：混合体制的安全链只挂在"非对称部分包裹得住对称密钥"上，裸 RSA（无填充）+ 小指数 $e=3$ 让 16 字节会话密钥的立方小于 $n$，取模形同虚设，==密文开三次方就是密钥==（[[09-密码学基础#5.3 弱点套路清单|09 章 5.3]] 的小明文攻击）；对称部分再标准也没用。换成 RSA-OAEP 后同一把攻击钥匙失灵——填充把短消息抬到模数尺度，这正是 [[C09-RSA攻击III|C09]] 反复强调"裸 RSA 不可用"的原因。

错误姿势清单，出题与做题两侧都按这张表过：

| 错误姿势 | 后果 | 处方 |
| ---- | ---- | ---- |
| 裸 RSA / 裸 SM2 分段拼接加密长数据 | 逐块确定性、可重排可删除；无填充的 RSA 盯着 [[C09-RSA攻击III\|C09]] 的 oracle 一族 | 数据走对称，非对称只包密钥 |
| ECB 加大文件、长报文 | 结构重复原样泄漏（[[09-密码学基础#3.3 分组密码与 ECB 的企鹅图\|09 章 3.3]] 的企鹅图） | CBC/CTR + 随机 IV（[[C06-分组模式攻击全集\|C06]]） |
| 对称密钥硬编码在前端 JS / 二进制里 | strings 或源码直接拿走 | 密钥会话内随机生成、按人分发 |
| 无填充 RSA(e=3) 包短会话密钥 | $key^3 < n$，开方直接出密钥（本节靶） | RSA-OAEP，或 SM2（内建 KDF） |

> [!note] SM2.encrypt 本身就是"微型混合加密"
> 式 (16.4) 里 KDF 生成的 $t$ 对明文逐字节异或——SM2 加密内部自带对称层。但==别因此把长数据整段塞给 `encrypt`==：那样性能差，且不带任何完整性保护。标准姿势仍是本节的分工：SM4 管数据，SM2 管 16 字节密钥；完整性再叠 HMAC 或 AEAD 模式（[[C06-分组模式攻击全集|C06]]）。

## 6. CTF 实战视角：识别与工具箱

没有符号的二进制里认国密，靠常数。五个最高频的识别锚点：

| 认什么 | 常数（hex） | 是什么 |
| ---- | ---- | ---- |
| SM4 | d690e9fe cce13db7 16b614c2 28fb2c05 | S 盒表头 16 字节 |
| SM4 密钥扩展 | a3b1bac6 56aa3350 | FK 前两个字 |
| SM3 | 7380166f 4914b2b9 172442d7 da8a0600 | IV 前 16 字节 |
| SM2 | 28e9fa9e 9d9f5e34 4d5a9e4b cf6509a7 | 曲线参数 $b$ 开头 |
| 国密 OID | 1.2.156.10197.x（SM2 曲线 .301、SM3 .401） | 证书、密钥文件里的算法标识 |

另有一条结构特征：SM4 的 CK 常数列是"字内 4 字节各为 $(4i+j)\cdot 7 \bmod 256$"的等差结构（`00070e15 1c232a31...`），与 AES Rcon 的 2 的幂完全不同，认错家族时用它复核。算法认出来之后，按 [[C05-分组密码内部|C05]] 的判断走：==不在轮函数上找洞==，把力气花在模式（[[C06-分组模式攻击全集|C06]]）、参数与随机数（[[C04-随机数攻防|C04]]）、实现（[[C15-实现漏洞与侧信道|C15]]）三层。

工具箱：

| 工具 | 覆盖 | 备注 |
| ---- | ---- | ---- |
| gmssl（pip，纯 Python） | SM2 / SM3 / SM4 | 源码可读适合抄公式；==默认 $k$ 非密码学安全==（4.3 的 warning） |
| OpenSSL ≥ 3.x | sm3 / sm4 / SM2 密钥与签名 | 命令行速查见下 |
| sage | 曲线运算 / ECDLP | [[C11-椭圆曲线与ECDLP\|C11]] 的全套点运算与攻击直接可用 |
| GmSSL（C 库 CLI） | 全家 | 与 pip 的 gmssl 是两套东西，API 不通用（[[#7. 常见问题\|常见问题]]） |

命令行一行流（OpenSSL 3.x）：

```bash
printf 'abc' | openssl dgst -sm3
printf 'flag{sm4_1s_n0t_aes}' | openssl enc -sm4-ecb -K 0123456789abcdeffedcba9876543210 | xxd -p
openssl ecparam -name SM2 -genkey -noout -out sm2.key
openssl pkeyutl -sign -inkey sm2.key -rawin -in m.txt -out m.sig
openssl pkeyutl -verify -inkey sm2.key -rawin -in m.txt -sigfile m.sig
```


三条读法：`dgst -sm3` 的输出就是第 3 节的标准向量值——命令行工具与手写实现互相印证的最快路径；`enc -sm4-ecb -K <hex>` 给原始密钥、PKCS7 填充，==这份 32 字节输出与 gmssl 的 `crypt_ecb` 逐字节一致==——跨实现对拍是检验解题脚本的第一道工序；SM2 签名验签要带 `-rawin`（吃原始消息、内部自动算 $Z_A$），==先 `dgst` 再 `pkeyutl` 会变成双重摘要==。

> [!note] 解题 checklist
> 1. 认算法：常数表 / 库名 / OID 三选一命中即定位；
> 2. 量密文结构：SM2 密文 64 + 32 + 明文长、SM4 密文是 16 的倍数、SM3 恒 32 字节——先量长度再猜结构；
> 3. 定攻击层：算法层无洞，逐层查模式、密文序/UID 一致性、随机数来源（[[C04-随机数攻防\|C04]]）；
> 4. 对拍：任何手写脚本先过标准向量，再过第二套实现（gmssl ↔ OpenSSL ↔ sage）。
>
> 练习来源：[[01-练习平台索引|01 练习平台]] 的 misc / crypto 分区以"国密""SM4""SM2"为关键词检索；自建靶复刻本章 4.3 与 §5 的两类事故是最快的内化路径。

## 7. 常见问题

| 现象 | 原因与解决 |
| ---- | ---- |
| `pip install gmssl` 后找不到命令行工具，或照 C 库教程敲的命令跑不了 | pip 的 gmssl 是纯 Python 库（`import gmssl`），GmSSL 是另一个 C 库及其 CLI，两套 API 不通用；先确认自己装的是哪套 |
| SM2 密文两把库互解不了 | 密文序 C1C3C2 / C1C2C3 不一致（[[#4.1 加密：KDF 混合与两种密文序\|4.1]] 的黑盒判别）；或一方 C1 带 0x04 前缀另一方不带，长度差 1 字节，剥掉或补上再解 |
| SM4 传 24/32 字节密钥不报错，以为密钥更强 | gmssl 静默只读前 16 字节；SM4 只有 128 位一档（[[#2. SM4：第二个 32 轮 SPN\|第 2 节]] 的 warning） |
| `openssl dgst -sm3` 报未知算法 | OpenSSL 1.1.x 的一些发行版没编 SM3/SM4；换 OpenSSL 3.x，或直接用 python 的 gmssl |
| SM2 验签恒失败但"算法没错" | 三查：$Z_A$ 是否参与（`sign` 与 `sign_with_sm3` 混用）、UID 是否一致、签名格式是裸 r\|\|s（64 字节）还是 ASN.1 DER（约 70 字节）（[[#4.2 签名：比 ECDSA 多一步 Z_A\|4.2]] 的 warning） |
| `openssl pkeyutl` 对 SM2 签名验不过 | 缺 `-rawin`：OpenSSL 期望原始消息自己算摘要，先 `dgst` 再签是双重哈希（[[#6. CTF 实战视角：识别与工具箱\|第 6 节]]） |
| gmssl 的 `decrypt` 解出乱码但不报错 | 3.2.2 的 decrypt 不核验 C3 哈希段；密文序错、密钥错都表现为乱码，解密后自行比对 u 与 C3 |
| 两枚 SM2 签名 r 不同，断定"不是 k 重用" | SM2 的 $r = (e + x_1) \bmod n$ 掺了消息摘要，同 k 的两枚签名 r 也不相同，ECDSA 的找靶信号在这里失效（[[#4.3 k 重用与低熵 k：移植 C12 的攻击\|4.3]]） |
| KDF 掩码长度对不上明文 | `klen` 单位是字节，按明文字节数传；掩码生成是以 SM3 为基础的计数器模式，不是一次 hash |
| ASN.1 DER 签名长度每次不一样 | DER 整数编码去掉前导零，r/s 高位含 0 时整体变短（70–72 字节都正常）；用 DER 库解析，别按固定偏移切 |
| 手写 SM3/SM4 与库对不上 | 先对标准向量再对库：SM3 查 T_j 分段与 rotl 位宽、SM4 查 CK 生成式与轮密钥倒序（[[#2. SM4：第二个 32 轮 SPN\|第 2 节]]、[[#3. SM3：MD 迭代与长度扩展\|第 3 节]]） |
| 题目给的 SM2 公钥喂不进 gmssl | gmssl 要 128 个 hex 字符的 x\|\|y 裸串；PEM、带 04 前缀、带冒号分隔的都先剥成裸串 |

## 8. 配套练习与延伸阅读

配套练习：

1. 给第 2 节的手写 SM4 加 CTR 模式（骨架抄 [[C06-分组模式攻击全集|C06]]），与 `openssl enc -sm4-ctr` 对拍；再把 nonce 重用一遍，验证两段密文异或等于两段明文异或——[[C06-分组模式攻击全集|C06]] 的结论在 SM4 上原样成立。
2. 把第 3 节的长度扩展脚本改造成通用解题模板：输入"已知 MAC + secret 长度候选范围 + 要追加的参数"，输出伪造 MAC；找一道 `sm3(secret||data)` 形态的 web 题实际打一遍。
3. 把 `sm2_lowk.py` 的爆破上界提到 $10^6$ 感受耗时变化，再改成 `k = int(time.time())` 的窗口扫描版（[[09-密码学基础#6. 随机数一瞥|09 章 6]] 的种子扫描思路），体会"时间戳当 k"在加密侧和签名侧的两种死法。
4. 用 sage 重建 sm2p256v1（`EllipticCurve(GF(p), [p-3, b])`），重做 4.3 的 k 重用恢复，对比手写点运算与 sage 的耗时；顺手把 [[C11-椭圆曲线与ECDLP|C11]] 的无效曲线攻击在 SM2 密钥交换场景里推演一遍。
5. 给 §5 的正确姿势加一道 HMAC-SM3 完整性校验（[[C10-哈希进阶|C10]]），然后翻转密文一个比特，观察解密方在哪一步拦下——把"加密 + 认证"的完整链路跑通。
