## 1. 全系列知识地图：看到什么，翻哪章

### 2.2 附件三件套与参数表

Crypto 题的附件通常三件：**脚本**（或一个服务地址）、**参数与密文文件**、**题面**。开题前三件事，顺序固定：

**第一件：有源码先读源码。** 自实现的轮函数、非常规的参数生成语句、奇怪的取模位置，都在脚本里。==源码改变攻击面==——题面只说"这是一个签名服务"，脚本才告诉你 nonce 是怎么生成的。没有源码只有参数的题，先按 [[C07-RSA攻击I#1.2 特征 → 攻击决策表|C07 1.2]] 的决策表分流，缺什么信息再决定要不要探测服务。

**第二件：列参数表。** 把附件里每个数抄进一张五行表，位数是第一关键字：

| 栏 | 记什么 |
| ---- | ---- |
| 名称 | n / e / c / p / q / g / y / k / iv / ct…… |
| 位数 | bit_length；同族参数摆在一起对齐看 |
| 个数 | 几组 n？几条签名？r 有没有重复？ |
| 形状 | 十进制 / 十六进制 / bytes；e 的大小；g 的大小；密文块数 |
| 备注 | factordb 查过没有；脚本里对应的生成语句在第几行 |

参数表的作用是把"看一眼"变成"可比较"：e 与 n 的位数关系、多条 n 之间有没有公因子、签名里 r 是否重复，这些特征全靠位数与个数暴露。本章 4.3 节的 peek.py 就是一张参数表的脚本化。

**第三件：nc 服务先手探一轮。** 发一次正常输入，看返回什么、多久返回、对错误输入的反应差多少。探测结论决定脚本的交互格式与攻击分类：报错随输入变化是 oracle 类（[[C06-分组模式攻击全集|C06]]、[[C09-RSA攻击III|C09]]），耗时随输入变化是时序类（[[C15-实现漏洞与侧信道|C15]]），返回结构化签名的是签名服务类（[[C16-国密与工程实践|C16]]）。

### 2.3 多题并行与队友同步

[[W20-Web赛事综合实战与策略#2.3 时间盒与多题并行：上下文切换卡片|W20 2.3]] 的上下文卡片 Crypto 手照用，另加两栏：

| 栏 | 填什么 |
| ---- | ---- |
| 中间量 | 已算出的 d、k、部分私钥——存成 hex 写进文件，不是只留在终端里 |
| 在跑的机器 | yafu 分解、BSGS 建表、碰撞多进程——启动了什么、预计多久、日志在哪 |

"中间量"这一栏是 Crypto 特有的：一道题算出的 d 可能就是另一道题缺的输入，中间量不落盘，换题回来等于重算。==机器在跑不算卡题==：分解、建表、碰撞都是"启动之后等结果"的活，和 Web 侧的扫描器同款，启动它们，然后切去下一题。

频道里的同步格式沿用 [[W20-Web赛事综合实战与策略#2.4 队友同步：一句一个攻击面|W20 2.4]]：每句话只说一个面，面 + 状态。Crypto 版的三句话长这样：

```text
[three_rsa] 三条 n：两两 gcd 出一条公因子，剩下两条独立，各挂了 yafu
[sign_srv] 100 条 DSA 签名：r 互不相同，但 s 全是偶数，怀疑 nonce 低位为 0，准备按 HNP 走
[enc_svc] padding oracle 成立：约 256 轮每字节，正在换并发版恢复
```

三句拆开三个面：第一句是分解进展，第二句是格方向的假设，第三句是 oracle 的类型与进度。队友扫一眼就知道哪块能接手、哪块在等机器。

### 2.4 时间分配与卡住信号

前 10 分钟读脚本、列参数表、查 factordb，定下方向再动手；[[R17-赛事策略与团队协作#5.3 卡题止损与 hint 决策|R17 5.3]] 的 30 分钟止损与 hint 决策原样适用。Crypto 题特有的卡住信号，出现即触发固定动作：

| 卡住信号 | 通常含义 | 固定动作 |
| ---- | ---- | ---- |
| factordb 无记录，yafu 与 ECM 跑了 20 分钟无果 | 大概率不是分解题 | 回 [[C07-RSA攻击I#1.2 特征 → 攻击决策表\|C07 1.2]] 找别的特征：e 的大小、多条 n、密文关系 |
| 脚本结果与服务行为对不上 | 取模、符号、字节序某处错了 | 先查负数取模与整除（[[C01-密码学导论与工具链#4. 大数运算陷阱\|C01 第 4 节]]），再查两侧库的行为差异 |
| Wiener / 格解出多个候选 | 收敛子或约减基给出多个短向量 | 用"解出来是否可读"逐个验，可读者为真 |
| 服务问了几百轮没进展 | 测量面选错 | 换报错、长度、计时三个面重新选（[[C15-实现漏洞与侧信道#3.3 统计判别的三种写法\|C15 3.3]]） |
| 题面每个字都认识，不知道考什么 | 特征没进地图 | 回第 1 节的地图逐行比对，或按第 3 节把特征交给 AI 出假设清单 |

==Crypto 题的时间大头在"选对攻击"而不是"写对脚本"==：攻击选对，脚本通常十行以内；攻击选错，脚本写得再好也是在错的路上加速。参数表的最大价值就在这里——它把选攻击需要的信息提前备齐。

## 3. AI 辅助：Crypto 方向的用法与边界

[[R16-综合实战案例复盘#8. AI 辅助分析：假设与验证的分工|R16 第 8 节]]给 RE 侧立了"AI 给假设、人工验证、修正"的闭环，[[P21-综合实战赛事策略与AI辅助#3. AI 辅助利用：能做什么，必须自己做什么|P21 第 3 节]]把 PWN 侧的边界落到了数值查证上。Crypto 侧的分工表不同、红线相同：

| 位置 | 你给它什么 | 它产出什么 | 你的动作 |
| ---- | ---- | ---- | ---- |
| 数论推导核对 | 自己推的方程与变形步骤 | 符号错误、漏项、边界提醒 | 两边各算一遍对拍；公式对错用数值说话 |

Crypto 题里有三类东西不是文本任务，AI 给不了可信结论：

1. **参数边界判断。** d 与 $n^{0.25}$ 的比较、格的维度与行列式估算、Wiener 与 Boneh-Durfee 两个边界之间的归属（[[C07-RSA攻击I#3.3 完整攻击脚本与边界对照|C07 3.3]]、[[C09-RSA攻击III#3. Boneh-Durfee：Wiener 抓不住的小 d|C09 第 3 节]]、[[C13-格密码与LLL#4. LLL 的近似保证与边界|C13 第 4 节]]）——这些都是代数，自己代数。模型对边界的知识常停在旧论文上，==边界要拿本题的数算，不靠背==。
2. **格构造的临场设计。** 行向量怎么排、模数与缩放因子放哪一列，换一道题就变。AI 给的构造多数对应教材原型题；构造对不对，看解出来的向量回代是否成立（[[C14-格密码应用#6. 格攻击方法论：什么时候想格|C14 第 6 节]]的方法论）。
3. **靶机行为的真实反馈。** 报错的差别、响应的时差、密文的字节序，一条命令就能落实的事，不问它。

> [!info]- 源码没提示 d 的位数怎么办

攻击脚本是 [[C07-RSA攻击I#3.3 完整攻击脚本与边界对照|C07 3.3]] 的模板套上本题的解析：

```python
# solve_wiener.py —— 环二：e/n 连分数收敛子恢复小私钥 d（Wiener，C07 3.3）
from Crypto.Util.number import long_to_bytes

vals = {}
for line in open('output.txt'):
    line = line.strip()
    if not line or line.startswith('#'):
        continue
    key, _, v = line.partition(' = ')
    if key in ('msg1', 'msg2', 'iv', 'ct'):
        vals[key] = v
    else:
        vals[key] = int(v)
n, e, c = vals['n'], vals['e'], vals['c']

def cf(a, b):                      # a/b 的连分数展开系数
    while b:
        aq = a // b
        yield aq
        a, b = b, a - aq * b

def convergents(seq):              # 逐个产出收敛子（分子, 分母）
    n1, n2, d1, d2 = 1, 0, 0, 1
    for a in seq:
        n1, n2 = a * n1 + n2, n1
        d1, d2 = a * d1 + d2, d1
        yield n1, d1

for k, d in convergents(cf(e, n)):     # e/n ≈ k/d，收敛子逐项试
    if k == 0 or (e * d - 1) % k:
        continue
    m = pow(c, d, n)
    parts = long_to_bytes(m).split(b',')
    if len(parts) == 3:                # 可读文本即判据：三个逗号分隔的段
        print('d =', hex(d))
        print('record =', long_to_bytes(m).decode())
        open('record.txt', 'wb').write(long_to_bytes(m))
        break
```

```bash
python3 solve_wiener.py
```

```
record = 239785fef669cd9ed655e8cb369added5d8f674,7416cae0a4da01586a85e0b2e3108e8a875f2042,565a0eda9794144b867abdcae2dcfb107fd2e83a
```

两行产出都对上了预期：d 是 50 个十六进制位——200 比特，与源码注释一致；record 是三个逗号分隔的十六进制段，形状是一个 r 配两个 s，与源码"固定 nonce、签了两条公告"互证。第二环完成：签名记录到手。

### 4.4 第三环：r 相同与 k 重用

record 里只有一个 r、两个 s——这正是 [[C04-随机数攻防|C04]] 说的"固定值当随机数用"在签名侧的形态：两条签名的 k 是同一个常量，所以 r 也相同。恢复公式两行（推导见 [[C16-国密与工程实践#4.3 k 重用与低熵 k：移植 C12 的攻击|C16 4.3]]）：两条签名方程 $s_1 \equiv k^{-1}(h_1 + x r) \bmod q$ 与 $s_2 \equiv k^{-1}(h_2 + x r) \bmod q$ 相减消去 x 解出 k，再代回任一条解出 x：

$$k = (h_1 - h_2)(s_1 - s_2)^{-1} \bmod q, \qquad x = (s_1 k - h_1)\, r^{-1} \bmod q \tag{20.1}$$

```python
# solve_kreuse.py —— 环三：r 相同 → 固定 nonce，k 重用恢复 x，解出公告
import hashlib
from Crypto.Cipher import AES
from Crypto.Util.Padding import unpad
from Crypto.Util.number import bytes_to_long, inverse, long_to_bytes

vals = {}
for line in open('output.txt'):
    line = line.strip()
    if not line or line.startswith('#'):
        continue
    key, _, v = line.partition(' = ')
    vals[key] = v
p_dsa, q_dsa, g_dsa, y_dsa = (int(vals[k]) for k in ('p', 'q', 'g', 'y'))
msg1, msg2 = vals['msg1'], vals['msg2']

r, s1, s2 = (int(t, 16) for t in open('record.txt', 'rb').read().split(b','))
h1 = bytes_to_long(hashlib.sha256(msg1.encode()).digest()) % q_dsa
h2 = bytes_to_long(hashlib.sha256(msg2.encode()).digest()) % q_dsa

k = (h1 - h2) * inverse((s1 - s2) % q_dsa, q_dsa) % q_dsa
x = (s1 * k - h1) * inverse(r, q_dsa) % q_dsa
print('k =', hex(k))
print('x =', hex(x))
print('y check:', 'pass' if pow(g_dsa, x, p_dsa) % q_dsa == y_dsa % q_dsa else 'FAIL')

aeskey = hashlib.sha256(long_to_bytes(x)).digest()[:16]
pt = AES.new(aeskey, AES.MODE_CBC, bytes.fromhex(vals['iv'])).decrypt(bytes.fromhex(vals['ct']))
print('flag =', unpad(pt, 16).decode())
```

```bash
python3 solve_kreuse.py
```

输出：

```
k = 0x941cb1fceb7bf9c3cd8f01463e804da51385ef85
x = 0x56cc09c84d17c714a50622faa50fb8626b2117c
y check: pass
flag = flag{c20_w13n3r_t0_kr3us3_cha1n}
```

flag 到手，链路闭环。`y check: pass` 是回代校验：x 恢复得对不对，拿公钥验一遍——$g^x \bmod p \bmod q$ 与公钥一致，公式与解析都没有错。

> [!warning] DSA 公钥 y 的定义是 $g^x \bmod p$，不是 mod q 之后的值
> 回代校验容易栽在这一步：$y = g^x \bmod p$ 是完整的千比特数（4.3 参数表里 y 是 1022 比特，正好说明这一点），而 $r$ 才是 mod q 之后的值。校验比较的是 $y \bmod q$ 与 $g^x \bmod p \bmod q$——把 y 当成 mod q 的数直接比，就会得到"x 明明能解密、校验却 FAIL"的假警报，把人引向排查根本不存在的错误。

### 5.1 Crypto 侧的模式库条目

> | 字段 | 内容 |

## 6. 常见问题

| 现象 | 原因与解决 |
| ---- | ---- |
| sage 没装全，赛时现装要一小时 | 赛前清单没过（2.1）：sage 赛前装好并启动一次；临时替代 fpylll + sympy 覆盖大部分格题、yafu 顶分解，替代路赛前也要试通 |
| 附件是 base64 套 gzip 再套 base64 | 编码层不是密码层：按魔数逐层剥（[[C01-密码学导论与工具链#3.3 hex 与 base64：编码层还是密码层\|C01 3.3]]），剥完先 file / xxd 看形态再谈密码 |
| 脚本算出负数，后面全错 | 手写取模的中间量忘了 `% q`，或 `//` 与 `/` 混用（[[C01-密码学导论与工具链#4. 大数运算陷阱\|C01 第 4 节]]）；Python 的 `%` 对负数返回非负值，除法先想清楚要的是商还是整除 |
| 大数打印只看到省略号或科学计数 | 用 `str()` / `hex()` 全量打印，或写进文件再读；日志里存 hex 不存十进制，方便与附件比对 |
| 30 分钟卡在分解一个 1024 比特的 n | 分解不是唯一入口：回 [[C07-RSA攻击I#1.2 特征 → 攻击决策表\|C07 1.2]] 决策表找参数特征；Wiener、Coppersmith 都是秒级动作，只有"真的要分解"才轮到 yafu |
| Wiener 解出多个候选 d | 收敛子逐项验证：能解出可读文本的那个是真的（[[C07-RSA攻击I#3.3 完整攻击脚本与边界对照\|C07 3.3]]） |
| k 重用解出的 x 回代校验失败 | 先查 y 的定义：$y = g^x \bmod p$ 是完整千比特数，校验比较 $y \bmod q$（4.4 的 warning）；再查 h 是否忘了 mod q |
| long_to_bytes 出来的密钥长度不对 | 前导零被自动吞（[[C01-密码学导论与工具链#3.2 long_to_bytes：自动长度与前导零\|C01 3.2]]）：两侧用同一个转换函数；跨语言对拍时用 to_bytes 定长 |
| nc 服务每轮重连，脚本状态丢失 | 先探清服务是无状态还是每轮新密钥：会话内的计数、已发送列表在客户端维护；每轮新参数的题要按"只交互一轮"重新设计信息获取 |
| AI 给的攻击边界一用就失败 | 边界要拿本题的数代（第 3 节"参数边界判断"一条）；模型的边界知识可能停在旧论文，Boneh-Durfee 与 Wiener 的归属按 [[C09-RSA攻击III#3. Boneh-Durfee：Wiener 抓不住的小 d\|C09 第 3 节]]的对照自己判 |
| curl 打本地服务超时 | shell 里设了代理变量，请求被送进代理：加 `--noproxy '*'` 直连（4.1 的实验约定） |
| 解密出来是乱码 | 先查解密前提：密钥派生、iv 拼接顺序、填充模式三方是否与出题侧一致（[[C06-分组模式攻击全集#2.1 填充规则\|C06 2.1]]）；AES-CBC 乱码先对比第一块，第一块对说明密钥对、错在 iv 或后续 |
| 复盘时想不起当时卡在哪 | 赛中没留痕：换题前 30 秒填上下文卡片，中间量落盘（2.3）；空白卡片救不回两天前的思路 |
